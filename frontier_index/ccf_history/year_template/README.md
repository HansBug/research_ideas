# 年度汇总模板

本文档是 `ccf_history/` 下单个年份目录的结构模板。

推荐目录结构如下：

```text
ccf_history/
└── 2025/
    ├── README.md
    ├── verification.json
    ├── metadata/
    │   └── icse_conf_a.json
    └── venues/
        └── icse_conf_a.md
```

其中：

1. `README.md` 负责年度总览、统计、规范口径和 venue 导航。
2. `verification.json` 负责逐 venue 计数复核。
3. `metadata/*.json` 负责结构化元数据与最终回写字段。
4. `venues/*.md` 负责单个 venue 的逐篇论文名录。

## 7. 单个 venue 页模板

`venues/<venue>.md` 默认建议包含：

1. 文件导航
   - 年度总页
   - `verification.json`
   - 对应 `metadata/*.json`
2. 基本信息
   - `CCF` 等级
   - 类型
   - `软工归属级别`
   - `氛围`
3. 关键信息页面
4. 本 venue 统计
   - 初筛分布
   - 一级总判定分布
   - 软工纳入判定分布
5. 论文名录表
   - 标题
   - 作者
   - 一句话说明
   - 一级总判定
   - 软工纳入判定
   - 判定来源
   - 人工复核状态
   - 软工主路径（`x.x.x`）
   - 软工次路径/标签
   - 判定依据（`X1/D1-D4`）
   - `DOI`
   - 官方落地页
   - 初筛
   - `PDF` 跟进
   - `BibTeX` key
6. 本 venue 年度观察

说明：`BibTeX` 默认直接内嵌保存在对应 `metadata/*.json` 的 `bibtex` 字段中，不再单独维护 `bib/` 目录。

## 8. 分类说明

1. `一级总判定` 默认使用：
   - `软件工程`
   - `系统软件`
   - `程序设计语言与形式化基础`
   - `跨域/待判定`
2. `软工纳入判定` 默认使用：
   - `属于软件工程`
   - `跨域但软工主导`
   - `不属于软件工程`
   - `待判定`
3. 对 `跨域/待判定` 条目，应单独判断是否“软工主导”。
4. `判定依据（X1/D1-D4）` 默认用于记录最小可追溯的软工判定依据。
5. 只有 `软工纳入判定` 最终落到 `属于软件工程` 或 `跨域但软工主导` 时，才填写 `软工主路径（x.x.x）` 与 `软工次路径/标签`。
6. 软工主路径与次路径默认参考 [../SOFTWARE_ENGINEERING_FIELD_TREE.md](../SOFTWARE_ENGINEERING_FIELD_TREE.md)。
