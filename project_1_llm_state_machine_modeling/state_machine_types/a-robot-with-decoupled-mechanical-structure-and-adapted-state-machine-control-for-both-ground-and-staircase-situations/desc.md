## 简报

这篇论文把楼梯递送机器人的复杂机动压成了一套很工程化的状态机。机器人硬件被拆成 chassis、tetrapod 和 slide-and-rail 三部分，控制上则用 `ground mode / Case 1 / Case 2 / Case I / Case III / Case IV` 等状态加上 `SC1` 到 `SC7` 传感条件，组织姿态校正、抬升、滑移、落脚和回到地面。

- 形式主义定位：面向楼梯递送任务的专用监督状态机，用来协调姿态校正与上下楼基本动作。
- 构造方式简述：状态机把 Mecanum 轮底盘、EH 伸缩腿和滑轨动作按传感器条件拆成若干 basic actions 与 Case 状态。
- 基础设施与场景简述：依托 hexapod wheel-legged 机器人、Mecanum wheels、auxiliary wheel-legs、激光测距与编码器，服务地面配送、室内转向和楼梯爬升。

```text
楼梯 / 地面感知 -> SC1..SC7 条件 -> Case 状态机 -> EH / 轮组 / 滑轨动作 -> 递送机器人执行
```

## 形式主义定义与核心对象

### 定义对象

论文中的关键对象包括：

1. `ground mode` 与多种 `Case` 状态。
2. `SC1` 到 `SC7` 的切换条件。
3. 前轮、轮腿和两端激光测距数据。
4. EH A/B/C/D 的伸缩长度。
5. chassis、tetrapod 与 slide-and-rail 的解耦动作。
6. 上楼与下楼两套状态流。

### 核心抽象

按论文结构，可把该控制器保守整理为：

$$
\mathcal{D} = (Q, q_0, \Sigma, \delta, \Lambda, \mathcal{A})
$$

上式中的符号逐项解释如下：

1. `Q` 是 `ground mode` 和各类 `Case` 状态集合。
2. `q_0` 是地面运行初始状态。
3. `\Sigma` 是由激光测距、EH 长度和姿态误差组成的条件集合。
4. `\delta` 是状态转移关系。
5. `\Lambda` 是传感器观测集合。
6. `\mathcal{A}` 是状态对应的基础动作集合。

论文给出了若干关键守卫条件，例如：

$$
SC_7 = SC_4 \lor SC_5 \lor SC_6
$$

上式中的符号逐项解释如下：

1. `SC_4` 表示前轮接近上一级台阶。
2. `SC_5` 表示前轮或轮腿满足继续爬升条件。
3. `SC_6` 表示轮腿到达近地恢复条件。
4. `SC_7` 是进入主爬升动作 `Case III` 的总触发条件。

论文还直接给出姿态修正和台阶接近类条件，例如：

$$
SC_2 : \text{stairs detected} \land |d_{1L} - d_{1R}| \ge \Delta d_{\mathrm{ad}}
$$

$$
SC_4 : d_{1L} < \Delta d_{\mathrm{up}} \land d_{1R} < \Delta d_{\mathrm{up}}
$$

上式中的符号逐项解释如下：

1. `d_{1L}, d_{1R}` 是前两只 Mecanum 轮上方传感器测得的距离。
2. `\Delta d_{\mathrm{ad}}` 是姿态修正阈值。
3. `\Delta d_{\mathrm{up}}` 是接近上一级台阶的触发阈值。

### 一个最小例子与通俗解释

一个最小例子是机器人带货开始上楼：

1. 机器人先在 `ground mode` 地面模式行驶。
2. 检测到楼梯且左右前轮与台阶距离不一致时，触发 `SC2`，进入 `Case 1` 做姿态校正。
3. 当满足接近台阶条件后，`SC7` 触发，进入 `Case III` 开始主要爬升动作。
4. 若前轮已经贴近上一级台阶，进入 `Case I`；若需要在楼梯上再做姿态调整，则进入 `Case 2`。
5. 当轮腿满足回到地面的条件时，进入 `Case IV`。
6. 最终 `SC1` 成立，状态机回到 `ground mode`。

通俗地说，这个模型像一个“楼梯档位箱”：机器人并不是连续优化每一刻所有关节，而是先判断现在该做“对准、抬升、滑移、落地”中的哪一种基础动作。

### 运行 / 接受 / 转移语义

其运行语义可写成：

$$
(q_t, \lambda_t, a_t) \xrightarrow{\delta} q_{t+1}
$$

上式中的符号逐项解释如下：

1. `q_t` 是当前状态。
2. `\lambda_t` 是当前传感器读数，如 `d_{1L}, d_{1R}, d_{2L}, d_{2R}` 与 EH 编码值。
3. `a_t` 是当前执行的 basic action。
4. `q_{t+1}` 是下一状态。

### 语义边界

这个模型的边界包括：

1. 它针对特定 wheel-legged 递送机器人结构，不是通用移动机器人语言。
2. 高层状态机强依赖激光测距和 EH 伸缩机构。
3. 楼梯几何假设较强，主要针对规则台阶。
4. 它解决的是基础机动与载荷稳定，不处理一般路径规划细节。

### 关键性质与判定边界

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 监督器骨架 | `$\mathcal{D} = (Q, q_0, \Sigma, \delta, \Lambda, \mathcal{A})$` | 把 Case 状态、传感条件和基础动作统一起来。 |
| 总爬升触发 | `$SC_7 = SC_4 \lor SC_5 \lor SC_6$` | 多类接近条件都可触发主爬升动作。 |
| 姿态修正守卫 | `$SC_2 : |d_{1L} - d_{1R}| \ge \Delta d_{\mathrm{ad}}$` | 用左右距离差判断是否先做姿态校正。 |
| 台阶接近守卫 | `$SC_4 : d_{1L}, d_{1R} < \Delta d_{\mathrm{up}}$` | 轮组接近上一级台阶时切到对应动作。 |

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|
| 状态 / 模式 | 强支持 | `ground mode`、姿态修正、主爬升和恢复状态明确。 |

### 形式化问题与性质

1. 论文把“楼梯爬升”拆成了可重复组合的基础动作与切换条件。
2. `SC1..SC7` 说明专用机器人也可以有清晰的 guard design，而不是纯脚本。
3. 硬件解耦和状态解耦相互配合，是该条目的核心工程价值。
4. 对 `project_1` 来说，它适合作为“复杂机械结构任务如何被压成少量显式状态”的应用样本。

建模入口主要包括：

## 适用场景与需求前提

### 适用场景

适合需要在平地、室内和规则楼梯间切换的递送、巡检或载货机器人。

### 需求前提

1. 机器人硬件结构与论文中的轮腿 / EH 解耦思想相近。
2. 楼梯几何相对规则，可由激光测距稳定感知。
3. 任务可以分解成有限的姿态与爬升动作。
4. 载荷稳定性比高速移动更重要。

### 不适用或高成本场景

如果楼梯高度变化剧烈、地面极度不平整或环境需要高度自适应动态规划，这套专用状态机会很快遇到扩展压力。

## 与相邻形式主义的关系

它比一般 `SMACH` 任务流更贴近机器人具体机构；相对通用层次状态机，它的状态语义几乎直接绑定机械动作；相对行为树，它更适合明确“先校正再爬升再恢复”的严格时序机动。

## 与本研究的关系

### 对 Project 1 的价值

它很好地展示了一个非常具体的控制问题如何被抽成一套可枚举、可传感驱动的状态机。

### 作为目标形式主义还是中间表示

对楼梯递送机器人，这类状态机可以直接作为目标形式主义；对更大的物流系统，它更适合作为底层机动子模块的中间表示。

### 对需求到模型生成的启发

1. 机械动作前置条件很适合直接转成 `SC` 守卫。
2. 状态名最好直接绑定任务阶段，而不是模糊命名。
3. 结构解耦和状态解耦往往要一起设计。
4. 应用型条目也应保留明确的传感变量和阈值。

### 现实限制

该模型高度依赖机器人结构与楼梯几何假设，迁移到其他平台时通常需要重写状态和守卫。
