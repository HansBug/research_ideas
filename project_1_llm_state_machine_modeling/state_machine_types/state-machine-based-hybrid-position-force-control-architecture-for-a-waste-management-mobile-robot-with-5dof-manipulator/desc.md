## 简报

这篇论文的状态机不是单纯在做任务排序，而是直接控制 hybrid position / force control 中 `S`-matrix 的切换。系统先用视觉得到目标在 `XOY` 平面的位置和类型，再由状态机组织 homing、平面定位、竖直对位、夹爪 force control、提起、投放和回位等阶段，并在需要时把夹爪自由度从位置控制切到力控制。

- 形式主义定位：面向垃圾分拣机械臂的任务监督状态机，用来协调不同自由度上的位置 / 力控制模式。
- 构造方式简述：状态机维护 `Si1 / Si2 / Si3 / SC1 / SC2 / SC3 / SC4 / SC5 / SES` 等状态，并通过更新 `S_p` 与 `S_f` 来切换控制类型。
- 基础设施与场景简述：依托 Festo 五自由度执行栈、视觉检测、`PLC` 和 `CoDeSys`，服务仓库式垃圾分拣与物体抓取投放。

```text
视觉检测 / 深度 -> 状态机 -> S-matrix 更新 -> PID 位置 / 力控制 -> 机械臂抓取与投放
```

## 形式主义定义与核心对象

### 定义对象

论文中的关键对象包括：

1. 主状态机与 homing / position / force 子状态机。
2. 控制选择矩阵 `S = S_p + S_f`。
3. 位置误差 `\Delta X` 与力误差 `\Delta F`。
4. `PID` 位置控制与力控制分支。
5. 基于视觉的目标位置、类型、深度与夹持力参考。
6. `PLC`、motor controller 与 `UDP/TCP` 通信链路。

### 核心抽象

按论文结构，可把该控制器保守整理为：

$$
\mathcal{H} = (Q, q_0, \Sigma, \delta, S_p, S_f, U)
$$

上式中的符号逐项解释如下：

1. `Q` 是主状态与子状态集合。
2. `q_0` 是初始化状态。
3. `\Sigma` 是新任务、到位、夹持稳定、释放完成和紧急停止等事件集合。
4. `\delta` 是状态转移关系。
5. `S_p` 是位置控制自由度选择矩阵。
6. `S_f` 是力控制自由度选择矩阵。
7. `U` 是最终下发给执行器的控制输入。

论文直接给出了控制选择矩阵的组合关系：

$$
S = S_p + S_f
$$

上式中的符号逐项解释如下：

1. `S` 是总体控制模式矩阵。
2. `S_p` 决定哪些自由度走位置控制。
3. `S_f` 决定哪些自由度走力控制。

论文还给出了位置 / 力控制分支与总控制输入：

$$
U_x = X_{\mathrm{PID}}(S_p, \Delta X), \quad U_f = F_{\mathrm{PID}}(S_f, \Delta F, F_{S-S}), \quad U = U_x + U_f
$$

上式中的符号逐项解释如下：

1. `U_x` 是位置控制分支的输出。
2. `X_{\mathrm{PID}}` 是位置 `PID`。
3. `U_f` 是力控制分支的输出。
4. `F_{\mathrm{PID}}` 是力控制 `PID`。
5. `F_{S-S}` 是与抓取摩擦和物体重量相关的补偿项。
6. `U` 是最终控制输入。

论文进一步给出误差构造：

$$
\Delta X = X_P(\mathrm{State}, \mathrm{Obj}(p,\mathrm{type}), \mathrm{Obj}(\mathrm{depth})) - X_r(\mathrm{Rob}_{\mathrm{kin}}(d_1,d_2,d_3,d_4,\theta_1))
$$

$$
\Delta F = F_P(\mathrm{State}) + F_{S-S}(\mathrm{Obj}(\mathrm{type})) - F_r(F_{\mathrm{conv}}(I_m))
$$

上式中的符号逐项解释如下：

1. `X_P` 是由状态和目标信息决定的期望位置。
2. `X_r` 是根据直接运动学算出的当前位置。
3. `F_P` 是该状态要求的参考力。
4. `F_{S-S}` 是根据物体类型估算的抓取补偿力。
5. `F_r(F_{\mathrm{conv}}(I_m))` 是由电机电流换算得到的实际力反馈。

### 一个最小例子与通俗解释

一个最小例子是抓取一个塑料瓶并投放到回收托盘：

1. 机械臂先完成 homing，进入 `Si3` ready 状态。
2. 视觉模块给出瓶子的 `XOY` 位置、深度和类型。
3. 状态机进入 `SC1` 和 `SC2`，先做平面定位、再做竖直定位和夹爪姿态旋转。
4. 到位后进入 `SC3`，把夹爪自由度切到 force control。
5. 夹持力稳定后，四自由度位置系统把物体提起并移动到托盘上方。
6. 状态机进入 `SC4`，切回位置控制并张开夹爪释放物体，之后回到等待新任务状态。

通俗地说，这个模型像一个“会切换控制模式的分拣流水工”：定位时用位置控制，夹紧时改用力控制，扔进托盘后再切回位置控制。

### 运行 / 接受 / 转移语义

其运行语义可写成：

$$
(q_t, O_t, S_t, \Delta X_t, \Delta F_t) \xrightarrow{\delta} (q_{t+1}, U_t)
$$

上式中的符号逐项解释如下：

1. `q_t` 是当前状态。
2. `O_t` 是当前目标对象的位置、深度和类型。
3. `S_t` 是当前控制模式矩阵。
4. `\Delta X_t` 是位置误差。
5. `\Delta F_t` 是力误差。
6. `q_{t+1}` 是下一状态。
7. `U_t` 是最终控制输入。

### 语义边界

这个模型的边界包括：

1. 它针对特定 Festo 执行器和夹爪结构，不是通用机器人控制 DSL。
2. 高层状态机强依赖视觉识别、深度估计和物体类型识别。
3. 它主要解决任务阶段与控制模式切换，不着重复杂规划。
4. 论文强调工程可实现性，而不是形式验证或理论稳定性证明。

### 关键性质与判定边界

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 控制器骨架 | `$\mathcal{H} = (Q, q_0, \Sigma, \delta, S_p, S_f, U)$` | 状态机、控制矩阵和输入输出接口一体化。 |
| 模式矩阵 | `$S = S_p + S_f$` | 用矩阵明确每个自由度当前是位置还是力控制。 |
| 控制合成 | `$U = U_x + U_f$` | 位置与力控制两条支路共同组成最终输入。 |
| 误差构造 | `$\Delta X$`, `$\Delta F$` | 状态机切换时不仅变状态，也重定义控制误差。 |

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|

### 形式化问题与性质

1. 论文最重要的点，是让状态机直接控制 `S`-matrix，而不是只做任务排序。
2. 位置 / 力控制的切换边界被显式建模为状态转移。
3. 目标类型进入抓取力计算，说明需求语义会影响控制模式。
4. 对 `project_1` 来说，这类条目适合抽取“任务状态 -> 控制模式 -> 参数矩阵”的复合建模模式。

## 构造方式与承载格式

### 建模入口

建模入口主要包括：

1. 先定义 homing、定位、抓取、投放等任务阶段。
2. 再为每个阶段指定 `S_p` 与 `S_f` 的配置。
3. 用视觉检测和深度感知生成参考位置与夹持力。
4. 由状态机决定何时切换位置 / 力控制。

### 机器可处理承载方式

原文直接给出的承载方式包括：

1. 主状态机与子状态机图。
2. `S`-matrix 及其 `S_p / S_f` 分解。
3. `PID` 控制方程和直接运动学表达。
4. `PLC` 与外部状态机之间的 `Ethernet-UDP` 消息。

### 交换与互操作

互操作重点在：

1. 视觉模块经 `TCP` 给出对象位置与类型。
2. 状态机决定当前任务阶段和 `S`-matrix 配置。
3. `PLC` 执行底层控制并回传状态。
4. `CoDeSys` 可视化界面用于调试各阶段与夹爪状态。

## 适用场景与需求前提

### 适用场景

适合垃圾分拣、仓储分拣、拾取-投放这类既需要精确定位又需要按物体类型调整抓取力的机械臂任务。

### 需求前提

1. 对象位置、深度和类型可以被稳定识别。
2. 机械臂至少部分自由度需要在位置与力控制之间切换。
3. 任务可拆成初始化、定位、抓取、投放等有限阶段。
4. 底层执行器支持较快的模式重配置。

### 不适用或高成本场景

若任务需要复杂接触规划、多手协同或高度不确定的柔性物体操作，仅靠这套专用状态机会受到明显限制。

## 与相邻形式主义的关系

它比普通 pick-and-place `FSM` 更进一步，因为状态切换不仅改任务阶段，还改控制矩阵；相对一般 hybrid automata，它没有把动力学当成形式对象去证明，而是更偏工程实现；相对工业任务流工具，它更突出“模式切换进入控制器内部”的设计。

## 与本研究的关系

### 对 Project 1 的价值

它很好地说明：状态机不仅能编排任务，也能充当控制模式与参数矩阵的上层接口。

### 作为目标形式主义还是中间表示

对垃圾分拣机械臂任务，它可以直接作为目标形式主义；对更大的工厂系统，它更适合作为操作子任务的中间表示。

### 对需求到模型生成的启发

1. 抓取类需求往往需要把“对象类型”直接接入状态参数。
2. 控制模式切换应该显式建模，而不是藏在控制代码里。
3. 外部视觉与内部状态机之间要保持清晰的数据接口。
4. 应用型条目也应尽量保留矩阵、误差和控制输入这些正式对象。

### 现实限制

该模型严重依赖特定硬件链和任务结构；如果平台或工艺变化很大，`S`-matrix 与状态图都要重构。
