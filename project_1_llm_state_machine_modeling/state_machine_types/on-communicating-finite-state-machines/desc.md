## 简报

这篇论文把“单进程有限状态机”扩展成“多进程有限状态机 + 显式消息通道”的协议模型。核心不是把每个参与者做得更复杂，而是把通信显式放到 full-duplex、error-free、FIFO channel 上，再用全局状态和可达性来问协议是否 well-formed、是否会 deadlock、哪些 reception 永远不可执行。

- 形式主义定位：面向异步消息协议的组合状态机模型。
- 构造方式简述：每个进程是一个局部 `FSM`，进程对之间通过成对 FIFO 通道交换离散消息。
- 基础设施与场景简述：论文本体提供的是 reachability / tree construction / boundedness 分析路线，适合通信协议、分布式交互和消息驱动控制器。

```text
协议参与方与消息集合 -> 局部 FSM + FIFO channels -> 全局状态可达图 -> missing reception / deadlock / boundedness 分析
```

## 形式主义定义与核心对象

### 定义对象

论文面向的是通信协议，而不是单机控制器。建模对象由若干个有限状态进程和它们之间的消息通道组成，关注的是“本地状态转移 + 通道中消息积压”共同决定的协议行为。

### 核心抽象

原文把一个协议定义为四元组：

$$
P = ((S_i)_{i=1}^N, (o_i)_{i=1}^N, (M_{ij})_{i,j=1}^N, \mathrm{succ})
$$

上式中的符号逐项解释如下：

1. `N` 是进程个数。
2. `S_i` 是第 `i` 个进程的有限状态集合。
3. `o_i \in S_i` 是第 `i` 个进程的初始状态。
4. `M_{ij}` 是从进程 `i` 发送到进程 `j` 的消息集合，且原文要求不同 `M_{ij}` 互不相交。
5. `\mathrm{succ}` 是部分函数，描述某个进程在发送或接收特定消息后进入哪个后继状态。

单个局部状态机并不足以表达协议整体语义，因此原文进一步引入全局状态：

$$
g = (S, C)
$$

其中：

1. `S = (s_1, \ldots, s_N)` 是所有进程当前局部状态组成的 `N` 元组。
2. `C = (c_{11}, \ldots, c_{NN})` 是所有通道内容组成的 `N^2` 元组。
3. 每个 `c_{ij}` 是消息序列，表示从进程 `i` 到进程 `j` 的 FIFO 队列内容。

### 一个最小例子与通俗解释

论文第一页就给了一个很典型的两进程协议：

1. `USER` 初始在 `READY`，`SERVER` 初始在 `IDLE`。
2. `USER` 发送 `REQ` 后进入 `WAIT`。
3. `SERVER` 接收 `REQ` 后进入 `SERVICE`，服务结束发送 `DONE` 并回到 `IDLE`。
4. `USER` 接收 `DONE` 后从 `WAIT` 回到 `READY`。

通俗解释是：`CFSM` 不是只盯着“每个组件现在在哪个状态”，而是同时记住“消息还堵在哪些通道里”。因此它比普通 `FSM` 更像“若干小状态机 + 若干邮件队列”的组合系统。

### 运行 / 接受 / 转移语义

论文把执行定义为全局状态之间的一步关系。若当前全局状态是 `g = (S, C)`，则发送一步和接收一步分别可保守写成：

$$
(S, C) \xrightarrow{\mathrm{send}\ x_{ik}} (S', C')
$$

当且仅当：

$$
s_i' = \mathrm{succ}(s_i, -x_{ik}), \qquad c_{ik}' = c_{ik} x_{ik}
$$

以及其它分量保持不变。

接收一步则是：

$$
(S, C) \xrightarrow{\mathrm{recv}\ x_{ik}} (S', C')
$$

当且仅当：

$$
s_k' = \mathrm{succ}(s_k, +x_{ik}), \qquad c_{ik} = x_{ik} c_{ik}'
$$

以及其它分量保持不变。

由此得到可达性：

$$
Reach(P) = \{ g \mid g_0 \xrightarrow{*} g \}
$$

其中初始全局状态为：

$$
g_0 = ((o_i)_{i=1}^N, (\epsilon)_{i,j=1}^N)
$$

这些语义公式中的符号逐项解释如下：

1. `x_{ik}` 是从进程 `i` 发往进程 `k` 的消息。
2. `-x_{ik}` 表示发送该消息，`+x_{ik}` 表示接收该消息。
3. `c_{ik} x_{ik}` 表示把消息追加到 FIFO 通道尾部。
4. `c_{ik} = x_{ik} c_{ik}'` 表示接收时从队首取走消息。
5. `\xrightarrow{*}` 是一步关系的反身传递闭包。
6. `\epsilon` 是空消息序列。

### 语义边界

这套模型是纯离散、纯消息导向的。它擅长表达异步通信，但不直接表达：

1. 数值数据上的复杂守卫和赋值。
2. 显式时间约束。
3. 层次状态或共享内存式并发。

更关键的是，FIFO 通道若允许无界增长，就可能成为“外部记忆”，进而把分析问题推向不可判定。

### 关键性质与判定边界

论文关心的核心不是语言接受，而是协议完备性和可分析性。几个典型问题可压缩为：

$$
\mathrm{ExecRecv}(s, x) \equiv \exists (S, C) \in Reach(P): s \in S \land x \text{ 位于某接收通道队首}
$$

$$
\mathrm{Deadlock}(g) \equiv \neg \exists g'.\ g \to g'
$$

$$
\mathrm{Bounded}(i, j, h) \equiv \forall (S, C) \in Reach(P),\ |c_{ij}| \le h
$$

论文给出的关键边界是：

1. 一般情况下，reception executability、well-formedness、deadlock 和 boundedness 都可能不可判定。
2. 若所有通道都有界，则这些分析问题回到可解。
3. 即使存在无界通道，某些受限拓扑下仍可处理；论文特别指出“两进程且仅一条通道无界”时可以保留可解性。

这些性质公式中的符号逐项解释如下：

1. `\mathrm{ExecRecv}(s, x)` 表示某个 reception 在某个可达场景下确实可执行。
2. `\mathrm{Deadlock}(g)` 表示全局状态 `g` 没有任何可继续的发送或接收动作。
3. `|c_{ij}|` 是通道 `c_{ij}` 中消息序列的长度。
4. `h` 是预设的通道上界。

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|
| 状态 / 模式 | 强支持 | 每个参与方都是显式局部有限状态机。 |
| 事件 / 触发 | 强支持 | 发送和接收消息就是核心触发机制。 |
| 守卫 / 数据 | 不支持 | 原始模型没有 EFSM 风格数据守卫与赋值。 |
| 层次 | 不支持 | 没有层次状态。 |
| 并发 / 同步 | 强支持 | 多进程并发，通过异步 FIFO 通道耦合。 |
| 时间约束 | 不支持 | 不含显式时钟或时间不变式。 |
| 连续动态 / 随机性 | 不支持 | 纯离散消息系统。 |
| 可执行 / 可验证性 | 部分支持 | 适合可达性与协议错误分析，但判定性依赖通道条件。 |

### 形式化问题与性质

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 协议定义 | `$P = ((S_i),(o_i),(M_{ij}),\mathrm{succ})$` | 每个进程是局部 `FSM`，通信经由成对消息集合。 |
| 全局状态 | `$g=(S,C)$` | 运行状态由局部状态元组和通道内容共同决定。 |
| 发送步 | `$(S,C)\xrightarrow{\mathrm{send}\ x_{ik}}(S',C')$` | 发送会更新本地状态并把消息压入 FIFO 队尾。 |
| 接收步 | `$(S,C)\xrightarrow{\mathrm{recv}\ x_{ik}}(S',C')$` | 接收会从 FIFO 队首取消息并更新接收方状态。 |
| 死锁 | `$\mathrm{Deadlock}(g) \equiv \neg \exists g'.\ g \to g'$` | 可达状态中是否存在协议停滞。 |
| 通道有界性 | `$\forall g \in Reach(P), |c_{ij}| \le h$` | 是否能为每条通道找到统一上界。 |

## 适用场景与需求前提

### 适用场景

适合通信协议、异步消息交互、分布式控制器协作和任何“参与方有限、消息离散、通道语义重要”的系统。

### 需求前提

1. 需求能分解为多个有限状态参与方。
2. 交互以离散消息为主，且消息方向明确。
3. 通道语义必须显式建模，尤其是 FIFO 队列积压会影响行为。
4. 若需要可判定验证，最好还能给出通道有界性或受限拓扑假设。

### 不适用或高成本场景

若系统核心是复杂数据变换、连续控制律、实时约束或共享变量并发，`CFSM` 就会显得过于瘦弱，通常需要 `EFSM`、`Timed Automata` 或更丰富的接口/组合模型。

## 与相邻形式主义的关系

相对普通 `FSM`，`CFSM` 把“通信中的消息积压”提升为一等公民；相对 `EFSM`，它弱在数据和守卫，强在异步通道语义；相对 `I/O Automata`，它更强调消息队列和协议执行，而不是 input-enabled 组合语义。

## 与本研究的关系

### 对 Project 1 的价值

它非常适合补“多组件控制逻辑中的通信侧状态机”这一空白。很多控制系统需求并不只描述控制模式，还会描述控制器、执行器、监控器之间的消息握手，这类结构用 `CFSM` 比单体 `FSM` 更自然。

### 作为目标形式主义还是中间表示

更适合作为中间表示或专题子模型，尤其适合描述通信子系统和接口握手部分，而不是整个控制系统的唯一顶层形式主义。

### 对需求到模型生成的启发

当自然语言需求里反复出现“组件 A 发送 X、组件 B 回复 Y、若超前收到 Z 则异常”等模式时，可以优先抽成若干局部状态机和消息通道，再做全局一致性分析。

### 现实限制

若不加通道约束，判定性很快失控；因此它虽能精确表达异步协议，但在自动化建模链里通常需要配套做 boundedness 假设、拓扑裁剪或抽象。
