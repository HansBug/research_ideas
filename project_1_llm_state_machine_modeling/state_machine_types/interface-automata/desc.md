## 简报

Interface Automata 把接口看成“对环境输入的假设 + 自身输出保证”的行为契约，而不是单纯的动作集合。它的关键点是 compatibility、illegal states、composition 和 alternating simulation/refinement，因此特别适合做组件接口匹配和替换性分析。

- 形式主义定位：面向组件协作的行为接口状态机。
- 构造方式简述：通过输入/输出动作区分、接口状态和组合规则定义接口行为。
- 基础设施与场景简述：原文是语义模型，不是工业交换标准；其主要价值在接口兼容性与 refinement 分析。

```text
组件交互契约 -> 输入假设/输出保证接口机 -> 组合兼容性分析 -> 替换与精化
```

## 形式主义定义与核心对象

### 定义对象

该模型针对的是软件组件、模块或服务之间的交互协议，而不是单个组件内部的完整控制逻辑。

### 核心抽象

接口自动机以状态和带方向的动作构成。与普通 I/O 模型不同，它把某些环境行为视为假设，并通过 compatibility 检查找出组合后的非法状态。

可把其核心对象写成：

$$
A = (Q, q_0, \Sigma^{I}, \Sigma^{O}, \Sigma^{H}, \delta)
$$

其中：

$$
\Sigma = \Sigma^{I} \uplus \Sigma^{O} \uplus \Sigma^{H}
$$

上式中的符号逐项解释如下：

1. `Q` 是接口状态集合。
2. `q_0` 是初始接口状态。
3. `\Sigma^{I}`、`\Sigma^{O}`、`\Sigma^{H}` 分别是输入、输出和内部动作集合。
4. `\uplus` 表示这三类动作互不重叠。
5. `\delta` 是迁移关系。
6. `\Sigma` 是三类动作合并后的总动作集。

### 一个最小例子与通俗解释

一个最小例子是“客户端必须先 `open` 再 `read`，服务器则先等待 `open`，再允许输出 `data`”。如果客户端此时想继续 `read`，而服务器没有准备好接住对应交互，组合后就会进入非法状态。

通俗解释是：`Interface Automata` 像在问“这两个接口是不是说得拢”。它关注的不是组件内部做了什么复杂计算，而是双方在每一步到底谁能说、谁能听、会不会一开口就撞车。

### 运行 / 接受 / 转移语义

运行时配置是接口状态，步语义为：

$$
q \xrightarrow{a} q' \iff (q,a,q') \in \delta
$$

对两个接口自动机 `A` 与 `B`，若共享动作满足一方输出对应另一方输入，则可构造组合：

$$
A \parallel B
$$

共享动作在组合中同步，非共享动作独立前进。Interface Automata 的关键不是普通 trace，而是“组合后是否进入 illegal states”。可把非法状态集保守写为：

$$
\mathrm{Illegal}(A,B) = \{(p,q) \mid \exists a,\ a \in \Sigma_A^{O} \cap \Sigma_B^{I},\ p \xrightarrow{a} \land q \not\xrightarrow{a}\} \cup sym
$$

其中 `sym` 表示交换 `A/B` 后得到的对称情形。它刻画的正是“某一方准备输出，而另一方并未准备接受”的接口冲突。

这些语义公式中的符号逐项解释如下：

1. `q \xrightarrow{a} q'` 表示接口在动作 `a` 下从状态 `q` 走到 `q'`。
2. `A \parallel B` 表示两个接口自动机的并行组合。
3. `(p,q)` 是组合状态，也就是 `A` 的状态 `p` 与 `B` 的状态 `q` 组成的有序对。
4. `\Sigma_A^{O}` 和 `\Sigma_B^{I}` 分别表示 `A` 的输出动作集和 `B` 的输入动作集。
5. `\not\xrightarrow{a}` 表示不存在标记为 `a` 的可执行迁移。
6. `sym` 表示把 `A/B` 互换后的对称非法情形。

### 语义边界

它强调接口协作和组件替换，而不是复杂内部数据或连续物理过程。其核心不是“系统本体怎么运行”，而是“两个接口能否安全协同”。

### 关键性质与判定边界

于是接口兼容性的核心判定就是：

$$
\text{Compat}(A,B) \iff \mathrm{Reach}(A \parallel B) \cap \mathrm{Illegal}(A,B) = \emptyset
$$

而 refinement / substitutivity 则通过 alternating simulation 表达。若记该关系为 `\preceq_{alt}`，则其关键目标是：

$$
A_1 \preceq_{alt} A_2 \Rightarrow A_1 \parallel B \preceq_{alt} A_2 \parallel B
$$

前提是相关组合均定义良好。也就是说，Interface Automata 的边界不在“表达内部算法”，而在于它只分析接口协作是否可接受，以及某个组件是否可被更精化的接口替换。

这里的性质公式符号逐项解释如下：

1. `\mathrm{Reach}(A \parallel B)` 是组合接口的可达状态集合。
2. `\text{Compat}(A,B)` 表示接口兼容性判定。
3. `\preceq_{alt}` 表示 alternating simulation，也就是接口精化关系。
4. `A_1`、`A_2` 是两个候选实现，`B` 是待组合的环境接口。

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|
| 状态 / 模式 | 支持 | 接口协议由显式状态刻画。 |
| 事件 / 触发 | 强支持 | 输入/输出动作方向性很关键。 |
| 守卫 / 数据 | 部分支持 | 原文核心不在数据变量。 |
| 层次 | 不支持 | 非层次模型。 |
| 并发 / 同步 | 强支持 | composition 和 compatibility 是核心。 |
| 时间约束 | 不支持 | 无显式时间。 |
| 连续动态 / 随机性 | 不支持 | 纯离散接口行为。 |
| 可执行 / 可验证性 | 强支持 | alternating simulation 与 refinement 明确。 |

### 形式化问题与性质

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 单步接口迁移 | `$q \xrightarrow{a} q'$` | 接口在动作驱动下变更状态。 |
| 组合 | `$A \parallel B$` | 共享输入/输出动作同步执行。 |
| 非法状态 | `$\mathrm{Illegal}(A,B)$` | 输出无法被对方接受的冲突状态。 |
| 兼容性 | `$\mathrm{Reach}(A \parallel B)\cap \mathrm{Illegal}(A,B)=\emptyset$` | 两接口能否安全协同。 |
| 交替模拟 | `$A_1 \preceq_{alt} A_2$` | 接口精化与可替换性的基础。 |

## 适用场景与需求前提

### 适用场景

适用于组件接口匹配、服务组合、协议兼容性检查、模块替换验证。

### 需求前提

1. 关注点是组件之间的交互行为，而不是单体内部算法。
2. 需要区分环境可提供什么和组件会输出什么。
3. 需要检查兼容性或替换性。

### 不适用或高成本场景

若需求主要关心内部控制模式、实时约束或连续动态，接口自动机并不是最直接主模型。

## 与相邻形式主义的关系

相对 `I/O Automata`，它更强调接口假设/保证与非法组合状态；相对 `Contract Automata`，它较少关注多方请求-提供匹配和 agreement 优化；相对 `FSM`，它更强在组合语义。

## 与本研究的关系

### 对 Project 1 的价值

它有助于分析多子状态机之间的接口边界，而不是把所有东西压进一个全局状态机。
