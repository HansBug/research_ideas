## 简报

这篇论文是少数把专用应用状态机写得很“像形式化模型”的工程论文之一。作者并没有停留在“机器人会先拍照再铺砖”的口语描述，而是把铺砖过程写成显式的状态、动作、参数和转移条件集合，再把它映射成有向图。整个状态机服务于一个核心目标：**在相机视场受限的条件下，仍然完成逐块砖的在线定位、姿态纠偏和放置**。

- 形式主义定位：面向施工机器人铺砖任务的专用监督状态机，核心是把视觉测量、位姿纠偏和机械臂动作串成可执行流程。
- 构造方式简述：状态机使用 `S0..S10` 表示初始化、拍照、三类边缘检测、位置计算、测高、水平移动、旋转、竖直移动和完成铺设。
- 基础设施与场景简述：依托 `FTR-II` 平台、机器人手臂、相机、激光传感器和 `ROS` 控制软件，服务实验室环境下的地砖铺设。

```text
初始化 -> 拍照 -> 选择 edge detector -> 位置/高度估计 -> 机械臂纠偏放置 -> 偏差复测 -> 完成一块砖
```

## 形式主义定义与核心对象

### 定义对象

论文中的关键对象包括：

1. 状态集合 `S = \{S_0, S_1, \ldots, S_{10}\}`。
2. 动作集合 `A`，对应相机、机械臂、吸盘、激光、边缘检测和位置计算等执行单元。
3. 参数集合 `P`，包括 `D_1 = (\Delta x, \Delta y)`、`D_2 = \{\theta\}`、`D_3 = \{h\}`。
4. 状态转移条件集合 `C`，包括 `con1/con2/con3` 和各类执行完成标志。
5. 图结构 `G = \{S, E\}`。
6. `S0..S10` 的状态表与动作绑定关系。

### 核心抽象

论文显式给出了状态机定义：

$$
\Sigma_{fsm} = \{S, A, P, C\}
$$

上式中的符号逐项解释如下：

1. `S` 是机器人铺砖状态集合。
2. `A` 是状态对应的程序动作集合。
3. `P` 是状态参数集合。
4. `C` 是状态转移条件集合。

论文进一步给出每个状态与三类对象之间的绑定关系：

$$
S_i = (A_i, P_i, C_i), \quad i = 1,2,\ldots,n
$$

上式中的符号逐项解释如下：

1. `S_i` 是第 `i` 个状态。
2. `A_i` 是状态 `S_i` 对应的动作单元。
3. `P_i` 是状态 `S_i` 使用的参数。
4. `C_i` 是从状态 `S_i` 出发的转移条件集合。

图论表示则写成：

$$
G = \{S, E\}
$$

$$
E = \{(S_i, S_j) \mid c_{i,j} \in C_{ij}\}
$$

上式中的符号逐项解释如下：

1. `G` 是状态转移有向图。
2. `S` 是图中的顶点集合，即所有状态。
3. `E` 是边集合。
4. `c_{i,j}` 是从 `S_i` 到 `S_j` 的条件。
5. 当 `c_{i,j}` 成立时，对应的状态边被激活。

论文中的关键参数还可写成：

$$
D_1 = (\Delta x, \Delta y), \quad D_2 = \{\theta\}, \quad D_3 = \{h\}
$$

上式中的符号逐项解释如下：

1. `D_1` 表示平面位置偏差。
2. `D_2` 表示姿态角偏差。
3. `D_3` 表示竖直高度偏差。

### 一个最小例子与通俗解释

最小例子可以直接用“铺下一块砖”的流程描述：

1. 系统从 `S0` 初始化后进入 `S1` 拍照。
2. 根据当前砖块在有限视场中的成像情况，转到 `S2`、`S3` 或 `S4` 之一做边缘检测。
3. 完成后进入 `S5` 计算当前砖与目标位姿之间的平移和旋转误差。
4. 进入 `S8` 测量高度，再依次经过 `S9`、`S6`、`S7` 做竖直、水平和平面旋转纠偏。
5. 系统重新拍照复测，若误差仍超阈值，则继续重复纠偏；若已在允许范围内，则转到 `S10` 释放吸盘完成铺设。

通俗地说，这个模型像“施工版精调工序卡”。每铺一块砖都必须走完同一套“看、算、抬、挪、转、复查”的工序。

### 运行 / 接受 / 转移语义

其运行语义可保守写成：

$$
(S_i, P_i, C_i) \xrightarrow{A_i} (P_i', c_{i,j}) \xrightarrow{} S_j
$$

上式中的符号逐项解释如下：

1. `S_i` 是当前状态。
2. `A_i` 是在该状态执行的动作。
3. `P_i` 是执行前的参数状态。
4. `P_i'` 是执行后更新得到的参数。
5. `c_{i,j}` 是由新参数触发的转移条件。
6. `S_j` 是下一状态。

对本文最关键的完成判据，可进一步理解为：

$$
(\Delta x, \Delta y, \theta, h) \in \mathrm{Tolerance} \Rightarrow S_{10}
$$

表示当平移、旋转和高度偏差都进入允许范围时，状态机进入完成状态。

### 语义边界

这个模型的边界包括：

1. 它针对特定铺砖单元流程，不是通用施工机器人语言。
2. 所有感知与操作都围绕有限视场视觉测量设计。
3. 移动平台导航问题被显著简化，重点是单次铺砖周期内部。
4. 状态机负责工序调度，不直接解决复杂轨迹规划或施工全局调度。

### 关键性质与判定边界

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 状态机元组 | `$\Sigma_{fsm} = \{S, A, P, C\}$` | 应用状态机被明确拆成状态、动作、参数和条件四类对象。 |
| 状态展开 | `$S_i = (A_i, P_i, C_i)$` | 每个状态都绑定动作、参数和守卫。 |
| 图论语义 | `$G = \{S, E\}$`, `$E = \{(S_i, S_j) \mid c_{i,j} \in C_{ij}\}$` | 转移条件被显式建模成有向边。 |
| 位姿误差参数 | `$D_1 = (\Delta x, \Delta y), D_2 = \{\theta\}, D_3 = \{h\}$` | 纠偏动作的依据被结构化成三类参数。 |

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|
| 状态 / 模式 | 强支持 | `S0..S10` 把铺砖流程拆得很细。 |
| 事件 / 触发 | 强支持 | 图像获取完成、边缘检测完成、位置误差是否达标都会触发转移。 |
| 守卫 / 数据 | 强支持 | `\Delta x, \Delta y, \theta, h` 和 `con1/con2/con3` 是显式 guard。 |
| 层次 | 弱支持 | 主要是单层工作流状态机。 |
| 并发 / 同步 | 弱支持 | 重点是单工位、单砖块铺设序列。 |
| 时间约束 | 弱支持 | 不强调显式时间语义。 |
| 连续动态 / 随机性 | 中等连续、无随机 | 机械臂运动连续，但高层调度是离散的。 |
| 可执行 / 可验证性 | 强执行、较强可追溯 | 论文给出显式元组、状态表和实验结果，但没有形式模型检验。 |

### 形式化问题与性质

1. 论文直接把应用状态机写成数学对象，这对文库非常有价值。
2. `A/P/C` 分层使状态机不再只是“状态图截图”，而是接近可机器处理的对象模型。
3. 误差参数的显式化，使“是否继续纠偏”这一需求可以直接落成 guard。
4. 实验上，系统连续铺设 `12` 块砖，总时长 `385 s`，平均每块 `32.1 s`，`x/y` 平均偏差分别为 `0.04 mm` 和 `0.11 mm`。

## 构造方式与承载格式

### 建模入口

建模入口主要包括：

1. 先把一次铺砖周期拆成拍照、检测、定位、测高、放置和复查几个阶段。
2. 再把不同成像工况拆成 `con1/con2/con3` 三类边缘检测分支。
3. 用 `D_1/D_2/D_3` 显式承载位置、姿态和高度误差。
4. 用状态表把动作执行单元 `Y1..Y6` 和状态一一绑定。

### 机器可处理承载方式

原文直接给出的承载方式包括：

1. `\Sigma_{fsm}` 数学定义。
2. `G = \{S, E\}` 图论表示。

4. 状态信息表 `Table 5` 与控制变量表 `Table 3`。

### 交换与互操作

互操作重点在：

1. 相机驱动边缘检测与位置估计。
2. 激光传感器提供高度参数。
3. 状态机把参数送给机器人手臂与吸盘动作。
4. 复测环节再把最新误差反馈给状态机判断是否继续纠偏。

## 适用场景与需求前提

### 适用场景

适合具有标准化砖块、可控工位和有限视场视觉测量条件的地砖铺设、类似面板放置和施工装配场景。

### 需求前提

1. 目标物尺寸和放置规则较稳定。
2. 图像中能够可靠提取边缘与位姿信息。
3. 机械臂动作可以分解成竖直、水平和平面旋转三类纠偏。
4. 允许每个工件走完整的“测量-修正-复测”闭环。

### 不适用或高成本场景

若施工现场几何变化大、移动平台定位误差高、目标物并非规则矩形，或者需要强实时协同，这种专用 `FSM` 需要较大幅度改写。

## 与相邻形式主义的关系

它比普通工业流程脚本更显式地形式化了状态和守卫；相对通用机器人任务图，它把视觉测量误差当成一等状态参数；相对行为树，它更强调严格工序顺序和复测闭环。

## 与本研究的关系

### 对 Project 1 的价值

这篇论文非常适合用作应用型状态机的正面样本，因为它直接给出了机器可读的元组、状态表和参数口径。

### 作为目标形式主义还是中间表示

对施工机器人而言，它可以直接作为目标执行载体；对更大的施工流程系统，也可作为单工位铺砖任务的中间表示。

### 对需求到模型生成的启发

1. 当需求天然包含工序卡时，LLM 可以直接生成 `S/A/P/C` 四元对象，而不是只生成自然语言摘要。
2. 视觉测量类应用中，误差参数应显式进入状态机变量集。
3. 若工况有稳定分类，应优先生成多分支检测状态，而不是在单个状态里堆很多 `if`。
4. 应用论文只要给出显式元组、状态表和参数，也完全值得正式入库。

### 现实限制

论文的状态机高度依赖 `FTR-II` 硬件和受控实验环境，迁移到复杂工地时仍需补足导航和现场适应能力。
