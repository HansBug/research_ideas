## 简报

这篇论文的重点不是单独设计某个低层控制器，而是把自动驾驶决策拆成三个明确层次：先判断车辆所处场景，再评估不同候选行为的“能效值”，最后由底层动作状态机输出具体驾驶动作。对本 collection 来说，它补的是“分层有限状态机如何作为自动驾驶行为规划骨架”这条应用型路线。

- 形式主义定位：面向多车复杂场景的三层层次状态机决策系统，其中状态机负责完成场景识别、行为评分和动作选择。
- 构造方式简述：上层按周车分布划分场景，中层根据安全/效率/车道空闲度计算能效函数，下层用状态转移矩阵输出 `加速 / 左变道 / 右变道 / 减速`。
- 基础设施与场景简述：依托 `PreScan`、`Simulink`、网格化车道占用模型和车载感知模块，服务直道多车跟驰与变道决策场景。

```text
周车分布 -> Top FSM 场景判断 -> Middle FSM 能效评估 -> Lower FSM 动作选择 -> 车辆动力学执行
```

## 形式主义定义与核心对象

### 定义对象

论文中的关键对象包括：

1. 三层状态机：场景决策层、能效评估层、动作决策层。
2. 场景集合，例如“前方无车”“侧方无车”“侧方有车”等子场景。
3. 候选行为集合 `A = {加速, 右变道, 左变道, 减速}`。
4. 安全距离模型，包括变道安全距离和跟驰安全距离。
5. 车道占用栅格和车道空闲率。
6. 综合安全、效率、车道可用性的能效函数。
7. 底层状态转移表和状态转移矩阵。

### 核心抽象

论文直接把每层有限状态机写成五元组：

$$
M = (S, \Sigma, f, S_0, F)
$$

上式中的符号逐项解释如下：

1. `S` 是状态集合，在本文中可表示各层任务点或场景状态。
2. `\Sigma` 是输入事件或情形集合，例如周车分布、相对速度和相对距离。
3. `f` 是状态转移函数。
4. `S_0` 是初始状态。
5. `F` 是终止状态。

为了表达层次结构，可把整套决策骨架保守整理为：

$$
\mathcal{H} = (M_{\mathrm{top}}, M_{\mathrm{mid}}, M_{\mathrm{low}}, U, P)
$$

上式中的符号逐项解释如下：

1. `M_{\mathrm{top}}` 是场景识别状态机。
2. `M_{\mathrm{mid}}` 是候选行为能效评估状态机。
3. `M_{\mathrm{low}}` 是底层动作选择状态机。
4. `U` 是综合能效函数。
5. `P` 是底层状态转移矩阵。

论文给出的综合能效函数为：

$$
U = \sum_{i=1}^{3} \omega_i U_i
$$

上式中的符号逐项解释如下：

1. `U_1`、`U_2`、`U_3` 分别对应效率、安全和车道空闲率相关指标。
2. `\omega_i` 是各指标的权重，原文通过层次分析法求得。
3. `U` 是某个候选驾驶行为的综合能效值。

底层动作机的状态推进则可保守写成：

$$
S_{t+1} = S_t P R_t^{\top}
$$

上式中的符号逐项解释如下：

1. `S_t` 是当前时刻的动作节点状态向量。
2. `P` 是论文中的静态转换矩阵。
3. `R_t` 是中层能效评估后得到的最优行为指示向量。
4. `S_{t+1}` 是下一时刻动作状态。

论文还给出变道安全距离模型，可用来表示中层评估中的安全条件：

$$
\mathrm{Min}_c(S) = \mathrm{Min}_c(S_1) + \mathrm{Min}_c(S_2)
$$

其中：

1. `\mathrm{Min}_c(S_1)` 是变道过程中的临界碰撞点安全距离。
2. `\mathrm{Min}_c(S_2)` 是变道完成后的安全跟驰距离。

### 一个最小例子与通俗解释

一个典型例子是：

1. 自车在中间车道行驶，前车较慢，左车道空闲。
2. `Top FSM` 根据周围车辆分布把当前局面识别为“前方有慢车、左侧可用”的场景。
3. `Middle FSM` 分别评估“加速、左变道、右变道、减速”的能效值，发现左变道收益最高。
4. `Lower FSM` 通过状态转移矩阵把当前动作节点推进到“左变道”状态。
5. 最终车辆动力学模块执行左变道动作。

通俗地说，这个模型像一个“三层秘书处”：第一层先看路况属于哪一类，第二层开会比较几种动作谁最划算，第三层再把“批准的动作”变成下一步要执行的明确指令。

### 运行 / 接受 / 转移语义

整套决策语义可以压缩为：

$$
\sigma_t \xrightarrow{M_{\mathrm{top}}} c_t
\xrightarrow{M_{\mathrm{mid}}} R_t
\xrightarrow{M_{\mathrm{low}}} a_t
$$

上式中的符号逐项解释如下：

1. `\sigma_t` 是当前交通观测信息。
2. `c_t` 是上层状态机给出的场景类别。
3. `R_t` 是中层评估后得到的最优行为指示。
4. `a_t` 是下层输出的具体驾驶动作。

这说明该框架的核心不是单一一张状态图，而是“场景分类 -> 指标评估 -> 动作落地”的层级流水线。

### 语义边界

这个模型的边界包括：

1. 它主要面向直道、多车、结构化车道环境。
2. 它负责行为决策，不负责高保真轨迹跟踪控制。
3. 中层的“能效函数”本质上是启发式综合指标，而不是严格最优控制证明。
4. 论文也明确承认轨迹规划细节和权重选择仍有改进空间。

### 关键性质与判定边界

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 单层 FSM 定义 | `$M = (S, \Sigma, f, S_0, F)$` | 每一层决策都被建模成有限状态机。 |
| 分层骨架 | `$\mathcal{H} = (M_{\mathrm{top}}, M_{\mathrm{mid}}, M_{\mathrm{low}}, U, P)$` | 三层状态机通过能效函数和转移矩阵协同。 |
| 综合评分 | `$U = \sum_{i=1}^{3} \omega_i U_i$` | 通过安全、效率、车道空闲率综合判断候选行为。 |
| 动作推进 | `$S_{t+1} = S_t P R_t^{\top}$` | 下层状态机按最优行为指示推进到下一动作。 |

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|
| 状态 / 模式 | 强支持 | 三层 `FSM` 都有清晰离散状态。 |
| 事件 / 触发 | 强支持 | 周车分布、速度、距离、车道占用共同驱动转移。 |
| 守卫 / 数据 | 强支持 | 安全距离模型、能效函数和占用栅格是核心数据守卫。 |
| 层次 | 强支持 | 论文明确强调 top/middle/lower 三层状态机。 |
| 并发 / 同步 | 弱支持 | 主体是单车行为决策，不是并发组合状态机。 |
| 时间约束 | 弱支持 | 没有显式时钟语义，时间主要体现在离散决策时刻。 |
| 连续动态 / 随机性 | 中等支持 | 车辆动力学和变道轨迹模型存在，但不构成连续状态机主体。 |
| 可执行 / 可验证性 | 强执行、弱验证 | 可在 `PreScan + Simulink` 中运行，但不是形式验证框架。 |

### 形式化问题与性质

1. 这篇论文真正提供的是“分层决策状态机骨架”，而不是单个启发式规则。
2. 上层场景机解决“现在属于哪类交通局面”，中层评分机解决“哪种动作更划算”，下层动作机解决“下一步到底执行哪个动作”。
3. 这种分层组织方式比单层扁平状态机更容易接纳多指标评价。
4. 对自动建模任务来说，这类结构说明需求文本完全可以先分解到不同抽象层，再分别生成状态机。

## 构造方式与承载格式

### 建模入口

建模入口主要包括：

1. 用周车位置关系定义上层场景状态。
2. 用安全距离、速度与车道占用定义中层评估指标。
3. 用行为节点和状态转移表定义下层动作状态机。
4. 用 `PreScan + Simulink` 承载决策与车辆执行仿真。

### 机器可处理承载方式

原文直接给出的承载方式包括：

1. 三层 `FSM` 模型。
2. 能效函数与权重矩阵。
3. 状态转移表和状态转移矩阵。
4. `PreScan` 仿真交通场景。
5. `MATLAB/Simulink` 决策与动力学模块。

### 交换与互操作

互操作重点在：

1. 感知模块输出周车位置、速度和占用信息。
2. 上层状态机把感知数据压成离散场景类别。
3. 中层根据场景和指标算出最优行为评估结果。
4. 下层把评估结果转成明确动作，再交给车辆动力学模块执行。

## 配套基础设施

- 建模/编辑工具：`PreScan`、`MATLAB/Simulink`。
- 解析/交换/元模型支持：无独立交换标准，主要依赖仿真模型和状态转移矩阵。
- 仿真/执行支持：完整的三车道、300m 道路交通仿真场景和自动车动力学模型。
- 验证/分析支持：通过典型场景和不同渗透率随机车流仿真评估决策效果。
- 代码生成/转换支持：原文未给出自动代码生成，重点在仿真验证。
- 标准化或社区生态：偏研究型实现，没有形成通用工具链标准。

## 适用场景与需求前提

### 适用场景

适合结构化多车道道路上的行为决策、直道跟驰与变道辅助、自动驾驶决策原型验证。

### 需求前提

1. 周围车辆分布、相对速度和相对距离可被稳定感知。
2. 行为集合可抽象为少量离散动作。
3. 决策问题允许通过多指标加权评分近似求解。
4. 下层已有动力学控制或轨迹执行模块承接动作输出。

### 不适用或高成本场景

如果场景是交叉口、混行交通、博弈性极强的复杂驾驶情形，单靠本文的三层 `FSM` 和固定权重会显得不足；如果需要严格的最优控制或安全证明，这一框架也不够。

## 与相邻形式主义的关系

相对单层驾驶行为状态机，它显式拆出“场景判断”和“候选行为评估”两层；相对纯 `MPC` 或轨迹规划器，它更偏离散行为选择；相对规则库，它又更结构化，因为所有规则都被压进状态转移和能效函数中。

## 与本研究的关系

### 对 Project 1 的价值

这篇条目证明了一件很关键的事：应用型状态机完全可以按抽象层分块生成，而不是把所有判断都塞进一张扁平图里。

### 作为目标形式主义还是中间表示

它更适合作为自动驾驶行为层的目标决策骨架，也可作为更底层轨迹控制之前的中间表示。

### 对需求到模型生成的启发

1. 需求文本中的“场景分类”“评价准则”“执行动作”适合被分配到不同状态机层。
2. 生成状态机时，除了状态转移，还要同步生成评分函数和转移矩阵。
3. 多指标需求非常适合先形成评估层状态机，再落到底层动作状态机。
