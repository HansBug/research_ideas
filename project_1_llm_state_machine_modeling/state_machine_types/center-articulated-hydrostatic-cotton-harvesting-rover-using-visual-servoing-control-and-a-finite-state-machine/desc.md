## 简报

这篇论文处理的是非常具体的农业机器人问题：**如何让液压采摘车在棉株前方不断“看见棉桃 -> 对准 -> 前后调整 -> 上下调整 -> 吸取采摘”**。作者把整个过程组织成一个 `SMACH` 状态机，核心变量不是抽象事件名，而是目标棉桃与末端执行器的三维相对位置。

- 形式主义定位：面向棉花采摘 rover 的专用视觉伺服状态机，用来协调图像获取、目标定位、车体移动、机械臂对准和采摘动作。
- 构造方式简述：每轮先回到 state 0 获取新图像，再依据 `X_b,Y_b,Z_b` 与 `X_m,Y_m,Z_m` 的关系选择前进、后退、机械臂上移、下移或采摘。
- 基础设施与场景简述：依托 `ROS`、`SMACH`、`tiny YOLOv3`、`ZED` 双目相机、液压 rover 和真空末端执行器，服务棉田中的逐株棉桃采摘。

```text
图像帧 -> YOLO/深度估计 -> 目标与末端执行器相对位置 -> 状态机决策 -> rover / manipulator / end-effector 动作
```

## 形式主义定义与核心对象

### 定义对象

论文中的关键对象包括：

1. `SMACH` 任务级状态机。
2. 状态 `state 0` 以及其后的前进、后退、机械臂上移、下移和采摘动作状态。
3. 目标棉桃三维位置 `X_b, Y_b, Z_b`。
4. 末端执行器三维位置 `X_m, Y_m, Z_m`。
5. `tiny YOLOv3` 棉桃检测结果与 `ZED` 深度估计。
6. rover 直线运动控制、机械臂逆运动学和真空采摘器。

### 核心抽象

按论文结构，可保守整理为：

$$
\mathcal{C} = (Q, q_0, O, \delta, \Psi, \mathcal{A})
$$

上式中的符号逐项解释如下：

1. `Q` 是采摘任务状态集合。
2. `q_0` 是 `state\ 0`，即获取图像并寻找棉桃的起始状态。
3. `O` 是感知输出集合，包括检测框、深度和末端执行器位置。
4. `\delta` 是状态转移函数。
5. `\Psi` 是由视觉、深度和末端执行器位置组成的观测变量集合。
6. `\mathcal{A}` 是动作集合，如前进、后退、抬臂、降臂和采摘。

论文 `Algorithm 1` 给出的核心守卫可压缩为：

$$
\delta(q, \Psi) =
\begin{cases}
\mathrm{move\_forward}, & Y_b > Y_m \\
\mathrm{move\_backward}, & Y_b < Y_m \\
\mathrm{arm\_up}, & Y_b = Y_m \land Z_m > Z_b \\
\mathrm{arm\_down}, & Y_b = Y_m \land Z_m < Z_b \\
\mathrm{pick}, & Y_b = Y_m \land Z_m = Z_b \land X_m - X_b < 37\ \mathrm{cm}
\end{cases}
$$

上式中的符号逐项解释如下：

1. `Y_b, Z_b, X_b` 是目标棉桃位置。
2. `Y_m, Z_m, X_m` 是末端执行器位置。
3. 前两行表示 rover 需要沿行向前后微调。
4. 第三、四行表示机械臂需要在垂直方向对准目标。
5. 最后一行表示当对准完成且水平距离小于 `37 cm` 时进入采摘。

论文还给出了深度计算关系：

$$
W_z = \sqrt{d_x^2 + d_y^2 + d_z^2}
$$

上式中的符号逐项解释如下：

1. `W_z` 是目标点相对左相机镜头的深度距离。
2. `d_x, d_y, d_z` 是 `ZED SDK` 给出的三维点云坐标分量。

### 一个最小例子与通俗解释

最小例子可以直接用“发现一个离机械臂稍远、且位置略高的棉桃”：

1. 系统从 `state 0` 获取当前图像。
2. `tiny YOLOv3` 检出最近棉桃，并用 `ZED` 点云得到其三维坐标。
3. 若 `Y_b > Y_m`，说明棉桃还在车体前方，状态机先让 rover 前进。
4. 当前后对齐后，如果 `Z_m < Z_b`，状态机让机械臂向上移动。
5. 当 `Y_b = Y_m` 且 `Z_m = Z_b` 后，再检查 `X_m - X_b < 37 cm` 是否成立。
6. 若成立，则进入采摘状态；完成后再回到 `state 0` 继续搜索下一颗棉桃。

通俗地说，这个模型像“看一眼就纠偏一次”的视觉伺服工头。它不是先规划一条很长的轨迹，而是每拍一张图就重新判断“车要前后挪，还是手要上下调，还是已经可以采了”。

### 运行 / 接受 / 转移语义

其运行语义可保守写成：

$$
(q_t, o_t) \xrightarrow{\mathrm{vision}} \Psi_t \xrightarrow{\delta} (q_{t+1}, a_t)
$$

上式中的符号逐项解释如下：

1. `q_t` 是当前状态。
2. `o_t` 是当前图像与深度观测。
3. `\Psi_t` 是算法计算出的目标与末端执行器相对位置。
4. `\delta` 是按 `Algorithm 1` 决定动作的转移逻辑。
5. `q_{t+1}` 是下一状态。
6. `a_t` 是对应动作输出。

由于每个动作完成后会重新回到 `state 0` 获取新图像，因此它的执行模式本质上是一个感知闭环：

$$
q_0 \to q_i \to q_0
$$

其中 `q_i` 可以是前进、后退、抬臂、降臂或采摘状态。

### 语义边界

这个模型的边界包括：

1. 它针对棉花采摘这类“发现最近目标并逐步对准”的任务，不是通用农机行为语言。
2. 状态切换高度依赖 `YOLO + 深度` 感知质量。
3. 机械臂和 rover 的运动都被简化为有限离散动作。
4. 复杂路径规划、遮挡处理和多目标优化不在状态机主体中展开。

### 关键性质与判定边界

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 视觉伺服状态机骨架 | `$\mathcal{C} = (Q, q_0, O, \delta, \Psi, \mathcal{A})$` | 把图像观测、状态切换和采摘动作统一起来。 |
| 关键 guard 集 | `$\delta(q, \Psi)$` 上述分段式 | 目标与末端执行器的相对位置直接决定下一动作。 |
| 深度计算 | `$W_z = \sqrt{d_x^2 + d_y^2 + d_z^2}$` | 双目点云给状态机提供可操作的三维距离信息。 |
| 感知闭环执行 | `$q_0 \to q_i \to q_0$` | 每做完一次微调都重新感知，避免一次性开环采摘。 |

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|
| 状态 / 模式 | 强支持 | 获取图像、前进、后退、抬臂、降臂、采摘等模式明确。 |
| 事件 / 触发 | 强支持 | 是否检测到目标、相对位置关系和可达性条件都触发转移。 |
| 守卫 / 数据 | 强支持 | `X/Y/Z` 坐标、深度与 reachability 阈值直接进入 guard。 |

### 形式化问题与性质

1. 论文把农业采摘中“感知-定位-微调-抓取”的闭环动作压成了少量显式状态。
2. `Algorithm 1` 非常适合被视作状态机 guard 生成模板。
3. 目标与末端执行器的相对坐标关系提供了稳定的状态切换依据。
4. 实验上，系统在模拟环境中达到 `CT = 17.3 s`、`ASR = 88.88%`、`MRR = 94.44%`，田间平均 `ASR = 78.5%`、`MRR = 95%`。

## 构造方式与承载格式

### 建模入口

建模入口主要包括：

1. 先确定感知主循环，即每次动作前重新获取图像。

3. 用视觉与深度结果计算目标与末端执行器的相对位置。
4. 用 reachability 条件决定何时从对准切到采摘。

4. 采摘完成后末端执行器与真空系统回到下一轮感知。

## 适用场景与需求前提

### 适用场景

适合果实/棉桃等目标可视觉检测、并且采摘动作可通过有限次“前后 + 上下 + 抓取”微调完成的农业采摘场景。

### 需求前提

1. 目标物可被视觉模型稳定检测。
2. 目标与末端执行器相对位置可被估计。
3. 机械臂和 rover 的动作可以被离散成少量原子运动。
4. 感知刷新频率足以支撑闭环微调。

### 不适用或高成本场景

若目标遮挡严重、可达性受复杂枝叶结构影响，或者采摘动作需要连续复杂轨迹优化，这种有限状态闭环会很快变得不够用。

## 与相邻形式主义的关系

相对一般移动机器人任务流，它更贴近视觉伺服；相对纯行为树，它的每条边都直接绑定几何条件；相对连续控制器，它保留了显式任务阶段和可解释的 guard。

## 与本研究的关系

### 对 Project 1 的价值

它给出了一个非常清晰的例子：需求中的“当目标在前方就前进、同高后再采摘”可以直接转成状态机条件，而不需要抽象到很复杂的规划模型。

### 作为目标形式主义还是中间表示

对农业采摘系统而言，它可以直接作为目标执行载体；对更复杂的农机系统，它也可作为采摘子任务的中间监督层。

### 对需求到模型生成的启发

1. 视觉任务里的空间关系词很适合直接映射为 guard。
2. 图像获取状态往往应该被保留为显式状态，而不是默认隐含。
3. 多模态变量如检测框、深度、可达性阈值，应进入状态机变量集。
4. 应用型状态机的关键质量在于 guard 是否对应真实感知量，而不是状态数多少。

### 现实限制

模型对视觉感知质量和机械臂标定很敏感，跨品种、跨光照、跨设备迁移时需要重新调参和重训检测器。

## 重要的相关工作

- `SMACH`：本文显式采用其作为任务级状态机框架。
- `tiny YOLOv3` 与 `ZED-YOLO`：提供棉桃目标检测与深度映射入口。
