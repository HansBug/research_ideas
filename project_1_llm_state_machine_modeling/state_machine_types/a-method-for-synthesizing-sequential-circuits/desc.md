## 简报

这篇论文的关键价值，不只是“教你怎么综合顺序电路”，而是把一类**输出依赖于当前状态与当前输入**的有限状态顺序机固定成了清晰的模型骨架。它把顺序电路从直觉化线路设计，收束成可写成 truth table、可画成 state diagram、可做等价约简的状态机对象，这正是后续 `Mealy Machine` 分支的经典蓝本。

- 形式主义定位：有限状态的输入/输出转导机，核心是“当前输入到来时立即给出输出，并切换到下一状态”。
- 构造方式简述：先给出输入组合、输出组合、当前状态与下一状态，再用 truth table 和 state diagram 固定行为。
- 基础设施与场景简述：原文依托 switching algebra、flow table 与状态约简方法，面向数字顺序电路与计算机控制逻辑综合。

```text
输入组合 + 当前状态 -> 输出组合 / 下一状态 -> truth table / state diagram -> 约简与综合
```

## 形式主义定义与核心对象

### 定义对象

论文把顺序电路抽象成具有有限输入、有限输出和有限内部状态的 switching circuit，并明确指出：

1. 当前输出由当前输入组合与当前状态唯一决定。
2. 下一状态也由当前输入组合与当前状态唯一决定。
3. 这类对象可以完全转写成 truth table，再转成 state diagram 做分析与综合。

### 核心抽象

原文给出的抽象定义可保守归一化为今天常用的 `Mealy Machine` 元组：

$$
M = (Q, \Sigma, \Gamma, \delta, \lambda, q_0)
$$

上式中的符号逐项解释如下：

1. `Q` 是有限状态集，对应论文中的 present states。
2. `\Sigma` 是输入字母表，对应论文中的 input combinations。
3. `\Gamma` 是输出字母表，对应论文中的 output combinations。
4. `\delta : Q \times \Sigma \to Q` 是下一状态函数。
5. `\lambda : Q \times \Sigma \to \Gamma` 是输出函数。
6. `q_0` 是初始状态。

这一定义与论文在第 2 节中的 truth-table 口径是一致的，原文把它写成：

$$
Q_k = Q(Q_i, X_j), \qquad Y_\ell = Y(Q_i, X_j)
$$

这里的符号逐项解释如下：

1. `Q_i` 表示当前状态。
2. `X_j` 表示当前输入组合。
3. `Q_k` 表示下一状态。
4. `Y_\ell` 表示当前输出组合。
5. `Q(\cdot,\cdot)` 与 `Y(\cdot,\cdot)` 分别是状态更新函数与输出函数。

### 一个最小例子与通俗解释

一个最小例子是“检测是否出现连续两个 `1`”。令状态集 `Q = \{q_0, q_1\}`：

1. `q_0` 表示“上一拍读到的不是 `1`”。
2. `q_1` 表示“上一拍读到的是 `1`”。
3. 当处于 `q_1` 且当前输入还是 `1` 时，输出 `alarm`；否则输出 `ok`。

可写成：

$$
\delta(q_0, 0)=q_0,\ \delta(q_0, 1)=q_1,\ \delta(q_1, 0)=q_0,\ \delta(q_1, 1)=q_1
$$

$$
\lambda(q_0, 0)=ok,\ \lambda(q_0, 1)=ok,\ \lambda(q_1, 0)=ok,\ \lambda(q_1, 1)=alarm
$$

上式中的符号逐项解释如下：

1. `0,1` 是输入符号。
2. `ok` 与 `alarm` 是输出符号。
3. 第一式描述读入后跳到哪个状态。
4. 第二式描述在当前状态和当前输入下立刻发出什么输出。

通俗地说，`Mealy Machine` 像一个“边读边回应”的门卫。它不会等切换完状态再决定说什么，而是看到当前输入的同时，就结合现在所处状态立刻给出反应。

### 运行 / 接受 / 转移语义

若输入串为 `$a_0 a_1 \cdots a_{k-1}$`，则其逐拍运行语义可以写成：

$$
q_{t+1} = \delta(q_t, a_t), \qquad y_t = \lambda(q_t, a_t)
$$

这组方程中的符号逐项解释如下：

1. `q_t` 是第 `t` 拍开始时的状态。
2. `a_t` 是第 `t` 拍输入符号。
3. `q_{t+1}` 是处理该输入后的下一状态。
4. `y_t` 是第 `t` 拍立刻产生的输出。

原文的 state diagram 正是这一语义的图形化写法：边标签记录 `input / output`，边的终点记录下一状态。

### 语义边界

与 `Moore Machine` 相比，它把输出挂在“状态-输入对”而不是“状态”上；与 `EFSM` 相比，它没有显式变量、守卫和数据更新；与 `Pushdown` 或 `Nested Word` 一类模型相比，它没有无界栈或显式层次嵌套。

### 关键性质与判定边界

原文最重要的形式化贡献之一，是把状态等价/约简问题固定下来。若记某状态在输入串 `$w$` 下产生的输出串为 `$\mathrm{out}(q,w)$`，则状态等价可写为：

$$
q \equiv q' \iff \forall w \in \Sigma^*,\ \mathrm{out}(q,w)=\mathrm{out}(q',w)
$$

其意义是：若任意输入序列都无法区分两个状态，就可以把它们合并。

论文还把这种等价关系用于电路约简：删除冗余状态后，得到与原设计实验等价、但状态数更少的模型。换句话说，它给出了 `Mealy` 分支非常经典的“语义等价 -> 状态约简”主线。

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|
| 状态 / 模式 | 强支持 | 有限 present states 是模型核心。 |
| 事件 / 触发 | 强支持 | 当前输入组合驱动输出与状态迁移。 |
| 守卫 / 数据 | 不支持 | 原始模型没有独立变量与守卫。 |
| 层次 | 不支持 | 状态空间是平坦的。 |
| 并发 / 同步 | 不支持 | 论文聚焦单机顺序电路，不直接表达并发组合。 |
| 时间约束 | 不支持 | 仅有离散步语义，没有时钟约束。 |
| 连续动态 / 随机性 | 不支持 | 纯离散、确定性。 |
| 可执行 / 可验证性 | 强支持 | 可写成 truth table、state diagram，并支持状态等价约简。 |

### 形式化问题与性质

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 下一状态函数 | `$q_{t+1}=\delta(q_t,a_t)$` | 当前状态和当前输入唯一决定下一状态。 |
| 输出函数 | `$y_t=\lambda(q_t,a_t)$` | 输出与当前状态、当前输入同时绑定。 |
| 状态等价 | `$q \equiv q' \iff \forall w,\ \mathrm{out}(q,w)=\mathrm{out}(q',w)$` | 冗余状态合并的语义基础。 |
| 约简目标 | `min |Q|` under equivalence | 保持外部行为不变地减少状态数。 |

## 构造方式与承载格式

### 建模入口

原文的建模入口是顺序电路需求的 flow table / truth table，而不是后来的图形 DSL。

### 机器可处理承载方式

论文给出的核心承载方式有两类：

1. truth table：列出当前状态、当前输入、下一状态和当前输出。
2. state diagram：边上写 `input/output`，顶点代表状态。

### 交换与互操作

原文没有统一交换标准，但它已经把行为抽象压缩到“表 + 图”两种稳定骨架，足以被后续最小化、综合和验证流程复用。

## 配套基础设施

- 建模/编辑工具：原文依赖 flow table、truth table、state diagram 与 switching algebra。
- 解析/交换/元模型支持：没有单独元模型标准，骨架是表格与状态图。
- 仿真/执行支持：可直接按表格逐拍执行。
- 验证/分析支持：支持状态等价、约简与可观测行为比较。
- 代码生成/转换支持：原文目标就是从表/图综合出顺序电路实现。
- 标准化或社区生态：后续数字电路、自动机理论和状态机教材广泛吸收了该模型。

## 适用场景与需求前提

### 适用场景

适合表达输入事件一到达就要立刻给出输出响应的控制器、协议端点或顺序电路。

### 需求前提

1. 需求可压成有限状态。
2. 输出需要依赖“当前输入 + 当前状态”的联合作用。
3. 不要求显式数据寄存器、层次、时间或无界存储。

### 不适用或高成本场景

若需求含复杂数据域、递归栈、并发同步、定时约束或连续动力学，则原始 `Mealy` 模型表达力不足。

## 与相邻形式主义的关系

相对 `Moore Machine`，它的输出更“贴近转移边”；相对 `Finite Automata`，它不仅接收/拒绝，还产生显式输出；相对 `EFSM`，它仍不带显式变量和守卫。

## 与本研究的关系

### 对 Project 1 的价值

它提供了最经典的“带输出状态机”基线，适合承接那些需要把动作发射点绑定到转移上的需求。

### 作为目标形式主义还是中间表示

更适合作为中间表示或低复杂度输出形式主义，而不是复杂控制系统的最终高保真模型。

### 对需求到模型生成的启发

它提醒我们：如果需求中的动作触发明显绑定在“状态变化边”上，`Mealy` 风格通常比 `Moore` 风格更自然。

### 现实限制

当需求包含模式层次、并发状态或定时约束时，需要进一步提升到 `Statechart`、`Timed Automata` 等更强家族。
