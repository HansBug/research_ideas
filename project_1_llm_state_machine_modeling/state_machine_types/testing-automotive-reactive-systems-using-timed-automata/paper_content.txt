Abstract— Model oriented testing methods are known 
relatively long time, but the right time for viable deployment is 
coming up now with the continuously growing amount of vehicle 
electronic systems. Paper proposes a new Model -Based Testing 
approach to testing of automotive electronics systems. The key 
concept is the utilization of Timed Automata for online testing of 
automotive electronic control units. System modeling, the new 
tool, a bit of necessary technology and preliminary results 
intended to identify future research goal are presented.  
 
Keywords — Model -Based, Testing, Timed; Automaton; 
Automotive; ECU  
I. INTRODUCTION  
Since the massive expansion of Electronic Fuel Injection

II. RELATED  WORK 
Timed automata are proved as very suitable for handling 
Real-Time systems  properties.  Therefore they are frequently 
used as the underlying formalism for various software tools. 
Mostly the tools deal with verification and validation. 
Overview of timed automata related tools is included in the 
paper [2]. Scope of the paper [2] i s primary to provide survey 
of timed automata variants. Utilization of timed automata in 
testing tools is not so widespread as for mentioned verification 
and validation.  Closely related to presented work are tools 
CoVer [3] and TRON [4]. Both belong to UP PAAL family. 
Common feature is employment of UPPAAL model checking 
engine verifyta for test generation. CoVer introduces the 
interesting solution for coverage criteria description named 
Observer Automata. Test generation is done offline in opposite 
the TRO N tool which uses online approach. Presented 
approach is inspired previously mentioned works, but with the 
bigger focus on testing itself. Research in meaningful test 
selection criteria and test control algorithms suitable for 
targeted area is the main obj ective.  
III. TIMED AUTOMATON  
Theory of timed automata was originally published by 
Alur and Dill [5]. The term timed automata usually means 
slightly modified version called Timed Safety Automata [6] 
which uses local invariant conditions to ensure automaton 
progr ess. Informally, the timed automaton is an oriented graph 
which contains states and transitions. One of the states is 
called initial. Transitions are labeled by guards which enable 
relevant transition. One of the key concepts of timed automata 
theory is pa rallel composition of individual automatons to the 
network of timed automata. The theoretical background for 
this operation provides parallel composition operator know 
from communicating sequential processes (CSP).

IV. TESTING CONCEPT  
Testing process utilizing presented tool Taster is based on 
following scheme. Fundamentally, it is Online Model -Based 
Testing (MBT) using Hardware -in-the-Loop method. Tested 
system and its environment are modelled by timed automata 
network in UPPAAL tool. Developed model is afterwards 
loaded by Taster. The oracle function is provided directly by a 
SUT model. Test is driven by environment model , and its 
exploration produces testing stimuli. Connection to tested 
hardware is provided by adapter between our tool and NI 
VeriStand. Described workflow is depicted in the Fig. 1.

V. SYSTEM DESCRIPTION  
As mentioned in previous sections, SUT and its 
environment are described by timed safely automata using 
UPPAAL tool editor. On tested system class, original modeling 
capabilities were restricted to reasonable subset. Sup ported 
data types are bool, int, clock  and synchronization type chan . 
Edges can contain guard , sync and update  expressions.  
Besides time automata modelling language implemented by UPPAAL tool, Taster additionally utilizes labeling of timed 
automata states  by relevance . Relevance  is natural number 
assigned to an automaton state. This parameter is used to 
distinguish the parts of a SUT with different criticality and thus 
influences the model exploration. Example of timed automaton 
with assigned relevance num ber is in the Fig.  5. 
VI. TASTER  
Presented concept is implemented in testing software tool 
called Taster. The tool provides platform for implementation 
and evaluation of proposed research ideas. First version of this 
tool was implemented by [9]. Software archi tecture can be 
divided into two parts and is depicted in Fig.  2. First part – the 
model analyzer provides lexical and syntactical analysis, parses 
the input model from UPPAAL 4 format and stores it in object 
model suitable for online exploration. Second pa rt is 
responsible for testing itself. It performs model execution, 
serves stimuli by controlling SUT inputs and observes 
responses by reading SUT outputs. Individual test case is 
recorded by trace logger enables further analysis or replay 
function.

In a nutshell, Taster offers following features. System 
model viewer enables inspection of loaded model. Test adaptor 
is providing the connection with SUT. The adaptor connects 
Taster to National I nstrument VeriStand Real -Time testing 
software. System testing is possible using three different 
exploration strategies. The random strategy is suitable for black 
box testing of systems without any additional knowledge about 
SUT. Systematic strategy approx imates conformance testing. 
Moreover, finally, algorithm labeled experimental uses 
relevance information described in section V. States with 
higher relevance number are favorited against lower relevant 
states or states without relevance assigned. A test ru n is 
terminated in one of the following ways. Invariant condition is 
violated, test is terminated by user, or a selected coverage 
criterion is fulfilled.  Printscreen of runtime windows is

VII. TESTING TECHNOLOGY /TECHNIC AL DETAILS  
This paragraph list s the  most important technical or 
implementation details of presented MBT testing solution. 
Reader interested in deployment of MBT method to real word 
problems might find these hints helpful. Taster tool is 
developed in C# usi ng .NET technology. Syntactical analyzer 
is generated by language recognition software ANTLR. 
Expression evaluation necessary for model execution is solved 
by Shunting -yard algorithm [ 10]. System models , as well as t he 
test run traces , are stored in XML -formatted  file. Hardware -in-
the-Loop testing method is realized on National Instrument 
platform with NI VeriStand software environment. Taster is 
connected to that platform by  .NET API  provided by National 
Instruments . 
VIII. KESSY  SYSTEM TESTING  
Following example shows application of presented concept 
on testing of a keyless access system. As the name suggest, 
purpose of keyless access system is to allow vehicle entry and 
engine start without using a key (only key RFID tag have to be 
detected). The example system f unction (textual specification) 
is captured by this description. Door locking system is 
controlled by lock button built in the driver side door handle. 
Engine operation is controlled by start/stop button. Ability to 
lock and unlock the door, as well as  start or stop the engine, is 
determined by detected key position. System contains two 
equal keys RFID tags marked Key 1 and Key 2. System 
recognizes following states of each key: detected outside the 
car, detected inside the car and not detected. The door 
unlocking is not possible, if no key is detected outside the car. 
The door locking is not allowed if a key is detected inside the 
car. The engine start requires a key to be detected inside a car.  
Conversion of textual specification into timed automata 
model r esults into following. According to the paper format, it 
is not possible to include complete model and thus only the 
most important parts are depicted.  
The SUT and its environment are modelled by individual 
automata. The environment is covered by start bu tton (Fig. 4), 
door lock button (Fig. 5) and key position. These models are 
compromise between fully permissive model and fully 
restrictive model. It simulates meaningful  buttons operations, but not meaningful behavior of imaginary driver. Also idling, 
which is very natural for system like this, is modeled.

IX. RESEARCH PROPOSAL  
Development of new MBT testing tool itself is not major 
objective. Instead, the Taster should provide a platform for 
experimental evaluation of our resea rch ideas. Some of them 
are outlined in this section. Demands on testing quality are 
growing with increasing electronics systems complexity. 
Therefore, this research is focused on specialized Model -
Based testing methods suitable for automotive integration 
testing process.  

--- Page 4 ---
 
Figure 6.  Engine State Observer  
These methods are not intended to substitute currently 
used methods required by various road regulations, but to 
offer attractive way how to decrease number of unrevealed 
problems in a SUT.  
First idea already proposed in this paper is to extend timed 
automata models by relevance  numbers. This number 
indicates criticality of the SUT parts. It can be used to state 
space exploration optimization. Relevance  origin is considered 
in expert knowledge. It can be inscribed by model developer 
based on SUT knowledge or machine extracted from test 
results database. Automatic relevance  extraction is topic  of 
future research.  
Situation covered in test suites are predominantly  designed 
from driver's point of view (i.e. are use case oriented). 
Uncommon system usage is frequently not covered by test 
suite at all. Hypothesis is that generation of unconventional 
test step sequences might reveal some extra bugs. 
Unconventional does not mean random; it means situation s 
not conforming to a typical system use case diagram. 
Objective is generation of test runs simulating anomalous 
driver behavior (e.g. remarkable quick or slow interact with a 
system).  
One of the test objectives in targeted area (integration 
testing of au tomotive electronics) is to investigate, if individual 
parts of the SUT are able to work together in synergy without 
any undesirable interference. Similarly to idea with imitating 
unusual car -driver interaction, hidden relation between parts of 
distributed  systems could be attractive test objective.  Black 
box, as well as grey box approach, is being considered for this 
problem.  
X. CONCLUSION  
New Model -Based solution including software 
implementation for testing of automotive electronics systems 
was proposed. T argeted application is testing of comfort part of 
vehicle electronics systems, such as door locking, 
exterior/interior lighting, and air condition. However, the application is not limited to automotive comfort systems or the 
vehicles itself. As a result, n ew software tool Taster 
implementing the method was pr esented . The suggested 
method utilizes well known timed automata formalism as 
system description language. The model has dual purpose. At 
first, provides the function of test oracle (defines SUT correct  
behavior). Environment model and its exploration generate test 
stimuli.  Testing using Hardware -in-the-Loop principle is 
realized by connection to the National Instrument hardware 
platform by the NI VeriStand software environment. 
Furthermore, Taster tool creates the platform for future 
research in the domain of automotive integration testing. 
Opportunity to examine Taster on genuine new vehicle systems 
came from cooperation with our industrial partner Škoda 
Auto  a. s.
