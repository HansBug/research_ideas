## 简报

Murata 这篇经典教程把 Petri 网作为“并发、异步、分布式、并行、非确定”系统的图形化与数学化统一工具来系统总结。它最重要的贡献不是提出新语法，而是把库所、变迁、token、marking、行为/结构性质、分析方法、子类和扩展放在同一张图谱中讲清楚。

- 形式主义定位：面向并发过程与资源流的网模型。
- 构造方式简述：places、transitions、arcs、tokens、marking 构成基本骨架。
- 基础设施与场景简述：原文系统梳理可达性、结构性质、子类、随机网、高层网等，是后续标准化和工具化的重要理论入口。

```text
并发/资源流需求 -> 库所-变迁网络 -> marking 演化 -> 可达性/活性/有界性分析
```

## 形式主义定义与核心对象

### 定义对象

Petri 网描述的是条件、资源、事件发生和 token 流动之间的关系，因此其主客体不是单一控制模式，而是并发过程和资源约束。

### 核心抽象

文中给出的基础定义可写为：

$$
N = (P, T, A, W, M_0)
$$

上式中的符号逐项解释如下：

1. `P` 是库所集合。
2. `T` 是变迁集合。
3. `A` 是弧集合。
4. `W` 是弧权函数。
5. `M_0` 是初始标识。
6. `M` 是一般 marking，也就是每个库所中的 token 分布。

### 一个最小例子与通俗解释

一个最小例子是“一个缓冲区里只有一个资源”的系统。`idle` 库所有一个 token 表示资源空闲，`use` 变迁把 token 移到 `busy`，`release` 再把 token 从 `busy` 放回 `idle`。

通俗解释是：`Petri Net` 不像普通状态机那样只盯着“我现在在哪个状态”，而是盯着“哪些地方手里有 token”。token 像筹码，谁拿到筹码谁就有资格继续发生，这使它特别适合表达并发和资源竞争。

### 运行 / 接受 / 转移语义

把 marking 看成向量：

$$
M : P \to \mathbb{N}
$$

则变迁 `t \in T` 在 marking `M` 下可激发，当且仅当：

$$
\forall p \in P,\ M(p) \geq Pre(p,t)
$$

记作：

$$
M[t\rangle
$$

一旦 `t` 发生，新的 marking 为：

$$
M' = M - Pre(\cdot,t) + Post(\cdot,t)
$$

记作：

$$
M[t\rangle M'
$$

于是可达标识集写成：

$$
R(N, M_0) = \{ M \mid M_0 [\sigma \rangle M \text{ for some firing sequence } \sigma \in T^* \}
$$

这条 token-game 语义就是 Petri 网全部分析能力的基础。

这些语义公式中的符号逐项解释如下：

1. `M : P \to \mathbb{N}` 表示 marking 是从库所到非负整数的映射。
2. `Pre(p,t)`、`Post(p,t)` 分别表示变迁 `t` 对库所 `p` 的输入权和输出权。
3. `M[t\rangle` 表示变迁 `t` 在 marking `M` 下使能。
4. `M[t\rangle M'` 表示 firing 后从 `M` 走到 `M'`。
5. `R(N,M_0)` 是从初始标识 `M_0` 出发的可达标识集。
6. `\sigma \in T^*` 是由若干变迁组成的 firing 序列。

### 语义边界

它天然强于平坦状态机的并发表示，但不以层次 UI 模式或对象化接口为核心。若需要复杂数据或时间，通常要进入高层网、着色网或时间网扩展。

### 关键性质与判定边界

Murata 教程最核心的性质整理就是围绕 marking 和 firing sequence 展开：

$$
\text{Reach}(N, M):\ M \in R(N, M_0)\ ?
$$

$$
\text{Bounded}(N):\ \exists k,\ \forall M \in R(N, M_0),\ \forall p \in P,\ M(p) \leq k
$$

$$
\text{Live}(N):\ \forall t \in T,\ \forall M \in R(N, M_0),\ \exists M' \in R(N, M),\ M'[t\rangle
$$

$$
\text{Deadlock}(M):\ \neg \exists t \in T,\ M[t\rangle
$$

这些性质的意义在于：Petri 网把“并发正确性”转换成对可达 marking 图和结构不变量的分析，而不是对单线程控制路径的分析。

这里的性质公式符号逐项解释如下：

1. `\text{Reach}`、`\text{Bounded}`、`\text{Live}`、`\text{Deadlock}` 是四类典型分析问题名。
2. `k` 是有界性分析里的统一上界。
3. `M' \in R(N,M)` 表示从 `M` 继续 firing 还能到达的某个标识。
4. `\neg` 表示逻辑否定。

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|
| 状态 / 模式 | 部分支持 | 用 marking 而不是单一模式状态表达系统状态。 |
| 事件 / 触发 | 支持 | 变迁触发 token 迁移。 |
| 守卫 / 数据 | 部分支持 | 基础 P/T 网弱，扩展网更强。 |
| 层次 | 部分支持 | 基础模型不强调层次，扩展可支持。 |
| 并发 / 同步 | 强支持 | 是 Petri 网最核心优势。 |
| 时间约束 | 不直接支持 | 基础 P/T 网无显式时间。 |
| 连续动态 / 随机性 | 部分支持 | 基础模型无连续，但论文讨论 stochastic nets 扩展。 |
| 可执行 / 可验证性 | 强支持 | 可达性、活性、有界性、结构分析成熟。 |

### 形式化问题与性质

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 使能条件 | `$\forall p,\ M(p)\geq Pre(p,t)$` | 变迁何时可发生。 |
| firing 语义 | `$M[t\rangle M' \iff M' = M-Pre(\cdot,t)+Post(\cdot,t)$` | token game 的核心更新规则。 |
| 可达集 | `$R(N,M_0)$` | 所有后续行为分析的基础。 |
| 有界性 | `$\exists k,\forall M\in R(N,M_0),\forall p,\ M(p)\leq k$` | 资源是否会无界增长。 |
| 活性 | `$\forall t,\forall M\in R,\exists M'\in R(N,M),\ M'[t\rangle$` | 变迁是否会永久饿死。 |

## 适用场景与需求前提

### 适用场景

适用于并发协议、工作流、资源共享、同步/异步协作和分布式过程建模。

### 需求前提

1. 需求关注资源流、同步与并发。
2. 系统状态更适合用 token 分布而非单模式表示。
3. 需要强分析能力，如有界性、活性、死锁检查。

### 不适用或高成本场景

若需求主要是层次控制模式或对象接口行为，Petri 网可能不如 Statecharts/UML 直观。

## 与相邻形式主义的关系

相对 `FSM/Statechart`，Petri 网更擅长并发和资源流；相对 `Coloured Petri Net`，它缺少高层数据抽象；相对 `Time Petri Net`，它缺少时间区间。

## 与本研究的关系

### 对 Project 1 的价值

它为并发控制需求提供了与传统状态机完全不同但非常重要的建模视角。

### 作为目标形式主义还是中间表示

适合作为特定并发/资源竞争需求的目标形式主义，也可作为并发补充视图。

### 对需求到模型生成的启发

若需求充满“资源占用/释放、同步、并发等待”语句，就不应强行压成单体状态机。

### 现实限制

对于以模式切换为主的控制逻辑，建模者需要额外适应 token 语义。
