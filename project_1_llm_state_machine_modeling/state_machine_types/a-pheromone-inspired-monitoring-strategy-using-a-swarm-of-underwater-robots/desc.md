## 简报

这篇论文的核心不是一般群体优化算法，而是把“水下机器人群如何在弱通信条件下持续巡检并同步搜索结果”压成一套很清楚的双层控制器：底层是虚拟信息素矩阵，顶层是 `Search / Visit / Report` 三态 `FSM`。机器人平时按局部或全局信息素去低密度区域搜索，达到回访周期 `t_back` 后切到最近通信节点上传 / 合并 / 下载矩阵，再回到搜索态。

- 形式主义定位：面向弱通信水下群体监测任务的协调状态机，把搜索、回站同步和目标上报统一起来。
- 构造方式简述：每台机器人维护自己的信息素矩阵 `P_i(t)`，行为由 `A(P_i(t))` 计算，节点访问时通过 `f_merge` 与网络矩阵同步。
- 基础设施与场景简述：依托海底通信节点、虚拟信息素矩阵、局部 / 全局行为律和低层 `PID` 航迹跟踪，服务海域监测、静态目标搜索、沉船 / 矿产 / 危险物巡检。

```text
AOI -> 信息素矩阵 P -> Search / Visit / Report FSM -> 节点同步 -> 继续搜索与上报
```

## 形式主义定义与核心对象

### 定义对象

论文中的关键对象包括：

1. 每个机器人维护的虚拟信息素矩阵 `P_i(t)`。
2. 通信网络维护的全局矩阵 `P_net(t)`。
3. 行为律 `A(\cdot)`。
4. 矩阵更新规则 `f_update` 和合并规则 `f_merge`。
5. 三态 `FSM`：`Search`、`Visit`、`Report`。
6. 回访周期 `t_back` 与通信节点集合。

### 核心抽象

论文直接给出了行为与矩阵更新的主方程：

$$
B_i(t) = A(P_i(t))
$$

上式中的符号逐项解释如下：

1. `B_i(t)` 是机器人 `i` 在时刻 `t` 的行为。
2. `A(\cdot)` 是信息素到行为的映射。
3. `P_i(t)` 是机器人本地维护的信息素矩阵。

$$
P_i(t+1) = \begin{cases} f_{\mathrm{merge}}(P_i(t), P_{\mathrm{net}}(t)), & \text{visiting node} \\ f_{\mathrm{update}}(B_i(t), P_i(t)), & \text{otherwise} \end{cases}
$$

上式中的符号逐项解释如下：

1. `P_i(t+1)` 是下一时刻的本地信息素矩阵。
2. `f_{\mathrm{merge}}` 是到达通信节点后的同步合并。
3. `P_{\mathrm{net}}(t)` 是通信网络维护的矩阵。
4. `f_{\mathrm{update}}` 是正常搜索时依据轨迹更新矩阵的规则。

论文还把行为律具体写成从矩阵到邻域单元的映射：

$$
f_{\mathrm{behavior}} : P \rightarrow CD
$$

上式中的符号逐项解释如下：

1. `P` 是当前信息素矩阵。
2. `CD` 是当前单元周围的候选邻域集合。
3. `f_{\mathrm{behavior}}` 给出下一步要去的邻域单元。

对局部策略，论文给出的最小信息素选择规则可写成：

$$
f_{\mathrm{behavior}}(P) = D_{i^\ast,j^\ast}, \quad p_{i^\ast,j^\ast} = \min \{ p_{i+a,j+b} \}
$$

上式中的符号逐项解释如下：

1. `D_{i^\ast,j^\ast}` 是下一步选中的单元。
2. `p_{i^\ast,j^\ast}` 是该单元的信息素密度。
3. 花括号中的项表示当前邻域内所有候选单元的信息素值。

### 一个最小例子与通俗解释

一个最小例子是单台机器人在海底目标搜索中的一次完整循环：

1. 机器人处于 `Search`，查看当前位置邻域单元的信息素密度。
2. 它优先前往低信息素、尚未被频繁访问的单元。
3. 搜索达到一个周期 `t_back` 后，进入 `Visit`，直奔最近通信节点。
4. 到达节点后进入 `Report`，上传自己最近的轨迹贡献并下载新的全局矩阵。
5. 同步完成后回到 `Search`，继续向新的低信息素区域扩展。

通俗地说，这个模型像一群“会定时回站同步地图的水下蚂蚁”：平时各自按局部信息素去没怎么搜过的区域，到了回访时刻再回通信节点把“哪里已经搜过、哪里还值得去”合并起来。

### 运行 / 接受 / 转移语义

其高层转移语义可写成：

$$
(s_t, P_i(t), \tau_t, n_t) \xrightarrow{\delta} (s_{t+1}, P_i(t+1))
$$

上式中的符号逐项解释如下：

1. `s_t` 是当前高层状态。
2. `P_i(t)` 是本地信息素矩阵。
3. `\tau_t` 是自上次通信以来的累计搜索时长。
4. `n_t` 是当前与最近通信节点的关系。
5. `s_{t+1}` 是下一状态。
6. `P_i(t+1)` 是执行更新或合并后的矩阵。

### 语义边界

这个模型的边界包括：

1. 它针对的是静态目标搜索与环境监测，不是强对抗多智能体协同。
2. 目标通信假设依赖固定 communication nodes，而不是全时直连。
3. 高层 `FSM` 只协调搜索与同步，不处理底层流体动力学控制细节。
4. 原文明确指出其生物启发式行为律并不证明收敛性。

### 关键性质与判定边界

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 行为律 | `$B_i(t) = A(P_i(t))$` | 行为直接由信息素矩阵驱动。 |
| 矩阵更新 | `$P_i(t+1) = f_{\mathrm{merge}}$ or `$f_{\mathrm{update}}$` | 到节点同步，否则本地更新。 |
| 邻域选择 | `$f_{\mathrm{behavior}}(P) = D_{i^\ast,j^\ast}$` | 机器人趋向低信息素单元。 |
| 覆盖率分析 | `$P_c = c_{\mathrm{visited}} / c_{\mathrm{total}}$` | 论文用覆盖率衡量群体监测性能。 |

### 形式化问题与性质

1. 论文清楚展示了“群体协同 + 弱通信”如何被压成一个小而稳的状态机。
2. 信息素矩阵提供了状态机的共享环境记忆，而不是直接消息广播。
3. `Search / Visit / Report` 三态适合后续抽取为可复用的协同任务模板。
4. 对 `project_1` 来说，这类条目特别适合研究“状态机 + 外部共享数据结构”的组合模式。

## 构造方式与承载格式

### 建模入口

建模入口主要包括：

1. 先把 `AOI` 映射成信息素矩阵。
2. 再定义本地 / 全局行为律如何从矩阵选邻域。
3. 用三态 `FSM` 组织搜索、回站与上报。
4. 用节点访问时的合并规则保持群体共享记忆。

### 机器可处理承载方式

原文直接给出的承载方式包括：

1. `m \times n` 信息素矩阵 `P`。
2. communication node 网络。
3. `Search / Visit / Report` 三态图。
4. `Algorithm 1` 到 `Algorithm 4` 描述的映射、更新、压缩与选邻域规则。

### 交换与互操作

互操作重点在：

1. 单机器人在本地维护 `P_i(t)`。
2. 到节点时和 `P_net(t)` 做合并。
3. 上层 `FSM` 把矩阵决策变成 waypoint 级行为。
4. 下层 `PID` 控制器负责真实平台跟踪航路点。

## 适用场景与需求前提

### 适用场景

适合大范围海域巡检、静态目标搜索、沉船 / 海底资源监测，以及通信能力受限但允许定期回站同步的机器人群。

### 需求前提

1. 任务可离散成 `AOI` 网格单元。
2. 存在可部署的通信节点或等价同步设施。
3. 目标主要是静态目标，且不需要实时全局广播。
4. 机器人能跟踪 waypoint 并定期返回通信节点。

### 不适用或高成本场景

若目标高速移动、通信节点无法部署，或任务要求强实时协同与全局一致性，这种信息素 `FSM` 会受到明显限制。

## 与相邻形式主义的关系

它不像协议自动机那样细化消息序列，也不像行为树那样依赖每周期重评估；它更像一个“以矩阵环境为共享记忆的任务状态机”。相对一般多机器人 `FSM`，它的特色是把共享信息放在外部虚拟信息素里，而不是把所有协同行为都硬编码进状态和边。

## 与本研究的关系

### 对 Project 1 的价值

它提供了一个很好的样本：状态机并不一定只看事件，也可以把外部共享矩阵作为主输入。

### 作为目标形式主义还是中间表示

对巡检群控任务来说，它可以直接作为目标形式主义；对更复杂海洋系统，它更适合作为上层任务协调器的中间表示。

### 对需求到模型生成的启发

1. “定期回站同步”这类需求适合直接转成状态。
2. 共享地图 / 信息素应作为状态机输入对象显式建模。
3. 弱通信场景下，状态机和外部记忆结构的分工很重要。
4. 应用条目也可以保留清晰的数学对象，而不必只写流程图。

### 现实限制

该模型的有效性高度依赖 `AOI` 网格化、节点部署和启发式参数设置；如果这些前提不成立，其表现会显著退化。
