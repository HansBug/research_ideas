## 简报

Harel 这篇论文是层次状态机主线的原始起点。它试图解决传统平坦状态图在复杂反应式系统上的状态爆炸问题，用 hierarchy、concurrency、communication 三个核心扩展把状态图从“玩具模型”提升为大系统行为规格语言。

- 形式主义定位：面向复杂反应式系统的层次化、并发化状态机。
- 构造方式简述：以图形状态图为主，增加 OR/AND 分解、跨层迁移、广播事件和 entry/exit 风格动作。
- 基础设施与场景简述：原文强调与计算机图形结合后的可管理性，适合大型事件驱动系统规格说明；正式标准化与交换格式留待后续 UML/SCXML/STATEMATE 线实现。

```text
复杂反应式需求 -> 层次/并发状态图 -> 图形化状态机规范 -> 仿真/验证/设计沟通
```

## 形式主义定义与核心对象

### 定义对象

论文直接面向 reactive systems，例如电话、汽车、通信网络、操作系统、航电系统等。核心对象是“系统在事件刺激下如何在多层模式之间演化”。

### 核心抽象

与传统状态图相比，Statecharts 的三个关键扩展是：

1. 层次：用超状态/子状态压缩大规模模式结构。
2. 并发：用 AND-decomposition 表示并行区域。
3. 通信：用事件广播与条件触发协调跨区域行为。

### 语义边界

它仍然是离散事件驱动模型，但已不再是平坦 `FSM`。其主要难点不是表达力不足，而是语义细节较多，例如优先级、历史状态、跨层迁移、广播事件处理顺序，这也解释了后来 `STATEMATE`、`UML State Machine`、`SCXML` 都必须进一步做语义收束。

## 适用场景与需求前提

### 适用场景

适合大型事件驱动控制逻辑、嵌套运行模式明显、并发子控制器并存的系统规格说明。

### 需求前提

1. 需求中存在明确的状态/模式层次。
2. 事件触发是主要驱动力。
3. 系统含有并发区域或跨层模式切换。

### 不适用或高成本场景

如果系统主要难点在复杂数据操作、数值优化、连续动力学或概率行为，单纯 Statecharts 不够直接。

## 与相邻形式主义的关系

相对 `FSM`，它用层次与并发解决平坦状态爆炸。相对 `UML State Machine`，它更原始、更少对象化约束。相对 `SCXML`，它是图形源头而不是 XML 承载格式。相对 `Petri Net`，它更强调模式结构而不是资源流。

## 与本研究的关系

### 对 Project 1 的价值

它是复杂控制逻辑从平坦状态机向工程可用模型升级的关键节点。

### 作为目标形式主义还是中间表示

可以作为目标形式主义候选，但若要落地到机器处理和互操作，通常还要再映射到 `UML` 或 `SCXML` 一类载体。

### 对需求到模型生成的启发

当需求里天然存在“主模式/子模式/并发子系统”时，直接生成层次状态机比平坦 `FSM` 更自然。

### 现实限制

原始语义仍有歧义空间，后续生成和验证通常需要选择更收束的语义子集。
