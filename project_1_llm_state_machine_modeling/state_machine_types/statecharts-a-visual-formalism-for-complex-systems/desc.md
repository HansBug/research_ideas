## 简报

Harel 这篇论文是层次状态机主线的原始起点。它试图解决传统平坦状态图在复杂反应式系统上的状态爆炸问题，用 hierarchy、concurrency、communication 三个核心扩展把状态图从“玩具模型”提升为大系统行为规格语言。

- 形式主义定位：面向复杂反应式系统的层次化、并发化状态机。
- 构造方式简述：以图形状态图为主，增加 OR/AND 分解、跨层迁移、广播事件和 entry/exit 风格动作。
- 基础设施与场景简述：原文强调与计算机图形结合后的可管理性，适合大型事件驱动系统规格说明；正式标准化与交换格式留待后续 UML/SCXML/STATEMATE 线实现。

```text
复杂反应式需求 -> 层次/并发状态图 -> 图形化状态机规范 -> 仿真/验证/设计沟通
```

## 形式主义定义与核心对象

### 定义对象

论文直接面向 reactive systems，例如电话、汽车、通信网络、操作系统、航电系统等。核心对象是“系统在事件刺激下如何在多层模式之间演化”。

### 核心抽象

与传统状态图相比，Statecharts 的三个关键扩展是：

1. 层次：用超状态/子状态压缩大规模模式结构。
2. 并发：用 AND-decomposition 表示并行区域。
3. 通信：用事件广播与条件触发协调跨区域行为。

为了便于后续分析，可以把原论文中的图形对象保守压成：

$$
SC = (S, \rho, E, T, s_0)
$$

上式中的符号逐项解释如下：

1. `S` 是状态集合。
2. `\rho` 记录状态分解关系，并区分 OR-state、AND-state 与 basic state。
3. `E` 是事件集合。
4. `T` 是带事件、条件和动作的迁移集合。
5. `s_0` 是初始激活结构。

### 一个最小例子与通俗解释

一个最小例子可以是“微波炉”。顶层有 `Idle` 和 `Working` 两种模式；`Working` 内又分成 `Heating` 与 `Paused`；同时还可以并行跟踪“门是否关闭”和“计时器是否在走”。

通俗解释是：`Statecharts` 像把普通状态机装进文件夹和分屏里。普通 `FSM` 只能平铺地写状态；`Statecharts` 可以说“这个大状态里面还有子状态”，也可以说“这几个子区域同时在活动”，所以特别适合复杂控制逻辑。

### 运行 / 接受 / 转移语义

Statecharts 不是单活动状态模型，而是“活动配置”模型。可把一个运行时配置写成：

$$
C \subseteq S
$$

并要求 `C` 满足合法配置条件：

$$
C \in \mathrm{Conf}(SC)
$$

这里的 `\mathrm{Conf}(SC)` 至少满足三条约束：

1. 若 `s \in C`，则其所有祖先状态也在 `C` 中。
2. 若 `s` 是 OR-state 且 `s \in C`，则 `C` 中恰有一个 `s` 的直接子状态处于活动。
3. 若 `s` 是 AND-state 且 `s \in C`，则 `C` 中包含 `s` 的所有并发子区域的活动子状态。

在事件 `e` 到达时，语义核心可保守压成：

$$
(C, e) \xrightarrow{SC} C'
$$

其中 `C'` 由被选中的 enabled transition 集的 exit / action / entry 效果共同决定。由于原论文强调广播事件，某个迁移产生的事件还可能在同一步或后续步骤中继续触发其他区域的转移。

这些语义公式中的符号逐项解释如下：

1. `C` 是当前活动配置，也就是当前所有活动状态组成的集合。
2. `\mathrm{Conf}(SC)` 是 `SC` 的合法配置集合。
3. `e` 是当前处理的事件。
4. `C'` 是处理事件后的新配置。
5. `\xrightarrow{SC}` 表示按照 Statecharts 语义执行一次配置更新。

### 语义边界

它仍然是离散事件驱动模型，但已不再是平坦 `FSM`。其主要难点不是表达力不足，而是语义细节较多，例如优先级、历史状态、跨层迁移、广播事件处理顺序，这也解释了后来 `STATEMATE`、`UML State Machine`、`SCXML` 都必须进一步做语义收束。

### 关键性质与判定边界

原论文最重要的“性质”不是某条单独复杂度定理，而是它把复杂控制逻辑压缩进层次和并发结构中。若给定某个具体语义收束策略 `\sigma`，则可以讨论其扁平化语义：

$$
\mathrm{Traces}_{\sigma}(SC) = \mathrm{Traces}(\mathrm{flatten}_{\sigma}(SC))
$$

但这里的关键边界是：`flatten` 和 `trace` 只有在优先级、历史、跨层迁移、广播调度等语义细节固定后才有明确含义。也就是说：

$$
\mathrm{Sem}(SC) = \mathrm{Sem}_{\sigma}(SC)
$$

这里的 `\sigma` 不是可省略实现细节，而是语义定义的一部分；这也是后来大量 `Statecharts` 形式化和模型检查论文存在的根本原因。

这里的性质公式符号逐项解释如下：

1. `\sigma` 表示某个具体的语义收束策略，例如优先级、广播和历史状态的处理方式。
2. `\mathrm{flatten}_{\sigma}(SC)` 表示在语义 `\sigma` 下把层次结构压平成可分析模型。
3. `\mathrm{Traces}_{\sigma}(SC)` 表示在语义 `\sigma` 下观察到的行为序列。
4. `\mathrm{Sem}_{\sigma}(SC)` 表示在语义 `\sigma` 下对 `SC` 的完整语义解释。

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|
| 状态 / 模式 | 支持 | 以显式模式和嵌套状态为核心。 |
| 事件 / 触发 | 支持 | 事件驱动迁移。 |
| 守卫 / 数据 | 部分支持 | 可附加条件和动作，但不是数据重型模型。 |
| 层次 | 强支持 | 超状态/子状态是核心创新。 |
| 并发 / 同步 | 强支持 | AND 状态允许并发区域。 |
| 时间约束 | 不直接支持 | 原文核心不在显式时钟语义。 |
| 连续动态 / 随机性 | 不支持 | 纯离散反应式。 |
| 可执行 / 可验证性 | 部分支持 | 原文强调可仿真和可管理性，验证语义需后续工作细化。 |

### 形式化问题与性质

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 活动配置 | `$C \in \mathrm{Conf}(SC)$` | 运行时状态是层次+并发活动集，而非单点状态。 |
| 事件驱动迁移 | `$(C,e)\xrightarrow{SC} C'$` | 事件到来后更新整组活动状态。 |
| 层次压缩 | `$\mathrm{flatten}_{\sigma}(SC)$` | 需要在确定语义策略后才能扁平化分析。 |
| 语义依赖 | `$\mathrm{Sem}(SC)=\mathrm{Sem}_{\sigma}(SC)$` | 原始 Statecharts 需要先固定优先级和广播等策略。 |
| 并发配置 | `$\forall s \in C,\ s \text{ 为 AND-state } \Rightarrow children(s) \subseteq C$` | 并发区是配置语义的一部分。 |

## 适用场景与需求前提

### 适用场景

适合大型事件驱动控制逻辑、嵌套运行模式明显、并发子控制器并存的系统规格说明。

### 需求前提

1. 需求中存在明确的状态/模式层次。
2. 事件触发是主要驱动力。
3. 系统含有并发区域或跨层模式切换。

### 不适用或高成本场景

如果系统主要难点在复杂数据操作、数值优化、连续动力学或概率行为，单纯 Statecharts 不够直接。

## 与相邻形式主义的关系

相对 `FSM`，它用层次与并发解决平坦状态爆炸。相对 `UML State Machine`，它更原始、更少对象化约束。相对 `SCXML`，它是图形源头而不是 XML 承载格式。相对 `Petri Net`，它更强调模式结构而不是资源流。

## 与本研究的关系

### 对 Project 1 的价值

它是复杂控制逻辑从平坦状态机向工程可用模型升级的关键节点。

### 作为目标形式主义还是中间表示

可以作为目标形式主义候选，但若要落地到机器处理和互操作，通常还要再映射到 `UML` 或 `SCXML` 一类载体。

### 对需求到模型生成的启发

当需求里天然存在“主模式/子模式/并发子系统”时，直接生成层次状态机比平坦 `FSM` 更自然。

### 现实限制

原始语义仍有歧义空间，后续生成和验证通常需要选择更收束的语义子集。
