## 简报

这篇技术报告把混成自动机作为“离散控制器 + 连续物理过程”统一模型来系统总结，明确了变量、控制图、初始化/不变式/流条件、跳转条件以及 transition semantics。它的价值在于把 `Timed Automata` 进一步推广到一般流条件与 jump condition，并讨论可分析的子类和语义组合。

- 形式主义定位：面向 CPS/物理控制系统的离散-连续混成状态机。
- 构造方式简述：控制模式图 + 连续变量 + init/inv/flow/jump 条件。
- 基础设施与场景简述：原文重点是理论语义、轨迹与组合，不提供工业文件标准；后续验证工具线围绕可判定子类展开。

```text
控制器模式 + 连续物理变量 -> 混成自动机 -> 轨迹/可达性/子类分析
```

## 形式主义定义与核心对象

### 定义对象

混成自动机直接面向包含连续物理演化和离散控制切换的 dynamical system。

### 核心抽象

原文 Definition 1.1 给出的关键对象包括：

$$
H = (X, V, E, init, inv, flow, jump, \Sigma)
$$

其中 `X` 是实值变量，`V` 是控制模式，`E` 是控制切换，`init`/`inv`/`flow`/`jump` 分别定义初始条件、不变式、流条件和跳转条件。

### 语义边界

相对 `Timed Automata`，它允许一般连续变量流而非单位速率时钟；因此表达力更强，但可判定性更弱，分析通常必须退回到特定子类。

## 适用场景与需求前提

### 适用场景

适用于控制器驱动物理对象、既有离散模式切换又有连续变量演化的系统，例如温控器、门控装置、嵌入式控制系统。

### 需求前提

1. 需求需要同时描述离散模式和连续状态。
2. 连续行为可由 flow condition 抽象。
3. 允许为可分析性选择特定混成子类。

### 不适用或高成本场景

如果系统只是纯离散实时逻辑，`Timed Automata` 更经济；若需要标准交换格式，混成自动机原始文献不提供载体。

## 与相邻形式主义的关系

相对 `Timed Automata`，它把时钟流扩展为一般连续流；相对 `Petri Nets`，它更强调模式切换与连续微分约束；相对 `TIOA`，它的重点不是接口组合，而是混成语义本身。

## 与本研究的关系

### 对 Project 1 的价值

当目标需求涉及环境物理量、连续阈值和控制回路时，它给出了最直接的形式主义上界。

### 作为目标形式主义还是中间表示

更适合作为高端目标形式主义或后续扩展目标，而不是默认主线输出。

### 对需求到模型生成的启发

需求分析时必须明确哪些变量是“离散模式”，哪些是“连续物理量”，否则难以正确选择是否进入混成建模。

### 现实限制

表达力强带来的代价是验证复杂度和工具门槛都更高。
