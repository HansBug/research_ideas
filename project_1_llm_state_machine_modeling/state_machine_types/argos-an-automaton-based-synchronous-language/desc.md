## 简报

`Argos` 的关键判断是：想保留 `Statecharts` 的层次和图形直觉，但又想拥有 `Esterel` 式“完全同步、可组合、可编译”的语义，就必须主动砍掉 multi-level arrows，把复杂控制流改写成自动机之间通过局部信号即时广播来协同。于是，`Argos` 不是一般意义上的图形状态图编辑器，而是一套“用布尔 Mealy 机做反应式控制编程”的同步语言。

- 形式主义定位：基于布尔 Mealy 机的同步反应式语言。
- 构造方式简述：基本构件是 deterministic/reactive Boolean Mealy machine，再通过 parallel、encapsulation、hierarchical refinement 等算子组合。
- 基础设施与场景简述：天然对接同步编译、中央顺序代码生成和形式验证工具，而不是开放交换标准。

```text
反应式控制需求 -> Boolean Mealy machines + local signals -> synchronous composition / refinement -> code generation / verification
```

## 形式主义定义与核心对象

### 定义对象

论文要解决的是：怎样在不引入多层箭头和含混广播语义的前提下，保留状态图的层次表达力，同时又保证同步语言需要的组合性和可编译性。

### 核心抽象

`Argos` 的基本构件就是布尔 Mealy 机：

$$
M = (S, s_0, I, O, T)
$$

上式中的符号逐项解释如下：

1. `S` 是状态集合。
2. `s_0` 是初始状态。
3. `I` 是输入信号集合。
4. `O` 是输出信号集合。
5. `T \subseteq S \times B(I) \times 2^O \times S` 是转移集合，其中 `B(I)` 表示基于输入信号的布尔条件。

论文的关键不是只给一个自动机定义，而是给一组自动机组合算子。对局部信号集合 `\Lambda` 的封装规则写成：

$$
n_\Lambda(M) = (S, s_0, I \setminus \Lambda, O \setminus \Lambda, T')
$$

其中一条转移 `(s, m, o, s')` 只有在满足以下局部同步条件时才会保留：

$$
m^+ \cap \Lambda \subseteq o \land m^- \cap \Lambda \cap o = \varnothing
$$

这里：

1. `m^+` 是单项式 `m` 中要求“本轮出现”的局部信号。
2. `m^-` 是 `m` 中要求“本轮不出现”的局部信号。
3. `o` 是该反应发射的信号集合。
4. 上式保证“局部信号若被当作真输入，就必须由系统某处在同一步发射；若被当作假输入，就不能又被发射”。

### 一个最小例子与通俗解释

论文的经典例子是 3-bit counter：

1. 第一个 bit 在接收到全局输入 `a` 时翻转。
2. 溢出时它发射局部信号 `b`，驱动第二个 bit 同步翻转。
3. 第二个 bit 再可能发射另一个局部信号，驱动第三个 bit。
4. 所有 bit 在同一个同步反应中一起完成状态更新。

通俗地说，`Argos` 像“把层次状态图拆成若干自动机，再用即时广播的局部信号把它们焊在一起”。看起来像并发，但运行语义最终会被编译成一个中心化顺序反应。

### 运行 / 接受 / 转移语义

`Argos` 的语义最终落在布尔 Mealy 机上，程序语义函数可以保守写成：

$$
\mathcal{S}(P) = M \text{ or } ?
$$

上式中的符号逐项解释如下：

1. `P` 是一个 `Argos` 程序。
2. `\mathcal{S}(P)` 是其语义结果。
3. `M` 是对应的确定、反应、布尔 Mealy 机。
4. `?` 表示该程序因为封装导致的非因果或失去反应性/确定性而被判为不正确。

论文定义程序等价为：

$$
P_1 \equiv P_2 \iff \mathcal{S}(P_1) \neq ? \land \mathcal{S}(P_2) \neq ? \land \mathcal{S}(P_1) \approx \mathcal{S}(P_2)
$$

其中：

1. `\approx` 是布尔 Mealy 机上的双模拟等价。
2. 这一定义只对“正确程序”谈组合性，不强行给非因果程序赋语义。

层次 refinement 的核心思想则是：控制自动机始终活着；处于某个 refined state 时，对应子自动机与控制自动机并行协作；离开该状态会杀死当前子过程，进入新状态会启动目标子过程的初始状态。

### 语义边界

`Argos` 的边界非常明确：

1. 它面向纯同步反应，不直接表达异步消息系统。
2. 基础核心只处理纯信号布尔接口，数值变量和超时是后续扩展。
3. 它宁可判程序“不正确”，也不愿给非因果组合硬塞一个语义。

### 关键性质与判定边界

论文最重要的性质包括：

1. 语义相对布尔 Mealy 机 trace/bisimulation 是组合的。
2. parallel、encapsulation、refinement 等算子在“正确程序”子集上保持等价性。
3. 通过局部信号即时广播，可以在不使用 multi-level arrows 的前提下编码很多层次状态图行为。
4. 程序正确性与因果性检查是语言设计的一部分，而不是运行时兜底。

## 关键特性

| 维度 | 支持情况 | 说明 |
|---|---|---|
| 状态 / 模式 | 强支持 | 基本构件就是自动机状态与转移。 |
| 事件 / 触发 | 强支持 | 输入条件基于布尔信号，输出是同步广播信号集合。 |
| 守卫 / 数据 | 部分支持 | 核心语言以布尔信号为主，变量和值信号属于后续扩展。 |
| 层次 | 强支持 | refinement 把子程序挂到控制自动机状态下。 |
| 并发 / 同步 | 强支持 | parallel composition + encapsulation 是主干。 |
| 时间约束 | 部分支持 | 可用宏表示 timeout，但核心并非显式时钟语义。 |
| 连续动态 / 随机性 | 不支持 | 面向离散同步控制。 |
| 可执行 / 可验证性 | 强支持 | 直接面向同步编译、代码生成与验证工具连接。 |

### 形式化问题与性质

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 基本自动机 | `$M = (S, s_0, I, O, T)$` | `Argos` 的核心语义对象是布尔 Mealy 机。 |
| 转移集合 | `$T \subseteq S \times B(I) \times 2^O \times S$` | 一条反应由输入条件、发射信号和目标状态决定。 |
| 封装结果 | `$n_\Lambda(M) = (S, s_0, I \setminus \Lambda, O \setminus \Lambda, T')$` | 局部信号封装既限制作用域，也实施同步广播约束。 |
| 封装条件 | `$m^+ \cap \Lambda \subseteq o \land m^- \cap \Lambda \cap o = \varnothing$` | 只有满足本地信号因果一致性的转移才会保留。 |
| 程序语义 | `$\mathcal{S}(P) = M \text{ or } ?$` | 非因果或破坏反应性/确定性的程序被判为错误。 |

## 构造方式与承载格式

### 建模入口

建模入口是 `Argos` 图形自动机：

1. rounded box 表示状态。
2. 箭头表示转移。
3. 本地信号通过 encapsulation 限定作用域。
4. refined state 下面可以挂子程序。

### 机器可处理承载方式

机器可处理承载是文本/图形化的 `Argos` 程序表达式，再通过语义函数编译到布尔 Mealy 机。

### 交换与互操作

它的互操作重点不是交换标准，而是：

1. 与同步语言工具链互通。
2. 向中心化顺序代码生成。
3. 与验证工具在布尔自动机层对接。

## 配套基础设施

## 适用场景与需求前提

### 适用场景

适合实时反应式控制、同步控制器、事件广播驱动逻辑以及需要层次自动机但又想保持同步语义和可编译性的场景。

### 需求前提

1. 需求核心是离散事件/信号驱动，而不是连续变量演化。
2. 组件之间可接受即时同步广播。
3. 需要明确的局部信号作用域与层次 refinement。
4. 需要把图形行为落成可编译、可验证的同步核心。

### 不适用或高成本场景

若系统主要依赖复杂数据流、开放异步通信或跨工具标准交换，`Argos` 的收益会明显下降。

## 与相邻形式主义的关系

相对原始 `Statecharts`，它主动去掉 multi-level arrows；相对 `SyncCharts`，它更像同步语言核心而不是抢占导向图形前端；相对 `Esterel`，它保留了自动机/状态图直觉。

## 与本研究的关系

### 对 Project 1 的价值

它证明了“状态图可视化”和“同步语言可验证性”不是二选一，可以通过语义收缩同时保留。

### 作为目标形式主义还是中间表示

更适合作为同步控制子系统的目标形式主义，或生成后再翻译为中心化代码的中间桥梁。

### 对需求到模型生成的启发

如果需求里存在跨层控制中止、局部广播和同步并发，生成器可以优先考虑“局部信号 + refinement”而不是直接依赖 multi-level arrows。

### 现实限制

它的工程影响主要在研究和语言设计链条里，不像 `SCXML` 或 `Stateflow` 那样已有广泛产业载体。
