## 简报

这篇论文研究的是 `Finite Automata` 另一个非常典型的“记忆替代增强”方向：不给机器加栈，但给它**多个只读头**。这些读头都在同一条输入带上向右移动，状态控制当前该让哪一个读头继续读。Rosenberg 证明了这会显著提升语言识别能力：`MH_1` 就是 regular sets，而 `MH_n` 随 `n` 严格形成层级；同时它还给出了和 `n`-tape automata 的等价刻画，以及补集、并/交、连接等闭包边界。

- 形式主义定位：有限自动机主干上的“多读头比较”分支。
- 构造方式简述：在单带上放置 `n` 个只向右移动的读头，由状态决定当前哪一个读头继续扫描。
- 基础设施与场景简述：原文完全是理论模型，没有工程工具；它的价值在于展示“不增加写存储，只增加观察点”也能严格增强表达力。

```text
输入串 -> 多读头同步/交替扫描 -> 块比较 / 关系约束 -> MH_n 语言类
```

## 形式主义定义与核心对象

### 定义对象

`Multi-Head Finite Automata` 仍然是有限状态控制，但输入带上不止一个读头。每一步只有一个由当前状态指定的读头前进一步，直到所有读头都读到 end-marker 为止。

### 核心抽象

按原文 Definition 1，`n`-head finite automaton 可写成：

$$
A = (K, s_A, s_R, \Sigma, \$, h, M, s_0)
$$

其中：

1. `K` 是有限状态集。
2. `s_A`、`s_R` 分别是接受与拒绝状态。
3. `\Sigma` 是输入字母表。
4. `\$` 是 end-tape symbol。
5. `h : K \to \{1,\dots,n\}` 是 head-selector function，决定当前由哪个读头继续读。
6. `M` 是 next-state function。
7. `s_0` 是初始状态。

原文定义的语言类记作：

$$
\mathcal{MH}_n = \{L(A) \mid A \text{ is an } n\text{-head finite automaton}\}
$$

### 一个最小例子与通俗解释

一个典型例子是识别：

$$
\{0^n1^n0^n \mid n \ge 1\}
$$

论文用 `2` 头模型给出非上下文无关集合的构造思路：一个读头可先跳过中间块，再用另一个读头与它配合比较不同块的长度。

通俗地说，`Multi-Head FA` 像一个没有笔记本但有多双眼睛的有限状态机。它自己仍然只有有限记忆，但可以把几双眼睛放到输入不同位置，通过来回切换“当前由哪一双眼睛继续读”，完成普通单头 `FA` 做不到的远距离块比较。

### 运行 / 接受 / 转移语义

若当前状态为 `s`，则 `h(s)` 指出第几个读头执行当前一步。机器的瞬时描述由“当前状态 + 各读头在输入带上的位置”组成；每一步：

1. 被选中的读头读取当前符号。
2. 读头右移一格。
3. `M` 决定下一状态。

接受语义是：当所有读头都读过 end-marker `\$` 后，机器进入 `s_A` 则接受，进入 `s_R` 则拒绝。

### 语义边界

这个模型仍然没有栈、计数器和写存储；它的增强来自“并列多个观察点”，而不是新增无界内存。相对 `Pushdown Automata`，它擅长比较多个块的相对关系，但不天然表达深层递归嵌套。

### 关键性质与判定边界

论文最重要的三类结果是：

首先，`n`-head 单带模型与 `n`-tape 模型之间存在等价刻画：

$$
A \in \mathcal{MH}_n
\iff
\exists B \in \mathcal{D}_n \quad A = \pi_i(B \cap E_n)
$$

其中：

1. `\mathcal{D}_n` 是 deterministic `n`-tape automata 定义的关系类。
2. `E_n = \{(t_1,\dots,t_n)\mid t_1=\cdots=t_n\}` 是对角关系。
3. `\pi_i` 是某个坐标投影。

其次，类 `\mathcal{MH}_n` 严格形成层级：

$$
\mathcal{MH}_n \subsetneq \mathcal{MH}_{n+1}
$$

再次，闭包边界非常有代表性：

$$
\mathcal{MH}_n \text{ 对 complement 封闭}
$$

但对 `n>1`：

$$
\mathcal{MH}_n \text{ 不对 union 或 intersection 封闭}
$$

论文还进一步证明：存在某个 `CFL` 不属于任何 `\mathcal{MH}_n`。

## 关键特性

| 维度 | 支持情况 | 说明 |

| 状态 / 模式 | 支持 | 仍是有限状态控制。 |

| 层次 | 不支持 | 不表达嵌套层次。 |
| 并发 / 同步 | 部分支持 | 多个读头并存，但每步只有一个读头移动。 |
| 时间约束 | 不支持 | 无时钟语义。 |
| 连续动态 / 随机性 | 不支持 | 纯离散。 |
| 可执行 / 可验证性 | 强支持 | 具备精确的层级、闭包与判定边界结论。 |

### 形式化问题与性质

| 问题 / 性质 | 形式化写法 | 原文意义 |
|---|---|---|
| 模型元组 | `$A=(K,s_A,s_R,\Sigma,\$,h,M,s_0)$` | 定义多读头有限自动机骨架。 |
| 语言类 | `$\mathcal{MH}_n=\{L(A)\}$` | 固定读头数后的语言类。 |
| 带关系刻画 | `$A=\pi_i(B\cap E_n)$` | 与 `n`-tape automata 的关系化等价。 |
| 严格层级 | `$\mathcal{MH}_n \subsetneq \mathcal{MH}_{n+1}$` | 读头数增加严格增强表达力。 |
| 闭包边界 | `$\mathcal{MH}_n$` 对 complement 封闭，但对 union/intersection 非封闭 | 体现其与 regular / CFL 的差异。 |

## 构造方式与承载格式

### 建模入口

建模入口是：

1. 选定读头数 `n`。
2. 定义状态集 `K`。
3. 定义 head selector `h`。
4. 定义 next-state function `M` 和 end-marker 语义。

### 机器可处理承载方式

机器可处理承载方式是 tuple 化的 `n`-FA / `n`-DA 定义和瞬时描述序列，不依赖图形 DSL。

### 交换与互操作

原文最关键的互操作是和 `n`-tape automata` 的往返刻画，以及通过对角关系 `E_n` 把单带多头问题改写成多带关系问题。

## 适用场景与需求前提

### 适用场景

适合表达“多个远距离块需要相互比较，但系统仍想保持有限状态控制”的线性串分析任务。

### 需求前提

1. 输入对象是线性串。
2. 强化需求主要来自多位置比较，而不是递归嵌套。
3. 不允许或不希望引入无界写存储。

### 不适用或高成本场景

若需求天然是括号嵌套、调用/返回配对或一般上下文无关结构，则 `Pushdown Automata` 更自然。

## 与相邻形式主义的关系

相对 `Two-Way Finite Automata`，它增加的是观察点数量，而非读头回看能力；相对 `Pushdown Automata`，它增加的是并列比较能力，而非栈记忆；相对 `Multi-Tape Automata`，它通过 `E_n` 对角关系与其紧密相连。

## 与本研究的关系

### 对 Project 1 的价值

它补全了演化树里“read-head augmentation”这条经典分支，让 `two-way` 与 `pushdown` 之间不再缺少一个关键的中间谱系节点。

### 作为目标形式主义还是中间表示

更适合作为能力边界和理论节点，不太适合作为控制系统最终交付形式。

### 对需求到模型生成的启发

它提醒我们：有些需求看似需要无界记忆，实际上只是需要“并列比较多个输入位置”；这时多读头分支可能比栈模型更贴切。

### 现实限制

它仍然不直接支持层次、时间、并发资源流和连续动力学，因此通常只在理论选型层面有价值。
