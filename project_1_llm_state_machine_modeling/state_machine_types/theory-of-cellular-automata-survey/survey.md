## 综述范围与结论

这篇 survey 并不把 cellular automata 当成某个单一规则族，而是把它当成一整类“局部、同步、均匀、离散时空系统”来整理。原文从最基础的状态集、邻域和全局转移函数讲起，接着按研究主题分出可逆性、守恒律、内在普适性、极限集、动力系统性质、线性局部规则和语言识别七条主线，最后把若干开放问题一起固化下来。

- 覆盖范围：基础定义、邻域族、`Game of Life / Rule 110` 等典型例子、`Garden of Eden`、可逆性、守恒量、动力系统、语言识别
- 主要比较轴：维度、邻域、全局函数性质、可逆性/守恒性、动力学行为、计算能力
- 对本 collection 的直接价值：它能帮助 `project_1` 明确“局部并行更新模型”与常规事件驱动状态机的根本差异，以及什么时候应把系统理解为规则传播网络而不是状态转移图

## 分类轴与比较框架

原文的比较逻辑非常清晰：先用**维度 + 邻域**给模型定骨架，再用**可逆性/守恒性/动力学/识别能力**这些全局性质给模型分流。换言之，原文不是按“某个具体规则 110 很厉害”来组织，而是按“全局函数有哪些结构性质”来组织。

| 形式主义 / 路线 | 核心结构 | 原文关注的比较维度 | 优势 | 代价或限制 |
|---|---|---|---|---|
| 基础 synchronous `CA` | 有限状态格点 + 邻域 + 同步局部更新 | 维度、邻域、全局转移函数 | 语义统一，适合作为并行局部动力系统基线 | 对层次状态与复杂数据结构不自然 |
| reversible `CA` | 要求全局函数可逆 | injective/surjective、逆自动机、`GMN-CA` 实现 | 适合可逆计算与物理可实现性分析 | 高维可逆性判定困难，逆邻域可能很大 |
| additive / number-conserving `CA` | 局部量在全局求和下保持不变 | 守恒律、可计算的守恒量空间 | 适合物理系统与资源守恒建模 | 需要需求明确给出可守恒的局部量 |
| linear `CA` | 局部规则在线性代数结构上定义 | equicontinuity、sensitivity、transitivity 等 | 某些动力学性质可快速判定 | 只覆盖受线性约束的局部规则 |
| `CA` / `OCA` 语言识别 | 用空间受限格点识别语言 | real-time / linear-time 能力、closure | 展示 `CA` 作为识别模型的理论能力 | 与控制系统状态机建模距离较远 |

原文的核心结论可以概括成一句话：细胞自动机最重要的不是“某个具体规则”，而是**邻域和局部规则如何诱导出全局函数性质**。这也是它与普通状态图最大的本体差异。

## 构造方式与表示格式版图

| 形式主义 | 图形表示 | 文本/DSL | XML/JSON/元模型 | 标准/交换格式 | 说明 |
|---|---|---|---|---|---|
| 基础 `CA` | 网格图可视化常见 | 局部规则函数/规则表 | 否 | 无统一标准 | 典型承载是状态集、邻域向量和局部更新函数 |
| `GMN-CA` / lattice gas | 是 | 分块更新规则 | 否 | 无统一标准 | 通过块分区和时钟周期表达可逆更新 |
| linear `CA` | 可视化较弱 | 线性系数/多项式表示 | 否 | 无统一标准 | 适合数学分析，不依赖工程交换格式 |
| `CA` 语言识别模型 | 否 | 邻域 + 接受状态 + 时间界限 | 否 | 无 | 更像 formal language 定义，而不是工业建模文件 |

这篇 survey 对构造方式给出的最重要信息是：`CA` 的自然机器承载不是层次图或 transition graph，而是**格点状态空间 + 邻域 + 局部规则**。如果未来要把这类模型纳入 `project_1`，中间表示不能只保留状态和迁移，还要保留拓扑邻域与同步更新口径。

| 路线 | 建模入口 | 机器承载 | 自动生成最关键的结构化信息 | 原文体现 |
|---|---|---|---|---|
| 基础 `CA` | 状态集、邻域、局部规则 | 规则表 / 函数定义 | 邻域、同步更新、边界条件 | 这些决定了全局函数性质 |
| 可逆 / 守恒路线 | 基础 `CA` + 全局约束 | 仍是规则定义 | 可逆性或守恒量候选 | 是原文最强调的理论分支之一 |
| 语言识别路线 | 输入编码、接受状态、时间上界 | 规则 + 接受条件 | 输入映射到格点、接收口径 | 说明 `CA` 也可视作 automata-like recognizer |

## 适用场景与需求映射

| 形式主义 | 适用场景 | 需求前提 | 不适合的情况 |
|---|---|---|---|
| 基础 `CA` | 局部交互、规则传播、离散物理模拟 | 系统行为可写成统一局部邻域更新 | 需求本质是事件驱动层次控制 |
| reversible `CA` | 可逆计算、物理可实现性分析 | 需求要求信息不丢失或关注逆演化 | 只需普通 reachability/状态图建模时 |
| number-conserving / additive `CA` | 资源守恒、守恒律建模 | 需求里存在明确的可守恒量 | 需求没有局部可加结构时 |
| `CA` 语言识别 | 大规模并行识别、formal language 理论 | 输入需编码到格点并接受同步更新时间口径 | 目标是工业标准模型或可解释状态图 |

| 需求信号 | 更适合的 `CA` 路线 | 原因 |
|---|---|---|
| 系统核心是局部邻域传播 | 基础 `CA` | 状态由邻域统一更新最自然 |
| 要求守恒或物理一致性 | reversible / additive `CA` | 原文正是围绕这些性质建立理论口径 |
| 需要研究极限行为或全局动力学 | linear / dynamical `CA` | equicontinuity、sensitivity、transitivity 都有成熟理论 |

## 对本研究的启发

### 对 Project 1 目标形式主义选型的启发

`CA` 不是 `project_1` 默认首选，但若需求天然是“局部约束不断传播直到稳定”的系统，它比状态图更贴切。也就是说，它适合一类**规则驱动**而非**事件驱动**的需求对象。

### 对中间表示设计的启发

如果未来要支持 `CA` 类模型，中间表示至少要能显式表示：

1. 网格维度和邻域。
2. 同步更新口径。
3. 局部规则而非显式迁移图。
4. 可能的守恒量或可逆性约束。

### 对后续扩库方向的启发

应优先补：

1. shift dynamics 语义基线。
2. injective/surjective 判定主线。
3. additive conserved quantities 主线。

### 原文未覆盖但本研究仍需补的空白

原文几乎不提供现代标准化建模文件、DSL、XML/JSON 交换格式或稳定工具链，因此它能回答“`CA` 是什么、有哪些性质”，但回答不了“如何作为统一建模工件交付”。
