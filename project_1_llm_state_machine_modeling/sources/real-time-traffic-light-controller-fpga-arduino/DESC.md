# FPGA 与 Arduino 实时交通灯控制器 / Real-Time Traffic Light Controller System based on FPGA and Arduino

## 论文在讲什么

这篇论文的主题是一个可在 FPGA 和 Arduino 两种平台上实现的实时交通灯控制器。论文本身带有明显的工程教学与平台比较色彩，但它不是只有性能比较，而是先把控制对象、工作模式、时序参数和交通灯状态循环写清楚，再去比较两种实现平台的代价与收益。

从控制逻辑看，这个系统不是一个单纯的固定灯色循环器。它同时考虑了主路和三条侧路的灯色、侧路传感器、行人请求按钮，以及晚间或故障条件下的 blinking 模式。作者还把 `TBASE / TEXT / TYEL / TBLINK` 这些时间量明确列出来，使得控制器有了非常清楚的时序骨架。

## 控制系统在文中的位置

我们关心的交通灯控制器是这篇论文的核心案例，而不是后面硬件比较的背景板。正文先用相关工作回顾不同 FPGA/Arduino 交通灯设计，再转入自己的 TLC 设计，随后讲 `FSM / D_RAM / timer / divider / latch / sensors` 这些组成件如何一起工作。

对 `sources/` 来说，这篇论文最有价值的部分是它同时保留了“外层模式”和“内层相位循环”两层信息。`read / write / normal / blinking` 像是上层模式；进入 `normal` 后，系统再在九个灯相状态之间运行，并用交通传感器和行人按钮改变持续时间或触发 walk light。这种结构比单层灯色序列更值得保留。

## 对我们为什么有用

这篇论文对 `🚦` 领域的补充，不在于它把交通灯写得更复杂，而在于它把一个很经典的多模式交通灯 controller 写得比较规整。文库里已有不少交通灯样本，但同时显式写出模式集、九状态循环、定时参数和行人请求处理的并不算多。

如果后续要做自动建模数据集，这篇特别适合作为“多模式 timed traffic controller”的训练样本。模型不仅要学会提取灯色相位，还要学会识别什么时候是配置/读写模式，什么时候进入正常循环，什么时候由于故障或夜间条件切换到 blinking，这会比只学一个固定灯相循环更有区分度。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 1 页摘要，再直接跳到第 5-6 页。首先抓住 `L1/L0` 选择的时间参数类型，以及 `read / write / normal / blinking` 四种模式；然后看九状态控制循环、侧路拥堵时如何延长绿灯、行人按钮如何在主路黄灯后触发 walk light。

等第一轮把状态和时间链读稳之后，再回头看 FPGA 与 Arduino 的实现比较、资源和速度差异。那些信息对于工程实现当然有帮助，但如果目标是重建 `STM.md` 或抽出状态机数据样本，优先级还是低于模式层级、计时参数和传感器/行人请求逻辑。
