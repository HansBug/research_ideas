# 六灯峰谷时交通灯控制 / Design of FPGA-Based Traffic Light Controller System

## 论文在讲什么

这篇论文讨论的是一个基于 FPGA 的真实路口交通灯控制系统，目标不是做抽象的交通优化理论，而是把马来西亚某城市中两处相连路口的信号控制，改造成带 peak / off-peak 区分的可编程控制器。作者明确把 `T1-T6` 六个交通灯拆成主路与窄路两类，并围绕这些灯的持续时长、传感器输入和相位顺序展开设计。

对 `sources/` 来说，这篇稿子的价值在于它不是只给“有传感器的交通灯”一句话，而是把六灯结构、`32 / 16 / 8 / 4 / 2 s` 时序、`Sensor1 / Sensor2` 条件分支以及窄路相位跳过都写清楚了。也就是说，它不是简单的硬件板卡实现，而是一条可以直接还原成状态机描述的控制链。

## 控制系统在文中的位置

这里的控制系统描述就是论文主体。文章的 road structure、timing setting、VHDL model 和 simulation results 都服务于同一个问题：在不同交通密度与不同传感器组合下，交通灯应该按什么顺序、在什么时长内切换。换言之，交通灯状态链不是辅助示例，而是整篇论文想要构建和验证的对象。

它和库里已有一些四状态固定轮转交通灯又不完全一样。作者保留了一个更接近实际路口的两主路口 + 两窄路口结构，而且 off-peak 时的行为不再只是简单缩短时间，而会根据 `Sensor1 / Sensor2` 是否触发切换到不同的第三阶段，甚至直接跳过窄路周期。因此它更像一个带 guard 的 timed controller。

## 对我们为什么有用

这篇论文对当前文库最直接的价值，是补了 `🚦` 方向里一种比“四状态倒计时交通灯”更接近真实交叉口控制的样本。它依旧是 `T1` 级工程定时，但状态链不再只是固定循环，而是已经出现 peak/off-peak 模式、主/窄路角色差异以及由传感器条件触发的分支切换，这对后续做自然语言到 EFSM 的建模任务更有用。

它也给检索策略提供了很清楚的正例特征：如果标题和摘要里同时出现 `traffic light + peak/off-peak + sensor + FPGA/VHDL`，而正文又把 `T1-T6`、具体秒数、哪组灯在哪个周期同时放行写出来，那么这类论文很容易达到双 A。相比之下，只写“smart traffic”或“monitoring”的交通稿，通常就没有这么完整的控制链。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 `2-3` 页的 abstract 和 `II. ROAD STRUCTURE`，先把 `T1-T6` 六灯布局、主路/窄路划分以及 peak/off-peak 的基本设定读清。随后直接细读 `A. TIMING Setting`，把 `32 / 16 / 8 / 4 / 2 s` 的时间规则和 `Sensor1 / Sensor2` 触发时第三阶段如何变化整理出来。

如果目的是重做 `STM.md`，最后再看 `III. RESULTS AND DISCUSSION` 里的几种仿真波形，确认 peak、双传感器开启、单传感器开启、双传感器关闭时控制链是否一致。至于 FPGA 器件说明和工具实现细节，可以第二轮再看，它们对复原状态机不是第一优先级。
