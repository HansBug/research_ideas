# 优先车位导引与密码解锁出场 / Modelling of Smart Car Parking System Using PLC

## 论文在讲什么

这篇论文围绕停车场导引、安全保护和密码解锁出场展开，当前 `STM.md` 抽到的核心对象是“智慧停车领域的 PLC/SCADA 停车场导引与安全控制系统”。如果只抓一句话理解它的主体，可以先把它看成：这是一个带优先车位分配、运动传感器保护和密码校验出场的停车场控制器。

从现有条目看，文中的离散控制链主要以 `EFSM（扩展状态机）` 的方式出现，时间语义属于 `T1（工程定时 / 局部定时）`。它不是只停在“有车位检测”这一层，而是把入场、车位引导、满位提示、停车后保护、密码解锁和报警都串成了一条完整流程，所以原文和可描述性都足以支持双 A。

## 控制系统在文中的位置

这里的控制系统描述不是论文里的陪衬，而是作者要证明“智能停车”成立的主体。文中既给了入场与出场的流程图，又在软件实现部分补上了车位计数、红绿指示、优先填位、密码界面和报警联动，因此控制逻辑就是论文最核心的工程内容。

更具体地说，这篇论文没有把重点放在感知算法或优化模型，而是放在 PLC 与 SCADA 如何把停车场变成一个可执行的离散控制系统。对我们来说，这种写法很有价值，因为它直接保住了状态推进、输入触发、输出动作和局部时间条件。

## 对我们为什么有用

对 `sources/` 来说，它补的是 `🅿️` 方向里偏“停车引导 + 安全联锁”的样本，而不是单纯的轨迹控制或视觉检测。当前库内停车方向虽然已经有一批样本，但这篇把 `priority method`、`passcode screen`、`motion sensor` 和 `2 chances within 20 seconds` 放在同一条控制链里，结构上仍然有明显补充价值。

后续做数据集时，第一轮最值得盯住的是“车入场后如何分配槽位、如何保护已停车位、在什么条件下允许出场”这条主链，而不是先去展开界面实现或 PLC/SCADA 通信细节。因为真正可复用的状态机语料就集中在这条主链里。

## 如果需要人工细读，建议怎么读

如果后续需要人工细读，建议先看第 3-4 页 的 `2.1 Entry of car / 2.2 Parking assistance / 2.3 Security / 2.4 Unparking of car`，先把入场、导引、密码解锁和报警四个环节串起来；然后再看第 5-6 页 的软件实现部分，核对车位计数、红绿提示、优先分配和 `10 s / 20 s` 定时到底是怎么落到系统行为上的。

像第 1-2 页 里更偏停车背景、一般性智能停车动机和 PLC/SCADA 平台说明的内容，第一次人工复核可以放到第二轮再看。除非要追问平台配置或仿真工具，否则先把流程图和软件实现里的控制链读稳，就足够支撑重新抽取 `STM.md`。
