# 智能交通灯控制器 / Design an Intelligent Traffic Light Controller

## 论文在讲什么

这篇论文围绕一个四路口交通灯控制器展开，目标是用 `FPGA + VHDL` 设计一套比普通定时灯序更灵活的路口控制系统。它不是只给一个简单的红黄绿轮换例子，而是把常规相位推进、道路空闲检测、特殊道路请求和拥堵延绿都放进同一套状态机框架里。

从我们关心的控制逻辑看，论文最有价值的是一个很明确的九状态基础灯序，以及三类功能增强：空路时提前切换、紧急或特殊道路请求时抢占当前相位、拥堵道路在到期前被检测到仍有大量车辆时延长绿灯。这些 guard 和时间点没有停留在概念层，而是直接配了状态图和条件表达。

## 控制系统在文中的位置

这套交通灯控制器就是论文主体。作者先给 regular design 的状态表和 bubble diagram，再逐步把 motion sensor、special request 和 loaded road request 叠加到控制器上，最后才回到仿真和 FPGA 实现，因此控制逻辑本身是正文主线，而不是为了展示硬件工具顺手带的例子。

对 `sources/` 来说，这种主次关系很重要。后续如果要把它纳入状态机数据集，我们不需要从实验章节反推控制器，也不需要把分散的工程实现碎片重新拼成控制链，因为原文已经把状态、灯色输出、时间条件和增强 guard 放到了同一组设计段落里。

## 对我们为什么有用

这篇论文对当前文库的主要意义，是补进了 `🚦` 方向里一个比较完整的 `EFSM + T1` 交通灯样本。相比只关注应急车辆优先或只讲密度优化的条目，它把基础相位链和多种实际路口需求一起保住了，所以更适合作为面向状态机自动生成的数据源。

它特别适合保留的部分，不是 FPGA 资源或仿真波形，而是“九状态基础灯序 + 5 秒黄灯切换 + 特殊请求抢占 + 59 秒负载判断延绿”这一整组条件化推进规则。对于后续做自然语言到状态机的建模任务，这类明确写出状态和 guard 的文章比纯算法描述更有训练价值。

## 如果需要人工细读，建议怎么读

建议先看第 `3` 页 regular design 的状态表和状态图，先把 `STANDBY / ONE_G / ONE_Y / TWO_G / TWO_Y / THREE_G / THREE_Y / FOUR_G / FOUR_Y` 这条主链读顺。第一轮只要把每个状态对应哪一路绿、哪一路黄、哪一路红抓住，就已经能恢复控制器骨架。

第二轮再看第 `5-6` 页的三种增强逻辑，重点读 motion sensor 如何提前结束相位、special request 怎样从当前绿灯跳转到被请求道路、loaded road request 又是如何在 `59 s` 左右触发延绿。至于后面的综合与实现部分，可以等需要核对硬件映射或资源占用时再回头看。
