# 气候舱温湿度-CO2-照明多变量监督控制 / Climate Chamber Control System Automation Using PLC

## 论文在讲什么

这篇论文讨论的是一个用于 urban farming 的气候舱自动控制系统，平台是 Siemens PLC、TIA Portal、Modbus、HMI 和若干温湿度/CO2/执行器接口。和很多只讲单一温控或湿控的论文不同，它同时处理温度、湿度、CO2 和照明，还把 schedule、插值、dew-point 保护与通信轮询都放进同一套 PLC 逻辑里。

从样本库角度看，这篇论文很强的一点是对象边界非常清楚。作者不是把环境控制笼统写成“保持目标条件”，而是逐项说明何时启加湿、何时启除湿、何时切换 AC 模式、何时定时投喂 CO2、何时因 dew point 风险强制切干燥模式，因此可以稳定抽成多变量环境控制的离散监督链。

## 控制系统在文中的位置

这里的气候舱控制系统就是论文主体。第 4 章几乎整章都在写控制器结构、模式、调度、Modbus、错误处理和 HMI，所以我们关心的控制逻辑并不是被顺手提到的案例，而是作者真正实现和交付的工程对象。

这类论文对 `sources/` 特别有用，因为它同时保住了离散模式和工程定时。很多环境控制论文会漂向连续调参与性能分析，但这篇明确写出 `Off / Automatic / Manual`、CO2 开阀定时、`500 ms` 轮询周期、day/night 与 12 段 schedule，因此特别适合作为 `EFSM + T1` 主样本。

## 对我们为什么有用

当前过程与环境控制方向虽然已有一些液位、水箱和灌装样本，但多变量气候舱这类“温湿度 + CO2 + 光照 + 调度 + 安全保护”结构并不多。它能补进一种更接近现代智能农业或环境舱设备的过程控制器，而不是传统单阈值启停链。

它对后续建模尤其有价值的一点，是 guard 很具体：有上下阈值、有 inner/outer band、有调度时间槽、有 dew point 保护、有通信轮询和 schedule 校验失败后的回退。这样即使以后要重写 `STM.md`，也很容易从原文重新拉出一条完整且细粒度的控制链。

## 如果需要人工细读，建议怎么读

建议先从第 18-24 页读起，把 `Setpoints.mode` 三个模式、温湿度阈值带、CO2 双定时器和 manual mode 的直接控制边界先抓稳。接着读第 24-33 页的 schedule、插值、`500 ms` Modbus 中断和 dew-point 保护，这部分是把“多变量过程控制”真正钉实的关键证据。

第一次人工复核时，不需要先钻进前面的 PLC 编程范式说明。那些内容有助于理解实现背景，但真正对 `STM` 有价值的是模式切换、阈值与定时规则、无效 schedule 回退、以及 HMI 如何暴露状态和错误。把这条主线读稳之后，再回头补通信寄存器和界面细节会更省力。
