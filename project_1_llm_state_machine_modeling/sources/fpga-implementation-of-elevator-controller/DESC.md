# FPGA 电梯控制器实现 / FPGA Implementation of Elevator Controller

## 论文在讲什么

这篇论文面向电梯控制器的 FPGA 实现。作者把电梯看成一个典型的反应式控制系统：轿厢需要根据内外呼梯按钮、楼层位置传感器、门状态和控制信号改变运行状态，并输出轿厢移动、停靠和开门控制。论文的工程目标是用 Verilog HDL 写出可参数化的控制器，使同一套控制逻辑可以通过控制变量扩展到不同楼层数。

系统描述集中在电梯控制器和状态图部分。原文明确说该电梯控制系统本质上是有限状态机，并采用 Mealy 模型；随后给出 `F1_OPEN`、`F2_MOVING`、楼层按钮、上下行外呼按钮、到站传感器、默认状态、门关闭定时器和多请求方向处理。这些内容比单纯的 FPGA 开发板介绍更接近我们需要的自然语言状态机样本。

## 控制系统在文中的位置

电梯控制器是论文的主体，不是附带演示。论文从摘要到 `Elevator Controller and Its Working`、`State Diagram` 和仿真结果都围绕控制逻辑展开：传感器提供当前楼层状态，按钮触发请求，控制状态机接收信号后决定下一位置和运动控制输出。

这篇论文与库内若干电梯样本相似，所以更适合作为降采样池中的双 A 变体，而不是新开一个完全不同的控制对象。它的优势在于状态名、输入名和到站迁移关系写得很直接，同时还保留了门定时器和多请求方向策略，对训练模型理解“请求 - 移动 - 到站 - 开门 - 复位”的电梯链路仍有价值。

## 对我们为什么有用

它补充的是 `🏢` 楼宇机电方向中的 FPGA/Mealy 表述。现有电梯条目中 PLC、SCADA 和梯形图样本较多，这篇用 Verilog/FPGA 的口径描述同类电梯调度与门控逻辑，可以增加同一控制对象在不同实现技术下的表述差异。

由于原文把状态集合、传感器、按钮和定时规则都文本化了，`STM.md` 不需要过度依赖图像。后续如果要构造电梯控制自然语言输入，可以直接从 `F*_OPEN / F*_MOVING`、`F_* / U_* / D_*`、`AF_*` 和 door timer 这些元素中抽样。

## 如果需要人工细读，建议怎么读

建议先读第 1 页 `Introduction` 末尾和 `Elevator Controller and Its Working`，确认作者为什么把电梯控制器视为 Mealy FSM，以及 proximity sensor、request flip-flop、timer 和 CSM 分别承担什么角色。然后读第 2-3 页 `State Diagram`，重点核对 `F1_OPEN` 到 `F4_OPEN`、`F1_MOVING` 到 `F4_MOVING`、内外呼按钮和 `AF_*` 到站传感器之间的映射关系。

第二轮再看仿真结果中 9 层控制例子，用 `F_7 -> F7_MOVING -> AF_7 -> door open` 这条链检查前面抽出的状态转移是否可运行。FPGA 背景、Xilinx 工具介绍和参考文献可后看，它们主要说明实现平台，对恢复状态机骨架不是关键。
