# 基于 STM32 的多层停车设备控制器开发 / The Controller Development of Multi-layer Parking Equipment Based on STM32

## 论文在讲什么

这篇论文讨论的是一种面向多层机械式停车设备的嵌入式控制器。作者希望用基于 `STM32F103` 的方案替代成本更高、布线更重的 PLC 控制方式，并围绕三层六车位停车设备给出硬件接口、传感器隔离和软件控制流程。

真正值得关注的不是单片机选型本身，而是软件部分把停车设备的工作方式写得很清楚：控制器如何区分自动与手动、何时进入故障/急停路径、停车过程里电机和限位条件如何一步步接管机械动作，都已经在主流程图和停车流程图里展开。

## 控制系统在文中的位置

这套控制器就是论文的核心对象。硬件部分负责说明为什么这个控制器能接传感器、继电器和总线，而第 3 节的软件结构设计则直接给出了“停车设备作为一个控制系统是怎样运行的”。

换句话说，论文不是拿停车设备做一个随手示例，而是在开发设备控制器本身。对于 `sources/` 来说，这类“机械执行机构 + 明确自动/手动/故障分支 + 限位驱动动作链”的样本非常适合保留。

## 对我们为什么有用

这篇论文对文库的意义在于，它补的是机械式立体停车设备的真实执行链，而不是单纯的门禁、空位显示或车位计数。它保住了设备级的动作顺序：升盘、旋转、后退、减速、下盘、前进、再下放，并且每一步都由明确的 limit 条件切换。

它还带有比较完整的模式边界。自动模式是主工作方式，手动模式用于自动运行受阻时的人工调整，同时正文明确出现 emergency braking、fault detect 和 voice alarm，因此它比很多“停车系统”短稿更像一个真正可建模的设备控制器。

## 如果需要人工细读，建议怎么读

人工重读时，建议直接先看第 3 节和 Figure 8、Figure 9。Figure 8 先帮你确认顶层模式边界：初始化、运行条件检查、自动/手动、故障和急停都在这里；Figure 9 再把 parking process 的动作链读顺，重点盯住 `M1 / M2 / M3` 与 `mount / rotate / slow down / stop / tray / mounter limit` 的配合关系。

硬件部分的隔离、滤波、总线和接口说明可以放在第二轮再看。它们有助于理解控制器实现背景，但对首轮 `STM.md` 抽取而言，优先级明显低于模式切换、限位触发和停车动作顺序本身。
