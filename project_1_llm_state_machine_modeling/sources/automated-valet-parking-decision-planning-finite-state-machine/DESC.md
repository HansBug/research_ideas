# 基于有限状态机的代客泊车决策规划系统研究 / Research on the Decision and Planning System of Automated Valet Parking Based on Finite State Machine

## 论文在讲什么

这篇论文讨论的是露天停车场里的自动代客泊车（AVP）与定点召回问题。作者不只是做一条泊车轨迹，而是把“车辆先在停车场道路里行驶、再切换到泊车、最后完成泊入或泊出”的整个高层决策过程组织起来，用分层有限状态机把功能模式、行车行为和泊车安全判定串成统一框架。

论文的技术主线有两部分。一部分是上层与下层状态机：上层负责代客泊车和定点召回的任务级切换，下层再细分为行车状态机和泊车状态机；另一部分是配套的路径与区域设计：作者用全局路径、局部行车规划、泊入路径规划以及行车/泊车切换区域，保证车辆在停车场复杂环境里能从“行驶”平稳切到“泊车”。

## 控制系统在文中的位置

我们关心的控制系统描述在这篇论文里是主体，不是附带案例。摘要、系统架构、上层状态机、行车状态机、泊车状态机、事件表和风险区域设计，都是围绕这个自动泊车监督控制器展开的。也就是说，状态机不是为了展示某种建模工具，而是作者表达控制决策逻辑的核心载体。

对 `sources/` 来说，这篇论文最有价值的地方在于它不是单一平面流程。它明确区分了任务级模式切换和行为级子状态，还把 `行车泊车切换区域`、`召回点区域`、`DE1-DE6` 事件和 `BE1` 风险事件写成了可追溯的控制触发条件。这让它更接近我们需要的“真实系统里的高层离散监督器”，而不仅是几条泊车轨迹的说明。

## 对我们为什么有用

当前 `🅿️` 领域在 `FSM/EFSM/HSM + T0/T1 + 双 A` 子集里一直偏少，而这篇论文正好补的是停车领域里少见的 `HSM + T0` 高层监督样本。它不是资源分配型停车管理，也不是纯几何泊车，而是把自动泊车系统本身的模式切换、行为决策和安全进入条件写得比较完整，因此能明显拓宽停车方向的样本结构。

另外，这篇论文也适合拿来和库里已有的停车控制条目做对照。它保留了代客泊车和定点召回两种任务入口，保留了行车与泊车两层行为粒度，还保留了 TTC、换道需求、目标区域进入和扫掠风险区域等 guard。后续如果要做“多层状态机自动生成”或“从自然语言分拆上层/下层控制器”的实验，这类样本会比只写一段停车分配逻辑的条目更有训练价值。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看摘要和第 1 节系统架构，再直接进 `1.1 上层状态机设计`、`1.2 行车状态机设计`、`1.3 泊车状态机设计`。重点先抓三件事：第一，上层四个主状态以及两条任务路径；第二，行车状态机的主行为集合与 `DE1-DE6` 事件；第三，泊车状态机如何用 `BE1` 把风险区域检查接到泊车执行之前。读完这三块，再回看图 1、图 4、图 5 和表 1-3，基本就能把高层离散控制链整理出来。

后面的全局路径、局部路径、五次多项式和几何推导可以放到第二轮再读。那些内容对于理解系统为什么能停进去很重要，但对我们当前要提取的状态机自然语言描述来说，优先级低于状态集合、进入条件、切换事件和任务级模式链。如果 `STM.md` 以后需要补得更细，再回第 3 节核对切换区域与风险区域的几何定义即可。
