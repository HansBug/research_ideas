# 停车位占用显示与门禁放行停车控制器 / Smart Car Parking System using PLC

## 论文在讲什么

这篇论文讨论的是一个面向多层停车场的 PLC 停车控制原型，目标不是做路径规划或停车诱导算法研究，而是把一个停车场最基本、最常见的离散控制链搭起来：车辆到达入口后如何检测、闸杆如何抬起与关闭、车位是否被占用怎样更新、入口外部的 LED 面板怎样显示剩余空位和具体空车位编号。

原文把系统构成写得比较直接。PLC 负责统计车辆数量和车位状态，IR 传感器分别布在入口、出口和各个车位上，Arduino 与伺服电机负责出入口栏杆动作，LED 面板负责对驾驶员显示剩余车位。也就是说，这篇文章关注的不是“智慧停车平台”那种后台管理系统，而是前端停车场门禁和车位占用更新控制本身。

## 控制系统在文中的位置

这里的停车控制器就是论文主体。文章虽然有一点项目背景和“为什么需要智能停车”的介绍，但后面的篇幅基本都围绕系统部件、工作流程和实验结果展开，尤其强调入口检测、车位状态变化、LED 指示和出口放行这几条主链，因此我们关心的控制系统描述并不是附属案例，而是整篇文章最核心的内容。

同时，这篇论文的写法偏工程实现稿而不是形式化建模稿。它没有显式给出状态表或状态图，但正文已经把“入口监视 -> 开闸放行 -> 车位占用更新 -> 出口放行 -> 返回监视”这一条控制闭环写得足够清楚。对 `sources/` 来说，这种文章依然有价值，因为它保住了完整控制对象、输入传感、执行动作和顺序推进关系。

## 对我们为什么有用

对当前文库而言，这篇论文补的是 `🅿️` 方向里较干净的一类停车场控制样本。已有不少停车相关文章会漂向车牌识别、感知平台、调度优化、HMI 监控或局部门禁 demo，而这篇文章反而更老实地把入口闸杆、车位检测和出口栏杆写成一条系统级控制链，因此更适合沉淀成可追溯的 `EFSM + T0` 数据集样本。

它对后续自动状态机生成任务的帮助也比较直接。停车控制对象明确，输入事件主要来自入口/出口/车位 IR 传感器，输出动作主要是栏杆升降和 LED 状态更新，语义边界干净，没有被大量连续控制、规划算法或平台架构描述稀释。换句话说，这是一篇适合做“小而完整”的停车控制 STM 样本，而不是只能抽出一两个 mode 名称的薄稿。

## 如果需要人工细读，建议怎么读

如果后续要人工重读原文，建议先看第 `1-2` 页的 `Abstract`、`Concept` 和 `Description of System`，先把系统边界读稳：到底有哪些硬件部件，PLC 与 Arduino 分别承担什么职责，入口、出口和车位传感器在控制链里各自触发什么动作。接着直接跳到第 `2-4` 页的 `How it works` 与 `Results and Discussion`，把入口放行、车位占用亮灯、车辆离位灭灯、出口开闸这几步顺着读一遍，就能恢复出主状态链。

像前面的停车痛点背景、面板布线或一般性自动化介绍可以放到第二轮再看。它们有助于理解项目动机，但对重建“停车控制器何时开闸、何时更新车位、何时回到监视状态”帮助不大。若后续 `STM.md` 需要复核，优先仍应围绕 `How it works` 与结果页中那些直接描述传感器触发和执行动作的段落。
