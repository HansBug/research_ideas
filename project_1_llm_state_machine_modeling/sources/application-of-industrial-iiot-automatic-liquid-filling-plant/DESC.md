# 多规格瓶高检测与定时灌装分拣 / Application of Industrial IoT in Developing a Sustainable and Automatic Liquid Filling Plant

## 论文在讲什么

这篇论文围绕一条带 IIoT 监控能力的自动液体灌装与分拣产线展开，当前 `STM.md` 抽到的核心对象是“工业自动化领域的多规格瓶装灌装与颜色分拣控制系统”。如果只抓一句话理解它的主体，可以先把它看成：这是一个先判瓶高、再选择阀位、再定时灌装、最后按颜色信号分拣的 PLC 产线控制器。

从现有条目看，文中的离散控制链主要以 `EFSM（扩展状态机）` 的方式出现，时间语义属于 `T1（工程定时 / 局部定时）`。这篇的优势不只是“有灌装”，而是把高度识别、位锁存、阀门选择、灌装时长和末端分拣全部串在一条链里，因此比常见的单瓶单阀短流程更丰富。

## 控制系统在文中的位置

这里的控制系统描述是整篇论文的主体实现，而不是配角。作者虽然在标题里带了 `IIoT`，但真正展开最多的并不是云平台，而是瓶子经过传送带后如何被传感器识别、如何被 PLC 分类、以及如何触发不同阀门和分拣灯。

换句话说，IIoT 更像是监控和展示层，而我们关心的状态机样本来自底层那条 PLC 控制链。这正适合 `sources/` 的目标，因为我们要的是可追溯的离散行为和阶段推进，而不是泛化数字化转型叙述。

## 对我们为什么有用

对 `sources/` 来说，它补的是 `🏭` 方向里偏“多规格分流 + 多阀定时灌装 + 末端分拣”的样本。当前库内已有若干灌装短流程，但大多只写“瓶到位 -> 停带 -> 开阀 -> 关阀 -> 走带”；这篇则多了一个前置的瓶高分类阶段和一个后置的颜色分拣阶段，结构更长。

这意味着后续做数据集时，可以把它当作比普通瓶装灌装更复杂的多段控制样本来使用。尤其是 “one/two/three IR sensors -> latch bits -> T4:x -> red/green/blue valve -> 10-second sorting indicator” 这条链，非常适合保留下来做较长控制语句的建模语料。

## 如果需要人工细读，建议怎么读

如果后续需要人工细读，建议先看第 1-3 页，把瓶高检测塔、位锁存和三种瓶型的对应关系读清楚；然后直接跳到第 7-8 页 的 `PROPOSED SYSTEM AND ALGORITHM / DEVELOPMENT OF PLANT`，这里集中给出了算法步骤、`T4:1/T4:2/T4:3` 定时、`20 s / 30 s / 50 s` 灌装时长以及末端 `10 s` 指示灯逻辑；最后再看第 9-10 页 的性能图，只把它当成对上述控制链可运行性的补充验证。

像第 3-6 页 里偏长的相关工作综述和 IIoT 宏观背景，第一次人工复核可以往后放。对重新抽取 `STM.md` 来说，真正值得先盯住的是算法段和开发过程段，因为状态、输入、输出和时间条件都集中在那里。
