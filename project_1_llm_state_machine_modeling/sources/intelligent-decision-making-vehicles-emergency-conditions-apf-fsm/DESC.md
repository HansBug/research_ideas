# 紧急工况自动驾驶决策状态机 / Intelligent decision-making method for vehicles in emergency conditions based on artificial potential fields and finite state machines

## 论文在讲什么

这篇论文讨论的是自动驾驶车辆在紧急工况下的行为决策问题。作者关心的不是单一换道轨迹或单一制动器件，而是当车辆遇到前车急减速、危险障碍或需要紧急换道时，系统应该如何在多种行为之间做出结构化切换，并把这种切换稳定地落到仿真平台里。

论文的方法把人工势场和状态机结合起来：用纵向、横向势场力去构造动态阈值，再把这些阈值交给状态机作为 guard。这样一来，状态切换既不是纯规则表，也不是完全黑盒优化，而是“连续量生成阈值、离散机做决策”的混合式行为控制框架。

## 控制系统在文中的位置

这里的行为决策控制器就是论文主线。第 `4` 节专门围绕 `Decision-making model considering APF and FSM` 展开，先给状态层级和状态集，再给状态编号和纵向/横向转移规则，最后把整套模型落实到 `Simulink/Stateflow` 的分层状态机实现里。

对 `sources/` 而言，这非常有价值，因为很多自动驾驶论文虽然会出现“模式”或“行为”字样，但真正的状态集合和 guard 经常埋在优化器或实验脚本背后。这里则相反，状态机本身被明确写成核心方法，因此可以比较稳地抽成面向状态机建模的数据样本。

## 对我们为什么有用

这篇论文补的是 `🚗` 方向里比较稀缺的“紧急工况分层决策状态机”样本。现有汽车条目里有监管信号处理、可中止超车和换道监督控制，但这篇更进一步，把自由行驶、跟驰、紧急制动和紧急换道放进同一个两层状态机里，并且用势场阈值来驱动纵向/横向分支。

它特别适合保留的部分，是四个显式状态、`0/1/2/3` 状态编码、纵向 `Fap/Fcf/Feb` 规则，以及横向 `kl/kr/Fhc` 触发规则之间的对应关系。这种“连续耦合 + 分层状态机”的写法，比只给一个单独的 lane-change FSM 或单独的 emergency braking rule 更有结构差异，对数据集的多样性帮助更大。

## 如果需要人工细读，建议怎么读

建议先直接读第 `6-8` 页的第 `4` 节。第一轮先把三件事抓住：为什么要用 `HFSM` 而不是平面状态机；四个行为状态分别是什么、如何编号；纵向与横向两层子状态机是怎么分工的。只要把这三件事读稳，就已经能恢复大部分决策骨架。

第二轮再细读 `Table 1-4` 以及相关公式，重点核对 `Fap` 相对 `Fcf / Feb` 的纵向切换条件、`vj` 与 `vi` 的速度比较、以及 `kl / kr` 何时触发左/右紧急换道。实验和联合仿真章节适合最后看，它们主要用于确认状态机在 `CarSim + Simulink` 环境下是否按预期运行，而不是第一次抽状态骨架时最关键的部分。
