# A Modular Autonomous Driving System for Electric Boats based on Fuzzy Controllers and Q-Learning

## 论文在讲什么

这篇论文讨论的是一套用于电动船的自主驾驶系统。它的目标不是单独优化某个模糊控制器，而是把出港、导航、避障、入港和虚拟锚泊这些功能组织成一个可以自动切换的完整船载控制体系。

系统整体是模块化的：下层是若干运动控制流水线和推进系统控制器，上层则有一个监督器负责根据传感器和人机交互命令在不同流水线之间切换。论文还讨论了模糊控制器训练和推进系统设计，但对我们最有价值的部分，是那个把不同航行任务串起来的六状态监督 `FSM`。

## 控制系统在文中的位置

我们关心的控制系统描述在文中是主对象之一，不是简单案例。论文从一开始就在讲为什么要用模块化结构来替代端到端控制，并且把监督层、驾驶层和运动控制层区分开来；监督层 `FSM` 则是整套系统真正的切换中枢。

换句话说，这篇论文里的状态机不是附属的模式标记，而是决定哪条控制流水线接管推进系统的核心逻辑。`Virtual Anchor / Manual Drive / Exiting / Navigation / Avoid / Enter` 六个状态对应的是不同船舶运行任务，而不是软件工作模式，这正是 `sources/` 需要的真实控制对象样本。

## 对我们为什么有用

对样本库来说，这篇论文补的是 `⚙️` 方向里很有代表性的“任务级监督控制器”样本。相比大量 `PLC` 顺序控制条目，它的对象更偏自主载具，但仍然保住了足够清楚的离散状态链，非常适合丰富控制对象谱系。

它还有一个重要价值，就是把层次结构写得很清楚。很多自动驾驶或船舶控制论文会停留在模块框图或算法说明层，但这篇明确说明监督层怎样利用 `FSM` 选择不同流水线，因此非常适合拿来作为“层次化任务监督器”这一类样本的代表。

## 如果需要人工细读，建议怎么读

人工细读时，建议先直接看第 3-4 页 `Proposed Autonomous Driving System Architecture`。第一轮只做三件事：确认监督层、驾驶层和运动控制层分别负责什么；记下四条驾驶流水线分别处理什么任务；然后把六个状态和状态之间的切换条件完整串起来。

推进系统、桨轮力学模型和后面的模糊控制训练细节可以放到第二轮。它们对复现整套系统当然重要，但如果目标只是重做 `STM.md` 或验证状态机边界，那么优先级明显低于监督层 `FSM`、多路复用选择机制以及 `sonar / obstacle / destination / dockside` 这些触发条件。
