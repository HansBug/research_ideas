# 高速搜索与拦截无人机任务控制 / Autonomous Aerial Robot for High-Speed Search and Intercept Applications

## 论文在讲什么

这篇论文围绕 MBZIRC 比赛里的高速搜索与拦截任务，完整介绍了一套可自主搜索目标无人机、逼近、抓取吊挂球体并在任务结束后降落的空中机器人系统。论文内容很全，既讲机体与抓手设计，也讲感知、状态估计、轨迹规划、控制和 mission control，但对我们最有价值的是第 5.5 节里那套任务有限状态机。

从系统层次看，这不是一个只在局部调度器里顺带提到 FSM 的例子。作者明确把 mission control 作为整套软件栈的一部分来描述，说明不同状态下哪些检测器开启、飞行速度如何设定、导航目标怎样切换，以及在何种检测事件满足时从搜索切换到跟踪、再切换到抓取和降落。

## 控制系统在文中的位置

这里的控制系统是高层任务主管，而不是底层姿态控制器。正文明确说选择 FSM 是因为 Challenge 1 的复杂度可以用少量状态和事件表示，而且这样便于快速试验不同任务逻辑版本。也就是说，FSM 在文中承担的是“把感知、速度策略和导航目标编排成完整任务”的职责。

这对 `sources/` 很重要，因为状态和事件都很清楚：`SEARCH`、`FOLLOW_LONG_RANGE`、`FOLLOW_SHORT_RANGE`、`CATCH_BALL`、`LAND` 再加上一组带帧数门槛的检测事件。相比很多 UAV 论文只在摘要里说“mission manager”或“behavior tree”，这篇对离散控制链的展开更直接，可追溯性也更强。

## 对我们为什么有用

它补的是航空航天方向里“高层 mission supervisor”这一类样本，而且比库里常见的巡检、航点飞行或着陆监督器更偏 search-and-intercept 任务闭环。这里既有感知驱动的状态切换，也有不同状态对计算资源、速度和导航目标的再配置，适合做面向 LLM 状态机建模的数据源。

从样本多样性看，这篇也有明显区分度。它不是单纯 `search -> track` 两态，也不是纯行为树叙事，而是长距 / 短距检测器切换、抓球阶段保持轨迹跟随、激光传感器确认抓取成功等具体任务逻辑。后续如果做抽样，优先保留 mission-control 这一层即可，底层 MPC、视觉估计和抓手机械实现可以作为第二层背景材料。

## 如果需要人工细读，建议怎么读

如果后续是为了人工重做 `STM.md`，建议先直接跳到第 5 节，尤其是 `5.5 Mission Control System`。第一轮先只做三件事：抄清状态名，抄清事件名和连续帧门槛，抄清各状态下检测器启停、速度设定和导航目标的不同，这样就能快速复原主控制链。

第二轮再回看前面的感知、估计和控制章节，主要是为了理解为什么某些状态要关掉长距检测器、为什么搜索轨迹是低空半椭圆、以及抓取阶段是怎样与轨迹规划耦合的。若不是要追算法细节，这些章节都不必压在第一次样本抽取时阅读。
