# FPGA 停车位监测与出入场控制 / FPGA-Based Smart Parking Management System with Real-Time Slot Monitoring and Entry/Exit Detection

## 论文在讲什么

这篇论文研究的不是自动驾驶里的泊车轨迹控制，而是停车场本身的离散监测与出入场管理。作者用 `Artix-7 FPGA + Verilog` 设计了一套小型停车场控制系统，重点放在四个车位的占用监测、入口/出口事件检测、剩余车位统计以及显示反馈上。

从控制叙事来看，它把停车场看成一个由事件触发的计数与状态更新系统：入口传感器触发后等待某个车位变成占用，出口传感器触发后等待某个车位恢复为空，然后同步刷新 `LCD`、7 段数码管和车位指示灯。换句话说，它更像一个停车场运行控制器，而不是一个只负责识别图像或推荐路线的附属模块。

## 控制系统在文中的位置

控制器是论文主线。正文专门给出 `System Overview`、`Flow Chart`、`Finite State Machine` 和 Verilog 模块说明，清楚交代 `IR1–IR4`、`IR5`、`IR6` 各自负责什么，`O` 和 `A` 如何更新，以及 `Idle / Entry / Exit` 三个状态如何响应不同传感器事件。

这对 `sources/` 很有帮助，因为我们不需要从零散实验描述里反推逻辑。原文直接把输入、状态、计数规则和显示输出绑在一起，后续做 `STM.md` 或数据集时，可以把它稳定地抽成一个“出入场 + 车位占用更新”的离散控制对象。

## 对我们为什么有用

这篇论文补的是 `🅿️` 方向里相对少见的“停车位监测 + 出入场事件联动”样本。现有停车类条目里有不少更偏门禁分配、计费或自动代客泊车的控制器，而这篇更强调停车位本身的状态更新、占用统计和多显示通道反馈，因而能补足停车场监测控制的表达形态。

它的另一个价值是结构非常清楚。`Initialize -> monitor IR5/IR6 -> update slot -> return to monitoring` 这条主链加上 `Idle / Entry / Exit` 三态 FSM，对于训练模型理解“事件触发 + 计数变量 + 显示反馈”类控制器很有帮助，不会退化成只有一个静态表格的硬件实现说明。

## 如果需要人工细读，建议怎么读

建议先看第 `4-5` 页 `System Overview`、`Flow Chart` 和 `Finite State Machine`，先把六个红外传感器、`O/A` 计数、LCD 与 7 段数码管的角色分清，再把 `Idle / Entry / Exit` 三态的迁移条件读稳。第一轮只需要确认“入口事件如何变成占用计数增加、出口事件如何变成占用计数减少”。

第二轮再去看 Verilog 模块和测试章节，重点核对三件事：`O = Σ4 (1−IRi)` 与 `A = 4 − O` 的计数规则、数码管上 `et / ei` 的意义、以及快速切换或同时变更车位时系统是否稳定。像前文的技术比较和性能宣传可以放到最后再看，对恢复状态机骨架不是最关键。
