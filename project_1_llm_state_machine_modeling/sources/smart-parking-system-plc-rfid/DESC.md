# RFID 多层停车楼 PLC 控制 / Rancang Bangun Sistem Parkir Pintar Berbasis PLC (Programmable Logic Controller)

## 论文在讲什么

这篇论文围绕一个多层微型停车楼展开，目标是让车辆不再由驾驶员自己寻找车位，而是由系统自动决定空位并完成入库。作者把 RFID 识别、Visual Studio 界面、MySQL 数据库和 Omron PLC 连成一条控制链，让用户刷卡后能够自动匹配身份、选择空车位并驱动车板与闸桥动作。

它的重点不是机械结构本身，而是停车存取过程的顺序控制。文中既给了缩比装置的硬件构成，也给了 `Mode Masuk / Mode Keluar`、目标车位 memory 位、平台与闸桥先后动作、满位提示和测试结果，所以对我们来说它是一个较完整的停车控制器描述，而不只是一个停车场管理概念。

## 控制系统在文中的位置

控制系统是这篇论文的主角。第 2 页到第 3 页先定义 PLC 的输入输出地址，把各类按钮、边界开关、光电检测和执行器地址都列出来；第 3 页到第 4 页又把 RFID + HMI 的上层逻辑补上，说明空位是怎样被选出来并传给 PLC 的。

到了第 6 页和第 7 页，论文把系统级测试写得更像控制案例：目标车位被选中后，先把对应车板调到地面，再放下闸桥让车辆入内；如果所有房间都满了，系统则不允许再进入入场模式。这种写法对 `STM.md` 非常友好，因为入库主链已经是天然的顺序控制描述。

## 对我们为什么有用

`🅿️` 领域当前有不少停车样本，但相当一部分更偏轨迹规划、模糊控制或者纯车位计数，而这篇论文对应的是另一类很实用的样本：停车楼内部的 electromechanical 存取控制。它不是连续控制，也不依赖复杂优化，更适合 project 1 做“自然语言到离散状态机”的抽取。

它还有一个好处是对象边界很清楚。控制器关心的是刷卡、判定空位、选择目标房间、驱动平台和门桥、阻止满位进入，而不是泛泛讨论停车管理业务流程。这让它在数据集里可以和自动泊车轨迹类样本形成互补。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看第 2-3 页的 `I/O` 地址表，把输入输出对象边界先定住，再读第 3-4 页关于 Visual Studio 和 MySQL 的段落，弄清 RFID 身份匹配与空位选择是如何传到 PLC 的。然后直接跳到第 6-7 页的系统测试段，把目标车位 memory 位、取板、降闸桥、满位阻塞这些顺序动作摘出来。

如果后续要补更细的实现级状态，可以再回看图 5 和图 6 的进出场流程图以及图 9 的梯形图。传感器硬件电路和光强敏感度测试可以第二轮再看，它们有助于理解装置可靠性，但不是首轮重构状态机主链所必需的。
