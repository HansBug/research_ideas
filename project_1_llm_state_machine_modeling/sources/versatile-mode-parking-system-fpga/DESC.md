# 四模式停车位识别与路径生成控制 / A Real Time Algorithm for Versatile Mode Parking System and Its Implementation on FPGA Board

## 论文在讲什么

这篇论文针对的是自动停车里一个很具体的问题：很多系统只覆盖平行泊车或垂直泊车中的一种，而实际环境里车位几何形态可能是 `parallel / perpendicular / head-in angled / head-out angled` 四种。作者因此提出了一个 Autonomous and Versatile mode Parking System (AVPS)，希望让移动机器人或未来车辆先识别当前车位属于哪一类，再生成对应的几何路径并执行停车。

文章不是泛泛讨论视觉感知或全局路径规划，而是把停车模式识别本身当成核心控制问题。正文集中讲的是：如何利用传感器测得的 `D1-D5`、角点检测结果、坡度存在性和角度 `α` 来判定具体模式，并把这套逻辑落到 FPGA 上的 VHDL 实时算法里。

## 控制系统在文中的位置

我们关心的控制系统描述在这篇论文里属于主角。作者真正要证明的不是“FPGA 可以跑算法”，而是“一个停车控制器能否在同一套离散决策链中兼容四类停车模式，并在 guard 满足时切到正确模式”。因此 Fig. 6 的 flowchart 和与之对应的文字说明，就是论文最核心的控制链。

它在文中的角色也比较清晰：先识别空车位，接着测量关键几何量，再根据 slope、`D2 = K`、`D2 = K * cos α`、`D1 ≥ D3/D4/D5` 这类判断分支选择模式，最后生成路径并驱动执行机构。换句话说，这不是“停车研究里顺手提到一个状态图”，而是停车控制的主要决策器本体。

## 对我们为什么有用

对 `sources/` 来说，这篇论文补的是停车方向里比较少见的一种“多模式选择器”样本。库里已有不少门禁、车位计数或托盘/升降式停车控制器，但这篇更强调“同一控制器在多个停车模式之间做结构化判别”，因此比单一 parallel parking 或单一 slot controller 更适合当作 `EFSM + T0` 的多分支决策样本。

它还有一个额外价值：虽然最后会进入几何路径跟踪，但离散主链并没有被连续控制淹没。原文里真正负责模式切换的那部分保住了 `控制对象 + 模式集合 + 输入观测 + guard + 输出动作` 这五个关键件，因此后续无论拿来做自然语言到状态机抽取，还是做“离散决策层与连续执行层耦合”的研究，都比较有代表性。

## 如果需要人工细读，建议怎么读

人工回原文时，建议先读摘要和 `2.2 Proposed Algorithm`，快速把系统边界锁定为“停车模式识别与路径生成控制器”，而不是整车导航系统。随后直接看第 `7-8` 页的 Figure 6 与文字分解，把 `(a)-(k)` 这组步骤读完整，并重点标出 `slope`、`D2 = K * cos α`、`D2 = K`、`D1 ≥ D3/D4/D5` 这些真正决定状态分支的 guard。

第二轮如果还要补实现细节，再回看前面几页的几何量定义和后面的 simulation/result 部分，确认各传感器、角点检测和电机响应在控制链里分别扮演什么角色。更偏算法背景、相关工作和性能比较的段落可以放后，因为真正支撑 `STM.md` 的主链已经集中在多模式 flowchart 本身。
