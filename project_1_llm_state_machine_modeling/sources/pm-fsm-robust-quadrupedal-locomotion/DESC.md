# 四足机器人接触感知步态 FSM / PM-FSM: Policies Modulating Finite State Machine for Robust Quadrupedal Locomotion

## 论文在讲什么

这篇论文讨论的是四足机器人步态控制，而不是一般性的强化学习框架。作者试图解决“纯 RL 不稳、纯模型法调参重”的问题，于是提出了一个 `Policies Modulating Finite State Machine` 架构：外层策略只负责调节频率、幅值和抬腿高度，真正负责步态组织和接触事件处理的，是一个显式的接触感知有限状态机。

对 `sources/` 来说，这篇论文的价值在于它不是抽象地说“FSM 可以用于 locomotion”，而是把每条腿的状态细化到了 `s1 / s2 / s3`，并把全局状态如何由 gait matrix 组合出来、何时因接触或目标角度满足而转移、何时触发上下楼反射都写清楚了。

## 控制系统在文中的位置

这里的状态机是论文的主体控制器，不是实验辅助模块。整篇论文围绕 PM-FSM 这个控制结构展开：连续参数由策略调节，但步态阶段推进、接触事件解释和反射动作都由 FSM 骨架承担。换句话说，论文讨论的核心问题正是“如何把离散 gait logic 与连续调节耦合起来”。

这种角色定位对样本库很重要，因为它让我们拿到的是一个真正的机器人控制器，而不是只在方法对比里带过几句的模式图。状态机在文中有明确的结构职责，也有直接的实验场景支撑。

## 对我们为什么有用

这篇论文补进来之后，`sources/` 在四足机器人方向会多一个质量很高的 `HSM + T0 + 连续耦合` 样本。相比只用两态支撑/摆动模板的步态论文，PM-FSM 的好处是把摆动又拆成了伸腿和回收两个子阶段，同时把 unexpected contact 写成显式反射分支，这使自然语言描述更像可建模的状态机说明书。

如果后续要做从自然语言到状态机的监督数据，这类样本尤其有用，因为它同时包含了子自动机、全局组合状态、触发条件和反射恢复链，比单纯的 gait-phase 命名更适合训练模型学会“层次状态机 + 事件恢复”的表达。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 1 页摘要，把 `contact-aware finite state machines` 这个总纲和论文想解决的问题读稳；然后直接看第 3-4 页的 `Figure 3`、`Section III-D` 与 `Section III-E`，这里已经覆盖了 `s1 / s2 / s3`、全局状态构造、状态转移条件以及上下楼反射的触发点，是重做 `STM.md` 的核心页面。

第 2 页的相关工作和更后面的实验结果可以放到第二轮再看，它们主要帮助理解为什么这个结构有效。若以后只想快速复原控制链，最值得优先保住的仍然是三态子自动机、全局状态推进条件和两类 reflex 触发逻辑。
