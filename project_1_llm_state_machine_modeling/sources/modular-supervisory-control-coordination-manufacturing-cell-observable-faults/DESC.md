# 制造单元可观测故障监督控制 / Modular Supervisory Control for the Coordination of a Manufacturing Cell with Observable Faults

## 论文在讲什么

这篇论文研究的是一个经典制造单元在存在设备故障时的离散监督控制问题。作者不是只给一个总框架，而是把制造单元拆成旋转工作台、分类与运输装置、钻孔机、测试装置等多个子系统，并且逐个把它们建模成有限确定自动机，再在此基础上设计 modular supervisors。

对 `sources/` 来说，这篇文章的价值不在于“形式化方法”四个字，而在于它把设备级状态、事件、故障、修复和可控/不可控事件划分写得非常明确。当前提取条目选的是旋转工作台 automaton，因为这部分最紧凑、最完整，也最适合落成单个 `FSM + T0` 样本。

## 控制系统在文中的位置

控制系统就是正文主体。作者首先声明各子系统都要用 finite deterministic automata 来建模，然后把期望功能和安全要求写成 supervisor forms。旋转工作台这个子系统尤其清晰：`idle`、`moving`、`faulty` 三态，配上 `start`、`stop`、`fault`、`repair` 四个离散事件，再给出哪些事件可控、哪些不可控，以及每个转移函数。

这说明论文不是抽象地谈“可监督控制理论”，而是把控制理论落到具体设备和故障恢复链上。这样的材料对 project1 很有用，因为它能提供一种“设备级离散控制 + 故障进入 + 人工修复释放”的高可信文字样本。

## 对我们为什么有用

这篇论文补进了一类当前文库里很重要但不算太多的样本：制造设备的 fault-aware supervisor。相比普通顺序控制或简单启停逻辑，这类文章更强调故障态引入、可控/不可控事件区分、以及修复后怎样回到安全初始态，因此非常适合后续做“生成-验证-修复”链条研究。

如果后续要把它用于数据集，至少应保住以下信息：子系统名称、状态集合、事件集合、可控/不可控划分、转移函数、以及故障如何进入与解除。只要这条链还在，就能很好地区分它和纯方法学或纯验证文章。

## 如果需要人工细读，建议怎么读

建议先读第 `1` 页摘要和第 `4-7` 页的子系统建模部分，优先看旋转工作台和钻孔机，因为这两段的状态表、事件表和转移函数都很清楚。把这一部分读懂之后，再回头看 supervisor form 和复杂度讨论，会更容易把“形式化设计”与“真实控制对象”对应起来。

第一次人工复核时不必把所有 supervisor form 都完整推一遍。对 project1 来说，更重要的是保住具体设备的离散控制链，而不是展开全部语言闭包和可控性证明。
