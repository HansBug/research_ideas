# 平移式立体车库排队式存取控制 / PLC Control System for Translation Motion Stereo-garage

## 论文在讲什么

这篇论文讨论的是一种 `stacker translation stereo-garage` 的 PLC 控制系统。作者先给出车库的选择机构与取送机构，再把“停车 / 取车”两条主流程写成排队式控制：用户在待机界面选择 `parking` 或 `taking`，停车时系统分配车位并按队列执行入库，取车时系统读卡并从对应车位取车。

它的重点不在轨迹规划，而在资源分配和执行链：怎样选车位、哪些传感器负责列/行检查、哪些电机负责升降和平移、哪些显示位和指示灯反映 `Parking/Taking` 与 `Ready`。因此这篇文献非常适合作为“多车位立体车库控制语义”样本，而不是简单闸门开关样本。

## 控制系统在文中的位置

控制系统是论文的主线。结构方案、自动停车/取车流程、I/O 分析和 PLC 模块选型都围绕车库存取控制展开，并不是为了支持别的算法而顺带出现的工程例子。

另外，这篇论文的一个特点是“系统级描述 + I/O 级落地”比较紧。它既写了待机、停车、取车和队列执行，也写了四台电机、`69` 个输入、`19` 个输出、限位开关和车位检测。因此它在 `sources/` 里能承担“流程和硬件映射都比较清楚”的停车样本角色。

## 对我们为什么有用

它补进的是停车领域里比单入口门禁更复杂的一类 `EFSM + T0` 样本：系统不只是判断“放行 / 不放行”，而是要先分配车位，再驱动选择机构和平移/升降机构执行完整存取链，还要把当前模式和目标车位显示出来。

对后续数据集构建来说，这类样本很适合训练“从系统级自然语言恢复资源分配与执行链”。尤其是 `standby -> parking/taking -> slot selection -> queue execution / card-based retrieval` 这条主链，比普通停车场计数器更接近立体车库的真实控制任务。

## 如果需要人工细读，建议怎么读

建议先看第 `2-4` 页的结构与流程说明，优先把选择机构、取送机构、待机模式下的 `parking / taking` 分支，以及“分配车位后排队入库 / 刷卡按号取车”这条主线抓住。

然后再看第 `3-4` 页的 `Table 1-3` 和 PLC 模块说明，确认四台电机的方向控制、限位开关、安全检测和 `69` 输入 / `19` 输出怎样支撑这条流程。至于更泛化的三维车库背景和 PLC/MCU 对比，可以放到第二轮再看；第一次回读只需要把存取流程与 I/O 语义读稳。
