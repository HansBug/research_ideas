# 四状态倒计时交通灯控制 / Design of Traffic Light based on FPGA

## 论文在讲什么

这篇论文是一个比较短的 FPGA 交通灯实现稿，核心目标不是做自适应信号优化，而是把一个十字路口的基本轮转控制和倒计时显示完整落成 `VHDL + FPGA` 设计。文章选的是东西向和南北向交替通行的经典场景，并明确给出绿灯、黄灯和红灯在每个阶段的持续时间。

对 `sources/` 来说，它的关键价值在于正文没有把状态机只停留在题目里，而是直接给出了 `S1-S4` 四个状态、`1 Hz` 分频思路、总周期计数器和用于数码管显示的倒计时子计数器。这使得它虽然简单，但仍然能被可靠地还原成一条 `FSM + T1` 的交通信号样本。

## 控制系统在文中的位置

这里的控制系统描述就是论文主体。作者围绕交通灯控制任务、状态划分、分频电路和显示电路展开，实验部分也只是验证这套控制器是否按预期运行，因此交通灯状态机不是方法载体之外的附属例子，而是文章本身要实现和展示的对象。

不过它的角色更接近“标准工程实现样例”，而不是复杂交通策略论文。也就是说，这篇稿子的价值在于把一个固定周期 timed controller 说清楚，而不在于引入复杂的传感器、优先级抢占或排队优化算法。

## 对我们为什么有用

这篇论文补的是 `🚦` 方向里最基础、但也最容易作为 canonical baseline 的 timed FSM 画像。库里已经有一些更复杂的交通灯样本，例如带 side-road sensor、walk request 或 emergency override 的版本；这篇则提供了一个更平的四状态固定轮转控制器，用于和那些 richer controller 做对照。

它适合作为降采样保留样本，而不是主集主力。原因不是原文不够，而是它和库里已有的 timed traffic-light 模式很接近。后续如果要比较“固定轮转”与“带 guard 的交通灯控制器”在语言表述上的差异，这篇就很有用。

## 如果需要人工细读，建议怎么读

人工重读时，先看第 `1` 页的 `2 TRAFFIC SIGNAL CONTROL TASKS`，把东西向 `39 s + 4 s` 和南北向 `20 s + 4 s` 的相位时序先读出来，再确认倒计时显示是控制目标的一部分，不是附带界面。随后直接看第 `2` 页的 `4.2 Traffic Signal and Digital Tube Display Circuit Design`，把 `S1-S4` 四个状态和 `68` 计数器、`39/4/20` 倒计时器之间的关系整理出来。

第一次复核时不需要在器件选择、引脚绑定和测试截图上花太多时间。那些内容更偏 FPGA 实现验证；如果目标是重做 `STM.md` 或确认样本是否仍满足 `FSM + T1`，优先把状态、持续时间和计数显示链读稳就够了。
