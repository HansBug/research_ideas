# 三罐液位 PLC 控制器 / Automatic Fluid Level Control Using Programmable Logic Controller

## 论文在讲什么

这篇论文讨论的是一家纺织厂中的液位控制怎样从传统继电器控制改成 PLC 自动控制。作者的出发点是工厂液体管理中存在浪费、人工干预多、维护困难等问题，因此提出一套由 PLC、压力开关、泵和电磁阀组成的自动液位系统。论文将系统拆成 reserve tank、operation tank 和 user tank 三个罐体，每个罐体对应不同的上限、下限或恒定液位需求。

它的正文没有停留在“用了 PLC 所以更先进”这种泛泛表述，而是把每个罐体的控制关系写到了 I/O 和动作层。比如 reserve tank 负责 dry run 保护和上限溢流控制，operation tank 通过上下液位去开闭 `Q2`，user tank 则通过 `I4` 保持工作液位常量。再加上结果部分给出的步骤和 truth table，整篇论文已经足够支撑一个完整的液位控制状态链。

## 控制系统在文中的位置

这里的 PLC 液位控制器就是论文的核心对象。作者虽然花了一些篇幅解释传统控制的问题和 PLC 的一般背景，但真正展开的部分集中在三只罐体怎样协同工作，以及 PLC 怎么根据不同压力开关状态去决定泵和电磁阀的输出。换言之，这不是“以液位控制为例介绍 PLC”的教学稿，而是围绕液位系统本身组织起来的工程控制描述。

这点对我们很重要，因为 `sources/` 需要的是能直接沉淀控制状态链的材料，而不是只停留在工具宣传或自动化常识。论文中的输入 `I1-I6`、输出 `Q1-Q5`、reserve/operation/user 三个层级的液位联动，以及 ready/off/low/full 几种结果步骤，都让它更像一个真实控制器说明文，而不是单纯的系统背景。

## 对我们为什么有用

这篇论文的价值在于，它为 `🌡️` 方向补入了一类典型但不空泛的多罐液位顺序控制样本。相比只写“低液位启泵、高液位停泵”的单水箱短文，这里至少有三个互相关联的受控对象，并且每个对象的阀门或泵动作都不一样。这样整理出来的状态机描述，不会只是一个单一阈值回路，而更接近工业现场里的联锁控制逻辑。

另外，论文把输入输出映射直接写在正文里，这对后续结构化尤其有帮助。`I1-I6` 与 `Q1-Q5` 这种明确编号，能够让后续数据集不仅保留“状态/动作”的自然语言，还能进一步保留一点工程实现语义，例如某个罐体的低液位如何对应到泵停机，某个上液位如何对应到阀门关闭。这种文本对状态机生成和 guard 抽取都比较友好。

## 如果需要人工细读，建议怎么读

人工重读时，建议先把第 3 页的 block diagram 和第 4 页 `3.2 Equipment's Used` 连起来读。第一遍的重点不是去抠罐体容积数字，而是搞清楚三类罐体分别承担什么角色、哪些输入属于哪个罐体、哪些输出是泵、哪些输出是电磁阀。把 reserve tank 的 dry run 保护、operation tank 的上下限调节和 user tank 的恒定液位控制三段先拆开看，再合回整套系统。

第二轮再去读第 5-6 页的 `Step 1` 到 truth table，把这些动作和前面的设备说明对齐，确认系统有哪些稳定状态和触发条件。如果后续要重写 `STM.md`，优先保住“主开关 ready/off + reserve 低液位/高液位 + operation 下限/上限 + user tank 恒位”这条主链；背景综述和 PLC 一般介绍可以放到最后再看。
