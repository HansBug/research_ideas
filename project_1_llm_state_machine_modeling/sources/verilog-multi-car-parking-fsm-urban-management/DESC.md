# 智慧停车与车位管理 / Verilog-Based Multi-Car Parking System Using Finite State Machines for Urban Parking Management

## 论文在讲什么

这篇论文讨论的是城市停车场里的多车位门禁与容量管理问题。作者把目标系统写成一个基于 Verilog 和 FPGA 的 multi-car parking system，强调它不是单纯显示剩余车位的监测平台，而是要把车辆到达、认证、放行、满位拒绝和状态显示这些动作统一交给一个有限状态机来处理。文中默认的实现平台是 Xilinx Vivado + ModelSim，控制对象则是一个最多支持四个车位、可继续扩展的停车场入口控制器。

对我们最重要的部分，是论文把停车控制链写成了显式五态结构。正文明确点名 `IDLE`、`WAIT PASSWORD`、`RIGHT PASS`、`WRONG PASS` 和 `STOP`，并且把入口传感、认证结果、`carcount` 容量判断、gate 放行和 LED / display 更新串到了同一条控制链上。也就是说，这篇文献提供的不是“停车系统会更智能”这种泛泛结论，而是一条可直接转写成 `EFSM + T0` 描述的工程控制流程。

## 控制系统在文中的位置

停车控制器本身就是本文的主体，不是为了验证某种通用算法而顺手加的例子。作者从摘要开始就在讲 multi-car parking system 的设计目标，后面把核心篇幅放在 `System Design and FSM Architecture`、状态图和 `carcount` 容量逻辑上，说明这篇文章的真正价值就是把停车场门禁控制如何离散化表达出来。

从 `sources/` 的角度看，这种对象很适合作为停车领域的停车场基础设施样本。它和已有的“轨迹规划型自动泊车”不一样，关注的是停车场入口门禁、认证和容量更新，而不是车辆连续运动轨迹。因此它能够补齐 `🅿️` 领域里更偏离散工程控制的一类表达，也能为后续“停车场门禁 / 车位状态 / 放行拒绝”这类自然语言状态机样本提供可追溯原文。

## 对我们为什么有用

当前 `🅿️` 方向虽然已经有一些停车相关样本，但不少都偏向轨迹规划、模糊控制或泊车辅助，本轮更需要的是门禁式、容量式、事件驱动式的离散控制器。这篇论文正好满足这一点：状态命名清楚，输入来自 entry sensor 和认证结果，扩展变量是 `carcount`，输出则是 gate 开启与 occupancy status 更新，控制闭环非常适合抽成训练用的 EFSM 文本。

它还有一个现实价值，就是便于和库里其他停车样本做分层对照。一类是“停车轨迹/泊车动作”样本，另一类是“停车场基础设施”样本。后续如果要做领域平衡或按控制对象分桶，这篇文献更应该归到后者。即便它和库内已有停车门禁样本在主题上接近，它仍然提供了另一个可追溯版本，能帮助后续判断哪些停车控制表达是真正稳定的公共模式，哪些只是个别论文的写法差异。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看摘要和 `A. System Design and FSM Architecture`，只抓四件事：系统解决的是什么停车问题、它到底控制的是入口门禁还是车辆轨迹、五个状态分别是什么、容量判断靠什么变量完成。确认这四件事之后，再直接跳到状态图和围绕 `carcount` 的说明，优先圈出 प्रवेश检测、认证成功/失败分支、gate 开启动作、display/LED 更新动作以及满位拒绝规则。

像前面的相关工作综述、对 IoT/YOLO/Fuzzy parking 的泛化讨论、以及文末偏实现平台与资源消耗的说明，可以放到第二轮再看。第一次回原文最重要的不是看 FPGA 资源表，而是把状态名、触发条件、变量和动作主链读稳；即使以后 `STM.md` 需要重写，只要按这条阅读路线回去，很快就能重新恢复完整的停车控制链。
