# 气动道口栏杆 PLC 控制 / Palang Pintu Kereta Api Pneumatik Otomatis Berbasis PLC Omron CP1E-NA20DR-A

## 论文在讲什么

这篇论文讨论的是一个无人值守铁路平交道口的自动栏杆系统。作者使用 PLC Omron CP1E-NA20DR-A 作为控制核心，在道口两侧各放一枚 proximity 传感器，并用气动执行机构、sirene、灯光和 solenoid 完成列车接近时的告警与栏杆升降。

和很多只停留在“检测到列车就关门”的简单项目不同，这篇论文把控制器写成了一个明确的四状态图，还把两个方向上的行为都测试了一遍。这样一来，它不仅说明了装置能工作，还把状态迁移顺序说清楚了。

## 控制系统在文中的位置

控制系统是文中的核心对象。第 2-4 页从系统设计、算法流程写到状态图，直接说明第一枚传感器触发后系统如何进入告警、关闭和恢复三段链路；第 4-5 页再用 PLC 程序和气动回路来说明这些状态是如何落地的。

从样本库角度看，这篇论文的价值并不在复杂算法，而在状态表达足够干净。`STA / STB / STC / STD` 的四状态图和 `T0-T6` 迁移关系，已经是非常适合 project 1 做离散状态机抽取的表达方式。

## 对我们为什么有用

`🚆` 方向已有不少联锁、进路和道口论文，但其中能同时满足“对象具体、状态图明确、时间窗口明确、双向测试完整”的样本并不多。这篇论文恰好补上了比较工程化的平交道口栏杆控制器案例，而且是相对简单、状态边界清晰的那一类。

它还为文库增加了一条很有用的模式：先检测来车，再进入保护，再等待另一侧传感器确认列车离开，最后恢复通行。这种跨两枚空间传感器的顺序控制，对后续训练模型理解“首触发关闭、次触发恢复”的链式状态机非常有帮助。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看第 3 页的算法流程和第 4 页的状态图，把四个状态及其迁移条件先钉住。然后顺着第 4-5 页把 `T1/T2/T3/T5` 与两次 `3` 秒执行窗口、solenoid maju/mundur、sirene/lampu 的对应关系补全，这样基本就能重建整个控制器。

如果想确认系统是否真的是双向对称的，再看第 8 页的测试表即可。那张表已经把 `S1` 先触发和 `S2` 先触发两种方向都列了出来，比只看前面的示意图更适合做最终一致性核对。
