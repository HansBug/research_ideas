# 红外触发、延时停机与安全制动扶梯控制 / Perencanaan Eskalator Lantai Satu ke Dua pada Gedung Direktorat Politeknik Negeri Samarinda dengan Kendali PLC

## 论文在讲什么

这篇论文围绕楼宇扶梯的 PLC 自动控制展开，当前 `STM.md` 抽到的核心对象是“楼宇机电领域的 PLC 扶梯乘客感知与安全制动控制系统”。如果只抓一句话理解它的主体，可以先把它看成：这是一个在检测到乘客后自动启动扶梯、在长时间无人后延时停机、并在安全开关触发时立刻制动的扶梯控制器。

从现有条目看，文中的离散控制链主要以 `EFSM（扩展状态机）` 的方式出现，时间语义属于 `T1（工程定时 / 局部定时）`。它的强度不只是“有红外感应”，而是把 `start key -> infrared detection -> main contactor -> star -> delta -> idle timer -> brake` 这条链写得很完整，并明确给出 `100 ms` 和 `10 min` 两个工程时间参数。

## 控制系统在文中的位置

这里的控制系统不是论文中的边角内容，而是整篇设计工作的核心。作者虽然也做了机械长度、功率、齿轮箱和制动器选型计算，但最终真正把扶梯变成“能自动运行、能节能、能在故障时停住”的，是后面给出的 PLC 控制逻辑和工作描述。

更具体地说，原文不只是泛泛提到扶梯有安全开关，而是明确说明红外传感器如何触发主接触器、星三角切换如何借助定时器完成、无人状态下如何经过一段延时才停机，以及安全触发后 `brake` 怎样保持到人工停复位。对 `sources/` 而言，这正是可直接转成状态机语料的部分。

## 对我们为什么有用

对 `sources/` 来说，它补的是 `🏢` 方向里相对少见的“扶梯自动运行与安全制动”样本，而不是已经较多的电梯轿厢调度或自动门控制。当前楼宇机电类样本里，电梯和门控都有较多条目，但扶梯这类“乘客触发 + 节能停机 + 安全锁停”的对象差异度更高。

后续做数据集时，最值得保住的是两类句子：一类是 `infrared detected -> main contactor -> star/delta -> running` 这种阶段推进句，另一类是 `no passenger for 10 minutes -> stop` 与 `safety switch triggered -> brake` 这种 guard 与异常处理句。它们都属于离散控制里非常好用、也很容易做验证剖面的语言模式。

## 如果需要人工细读，建议怎么读

如果后续需要人工细读，建议先看第 1 页 的英文摘要和印尼文摘要，把系统边界、输入和安全目标先抓住；然后直接跳到第 14-15 页 的 `Deskripsi Kerja Rangkaian Kontrol`，这里集中给出了扶梯 1 和扶梯 2 的启动、星三角切换、无人延时停机和 `brake` 锁停逻辑；最后再回看第 13-14 页 附近的 `Diagram Kontrol PLC` 与符号表，把文字描述和 PLC 图对应起来。

像第 2-12 页 里更偏扶梯机械结构、功率、转矩和轴强度计算的内容，第一次人工复核可以放到第二轮。除非要追问执行机构选型是否会反过来影响控制逻辑，否则先把页面 1、14、15 的输入-状态-输出-时间链读稳，就足够重新抽取出高质量 `STM.md`。
