# 铁路平交口规格与验证论文 / Specification and Verification of a Railway Level Crossing

## 论文在讲什么

这是一篇围绕比利时 Infrabel 铁路平交口系统的硕士论文，核心任务是把半形式化功能规格转写成 Event-B 模型，并检验安全性质是否成立。论文的主体当然包含建模和证明，但它的原始输入并不是抽象 benchmark，而是真实铁路平交口的逻辑规格，因此里面保存了不少适合转成状态机样本的控制描述。

对我们来说，最有价值的部分不是证明器怎么工作，而是 Chapter 3 里对平交口状态、输入变量、输出命令和时钟语义的重述。尤其是二类道口的 `7` 态控制机，把栏杆、红灯、白灯、声响和延时变量 `T15 / Ttrans` 连成了一条很完整的控制链。

## 控制系统在文中的位置

这篇论文的控制系统描述既是方法载体，也是被分析对象。作者要做形式化验证，必须先把平交口逻辑细化成可执行的状态更新规则，所以文中的状态、变量和时钟不是随手举例，而是证明活动的前提模型。换句话说，形式化章节之所以成立，是因为控制对象本身已经被展开得足够清楚。

另外，论文同时区分了三类道口和二类道口。三类道口只有开/闭两态，更像轻量基线；二类道口因为加入栏杆，状态会扩展成 `7` 态，并引入 `T15 / Ttrans` 这类工程延时，因此更适合作为主样本。做 `STM` 抽取时，应该明确把焦点放在 richer 的二类模型上，而不是平均摊到两个类别。

## 对我们为什么有用

对 `sources/` 而言，这篇论文补的是 `🚆 + EFSM + T1 + 显式时钟` 的平交口监督控制样本。相比大量偏 `route/resource-flow` 的铁路联锁文献，它提供的是“道口告警与栏杆闭锁”这一类更贴近工程设备控制的状态链，而且变量和状态的边界非常清楚。

它也能帮助平衡当前铁路样本的内部结构。铁路方向已经有不少资源互斥式联锁、进路建立和 route release 逻辑，但带明显局部时钟的道口控制样本相对更少。这篇 thesis 恰好把 `Avert_train -> Barrière_fermeture` 之间的延迟语义写实了。

## 如果需要人工细读，建议怎么读

如果后续要人工复核或重写 `STM.md`，建议先读第 14-16 页的建模总述，先确认系统每个 cycle 的执行顺序，以及输入、内部变量、输出和时钟各自扮演什么角色。然后直接读第 22-25 页的 `3.5.2 2e catégorie`，把 `7` 个状态及其进入条件完整标出来。最后再回到第 27-28 页附近，核对 `T15` 和 `Ttrans` 是如何驱动 `Avert_train -> Barrière_fermeture` 这段关键延时逻辑的。

证明过程、Rodin 使用方式和大量性质分类可以放到第二轮再看。它们对理解论文整体贡献重要，但对当前样本抽取不是第一优先级。我们首先要锁定的是控制对象本身的状态骨架和时钟语义，而不是每条性质的证明细节。
