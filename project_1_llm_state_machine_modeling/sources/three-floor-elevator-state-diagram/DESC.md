# 三层电梯呼梯与选层控制 / Perancangan simulator lift 3 lantai menggunakan diagram keadaan

## 论文在讲什么

这篇论文讨论的是一个基于 `diagram keadaan / state diagram` 方法设计的三层电梯控制器。作者的重点不是做高层调度优化，也不是做乘客流量建模，而是把一个真实可实现的电梯呼梯与选层逻辑拆成状态图，再进一步翻译成 PLC 的 `ladder diagram`。论文前半段给出问题背景，后半段则把“电梯当前停在哪一层、用户从哪一层呼叫、轿厢内选了哪一层、应当驱动上行还是下行”这些离散决策逐条落成状态方程和输出方程。

从我们关心的控制链来看，文中最核心的是两套互补的状态图。第一套负责处理轿厢外部的呼梯请求，第二套负责处理轿厢内部的楼层选择。两套图都围绕楼层按钮、限位开关和 `MOTOR_UP / MOTOR_DN` 输出来组织，因此虽然它是一个教学/实训型 miniature lift 论文，但控制链本身并不空泛，已经能直接看见按钮触发、楼层到达、运动停止这些主状态关系。

## 控制系统在文中的位置

这套电梯控制器就是论文的主案例本体。作者不是为了说明某个抽象建模框架而随手举一个 elevator 例子，而是确实把电梯作为目标系统来组织全文：先讲为什么常见顺序式写法不够系统，再引入状态图，再把状态图翻译成梯形图，最后做实物/模拟验证。也就是说，控制系统本身就是论文的“方法落地对象”。

不过它在文中的角色仍然更偏工程设计与教学实现，而不是复杂系统研究型案例。你会看到作者把大量篇幅放在“怎样把按钮、限位开关和方向输出整理成状态方程”上，而不是展开更复杂的多梯协同、拥塞优化、门控异常恢复或能耗策略。正因如此，它对 `sources/` 的价值主要在于提供一条非常干净、非常可追溯的电梯主控制链，而不是提供新的结构创新。

## 对我们为什么有用

对 `sources/` 来说，这篇论文的价值首先在于“原文双 A 可落地”。它不是只有一张图或一句摘要，而是把外部呼梯和内部选层都拆成可追溯的状态、转移和输出方程，因此适合作为楼宇机电方向中那类“按钮-限位-电机驱动”基础离散控制样本。后续如果需要训练模型学习如何把自然语言控制逻辑改写成状态机描述，这类样本很有帮助，因为输入、状态和输出的对应关系相当清楚。

但它同时也属于明显的电梯趋同簇。文库里已经有多篇 `elevator + PLC + direction priority / hall call / limit switch` 的强相似样本，因此这篇虽然质量过线，仍更适合作为降采样池成员，而不是继续提升电梯主簇权重。它的作用更像“把三层、纯限位、无显式 timer 的轻量写法补齐”，而不是为主集再增加一个新的核心代表。

## 如果需要人工细读，建议怎么读

如果后续需要人工重读，建议先看第 1-2 页的摘要和引言，只确认系统边界是“三层呼梯 + 轿厢内选层 + PLC 梯形图实现”，不要在背景段落停留太久。然后直接跳到第 4-5 页去读 `Gambar 3 / Gambar 4` 以及 `Tabel 1 / Tabel 2`，这里是整篇最关键的部分：外部请求如何映射到 `S1-S6`，内部选层如何映射到 `S7-S12`，以及哪些 `limit switch` 负责结束上行或下行输出。最后再看后续实现和测试页，只用来核对这些状态方程确实被实施到 PLC 程序里。

像文中较前面的背景综述、实训语境说明和较后面的实现展示，可以放到第二轮再看。除非你需要进一步核对具体 PLC 接线、I/O 分配或教学场景，否则第一次人工复核最重要的是先把状态图和转移方程读稳，因为这部分已经足够支撑重新抽取一个完整 STM 条目。
