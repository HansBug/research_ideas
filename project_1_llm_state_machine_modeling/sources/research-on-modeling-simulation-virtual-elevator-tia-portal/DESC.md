# 六层虚拟电梯 PLC 控制链 / Research on Modeling and Simulation of Virtual Elevator System Based on TIA Portal

## 论文在讲什么

这篇论文讲的是一个基于 `TIA Portal V17`、虚拟 `PLC` 和虚拟 `HMI` 搭建的六层电梯控制系统。论文目的不只是做界面展示，而是把呼梯、轿厢运行、平层停车、门控、夹人和超重报警这些典型电梯控制功能放进一套可仿真的 `PLC` 程序里。

原文最有价值的部分，在于它把电梯控制需求拆成几段很明确的程序链：开关门、平层到位、运行方向控制，以及夹人/超重报警。再加上后面的测试表和图示，整篇已经足以恢复出一条完整的 `EFSM + T1` 楼宇机电控制样本。

## 控制系统在文中的位置

控制系统是这篇论文的主对象。前半部分虽然会介绍虚拟控制器和 `HMI` 的搭建，但这些内容最终都是为了支撑那套电梯控制程序的实现和验证，而不是单纯展示软件平台。

我们关心的不是 `TIA Portal` 工具本身，而是电梯如何根据内外呼、当前楼层、目标楼层、门障碍和载重条件决定上行/下行、何时开门关门、何时禁止运行。这些控制链在文中都处于核心位置，并且配有流程图和测试数据支撑。

## 对我们为什么有用

对 `sources/` 来说，这篇论文直接补进了 `🏢` 方向一个原文强度很高的电梯样本。它比只有上下行流程图的轻量电梯稿更完整，因为门延时、夹人重开门、超重禁行、指令消除和平层联动都写到了正文里，而不是只留在图里或实现细节里。

它也适合做状态机自动生成的数据源，因为对象边界清楚、输入输出明确、异常链真实存在，既有标准的 nominal path，也有 obstruction 和 overload 这类安全联锁。后续如果要比较电梯类样本的门控细节、调度粒度和异常处理链，这篇会很好用。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 2-3 页里关于 PLC 输入/输出刷新和系统结构的说明，把系统边界、门机、曳引机、楼层显示和内外呼信号先定下来。然后直接读第 6-10 页的门控、平层、方向和夹人/超重几段，把“请求 -> 运行 -> 平层 -> 开门 -> 延时 -> 关门 / 重开门 / 禁行”这条主链抽稳。

最后再看第 11-14 页的测试表和结论，用来核对外呼服务、内呼服务、平层到位和异常报警有没有在场景里真实跑通。像虚拟控制器安装与 `HMI` 选型这类平台搭建细节，可以放到第二轮再看，不影响先恢复主控制链。
