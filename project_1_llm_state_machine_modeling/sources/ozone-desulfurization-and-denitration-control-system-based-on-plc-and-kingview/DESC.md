# 过程与环境控制 / Design and implementation of ozone desulfurization and denitration control system based on PLC and kingview

## 论文在讲什么

这篇论文针对锅炉烟气治理系统，讨论如何把臭氧喷射、脱硫塔循环、碱液配置和监控报警整合到一套 `PLC + Kingview` 控制系统中。作者先从现有锅炉尾气治理设备出发，说明为什么要升级到臭氧脱硫脱硝一体化方案，然后把系统拆成臭氧发生、脱硫脱硝循环、碱液制备、报警和人机交互等多个模块。

论文的重点不是化学机理本身，而是这些模块如何被 `PLC` 串起来做实时监控和自动调节。原文持续围绕烟气流量、液位、压力、温度、`pH` 和 `NOx` 浓度来组织控制逻辑，因此它呈现的是一条比较完整的工程监督链，而不是抽象的工艺框图。

## 控制系统在文中的位置

控制系统是这篇文章的核心叙事对象。作者把硬件设计、软件流程、触摸屏交互和自动运行逻辑都写成了“控制系统如何工作”的展开，控制器并不是为了支撑别的方法验证而临时引入的案例。

对我们最关键的是，文中同时给出了初始化等待、手动/自动模式选择、阈值触发的加碱和补液链、主备喷射泵切换、以及异常报警处理。这种写法非常接近可直接抽取状态、条件和动作的控制描述，所以它比很多只谈“环保工艺升级”的论文更适合进入 `sources/`。

## 对我们为什么有用

这篇论文给 `🌡️` 方向补进了一种不同于“定时批处理”或“连续 PID 调节”的过程监督控制样本。它更像一个带有多模块监控、阈值判断和主备切换的现场控制器，尤其是 `NOx` 过高时启用主喷射泵、主泵故障时自动切到备用泵、数值恢复后自动关闭喷射并回到下一轮循环，这条链很适合沉淀为 `EFSM + T0` 样本。

它的另一个价值是保住了工程实现层的传感器和执行器词汇。后续如果做人类需求描述到状态机的映射，这篇文章能提供一类非常典型的“监测量 -> 阈值判断 -> 泵/阀动作 -> 告警/回路等待”表达模式。

## 如果需要人工细读，建议怎么读

建议先看第 `3.1.2` 到 `3.1.6` 节，把臭氧发生、脱硫塔循环、碱液配置和报警模块的输入输出关系先读清楚。随后直接跳到第 `4.1` 节，把初始化、等待、手动模式和自动模式的主流程重新串起来，这一步最容易恢复出状态和转移关系。

第一次人工复核时，不必把工艺背景或环保政策说明读得很细。更值得优先确认的是：哪些变量在驱动控制切换、操作员在手动模式下可以触发哪些动作、自动模式下主泵和备用泵怎样切换、以及报警是在什么条件下发出的。把这些点读稳，基本就能独立重做 `STM`。
