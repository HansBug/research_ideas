# VROOM 缩比无人车高层行为监督器 / How to Win Bosch Future Mobility Challenge: Design and Implementation of the VROOM Autonomous Scaled Vehicle

## 论文在讲什么

这篇论文围绕 `Bosch Future Mobility Challenge` 的一辆 `1:10` 缩比无人车展开，整体上讲的是一套面向嵌入式硬件约束的自动驾驶软件硬件协同设计。全文不仅介绍了感知、通信和执行层，还把行为选择层单独拿出来讲，说明这辆车如何在赛道上完成车道保持、路口通行、环岛、泊车、超车、行人避让和速度调节等任务。

对我们真正重要的，不是论文里的模型训练或图像处理细节，而是它把高层行为决策明确写成了一个以 `Lane Keeping` 为核心的状态机。作者还没有停在“有一个高层 FSM”这一步，而是继续展开了 `Parking` 和 `Overtake` 两个子流程，把停车位检测、轨迹计算、修正动作，以及左变道、超越、回到右车道这些阶段性的控制逻辑都写了出来。

## 控制系统在文中的位置

这篇里控制系统描述是文章的核心构成之一，不是附带案例。整套系统被分成 `Input / Perception / Control / Output` 四层，而 `Control` 层中的 `FSM` 就是把感知结果转成行为动作的关键部位。也就是说，控制器在文中并不是为了展示某个形式化方法才被引入的，它本身就是这辆车能完成比赛任务的中枢。

同时，这篇控制器描述也不是单纯的平面流程图。高层用 `Lane Keeping` 串起各种任务状态，底下又有停车和超车子流程与连续转向控制耦合，因此它比许多只在摘要里提一句“我们用了 FSM”的自动驾驶论文要实得多，能真正支撑 `HSM + T1` 级别的样本整理。

## 对我们为什么有用

这篇对 `sources/` 的价值在于，它提供了一个很典型但又细节充分的自动驾驶高层监督器样本。库里已经有一些城市道路行为规划、换道控制和任务管理条目，但这篇的优点是结构完整：顶层优先级、检测触发、局部反应延迟、停车子流程、超车子流程都在同一篇里有比较清晰的叙述。

它还补了一个很适合 `project_1` 数据集的语言模板，即“默认状态 + 优先级切换 + 子任务阶段展开 + 与连续控制耦合”的写法。后续如果要比较简单 `FSM`、带数值 guard 的 `EFSM` 和具有子流程展开的 `HSM` 在自然语言表达上的差异，这篇会是一个相当稳定的汽车领域参照样本。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看 `4.3 Logic Implementation`，把 Figure `7` 对应的高层行为选择机读出来，确认默认状态、优先级顺序以及哪些触发会把系统从 `Lane Keeping` 切到别的任务状态。然后接着看第 `21` 页关于分类结果如何触发动作的段落，特别是 `vehicle / pedestrian / traffic light` 的分支和 `0.3 ± 0.1 s` 的检测反应约束。

之后重点看 `4.4.6 Parking Navigation` 和 `4.4.7 Overtake Procedure`，这两节是重做 `STM.md` 时最有价值的部分，因为它们给出了子流程的阶段划分和连续转向的切换边界。更前面的感知算法、路径拟合和部署细节可以第二轮再看；第一次回读最重要的是把高层状态机和两个典型子机读稳。
