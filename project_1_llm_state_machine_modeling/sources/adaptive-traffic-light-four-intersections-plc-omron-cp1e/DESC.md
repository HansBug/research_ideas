# 四路口 PLC 自适应交通灯控制 / Desain Sistem Kontrol Traffic Light Adaptif pada Empat Persimpangan Berbasis PLC Omron CP1E

## 论文在讲什么

这篇论文讨论的是一个四路口交通灯自适应控制系统，目标是解决固定配时在高峰期对拥堵方向不敏感的问题。作者使用 PLC Omron CP1E 作为主控制器，在每条进口道上布置三枚队列传感器，再在路口中央增加两枚总堵塞传感器，让系统能根据排队长度和路口中央是否阻塞来调整信号灯行为。

文章并不是只给一个概念性的“智能交通灯”想法，而是把控制流程、硬件组成、配时表和等待时间分析都落了下来。正常模式、分级拥堵模式和总堵塞模式三层控制关系在文中是清楚的，尤其适合拿来做“带工程定时量的离散控制流程”样本。

## 控制系统在文中的位置

我们关心的控制系统就是论文主体本身。第 4 页到第 7 页集中给了系统工作层级、传感器布局、I/O 规模和时间分配表，第 11 页到第 12 页进一步给了传感器持续遮挡条件、最长等待时间和总堵塞恢复条件。

也就是说，这篇论文不是借交通灯举例展示某种抽象算法，而是在直接说明一套可实现的 PLC 交通灯控制器。它的状态语义虽然没有被正式画成自动机，但“模式切换 + 传感器守卫 + 绿灯延长 + 全红封锁”已经足够稳定地整理成 `EFSM + T1` 描述。

## 对我们为什么有用

`sources/` 里交通灯样本很多，但双 A 样本真正有用的，不是泛泛提一句“按密度调时长”，而是同时给出传感器条件、模式层级、定时表和队列等待边界。这篇论文在这四点上都给得比较集中，尤其是 `7/12/17/22` 秒的分档配时和 `45/81` 秒等待范围，很适合训练模型识别“离散守卫导致的局部时间延长”。

它对文库平衡性的价值还在于，这不是应急车辆优先或图像识别那一路交通灯论文，而是更典型的 PLC 工业实现视角。对后续 project 1 的状态机自动生成任务来说，这类“规则简单但状态切换完整”的工程样本通常比高度算法化的交通优化论文更稳。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看第 4-5 页，把系统分成哪三层、每层各自依赖哪些传感器先读清楚。然后直接跳到第 7 页的时间表和第 11-12 页的传感器激活条件，把 `7/12/17/22` 秒、单传感器持续 `5` 秒、总堵塞持续 `1` 分钟和恢复 `30` 秒这些时间量先摘出来，这样就能快速重建主控制链。

第 9-10 页的梯形图和单车道流程图可以作为第二轮核对材料，用来确认实现级细节是否和正文文字一致。背景综述和前人工作对理解“为什么要做自适应交通灯”有帮助，但对重做 `STM.md` 并不是第一优先级。
