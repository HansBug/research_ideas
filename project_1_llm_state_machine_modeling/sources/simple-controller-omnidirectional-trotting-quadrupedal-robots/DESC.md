# 四足机器人定步时对角步态调度器 / A Simple Controller for Omnidirectional Trotting of Quadrupedal Robots: Command Following and Waypoint Tracking

## 论文在讲什么

这篇论文研究的是一种计算量较低的四足机器人全向 trotting controller，目标是在不占用太多算力的前提下，让机器人还能把计算资源留给感知和规划。作者没有走复杂 MPC 路线，而是把低层步态控制拆成一个简单的腿部调度状态机、参考轨迹生成器和关节控制器。

对 `sources/` 来说，最值得保留的是它把 trot gait 的调度逻辑写得相当直接：哪些腿组成对角组、何时按固定步时切换、切到 stance 和 swing 后各自使用什么扭矩组合。这种写法非常接近工程实现里的可执行状态机说明。

## 控制系统在文中的位置

状态机在文中承担的是低层 gait scheduler 的职责。高层控制只负责给出 `vx / vy / w` 和航点跟踪命令，真正决定哪两条腿当前支撑、哪两条腿当前摆动，以及何时切换的是这个有限状态机。它不是附带说明，而是低层控制总览的一部分。

这种位置很适合样本库，因为它让我们拿到的是一个真实机器人控制器中的离散调度链，而不是泛泛的 locomotion 背景描述。原文还明确说明了该状态如何喂给轨迹生成器和扭矩块，这使建模边界非常清楚。

## 对我们为什么有用

这篇论文补入的是一个典型的 `FSM + T1` 步态调度样本。仓库里已有不少四足与腿式机器人案例，但很多偏向接触反射、复杂层次逻辑或方法比较；这篇论文的价值在于它足够简单而完整，能稳定提供“固定工程步时 + 对角腿组切换 + 状态依赖输出”的清晰表达。

后续做数据集时，这类样本很适合当作定时切换型 gait scheduler 的基准样本。它能够帮助模型学会把工程里的步时 `ts`、腿组配对和状态依赖扭矩分配识别成显式状态机，而不是误判成纯连续控制。

## 如果需要人工细读，建议怎么读

如果要人工重读，建议先看第 1 页摘要，把 `leg scheduler`、`fixed step time` 和命令跟踪/航点跟踪的总目标先读清楚；然后重点看第 3 页 `3.2 Overview` 与第 4 页 `3.10 Single Leg Implementation`，这里已经覆盖了状态机的角色、对角腿组、固定步时切换和 swing/stance 对应输出。

更后面的高层模型和反馈线性化部分可以放到第二轮阅读，它们主要解释如何生成上层速度命令，而不是低层状态机本体。若以后需要重做 `STM.md`，最重要的是保住 `FR-RL / FL-RR` 对角组、`ts` 触发的切换条件，以及 stance/swing 两类腿的不同扭矩组合。
