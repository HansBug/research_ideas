# 室外搜窗到室内灭火再返航的分层任务监督器 / Autonomous Firefighting Inside Buildings by an Unmanned Aerial Vehicle

## 论文在讲什么

这篇论文研究的是一架微型无人机怎样在室外接近建筑、找到可进入的窗户、穿窗进入室内、搜索火源、执行灭火，并最终安全离开建筑并返航。文章整体当然也涉及感知、建图、定位、避障、灭火机构等多个子系统，但它真正想证明的是：这些子系统如何被组织成一套能在真实场景中跑通的自治消防任务系统。

和很多只讲单项感知或规划模块的无人机论文不同，这篇把任务主链写得非常完整。作者明确说整套行为结构被构造成 `hierarchical state machine`，而且还把主状态机、`outdoor phase`、穿窗子机和 `indoor phase` 分开说明。所以它不是“有若干模块的系统论文”，而是一篇确实公开了 mission supervisor 结构的 `UAV + HSM` 样本。

## 控制系统在文中的位置

这里的控制系统描述就是论文把整套消防系统串起来的骨架。无论是窗户检测、室内探索还是火源定位，本质上都不是孤立运行，而是被高层状态机安排在“什么时候开始、什么时候失败回退、什么时候切到下一阶段”的任务框架里。作者甚至明确指出，这套状态机是为了解决子系统错误顺序和并发操作导致的失败问题而设计的。

这篇最值得保留的地方，在于它不只给 nominal path。原文清楚写出若窗户估计丢失时进入 `Escaping` 回到窗前悬停、若室内找火失败则继续探索、若火源在灭火过程中丢失则暂停喷射并重新搜索、若最大飞行时间耗尽则直接落地。这些恢复与回退链对构建高质量状态机样本非常关键，也是许多任务型 UAV 论文里最容易缺失的部分。

## 对我们为什么有用

对 `sources/` 来说，这篇的意义很大，因为它补进了一类高质量的“复杂任务监督器”样本。航空航天方向已有不少飞行模式管理、安全模式和任务管理论文，但这篇更进一步，把 outdoor-indoor transition、window flythrough、室内探索和灭火操作都纳入一个统一的层次控制链里，而且主链和异常链都公开得比较完整。

它还补充了一种非常适合后续自动建模的数据形态：上层是任务阶段，下一层是阶段内子机，再往下才是感知和控制模块。对于希望从自然语言里恢复层次状态机的任务来说，这篇比只给一张飞行模式图的论文更有层次感，也更能体现“状态机如何协调多个能力模块、如何显式表达 recovery path”。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 `10` 页 `F. High-Level Behavior Control`，先把主状态机读稳：起飞前检查、自动起飞、`outdoor phase`、`indoor phase`、返航降落。这个部分能快速确认论文不是把状态机停留在示意层，而是真正用它来管理整套系统任务流。

接着顺着第 `10-12` 页读 `outdoor phase`、穿窗过程和 `indoor phase` 三段说明，重点圈出 `2 m` 窗前定位、`Escaping`、火源丢失后的重新探索、灭火剂耗尽后的出窗与返航这些关键转移。至于热成像、窗口检测、LIDAR、灭火嘴标定等子系统细节，可以放到第二轮再补；第一轮只要把任务主链和回退链抓住，就足够稳定重建这篇论文里的核心状态机样本。
