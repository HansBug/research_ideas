# 基于 Verilog 的半自动交通灯安全状态控制 / An FPGA-Based Semi-Automated Traffic Control System Using Verilog HDL

## 论文在讲什么

这篇论文讨论的是一个 FPGA 实现的四路口半自动交通灯控制器。作者不是只做一个简单红黄绿轮转，而是把传统交通相位、人工介入的应急放行、以及两者之间的 `Safe State` 过渡状态一起纳入同一个 Mealy 状态机设计。

它的核心贡献不在于算法高级，而在于控制链条写得直接而完整：路口结构、每路六类灯、传统相位的 `60 sec / 15 sec` 时序、应急状态的特殊放行方式，以及 `Safe State` 为什么要插在普通状态和应急状态之间，都在文中给了明确表格和流程图。

## 控制系统在文中的位置

状态机就是本文的主体实现方式。论文前半部分先说明使用 Mealy machine 和 sequential encoding，随后第 3 节直接进入状态分类、定时表和 flow chart，没有把状态机放在附录或仿真细节里。这意味着我们要提取的离散控制逻辑，正是作者表达系统设计的中心内容。

对于 `sources/` 来说，这篇论文最大的价值是它给了一个很清楚的“正常轮转 + 应急插入 + 安全过渡”链条。很多短篇交通灯论文只有固定相位轮转，而这里多了一个有明确安全目的的中间状态，使它比普通 fixed-cycle controller 更值得保留。

## 对我们为什么有用

`🚦` 方向虽然样本不少，但能把应急 override 和安全过渡都写清楚的双 A 条目并不多。这篇稿子正好补了一个很工程化的 `FSM + T1` 例子：时间明确、guard 明确、状态切换顺序明确，还保留了 zebra-crossing 信号这一类额外执行器信息。

它也适合做“从时序表恢复状态机”的训练样本。因为正文不是只给自然语言叙述，而是同时给了传统状态表、应急状态表和 Safe State 表，这对后续做结构化抽取非常友好。

## 如果需要人工细读，建议怎么读

人工重读时，建议直接看第 3 节。先抓 Table 1 的传统状态轮转，再抓 Table 2 的 emergency state，最后看 Table 3 和 Fig. 2，确认 `Safe State` 的插入位置。把这三块串起来之后，这篇论文的控制逻辑基本就已经完整了，电路原理图和实现工具可以放到第二轮再看。
