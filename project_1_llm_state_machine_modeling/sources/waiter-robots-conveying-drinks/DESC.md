# 送饮料 waiter robot 运动策略状态机 / Waiter Robots Conveying Drinks

## 论文在讲什么

这篇论文聚焦的不是普通餐厅服务机器人“能不能导航”，而是一个更具体的问题：机器人如何在送饮料和汤类这类容易洒出的任务中，改用更平滑、更符合载荷特征的运动方式。作者因此提出了一套基于 `ROS SMACH` 的状态机，让机器人在空载、送固体食物和送液体饮料这几类任务之间切换不同的速度轮廓。

正文把问题讲得很工程化。它一方面给出三种速度行为 `step / ramp / S-velocity`，另一方面把这些行为如何通过 `Dock`、`Cruise`、`Throttle`、`Brake` 和 terminal docking 这些状态组织起来说清楚，还补上了 `0.5 s` 加速过渡、`1 ms` 发布周期和约 `1 s` 的响应时间。因此，这篇论文真正的重点是一个带局部时序约束的运动策略监督器，而不只是“做了一个 waiter bot”。

## 控制系统在文中的位置

控制系统描述在文中占主导地位。实验、结果和讨论几乎都围绕 `VelProSMACH_V2.py` 的行为状态机展开，关心的是不同状态和速度策略是否能让机器人更平稳地送餐、减少溢洒并提升 docking 精度。它不是在讲高层商业流程，也不是在讲某种通用 ROS 框架，而是在讲机器人运动策略如何被离散地组织和切换。

这也让它和很多只讨论轨迹平滑或低层控制的机器人论文不同。这里的离散控制描述足够明显，尤其是 `Dock` 作为策略切换 hub，以及 `Cruise/Throttle/Brake` 对剩余距离、目标位置和障碍物的响应关系，都能直接回收到状态机语料里。

## 对我们为什么有用

这篇对 `sources/` 的主要价值在于，它提供了一种不太像传统工业顺序控制的状态机写法：状态迁移并不是围绕机械工位或任务步骤，而是围绕运动风格、载荷类型和局部速度响应来组织。对后续数据集来说，这种“策略型控制器”有助于扩展样本多样性。

它还补充了一类带工程时间参数的服务机器人样本。相比单纯的 `FSM + T0`，这篇把加速度上升时间、命令发布周期和反应时间都写进了控制描述里，因此很适合用来研究自然语言中如何表达 `T1` 级局部时序，以及如何从描述里恢复“状态在加速阶段不可中断”这种工程语义。

## 如果需要人工细读，建议怎么读

人工细读时，建议直接从第 `8` 页开始，看 `3. Designing the Waiter Robot Motion Behaviors` 和 `3.1 Motion Behavioral Strategies`。先把 `step/ramp/S-velocity` 各自对应的任务场景搞清楚，再抓住 `Dock` 如何根据 payload 把机器人送进 `Strategy 1/2/3`，以及返回等待点时如何回到 `Strategy 1`。

之后重点看第 `10-11` 页 `Reactive and Non-Reactive States for a Multispeed Design`，这里最适合重做 `STM.md`，因为 `Cruise`、`Throttle`、`Brake`、terminal docking 和 `0.5 s / 1 ms / 1 s` 这些关键信息都集中在这里。第一次回读时可以暂时少看更外围的实验图表；如果只是核对样本强度，先把状态机和局部时序读稳最重要。
