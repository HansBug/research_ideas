# Priority 停车引导与密码放行控制 / Modelling Of Smart Car Parking System Using Plc

## 论文在讲什么

这篇论文讨论的是一个基于 PLC 和 SCADA 的 smart parking system，目标不是做纯粹的车位信息展示，而是把“入场、引导、占位保护、出场认证”整成一条完整的自动化停车控制链。作者把系统设计成四车位原型，强调 priority-based slot filling、唯一 security code、motion sensor 保护和远程监控，试图用较低成本解决大型公共建筑停车区常见的排队、找位和安全问题。

原文的控制描述比较成体系。停车位按 `45°` 布局，每个车位带 motion sensor；车辆进入后，停车引导支路打开，箭头形 LED 指向当前优先级最高的空位；车停稳后，系统把该位切换到受保护状态；取车时必须先经过 `Unpark` 与 passcode screen；密码连续输错则触发 security breach alarm。也就是说，这篇论文并不是把停车当作单个门禁开关，而是把整个停车设施的主运行链组织成了一个可建模的离散控制对象。

## 控制系统在文中的位置

停车控制逻辑是全文主角。引言、方法、结果和 SCADA 讨论全部围绕同一条控制链展开：如何给进入车辆分配车位，如何在占位期间保护车辆，如何授权释放车位，如何在异常访问时报警。虽然论文也提到 PLC/SCADA 的工程实现和软件界面，但这些内容不是独立主题，而是为了落地这条停车监督逻辑服务。

这对 `sources/` 的价值很直接，因为我们需要的是“可被语言描述出来的控制系统状态链”。这篇文章恰好给了比较完整的停车设施语义：优先级、车位互斥、密码认证、占位保护、时间窗口、报警。和很多只讲 HMI 或空位显示的停车短文相比，它的控制主链更完整，更适合作为 `🅿️` 方向的数据集样本。

## 对我们为什么有用

对当前文库来说，这篇论文补的是 `🅿️` 方向里相对稀缺的“停车引导 + 安全取车”组合链。现有停车样本有不少集中在轨迹泊车、塔库、门禁或纯空位检测，而这篇材料把 priority-based guidance、slot occupancy、passcode release 和 two-alarm security branch 明确串在一起，能补强停车设施控制的离散监督语义。

它还保留了几个对状态机建模很友好的工程细节，比如 `10 s` 的 motion sensor 抑制窗口、`20 s` 的密码重试窗口、优先车位填充顺序，以及“绿灯代表可用、红灯代表已满/阻塞”的输出语义。这些都不是背景说明，而是直接参与控制判定和状态切换的事实，因此很适合沉淀成 `EFSM + T1` 的自然语言样本。

## 如果需要人工细读，建议怎么读

如果后续要人工细读，建议先看第 `2-6` 页的 `Methodology` 和 `Results and Discussion`。第一次阅读优先抽稳四件事：入场后 parking assistance 如何启动、priority method 怎样决定空位引导、passcode 和 motion sensor 如何保护已停车辆、错误密码和非法侵入分别怎样触发报警。把这四条链读清楚，就足够重建一版高质量的停车 STM。

像前面的停车问题背景、后面的 PLC/SCADA 配置步骤和通用设备介绍可以放到第二轮再看。它们能帮助理解工程实现，但对“系统有哪些状态、哪些 guard、哪些输出和异常分支”并不是最关键的信息源。第一次人工复核时，最值得花时间的仍然是 entry / guidance / parking / unpark / alarm 这条主控制链。
