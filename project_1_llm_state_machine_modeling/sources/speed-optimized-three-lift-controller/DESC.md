# 双梯优先分配与门控计时控制 / Speed Optimized Implementation for Three Lift Controller

## 论文在讲什么

这篇论文讨论的是一个 Verilog 电梯群控器，重点是如何在多个请求之间分配电梯、处理开关门、以及在门阻挡和门停留计时存在时保持系统可运行。虽然题名写的是 `Three Lift Controller`，但正文里真正展开的详细设计是一套双梯、双层场景下的离散控制逻辑。

它不是从连续电机控制或调度优化切入，而是直接围绕控制状态机写请求输入、优先规则、门计时和位置切换。对样本库来说，真正有价值的是正文后半部分的状态图、状态说明和测试波形，而不是前面对 FSM / Moore / Mealy 的一般性铺垫。

## 控制系统在文中的位置

我们关心的电梯控制器是这篇论文的主对象。摘要已经把 proximity sensor、obstruction sensor、timer、request flip-flop 和 control state machine 串起来，后面的设计部分则把它落实成默认楼层、优先楼层、开门计时、阻挡检测和请求分配规则。

需要注意的是，文中标题和摘要的“three elevator”表述与详细设计部分并不完全一致。做样本抽取时，应该以后文真正展开的双梯控制链为准，而不是按标题机械外推到三梯群控。

## 对我们为什么有用

这篇论文对 `sources/` 的价值，在于它补的是 `🏢` 方向里一种偏 HDL/门控计时风格的电梯控制样本。库里已有若干 PLC 电梯案例，但这篇更强调单梯六状态 Moore 机与双梯请求分配的组合，对比现有 PLC 样本能补出另一类实现语言和控制表达方式。

此外，它把 `20 second` 门停留、阻挡保持开门、默认优先楼层、请求归属和“更近电梯可接管请求”的规则写得比较直。后续做数据集时，这种“门控 + 调度 + 传感器 + 局部 timer”的组合很适合保留。

## 如果需要人工细读，建议怎么读

人工细读时，先看第 1-3 页摘要与 `Designing of Elevator`，把请求输入、优先规则、默认状态和 `20 second` 门停留规则先固定下来。然后直接跳到第 5-6 页 `State Diagram`，这是最关键的部分，需要把 `S0-S5` 分别对应什么动作、哪些输入触发状态切换、门在什么条件下关闭这些内容读稳。

最后再看第 6-7 页测试案例，用波形说明去验证“优先电梯”和“更近电梯”这两类分配行为是否和状态图一致。中间关于 Moore / Mealy 的通用背景可以第二轮再看，因为它对重建具体控制链帮助有限。
