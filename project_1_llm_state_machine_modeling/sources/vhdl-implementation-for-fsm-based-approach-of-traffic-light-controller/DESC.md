# 双向交通灯三模式定时 FSM / VHDL IMPLEMENTATION FOR FSM BASED APPROACH OF TRAFFIC LIGHT CONTROLLER

## 论文在讲什么

这篇论文研究的是一个双向交通灯控制器的 `VHDL` 实现，重点不是交通优化算法，而是如何把交通灯本身写成一个可综合的 timed FSM。作者把系统拆成 `regular / test / standby` 三种模式，并在常规模式下进一步用 `RG / RY / GR / YR` 四个相位组织灯色切换。

从控制逻辑上看，这篇论文的价值在于它不只给一个“红黄绿轮转”的常识描述，而是把模式切换、输入信号和具体相位时间一起写了出来。对 `sources/` 来说，这正好是一类适合保留的轻量级 `FSM + T1` 交通灯样本。

## 控制系统在文中的位置

交通灯控制器就是文中被实现的主体。论文先用 FSM 基础概念做铺垫，然后马上进入 `FSM FOR TRAFFIC LIGHT CONTROLLER`，给出工作模式、相位定义、状态图和定时表，最后用 VHDL 仿真结果收尾。它不是拿交通灯做一个很轻的教学插图，而是把交通灯当成核心案例。

这使得我们后续做 `STM.md` 时能直接抓到需要的控制事实：系统有哪些模式、模式内有哪些相位、输入是什么、输出是什么、每个相位持续多久，以及待机模式会把灯切成什么样。原文虽然短，但状态机骨架很清楚。

## 对我们为什么有用

交通信号方向里目前已有不少 `EFSM + T1` 条目，但纯粹以 `FSM` 口径、并把测试模式和待机模式也写进主控制器的样本并不多。这篇恰好补的是一种更基础、更教材化、但又足够完整的定时状态机表达。

它对数据集的意义主要不在复杂异常恢复，而在“明确状态名 + 明确灯色输出 + 明确时长 + 模式切换”。这种形式非常适合给模型学习如何从规范性文本恢复一个小而完整的 timed FSM，而不是只能处理大而散的工程长文。

## 如果需要人工细读，建议怎么读

建议直接读第 `3` 页 `FSM FOR TRAFFIC LIGHT CONTROLLER` 和 `Simulation` 部分，先把 `regular / test / standby` 三模式和 `RG / RY / GR / YR` 四相位读下来，再把 `clk / stby / test` 输入和 `r1 / y1 / g1 / r2 / y2 / g2` 输出对应起来。第一轮人工重读时，重点是确认“哪些转移是 timed only、哪些时间值在 regular 和 test 模式下不同”。

第二轮再看表格和状态图，把 `30 s / 5 s / 45 s / 5 s / 1 s` 这些时长和具体状态逐一对回去。前半部分关于一般 FSM、Mealy/Moore 和 elevator 示例的讲解可以后看，因为它们更多是背景铺垫，不是交通灯控制器自身的证据主体。
