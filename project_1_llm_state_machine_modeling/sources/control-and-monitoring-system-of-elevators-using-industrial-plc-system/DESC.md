# 三梯竞争调度电梯控制 / CONTROL AND MONITORING SYSTEM OF ELEVATORS USING INDUSTRIAL PLC SYSTEM

## 论文在讲什么

这篇论文讨论的是一个工业 `PLC + SCADA` 驱动的三梯控制与监控系统，目标不是只做单梯启停实验，而是把 `103` 层楼宇里的三部电梯放到同一个调度问题下。作者用 `Micro850 PLC`、变频器和 `SCADA` 平台搭了一个可仿真的群控环境，重点解决“谁去响应外呼”“内呼如何插入队列”“轿厢该以什么速度运行”“何时减速、停靠、开关门”这些工程问题。

它的正文不是那类只讲硬件接线或 HMI 画面的电梯短文。真正有用的部分在 `PLC Logic Structure` 之后：作者把外呼竞争、内呼入队、方向标志、速度阈值、停靠协议和门操作时间连续写出来，又用三组队列测试验证了“同方向优先、反方向后置、门操作时间会改变分配结果”这些调度行为。

## 控制系统在文中的位置

这里的电梯控制器就是论文主体，而不是为了论证某种验证方法才附带出现的案例。作者先定义三类任务：外呼分配、内呼入队和轿厢执行控制；随后分别给出每一类任务的输入条件、决策规则和流程图，因此我们关心的离散控制逻辑是正文的主线之一。

更重要的是，这篇论文同时覆盖了“群控分配层”和“单梯执行层”。外呼阶段要比较三部电梯的队列和等待时间，内呼阶段要把目标楼层按方向关系插入合适位置，执行阶段又要处理上/下方向、速度分档、减速阈值和 `6` 秒门操作时间。这使它比普通电梯启停稿更接近一个可恢复的系统级控制样本。

## 对我们为什么有用

对 `sources/` 来说，这篇论文补的是 `🏢` 方向里比较缺的“多梯竞争调度”样本。现有楼宇机电条目里已经有若干单梯门控、停层或安全链样本，但这篇把三部电梯之间的竞争分配和单梯内部队列控制都写了出来，能明显提升电梯方向样本的结构多样性。

它也很适合 `project_1` 的状态机数据建设，因为文中不是只给出“有请求就去响应”的抽象话，而是保留了可直接转写成自然语言状态机描述的关键件：方向、队列、同向优先、反向排后、距离阈值减速、短/长距离两档速度、开关门时间以及队列清空后的回到空闲。后续无论做手工抽样还是让模型学“带变量的工程调度链”，这篇都比薄弱的单梯原型更有价值。

## 如果需要人工细读，建议怎么读

人工细读时，建议先从第 `2-4` 页的 `PLC Logic Structure` 开始，按 `4.1 -> 4.2 -> 4.3` 的顺序读。第一轮要先把三层逻辑分开：外呼竞争怎样比较三梯、内呼怎样插入已有队列、单梯执行怎样决定方向、速度和停靠。只要这三层边界读清楚，后面重做 `STM.md` 时就不容易把调度层和执行层混在一起。

第二轮再看第 `4-5` 页的 `Results of Field Trials`。这里的队列表最关键，因为它们验证了正文前面写的分配规则确实如何落到具体呼叫序列上，尤其是“同方向优先”“反方向后置”和“门操作时间会改变下一次分配”这几条。前面的算法背景综述和模糊控制相关工作可以后看，它们有助于理解群控问题背景，但对恢复当前这篇论文自己的控制链不是首要材料。
