# 主路优先的 Mealy 交通灯延时控制器 / A Reconfigurable Control Mechanism for Smart Traffic Management for Highly Congested Route

## 论文在讲什么

这篇论文处理的是一个非常经典但也非常实用的交通灯问题：主干道车流持续存在，而支路/乡村道路只有在有车时才需要短暂放行。作者选择用 FPGA 上实现的 Mealy 状态机来构造一个可重配置交通灯控制器，并把应急场景与拥堵响应也作为系统目标的一部分。论文不仅给出状态图，还直接给出 Verilog 状态定义、输出映射和状态转移逻辑。

因此，这篇论文的重点不在硬件平台本身，而在于它把一个实际路口的相位切换逻辑写得非常明确：主路默认绿灯；支路来车时，通过黄灯、全红、支路绿灯、支路黄灯的链条完成切换；当支路无车时再回到主路优先。这种写法对状态机抽取极为友好，因为状态、输入、输出和延时常量全都落在正文和代码里。

## 控制系统在文中的位置

交通灯控制器就是这篇论文的主体对象。与那些只展示仿真波形或把状态机作为“实现手段”一笔带过的稿件不同，这篇论文把控制规格、状态表和程序实现紧密放在一起。它先说明为什么主路要默认保持通行，再说明 `X` 传感器如何表示支路来车，最后再通过代码把 `S0→S1→S2→S3→S4→S0` 这条完整相位链固定下来。

换句话说，这篇论文里的控制系统不是背景知识，而是作者真正要设计和验证的工程对象。对于 `sources/` 来说，这类稿件非常理想，因为我们不需要从大量连续控制或优化内容里艰难扒离散逻辑，原文本身已经把状态机的核心元件明明白白写出来了。

## 对我们为什么有用

这篇论文最大的价值，是补进了一条很标准的 `FSM + T1` 交通灯样本。它既有默认优先级，也有基于传感器输入的相位切换，还有通过 `Y2RDELAY` 和 `R2GDELAY` 显式写出的工程定时。相比很多只给相位顺序、不给延时结构的交通灯短文，它更适合进入后续的状态机自然语言数据集。

此外，它也能帮助交通灯方向样本保持内部差异。文库里已有不少四向路口、应急优先或多模式交通灯案例，而这篇更像“主路-支路优先 + 可配置间隔”的控制器。它没有复杂的多路应急协议，但把最基本的优先级交通逻辑写得很清楚，这对于训练模型识别简单但完整的状态机链条同样重要。

## 如果需要人工细读，建议怎么读

如果后续需要人工重读，建议先看第 3-7 页，也就是设计规格、FSM 图和 Verilog 程序三块。先把控制规格里的主路默认绿灯、`X` 传感器、支路有车时的放行原则和四段延时读清楚，然后再去读代码里的 `S0-S4` 定义与 `repeat(...)` 延时转移，这样就能非常快地重建整条控制链。

前面的 FPGA 平台介绍、编码策略和更泛化的交通拥堵背景，可以留到第二轮再看。它们有助于理解实现选择，但对重做 `STM.md` 的优先级不高。第一次人工复核最该确认的是：默认状态是什么、支路来车时如何切换、什么时候保持支路绿、什么时候回到主路优先，以及这些动作的延时是否由显式时钟常量控制。
