# 过程与环境控制 / Automation of Tank Level Using Plc and Establishment of Hmi by Scada

## 论文在讲什么

这篇论文讨论一个基于 `S7-300 PLC` 和 `WINCC` 的液位自动化系统。对象是地下水箱和高位水箱之间的补水过程，作者把传感器、PLC、继电器与电机、以及 HMI 监控界面连成一个完整方案，用来实现液位检测、泵启停和远程监视。

对 `sources/` 来说，最有价值的部分不是 PLC 通用介绍，而是第 3 节里直接给出的控制逻辑：低液位启动、高液位停止、地下水箱低液位时禁止泵运行、`10` 分钟连续运行报警、以及手动启停对自动逻辑的完全覆盖。后面的结果部分又把系统运行状态拆成 `empty / filling / full / draining` 四种情况，进一步补强了控制链可读性。

## 控制系统在文中的位置

这里的控制系统不是方法落地的附属例子，而是论文本身的主对象。第 3 节从设计与实现角度说明液位控制器如何工作，第 4 节又用变量表和 HMI 状态展示其运行结果，因此状态切换和执行动作都处在正文中心。

更具体地说，论文关心的是“如何让 PLC 根据液位与手动开关做决策并把结果同步给 HMI”。所以我们能同时拿到输入侧的 `UG_LL / OH_LL / OH_HL`，逻辑侧的自动与手动覆盖，和输出侧的泵、排液阀、报警与界面状态，这使它明显优于只给阈值启停一句话的薄弱样本。

## 对我们为什么有用

这篇论文对 `🌡️` 方向的价值，在于它提供的是一个带异常保护和人工接管的液位监督器，而不是纯粹的“低液位开泵、高液位关泵”极简模板。地下水箱干转保护、运行超时告警和 HMI 明确状态展示，都让这条控制链更接近实际工业自动化场景。

从数据集角度看，它可以补一类 `EFSM + T1` 的过程控制样本。后续如果做自动建模，既可以抽出上下液位 guard 和泵阀动作，也可以把 `10` 分钟报警阈值、手动覆盖和四种状态展示当成附加监督信息。

## 如果需要人工细读，建议怎么读

第一次人工重读建议直接从第 3 节开始。先看 `Design And Implementation` 和 `Sensor Positioning`，把低/高液位、干转保护、手动覆盖和报警规则圈出来；随后读 `Results` 里的四个状态说明，把空箱、补水、满箱和排空过程按顺序串起来。

像前面第 2 节里 PLC、继电器和 HMI 的一般性介绍，以及后面更偏接线与模块编号的内容，可以留到第二轮再看。只要先把“哪些输入触发泵和阀、哪些条件触发报警、HMI 上四种状态如何对应”读稳，就足够重新生成这条状态机样本。
