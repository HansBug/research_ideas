# Synthesis & Simulation Model of Parallel Lift Controller Using Verilog

## 论文在讲什么

这篇论文讨论的是一个三部电梯并行工作的楼宇电梯控制器。作者的目标不是单梯教学示例，而是一个能在多个候梯请求之间做最近梯选择、控制门开闭并完成楼层服务的主控制器，并将其用 Verilog 方式实现。

文中最有价值的不是 RTL 图，而是 `STATE FLOW` 段落。这里把 `idle acknowledgement`、外部呼梯请求登记、最近梯优先分配、到层开门、目的层更新、门控定时和任务完成后回到 idle 这条闭环流程写得比较完整，足以恢复出一条较清楚的电梯调度 EFSM。

## 控制系统在文中的位置

控制系统描述在这篇论文里是主线。摘要就说明了 “Three-Lift Controller” 和 “finite state machine”；第 2 节又补了八层、两类按钮、双计时器和门障碍检测；第 3 节则把状态流拆成 `Elevator Idling Block`、`User Signal Request Call`、`User Activated Block` 三段。

这意味着它不只是“写了 Verilog 的电梯设计”，而是明确给出一个主控制器如何在三部并行电梯之间分配任务、如何处理门控、以及服务完成后怎样回到待命的控制流。

## 对我们为什么有用

这篇论文对 `🏢` 方向的价值，在于它补的是“多梯并行 + 最近梯分配”这类相对少见的样本，而不是更常见的单梯上下行服务。当前文库里电梯样本不少，但多梯并行调度的控制链还不算多，这篇正好补上这一块差异。

它还有一个额外好处，就是把门控计时写得比较直接。`clock 2 counts from 3 to 0`、到层后再计时开门、障碍检测时保持开门，这些都让它比只写“到层开门”的简化流程更接近实际机电控制器。

## 如果需要人工细读，建议怎么读

人工细读时，建议先读摘要和第 2 节，把系统边界先固定下来：三梯、八层、双计时器、门障碍检测。然后直接进入第 3 节 `STATE FLOW`，按 `Elevator Idling Block -> User Signal Request Call -> User Activated Block` 的顺序把流程读顺。

第一轮重点抓四件事：怎样识别 idle、怎样选最近梯、门开闭受哪个时钟控制、到达目的层后如何重置回 idle。后面的综合图和实现截图可以放到第二轮再看，因为它们对理解硬件实现有帮助，但对恢复状态机主链的帮助不如状态流正文直接。
