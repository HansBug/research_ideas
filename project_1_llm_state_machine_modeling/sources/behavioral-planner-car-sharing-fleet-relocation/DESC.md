# 车共享重定位 follower 五态行为规划器 / A Complete Framework for a Behavioral Planner with Automated Vehicles: A Car-Sharing Fleet Relocation Approach

## 论文在讲什么

这篇论文研究的是城市车共享场景中的车辆重定位问题。作者设定了一种比较具体的运行图景：由人类驾驶一辆 leader 车辆，把一串原本停在不同停车位的自动驾驶车辆依次接入车队，再带到新的停车点完成重新布置。论文不是泛泛谈调度，而是把 follower 车辆在这个过程中如何从停车位出来、并入车队、跟驰、再驶入新车位，组织成一个明确的行为规划框架。

从控制描述的角度看，文中最重要的不是连续轨迹控制，而是 follower 的离散机动切换。作者直接给出 `waiting / de-parking / joining / platoon-following / parking` 五态有限状态机，并用基础 `V2V` 消息来连接 leader 与 follower 的互动。因此它属于很典型的“先有工程任务，再把任务拆成若干可切换机动状态”的样本，而不是只在仿真里顺带提一句用了状态机。

## 控制系统在文中的位置

我们关心的控制系统描述在这篇论文里是主体。论文的贡献之一就是 behavioral planner 本身，状态机和消息协议不是背景配角，而是承载整个重定位流程的中心骨架。换句话说，如果拿掉这条离散行为链，后面的仿真和车队重定位实验就没有统一的行为组织逻辑可谈。

同时，这篇论文也不是那种只写“可加入 / 可停车”概念流程的停车文献。它把 follower 车辆的初始广播、leader 判定是否可加入、离开车位、与车队末尾对齐、更新 platoon list、接收目标停车位这些步骤都落到了可追溯文本里，所以非常适合作为“停车/车队协同交界面”上的行为状态机样本来保留。

## 对我们为什么有用

对 `sources/` 来说，这篇论文的价值主要有两层。第一，它补的是当前相对稀缺的 `🅿️` 领域双 A 样本，而且不是传统模糊并联泊车轨迹控制，而是“车共享重定位 + follower 行为规划 + leader-follower 消息协调”这一条新类型。第二，它用的是显式 `FSM + T0 + 协议交互` 画像，能和现有偏 `Hybrid / T3` 的泊车样本形成很清楚的补充关系。

它还提供了一个很适合后续做自然语言到状态机生成的数据点：控制对象明确，状态集合明确，进入和退出条件也写得清楚，外加消息字段本身就是状态机语料里很有用的上下文信息。相比只谈轨迹或模糊控制器的停车论文，这类样本更接近我们想要的“可直接还原成离散行为图”的文献。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 `3-5` 页的 `Section 2.1 Overview` 和 `Figure 1-3`。第一轮只抓四件事：车辆重定位的完整业务循环是什么；五个状态分别是什么；什么条件让车辆从 `waiting` 进入 `de-parking`、再进入 `joining` 和 `platoon-following`；leader 给 follower 的消息里到底携带了哪些关键字段。只要这四件事抓住，`STM.md` 的主链基本就稳了。

之后再去看后续各个 manoeuvre 的实现细节与仿真章节，主要是为了补证某些状态内的控制含义，而不是为了重新确认状态机骨架。像全局路径规划、仿真平台搭建和控制器参数比较这些内容可以放到第二轮再看；它们对理解论文整体有帮助，但对提取离散行为状态机来说不是最优先部分。
