# Semi-Automated Parking System Using VHDL

## 论文在讲什么

这篇论文讨论的是一个基于 `VHDL` 的半自动停车门禁系统。它关心的不是轨迹规划级自动泊车，而是更偏工程入口控制的那条主链：车辆到达、密码输入、门禁放行、红绿灯提示，以及当前车辆未完全通过时对后车进行阻塞。

论文整体是比较典型的硬件实现短文，前半部分有很多停车系统背景、Vivado 使用和通用 FPGA 说明，但它并没有完全停留在平台介绍层。正文中间把停车控制器明确落到了 `FSM` 语义上，给出了命名状态、前后传感器、密码判定以及仿真状态跳转，因此仍然足以作为 `sources/` 里的一个离散控制样本。

## 控制系统在文中的位置

我们关注的控制系统描述在文中属于“工程实现主对象”。虽然作者也谈了软件环境和设计流程，但真正的核心不是 GUI，也不是计费管理，而是一个停车场入口门禁控制器如何按状态机方式工作。

这点在 `Finite State Machine` 一节里比较直接。文中没有把控制逻辑埋在零散图注里，而是明确写出 `INACTIVE / IDLE / WAIT_PASSWORD / RIGHT_PASS / WRONG_PASS / STOP`，并说明哪些传感器和密码条件触发这些状态切换。仿真结果部分又用 `Reset_n / front_sensor / back_sensor` 的组合进一步把这条控制链补实了。

## 对我们为什么有用

对 `sources/` 来说，这篇论文的价值在于它补的是停车方向里一类比较干净的“密码门禁 + 跟车阻塞”样本。现有停车条目里已经有若干门禁、车位计数和自动泊车控制，但这篇把“等待密码 `4` 周期、密码错误转红灯、前后车冲突转 `STOP`”写得更直白，适合进入 `FSM + T1` 这一类停车控制样本池。

它的另一个价值是文本粒度相对统一。虽然论文不长，但状态名、输入条件、灯光输出和复位回路都集中在少数几段里，后续如果要把它改写成更规范的数据集文本，成本会比那类只有波形图、没有显式状态名的短篇 `FPGA` 稿低很多。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看第 3 页 `3.2 Finite State Machine`。这一段已经把主状态和主要切换条件写全了，第一轮阅读只需要确认四件事：初始态是什么、入口检测后怎么进入等待密码、密码对错分别走哪条链、当前车未通过时后车怎样被阻塞。读完这段后，再接着看第 4-5 页的仿真结果，把 `Reset_n`、`front_sensor`、`back_sensor` 和状态跳转一一对上。

第 1-2 页关于停车背景、Vivado 软件和一般性硬件流程的内容可以放到第二轮再看。它们有助于理解这篇论文为什么采用 `VHDL` 实现，但对重做 `STM.md` 或校验状态机边界来说，优先级明显低于命名状态、传感器条件、密码判定和 `STOP` 状态的进入/退出逻辑。
