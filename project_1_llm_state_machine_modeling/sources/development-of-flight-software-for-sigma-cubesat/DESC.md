# SIGMA CubeSat 七模任务软件 / Development of Flight Software for SIGMA CubeSat

## 论文在讲什么

这篇论文围绕 SIGMA CubeSat 的机载软件设计展开，核心对象不是泛泛的软件框架，而是一个真正负责卫星模式切换、载荷调度和任务执行的 flight software supervisor。论文先交代 SIGMA 的任务目标和硬件环境，再把软件为什么采用集中式单进程结构讲清楚，随后给出系统需求、任务场景、运行模式以及任务/状态管理结构。

从 `sources/` 的角度看，最值得保留的是它把顶层任务链写得比较实：有 `INIT / STABLE / NORMAL / SCIENCE / SCIENCE AUTO / ACS / RECOVERY` 这套明确模式，有 `2 周`、`3 天`、`10 秒` 这类工程定时语义，也有 `TEPC 仅在电池电压高于 7V 时运行`、`MAG 与 TEPC 不可同时运行` 这样的 guard。它不是只说“用了状态机”，而是真正把卫星怎么切模式、什么时候自动启动科学任务、哪些条件会限制载荷运行写进了正文。

## 控制系统在文中的位置

这套控制系统描述在文中属于核心主体。作者讨论的不是单个算法模块，也不是测试或验证平台，而是整颗 CubeSat 在轨运行时的顶层软件组织方式。换句话说，状态机不是附带案例，而是承载整篇论文主张的主骨架。

更具体地说，论文把软件分成 `BOOT` 与 `APP` 两层，在 `APP` 中又把 7 个运行模式实现成任务，由 task manager 调度、由 state manager 在任务内部循环检查状态并执行地面命令或自动命令。这意味着我们关心的状态机链路不仅有模式名，还有任务级执行结构、自动转移条件和约束条件，因此非常适合做“自然语言到状态机”的监督样本。

## 对我们为什么有用

对 `project_1_llm_state_machine_modeling/sources/` 来说，这篇论文补入的是一个质量很高的 CubeSat 顶层 mission supervisor 样本。仓库里已经有一些航空航天方向的模式管理条目，但 SIGMA 的独特价值在于它把“固定任务期 + 无指令自动转科学模式 + 电压约束 + 载荷互斥”这几类离散控制因素放到了同一条清晰主链里。

做数据集时，这类样本尤其重要，因为它既有比较标准的 mode-switching 结构，又保住了工程上常见的辅助条件：时间窗口、电源约束、载荷互斥、自动回退到常态模式等。它能帮助后续模型学习到“状态机不只是模式名列表，而是带 guard、timer 和动作后果的任务监督器”。

## 如果需要人工细读，建议怎么读

如果后续要人工重读这篇论文，建议先看第 3-4 页的 `시스템 요구조건 / 위성운용시나리오`，先把需求表、运行模式表和 `INIT -> STABLE -> NORMAL -> SCIENCE AUTO` 的主链读稳；这里基本已经覆盖了模式集合、时间阈值和载荷约束。然后再看第 5-6 页的软件结构部分，把 `task manager` 和 `state manager` 的分工读清楚，用来确认这些模式在实现上是怎样被调度和执行的。

像第 1-2 页的卫星背景、载荷介绍和硬件总览可以放在第一轮之后再补看，它们主要帮助理解任务语境，而不是直接决定状态机链路。若将来需要重做 `STM.md`，最优先保住的仍然是模式名、自动转移阈值、`7V` 电压约束、`10 秒` HK 周期和 `MAG / TEPC` 互斥关系。
