# 基于 State Flow 图与 FPGA 原型的智能车辆交通信号控制系统 / An Intelligent Vehicular Traffic Signal Control System with State Flow Chart Design and FPGA Prototyping

## 论文在讲什么

这篇论文研究的是四路口交通灯控制系统，目标是从固定时长的传统交通灯切换到按交通密度动态调节的智能控制器。作者把路口每个方向都布置成三档密度传感器输入，然后在 State Flow 里实现一套状态机逻辑，再把这套逻辑转换成 VHDL 并做 FPGA 原型验证。

论文的关注点不是城市级信号优化，而是一个具体路口控制器的离散控制链。作者明确把最小/中等/最大密度对应到不同绿灯持续时间，又单独处理了传感器故障时的回退行为，因此这篇论文的核心是“一个可综合成硬件的交通灯状态机控制器”，而不是一般性的交通管理综述。

## 控制系统在文中的位置

我们关心的控制系统在文中就是主对象。第 3 节先定义四向路口、12 个传感器、密度等级和故障条件，再把这些控制规则组织成 State Flow 状态机，随后用仿真图去验证不同密度组合和故障组合下的灯序响应。换言之，交通灯状态机不是为了衬托 FPGA，而是整篇论文真正要实现和验证的系统。

从 `sources/` 的角度看，这篇论文比较有价值的地方在于它提供了一个“密度驱动 + 故障回退”的交通信号控制样本。库里已有不少应急车辆优先、图像配时之类的交通灯条目，但这篇是更朴素也更工程化的四路口密度控制器，能补足交通灯领域里 `EFSM + T1` 的另一种表达方式。

## 对我们为什么有用

如果后续要做状态机自动生成，这篇论文给的是很好的工程控制模板。它的输入是离散传感器组合，输出是信号灯颜色和持续时间，状态转移由密度等级和故障条件驱动，中间几乎没有复杂连续控制推导，所以非常适合转写成自然语言状态机描述。

另外，这篇论文还能帮助我们补“故障时回退到预设模式”这一类交通控制策略。很多交通灯论文只写正常相位切换，不写异常输入怎么处理；这篇则把高编号传感器亮而低编号没亮的异常当作 fault pattern，并明确切换到 `PCT mode`。这类异常回退链对后续做验证场景或负样本对比都很有用。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看摘要和第 3 节，重点只抓四块内容：路口与传感器布置、密度等级和绿灯时长的映射、同密度下的服务顺序、故障条件触发的 `PCT mode` 回退。然后再看第 4 节仿真结果里图 5-8 的文字说明，确认这些规则在仿真里是否真的按文中描述执行。

FPGA 面积、时序和功耗分析可以放第二轮阅读。那些内容说明硬件实现可行，但对我们提取控制逻辑本身帮助不大。若后续需要重做 `STM.md`，仍建议先抓 `Table 1`、`Table 2`、`Fig. 2` 附近的状态机逻辑，再回头补 `RTL` 或 `VHDL` 层面的实现性细节。
