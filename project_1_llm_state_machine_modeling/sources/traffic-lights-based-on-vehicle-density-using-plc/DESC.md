# 道路交通信号控制 / PENGEMBANGAN SISTEM TRAFFIC LIGHTS BERDASARKAN KEPADATAN KENDARAAN MENGGUNAKAN PLC

## 论文在讲什么

这篇论文研究的是一个基于车流密度的 PLC 交通灯控制器。作者不是做纯优化模型，而是把问题落成一个四路口原型系统：每条车道布置三个传感器，用它们来区分 `Kosong / Sepi / Normal / Padat` 四种密度状态，再由 PLC 的内部定时器决定该车道应该获得多长的绿灯时间。论文同时给出单车道 flowchart、四车道 wiring 与传感器位置说明，因此控制器并不是抽象算法，而是一个可接线、可仿真的工程原型。

它的核心亮点在于对相位切换写得比较细。文章明确说明黄灯会在绿灯前后各出现一次，而且这两次黄灯的组合方式不同：绿灯前是黄+红，绿灯后则是黄灯单独亮起后再切换到红灯。再叠加 `5/10/20/40` 秒的密度映射，这让整篇论文可以被整理成一个典型的“传感输入驱动定时阶段切换”的交通灯 `EFSM` 样本。

## 控制系统在文中的位置

这里的交通灯控制器是全文的核心对象。传感器电路、单车道 block diagram、单车道 flowchart、四车道 wiring、真实路口密度观测数据和绿灯时长表，全部都是围绕“交通灯如何根据车辆密度切换相位”这个问题展开的。论文并没有把交通灯当成某种教学附属案例，而是把它作为设计和实验的中心。

对 `sources/` 来说，这类稿子很合适，因为我们关心的不是拥堵分析本身，而是“离散控制器怎样根据传感输入在不同时长和相位之间切换”。这篇论文恰好把输入、状态划分、时间映射和跨车道串行约束都保留了下来，后续不需要从图像识别、模糊优化或交通规划层面再去二次筛出一小段控制逻辑。

## 对我们为什么有用

这篇论文最大的价值，是给 `🚦` 方向补了一条很标准、但又不是过于贫瘠的密度感知交通灯样本。文库里已有不少路口控制条目，但有些偏 FPGA 状态编码，有些偏应急优先，有些则偏图像处理或仿真框架。这篇样本的不同点在于：它直接把“三传感器 -> 四密度状态 -> 四档绿灯时间”的映射写成了工程实现规则，而且还把黄灯前后两段行为和四路口串行轮转关系讲清楚了。

另一个价值是，它能补到一类非常适合自然语言状态机建模的数据形态：状态不需要很多，但 guard 很硬，时间也不复杂却足够明确。后续如果做轻量状态机抽取、提示词构造或小规模仿真，这种“密度状态 + 定时动作 + 串行轮转”的控制器非常适合作为基础样本。

## 如果需要人工细读，建议怎么读

如果后续需要人工重读，建议先跳到 `3.2 Blok Diagram Dan Flow Chart` 和 `4.2 Data Durasi Lampu Hijau Menyala`。第一轮阅读时，重点不是看真实路口采样数据，而是先把三个传感器如何划分 `Kosong / Sepi / Normal / Padat`、黄灯两次亮起的顺序、以及 `5/10/20/40` 秒是如何从状态映射出来的这几件事读稳。然后再看“下一车道必须等待上一车道结束”的描述，把四路口整体轮转约束补上。

像前面的传感器发射/接收电路和后面的实地观测表，可以放到第二轮再看。它们对于理解系统实现当然有帮助，但如果目标是重建 `STM.md`，更值得优先核对的是密度判定规则、内部 timer 的作用、黄灯前后顺序，以及四车道之间的串行服务关系。
