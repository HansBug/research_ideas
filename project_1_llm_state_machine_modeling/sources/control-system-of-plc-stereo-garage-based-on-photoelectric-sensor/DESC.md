# 光电传感立体车库存取与速度闭环控制 / A Control System of PLC's Stereo Garage Based on Photoelectric Sensor

## 论文在讲什么

这篇论文讲的是一个垂直升降式立体车库 PLC 控制系统。作者把车板存在与否、平台回零、车辆是否满足停车标准、用户确认停车、升降到目标层、横移入库、回位复位这些步骤串成了一条完整的存车控制链，同时又补了速度闭环、爬行定位、传感器互检和故障自诊断。

因此它不是只写“立体车库可以停车”这种概述，而是把控制器真正关心的事情写了出来：升降和横移不能同时运行，复位子程序先建立初始状态，停车子程序要先判断车板和零层，再做尺寸/位置检查，运动过程中还要靠光电传感器、编码器和时间保护避免撞车或越位。

## 控制系统在文中的位置

控制系统本身就是全文中心。机械结构、PLC 选型、S7-300/S7-200 分工、速度曲线和软件子程序都是为这套车库控制链服务的，并不是为了说明某个独立优化算法。

这篇文献还兼具“流程控制”和“运动控制”双重价值。一方面它有很明确的停车子程序流程图，另一方面它又把速度参考、匀速/减速/爬行段、`5 ms / 50 ms` 扫描节拍和传感器互检写进去了，所以比单纯逻辑门禁样本更厚实。

## 对我们为什么有用

它对 `sources/` 的价值，在于补进了一类兼顾顺序逻辑和局部时间/位置控制的 `EFSM + T1` 停车样本。和只做车位分配的车库论文相比，这篇还给出了运动阶段、互锁约束和故障防护；和只讲速度闭环的运动控制论文相比，它又保留了清晰的停车主流程。

这类样本对后续“从自然语言抽恢复多阶段执行控制链”尤其有帮助，因为它同时包含了 `reset -> zero floor -> standard check -> confirm -> lift -> traverse -> reset` 这条顺序主链，以及传感器故障、自诊断、时间保护、爬行定位这些建模时常被漏掉的局部约束。

## 如果需要人工细读，建议怎么读

建议先看第 `3-4` 页关于停车流程和运动定位的正文，把“有无车板”“是否到零层”“尺寸/停放是否达标”“确认停车后如何升降与横移”这条主链读清楚；再看第 `6-7` 页的复位和停车子程序流程图，核对哪些分支会报警、哪些分支会等待确认、哪些步骤会触发电机复位。

最后再看第 `3-4` 页和第 `7` 页末尾的速度控制与安全保护说明，重点确认爬行段、光电 + 编码器互检、时间保护以及 `5 ms / 50 ms` 控制节拍。更一般的 PLC 模块选型和通信接口可以留到第二轮；第一次人工复核时，优先保住停车主链和安全链。
