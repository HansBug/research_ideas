# 楼宇机电与电梯控制 / Development of an Automatic Door Controller for a Smart Building

## 论文在讲什么

这篇论文讨论的是智能楼宇里的自动滑门控制器。作者没有把重点放在整套楼宇自动化平台，而是把问题压缩成一扇门应该如何根据人是否靠近、人与门之间的距离、以及当前控制逻辑来决定开门还是关门。系统采用 `ATmega 328P`、PIR 传感器、超声波传感器、继电器、直流电机和 LCD，写法明显偏工程实现，但控制条件交代得比较完整。

从控制逻辑上看，这篇论文并不复杂，却很完整。它强调两类输入必须联合作用：人体运动被检测到，且目标距离落在 `10 cm` 到 `60 cm` 之间；只有同时满足，门才会打开。若条件不满足，则系统输出关门信号。论文还给出引脚定义、程序片段和结果表，因此不只是描述一个概念，而是把门控逻辑真正落到了可运行实现。

## 控制系统在文中的位置

这里我们关心的控制系统描述就是论文的主设计对象，不是某个附属示例。文章从摘要开始就围绕这套门控系统组织，后面依次介绍传感器、程序逻辑、驱动电机方向切换、电路仿真和结果表，所有章节都服务于“门该什么时候开、什么时候关”这件事。

对于 `sources/` 来说，这很有价值，因为它让门控逻辑在原文里具备了非常清楚的边界。我们不需要从楼宇平台、能耗管理或 IoT 系统里抽取一小段局部行为，而是可以直接把这套自动门视为一个带 guard 的离散控制器：运动检测和距离检测构成输入，`FMOTOR/RMOTOR` 构成输出，门的 opened/closed 结果在表格里也被直接列出。

## 对我们为什么有用

这篇论文最直接的价值，是补进了 `🏢` 领域里一条“传感输入非常清楚、门控 guard 非常具体”的自动门样本。文库里已有一些自动门和电梯门控材料，但这篇的优势在于把 guard 条件写得特别硬：只有“检测到人运动”且“距离处于 `10-60 cm` 区间”时才开门，反例表也给得完整。这对构造可追溯的自然语言状态机描述很友好。

另外，它是一个很典型的 `EFSM` 文本样本。状态本身不多，但输入条件、输出动作、程序判断和结果枚举都足够明确。后续如果做样本清洗或轻量仿真，这类“逻辑简单但 guard 明确、I/O 明确”的论文很值得保留，因为它们能提供另一类与大型分层控制系统不同的基础样本。

## 如果需要人工细读，建议怎么读

如果后续需要人工细读，建议先看第 1-2 页的摘要和引言，确认系统目标就是“用运动检测和距离检测驱动自动滑门开闭”。然后直接读第 2-7 页，把传感器说明、`if/else` 判断、引脚定义、`FMOTOR/RMOTOR` 输出逻辑和 Table 1 的距离结果一起串起来看；这几部分合在一起基本就构成了完整控制链。最后再看结论，确认作者对 guard 条件的总结是否和前面的实现一致。

像微控制器背景、Proteus 软件介绍以及更泛的智能楼宇节能背景，可以放到第二轮再看。第一次回原文时，更值得优先确认的是“哪些输入联合为 true 时开门、哪些条件导致关门、表格是否覆盖边界距离、输出如何映射到电机方向”。只要这条链条读稳，这篇论文就足以作为一个高质量自动门控制样本入库。
