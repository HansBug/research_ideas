# 双开车库门的 RFID-光电门控与故障回退 / Implementation of Automated Double Doors with Programmable Logic

## 论文在讲什么

这篇论文讨论的是一个用 Omron PLC 实现的自动双开车库门控制系统。系统不是单纯的“按钮开门器”，而是把 `RF-ID` 识别、遥控触发、光电传感器自动关门、障碍检测、故障回退和照明控制一起纳入同一套 ladder program 里，因此对象边界很清楚。

论文本身偏工程实现，但控制链写得并不薄。作者把程序分成 `Ohjelma` 和 `Output_Ohjaus` 两部分，用步骤式方式说明开门、关门、障碍检查、故障复位和 `40` 秒照明延时，所以后续做状态机抽取时并不需要靠脑补把它凑成控制器。

## 控制系统在文中的位置

我们关心的控制系统描述就是论文的主设计对象。第 4 章几乎整段都在写这套门控系统如何被程序化，包含开门触发、传感器检查、辅助位、输出控制和测试结果，而不是把自动门逻辑当成更大楼宇系统里的一个附带模块。

这也让它和很多只谈“智能建筑背景”的自动门论文不一样。这里真正重要的是门该在什么条件下打开、何时自动关闭、遇到障碍时如何切断电机并进入手动状态。对于 `sources/` 来说，这正是一条可追溯、可直接建模的门控状态链。

## 对我们为什么有用

它对文库的直接价值，是补进了一种比常见电梯门控更轻、更集中、但仍然足够完整的 `🏢` 样本。文库里楼宇机电方向已有很多电梯系统，容易形成强趋同；而这篇是车库双门控制，输入、输出和异常链都不同，能提供更真实的结构差异。

另一个价值是它保住了局部工程定时和异常回退。`40` 秒照明保持、光电束恢复后自动关门、再次遮挡时切断电机、故障后手动处理与按钮复位，这些都使它不只是一个“开/关门 IF 语句”，而是一条更接近实际门机控制器的离散监督链。

## 如果需要人工细读，建议怎么读

建议先读第 13 页的 `Ohjelman kuvaus`，先确认两种开门入口、照明延时和光电自动关门的主链。然后直接跳到第 18-23 页，按“第三步关门逻辑 -> 第四步障碍检查 -> 第五步故障状态 -> 输出控制段”的顺序重读，这部分最适合还原 `STM.md`。

像前面的器件选型、CAD 接线和测试工装可以放到第二轮再看。第一次人工核验时，更值得抓的是：触发开门的 guard 是什么、什么时候进入自动关门、障碍如何中断关门、故障后为什么需要人工关闭与按钮复位。只要把这些节点抓稳，这篇论文就能稳定保住双 A。
