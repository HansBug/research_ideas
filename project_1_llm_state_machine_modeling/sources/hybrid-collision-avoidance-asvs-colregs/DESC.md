# 自主水面船舶 COLREGs 规则状态机论文 / Hybrid Collision Avoidance for ASVs Compliant With COLREGs Rules 8 and 13-17

## 论文在讲什么

这篇论文研究的是自主水面船舶的混合碰撞规避系统。作者把整个系统分成三层：高层负责能量优化航迹，中层负责考虑动态障碍与海上避碰规则的规避规划，短时层则处理更紧急的近场避险。整篇文章真正新增的核心，是中层如何把 COLREGs 规则转成可执行的离散判断逻辑。

因此，论文并不是一般意义上的“船舶路径规划”文章。它试图回答的是：面对不同来向、不同相对速度和不同碰撞风险的障碍船，系统到底应把它识别成 overtaking、head-on、give-way、stand-on 还是 emergency，并在此基础上约束后续规避动作。对我们来说，这正是一类很典型的规则监督控制器。

## 控制系统在文中的位置

这里的状态机不是背景示意图，而是整套 COLAV 系统中的关键解释器。高层和短时层此前已有基础，本文的主要贡献之一就是把中层 COLREGs 合规逻辑做成一个明确的状态机，并让它持续输出对每个障碍物的规则分类。后面的代价函数与 MPC 规划，都要基于这个分类结果工作。

这意味着文中保存下来的不是抽象法规综述，而是一套实际用于自主船舶控制的软件监督逻辑。状态名、进入条件、退出条件、迟滞设计和场景输出之间是连起来的，能直接支撑后续状态机建模、规则验证或场景生成任务。

## 对我们为什么有用

对 `sources/` 来说，这篇论文补的是 `⚙️ + EFSM + T1` 的一般控制领域样本，而且它的控制对象不是常见的机械顺序控制或门控系统，而是面向规则解释的航行监督器。样本价值在于：状态虽然只有六类，但每个状态都有明确的法律语义和风险语义，转移 guard 又由 `dCPA / tCPA / tcrit` 这组工程量驱动，结构非常清楚。

它还提供了很好的“规则文字到状态机 guard”的映射样本。很多法规型论文只会停在自然语言解释或代价函数设计层，而这篇文章真正给出了进入/退出阈值、迟滞、状态保持和场景验证结果，能帮助后续研究更好地处理“法规约束 + 连续测量量 + 离散状态输出”这类混合表达。

## 如果需要人工细读，建议怎么读

如果后续要人工重做 `STM.md`，建议先直接读 `4.2.1 State Machine` 和 `4.2.2 Entry and Exit Criteria`。先把 `SF / OT / HO / GW / SO / EM` 六个状态及其含义记清，再把 `tCPA`、`dCPA`、`tcrit` 分别对应的风险判断作用理顺，最后确认 exit criteria 是如何通过不同阈值形成迟滞的。

然后再跳到场景部分，优先看 `Scenario 1-3` 中 state machine output 的解释段落。这里的阅读目标不是把所有轨迹细节重算一遍，而是检查状态机输出是否真的驱动了“stand-on 保持”“give-way 向右规避”“head-on 维持到安全通过”这些离散行为。代价函数、MPC 细节和短时规避算法可以放到第二轮再读，因为它们不是当前抽取规则状态机主链的关键路径。
