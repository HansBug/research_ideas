# 三层电梯楼层状态与开门计时控制 / Elevator Control Circuit

## 论文在讲什么

这篇项目报告讲的是一个三层电梯控制器的完整数字电路设计。作者采用 `controller-datapath` 结构，把楼层请求、门开关和显示逻辑拆成控制器与数据通路，再用 `ASM` 图把电梯在 `GRD / FIR / SEC` 三个楼层状态之间的跳转、门保持开启、重新开门和楼层显示写清楚。

和很多只给“呼梯后上下行”概述的电梯实现不同，这篇报告把主控制链交代得比较细：哪些按钮是输入、哪些楼层请求会让轿厢上行一层或跨两层、门为什么会保持开启 `7` 秒、`OPEN / CLOSE` 怎样改变计数器，这些都直接写进了正文。因此它更像一篇“可直接拿来恢复顺序控制器”的电梯样本，而不只是教学背景。

## 控制系统在文中的位置

电梯控制器本身就是全文主角。前半部分虽然有一些关于状态机、ASM 和数字系统分解的铺垫，但真正落地的对象一直都是三层电梯控制电路，后面的状态图、状态表、计数器和楼层跳转逻辑都围绕这一个系统展开。

从 `sources/` 的角度看，它不是“拿电梯举例解释方法”，而是“用方法把一套电梯控制器设计出来”。这意味着后续人工回读时，不需要先去区分算法章节和系统章节，直接顺着输入、状态、门控计时和电机动作去读就能抓住控制主链。

## 对我们为什么有用

它对文库的价值，在于补进了一类比较干净的 `FSM + T1` 楼宇机电样本：状态名明确、楼层请求到迁移的映射明确、门保持开启的局部定时明确，而且电梯并不会因为 `OPEN`、`CLOSE` 和“已在目标层”这些 guard 被压成一条空洞流程。

同时，这篇报告还能提供一个很好的“状态机设计文档型”样本。后续如果需要对比“工程论文只写实现结果”和“设计报告把状态、计数器、状态表都交代出来”的差异，这篇电梯文献正好能作为后者的代表。

## 如果需要人工细读，建议怎么读

建议先看第 `20-24` 页附近的 `Design specification`、`Description of the system requirement` 和 `ASM Chart` 章节，先把 `GRD / FIR / SEC` 三个状态、各楼层请求对应的迁移，以及 `OPEN / CLOSE` 对门行为的影响抓住。

然后再看第 `29-31` 页的数据通路与计数器说明，重点确认 `counter 3` 怎样把开门保持时间实现成 `7` 秒，以及哪些“immediate / jump / through immediate floor”组合对应一层和跨层运行。电路级门、触发器和组合逻辑推导可以放到第二轮再看；第一次人工复核时，真正关键的是把楼层状态链和门计时链读稳。
