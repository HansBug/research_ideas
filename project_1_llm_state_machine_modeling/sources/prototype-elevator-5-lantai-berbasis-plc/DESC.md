# 五层 PLC 电梯原型控制 / Prototype Elevator 5 Lantai Berbasis PLC

## 论文在讲什么

这篇论文围绕一个五层 elevator prototype 展开，目标是用 PLC、proximity sensor、infrared sensor、load cell 和 AC/DC motor 构造一套接近真实楼宇电梯的控制系统。论文前半介绍了结构件、门机构和控制电路，但后半最值得保留的是作者没有只停留在“能上下楼”的一句话，而是用两段完整运行场景把五层电梯如何开门、关门、判断超载、处理途中叫梯和 emergency 停机写成了可顺着复现的控制逻辑。

就样本价值而言，这篇论文比很多只给简短 ladder 图或粗粒度“up/down/stop”状态名的 elevator 短文更强，因为它把 `delay 3 detik`、`10 detik` 自动关门、`infrared` 检测重开、`load cell` 超载保持开门、途中停靠以及机械故障时按 `emergency` 停止系统这些细节全都写了出来。也就是说，它不仅有门控和楼层调度，还有安全链和异常链。

## 控制系统在文中的位置

这里的控制系统描述就是论文的主角。前面的结构件、机械布局和电机配置只是说明 prototype 怎么搭起来，而真正决定 elevator 如何工作的，是后面的测试场景与结论部分。作者在两组条件中分别讨论“当前笼厢在 1 楼、乘客要去 3 楼”和“笼厢在 3 楼、2 楼乘客请求下行”的全过程，这些场景本质上就是在验证 PLC 主程序是否按预定状态链执行。

因此，文中我们关心的控制逻辑不是附带案例，而是原型能否成立的核心证据。尤其同向优先处理、途中停靠、门延时、IR 重开、超载蜂鸣与 emergency 停机，都是直接决定系统安全和可用性的状态机语义。对 `sources/` 来说，这种“用运行场景把控制链写透”的材料比抽象系统框图更可用。

## 对我们为什么有用

这篇论文补的是 `🏢` 方向非常实用的一类 `EFSM + T1` 电梯样本。虽然库里已经有一些电梯和扶梯条目，但很多样本要么只有楼层请求和方向状态，要么门控细节不够。这篇则把 door cycle 和 load/emergency chain 一起保住了，因此即便它与已有 elevator 条目存在邻近相似性，仍然能提供更完整的安全与异常恢复表达。

它同时也提醒后续筛选时不要误判。“prototype” 这个题名在很多情况下会导向教学平台或硬件展示稿，但这篇原文确实写出了顺序控制、定时、途中停靠和故障处理，因此值得留下。换句话说，关键不在于题名有没有 `prototype`，而在于正文是否真的把控制链讲细。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 `4-6` 页的两段测试场景，这是最快重建状态机的方法。先把 `3 detik` 开门、`10 detik` 自动关门、IR 检测重开、load cell 超载保持开门、途中停靠与同向优先服务读稳，再看 `emergency` 如何停止系统。这样很容易把 elevator supervisor 的 nominal path 和 safety path 一起抽出来。

结构设计、传感器硬件和门机构构造可以第二轮再看。它们对理解 prototype 有帮助，但如果目的是重写 `STM.md` 或做后续数据集抽样，第一次人工细读不需要过多停在机械细节上。优先读场景化运行链，再回看前文确认 proximity、IR、load cell 和 limit switch 分别对应哪些输入即可。
