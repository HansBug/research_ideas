# 特权等级电梯优先调度 / The Realization of a Control Algorithm and its PLC Based Program Able to Authorize Four Different Ranks of Priority to Elevator Users

## 论文在讲什么

这篇论文讨论的是公共建筑和医院场景里的电梯优先使用问题。作者不是做一般性的群控优化，而是想解决“VIP 专用梯闲置、普通梯拥堵、紧急人员又需要优先通行”这类现实矛盾，因此提出了一个基于 `PLC` 的四级授权控制程序，把普通用户和三种不同级别的特权用户统一纳入同一套调度逻辑里。

对 `sources/` 来说，它最有价值的部分不在硬件原型，而在第 `1-2` 页对四种模式的规则化描述。论文把 `Normal / Rank1 / Rank2 / Rank3` 分别写成不同的服务策略，并说明普通模式下如何按方向和就近原则运行，特权模式下又如何抢占、保留或延后其他呼叫。

## 控制系统在文中的位置

这里的控制系统描述就是论文主体。作者的目标就是把四级优先权电梯算法落成一套可执行的 PLC 程序，并配合 `SCADA` 和伺服电机原型去验证，因此控制模式、模式切换和抢占逻辑都不是边角信息，而是整篇文章真正要交付的核心对象。

更重要的是，这篇论文不是只写“有 VIP 优先”这种概念。它继续区分了最高级别完全抢占、中等级别保留部分既有 cabin call、低等级别先服务既有请求再抑制 normal call 这些具体差别，所以后续人工回原文时，很容易把它还原成一个带层次 override 关系的监督控制器。

## 对我们为什么有用

这篇论文补的是 `🏢` 方向里比较少见的“权限等级驱动的电梯服务监督器”样本。库里已有不少楼层请求、门控、超重或定时开关门电梯稿，但多数都围绕单梯运行链展开；这篇则把“谁有权改变服务规则”作为离散控制的主轴，和普通电梯门控样本形成了明显差异。

它也很适合支持后续状态机自动生成研究里的“模式覆盖 + 抢占”能力。这里真正值得保住的不是 Karnaugh 图本身，而是四种模式各自允许什么、不允许什么，以及从普通模式切到特权模式时旧请求怎样处理、同级请求怎样复用 collective operation。只要这些规则保住，这条样本就很有区分度。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 `1-2` 页摘要和引言里对四级权限需求的说明，先确认系统边界：它是单电梯服务监督器，不是纯调度理论，也不是多梯群控综述。随后直接进入 `2.2 Elevator Control Algorithms`，把 `Normal / Rank1 / Rank2 / Rank3` 四种模式及其差异逐条圈出来，再看 `2.2.2 Privileged Modes` 里模式转换和同级 collective operation 的说明。

第二轮再去看 `SCADA`、原型和 PLC 实现细节。那些内容有助于确认工程可实现性，但如果目标是重做 `STM.md` 或复核样本边界，第一次阅读时只需要先把模式层和抢占规则读稳；等状态链确定以后，再回去补程序实现和实验部分即可。
