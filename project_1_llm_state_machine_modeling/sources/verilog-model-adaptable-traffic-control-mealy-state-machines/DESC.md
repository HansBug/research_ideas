# 五路口 Mealy 自适应交通灯控制 / A Verilog Model of Adaptable Traffic Control System Using Mealy State Machines

## 论文在讲什么

这篇论文研究的是一个基于 `Verilog` 和 `Mealy` 状态机的复杂交通灯控制器。和普通只做四相轮转的路口控制不同，作者把一个五条主路组成的 `chowk` 展开成十个信号灯，并额外加入了两类动态因素：一类是按车流负载改变绿灯时长，另一类是对救护车等应急车辆做优先放行。

因此，这篇论文的重点不是 FPGA 资源占用本身，而是“交通灯序列怎样组织得更灵活”。它既保留了可追溯的定时相位链，又把应急优先和时长伸缩整合进同一套状态机，是典型的离散交通控制样本。

## 控制系统在文中的位置

我们关心的控制系统描述在文中就是主体。作者先讲为什么固定配时和没有应急优先的传统系统不够用，然后直接进入 `Roads Structure`、`State Table` 和仿真结果，把控制器的输入、道路结构、输出信号和相位推进规则一项项写出来。

这对 `sources/` 很有帮助，因为论文并不是只说“用了 FSM”，而是真的把控制对象、时序状态和中断规则落到了文字上。特别是 `TS/TL` 对绿灯时间的调整，以及 `SW1-SW4` 应急请求中断并恢复原序列的机制，让它比常见的单纯 timed traffic light FSM 更丰富。

## 对我们为什么有用

虽然 `🚦` 方向已有不少交通灯样本，但大部分要么是规则相位偏简单，要么没有把优先请求和调时机制写得足够清楚。这篇论文的价值在于它同时覆盖了多路口、多输出组、负载调时和应急优先四个层面，因此仍然能为交通信号控制子集补充结构差异。

另外，它是较少数明确点名 `Mealy` 的交通灯论文。对后续状态机自动生成来说，这意味着我们不仅能拿到“相位序列”，还能拿到“输出与当前输入共同决定”的建模暗示，这对区分不同类型的离散控制器也有帮助。

## 如果需要人工细读，建议怎么读

建议先看摘要和引言，确认这篇论文要解决的两个问题：固定配时不足，以及应急车辆优先缺失。然后直接读 `Roads Structure`、`State Table` 和 `Pins Description` 三段，把十个信号灯的分组、`SW1-SW4`、`TS/TL`、正常轮转顺序和应急恢复规则全部串起来。

编码方案比较、FPGA 切片利用率和仿真平台介绍可以放到第二轮再看。那些内容有助于理解实现代价，但对我们重建交通灯状态链来说，优先级低于相位顺序、应急中断、调时输入和输出组映射。
