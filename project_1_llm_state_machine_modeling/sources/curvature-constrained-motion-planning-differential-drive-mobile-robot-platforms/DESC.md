# 曲率约束差速机器人航点跟踪控制 / Curvature-Constrained Motion Planning Method for Differential-Drive Mobile Robot Platforms

## 论文在讲什么

这篇论文研究的是重载差速移动机器人在城市物流和厂内物流环境里的航点跟踪控制。问题的关键不是“怎么找到一条路径”，而是这种平台存在不可忽略的最小转弯半径，如果沿用默认的 waypoint follower，很容易隐含原地旋转或过于激进的转向假设，实际平台并不能稳定执行。

作者给出的解决方式非常直接：把控制器写成一个 `Align / Goto / Pause` 三态有限状态机，并把曲率上界显式塞进状态机内部，而不是另起一个复杂的在线优化器。这样，机器人在对齐航向、推进到目标点、以及到站执行任务这三种行为之间切换时，始终遵守最小转弯半径约束。

## 控制系统在文中的位置

文中最核心的控制单元就是这个 event-driven finite-state machine。`Align` 负责在较低速度下做有界曲率的航向校正，`Goto` 负责常规前向推进，`Pause` 负责到站后的停机、任务执行和延时等待。作者不仅说明了三态含义，还把 `εθ`、`εd`、`tpause`、`κmax` 和 `Rmin` 这些决定转移和动作的关键参数写进了算法伪代码。

因此，这篇论文虽然也包含几何推导，但并没有把状态机藏在框架层。相反，状态机就是整篇控制执行逻辑的主表达方式，也是为什么它适合作为 `FSM + T1` 的 project1 样本。

## 对我们为什么有用

这篇论文的价值在于它提供了一个很干净的“离散状态切换 + 明确阈值参数 + 物理转向约束”的机器人执行器样本。很多移动机器人论文会讲跟踪控制或轨迹平滑，但不会把状态、守卫和任务停顿写到足够可追溯；这篇文章把这些内容压缩进了一个小而完整的控制器里。

对数据集来说，最值得保留的是四类信息：三态集合 `Align / Goto / Pause`，触发 `Align -> Goto` 与 `Goto -> Pause` 的门槛条件，曲率裁剪逻辑如何与状态动作绑定，以及 `Pause` 中的任务服务与延时等待。

## 如果需要人工细读，建议怎么读

建议先读第 `7-8` 页的 `2.5 Curvature-Constrained Control Framework` 与 Algorithm `1`，把三态职责和转移条件记住；然后看同页 Table `1`，把 `εθ`、`εd`、`tpause`、`κmax` 等参数与状态动作一一对上。最后再回看前面的几何推导部分，理解为什么这里坚持用曲率受限的前向弧线，而不是原地转向。

如果只为了 project1 的状态机语料，第一次不必深挖所有几何公式。先抓住“有哪些状态、什么条件切换、切换后执行什么动作、哪些参数约束这些动作”这条主链即可。
