# 双无人机协同搜索与确认任务 / Flight Demonstrations of Unmanned Aerial Vehicle Swarming Concepts

## 论文在讲什么

这篇文章回顾了 APL 在 `2001-2005` 年间围绕 UAV swarm autonomy 做的一系列飞行演示，包括 simple teaming、consensus variables 和 stigmergic potential fields 等多种思路。对 `sources/` 来说，最值得保留的不是“群体智能”这个大题目本身，而是 simple teaming 里那条写得非常清楚的双 UAV 参考任务链。

这条参考任务链把两架自主无人机如何协同搜索、发现候选信标、请求另一架无人机脱离搜索模式前往复核、然后根据第二架无人机是否检测到另一频率来决定是恢复搜索还是盘旋拍摄并返航，写成了一个清楚的任务控制流程。它是非常典型的高层任务 FSM，而不是只讲队形或轨迹优化。

## 控制系统在文中的位置

控制系统在这篇文章里属于案例实现核心。虽然整篇文章会谈多个 swarming 概念，但一旦进入 reference mission 和 mission control software 部分，作者明确把任务规范表示成 `finite state automata`，并把状态迁移触发条件、消息交换和执行动作说清楚。

这让它和很多“群体无人机综述式论文”不同。这里不是简单说“swarm members cooperate”，而是确实给出了哪些事件会导致搜索模式切换、何时发请求、何时恢复原脚本、何时进入目标确认与成像环节。对数据集建设来说，这种跨载具消息驱动的离散任务控制链非常有价值。

## 对我们为什么有用

它对 `sources/` 的意义在于补进了一类“协议交互主导”的高层任务状态机样本。文库里已有不少单机 mission manager、模式管理和故障恢复案例，但像这种通过队友消息与观测结果来驱动状态迁移的协同任务控制器并不算多。

此外，这篇论文很适合后续 LLM 建模，因为它的状态链条非常自然语言化：搜索、发现、请求、确认、盘旋、返航。即便不直接照搬图，也能从正文整理出清楚的状态、事件和动作关系，同时还能保留“人与地面站只是下发高层任务，机载控制器负责离散决策”的系统边界。

## 如果需要人工细读，建议怎么读

人工重读时，建议先跳到 simple teaming 部分，把参考任务 `1-5` 步骤完整读一遍，先建立整个协同任务骨架。接着立刻看 mission control software 那几段，把控制器输入、消息接口、状态变化触发条件和 FSA 的实现位置对齐起来，这两部分已经足够支撑高质量 STM 抽取。

之后再看 demonstration results，把仿真、HIL 和飞行演示如何逐级验证这套 FSA 实现补上。consensus variables 和 stigmergy 那两条线可以放在第二轮再看，因为第一次人工复核最重要的是保住这条“双机协同确认目标”的主控制链，而不是把所有 swarm 变体一次性读完。
