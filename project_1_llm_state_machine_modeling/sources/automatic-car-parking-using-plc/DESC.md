# 多层自动停车存取车控制链 / AUTOMATIC CAR PARKING USING PLC

## 论文在讲什么

这篇论文讨论的是一个基于 `PLC + HMI + IR sensor` 的多层自动停车系统。它不是只讲停车场管理平台，而是把“车开到入口之后如何被托盘接走、如何搬运到空位、之后又如何按车号取回”这一整条离散控制链写了出来。系统的执行机构是升降与横移机构，感知端主要依靠入口与托盘上的红外检测，控制端则用 PLC 的梯形图去协调托盘、升降和闸门动作。

文中对系统边界交代得比较清楚：车辆先进入入口区，PLC 先检查是否还有空托盘和可用车位，再决定是否允许进入；存车时记录车与托盘的对应关系，取车时根据 HMI 输入的车号回查并把目标托盘送到出口。这使它不是一个只有“满位显示”或“门禁计数”的轻量停车样例，而是一条较完整的自动存取车流程。

## 控制系统在文中的位置

我们关心的控制系统描述在文中处于主体位置。论文虽然带有机械结构、元件选型和硬件说明，但这些内容都服务于同一个核心目标：让 PLC 可靠地调度入口检测、空位分配、托盘搬运、存储记录、车号匹配和取车回送。

更具体地说，正文里最关键的不是停车场背景，而是 `Working Principle` 那一段控制流程。作者直接说明了入口传感器先触发空托盘检查、车辆上托盘后再由 IR 与 HMI 信息完成绑定、离场时由 HMI 输入车号触发检索，以及在无空位时由 PLC 保持闸门关闭并点亮 `Car Park Full`。这套描述已经足以支撑我们把它整理成一条可追溯的 EFSM 风格样本。

## 对我们为什么有用

对 `sources/` 来说，这篇论文补的是 `🅿️` 方向里“真正带存车与取车回路”的停车控制样本，而不是只带占位检测或支付管理的停车系统。它把状态机式控制最关键的几类部件都保住了：入口触发、空位检查、内部状态存储、后续检索、出口回送，以及满位拒绝进入的分支。

如果后续要做数据集，这篇论文最值得保留的不是机械尺寸和传动机构，而是那条清楚的主控制骨架：`入口检测 -> 空托盘到位 -> 上车确认 -> 记录车位 -> 存车搬运 -> HMI 取车 -> 匹配检索 -> 回送出口 -> 满位闭门`。这条链对自然语言到状态机建模任务很友好，因为它天然包含 guard、数据记忆和分支回退。

## 如果需要人工细读，建议怎么读

如果后续要人工复核 `STM.md` 或重新抽案例，建议先读第 1 页摘要和引言，确认系统范围确实是自动立体停车而不是单纯停车场监控；然后直接跳到第 2-3 页 `III. METHODOLOGY / Working Principle`，把入口传感器、空托盘分配、IR 确认、HMI 记录与检索、出口回送、满位闭门这几步按顺序圈出来。

之后再看第 3-5 页的部件和机械模型说明，只把那些会影响控制边界的事实补回来，例如 IR 既检测车也检测托盘、步进电机负责升降与横移、HMI 负责车号输入与状态显示。更细的机械结构、尺寸和硬件图片可以放到第二轮再看；第一次阅读只需要先把主控制链读稳。
