# 基于 PLC 的自适应拥堵交通灯 / DESAIN SISTEM KONTROL PENANGGULANGAN KEMACETAN LALU LINTAS ADAPTIF BERBASIS PLC

## 论文在讲什么

这篇论文讨论的是一个基于 `PLC Omron` 的自适应交通灯系统。作者针对固定配时交通灯在不同时间段无法反映真实车流的问题，在每个路口方向放置 `LDR` 传感器，用来判断某一方向是否进入拥堵状态，并据此改变绿灯持续时间。

它不是只停留在“根据车流调整配时”的概念层，而是把控制逻辑落到了可执行的 `PLC ladder` 程序上：正常情况下绿灯约 `5 detik`、黄灯约 `3 detik`；当某一路拥堵时，绿灯通过附加计时段被延长到 `10 detik`。因此整篇论文更像一条顺序控制链说明，而不是交通优化算法稿。

## 控制系统在文中的位置

控制器设计就是这篇论文的中心内容。第 2 页给出系统框图和流程图，第 4-5 页按主程序、各路子程序和传感器子程序展开，逐段说明某些线圈和定时器在什么条件下激活、对应哪一路绿灯持续多久。

对样本库来说，这篇论文的意义不在复杂性，而在它把“固定轮转 + 拥堵分支”说得足够工程化。很多近题交通灯论文只给一个概念性 flowchart 或图像检测框架，但这篇保住了 `sensor -> PLC -> timer -> lamp outputs` 的完整链条。

## 对我们为什么有用

它补入了一条典型的 `EFSM + T1` 路口控制样本，而且原文和描述都能保持在 A 级。对于后续做“外部感知触发局部时长扩展”的状态机抽取，这篇是很直接的基线：正常配时是 nominal path，拥堵传感是 guard，`5 detik -> 10 detik` 则是非常清楚的时间语义。

另外，这篇论文还保住了多路口互斥关系。它不是只说“某一路延时更久”，还明确写了当某一路绿灯或黄灯工作时，其他路口对应红灯的关系，因此更容易重写成结构完整的交通信号控制描述。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看摘要和第 2 页 `Gambar 3` 的系统流程，把 `S1/S2/S3` 的拥堵分支和 `5 / 10 / 3 detik` 三组时间参数先钉住。然后直接跳到第 4-5 页的程序测试部分，对照 `TM1/TM3/TM5/TM6` 和 `PADATJ1` 这些变量，把“正常子程序”和“拥堵子程序”的对应关系补完整。

如果只是为了重建状态机，不需要把驱动电路、电阻计算或硬件电压细节看得很深。第一次回原文时，最值得花时间的是四个车道的相位关系、传感器触发条件，以及拥堵时到底是如何从 `5 detik` 切到 `10 detik` 的。
