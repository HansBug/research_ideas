# GNSS-denied 无人机任务框架 / An Efficient Framework for Autonomous UAV Missions in Partially-Unknown GNSS-Denied Environments

## 论文在讲什么

这篇论文围绕一个 Leonardo Drone Contest 竞赛场景展开，目标是在部分已知、部分未知障碍的室内 GNSS-denied 环境里，让低成本无人机完成自主起飞、搜索移动目标、稳定跟踪、接收任务列表、执行拍照或精确降落并最终安全返航。论文主体不只是算法堆叠，而是把视觉定位、全局规划、局部避障和任务级逻辑拼成一套可实际飞起来的 ROS/PX4 框架。

对 `sources/` 来说，最重要的部分是作者没有把任务管理停留在“框架模块图”层面，而是明确说 mission planner 由一套有限状态机统筹。原文给出了 `Idle`、`Hover`、`Search`、`Tracking`、`Wait for Mission`、`Select Action` 等状态，以及 `10 s` 持续跟踪门槛、`10 s` 落地等待、动作队列循环和最终回到 `Idle` 的闭环。

## 控制系统在文中的位置

这里的控制系统描述是论文的主角之一，而不是顺手带过的实现细节。作者在 `3.6 Mission Planner` 里把整场挑战的高层逻辑压成 FSM，并用它来解释无人机什么时候探索、什么时候跟踪、什么时候等待地面站发任务、什么时候执行单个动作、什么时候完成整场任务。换句话说，这不是“某个算法模块碰巧有几个状态”，而是整机任务行为的明确调度器。

虽然论文前半也讨论了地图、轨迹和避障，但这些模块在文中的角色更像是被 mission planner 调用的能力层。对建模任务而言，这种“上层离散监督 + 下层感知与规划”的分层关系很有价值，因为它把可抽成状态机的数据边界划得比较清楚。

## 对我们为什么有用

这篇论文补的是 `✈️` 领域里比较典型、而且原文够完整的 `EFSM + T1` 任务监督样本。库里已经有搜索救援 UAV、行为树任务管理和 CubeSat 模式管理等条目，但这篇的优点是把竞赛任务执行逻辑写得更像一个可以直接落数据集的离散控制链：有明示状态、有 guard、有 `10 s` 定时、有动作队列，还有执行失败后的回退。

它还带来一个很有用的表达面向：不是设备级 actuator 控制，也不是纯飞控连续环，而是“任务级监督控制器”如何约束下层规划模块。这类样本对后续 LLM 从自然语言恢复 mission-state supervisor 很重要，因为它逼近了实际工程里的高层行为控制写法。

## 如果需要人工细读，建议怎么读

人工重读时，建议先直接看 `3.6 Mission Planner` 所在的第 `11-12` 页，把状态集合、每个状态的进入条件、`Tracking` 的 `10 s` 条件、`land/photo` 两类动作和最终回到 `Idle` 的结束链先抓出来。这一步能最快重建状态机骨架。接着回到第 `2-3` 页的 `Competition Details and Proposed System Overview`，确认挑战任务本身要求了哪些动作、目标和约束，从而验证这些状态为什么存在。

之后如果要补更细的环境交互语义，再看第 `13-16` 页的实验部分，尤其是动作执行、障碍规避和 GUI 监控界面的说明。定位、地图和轨迹插值的数学细节可以放到最后看，因为它们主要解释下层连续能力，不是重建任务级状态机的首要入口。
