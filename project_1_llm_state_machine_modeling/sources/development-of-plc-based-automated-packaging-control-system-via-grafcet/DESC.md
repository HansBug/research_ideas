# 基于 Grafcet 的 24 罐包装顺序控制 / Development of PLC-based Automated Packaging Control System via Grafcet

## 论文在讲什么

这篇文档讨论的是一个面向中小型罐装食品生产线的自动包装控制系统。作者要解决的问题不是单纯“做个 PLC 小实验”，而是把 `24` 罐产品按固定列、固定行和固定堆叠顺序自动装进纸箱，用 `PLC + Grafcet` 代替人工重复搬运和摆放。

系统的核心不是某一个单独气缸，而是一整条顺序控制链。作者把完整过程写成 `[({[B+B-] x 4} + [A+A-]} x 3) x 2]`，并把它拆成三段去建模和调试：先做列、再做行、最后做堆叠。这种写法让它天然适合被整理成离散控制状态机样本。

## 控制系统在文中的位置

包装控制器是全文的绝对主线。摘要、问题定义、Grafcet 基础、仿真设计、测试、梯形图转换和硬件调试，全部都是为了实现这套包装顺序控制系统。文中不是把包装当一个背景案例，而是把它当成需要被完整编程、仿真和落地的工程系统。

对 `sources/` 来说，它的优势在于把执行器层级写得很细：哪些气缸需要往复几次、什么时候计数、什么时候允许下一个步骤启动、什么时候把 Grafcet 转成梯形图并上 PLC。这样的原文很适合整理成 `STM.md`，因为控制链条并不依赖猜测。

## 对我们为什么有用

工业自动化方向里已有一些输送带、灌装和包装线样本，但直接用 `Grafcet` 把多段顺序、计数器和多个气缸动作写成一条总公式的材料并不多。这篇补的是一种很典型的离散制造顺序控制表达，不是简单的 “sensor -> motor” 短链。

它还补到了一个很实用的建模特征：同一系统里同时出现分段拆解、局部计数器、过渡条件和后续 PLC 落地。对后续研究 `LLM` 从自然语言恢复制造顺序控制器来说，这种样本比只讲某一个局部动作的短文更有结构价值。

## 如果需要人工细读，建议怎么读

建议先读第 `29-35` 页 `Results and discussion` 里的三段式顺序说明，先把总公式、`B` 气缸四次往复、`A` 气缸三次往复和 `D` 执行器最终堆叠的关系读清楚。第一轮人工重读时，目标就是恢复“列 -> 行 -> 堆叠”这条主顺序和每一段依赖的计数与转移条件。

第二轮再读第 `35-44` 页的 `Simulation testing`、梯形图转换和 `Testing and commissioning`，重点核对三个事实：`Grafcet` 步骤是否必须等过渡条件满足才能推进、实际硬件用了哪些执行器/开关、输送带在最终系统里是怎样和计数器联动的。前面的自动化与 PLC 泛背景可以后看，不是恢复状态机最核心的证据。
