# RFID 智慧停车系统 / Smart Car Parking System

## 论文在讲什么

这篇论文讨论的是一个 `IoT` 化停车系统。作者把 `NodeMCU`、`RFID`、入口与车位 `IR` 传感器、移动应用和 `Firebase` 后端连在一起，目标是减少人工干预，并让用户在进场前后都能实时看到空车位状态。

论文的控制核心不是复杂的路径规划，而是一条停车场业务流程：车辆接近入口后先检测与验卡，验证通过才开闸；进场后由车位传感器更新占用状态；出场时再依据停放时长自动计算费用。这让它很适合作为“门禁 + 状态同步 + 计费”一体化停车样本。

## 控制系统在文中的位置

控制系统是论文主体，而不是附带展示。第 3 页 `Theoretical framework` 和 `Implementation` 两节几乎把整条控制链都写清楚了，包括 `RFID` 标签如何和账户绑定、入口闸门何时由伺服电机打开、车位状态怎样写回数据库，以及出场费用怎样按时长分支计算。

对样本库来说，这篇的价值在于它把离散控制行为和后端状态联动放在同一条链里。很多停车论文只保留“有空位显示”或“有门禁识别”其中一部分，而这里把认证、放行、占用写回和收费都保住了。

## 对我们为什么有用

这篇论文给 `🅿️` 方向补了一类比较实用的 `EFSM + T0` 样本。它不是机械立体车库那种升降横移控制，而是更贴近日常停车场运营流程的门禁控制器，对后续构造更贴近应用侧的状态机语料很有帮助。

另外，这篇也有比较清楚的 guard 语义：入口 `IR` 检测只是触发条件，真正决定是否放行的是 `RFID` 是否有效；车位颜色变化对应数据库中的 `0 / 1`；出场分支则取决于停放时长是否超过阈值。这样的条件链比较容易转写成结构化状态机描述。

## 如果需要人工细读，建议怎么读

人工重读时，建议直接先看第 3 页的 `Theoretical framework` 和 `Implementation`。前者能帮你迅速抓住系统组成与业务顺序，后者则把“有效卡开闸、应用鉴权、车位 `0/1` 更新、超时加价”这些关键分支写得最集中。

第 1-2 页的引言和文献综述可以快速浏览，但不必花太多时间。若目标是重建 `STM`，最值得重点标出的就是入口感知、`RFID` 验证、数据库状态更新和出场计费这四个节点，因为它们共同构成了这篇论文最主要的状态机骨架。
