# 海上平台 UAV 视觉伺服降落 / Visual Servoed Autonomous Landing of an UAV on a Catamaran in a Marine Environment

## 论文在讲什么

这篇论文研究的是四旋翼无人机在海上 `catamaran` 平台上的自主降落问题。和普通地面平台回收不同，作者面对的是浪涌引起的平台上下起伏、相对位姿持续变化、GNSS 精度不够以及视觉目标可能暂时丢失等实际海上约束，因此整套方案同时使用 GNSS、AprilTag 视觉定位、超声测距和 Kalman 估计来组织回收过程。

论文并没有只给一个连续控制器，而是把整套回收任务拆成 `8` 个离散状态：初始化、搜索、跟踪、悬停、下降、上升、补偿和着陆。作者还把 searching 的圆轨迹公式、失视 `> 1 s` 进入 hovering、`0.1 m` 级高度步进以及最终落地阈值都写出来了，所以它不仅是一个视觉伺服案例，更是一个非常完整的飞行监督状态机样本。

## 控制系统在文中的位置

这里的状态机是全文控制骨架。视觉系统、水平跟踪、垂向补偿和软件架构这些内容，最终都要通过 `3.4 Finite State Machine` 这一节的状态图串起来，决定 UAV 在什么时候搜索平台、什么时候恢复初始化、什么时候因失视悬停、什么时候进入最终 landing。

这点对 `sources/` 很重要，因为我们关心的不是“作者用了哪些传感器”，而是“这些传感器怎样驱动离散状态切换”。这篇论文恰好把这条链写得很清楚：状态、切换条件、时间条件、安全回退和终止动作全部具备，因此非常适合转写成 `FSM + T1` 的自然语言建模样本。

## 对我们为什么有用

对当前文库来说，这篇论文补的是 `✈️` 方向里很有代表性的海上 UAV 回收控制样本。它和起落架、CubeSat 模式管理、搜救任务 HSM 不同，强调的是“动态平台接近 + 视觉丢失恢复 + 低空补偿 + 安全着陆”这条完整任务链，能明显扩展航空航天样本的对象类型与行为结构。

它的另一个价值，是把多个工程定时语义直接保留在主控制链里，比如 `timeout`、`1 s` 失视悬停、`0.1 m` 高度增减、搜索圆半径增量等。这些信息对后续构建 `T1` 样本特别有用，因为它们不是实验说明，而是直接参与状态转移和动作执行的控制条件。

## 如果需要人工细读，建议怎么读

如果后续要人工细读，建议先从第 `7-10` 页的 `3.4 Finite State Machine` 读起，按 `Figure 4` 的状态图和 `3.4.1-3.4.8` 的子节顺序逐个读状态职责与转移条件。第一轮只需先把 `searching / tracking / hovering / descending / ascending / compensation / landing` 的进入条件、退出条件和动作逻辑抽稳，再回头看前面的视觉与补偿算法。

像前面 `3.2 Horizontal Tracking`、`3.3 Vertical Compensation` 的控制律推导、Kalman 细节、软件中间件结构和后面的仿真曲线，可以放到第二轮再看。除非你要核对某个阈值或补偿公式的精确来源，否则第一次人工复核的重点应该始终放在“状态图如何组织整条回收任务链”上。
