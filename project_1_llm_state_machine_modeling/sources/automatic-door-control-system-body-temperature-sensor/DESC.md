# 体温筛查自动门控制系统 / Automatic Door Control System With Body Temperature Sensor

## 论文在讲什么

这篇论文介绍的是一个疫情场景下的自动门原型。系统入口前放置红外传感器与 `MLX90614` 体温传感器，来访者靠近后先完成温度读取，再由直流电机带动滑门开关，同时用 `LCD`、`LED` 和 `buzzer` 给出状态反馈。

它的论文体量不大，但控制对象很明确，不是泛泛的“智能楼宇”概念稿。作者真正交代的是一条离散门控链：先检测、再测温、再按阈值分支到“开门并延时关门”或“拒绝开门并告警”。

## 控制系统在文中的位置

控制器设计就是本文的主体，不是附带案例。摘要、系统概述和“Functions and How it Works”几段基本把整个控制链都直接写出来了，输入、阈值、执行器和异常反馈都围绕这套门控系统展开。

对 `sources/` 来说，这篇论文的价值在于它把门控逻辑写得足够像一个可直接抽成 `EFSM` 的工程样本。它虽然没有复杂的层次结构，但保住了很完整的 guard 和输出动作：红外触发、体温阈值、正常放行、异常告警，以及几秒后反向关门。

## 对我们为什么有用

楼宇机电方向里，自动门近题很多会退化成部件介绍或简单便利性说明，而这篇保住了更像控制器正文的表达。后续做状态机自动生成时，可以直接把它看成“阈值筛查 + 门控执行 + 异常拒绝”的小而完整样本。

另外，这篇还有一个很适合当数据集样本的点：它把 nominal path 和 abnormal path 都写在同一条链里。正常温度对应开门和回关，异常温度对应锁门和蜂鸣，这比只写“温度正常则开门”的单分支门控稿更有价值。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 2 页 `3.1 Prototype Overview` 和 `3.2 Functions and How it Works`。这两段已经足够锁定状态机主链，重点是确认 `Infrared -> MLX90614 -> LCD -> normal / abnormal branch -> motor or buzzer/LED` 这条顺序，以及“几秒后反向关门”的时间语义。

第 1 页的引言可以只作为背景补充，帮助理解为什么这里要把体温筛查接到自动门上，但不需要花太多时间。真正值得反复核对的是第 2 页正文，因为 `STM.md` 里的关键 guard、动作输出和异常分支几乎都集中在那里。
