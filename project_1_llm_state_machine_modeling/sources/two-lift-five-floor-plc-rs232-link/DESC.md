# 双梯五层主从组控电梯 / Miniatur 2 Lift 5 Lantai Menggunakan Kontroller 2 PLC Omron CPM1A dengan One to One PC Link Connection Menggunakan Kabel RS232

## 论文在讲什么

这篇论文研究的是两台并列五层电梯的协同控制，而不是单梯的简单上下行。作者使用两台 Omron CPM1A PLC，通过 `RS232` 的 `one-to-one PC link` 进行通信，一台作为主控负责任务分配，另一台作为从控负责执行和回传状态，从而把双梯协同问题落到一个可运行的缩比系统上。

文章的核心不是机械建模，而是怎样让两台电梯在同一栋楼里“互相知道彼此在做什么”。因此文中比较详细地写了主从通信、楼层位置与方向状态、任务计数、厅外按钮分配、舱内按钮执行、过载告警以及突然断电后的恢复行为。

## 控制系统在文中的位置

控制系统就是论文主线。第 2 页先定义 `duplex-collective` 的协同原则，第 3 页到第 6 页把主控与从控程序结构拆开写，主控负责接收状态、比较任务、按位置和方向分派呼叫，从控负责接收分派结果并执行单梯运动。

对 `sources/` 来说，这篇论文最有价值的是它天然呈现出层次结构。最外层是双梯调度器，下一层是两台单梯执行器，再往下才是电机、限位和蜂鸣器等实现细节，所以它比常见单梯样本更像一个真正的 `HSM` 案例，而不仅是平面的上行/下行流程图。

## 对我们为什么有用

当前 `🏢` 方向虽然有不少电梯论文，但大量样本都集中在单梯调度和门控定时。双梯组控样本能补的是“多执行体 + 上层调度器”的结构，这对 project 1 后续处理层次状态机和并行执行器描述很有帮助。

另一个价值在于它的异常链并不薄。过载告警、供电中断、重新上电后 first cycle 复位到最近楼层，这些都属于真实控制系统里很重要但在简化论文里经常被略过的部分。它让这篇文献不仅能提供正向任务分配逻辑，也能提供恢复和告警分支。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看第 2 页的 `duplex-collective` 说明，再顺着第 3-5 页的主控程序逻辑读下去，把“接收状态 -> 比较任务 -> 分组位置 -> 分派呼叫”这条上层调度链先抓出来。随后看第 5-6 页的电机控制段，把 latch、限位、上下优先级和 stop timer 如何落到单梯执行器上再补全。

如果要核对异常与边界情况，就直接看第 6-7 页的整体测试表和文字说明。那里已经把过载蜂鸣器、同时多呼叫、供电中断以及上电恢复后的行为顺序写得比较清楚，比只看流程图更适合重构 `STM.md`。
