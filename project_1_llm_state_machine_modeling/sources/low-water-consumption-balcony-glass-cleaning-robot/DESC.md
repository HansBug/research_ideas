# 低耗水阳台玻璃清洁机器人 / Design and Implementation of a Low-Water-Consumption Robotic System for Cleaning Residential Balcony Glass Walls

## 论文在讲什么

这篇论文讨论的是一个面向住宅阳台玻璃外侧的清洁机器人系统。作者关注的不只是“怎么把刷子装到窗户上”，而是怎样在受限的阳台窗框空间里，把润湿、刷洗、污液回收、故障停机和低耗水运行组织成一套可重复的自动维护流程。

论文的系统由线性执行器、刷洗电机、真空回收模块、液位/限位/电流传感器和 `ESP32` 控制核心组成。真正值得保留的是其事件驱动状态机：状态不是单纯的机械动作顺序，而是与 current spike、limit switch、watchdog 和 low-fluid 这些工程保护条件直接耦合的监督控制逻辑。

## 控制系统在文中的位置

这里的控制系统描述就是论文主线之一。第 `2.3.1` 节明确把 `AWCS` 写成 formal event-driven `FSM`，给出 `S0-S4` 五个状态以及 `e0-e5 / ef` 事件，再往后用实验场景逐个验证这些状态转移是否真的按设计触发。

这使它并不是一篇单纯偏机械结构或节水装置的论文。对 `sources/` 来说，最重要的不是玻璃刷本体，而是这套“启动归零、润湿、刷洗、回收、故障中断”的控制器如何被明确定义、执行和验证。

## 对我们为什么有用

这篇论文对 `🏢` 方向有帮助，因为它补进的是建筑维护机器人样本，而不是文库中更常见的电梯、自动门和楼宇环境控制。它带来的不是传统楼宇机电顺序控制，而是一个面向建筑表面维护任务的事件驱动监督器，能拉开领域内部的样本差异。

同时，它的状态链既包含 nominal operation，也包含 fail-safe 逻辑。`<50 ms` 异步中断、`200 ms` watchdog、液位保护和边界限位都不是背景参数，而是状态机的一部分，这使它很适合补充“异常恢复链”和“工程定时保护链”类样本。

## 如果需要人工细读，建议怎么读

建议先看第 `9-10` 页的 `Control Logic and Deterministic State Transition`。第一轮先把 `S0-S4` 与 `e0-e5 / ef` 记清楚，再确认 nominal cycle 和 fault path 分别是什么；这一步就能恢复大部分监督控制骨架。

第二轮再看第 `15-16` 页的验证场景以及第 `20` 页的 failsafe protocol。前者告诉你这些状态迁移怎样在实验里被触发，后者则把 boundary、torque、watchdog、low-fluid 这些 fault guard 说清楚。机械结构和节水性能分析可以放到第三轮再看。
