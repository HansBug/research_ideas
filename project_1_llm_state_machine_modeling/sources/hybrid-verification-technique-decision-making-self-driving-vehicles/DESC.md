# 自动驾驶车辆混合验证与停车场行为监督 / Hybrid Verification Technique for Decision-Making of Self-Driving Vehicles

## 论文在讲什么

这篇论文整体上讲的是如何把自动驾驶车辆的决策系统同时放进 `MCMAS` 和 `PRISM` 做混合验证，但它并不是一篇只有方法框架的验证论文。作者同时搭了一套真实的自动驾驶软件平台，包含 perception、rational agent 和 feedback control，并且专门用停车场场景来展示车辆如何搜索空位、识别行人/车辆、评估成功概率，再把最合适的动作真正下发到执行层。

对我们最关键的是，文中没有把停车场决策只写成一句“系统会自动泊车”。它明确把行为层写成 finite-state 风格的决策结构：找不到车位时进入探索，发现空位后切到泊车，遇到人或来车时再根据距离切换为避障、减速或停止，并且把这些动作和 `5 mph / 2 mph`、`12-6 m / 6-3 m` 这种 guard 绑定在一起。因此这篇论文虽然带 formal verification 背景，但真正可用的样本落点仍然是车辆行为监督器本身。

## 控制系统在文中的位置

我们关心的控制系统描述属于论文的核心案例，而不是边角实现细节。作者需要先把自动驾驶行为层写成足够明确的离散决策结构，才能进一步在 `MCMAS` 中检查规则一致性、在 `PRISM` 中评估动作成功概率，所以停车场行为监督器其实是整篇方法链能够成立的前提。

同时，这套控制逻辑的角色又和库内常见的“直接画状态图的自动驾驶行为规划器”略有不同。这里的行为状态是通过 belief、rule 和 action 的执行计划来组织，再通过感知上下文触发切换。也就是说，论文主体既包含“如何验证”，也包含“被验证的具体行为监督器是什么样”，后者正是 `sources/` 需要留下来的样本。

## 对我们为什么有用

这篇论文对 `🚗` 方向的价值，在于它补的是一个“停车场场景下的高层行为监督器”样本，而不是常见的高速换道、超车或城市道路路口决策。它把停车场探索、目标泊位确认、对行人和来车的距离分级响应都写成了清晰的离散链条，能补充自动驾驶领域在低速停车环境下的状态切换样本。

它也很适合作为 `FSM + T0` 风格的高质量条目。这里没有显式时钟窗口，但有很稳定的上下文 guard、模式切换和动作输出：探索时生成 exploration waypoint，泊车时生成 parking waypoint，危险逼近时切 slow mode 或 stop mode。对后续做自然语言到状态机建模，这类“环境驱动的离散模式管理”比单纯的验证结论更有直接数据价值。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 `14` 页附近关于 behavior layer 的总说明，把“每个 driving behavior 都可视作 finite state machine state”这一层边界锁定住。然后直接跳到第 `17-18` 页的 executable plans，把 `Need to explore parking lot`、`Commencing parking operation`、行人/车辆距离触发的 `slow mode / stop mode / avoidance` 这几条主链读完整。

第二轮再看第 `21-22` 页的 predicates、future consequences 和 action 集合，用它们把状态边界、guard 条件和动作输出补严。至于更前面的 `MCMAS / PRISM` 建模细节、概率验证和数学定义可以后读，因为那些内容主要服务于“如何验证这套行为层”，而不是先恢复停车场监督控制器本身。
