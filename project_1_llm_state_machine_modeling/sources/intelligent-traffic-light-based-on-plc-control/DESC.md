# 基于 PLC 的三模式交通灯自适应控制 / Intelligent Traffic Light Based on PLC Control

## 论文在讲什么

这篇论文讨论的是一个以 `Siemens S7-200 PLC` 为核心的四路口交通灯控制器，目标不是只复现传统固定配时，而是把交通流感知、时段划分和倒计时提醒整合到同一个离散控制系统里。作者把研究对象放在学校和商圈共存、峰时拥堵明显的路口，因此控制重点集中在“什么时候该采集流量、什么时候该切换模式、哪个方向应该拿到更长的绿灯”。

正文里的系统边界相对清楚：有双激光光电传感器、PLC 内部时钟、直行与左转灯组、数码管倒计时和按时段运行的逻辑。它不是在讲抽象算法框架，而是在讲一个能实际运行的信号机流程，尤其是峰时与夜间两类策略如何切换。

## 控制系统在文中的位置

交通灯控制器本身就是论文主体，不是为了展示别的方法而附带的案例。作者直接把“智能模式 / 常规模式 / 夜间模式”作为系统工作模式来讲，并进一步把传感采样周期、计数器比较和绿灯时长分配放到 PLC 程序设计里说明。

对 `sources/` 来说，这类材料的价值在于它不只给了“交通灯会循环”的泛泛描述，而是给出了一个比较完整的工程控制画像：有模式切换，有输入计数，有按比值分配输出时长，也有倒计时和夜间退化策略。这使它更适合作为 `EFSM + T1` 的工程交通信号样本，而不只是简单的红黄绿定时轮换。

## 对我们为什么有用

这篇样本适合补充那类“同一控制对象在不同时段采用不同模式”的信号控制语料。它比纯固定时长交通灯更接近真实工程，因为文中明确写了峰时与常规时段的不同采样频率，也写了 AC / BD 两方向在不同流量关系下的绿灯时长会改变。

从数据集角度看，最值得保留的不是硬件接线，而是它把控制语义压成了几条稳定规则：白天先分峰时和常规时段，夜间停用流量感知；峰时进入智能模式后，用计数器比值判谁拿 `33 s`、谁拿 `13 s`；所有绿灯尾部再统一接一个 `3 s` 闪烁倒计时。这些都是后续自动建模容易抓住的离散控制骨架。

## 如果需要人工细读，建议怎么读

人工回原文时，建议先看 `2. Function Description` 和 `3. Design ideas`，先把三种工作模式、峰时/常规的采样周期和夜间停用传感的边界读清楚；随后直接跳到 `5.1 main program design` 与 `5.3 Countdown program design`，重点抽取计数器比值如何影响 `33 s / 13 s` 绿灯分配，以及倒计时末 `3 s` 闪烁这一段。

如果还要进一步核实实现细节，再回看 `4. PLC Hardware Design` 里的输入输出分配表，确认传感器、直行/左转灯组和倒计时显示在系统中的角色即可。图示和接线部分可以放在第二轮，因为真正支撑 `STM.md` 的主链已经主要体现在模式划分、采样周期、比值判断和输出时长规则里。
