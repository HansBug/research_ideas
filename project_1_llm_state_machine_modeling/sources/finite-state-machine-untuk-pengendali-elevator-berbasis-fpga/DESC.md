# 楼宇机电与电梯控制 / Finite State Machine untuk Pengendali Elevator Berbasis Field Programmable Gate Array

## 论文在讲什么

这篇论文研究的是一个基于 FPGA 的电梯控制器。作者的切入点不是楼宇调度优化或电梯群控，而是更直接地讨论怎样用 `state diagram -> VHDL -> FPGA` 这条链，把电梯的上行、下行、停止和等待逻辑落实到一个可综合的数字控制器上。论文明确采用 Moore 型有限状态机作为主设计方法。

它的关键价值在于，正文不是只说“用了 FSM”，而是把六个状态和三类核心输入信号都写了出来。`dn_slow / stop_dn / done / stop_up / wait / up_slow` 这些状态，以及 `at_flr / start / keep_going` 这些 guard，构成了相当清楚的电梯运动逻辑骨架。对于 `sources/` 来说，这已经足够形成一条高质量 `FSM + T0` 电梯样本。

## 控制系统在文中的位置

我们关心的控制系统描述是论文的主设计对象。文章的背景部分会回顾 FPGA 输入方式和相关电梯控制研究，但真正进入主体后，作者直接围绕这套电梯 FSM 展开，包括状态编码、输入输出信号、状态迁移条件和在 Spartan-3E 开发板上的实现结果。

这意味着它不是把电梯当成某种验证工具的演示对象，也不是只给一张模糊的状态图。相反，论文把电梯控制器本身当成实现目标，文本里已经足够清楚地说明哪些信号触发状态转移、哪些状态负责等待、哪些状态负责上行或下行，因此很适合直接转写为单条核心 `STM` 条目。

## 对我们为什么有用

这篇论文对 `sources/` 的价值，在于它补的是 `🏢` 领域里一条比较少见的“纯 FSM、无显式定时”的 FPGA 电梯控制样本。文库里电梯类材料很多都偏 `EFSM + T1`，强调门控等待、楼层优先和局部定时；而这篇更接近一个用明确状态和 guard 驱动的 Moore 控制器，能有效增加当前电梯领域内部的结构差异。

它还有一个很重要的优点，就是状态名和 guard 没有藏在图里不解释。作者明确解释了从 `dn_slow` 到 `stop_dn`、从 `stop_dn` 分叉到 `dn_slow` 或 `stop_up`、再到 `up_slow` 的条件关系，这使它不仅能做摘要级样本，还能做具有明确状态词汇的文本样本。

## 如果需要人工细读，建议怎么读

如果后续需要人工细读，建议先跳过大部分 FPGA 背景综述，直接看第 2-3 页的 `HASIL PENELITIAN DAN PEMBAHASAN`。先把状态集合、输入输出信号和 `dn_slow / stop_dn / stop_up / up_slow` 的跳转条件读稳，再回头看图 2 对照状态图，就能很快把整条控制主链恢复出来。

第一轮复读时，资源占用、时钟周期分析和一般 FPGA 实现细节都可以放后。真正优先级最高的是状态集合、`at_flr / start / keep_going` 的作用、以及哪些状态只是等待态、哪些状态在驱动运动。只要这条线读稳，这篇论文就足以稳定支撑一个电梯 FSM 样本。
