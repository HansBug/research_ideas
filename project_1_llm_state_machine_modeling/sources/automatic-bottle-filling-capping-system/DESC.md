# 多规格双液体灌装封盖控制 / Automatic Bottle Filling And Capping System

## 论文在讲什么

这篇论文讨论的是一个把灌装、封盖和出料分拣整合到同一台设备中的瓶装生产系统。作者要解决的问题不是“怎么做单一瓶型灌装”，而是如何在一条线上同时处理 `250 ml / 500 ml` 两种容量和 `water / juice` 两种液体，并在灌装后继续完成封盖和四路出料。系统使用 Arduino 作为中央控制器，配合推瓶机构、旋转平台、泵、阀、封盖机构和输送带来实现整条流程。

论文写法的价值在于它不是只讲机构，而是把顺序也写出来了。用户先输入每种组合需要的瓶数，随后系统按指定顺序送瓶、停位、灌装、封盖，再根据容量和液体类型送往不同出口。这种“面向批次组合任务的顺序控制”比很多只剩单瓶到位灌装的短稿更完整。

## 控制系统在文中的位置

控制系统是论文的核心对象。摘要已经把目标写成 `fill -> cap -> dispense` 的一体化自动系统，方法部分则按 `Bottle Selection / Bottle Placement / Filling Process / Capping Process / Dispensing Mechanism` 分段展开，几乎每一段都在回答“控制器下一步应该做什么”。这说明文中的状态推进不是附属说明，而是作者真正要表达的系统行为。

另外，这篇论文还保住了一个比较少见的控制点：用户输入不只是触发启动，而是决定后续生产顺序。也就是说，这套系统既有现场传感驱动的停位与执行，也有作业任务层的顺序编排。这让它相比许多单一工位论文更适合被整理成较完整的 `EFSM + T1` 样本。

## 对我们为什么有用

它对 `sources/` 的意义在于提供了一个“多规格 + 多液体 + 封盖 + 分拣”的复合制造控制对象。现有库里虽然已经有若干灌装样本，但很多只覆盖灌装本身，而这篇把上游瓶型选择、中游灌装、下游封盖和末端分类出料全部串起来，因此在样本跨度上更完整。

同时，这篇论文对数据集的帮助不只是多一个工业对象，而是多一种控制粒度。它一方面保留了 IR 触发停位、阀泵执行、封盖机构动作这些工位级细节，另一方面又保留了批次顺序和任务组合，这让后续做自然语言到状态机建模时，可以更好地区分“单工位控制”和“批次流程控制”。

## 如果需要人工细读，建议怎么读

人工细读时，建议先从第 `3.2-3.6` 节入手，也就是 `paper_content.txt` 第 `152-216` 行。这一段已经按用户输入、推瓶、灌装、封盖、出料的顺序把整条主链写明白了，足够先搭建状态机骨架。接着读第 `230-273` 行的 block diagram 说明，用它补强旋转平台、IR 停位、阀泵灌装和四路出料之间的动作关系。

如果之后还需要更细的硬件边界，再回看第 `11-17` 行摘要和前面的部件介绍即可。相比之下，关于 Arduino 基本参数、电源配置和电路连接的说明可以后看。真正重做 `STM.md` 时，需要优先保住的是：用户输入如何决定顺序、灌装为何属于时间驱动、封盖为何由第二个 IR 触发，以及四路出料是如何按“容量 × 液体类型”区分的。
