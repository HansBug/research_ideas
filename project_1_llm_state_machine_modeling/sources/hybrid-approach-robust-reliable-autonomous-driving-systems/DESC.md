# 城市场景自动驾驶 Moore FSM 决策控制 / Integrating Modular Pipelines with End-to-End Learning: A Hybrid Approach for Robust and Reliable Autonomous Driving Systems

## 论文在讲什么

这篇论文讨论的是一种“模块化管线 + 端到端学习”的自动驾驶混合架构。作者并不是完全端到端地把所有决策都交给神经网络，而是保留了感知、碰撞风险评估、局部规划和控制这些模块，再把学习模块嵌进去，以提升系统在复杂城市场景中的鲁棒性和可靠性。

对 `sources/` 来说，最关键的不是整体混合架构口号，而是作者仍然把 decision-making module 明确实现为一个同步 `Moore` 有限状态机。它根据碰撞风险评估模块输出的二进制输入，在 `Drive / Follow the Leader / Red Light / Stop Sign` 四个状态之间切换，并把期望速度交给后续纵向控制器执行。

## 控制系统在文中的位置

这里的 FSM 不是附属案例，而是 modular pipeline 中连接风险判断和执行控制的核心离散决策层。上游 `CRA` 负责抽象出道路前方是否有障碍、红灯或停车牌，下游 `PID` 负责根据目标速度生成实际制动和油门指令，而中间“当前到底该采用哪种速度/停车策略”的选择，则由这个同步状态机负责。

这也使它在论文里扮演了一个非常清晰的工程角色。相比很多只说“有 behavior planner”但不给状态机细节的自动驾驶论文，这篇文章把输入编码、四个状态的功能、`TTC` 逻辑以及 `10 Hz` 运行频率都写明了，因此更适合作为自动驾驶离散决策样本收进 `sources/`。

## 对我们为什么有用

这篇论文补的是 `🚗` 方向里较少见的 `FSM + T1` 城市场景决策样本。库里汽车方向已有不少 `HSM` 行为规划、车队协议和连续耦合换道控制，但这种“同步 `Moore` FSM + 显式输入编码 + 工程采样频率 + 速度输出接口”的写法还不算多，能够明显增加样本分布的多样性。

同时它也比较利于后续数据集化。原文直接给出四个状态、四类输入、各状态的速度/停车职责、`TTC` 参与方式以及输出到 `PID` 控制器的接口，因此能稳定地转写成“输入触发 + 状态职责 + 输出动作 + 工程时间语义”这一类高质量自然语言样本。

## 如果需要人工细读，建议怎么读

人工重读时，建议先直接看第 `9` 页的 `3.4 Decision Making`、`Figure 6` 和 `Table 2 / Table 3`，先把四个状态、输入编码、状态转移和 `10 Hz` 同步执行频率完整读出来。随后顺着第 `9` 页 `3.5 Control` 往下看，确认这个 FSM 输出的是期望速度，并由 `PID` 纵向控制器负责跟踪执行。

至于前面的 perception、端到端学习模块、网络结构和后面的实验对比，可以放到第二轮再看。第一次人工复核时，最值得优先锁定的是“碰撞风险评估如何被压成输入符号，FSM 如何把它们映射成四类 driving states，并通过目标速度影响实际控制”这条离散决策主链。
