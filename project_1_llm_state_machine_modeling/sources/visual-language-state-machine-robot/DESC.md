# 视觉语言模型驱动的移动机器人主状态机 / Visual Language State Machine Robot

## 论文在讲什么

这篇论文讨论的是一台移动机器人如何利用视觉语言模型理解环境、识别人类手势和危险物，并把这些感知结果转成离散行为切换。作者的重点不是训练一个端到端策略，而是把 VLM 当作高层感知器，再用显式状态机把导航、跟随和人工接管组织起来。

系统对象也很具体，就是一台基于 ROS 的 RoverZero 机器人。论文说明它在 `Navigation` 状态下会根据环境语义调整导航参数，在 `Follow` 状态下直接根据检测到的人体位置控制速度，而在检测到危险物时会进入通知和远程控制链，这使它成为非常清楚的“感知驱动行为监督器”样本。

## 控制系统在文中的位置

控制系统是论文的主体实现方式。VLM 在文中并不是独立目标，而是为状态机提供 `environment / object / person / gesture` 这类离散输入；真正决定机器人此刻做什么的是 master state machine 和各状态下的执行逻辑。作者还把决策算法写成了规则化流程，而不是模糊地说“模型学会了行为切换”。

这点对 `sources/` 很重要，因为它保住了我们真正关心的控制链。论文不但给出 `Navigation / Follow / Notification + Remote control` 状态图，还给出 `2 s / 10 s` 稳定化窗口、`30 s` 跟随上限、`tracking lost > 1 s` 退出条件以及危险物触发的远程帮助协议，因此不是只有图没有 guard 的薄状态样本。

## 对我们为什么有用

这篇论文补的是 `⚙️` 方向里一种比较新、但仍然保持可追溯状态机骨架的机器人行为控制样本。它的特别之处在于感知侧用了 VLM，但离散控制侧没有因此退化成黑箱，反而更清楚地展示了“语义识别结果 -> 模式切换 -> 参数/速度输出 -> 人工接管”的完整链路。

对后续数据集建设来说，这类样本很适合补“语义感知驱动的监督器”子类。它不像传统工业 PLC 那样围绕硬件传感器和继电器，也不像纯人机交互论文那样只讲界面体验，而是把机器人行为模式、局部时间规则和人工接管流程都写成了可直接抽取的控制逻辑。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看 Fig. 3 和 `3.1-3.2`，先确认主状态图里有哪些模式，以及 `Navigation`、`Follow`、`Remote` 各自控制的是什么。随后直接看 Algorithm 1 和 Algorithm 2，把输入 JSON 如何决定主状态、`2 s / 10 s` 稳定化如何实现、`30 s` 跟随计时器和 `lost > 1 s` 退出条件怎样约束跟随行为读清楚。

第二步再看 `3.5-3.6` 和实验部分，重点核对危险物检测如何触发通知模块、机器人何时停止等待、远程控制何时接管和结束。VLM API、模型吞吐、系统部署细节可以放到第二轮，因为第一次人工复核最关键的是这套状态机如何把语义感知结果转换成离散模式切换和人工干预链。
