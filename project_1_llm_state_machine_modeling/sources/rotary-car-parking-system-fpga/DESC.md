# 旋转立体停车安全与取车控制 / Hardware Design and Implementation of Automated Rotary Car Parking System on FPGA

## 论文在讲什么

这篇论文讨论的是一个基于 `FPGA` 的旋转立体车库控制系统。它关心的不是停车推荐、导航或计费平台，而是车真正进入旋转停车装置之后，系统如何检查车辆是否允许入场、如何把车分配到存储位置、如何在用户取车时转到正确方向并把车送回取车口。

论文主体围绕几个非常具体的控制子链展开：入场前的前后轮重量校验、车位占用计数、取车密码认证、左右最短路径旋转、火警温度联锁以及停车时间累计与费用计算。它虽然是 `FPGA` 实现文，但正文没有停留在纯硬件平台展示层，而是把这些控制逻辑分别写成了可追溯的算法与结果说明。

## 控制系统在文中的位置

我们关心的控制系统描述在文中就是核心对象。作者先在方法部分把整个旋转车库拆成若干子功能模块，再在结果部分逐一用仿真解释计数、消防、重量校验、最短路径和计时模块如何工作，这使得控制逻辑并不是藏在零散图里，而是被文本明确说明了。

尤其值得保留的是，这篇论文把“系统什么时候不动作”也写得比较清楚。比如密码错误时电机不转、错误房号或空房间取车时给出错误响应、温度超过阈值时泵和报警同时开启，这些都让它比许多只有入场/出场主链的停车稿更接近真实工程控制器。

## 对我们为什么有用

对 `sources/` 来说，这篇论文的价值在于它补的是停车方向里比较完整的一类“系统级监督控制”样本。现有停车条目里虽然已有门禁、升降和选位控制，但这篇把重量门槛、最短路径、密码认证、消防和计费同时放在一套停车设备控制里，覆盖面更宽。

它的另一个价值是细节密度高而且分布比较均匀。方法部分负责讲规则，结果部分负责把这些规则再验证一遍，因此后续不管是抽取更规范的状态机自然语言描述，还是人工回原文校验 guard、异常响应和时间语义，成本都比较低。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看第 4-7 页 `Methodology`。第一轮先抓五件事：重量校验门槛是什么、入场后如何计数和开始计时、取车时密码如何参与、房间号怎样映射左右旋转方向、温度超阈值后会触发哪些动作。读完这一段后，再看第 8-12 页的仿真结果，把这些规则和模块行为逐一对上。

第 2-3 页的大段停车背景、`FPGA` 与 `SoC` 一般性介绍可以放到第二轮再看。它们有助于理解作者为什么选 `FPGA`，但对重做 `STM.md` 来说，优先级明显低于重量约束、计数/计时、密码认证、最短路径和消防联锁这几条主控制链。
