# 社会导览机器人并行导航监督器 / Autonomous Social Robot Navigation using a Behavioral Finite State Social Machine

## 论文在讲什么

这篇论文讨论的是一个社交导览机器人怎样在带访客的人群场景里完成引导任务。作者把问题设定得很具体：机器人需要带着一个访客小组沿若干参观点移动，同时还要在访客暂时离队、机器人急转弯、视野丢失等情形下保持“社会化”的反应，而不是只按最短路径机械行走。为此，论文没有只谈局部避障或轨迹规划，而是把速度管理、目标点序列和语音反馈一起组织进一个带行为状态的控制框架。

从系统组成上看，文中最关键的是 `speed manager`、`goal sequencer`、`APF` 控制器和 `announcement lock` 的配合。`speed manager` 负责基于访客是否可见和丢失时长调整速度，`goal sequencer` 负责把参观点分解成子目标并推动游览进程，`APF` 则把这些目标与许可速度转成底层运动控制。这样一来，论文虽然带有机器人导航背景，但真正值得保留的是它把“游览任务推进”和“访客掉队后的 regrouping”写成了明确的离散控制链。

## 控制系统在文中的位置

我们关心的控制系统描述在这篇论文里不是陪衬，而是主体。作者专门用一节讲 `Speed manager`，把它明确定义成 `BFSSM`，并进一步给出 `moving`、`stopped`、等待 announcement lock、等待访客返回、再出发这些状态以及 `tstop`、`tannounce` 一类工程定时变量。也就是说，文中并不是只说“机器人会停下来等人”，而是把停、等、播报、恢复运行这整条监督逻辑写清楚了。

更重要的是，这套控制并不是孤立的单状态图。论文同时说明 `speed manager` 与 `goal sequencer` 是并行运行的，并通过 `announcement lock` 共享语音资源，`APF` 还要读取 sequencer 给的子目标和 speed manager 给的速度上限。对 `sources/` 来说，这种“顶层任务推进 + 局部定时 regrouping + 共享资源仲裁”的结构，比只给机器人若干导航模式名的论文更有价值。

## 对我们为什么有用

这篇论文对文库的价值首先在于它补进了一个此前相对少见的 `⚙️` 方向双 A 样本，而且不是常见的工业机械臂或移动服务机器人一般任务管理，而是专门面向社交导览场景的 timed supervisor。它同时保住了状态、定时、共享资源、并行模块边界和恢复链，这些都很适合后续做“自然语言到状态机”的建模样本。

其次，这篇样本和库里常见的 `PLC / 电梯 / 交通灯 / 铁路道口` 控制器差别很大。它的输入不只是按钮或传感器阈值，还包含“访客是否仍在视野内”这种任务语义；它的动作不只是开关执行器，还包含继续移动、减速、停下、播报等待消息、播报恢复消息等。这让它在结构和语义上都能拉开与传统顺序控制样本的差异，对文库平衡性是有帮助的。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 11 页附近 `Fig. 2` 与 `4.2 Speed manager`，先把四个模块的边界固定下来：谁给目标、谁限速、谁做运动控制、谁仲裁 speaker。接着直接读第 11-13 页关于 `moving`、`stopped`、`wait for visitors`、`announcement lock` 以及 `Algorithm 1 Velocity manager` 的段落，把 `tstop`、`tannounce`、`announcementLock`、`visitorsStatus` 这些真正驱动状态迁移的变量圈出来。

第一次人工复核时，不必优先深究人脸检测网络、局部势场公式或实验对比指标。那些内容当然有背景价值，但对重新抽取 `STM` 来说，优先级明显低于“并行模块怎么交互、什么时候停止、什么时候播报、什么时候恢复游览、子目标如何推进”这条主控制链。只要先把这条链读稳，这篇论文就已经足够支撑高质量状态机样本。
