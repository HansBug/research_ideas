# 车形机器人并联停车五步自动机 / A RULE-BASED CONTROLLER SIMULATION FOR AN AUTONOMOUS PARALLEL PARKING OF A CAR-LIKE ROBOT USING LASER SENSORS

## 论文在讲什么

这篇论文解决的是并联停车辅助控制问题。作者把一个缩比车形机器人放进自建仿真环境里，用前后两组 `LIDAR`、里程计和罗盘信息来驱动一套 rule-based finite automaton，让车辆自动完成停车位搜索、预对位、倒车切入、反打方向和最终居中。论文目标很明确，就是用接近“熟练驾驶员操作步骤”的方式，验证有限自动机能否稳定完成并联停车。

从内容组织上看，这不是单纯的轨迹规划论文。作者虽然也讲了 bicycle kinematics 和传感器模拟，但核心部分明显是第 4 节那套停车自动机：有五步状态，有各步使用的传感器条件，有停车位长度与最小转弯半径的判定，还有何时打满方向、何时反向打轮、何时通过 `SF3` 和 `SR3` 逼近停车位中心。

## 控制系统在文中的位置

我们关心的控制系统描述是正文主线。摘要一开始就说明 automatic mode 根据前后 laser sensor 数据生成 acceleration 和 steering commands，到了第 4 节则直接给出 finite automaton 图，把每一步的触发条件和车辆动作展开。换句话说，控制器不是某个附带模块，而是论文的核心贡献。

这篇论文尤其适合 `sources/` 的原因，是它把“停车”这个很容易被写成纯轨迹优化的问题，改写成了离散阶段控制链。slot search、vehicle positioning、entry、counter-steer、alignment 这些动作都通过传感器阈值和几何约束连接起来，因此比只给一条平滑轨迹的论文更接近状态机样本。

## 对我们为什么有用

当前 `🅿️` 方向的双 A 条目仍然偏少，而且很多停车类论文容易滑向局部计数模块、安防显示模块或纯连续控制。这里补进来的这篇不一样，它明确给出了一条系统级停车动作链，而且 guard 既包含传感器触发，也包含 `R / Rmin / s` 这类几何约束，能很好地补强停车样本里 `EFSM + T0` 这一侧。

它还有一个现实价值：作者试图把“会停车”的经验步骤形式化，所以状态划分和 guard 命名都比较直观。对后续做自然语言到状态机建模来说，这种“可读性高、每步有物理含义、条件和动作都不藏着”的样本很适合作为高质量停车控制案例。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看摘要和第 4 节开头，把 Figure 7 那个五步 automaton 先读顺，再去看文字解释每一步在做什么。然后重点盯住 `SF1`、`SR1`、`SR3`、`SF3`、里程计计数器以及 `R / Rmin / s` 这些变量，因为它们几乎决定了整条状态链的切换边界。

第 3 节的仿真器、车模和传感器噪声部分可以放到第二轮再看。它们确实解释了实验平台和数据来源，但如果目标是重做 `STM.md` 或提炼数据集样本，优先级明显低于第 4 节关于停车状态、触发条件和转向动作的直接控制描述。
