# 瓶盖缺陷检测与拒收臂控制 / Embedded Device Berbasis PLC pada Miniatur Konveyor untuk Pengoperasian Simulator Rejection System

## 论文在讲什么

这篇论文讲的是一条小型输送带上的瓶盖缺陷拒收系统。作者用 `PLC Omron`、多个 `proximity sensor`、一个瓶位 `optical sensor` 和步进电机驱动的 rejector 臂，构建了一套能把缺盖或压盖不良瓶推出输送线的顺序控制装置。

它的重点不只是“做了一个质检原型”，而是把检测、等待对位、推出、计数和停机这些动作顺序写成了完整控制链。尤其是“先判缺陷，再等瓶位到位，再执行 rejector”这一层次，在制造样本里很有代表性。

## 控制系统在文中的位置

控制系统是这篇论文的中心内容。前面虽然有不少输送带、传感器和面板搭建描述，但这些并不是独立背景，而是直接服务于 rejection logic：哪个传感器判断缺陷、哪个传感器负责位置对齐、步进电机如何动作、计数何时增加。

对我们有用的不是通用机器视觉或工业质检背景，而是这一条具体的 `PLC` 顺序控制链。原文把自动模式、手动模式和急停分支一起保留下来，因此它不仅可用于 nominal path，也能提供维护/安全类分支样本。

## 对我们为什么有用

对 `sources/` 来说，这篇论文补的是一个很适合建数据集的制造质检样本。它既不像纯灌装那样只强调定时填充，也不像纯分流那样只做颜色路由，而是多了一层“检测不良 -> 对位 -> 拒收”的异常处理链。

这种结构很适合抽出状态机，因为状态阶段很自然：输送、检测、等待对位、推出、恢复。再加上 `30 ms` 的步进动作和 `manual / auto / emergency stop` 分支，后续做状态机生成、异常恢复或多模式分类时都能用上。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 4-5 页关于 `proximity #1/#2/#3`、`optical sensor` 和 rejector 臂的说明，把各个输入和执行器的角色固定下来。然后直接读第 7-10 页的算法、I/O 地址和自动模式操作说明，重点圈出“缺陷信号何时成立”“为什么要先等瓶子对齐”“`30 ms` 步进脉冲何时发出”这三件事。

最后再看第 10-11 页结论和展示图，确认 rejector 的动作不仅存在于逻辑描述里，而且和实际装置行为一致。输送带尺寸、供电和面板布线可以放到第二轮再看，不影响先抽取主控制链。
