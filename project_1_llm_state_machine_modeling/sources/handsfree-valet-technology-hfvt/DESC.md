# HANDSFREE VALET TECHNOLOGY (HFVT)

## 论文在讲什么

这篇论文讨论的是一种面向停车场场景的自动代客泊车原型。它的重点不是做停车场管理平台，也不是做纯几何轨迹推导，而是把“车辆先搜索空位、再确认车位、接着完成对齐和泊入、最后做停车后修正”这条高层控制链组织成一个有限状态机。

论文里最有价值的部分，是它没有把自动泊车写成一句“发现车位就停车”。作者明确保留了 `Looking`、`Detecting`、`Alignment`、`Park`、`Stop` 这些命名状态，并且把并联泊车和头入泊车分成两条动作分支，同时写清楚了超声与触碰传感器在状态切换中的作用。

## 控制系统在文中的位置

这里的控制系统描述是正文核心，不是附带例子。摘要先把自动搜索车位和自主完成 `parallel / head-in park` 说清楚，后面的 `Parking Algorithm` 又继续把高层状态、进入条件、回退条件和停车后修正展开。对 `sources/` 来说，这意味着我们可以直接从原文恢复一条完整的离散监督链，而不需要靠猜测补状态。

需要如实说明的一点是，正文有一句话写“six states”，但提取文本里被完整枚举并解释的命名状态是 `Looking / Detecting / Alignment / Park / Stop` 这五个。好在这些状态本身和转移逻辑已经足够完整，仍能稳定支持 `STM.md` 的主条目。

## 对我们为什么有用

这篇论文对当前文库的价值，在于它补的是 `🅿️` 方向里偏“停车行为监督器”的样本，而不是常见的车位计数、门禁引导或连续轨迹控制。它保留了感知、状态、分支和停车后修正四类信息，对后续做“从自然语言恢复停车 FSM”的任务很有帮助。

另外，它和库里已有的一些停车管理稿形成互补。已有条目里有不少是 `gate / password / vacancy` 型停车场控制，也有一些是分阶段轨迹规划；这篇则更像车辆本体的停车任务机，把搜索、判位、对齐和执行四段更清楚地串起来。

## 如果需要人工细读，建议怎么读

人工重读时，建议先读第 1 页摘要，再直接看第 2-3 页的 `Parking Algorithm`。第一轮优先抓四件事：一是四个传感器和两个电机分别承担什么角色；二是 `Looking -> Detecting -> Alignment -> Park -> Stop` 的主链；三是 `isParallel` 如何把流程分成并联泊车和头入泊车两条分支；四是 `Stop` 状态如何用超声差值和触碰反馈做停车后修正。

后面关于实现与传感器选型的段落可以放到第二轮再看。那些内容有助于理解原型怎么搭起来，但对我们当前最关心的状态机恢复来说，优先级低于命名状态、触发条件和回退路径。
