# 视觉驱动的双优先模式交通灯监督器 / Prototipe lampu lalu lintas menggunakan PLC dan SCADA berbasis computer vision dengan raspberry pi 4B

## 论文在讲什么

这篇论文讨论的是一个结合 `computer vision`、`Raspberry Pi 4B`、`PLC Omron` 和 `SCADA` 的智能交通灯原型。核心思路不是简单固定配时，而是由相机实时统计车流，再把车流数据写入 PLC，由 PLC 根据当前优先模式决定绿灯应该延长、缩短，还是保持默认时长。

与很多只讲“相机识别 + 智能交通”概念的论文不同，这篇文献把控制器真正写到了工程实现层：它定义了 `padat / sepi` 的阈值，规定了 `Prioritas 1` 和 `Prioritas 2` 两种互斥模式，并明确给出 `10 detik -> 15 detik` 与 `10 detik -> 5 detik` 这两类时长变化。

## 控制系统在文中的位置

控制系统是文中的主角。虽然前面有机器学习和数据集训练的篇幅，但这些内容服务的目标很明确，就是给 `PLC` 提供可用于相位调整的车辆数量输入。真正的系统价值体现在“Raspberry Pi 如何写入寄存器、PLC 如何读这些寄存器并切换优先模式、SCADA 如何监控和介入”这条链上。

从样本库视角看，它不是单纯的视觉算法论文，也不是只做界面展示的 `SCADA` 稿件，而是一篇把感知、控制和监督接口串起来的交通灯控制论文。这让它在交通灯方向上比传统 `IR sensor + timer` 样本多了一层“外部感知驱动的模式监督”语义。

## 对我们为什么有用

它为 `sources/` 补入了一类比较少见但很实用的 `EFSM + T1` 样本：主控制链仍然是离散交通相位，但 guard 不再只靠简单按钮或物理开关，而是由视觉计数结果驱动。对后续做“感知数据进入 PLC 后如何影响状态机模式切换”的数据集整理，这类样本比单纯固定配时论文更有区分度。

另外，这篇论文还有一个很有用的优点，就是保住了寄存器级映射。`D0 / D1 / D42 / D43` 这些地址说明不是噪声细节，而是把外部计数结果和 PLC 决策状态连接起来的关键桥梁；这会让后续人工回读时更容易确认每个 guard 到底落在哪个输入位上。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看第 7 页的 `2.6 Prinsip Kerja Sistem Traffic Light`，把两种优先模式、`>3 kendaraan` 阈值和 `Timur-Selatan / Selatan-Barat` 这两组受控方向先钉住。接着直接看第 8-11 页的测试表，把 `D0 / D1 / D42 / D43` 与 `10 -> 15 detik`、`10 -> 5 detik` 这两条时长调整链对齐。

如果只是为了重建状态机，机器学习训练细节、数据标注和 3D 原型搭建可以后看。第一次回原文时最值得优先看的，是“模式怎么切”“阈值是什么”“PLC 存了什么”“SCADA 能不能人工介入”这四件事。
