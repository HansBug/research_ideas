# 园区低速自动驾驶七态决策监督器 / Decision-making System based on Finite State Machine for Low-speed Autonomous Vehicles in the Park

## 论文在讲什么

这篇论文讨论的是园区场景下的低速自动驾驶决策、局部规划与控制。作者把应用背景限定得很具体：对象不是高速公路自动驾驶，也不是通用 urban benchmark，而是有固定道路、静态障碍、会车和低速通行约束的 park 场景。论文的目标是把决策层、Bezier 曲线路径规划和横纵向控制整合到一台实车上，并证明这套系统能够在真实园区道路中稳定运行。

对文库最有价值的是，论文没有只说“我们用了一个 FSM”。正文直接把 decision-making system 的七个状态列出来，并分别解释每个状态负责的信息过滤、定速、跟车、选道、局部规划、停车等待和轨迹跟踪职责。随后作者又补上了距离保持规则、静态障碍换道条件以及 `Xob` 阈值下的 planner / wait 分支，因此这不是一个只有框图的概述稿，而是有完整监督链的车辆控制样本。

## 控制系统在文中的位置

这里的控制系统描述是论文主体之一，不是附属案例。虽然文章同时讲路径规划和控制器实现，但 decision-making layer 被明确组织成一台 FSM，并作为连接感知、规划与车辆控制的上层监督器存在。系统结构上，感知与定位模块提供输入，FSM 负责决定当前该保持巡航、跟车、等待还是变道规划，再把结果交给 `LocalPlanner` 和 `VehicleController` 落地。

这点很重要，因为很多自动驾驶论文会把离散状态只当成实验脚本或仿真开关，这篇不是。七个状态本身承担了实际 driving policy 的切换职责，尤其是在静态障碍场景下，论文把“何时忽略障碍、何时计划变道、何时必须停车等待”直接写成阈值与分支规则，所以它留下的是决策监督控制语义，而不是泛化的算法流程。

## 对我们为什么有用

对 `sources/` 来说，这篇论文补进的是 `🚗` 方向里较干净的一类 `FSM + T0` 自动驾驶决策样本。它不像很多 highway / urban planning 论文那样把重点放在连续轨迹优化或行为博弈上，而是保住了较完整的离散驾驶监督链：状态集合明确、每个状态的职责明确、守卫条件具体、输出动作也能和速度控制、路径规划、停车等待等行为一一对应。

这篇样本还有一个优势，就是它能补一类常见但不总是写得足够清楚的“障碍绕行 supervisor”。原文不仅讲到常规跟车，还把对向来车等待、返回原车道、障碍距离阈值和变道规划的切换关系写了出来。对后续做状态机建模或抽取带 guard 的车辆监督逻辑，这种样本比只给 lane-change 模块名和少量行为标签的论文更稳定。

## 如果需要人工细读，建议怎么读

人工回原文时，建议先读第一页摘要和引言，确认系统边界是“园区低速自动驾驶 decision-making system”，不是单纯的 path planner。随后直接跳到第二页 `III. Decision-making System based on FSM`，先把七个状态及其职责完整抄出来，再继续看 `A. Distance Keeping` 和 `B. Lane Choosing`，把跟车安全距离、会车等待和返回原车道的控制逻辑读清楚。

接着再看第三页 `C. Local Planner` 里围绕 `Xob` 的阈值段落，确认 `>12`、`8-12`、`<8` 三段对应的 ignore / lane change / stop-and-wait 分支。Bezier 曲线数学细节、路径跟踪控制公式和后续实验部分可以放到第二轮，因为第一次重建 `STM.md` 时，最核心的仍然是七态 FSM 本身及其 guard/action 主链。
