# 水滤测试台的主状态与阀泵监督控制 / Control System Design of Water Filter Test Bench

## 论文在讲什么

这篇论文讨论的是 Parker 水滤测试台的控制系统应该如何设计。作者不是先写 PLC 程序再回头整理文档，而是先用 UML state machine diagrams 把主状态和组件状态建出来，再把这些模型作为后续 PLC 实现的依据。控制对象包括多种阀门、泵、传感器、手动控制与测量模式。

它和很多只谈测试标准或液压回路的论文不同，真正把控制边界钉得很清楚。文中先定义 normal state、两类 measurement state 和 manual control state，再分别展开阀门和泵的状态机与 guard，这使得它非常适合作为“从设计建模阶段就显式采用状态机”的样本。

## 控制系统在文中的位置

这里我们关心的控制系统描述就是论文主体。摘要已经明确说明先建主状态机、再建组件状态机，后面的第 4.5 节也整段都在写这些 state machine diagrams 如何决定哪些组件可被 actuate、哪些 sensor/state data 暴露给 HMI、以及哪些 guard 必须满足才能触发动作。

这意味着论文不是把状态机当成一个说明性插图。相反，状态机模型就是控制系统设计成果本身。对 `sources/` 来说，这种论文非常有用，因为它同时覆盖了系统级模式切换和组件级阀泵状态机，粒度层次比普通 PLC 样本更丰富。

## 对我们为什么有用

它直接补进了一类 `⚙️` 方向的层次化控制样本。文库里已有不少过程控制和液位/水处理样本，但这篇不是单纯按阈值启停，而是把测试台拆成 normal、measurement、manual、stop 等主状态，再用阀泵子状态机细化动作条件，因此结构差异很明显。

另一个价值是 guard 写得非常工程化。无论是启动 multi-pass test 时对泵、阀、bypass 和 sensor pump 的联合条件，还是 `A.V.1` 在不同主状态下的左右切换约束，都是后续做形式化建模、需求重写和状态机生成时非常好的训练材料。

## 如果需要人工细读，建议怎么读

建议先读摘要和第 34-37 页的 `Main states`，先把 `normal -> Lobby1 / Lobby2 / lobby3` 以及全局 `E.1` stop 路径的主框架抓住。接着继续读第 37-40 页的 valve state machine 段落，用 `A.V.1`、`A.V.2` 这类组件状态机去补足主状态之下的动作约束。

如果后续需要重做 `STM.md`，第一次不必先细抠液压硬件规格和全部元件清单。更应该优先抓住的是：主状态之间如何切换、哪些 guard 才允许启动 multi-pass test、为什么 stop 会把系统导向 manual control、以及单个阀门怎样在不同主状态下响应按钮和自动事件。把这四条主线读稳后，这篇论文的状态机价值就非常明确了。
