# 多车位密码门禁停车控制 / Verilog-Based Solution for Multi-Vehicle Parking

## 论文在讲什么

这篇论文讨论的是一个面向封闭停车场的数字门禁控制器，而不是自动驾驶里的连续泊车轨迹。作者用 `Verilog` 设计了一套多车位停车系统，把用户名/密码认证、入口/出口传感器、红绿灯提示和停车位容量限制放到同一个控制链里。它的目标很直接：让车辆进场前先认证，再依据车位是否已满决定放行还是阻断。

从系统结构上看，这个样本最有价值的地方在于它不是只说“有个停车计数器”，而是把五个状态、两个认证变量、两个方向传感器和 `car_count` 变量串成一条完整离散链。对 `sources/` 来说，这比纯图像识别或纯计费系统更接近我们要的停车基础设施状态机样本。

## 控制系统在文中的位置

停车控制器就是论文主角。正文先用一般 FSM 解释打底，然后直接切到作者自己的停车系统，给出五态停车控制框架、密码校验逻辑、入口/出口传感器更新方式以及满位阻断规则。它不是顺手附带一个小例子，而是整篇文章的核心实现对象。

这意味着我们在回读原文时，不需要从零散实验现象里反推状态机。原文已经明确告诉我们系统有哪几个状态、输入怎么改变量、何时准入、何时拒绝、车离场时怎样回写容量，因此很适合作为停车门禁与容量控制样本。

## 对我们为什么有用

当前 `🅿️` 方向里虽然已经有车位分配、门禁计费和代客泊车等样本，但“密码门禁 + 多车位容量寄存器”这类离散停车控制器还不多。这篇补的是一种更偏数字门禁与容量守卫的表达形态，和现有 `RFID` 或纯槽位计数控制器并不完全重合。

它还保留了比较适合数据集的关键件：显式状态名、认证 guard、满位 guard、入口/出口事件、容量变量和指示灯输出。后续如果要做 `NL -> state machine`，这类同时含有输入验证和容量约束的停车控制样本比只讲“有空位就开闸”的简化方案更有区分度。

## 如果需要人工细读，建议怎么读

建议先读第 `3-4` 页 `IMPLEMENTATION OF PROPOSED ARCHITECTURE` 和 `Figure 4`，先把 `IDLE / WAIT_PASSWORD / RIGHT_PASS / WRONG_PASS / STOP` 五态、`password_1 / password_2`、`sensor_entrance / sensor_exit` 和 `car_count` 的关系读清楚。第一轮人工重读时，重点是确认“认证通过后怎样进场、认证失败怎样停留、满位时怎样进入 STOP”。

第二轮再看第 `5-6` 页的 `RESULTS & DISCUSSION` 与 `CONCLUSIONS`，主要核对 `PASS_1 / PASS_2`、前后方向传感器和红绿指示灯在模块图里的职责，以及多车位上限是怎样被硬件寄存器守住的。前面的停车行业背景和泛化动机可以后看，不是恢复状态机骨架最关键的部分。
