# 双向路口四状态交通灯控制器 / Traffic Signal Control Using Discrete Logic and FSM

## 论文在讲什么

这篇论文的目标是用离散逻辑和有限状态机重新组织一个路口交通灯控制器。它不是把交通灯当成一个纯固定周期的信号灯，而是试图在较轻量的数字逻辑框架下，把状态、定时触发和车辆存在检测结合起来，做出一个既易实现又能感知基本交通需求变化的 controller。

文中最关键的设计是一个四状态 FSM：南北向绿 / 东西向红、南北向黄 / 东西向红、南北向红 / 东西向绿、南北向红 / 东西向黄。作者进一步说明这些状态不是机械轮转，而是受到 `T1` 定时到期和 `VNS / VEW` 车辆存在信号共同驱动。再往下，它把状态编码成 `Q1 / Q0` 两个状态位，并说明用 `D` 触发器和基本逻辑门实现状态存储与转移。

## 控制系统在文中的位置

这里的交通灯控制器就是论文的主体设计对象。虽然文章也回顾了固定时长控制、传感器控制和更复杂的自适应控制，但这些内容主要是在说明为什么作者选择 `FSM + discrete logic` 这条路线。真正被展开的，还是这个路口 controller 本身的状态定义、状态编码和触发条件。

这使得它对 `sources/` 来说仍然是可用样本。我们关心的不是这篇论文有没有做大规模城市网络优化，而是它是否把一个具体控制对象写成了可追溯的状态链。这里的答案是肯定的：相位是什么、什么时候切换、哪些输入参与切换、状态怎样在硬件层保存，这些都直接对应状态机建模所需的关键件。

## 对我们为什么有用

对当前文库来说，这篇文章补的是 `🚦` 方向里比较干净的一类 `FSM + T1` 样本。现有交通信号样本里，很多更偏 PLC 相位表、应急优先或复杂 STT/ASM 表达；这篇论文则把问题压缩到四状态、两位编码和基本输入条件上，适合作为更轻量、更标准的 traffic-light FSM 参考。

它对后续自动生成任务的价值在于：原文没有把控制语义埋在冗长设备说明里，而是直接给出相位状态名、输入触发和逻辑实现骨架。对于想训练模型从自然语言生成小型交通灯状态机的任务，这类结构规整、边界清晰的样本非常有用。

## 如果需要人工细读，建议怎么读

如果后续要人工细读，建议先从第 `10-11` 页的 `FSM State Diagram for Traffic Signal Controller` 和 `State Encoding and Transition Equations` 开始。第一次阅读时只需把四个相位状态、`T1`、`VNS / VEW`、以及 `Q1 / Q0` 的角色读稳，就已经能恢复出主控制链。

接着再看硬件/仿真实现部分，确认 `D` 触发器和逻辑门只是实现手段，而不是改变控制语义的新层次。前面的文献综述、固定时长控制背景和较泛的 ATCS 比较可以放到第二轮再看；它们能帮助理解选型理由，但不是重建交通灯 STM 的第一信息源。
