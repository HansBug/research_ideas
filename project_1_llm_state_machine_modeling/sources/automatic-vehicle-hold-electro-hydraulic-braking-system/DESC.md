# 基于电液制动系统的自动驻车保持功能模型 / Functional Model of an Automatic Vehicle Hold Based on an Electro-Hydraulic Braking System

## 论文在讲什么

这篇论文研究的是新能源汽车或电液制动车辆中的 `Automatic Vehicle Hold (AVH)` 功能应该怎样建模和实现。作者并没有把重点放在制动器液压连续控制本体，而是把 `AVH` 当作一个面向驾驶场景的软件功能来设计：车辆在平地或坡道停车后如何判断需要保持多少液压、何时进入保压、起步时怎样分阶段释放、以及在防溜车约束下如何等到驱动扭矩足够再完全松闸。

文章把这一逻辑拆成了 slope judgment、多级目标液压计算、parking function unit 和三阶段起步释放策略。文中明确给出坡度等级到 `PTarLv1-PTarLv4` 的映射、`> 5 bar` 的重算触发、内部时间阈值超限后升到最大液压、以及释放完成需要满足的 `< 3 bar` 压差条件，所以这不是泛泛的“自动驻车可以防止溜坡”介绍，而是一套可以恢复成监督器的功能模型。

## 控制系统在文中的位置

控制系统描述是论文真正的主体。作者反复强调这是 `automatic vehicle hold software` 的功能设计，并通过 `Matlab/Simulink` 模块化建模把坡度判断、保压、释放和起步控制串成一个完整软件链条。后面的整车验证也围绕这套功能模型是否能在平路和坡道上稳定完成驻车与起步展开。

这也意味着它和常见的 `ABS / brake-by-wire` 连续控制论文不同。文中固然有液压力、驱动扭矩和坡度这些连续量，但它们主要是作为 guard 或目标等级输入来驱动 `request parking -> pressure preservation -> release mode -> release complete` 这样的离散阶段切换，因此更适合被看成一个 `AVH` 监督控制器样本。

## 对我们为什么有用

它对文库的主要价值，是在 `🚗` 方向补进了一个和换道、超车、行为规划明显不同的底盘功能样本。这里的控制对象不是高层驾驶策略，而是底盘执行层的驻车保持与起步释放逻辑；它仍然具备明确状态、阈值、阶段链和时间条件，因此能让汽车领域样本分布更均衡。

它还提供了一个很典型的 `EFSM + T1` 控制链。状态切换依赖坡度等级、目标液压等级、驱动扭矩和压差阈值，同时内部又带“超过时间阈值后提升到最大液压”这样的局部时序约束。这类材料非常适合作为“连续测量驱动的工程阶段控制”样本，而不是单纯的纯离散行为图。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 `5-7` 页附近的 `2.4 Calculation Module` 与 `2.5 Parking Function Unit Module`，把坡度等级判断、目标液压等级选择、`request parking`、`pressure preservation` 和 `release mode` 这些状态链读清楚。随后直接看第 `10` 页 Figure `7` 的 `automatic vehicle hold strategy`，把 `Stage 1 / Stage 2 / Stage 3` 的起步释放逻辑和驱动扭矩约束补完整。

第二轮再看后面的整车验证章节，用平路与坡道实验确认保压、释放和防溜车逻辑确实按文中描述触发。关于液压模型、动力学细节和 Simulink 代码生成说明可以后读，因为它们更偏实现与验证背景，而不是先恢复 `AVH` 状态机链条所必需的材料。
