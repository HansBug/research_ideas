# 汽车行为决策三级层次状态机 / Decision making framework for autonomous vehicles driving behavior in complex scenarios via hierarchical state machine

## 论文在讲什么

这篇论文讨论的是自动驾驶车辆在复杂直线路段中的高层行为决策，而不是单独的感知、定位或轨迹跟踪模块。作者关心的问题是：车辆在面对前车、侧向车辆、换道机会和安全约束时，怎样用一个稳定的离散决策骨架，把“看见了什么场景”和“下一步该执行什么动作”连接起来。

为了解决这个问题，论文提出了一个自上而下的三级层次状态机。上层先判断周围车辆分布对应的交通场景，中层根据安全、效率和车道空闲度评估候选行为，下层再把上层输出落实成具体动作规划。从 `sources/` 的角度看，这类写法的价值在于它没有把行为决策埋进黑箱优化，而是把决策骨架直接写成分层 FSM。

## 控制系统在文中的位置

我们关心的控制系统描述是这篇论文的核心，不是为了验证某种算法才顺带举出的 toy example。摘要就把“hierarchical state machine”和“三层 finite state machine decision system”作为主贡献，后面的场景划分、能效评价和动作规划也都是围绕这套离散决策框架组织的。

更具体地说，这篇论文不是只定义几个驾驶模式名词就结束，而是把它们放进一个明确的任务网络里，强调只有各层决策完成之后，车辆才会进入下一步动作。也就是说，FSM 在这里承担的是 supervisor 骨架的角色，而能效评价函数只是用来为状态切换补充判据。

## 对我们为什么有用

这篇论文对 `sources/` 的主要价值，是补充了 `🚗` 领域里一种比较清楚的“场景层 -> 行为层 -> 动作层”层次状态机样本。当前文库里虽然已经有一些自动驾驶行为机，但不少样本更偏单层模式选择或单次 maneuver supervisor；这篇则把层次关系本身写得很直白。

其次，它的状态机并不是空泛的“有几种驾驶模式”，而是明确给出有限状态机五元组、顶层场景分类和中层候选行为集合。后续如果做数据集，这篇论文最值得保留的是“层次结构如何组织”“上层场景判断如何约束下层动作决策”这两层信息，而不是更细的碰撞距离公式推导。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 1 页摘要和第 3-4 页的 `FSM mission planning model`。这里最重要的是把三层任务网络、`M(S, Σ, f, S0, F)` 五元组和“每层都完成后才能进入下一步动作”这几个核心句子读稳，先确认控制对象就是一个分层离散决策器。

随后再读第 4-6 页，把顶层场景分类和中层候选行为放在一起看，重点抓“no vehicle in front / no vehicle on the side / vehicle on the side”这样的场景分组，以及 `free driving / lane change / following` 这样的候选行为。涉及安全距离和能效公式的页面可以第二轮再看，因为首轮抽 `STM.md` 时，更关键的是把层次关系和行为边界固定下来。
