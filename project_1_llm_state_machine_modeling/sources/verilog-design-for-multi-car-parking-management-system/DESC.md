# 多车位口令校验与进出计数控制 / Verilog Design for Multi-Car Parking Management System

## 论文在讲什么

这篇论文讨论的是一个多车位停车场出入口管理系统，重点在于如何用 Verilog 和状态机把口令校验、车辆进出检测和可用车位计数组合起来。论文的背景部分有不少停车问题的一般性叙述，但真正的控制主体比较集中：车辆到达后先输入用户名和密码，认证通过才允许进入；车辆进入和离开时由两只传感器更新占位计数；达到容量上限后系统转入拒绝入场状态。

它的控制链比很多只做空位计数或显示的停车短文更完整，因为作者明确写出了 `IDLE`、`Right Pass`、`Wrong Pass` 和 `Stop` 等状态，也给出了固定口令、入口/出口传感器和 `car count` 变量。虽然正文中“five states”与已展开列出的状态名之间有一点不够严丝合缝，但系统的实际主控制链仍然是可追溯、可复原的。

## 控制系统在文中的位置

这里的控制系统是论文的核心，不是某个外围接口模块。文章摘要、提出的方法和结果部分都围绕同一个停车出入口控制器展开，控制器承担的职责也相当清楚：认证、放行、重输、计数和满位拒绝。它不是停车检测平台的一部分，也不是智慧停车平台的一个 UI 样例，而是一个较完整的局部控制器。

不过也要如实区分，这篇属于比较轻量的停车控制样本，而不是复杂的机械立体车库或多层路径规划系统。它的价值主要来自“认证变量 + 占位变量 + 传感器 + 状态切换”这套组合写得较为完整，因此适合作为停车方向里更基础、更干净的一类 EFSM 样本。

## 对我们为什么有用

这篇论文对 `🅿️` 方向的意义，在于补进了一个比单纯 `slot count` 更有控制味、但又没有复杂机械执行背景的出入口管理样本。现有停车方向条目里，有些更偏门禁密码锁，有些更偏机械搬运或路径分配，而这篇把口令验证和停车占位管理合在一起，正好提供了一类中等复杂度的停车控制器。

它也适合作为后续清洗和建模的桥梁样本。因为正文里既有显式状态，又有传感器和变量扩展，不会像纯 FSM 教学稿那样只剩状态名，也不会像复杂立体车库那样把控制链拉得过长。对自动生成状态机数据集来说，这类样本很适合连接“简单门禁控制”和“复杂停车监督控制”之间的中间层。

## 如果需要人工细读，建议怎么读

人工重读时，建议直接跳到 `III. Proposed Work`，把状态集合、`username/password`、`car count`、`sensor_entrance`、`sensor_exit` 这些核心元素先摘出来，再确认认证成功、认证失败和满位拒绝分别走向哪些状态。这一段基本决定了这篇样本的主控制链，不必先在背景综述里停留太久。

之后再看结果和波形部分，只把它当成一致性核对，确认作者确实是在实现同一个停车控制器，而不是正文说一套、实验只验证局部模块。相关工作、功耗讨论和未来工作可以放到第二轮再看；第一次复核只要把认证、计数、传感器和拒绝入场这四条线读稳即可。
