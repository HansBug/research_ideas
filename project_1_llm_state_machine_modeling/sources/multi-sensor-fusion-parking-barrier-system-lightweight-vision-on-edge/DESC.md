# 多传感器融合停车道闸状态机 / A Multi-Sensor Fusion Parking Barrier System with Lightweight Vision on Edge

## 论文在讲什么

这篇论文讨论的是停车位边缘节点如何在低算力平台上同时兼顾识别准确率、实时性、低功耗和业务联动。作者没有停留在“YOLO 检测车有没有停进去”，而是把红外、视觉、惯导、LoRa 上报、云端一致性和前端告警串成了一个完整的停车位状态机系统。

最关键的部分是多传感器融合状态机：红外距离先做低成本触发，视觉做车辆确认，惯导负责碰撞和姿态异常兜底。这样一来，系统不只是输出 occupancy，而是能区分正常占位、碰撞占位、其他物体异常、设备倾斜异常和正常空位五种状态。

## 控制系统在文中的位置

状态机在文中是主角，不是装饰性的流程图。摘要先点名 `infrared trigger - visual confirmation - inertial fallback`，第 3.3 节进一步给出 `80 cm` 触发阈值、`25°` 倾角阈值和 collision fallback，第 5 页的图还把最终状态集合完整画出。第 3.4 节和第 5.5 节则继续把状态上报、一致性收敛和 `5 s / 10 s` 休眠策略接到后面。

对 `sources/` 来说，这一点很重要，因为它说明这篇论文不是单纯的视觉检测论文，而是真正把停车位控制节点当作一个离散 supervisor 来设计。

## 对我们为什么有用

当前 `🅿️` 方向常见的问题，是很多论文只给检测算法或局部硬件模块，系统级状态链并不完整。这篇论文补的是一条更接近工程落地的 `EFSM + T1` 样本：状态集合清楚、guard 明确、睡眠策略明确、云边一致性也明确。

它还补了一个库里相对少见的位点：停车场景中的“异常状态”不是简单报警文本，而是直接作为状态机终端状态出现，并且和边缘上传、告警显示形成闭环。这对后续抽取异常恢复链、告警状态链和边缘-云一致性逻辑都有用。

## 如果需要人工细读，建议怎么读

人工重读时，先看摘要和第 3.3 节，再直接看第 5 页 Fig. 3。优先抓住五个最终状态、`dist < 80 cm`、`tilt > 25°`、collision fallback 以及 `5 s / 10 s` 轮询策略。把这几块串起来之后，再回到第 3.4 节看云端 idempotent update，基本就能把整条停车位状态控制链读顺。
