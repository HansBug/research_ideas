# 风场与机动条件驱动的 SUAS 参数切换状态机 / Development of a Finite State Machine for a Small Unmanned Aircraft System Using Experimental Design

## 论文在讲什么

这篇 AFIT 硕士论文研究的是一个很具体的飞行控制问题：固定翼小型无人机在跟踪地面车辆时，默认 APM:Plane 参数在不同风况和不同地面机动下表现不稳定，导致跟随距离方差较大。论文的核心做法不是重新发明整套导航算法，而是通过实验设计估计每种工况下更优的 autopilot 参数，再把这些工况组织成一个可以实时切换的有限状态机。

因此，这篇论文既有实验设计与统计建模的一面，也有很清楚的控制器组织方式。它把 `wind direction / wind speed / ground maneuver` 三个输入维度离散化后，形成一个 `36` 态的条件切换器，让 UAV 在运行中根据传感器读数进入不同状态，并写入对应的 `max bank angle / waypoint radius / waypoint loiter radius` 参数。

## 控制系统在文中的位置

这里的控制系统描述是论文的主结果之一，而不是附带案例。论文的前半部分在解释为什么默认跟踪策略对不同风况不够稳、实验因素该怎么选、HIL 怎么做；但最终产物不是一张统计表，而是一套可直接放进 APM 中执行的 FSM。作者明确说明“每个风向、风速、地面机动组合都成为一个状态”，并把这些状态映射到具体参数输出。

这类写法很适合 `sources/`，因为它不是纯连续控制性能论文，也不是泛泛的实验设计教程。真正值得保留的，是它把外部环境条件如何驱动控制器切换写得很清楚，而且状态输出不是抽象模式名，而是可执行的 autopilot 参数设置。

## 对我们为什么有用

它补的是航空航天方向里一种相对少见但很有代表性的 `FSM + T0` 样本：状态并不是“起飞/巡航/降落”这类任务阶段，而是“风况与机动条件组合”驱动的参数切换逻辑。对后续数据集来说，这有助于扩展状态机样本的表达面，让模型看到“离散状态也可以表示环境工况与调参模式”，而不仅仅是顺序过程或故障恢复链。

同时，这篇论文的证据粒度非常好。摘要给了 `36` 态总览，方法部分给了“怎样从条件组合生成状态”，`Table 13` 又把具体参数写到足以直接复原状态输出的程度，因此很适合保留为高质量样本，而不是仅作背景材料。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看摘要和 `1.6 Methodology Overview`，先确认这篇论文真正的控制器对象是“工况驱动的参数切换 FSM”，不是实验设计本身。随后直接跳到 `3.8 Finite State Machine` 和 `Table 13`，把状态生成逻辑与参数表读清，尤其是三类 ground maneuver 与四类风向、三档风速怎样形成状态，以及每类状态输出哪些参数。

如果后续要更深入理解这些参数为什么这样选，再回到实验设计和回归分析章节去看。第一轮不必陷进统计建模细节，因为对状态机样本抽取而言，最重要的是状态定义、输入维度和每个状态对应的控制输出，而这些信息已经在方法概述和状态表中高度集中地给出来了。
