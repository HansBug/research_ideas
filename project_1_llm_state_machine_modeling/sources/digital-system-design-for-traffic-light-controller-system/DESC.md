# 交通灯控制器数字系统设计 / Digital System Design for Traffic Light Controller System: A Systematic Approach

## 论文在讲什么

这篇论文讨论的是一个双向十字路口交通灯控制器的数字系统设计。作者把 `street_a` 和 `street_b` 两个方向的红黄绿灯作为对象，用 `FSM + TIME_COUNTER` 的结构描述其控制逻辑，再进一步给出 Verilog HDL 实现和测试平台。

从写法上看，这是一篇偏数字设计教学和工程实现的论文，但并不是只有代码。正文先给出控制对象和输入输出接口，再明确说明 `1 Hz` 主时钟、`29/4/2` 三组定时量、六个状态以及复位条件，所以状态机骨架是清楚落在文字里的。

## 控制系统在文中的位置

我们关心的控制系统是这篇文章的核心案例。它不是随手拿交通灯举例，而是围绕这个控制器本身展开“需求说明 -> 状态机划分 -> HDL 实现 -> test-bench 验证”这条主线。对 `sources/` 来说，真正有用的是中间那层 FSM 设计，而不是后面的代码细节。

这篇文章的价值在于它把一个非常典型的交通灯相位控制器写得足够规整。哪怕图表中的每个灯色组合没有完全转成纯文本，单从正文也能把“两个方向、固定时长、六个状态、显式 reset”的结构读出来，因此适合作为干净的 `FSM + T1` 样本。

## 对我们为什么有用

当前 `🚦` 领域里已经有若干交通灯样本，但很多要么偏 PLC 相位控制，要么偏传感器优先权与应急覆盖。相比之下，这篇论文更像一个标准化、离散化、数字电路表达很直接的基础交通灯 FSM，正好能补“纯定时相位循环”这一类。

对后续做状态机自动生成来说，它尤其适合训练模型识别“控制对象 + 固定时钟 + 若干离散状态 + reset 入口”这种最基础的形式。也就是说，它未必是最复杂的交通灯案例，但它足够规整，适合作为主集里的标准样本。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看第 2-3 页，也就是问题定义和 `FSM modules analysis` 两部分。先把 `street_a / street_b / clk / rst_n` 这些接口量与 `TIME_COUNTER / FSM` 两个模块的关系理清，再重点摘出 `29/4/2` 定时参数、六状态和 `AR_BR1` 复位态。

如果后续需要核对更细的灯色组合和状态编码，再回到第 3 页的输出状态表和第 4-6 页的 Verilog 图。代码和 test-bench 可以放在第二轮阅读，因为对 `STM.md` 首轮提取来说，优先级更高的是时钟、状态数量、状态命名和相位推进方式。
