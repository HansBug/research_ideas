# 六状态四向路口交通灯 / Accelerating Urban Traffic Management via FPGA-Based FSM Architecture

## 论文在讲什么

这篇论文讨论的是一个部署在 `Digilent Basys 3` FPGA 板上的四向路口交通灯控制器。作者把问题表述得比较直接：南北向和东西向两条道路分别有红黄绿灯，控制器用一套 Moore 状态机按固定顺序切换相位，并用按钮来模拟车辆检测输入。就控制链本身而言，论文核心不是“智慧城市”宏大叙事，而是一个带明确秒级配时的 FPGA 交通灯实现。

正文最关键的是 `System Architecture` 里的状态定义和 `Testing` 里的行为验证。作者列出六个状态：`NS Green`、`NS Yellow`、`NS Red`、`EW Green`、`EW Yellow`、`EW Red`，并为绿灯、黄灯和全红切换分别配 `30 s`、`5 s` 和 `2 s`。同时，控制逻辑部分还交代了 `100 MHz` 时钟如何分频到 `1 Hz`，以及按钮如何作为传感输入触发状态机行为。因此尽管论文整体带有课程化或工程报告色彩，状态机主链本身是清楚的。

## 控制系统在文中的位置

这篇论文里的控制系统描述就是文章主体。无论是硬件结构、RTL 设计还是板级测试，都是围绕同一个 traffic controller 展开的，而不是先讲平台、再顺手放一个交通灯示例。换句话说，控制器不是验证载体的陪衬，而是论文实际要实现和证明的对象。

不过也要如实区分它的角色层级：这篇更像一个定时交通灯控制样本，而不是复杂自适应交通系统论文。它的价值主要来自“相位集合明确、输出配置明确、时序明确、测试行为明确”，而不来自复杂交通策略。对 `sources/` 来说，这反而是优点，因为它提供了一条边界清楚的基础交通相位控制样本。

## 对我们为什么有用

这篇论文对样本库最直接的帮助，是为 `🚦` 方向补进一个非常纯粹的 `FSM + T1` 四向路口控制器。现有交通灯条目里已有不少密度感知、紧急车辆优先或视觉检测增强样本，但越是复杂的交通控制，越容易把状态机主链和感知/优化支链揉在一起。这篇则提供了更标准的“六状态相位机 + 固定秒级配时 + 按钮模拟传感”结构，适合作为定时相位控制的基础模板。

它也有助于平衡数据集中 `EFSM` 占比过高的问题。因为这篇核心是 Moore 状态机，输出仅由当前状态决定，状态集合和持续时长的对应关系很清楚，后续如果要构造更纯的 `FSM` 训练样本，这种论文比带很多阈值、计数器和优先级分支的交通控制器更适合作为干净基线。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 4-5 页 `Moore Finite State Machine` 与 `Control Logic`，把六个状态和 `30/5/2 s` 的时长映射先抄出来，再记住 `100 MHz -> 1 Hz` 的时钟分频逻辑。随后跳到第 8 页 `Simulation Testing / Hardware Testing`，确认测试是否真的覆盖了完整相位轮转和按钮输入触发行为。这样读可以最快把状态集合、相位顺序和计时语义固定下来。

如果还要进一步核实现层，可以再回看 block diagram、RTL 和 resource utilization；但这些属于第二轮阅读。第一次人工复核时，应优先确保三件事：状态名是否完整、每个状态的灯色配置和时长是否明确、按钮输入是否真的进入状态机测试。只要这三点读稳，这篇论文就足以支撑交通灯方向的一条高质量 FSM 样本。
