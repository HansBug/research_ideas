# 药用批混系统 PLC-SCADA 顺序控制 / Automation of a Pharmaceutical Batch Mixer Using Programmable Logic Controller (PLC) and Supervisory Control and Data Acquisition System (SCADA)

## 论文在讲什么

这篇论文研究的是一个药剂批混系统的自动化改造，作者把原本人工参与较多的投料、加热、搅拌、排放和冷却过程改造成 `PLC + SCADA` 共同控制的批处理系统。它不只是做一个简单的搅拌器开关，而是试图把整个批次生产链都纳入顺序控制和在线监控。

从样本角度看，这篇文章最重要的部分是第 3-4 页的八步工艺描述。作者把每一步的名义时长、温度条件、阀门与搅拌器动作都列出来，因此我们能直接读出一条完整的阶段推进链，而不是只能从 HMI 截图里反推系统逻辑。

## 控制系统在文中的位置

这里的控制系统是全文的绝对核心。设备建模、PLC 编程、SCADA 设计和仿真结果都是围绕“怎样让批混过程自动按阶段推进并可实时监控”这一个问题展开的。

对我们最有用的是，文中控制逻辑不是零散藏在图里，而是先用八步 statement list 把工艺顺序讲清楚，再在后文补上 HMI/SCADA 如何把批次阶段、温度、阀位、搅拌速度和报警映射到操作界面上。也就是说，这是一篇把工艺顺序和监控语义同时保住的过程控制样本。

## 对我们为什么有用

它补进的是一类很适合做 `EFSM + T1` 的工业过程样本。和纯灌装、纯门控或纯能量管理不同，这里既有按钮触发，也有明确的分钟级步骤时长，还有 `75 °C / 40 °C` 这样的过程阈值，因此非常适合验证模型能否同时恢复“顺序+条件”两类信息。

另外，这篇论文也能帮助区分“过程制造型状态机”和“离散装配型状态机”。它的状态不是单纯的某个执行器开闭，而是工艺阶段本身，比如准备、反应、混合、排放、转储和冷却，这对扩充数据集语义覆盖面很有价值。

## 如果需要人工细读，建议怎么读

人工重读时，先看第 3-4 页 `2.1.1 Process Description`，把八个步骤及其时长、温度和执行器动作逐条勾出来；然后再看中后段 `3.1.3 SCADA HMI Design and Implementation` 与 Figures 21-23，确认这些阶段在操作界面里是怎样被显示、报警和人工干预的。

数学建模、泵/阀方程和更一般性的自动化背景可以放到第二轮再看。第一轮最值得优先固定的是“哪一步之后进下一步、靠什么阈值切换、哪些执行器在该阶段必须开启或关闭”，因为这正是后续状态机恢复最需要的控制骨架。
