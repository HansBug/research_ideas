# 优先级驱动车库自动泊入与取车控制 / Modeling and Implementation of Automatic System for Garage Control

## 论文在讲什么

这篇论文讨论的是一个自动车库控制系统，目标不是只做车位检测或道闸开关，而是把“新车到达入口之后如何分配车位并自动泊入，以及车主请求取车之后如何自动驶向出口”写成一套完整的分布式控制方案。作者把系统分成中央子系统和车载子系统两部分：中央侧负责管理车位优先级、控制出入口门、向车辆下发路径指令，车端则负责按指令完成直行、转向、泊入、驶离和避障。

论文的实现载体是 FPGA 和虚拟仿真环境，但正文真正有价值的部分并不是“用了 FPGA”，而是系统级控制逻辑写得比较具体。它不仅说明了入口等待、路径引导、目标车位分配和出口释放这些主流程，还专门展开了优先级缓冲区、动态重排车位优先级以及分层状态机场景模块，这使论文更像一篇完整车库监督控制论文，而不是一个局部停车演示稿。

## 控制系统在文中的位置

这里的控制系统描述是整篇论文的核心对象。中央子系统的结构图、优先级管理、车位分配规则，以及车载侧的场景模块，都不是为了陪衬某个算法或仿真平台而临时放进去的，而是作者真正要设计和验证的主体。换句话说，论文的“问题”本身就是车库控制，而不是“借车库案例展示一种更一般的建模方法”。

对 `sources/` 来说，这篇尤其值得保留的地方在于它把中央监督和车辆执行两层关系写得很清楚。很多停车方向文献最后只剩空位计数、超声检测或显示模块，而这篇保住了“谁负责决策、谁负责执行、路径如何下发、车位优先级如何影响分配”的系统级主链，因此在文库里更接近真正的 HSM 风格车库控制样本。

## 对我们为什么有用

这篇论文对样本库最直接的价值，是为 `🅿️` 方向补进一条比较少见的 `HSM + T0` 样本。现有停车方向条目里，很多更偏门禁、空位统计、机械搬运或简化顺序控制，而这篇同时覆盖了优先级管理、路径指令和分层执行场景，能把停车领域里“监督分配层”和“车辆执行层”的关系补得更完整。

它也适合后续做“系统级停车控制描述”类数据。因为正文里不仅有对象、状态场景和动作链，还有优先级重排这种更接近工程调度层的因素，后续如果要比较“停车门禁式样本”和“真正车库监督式样本”的差异，这篇会比只含 `slot count` 或 `password` 的稿子更有辨识度。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 1 页摘要和引言，把系统边界确认成“中央车库监督器 + 车载执行器”的双层结构，而不是把它误读成单一的泊车模块。随后直接跳到第 2 页中央子系统结构和指令序列部分，把“等待开门、驶向位置 A/B、进入车位 i”这条入口主链先抄出来，再把优先级缓冲区和动态优先级调整的作用圈清楚。

第二步再去第 5 页 `Car sub-systems` 和仿真场景部分，重点读 hierarchical FSM 场景模块如何覆盖直行、转向、泊入、出库和避障。数据结构、链表/二叉树细节和硬件实现细节可以放到第二轮再看；第一次人工复核时，只要先把“中央分配如何驱动车端分层执行”读稳，就足够支撑重新抽取这篇样本。
