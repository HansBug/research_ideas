# 阈值驱动水箱补水与手动复位控制 / Intelligent Water Tank Automation System using FPGA for Efficient Water Management

## 论文在讲什么

这篇论文讨论的是一个基于 FPGA 的水箱自动补水系统，目标很明确：利用水位传感器、ADC、继电器和泵，在不依赖人工值守的情况下避免溢流和空转。作者把系统写成一个硬件实现明确、控制逻辑也明确的工程方案，核心并不是云平台或远程监控，而是本地实时控制链如何依据水位阈值做启泵、停泵和状态反馈。

正文的主线很直接。它先说明硬件组成，再给出 `25%` 和 `90%` 两个阈值，随后把控制逻辑收束成三状态 FSM：`Idle`、`Pump ON`、`Pump OFF`。LED 输出如何表示低/中/高水位、人工开关如何把系统拉回安全态、仿真和原型测试分别如何覆盖低/中/高水位场景，这些都在文中有清楚说明，因此论文虽然工程风格较强，但控制链条是完整的。

## 控制系统在文中的位置

这里的控制系统显然是文章主角。无论是硬件结构、Verilog 逻辑、阈值算法还是测试场景，都是围绕同一个水箱自动化控制器展开的，并不是先讲某个更大的智慧水务平台，再顺带放一个小案例。作者真正要证明的是 FPGA 能否把这条启停监督链做得可靠、可扩展和可测试。

这对 `sources/` 很重要，因为很多水位或水泵方向论文容易漂向 IoT 平台、传感网络或一般性节水叙事，而主控制链只剩一句“低水位开泵、高水位停泵”。这篇则把状态机、阈值、输出编码和测试场景都写了出来，因此是过程与环境控制方向里比较干净的一条基础样本。

## 对我们为什么有用

这篇论文对 `🌡️` 方向的直接价值，是补进一条非常标准的 `FSM + T0` 水位监督器样本。当前文库里过程控制类样本里，很多条目更偏 PLC 顺序控制、多罐流程或复杂工艺阶段切换；这篇则是一条边界清楚、状态数少但控制语义完整的阈值型样本，适合作为“水位阈值启停”类控制语料的代表。

它还有一个好处是保留了人工复位和状态反馈。也就是说，这篇不是纯粹的阈值比较器描述，而是保住了 `Idle` 安全态、泵状态和 LED 编码，这让后续做自动状态机建模时，不至于只拿到一条贫乏的 if-else 规则，而能拿到更像监督控制器的自然语言材料。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 2 页 `Proposed Solution` 和第 5-6 页 `Control Logic Design / Threshold-Based Algorithm / FSM Design`，先把控制边界固定成“读取 ADC 水位值，根据两个阈值和手动复位切换三状态”。这一步最关键的是把状态名、阈值和 LED 输出映射先圈出来，因为这些信息直接决定后续状态机抽取质量。

然后再看第 7-9 页的仿真与原型测试，确认低/中/高水位和手动复位是否真的在实验里被触发并验证。背景综述、IoT 拓展愿景和性能宣传可以放到第二轮再看；第一次复核只要把三状态、两个阈值、一个手动复位和三档输出编码读稳，就足够重做这篇样本。
