# 离位倒车告警状态机与 CAN-Bus 门控 / Vision-based Parking Assistance System for Leaving Perpendicular and Angle Parking Lots

## 论文在讲什么

这篇论文关注的不是“如何把车倒进车位”，而是“如何从垂直或斜列车位安全倒出”。作者把问题定义成一个真实的驾驶辅助场景：侧边停放车辆会遮挡驾驶员视野，导致驾驶员在倒出车位时无法可靠观察横向来车。为了解决这个问题，论文提出了一套基于单目灰度摄像头的离位辅助系统，并把车尾右侧摄像头、处理器和 CAN-Bus 信号整合成一个可以自动发出 warning 的 ADAS 模块。

从控制逻辑上看，这篇论文并不只是讲感知算法。它明确说明检测模块如何被手动激活、何时等待进入工作状态、何时在倒挡条件下真正运行，以及在什么情况下必须立即退出检测。也就是说，感知算法只是服务于一个更大的离散控制壳：只有当手动激活已完成、倒挡接入、车速足够低、转角足够小的时候，警报控制链才被允许真正进入工作状态。

## 控制系统在文中的位置

我们关心的控制系统描述在这篇论文里是非常核心的，而不是附带示例。作者专门把检测模块的启停逻辑画成了 `FSM`，并明确指出它由三个 CAN-Bus 变量和一个人工信号共同驱动。换句话说，这里不是“论文顺便用了状态机”，而是整个系统能否在对的时机介入、在不安全或不适用的工况下退出，完全依赖这条状态机控制链。

同时，这条控制链和视觉识别模块之间的边界也写得比较清楚。视觉侧负责把邻近车道判成 `oncoming traffic` 或 `free road`，而状态机负责决定什么时候允许检测、什么时候要停用模块、以及 warning 何时真正对驾驶员生效。这种“感知输出 + 离散启停监督”的组合，对 `sources/` 来说很有价值，因为它比纯算法论文更接近实际车载控制系统的落地写法。

## 对我们为什么有用

这篇论文对文库的意义在于，它补进了一类比较少见但很真实的停车辅助控制样本：控制对象不是整车轨迹规划器，也不是纯连续控制的转向器，而是一个围绕人工激活、档位、车速、转角和警报输出构成的离散监督模块。对于 `project_1` 的状态机建模任务来说，这种对象很适合抽成 `EFSM + T0` 风格的自然语言样本，因为 guard 条件和状态切换原因非常集中，且都能回到原文。

另外，这篇论文也有助于拉开停车方向样本的结构差异。文库里已有不少停车相关论文更偏密码门禁、车位分配或轨迹规划，而这篇是典型的“离位辅助 + warning gating”路线。后续如果要做领域内多样化训练集，它能提供一条和立体车库、自动泊车轨迹、停车场资源分配都不一样的控制链表达。

## 如果需要人工细读，建议怎么读

如果后续需要人工重读，建议先看第 1 页摘要和引言，先确认系统目标不是入位控制而是离位告警；然后直接跳到第 2-3 页 `SYSTEM DESCRIPTION` 与 Fig. 4，把 `INIT_STATE / PRE_DETECTION / DETECTION`、手动激活、倒挡、`5 km/h`、`10°` 这些关键 guard 先圈出来；再回到第 2-4 页看视觉侧怎样把 `oncoming traffic` 与 `free road` 区分，并确认 warning 是如何从分类结果触发出来的。

像后面更偏 `STHOL` 特征、扫描线分布和统计分类细节的部分，第一次人工复核可以放到第二轮再看。对我们最关键的是先把“模块什么时候进入、什么时候退出、warning 在什么条件下生效”这条主控制链读稳；只要这条链抓住了，即使后续要重写 `STM.md`，也已经有足够清晰的原文入口。
