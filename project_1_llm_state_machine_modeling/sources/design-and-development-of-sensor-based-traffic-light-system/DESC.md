# 传感队列驱动的交通灯控制器 / Design and Development of Sensor Based Traffic Light System

## 论文在讲什么

这篇论文研究的是一个面向四向路口的 sensor-based traffic light controller。作者的目标不是做交通流宏观优化，而是把单个路口的信号机写成一个能根据车辆排队长度动态调整绿灯时长的控制器，并通过 `MATLAB`、`LabVIEW`、`BS2` 和红外传感器做了算法仿真与硬件联调。

文中的控制逻辑很直接：先把单灯抽象为 `Red / Yellow / Green` 三状态 finite state machine，再把南北、东西两个方向的成对信号灯同步起来，最终形成路口级相位输出。真正让它超过“普通定时灯”的地方，在于每条车道都有三只红外传感器，系统会根据触发数量计算不同的绿灯倒计时，并按四个方向顺时针轮转。

## 控制系统在文中的位置

这套交通灯控制器是论文主体本身。文章的“设计与开发”并不是泛讲一个智能交通概念，而是围绕控制器本体展开：状态怎么定义、输入是什么、双向灯如何同步、倒计时如何与传感器数量关联、相位如何按顺序切换，这些都直接服务于路口控制逻辑。

同时，这篇论文的价值不在于更复杂的算法名词，而在于它把一个看似简单的路口控制器写成了足够完整的实现链。它既保留了三状态状态机骨架，又叠加了传感器数量、倒计时、相位等待和全路口轮转顺序，因此很适合作为 `sources/` 里的“短篇但控制链完整”的交通信号样本。

## 对我们为什么有用

它对 `🚦` 方向的意义，在于补进了一类非常典型的 `EFSM + T1` 信号机样本。这里的相位并不只是固定轮换，而是会根据每条车道三只传感器的触发数量调节绿灯时长，并通过 countdown timer 驱动状态切换。这类“相位状态 + 传感 guard + 倒计时”组合，是后续数据集中非常标准且容易复用的状态机描述模式。

虽然 traffic-light 样本在库里已经不少，但这篇条目的好处是实现层次清晰：单灯三状态、双向同步、全路口顺时针轮换、`8/16/24 s` 三档绿灯倒计时、`2 s` 黄灯和 `1 s` lane-switch wait 都写得很实。相比只给抽象相位名的薄链稿，它更适合作为可直接抽样的数据集正例。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 `3-4` 页的 `Implementation` 与 `Results and Discussion`。先把单灯三状态、成对同步和 `3 × 3 = 9` 组合输出读清楚，再把三只红外传感器、`8/16/24 s` 倒计时和 `2 s + 1 s` 相位切换链补上，这样就能很快恢复完整监督器。

如果还需要确认它和实际硬件的关系，再回到第一页摘要与实现描述，看 `BS2`、红外传感器和 `LabVIEW` front panel 的角色。至于更前面的交通拥堵背景与一般智能交通介绍可以后读，因为那些内容主要是问题动机，而不是恢复这套路口状态机的关键材料。
