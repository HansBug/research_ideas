# 轮式足球机器人任务 FSM / Sistem Kontrol Robot Sepak Bola Beroda menggunakan Finite State Machine (FSM)

## 论文在讲什么

这篇论文围绕一个轮式足球机器人展开，目标不是做高层策略综述，而是用 `FSM` 把机器人从找球到射门的任务流程真正跑起来。系统以 CMUCam5 作为视觉输入，机器人通过 omni-directional 轮运动，并在状态机内完成找球、姿态校正、找门、带球推进和射门。

它的价值在于，作者没有只写“使用了 FSM”，而是把任务状态逐个拆开解释。论文既给了球的检测距离和角度范围，也明确说明找不到球时如何进入 wander 闭环、球接近到什么程度切换到找门、门距缩短到什么程度执行射门，因此非常适合做机器人任务型离散控制样本。

## 控制系统在文中的位置

这里的控制系统就是论文的中心。机器人硬件、相机标定和场地实验都在为同一件事服务：验证这套 FSM 是否能让机器人在不同球位和初始姿态下稳定完成任务。

换句话说，文中的视觉检测和轮子运动并不是独立主题，它们都被组织进一个扁平 FSM 里。`wander`、`posisi bola`、`maju bola`、`mencari gawang`、`maju ke gawang`、`menendang` 这些状态构成了论文最值得保留的离散骨架。

## 对我们为什么有用

对 `sources/` 来说，它补进的是一个比较稀缺的“移动机器人任务执行 FSM”样本。和很多工业 PLC 或电梯/交通灯类样本不同，这里关注的是任务搜索、姿态修正和目标完成链，因此能明显增加数据集的对象类型差异。

同时，这篇论文的状态切换条件并不含糊。它给出了球距、门距、角度范围、扫描失败后的回退闭环，以及局部的 1 秒前进动作，所以后续做状态机自动生成时，可以拿它测试“机器人任务描述”是否也能被稳定还原成状态与 guard。

## 如果需要人工细读，建议怎么读

人工重读时，建议先看第 1 页摘要，先把任务边界和相机检测范围锁定；然后直接跳到第 6-7 页 `Gambar 6` 的状态说明，把每个状态的职责、进入条件和退出条件读清楚；最后再看第 9-13 页的各状态测试与总体成功率，确认这些状态在实际场景中是怎样串起来的。

相机标定表和光照误差分析可以放到第二轮再补。第一轮最重要的是把 `找球 -> 对球 -> 找门 -> 对门 -> 前进 -> 射门` 这条主链读稳，并特别注意找不到球时的 wander 闭环和局部定时动作，因为这两部分最能体现它为什么是个完整 FSM 控制器。
