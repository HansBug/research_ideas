# 四路口直行/转向定时循环控制 / Four Junction Traffic Light Controller using PLC (S7-200)

## 论文在讲什么

这篇论文讲的是一个四路口交通灯 PLC 原型，核心对象不是车流预测或图像识别，而是一个明确的相位时序控制器。作者把主路、侧路和两侧转向灯组拆成 PLC 输出，配合 `start/stop` 输入与固定的 `15 s / 5 s / 15 s / 5 s / 10 s / 10 s` 相位驻留时间，构成完整的交通灯轮转循环。

对我们来说，这是一类非常典型的 `FSM + T1` 工程样本。它不像很多交通论文那样把篇幅放在优化策略、密度评估或救护车检测上，而是清楚地把“哪盏灯亮、亮多久、下一步切到哪里”写成了直接可建模的状态序列。尤其是主路直行、侧路直行和两段转向相位都被单独拉出来，这让它比普通三相交通灯稿更完整。

## 控制系统在文中的位置

交通灯控制器就是论文的中心对象。作者先说明硬件和 PLC 接线，再给出程序实现、流程图和实验结果截图，全文的主要目标就是证明这个四路口相位控制器能够稳定运行。

这意味着后续人工回看时，不需要在方法章节和实验章节之间来回跳转去找控制证据。页面 5-8 的实现、流程图和结果本身就是状态链证据，灯组定义与定时值都直接服务于控制器本体，而不是从属说明。

## 对我们为什么有用

当前 `🚦` 方向里，很多样本集中在“传感器优先级”“应急优先”或“图像密度调时”上，而这种固定时序但包含直行/转向双层灯组的 PLC 稿件，可以补一类更基础、更规则化的相位状态机。对于自动建模来说，这类样本很适合作为 canonical timed cycle 基线。

它还具有一个很强的工程可执行性：启动输入、停止输入、每段灯组输出和时间常量都已经写清楚。后续如果要做状态机生成、定时约束生成或相位顺序验证，这篇文章都能直接提供稳定的 nominal path 文本。

## 如果需要人工细读，建议怎么读

人工细读时，先看第 5 页 的接线和软件实现，把 `start/stop` 输入、主路/侧路输出和灯组符号 `Gm/Ym/Rm/Gs/Ys/Rs/Gt1/Gt2/Rt1/Rt2` 对齐；随后直接跳到第 6 页 的流程图，把完整相位顺序和持续时间一口气读下来。

之后再看第 7-8 页 的实验结果图，把文字里的定时相位和实际点灯截图对照起来，确认主路直行、侧路直行、主路转向、侧路转向四段是如何串起来的。文章前半段的交通灯历史和一般背景可以快速略读，不必在第一轮耗费太多精力。
