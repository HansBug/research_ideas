### 2. 基于原文整理后的自然语言描述

The UAV mission manager is organized around a hierarchical `Planner agent` whose top layer switches between `generate-plan` and `modify-plan`, depending on whether a flight plan already exists or a replanning trigger has arrived from situational awareness. Inside `generate-plan`, the controller descends through `old-plan`, `take-off`, `main-mission`, and `approach`, and the `main-mission` branch is itself refined into `plan-sequencing`, `actions-definition`, and `plan-optimization`, so the flight plan is built incrementally from objectives to executable actions. When the final `Park` action has been appended, the plan is sent to the `Execution agent`, and the planner returns to `modify-plan` so it can watch for new triggers and regenerate a plan that preserves already executed parts of the mission. The `Execution agent` then walks action numbers in order, verifies completion, and translates each action type such as `parking`, `taxi`, `take-off`, `climb`, `travel`, `target-recon`, `circle-hover`, `descent`, and `landing` into concrete UAV commands.
