# 八层电梯请求与安全门控控制器 / FSM for Elevator Controller

## 论文在讲什么

这是一份本科项目报告，目标是把楼宇电梯控制器写成一个基于 Verilog HDL 的有限状态机，并在仿真环境里验证其运行逻辑。报告围绕八层电梯展开，重点不是楼宇调度算法的大规模优化，而是把“请求楼层输入、当前楼层更新、运动方向判定、到站停机、门超时报警、超载报警”这些最核心的离散控制链固定成一个可综合的数字控制器。

从原文能看出的控制思路比较直接：电梯持续比较 `Request_Floor` 与当前楼层，决定上行还是下行；每层都有传感器把经过的楼层重新编码回控制器；一旦到达目标楼层就停止更新运动输出。同时，报告把两个安全约束直接接入主控制链，一个是门打开超过 `3 min` 触发 `Door_Alert`，另一个是载重超过 `4500 lb` 触发 `Weight_Alert`。因此它虽然是课程型实现稿，但并不是只给一个静态电路，而是给出了可追溯的电梯运行监督逻辑。

## 控制系统在文中的位置

这里的控制器就是全文主体。摘要、引言和设计策略并没有把电梯只当作一个附带示例，而是从一开始就把 elevator controller 作为要实现的目标对象：输入是什么，输出是什么，哪些异常条件会强制停机，运动怎样根据请求楼层切换方向，这些都直接围绕控制器组织。

这对 `sources/` 很重要，因为我们关心的是“真实控制客体的离散行为链”而不是 HDL 语法本身。报告虽然包含若干 Verilog 代码页和仿真页，但这些页服务的仍是同一条控制主线：请求楼层驱动运动方向，楼层传感器反馈到站条件，门超时和超载中断正常运行。也就是说，它更接近一个楼宇机电控制器案例，而不是单纯的 FPGA 教学文档。

## 对我们为什么有用

对当前样本库来说，这篇材料补的是 `🏢` 方向里“多层电梯请求服务 + 安全联锁”的一条典型链。现有楼宇机电样本里，很多电梯论文更偏三层或五层 PLC 控制，这份报告则保留了八层请求比较、门超时和超载两个安全支路，以及双向运行仿真，因此在同域内仍然有补样价值。

它对后续状态机自动生成任务也有直接帮助，因为原文里的控制语义非常适合转成自然语言样本：有明确的控制对象，有请求输入、楼层反馈、方向输出，也有异常 guard。换句话说，这不是只能摘出几个 mode 名称的薄链稿，而是能保住“正常服务链 + 安全停机链”两类关键信息的可追溯样本。

## 如果需要人工细读，建议怎么读

如果后续要人工重读，建议先看第 `6-9` 页的摘要、引言和 `Design Strategy`。第一轮只需要把以下问题读稳：控制器服务几层、如何比较请求楼层与当前楼层、门超时和超载分别如何影响输出、每层传感器在控制闭环里承担什么角色。只要这几件事读清楚，就已经能重建出一版可靠的电梯 STM。

第二轮再回看后面的 Verilog 代码页和仿真结果页，用它们核对状态边界和双向运行链是否一致。像致谢、证书页、工具介绍和版图实现页都可以后看；它们对理解“电梯怎么切状态、什么时候停机、哪些输入会触发安全分支”帮助不大，不必在第一次复核时消耗注意力。
