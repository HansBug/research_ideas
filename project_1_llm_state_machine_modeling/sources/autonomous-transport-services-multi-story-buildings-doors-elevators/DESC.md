# 多楼层建筑中带门与电梯的自主运输服务 / On realizing autonomous transport services in multi story buildings with doors and elevators

## 论文在讲什么

这篇论文讨论的是一个真实部署在养老院和大学办公楼中的运输服务机器人，怎样在非 barrier-free 建筑里独立完成跨楼层配送与消息传递。系统对象是一台带差动底盘和 7 自由度机械臂的 `SCITOS G5` 机器人，任务不是单纯导航，而是把“到达目标点”扩展成一整套楼宇通行能力，包括门状态识别、门把操作、呼梯、乘梯、楼层确认以及与路人礼让。

论文的总体写法很工程化。它先交代分层架构，再说明地图里如何编码门和电梯按钮面板，随后进入最关键的行为层：`Drive To Navpoint` 在需要换层时调用 `Ride Elevator`，在规划路径被关闭的门阻断时调用 `Pass Door`，底下再由 `Press Button`、`unlatch door`、`pull/push door` 等技能配合完成操作。也就是说，论文并不是只做单点感知或单个 manipulation 动作，而是在讲一个能长期跑实际配送任务的楼宇通行控制链。

## 控制系统在文中的位置

我们关心的控制系统描述在文中是绝对主角。论文虽然也写了感知、地图和局部运动规划，但这些内容基本都是为了让门梯行为控制器真正能跑起来。正文里最值得关注的不是某个 detector 的精度，而是行为层怎样按顺序调用各子行为、怎样判断该礼让、何时重试、什么情况下升级为人工介入。

尤其是 `Ride Elevator` 与 `Pass Door` 两块写得很完整。前者不仅给出“呼梯-进梯-选层-出梯”的 nominal 流程，还补了“前方有人先等候”“门只开 6 秒”“到错层后重新拨号”“按键后电梯不动时重试”这些实际 guard 和 fallback。后者则把门状态细分为 `closed -> unlatched -> partly open -> fully open`，并明确外界干扰、夹持器打滑与三次失败后的人机交接条件，因此非常适合抽成状态机自然语言样本。

## 对我们为什么有用

对 `sources/` 来说，这篇论文的价值在于它补的是“真实楼宇服务机器人如何跨越门与电梯”这一类难得的系统级样本，而不是教学式 elevator demo 或单个 door-opening 技能论文。当前文库里楼宇机电方向已有不少传统 PLC 电梯控制器，但像这样把礼让规则、门状态推进、按钮交互、时间限制和失败重启整合进同一行为层的样本并不多，结构差异明显更强。

它也很适合作为后续自动建模数据集里的高质量正例。因为这篇论文同时保住了控制对象、显式行为层次、状态推进顺序、局部时间限制和异常恢复链，后续无论是做 `NL -> state machine`，还是做“验证失败后让 LLM 回看原文修模型”，都能从中直接拿到足够密的控制语义，而不必再从图表边角去拼主链。

## 如果需要人工细读，建议怎么读

如果后续要人工复核 `STM.md` 或重做样本，建议先看第 1-2 页摘要、引言和 Figure 1，只用来确认系统边界、部署场景与机器人硬件条件。随后直接跳到第 4-7 页的 `3.1.3 Operating the elevator` 和 `3.1.4 Opening doors`，优先标出行为层名字、进入条件、礼让规则、6 秒门开窗口、门状态序列、重试次数以及“何时交还给人”的边界。最后再去看后面的实验和成功率部分，确认这些行为是不是只停留在设计层，还是确实在真实楼宇里跑通了。

至于门按钮检测、点云/激光感知、局部碰撞地图和臂运动规划这些内容，可以放到第二轮再看。它们对理解系统为什么能工作很重要，但若目标是抽取状态机样本，第一轮更该先锁定高层行为链和各子行为之间的调度关系；等主控制链清楚之后，再回头补感知误差、地图建模和 manipulation 细节会更省力。
