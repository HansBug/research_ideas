# UGV 路口优先权监督 / A Vision-Based System for a UGV to Handle a Road Intersection

## 论文在讲什么

这篇论文关注的是 UGV 在四向 stop-sign 路口如何根据三路来车情况决定何时通过。作者把问题拆成车辆检测、车辆跟踪和路口交通状态机三部分，其中我们最关心的并不是前两者的视觉算法本身，而是最后那个把车辆行为压缩成离散状态并把结果送给 autopilot 的路口监督逻辑。

论文场景很具体：UGV 到达路口并完全停车后，系统开始观察左、前、右三路的来车，只关心各路最前面的车辆是否正在接近、等待或通过。然后，状态机根据车辆位置、速度、加速度和尺度变化，把每一路交通行为写成 `No Vehicle Waiting / Arriving / Waiting / Passing` 四态，并据此告诉 autopilot 现在是否安全通过。这种写法虽然篇幅不长，但控制链非常集中，适合作为紧凑型自动驾驶监督样本。

## 控制系统在文中的位置

这套 FSM 是整篇论文的核心决策模块。车辆检测器和 tracker 给它提供输入，autopilot 则把它的输出当成是否过路口的控制信号，所以它承担的是“把连续视觉量转成离散交规决策”的职责。也正因为如此，论文在 `Finite-State-Machine Intersection Model` 这一节里交代了状态集合、状态转移条件、静止判定阈值和通过后的安全等待时间。

从 `sources/` 的角度看，这篇论文的价值不在于它是不是最复杂的自动驾驶系统，而在于它给了一条很规整的、可直接抽取的离散监督链。它既不是单纯的行为框架综述，也不是仅靠图表撑起来的概念稿，而是明确写出“何时算 Arriving、何时转 Waiting、何时进入 Passing、Passing 结束后还要额外等多久”这一整套监督逻辑。

## 对我们为什么有用

这篇论文对样本库的意义，在于补入一种很适合做入门级自动驾驶离散控制数据的 case。它的状态数量只有四个，但条件和动作并不空：有速度/加速度/尺度的 guard，有 `15 frames` 的静止确认，还有 `2 s` 的通过后等待。对于后续做状态机自然语言建模，这类“状态少、转移清楚、跨页少”的样本反而很有价值，因为它能作为更复杂自动驾驶 HSM/EFSM 的对照基线。

另外，它还把多视角融合后的 right-of-way 规则说清楚了。UGV 不是简单地只看有没有车，而是区分“对方在 UGV 到达前已经 Waiting”与“对方是在 UGV 到达后才 Arriving/Waiting”，并只在前者或 `Passing` 情况下让行。这样一来，它保住了真正与交规和监督控制有关的语义，而不是只剩感知模块描述。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看第 1-2 页的摘要、问题描述和系统概览，只确认场景假设和 autopilot 的职责边界；然后直接跳到第 4-5 页的 `Finite-State-Machine Intersection Model`，把四个状态、进入条件、空间阈值、`15 frames` 静止判定和 `2 s` 额外等待读稳，这样就能快速重建整条监督链。

如果后面还要更细化验证，再回到检测与跟踪部分，看 OT-MACH 检测器和 tracker 提供了哪些量给状态机。对第一次抽取来说，不需要深挖视觉相关实现细节；先把状态机和多视角 right-of-way 规则读出来，比先看检测算法更有效。
