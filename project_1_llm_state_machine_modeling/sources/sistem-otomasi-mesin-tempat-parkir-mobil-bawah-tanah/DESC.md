# 地下立体停车升降-旋转-推送控制链 / Sistem Otomasi Mesin Tempat Parkir Mobil Bawah Tanah dengan Menggunakan Programmable Logic Controller

## 论文在讲什么

这篇论文讨论的是一个地下自动停车装置的 miniaturized 原型系统。它不是泛泛谈“停车管理”，而是把中置载车机构、三层二十四车位结构、升降电机、旋转步进电机、气动推送机构、层位限位开关、槽位光电检测，以及 PC 与 PLC 的分工都写进了同一条工程链路里。

对我们更重要的是，作者没有把控制逻辑埋在几张效果图里，而是明确说明 PC 程序负责数据库和槽位命令，PLC 负责所有机械执行，并把执行流程拆成 `pengambilan pallet` 与 `peletakan pallet` 两个阶段。这样读者可以直接把它看成一个停车基础设施控制器，而不是一篇单纯展示装置搭建的停车原型稿。

## 控制系统在文中的位置

这里的控制系统就是论文主体本身。机械结构、传感器布置、PLC 输出接口、PC 通信和测试过程，几乎都在为“如何把车送到指定槽位并再取回来”这条主控制链服务，因此控制描述不是附属案例，而是全文成立的中心骨架。

文中的状态机语义主要不是靠显式状态图命名，而是靠“命令输入 + 层位/槽位检测 + 执行动作序列 + 返回初始位”的工程顺序来展开。对 `sources/` 而言，这类文章很有价值，因为它能提供一种与连续泊车轨迹规划完全不同的停车样本类型，即停车设施内部的离散执行控制链。

## 对我们为什么有用

当前停车领域里高质量双 A 样本虽然已经有所回补，但很多更偏轨迹规划、视觉泊车或局部门禁模块。本文补进的是另一类更贴近机械停车设备本体的样本，它把“槽位选择、楼层到位、旋转定位、推送/回收、应急手动控制”串成一条很完整的 `EFSM + T0` 控制链。

它对后续数据集尤其有用的一点，是输入、执行和流程阶段都相当具体。后面如果需要比较“停车基础设施控制”和“车辆运动学泊车控制”的差异，这篇可以作为非常典型的设施侧样本，而不会和模糊控制轨迹稿混在一起。

## 如果需要人工细读，建议怎么读

建议先看第 2-4 页，把装置结构、三自由度机械链、PC/PLC 分工以及 `limit switch / photoelectric` 这套输入输出边界先读稳。接着直接跳到第 6-7 页的软件与测试部分，重点抓 `ambil / letakkan` 两阶段程序、槽位选择、`2A` 放车示例帧序列，以及返回初始位的动作闭环。

第一次人工重读时，不必把所有硬件连接细节都逐个吃透。像驱动接口、电路细节和继电器保护设计可以放到第二轮再看；第一轮最重要的是把“命令如何下发、位置如何确认、动作如何顺序执行、异常时如何手动接管”这条主控制链重新抽出来。
