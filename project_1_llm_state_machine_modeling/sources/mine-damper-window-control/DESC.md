# 矿井风门/风窗联动控制 / Design and application of the control system of mine damper and window

## 论文在讲什么

这篇论文针对的是矿井联络巷中的风门与风窗控制问题。作者面对的不是抽象的“自动化升级”口号，而是非常具体的现场痛点：人工开门通行不方便、通风调节不及时、传统挡板式风窗调风范围小，而且双风门误开还会打乱风流组织。论文因此把对象落在一套真实矿井通风辅助设施上，并明确提出要把风门通行控制和风窗风量调节一起做成可远程监测、可联网、可自动运行的系统。

系统结构也写得比较清楚。风门部分由双侧红外、气缸、互锁和声光报警组成，负责人员或车辆在两道风门间的安全通行；风窗部分则由电机、连杆和角度编码器组成，负责百叶角度调节。论文的重点不在机械结构本身，而在“检测到了谁、等待多久、什么时候开、什么时候关、关到一半被再次触发怎么办、两道门怎么互锁”这些离散控制逻辑上。

## 控制系统在文中的位置

这里的控制系统是全文主角。摘要已经明确说论文研究的是 `damper window control system`，而正文最关键的第 `2.2` 节直接给出了八步软件流程，把通行链条拆成了外侧检测、`3 s` 延迟开门、等待通过、内侧检测关门、`15 s` 超时关门、触发防夹回开、对向门镜像流程等顺序动作。也就是说，这不是“顺手提一下控制器”的装置论文，而是以控制流程为核心来解释整套系统为什么能在矿井环境里稳定运行。

另外，这篇论文还不是只停在 nominal path。作者明确补上了对我们很重要的两个控制维度：第一是双门不能同时开启，否则会造成风流紊乱，因此要加电气互锁与报警；第二是门在关闭过程中若红外再次触发，就要立即停止关门并返回开门步骤。这使得它不只是一个“检测后开门再关门”的薄样本，而是一篇保住了异常约束与恢复回跳的工程控制文献。

## 对我们为什么有用

从 `sources/` 的样本建设视角看，这篇论文的价值首先在于对象类型比较稀缺。它不是常见的停车、电梯、交通灯或一般门禁，而是矿井通风系统中的风门/风窗协同控制。这种对象天然同时带有安全约束、互锁关系和局部时间语义，能够补充过程与环境控制方向里“通行设施 + 通风调节”这一类比较少见的离散控制样本。

其次，它对状态机抽取很友好。风门部分可以直接整理成带 guard 和 timeout 的 `EFSM + T1` 链，风窗部分则给出了一个简单但明确的角度调节子逻辑。后续如果要做“从自然语言控制流程重建带恢复分支的状态机”，这篇论文既有主链，也有回跳，还保住了互锁和报警，信息密度明显高于许多只讲设备组成或效果展示的地方性短文。

## 如果需要人工细读，建议怎么读

人工细读时，建议先看第 `2.2` 节对应的 `paper_content.txt` 第 `76-100` 行，把八步流程完整抄清楚，这是整篇最关键的控制证据。接着读第 `3` 节中 `112-131` 行的实际运行说明，用它校对门 `A/B` 的镜像关系、报警提示语和互锁行为。最后再回看第 `55-68` 行与第 `128-141` 行，确认风窗 `0-90°` 调节与远程控制边界，这样就能快速建立一条“通行控制 + 风量调节”的双子系统视图。

相对而言，背景性的矿井通风意义、经济效益估算以及前言里的通风系统概述可以后看。真正重做 `STM.md` 时，最值得优先锁定的是：`3 s / 15 s` 这两个时间点、关门过程中的再触发回开、双门互锁防风流紊乱、以及风窗正反转对应的角度变化。只要这几块抓住，这篇论文的状态机主链就不会跑偏。
