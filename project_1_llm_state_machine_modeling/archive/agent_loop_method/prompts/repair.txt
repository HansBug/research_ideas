## pyfcstm DSL syntax cheat-sheet

> Every code snippet below has been verified to parse + convert to a
> state-machine model via the actual pyfcstm runtime. Follow the patterns
> exactly.

### Top-level structure (REQUIRED)

```
def int counter = 0;             // variable definitions (int / float) BEFORE the root state
def float temp = 25.0;

state Root { ... }               // EXACTLY ONE top-level state
```

### State / lifecycle / aspect / pseudo

```
state A;                                              // leaf, declaration only
state B { during { counter = counter + 1; } }         // leaf with lifecycle
state Composite {
    [*] -> Child;                                     // composite MUST have an initial transition
    state Child {
        enter { counter = 0; }
        during { counter = counter + 1; }
        exit  { counter = 0; }
        enter abstract InitHardware;                  // abstract placeholder (Python handler @ runtime)
    }
    >> during before { counter = counter + 1; }       // aspect: before every descendant leaf during
    >> during after  { counter = counter * 2; }       // aspect: after every descendant leaf during
}
pseudo state Junction;                                // non-stoppable routing state
```

### Transitions — CRITICAL SYNTAX RULES

Grammar shape: `Source -> Dest [SCOPE] (; | effect { ... })`

**SCOPE** is AT MOST ONE of the following (event and guard are MUTUALLY
EXCLUSIVE on the same transition):

| form | event path resolved as | semantic meaning |
| --- | --- | --- |
| `S1 -> S2 :: Tick` | `<Parent>.S1.Tick` | **LOCAL** — event in source-state namespace (S1 owns it) |
| `S1 -> S2 : Tick` | `<Parent>.Tick` | **CHAIN / parent-relative** — event in enclosing parent's namespace (siblings share) |
| `S1 -> S2 : /Sub.Tick` | `<RootName>.Sub.Tick` | **ABSOLUTE** — `/` itself = Root, **do NOT repeat root name** after `/`. `/Sub.Tick` = Tick owned by Root's direct child Sub. `/Tick` = Tick owned by Root itself. |
| `S1 -> S2 : if [expr]` | (no event) | **GUARD** — leading `:` REQUIRED |

ALL of these are **VALID**:

```
A -> B;                                              // bare
A -> B effect { counter = 0; };                      // effect-only
A -> B :: Tick;                                      // event-only (local)
A -> B :: Tick effect { counter = 0; };              // event + effect
A -> B : Tick;                                       // event chain (parent-relative)
A -> B : /Global;                                    // event absolute (Root itself)
A -> B : /Sub.Tick;                                  // event owned by Root's direct child Sub
A -> B : if [counter > 0];                           // guard-only (leading `:` REQUIRED)
A -> B : if [counter > 0] effect { counter = 0; };   // guard + effect
[*] -> A;                                            // initial transition
[*] -> A :: Start effect { counter = 0; };           // initial with event + effect
A -> [*];                                            // exit transition
```

These are **INVALID** (parser will reject):

```
A -> B :: Tick if [counter > 0];                     // ✗ event + guard cannot coexist
A -> B :: Tick : if [counter > 0];                   // ✗ same (with explicit `:`)
A -> B if [counter > 0];                             // ✗ guard MUST have leading `:`
```

### Forced transitions (`!` prefix) — same SCOPE rules, **NO effect block**

```
! Source -> Target :: Event;                  // descendants of Source → Target on Event
! * -> ErrorHandler :: Error;                 // ANY descendant → ErrorHandler on Error
! * -> ErrorHandler : if [error_flag > 0];    // ANY descendant → ErrorHandler when guard true
```

**CRITICAL — forced transitions DO NOT support `effect { ... }` blocks**
(grammar terminates them with `;` only). If you need side-effects, move them
to the target state's `enter { ... }` action:
```
// WRONG:  ! * -> Red :: Reset effect { timer = 0; };
// RIGHT:  state Red { enter { timer = 0; } } + ! * -> Red :: Reset;
```

### Variable expressions inside guards / effects

arithmetic / bitwise / comparison / logical / ternary / 22 math functions
(`sin / cos / sqrt / abs / log / exp / ...`) / constants (`PI_CONST` etc.).
Inside `effect { ... }` you may use nested `if [cond] { ... } else if [...] { ... } else { ... }`.

All variables MUST be declared with `def int / def float` at the top level.
Undeclared variable references fail at semantic-validation stage (after parsing).

## Feedback you'll receive

- **ParseFeedback**: syntax error from ``pyfcstm.dsl.parse_with_grammar_entry``.
  Includes ``line`` / ``col`` / ``expected_tokens`` / ``got`` / ``snippet``.
  → Fix the listed token at the listed location. Common causes: missing
  ``;``, missing ``[*] ->`` initial transition for a composite state, wrong
  event-scope operator (``::`` vs ``:`` vs ``/``), missing ``state`` keyword.
- **SemanticFeedback**: AST → model conversion failed. Lists
  ``missing_states`` (a transition references a state name not declared),
  ``dangling_transitions``, ``unresolved_event_refs``, ``undefined_vars``,
  ``type_mismatches``, ``other_errors``, and raw ``diagnostics``.
  → Declare missing states / variables, fix event-scope references, or
  address the structured diagnostic code without regex-matching the human
  message.
- **SimFeedback**: ``SimulationRuntime`` rejected a transition or hit a safety
  limit. Lists ``unreachable_states``, ``deadlocks``, ``witness_path``,
  ``safety_limit_hit``, and ``dfs_error_message`` enumerating pathological
  patterns (composite with no enabled init, pseudo chain never settles,
  exit-vs-parent-continuation cycle, mutually-blocking guards).
  → Add a valid ``[*] -> ...`` for the composite, weaken a guard so at least
  one outgoing transition is enabled, or remove a pseudo-state hop that
  doesn't lead anywhere stable.
- **JudgeFeedback**: ex1 ExpertReviewAgent rubric (5 dim: coverage / fidelity
  / structure / executability / safety) and ``evidence_spans`` pointing at
  specific lines / states / transitions that scored low. ``overall`` is in
  ``[0, 1]``.
  → Address the lowest-scoring dimension. Coverage low ⇒ add the missed
  state / event / variable; fidelity low ⇒ a transition contradicts the NL;
  structure low ⇒ refactor hierarchy; executability low ⇒ fix unreachable
  parts; safety low ⇒ add fault recovery / forced escape.
