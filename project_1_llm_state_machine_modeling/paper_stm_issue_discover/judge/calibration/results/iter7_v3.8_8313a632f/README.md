## 逐条读 reason 之后的归因

current 侧 gold 有效被判 D0 的 29 行、baseline 侧 gold N 被判 I 的 18 行，按 judge 理由归到六个来源：

1. **记法良构性规则吞掉了行为缺陷（current 5 行 gold K）。** 初始边带触发或守卫、普通迁移代替初始伪状态，会让描述的首个状态变成条件进入或事件门控进入，是行为缺陷；v12 把它们写进「记法抱怨 → D0」的例子里，judge 照做。
2. **「不出 D1」被从事件名标签泛化到布尔标签（两侧 13 行 gold D1）。** 载体规则本来就是事件名 → D0、布尔表达式 → D1；v12 新句子没限定标签类型。
3. **事件名被当成已写动作（3 行 gold K）。** 计时器启停根本没写成动作，只有名为 Timer Expired 的事件；v12 的「或命名的事件 / 信号」半句让 judge 把事件名当实现。
4. **「设计读法更自然 → D0」是纯判断性半句（约 7 行 gold D1 / K）。** 它没有对应的可查证形状，judge 用它把任何有替代读法的报告降为 D0。
5. **FALSE_POSITIVE 锚定没有生效（两侧 9 行 gold 有效，含 6 行 gold K）。** 同一家族：报告说某状态「未定义 / 未声明」，该状态只作为迁移端点出现、无声明无出边；judge 仍判「事实为假」，gold 判事实为真再问义务。v12 的措辞没有点到这个形状。
6. **relation 恢复 v10 没有减少漏匹配（baseline 6 行、current 4 行 gold K 判 N）。** 报告与台账条目在同一组合态 / 区域、同一义务族但点名不同迁移或 facet，两种措辞下 judge 都判 NO；两读分歧时仲裁两次都倒向 NO（0023：PARTIAL 与 FULL 仲裁成 NO；0057：NO 与 FULL 仲裁成 NO）。对有效报告 PARTIAL 就足以升 K。

另有两侧 gold 自身的宽严差：完全覆盖、子态重复边界迁移、组合态层已实现这些 prompt 早已列为 D0 的条款，v12 让 judge 一致地执行了，current 侧 gold 也判 D0，baseline 侧 gold 却判 D1 / D2（两侧出自不同的重审批次）。judge 必须对两臂用同一规则，这部分不追。

## 由本轮导出的 prompt v13（六处，锚点唯一）

(0) 忠实度条款只保留表示论半句：缺陷读法仅要求更显式 / 更可执行 / 更字面的表示 → D0；描述的行为本身缺失、被改变或不可达 → D1，即便设计读法也自然。(i) 「不出 D1」限定事件名标签，布尔标签维持 D1。(ii) 删去「命名的事件 / 信号」，事件名不是动作。(iii) 初始边守卫 / 触发与普通迁移代替初始伪状态按行为效果判：进入变成条件的、事件门控的、阻塞的或缺失的就是缺陷。(iv) 只作为端点出现、无声明无出边的状态，报告说它未定义时事实为真，按义务判，永不 FP。(vi) PARTIAL 覆盖同组合态 / 区域 / 迁移族且同义务族（进入、并发、终止、计时或数据侧）的关系，NO 要求不同位置或无关义务。
