# X1-v2 事前登记：schema 臂身份泄漏修复后的全网格重跑

> ⛔⛔ **本文件必须在跑之前推到远端。** 它的全部价值来自「写在看到结果之前」，⛔ 而这一点只有远端时间戳能证明。

## 一、为什么重跑

X1-v1（`runs/paper1/x1-baseline-v1/`）的输出契约 `src/schema.py` 有一处**臂身份泄漏**：pydantic 把**类 docstring** 放进 `model_json_schema()` 的**顶层 `description`**，因而随 schema 进入生产者上下文。泄漏的逐字内容包括：

- `NaiveIssue.__doc__`：「**基线**报出的一条不符之处。」
- `NaiveReview.__doc__`：「⋯**主臂**是**八阶段循环**、每阶段有 rationale⋯**X1 是单次调用**⋯」「主臂做了**五类多报分类**」「⛔ 它不是 **C-③**」

⛔ **即：模型被告知自己是一个对照实验里的基线臂，并被告知另一臂的架构。**

⚠️ **边界**：⛔ **没有缺陷内容泄漏**——无台账 ID、无分类学、无谓词名、无「该找哪一类问题」的暗示；`prompt/naive_v1.txt` 本身干净中立。⭐ 这是**需求特征（demand characteristics）污染**，⛔ 不是作弊。

**修复**：类级说明改写成类定义上方的 `#` 注释（注释不进 `__doc__`）。修后 `model_json_schema()` 的顶层与 `$defs.NaiveIssue` 的 `description` 均为 `None`，schema 从 1282 字符降到 887（−30.8%），剩余全部是中性英文字段说明。

**回归防线**（两条，已反向验证：注入泄漏则两条都失败）：
- `test_schema_carries_no_arm_identity`：schema 序列化文本不得含臂身份词表（主臂 / 基线 / 对照 / 八阶段 / 单次调用 / C-①②③ / contribution / 多报 / 伞 PR / §4B ⋯）
- `test_class_docstrings_are_absent_from_schema`：两个模型类**不得有 docstring**（⭐ 堵通道，⛔ 不只是查词）

## 二、⛔ 这次重跑要回答的唯一问题

> **那处泄漏有没有实质改变 X1 的表现？**

⛔ 这个问题**不能靠论证回答**——「方向未知」是一个诚实的表述，⛔ 但它不能作为「结果可靠」的依据。⭐ X1 全网格只要约 7 分钟、成本是主臂的 1/212，⛔ **所以没有任何理由不重跑**。

## 三、事前写死的判据

**配置必须与 v1 完全一致**（⛔ 只有 schema 变了）：

| 项 | 值 |
| :-- | :-- |
| 网格 | 54 pair × 2 模型 × 3 轮 = **324 格** |
| 模型 | `gpt-5.5` 与 `claude-opus-4-7`（与 v1 同 profile） |
| prompt | `prompt/naive_v1.txt`，⛔ **一字不改**（sha256 必须与 v1 记录一致） |
| 温度等采样参数 | ⛔ 与 v1 一致（provider 默认，无覆盖） |
| 输出目录 | `runs/paper1/x1-baseline-v2/`（⛔ 不覆盖 v1） |

### 主判据（⭐ 跑前写死）

**H0：泄漏无实质影响。** 判据是**产出体量**与**产出形态**，⛔ 不是 `hit@1`——因为 v2 的判定尚未做，⛔ 而用未判定的数据反推 hit 会引入循环。

| 量 | v1 实测 | H0 的容许区间 | ⛔ 若落在区间外 |
| :-- | --: | :-- | :-- |
| 总 issue 数 | **1365** | **[1229, 1502]**（±10%） | ⛔ 泄漏改变了产出体量，v1 结果需重判 |
| 每格均值 | **4.21** | [3.79, 4.63] | 同上 |
| claude 侧总数 | **905** | [815, 996] | ⛔ 若只有一侧越界，记为模型特异反应 |
| gpt 侧总数 | **460** | [414, 506] | 同上 |
| 零产出格数 | **9** | [0, 18] | ⛔ 若显著上升，说明泄漏原本在**鼓励**它多报 |
| 失败格数 | **0** | **必须为 0** | ⛔ 非 0 则本次运行作废重跑 |

⭐ **±10% 的来由**：v1 与 v2 是**两次独立采样**，⛔ 即使代码完全不变也会有差异。⚠️ 我们没有 v1 的重复采样来估计这个天然波动，⛔ 所以 ±10% 是一个**先验选择**，⛔ 不是从数据来的——⭐ 这一点必须在报告里如实写明，⛔ 不得事后调整。

### 次判据

- **形态相似度**：v2 与 v1 在同一格的 issue 是否指向同一批模型元素？⭐ 用元素名重叠率度量，⛔ 只作描述性证据（两次独立采样本就不该逐字相同）。
- **成本**：token 与墙钟应与 v1 同量级（v1 约 7.2 分钟 / 849,086 token）。

### ⛔ 判定安排

- ⭐ **若主判据全部落在容许区间内**：认定泄漏无实质影响，⛔ **v1 的 588 位判定继续有效**，⭐ 在 talk 中如实记录「已用修复后重跑验证」。
- ⛔ **若任一主判据越界**：v1 的结果**必须重判**，⛔ 而 talk 里所有基于 X1 的数字都要标为待复核。

## 四、⛔ 事前声明的三条纪律

1. ⛔ **不许事后调整容许区间。** ±10% 与各项区间在本文件推送时冻结。
2. ⛔ **不许因为「结果符合预期」就少报。** 即使全部落在区间内，也要给出逐项实测值。
3. ⚠️ **本次重跑不改变任何已知的其它缺陷**：判定材料不对称（§5.1）、判定端可读维护版判据（§5.3.1）、台账零人类校验（§六）⛔ 都不受本次修复影响。⭐ 修好一处不等于实验干净了。

## 五、⚠️ 一个必须写下的利益冲突

⛔ **我方希望的结果是「无实质影响」**——因为那意味着已有的全部分析不必重做。⚠️ 正因如此，判据必须在跑前冻结，⛔ 且必须选**对我方不利也能被检出**的量：若泄漏原本在**压低** X1（例如「你是基线」让它敷衍），那 v2 的产出会**上升**并越界——⛔ 那对我方是坏消息（真实差距更大），⭐ 但判据同样会抓到它。
