# X1-v3 事前登记：把「去臂身份」与「去对象说明」两个通道分开

> ⛔⛔ **本文件必须在跑之前推到远端。**

## 一、为什么有 v3

**v1**：schema 含臂身份泄漏（类 docstring 进 `model_json_schema()` 顶层 `description`）。**v2**：把两个类 docstring **整段删掉**。⛔ 结果**零产出格从 9 涨到 22**（claude 侧 0/162 → 8/162，Fisher $p = 0.0072$），⛔ 越界。

⛔⛔ **v2 的问题是修复过度**：那两段 docstring 里除了臂身份，还带着**唯一的对象级说明**（「一条不符之处」）。⛔ **所以 v2 分不开两个通道**：

| 通道 | 内容 | 该不该去 |
| :-- | :-- | :-- |
| **① 臂身份** | 「基线」「主臂是八阶段循环」「X1 是单次调用」「五类多报分类」「C-③」 | ⭐ **必须去** |
| **② 对象说明** | 「一条不符之处」——即**它被要求产出什么** | ⛔ **不该去** |

⭐ **判据**：去掉的必须只是「它在参与一个比较」这件事，⛔ 不能连「它被要求做什么」一起去掉。

## 二、v3 的改动（⭐ 只有一处）

把对象级说明加回到 **`Field(description=...)`**（⛔ 不是 docstring），中性英文、⛔ 不提另一臂、⛔ 不提实验设计：

```
issue:    "One non-conformance between the model and the specification. Free text."
analysis: "Optional: your overall analysis after reading both inputs, before listing the non-conformances."
```

schema 长度：v1 **1282** → v2 **887** → v3 **967**。顶层与 `$defs.NaiveIssue` 的 `description` 仍为 `None`（⭐ 两条回归测试仍通过，54 passed）。

⛔ **其余一切不变**：`prompt/naive_v1.txt` 一字不改（sha256 `17e5067b…`）· 同 profile · 3 轮 · 54 pair × 2 模型 = 324 格 · 无温度覆盖 · 16 并发 · 输出目录 `runs/paper1/x1-baseline-v3/`。
