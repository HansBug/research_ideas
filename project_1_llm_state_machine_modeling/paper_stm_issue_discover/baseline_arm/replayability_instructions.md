## 一、第一轮判据缺了什么

`assertable` 问的是「这条发现能否转写成对模型可求值的命题」。⚠️ 它**默许了期望值那一半**：

> 「模型缺 X，**因为规范要求 X**」——`has_effect(...) = False` 对模型确实可判定，⛔ 但「这里**应当**有 effect」这半边来自**一个人读了 NL 并裁定它是义务**。

⭐ 于是「NL 要求 X / 模型没有 X」这一整类全部通过。⛔ 那不是基线的能力证明，是判据把 NL 解释那一半豁免掉了。

## 二、⭐ 本轮判据：`replayable`

> **这条发现能否被转写成一个命题 $P(E)$，使得「问题还在不在」可以在模型演化后被自动重新回答？**

⭐ **一句话的操作化测试**：**把模型改一改、重新跑这条命题，能不能不靠人就得出「问题还在不在」？**

三条要件，⭐ **三条全中才算 `replayable`**：

### 要件 1 · 输入闭合于模型

$E$ 的全部元素在模型内**可唯一定位**，且 $P$ 求值时**只读模型**——⛔ 不读 NL、⛔ 不读参考模型、⛔ 不问人。

### 要件 2 · ⭐⭐ 期望值已固化（**本轮新增的那一条**）

「这条发现成立」必须等价于 $P(E) = c$，其中 $c$ 是一个**写在命题里的常量**。

⛔ **不满足的形态**：判断这条发现成不成立，需要**重新裁定「NL 要不要求这件事」**。

| ✅ 满足 | ⛔ 不满足 |
| :-- | :-- |
| 「不存在从 `DoorOpen` 经 `Door Closed` 到 `DoorShut` 的迁移」——⭐ 命题连同它的期望（应存在）一起固化了 | 「模型未体现规范要求的 timer 启停」——⚠️ 「规范要求 timer」这半边每次都要人回去读 NL 确认 |
| 「`DoorsClosing` 的 entry 动作集含 `Accelerate`」+ 期望「应为空」 | 「这里应该有一个动作，因为需求提到了」 |

⚠️ **判别方法**：问「**如果我明天把这条命题交给一个自动化脚本，它需不需要人再告诉它『NL 要求这个』？**」需要 → ⛔ 不满足。

⭐ **注意这不是在问「有没有引用需求」**，而是在问「**期望值是不是已经被固定下来**」。⚠️ 一条发现可以完全不提需求却仍然固化了期望（例如「该状态不可达」——不可达本身就是缺陷，无需 NL 授权），也可以引用了需求但没固化（「规范似乎要求 X」）。

### 要件 3 · 单一方向

⭐ 与第一轮同：⛔ 不是若干可能性的并列。

## 五、⭐ 两个判定组的原话（口径由来的证据，⛔ 不得删改）

**A1**（110 位，94.5% assertable）：

> ⛔ **NL 侧的期望值被默许，模型侧却被严查。** 指令 §要件2 自己举的 ✅ 例是「该边的目标**应**是 X 而模型写的是 Y」——那个「应」来自 NL 解释，同样不可机械求值。于是「NL 要求 X / 模型没有 X」这一整类全部记 `true`。这不是基线的能力证明，而是判据把 NL 解释这一半豁免掉了。**若把「期望值本身必须可机械导出」也纳入要件，`0025/0035/0055` 的 timer 类、`0026-02` 的数量递减、`0034-04/05` 的信号发送都会翻成不可断言**，比例会从 94.5% 掉到大概六成上下。

**A2**（111 位，100% assertable）：

> ⭐ **最关键：判据回避了「相对于什么可求值」这个歧义，并且默认选了宽松的一侧。** 要件 2 写的是「**给定这份模型**，它要么真要么假」。但这 111 条里绝大多数的形状是「模型缺 X / X 放错槽位，**因为规范要求 X**」……⛔ 若论文 §1 的承重词「可机械求值」指的是**连义务一起不需人读 NL**，那么这批里相当大一部分要翻为不可断言；若指的只是模型侧谓词可求值，则 100% 全过——**而判据现在的字面选的是后者**。

⭐ **本轮口径选的是前者**，理由是 [story/paper_story.md](../story/paper_story.md) §7 逐字：**「求值阶段的输入里**没有需求、没有参考模型**，真值因此只由被评审模型决定」**——⭐ 那正是「期望值已固化」的另一种说法，⛔ 且它写在看到本轮任何结果之前。
