### 1.1 ⛔ 事前登记在这个方向上失效了，必须记录

[preregistered.md](../preregistered.md) §5.3 的档位表以 **带符号的** $\Delta$ 为自变量，而 $\Delta = -16.0$pp 满足 `Δ ≤ 2.0pp` 那一支，于是照字面要求写「在本语料上未观察到可归因的差异」——⛔ **那与事实不符**。

⭐ **这是登记的缺陷，⛔ 不是可以利用的空间。** 独立审查者在跑格前就预警过这一支缺 $\Delta < 0$ 分支（场景 D）。⭐ 按登记的**精神**（如实报告、不得声称超出数字支持的范围）处置：**如实报告基线更高**，并在下一代次登记里把档位改挂 $|\Delta|$ 并强制陈述符号。

## 2. ⭐ 逐位分解：两臂**互有胜负**，⛔ 不是一边宽松

588 位逐位并列（两臂键格式逐字相同，可直接对拍）：

| | 位数 | 占比 |
| :-- | --: | --: |
| 两臂都命中 | 271 | 46.1% |
| **仅主臂命中** | **84** | 14.3% |
| **仅 X1 命中** | **178** | 30.3% |
| 两臂都未命中 | 55 | 9.4% |
| 净差 | $+94$ | $= 16.0$pp ✅ 与 `hit@1` 的 Δ 闭合 |

⭐⭐ **「仅主臂命中 84 位」是排除「X1 判定普遍宽松」的关键证据**：若 X1 判得松，我们会看到 `x1_only` 很大而 `main_only` 趋近 0。实际两臂各有 14.3% 与 30.3% 的独有命中——**这是能力正交的形状，⛔ 不是一边放宽的形状。**

### 2.1 ⚠️ 按主臂四池分布：X1 的命中与主臂**几乎不相关**

| 主臂池 | 位数 | X1 在该池的命中率 |
| :-- | --: | --: |
| 满格 6/6 | 222 | $171/222 = 77.0\%$ |
| 近满格 5/6 | 78 | $67/78 = 85.9\%$ |
| 不稳定 1–4/6 | 150 | $101/150 = 67.3\%$ |
| 零命中 0/6 | 138 | $110/138 = \mathbf{79.7\%}$ |

⭐⭐ **满格池 77.0% 与零命中池 79.7% 几乎相同。** 即：主臂能否稳定命中某条缺陷，与 X1 能否命中它**基本无关**。⛔ 这直接反驳「基线只是把容易的那些捡了一遍」。

⚠️ **一处必须纠正的诊断逻辑**：`cross_arm.py` 的 `diagnose()` 曾把「满格池上 X1 独有命中 = 0」当作判定标准未放松的证据。⛔ **那是错的**：满格池按定义主臂全命中，`x1_only` 恒为 0，不含任何信息。⭐ 有信息的是上表的**池内命中率**与 §2 的 `main_only` 计数。

## 3. ⛔ 已查实的判定缺陷（必须修，且已修）

### 3.1 判定材料漏渲染 `basis_superseded_by_ruling` —— 影响 12 位

跨臂对拍暴露：`EIS-0000-02` 的 5 位分歧上，**两侧在读不同的台账命题**。主臂判定者的 argument 逐字：

> 台账 `basis_superseded_by_ruling` 明文撤回了「缺少可单独触发的事件」这条归因依据（NL 逗号列举，未授权析取解释）。改后的 primary 是 `stays_in(AutoNavigating, 融合事件)=False`

而 X1 判定组按 statement 散文判命中——因为 [present.py](../analysis/present.py) 初版**没有渲染该字段**。

⛔ **这是判定伪影，方向抬高 X1。** 全语料只有 **2 条**记录该字段非空（`EIS-0000-02` / `EIS-0050-01`），影响 $2 \times 6 = 12$ 位 = 2.0% 的分母。⭐ 已修 `present.py`（该字段现以「原判据已被裁定部分撤回」的显式警示渲染）。⚠️ 即使这 12 位全部翻转，$\Delta$ 仍为 $-14$pp 量级——⛔ **它不是 Δ 为负的原因。**

### 3.2 判定组的自报歧义（逐条已登记，供复核）

6 个判定组各自报出了判得犹豫的位，其中影响最大的三处：

| 位 | 组 | 歧义 | 若改判的影响 |
| :-- | :-- | :-- | :-- |
| `EIS-0049-03` | J1 | 五格报的是与台账**相反**方向（台账「三条子态级完成边冗余」vs 产出「完成边覆盖不足」）。按纪律 2 判未命中 | 该记录 1/6 → 6/6 |
| `EIS-0005-02` | J3 | 三格触及同一段代码块且同样点名自造子态，⛔ 但明确主张「行为等价」，否定台账的互斥性破坏 | 该记录 0/6 → 3/6 |
| `EIS-0046-01/02` | J6 | 产出主张与台账**修法方向相反** | 2 位可能翻转 |

⭐ **注意方向**：这三处的自报歧义**若全部改判，X1 的数字会更高**。即判定组在这些位上取了**压低 X1** 的一侧。

## 4. ⚠️ 两臂不对称：⛔ 两个方向都必须披露

### 4.1 压低 Δ 的（即：使 X1 看起来相对更好——⭐ 而实测 Δ 已经是负的，所以这些**加重**了主臂的不利）

| # | 不对称 | 状态 |
| --: | :-- | :-- |
| 1 | ⭐⭐ **两臂读的不是同一份制品** | X1 读 `plantuml.puml`（**作者源**），主臂读 `fcstm.fcstm`（**编译产物**）+ trace + 契约。⚠️ 实测主臂源码树 `grep -rn 'plantuml\|\.puml'` **只有一处注释命中**。⛔ 而**台账缺陷是按作者源标的**——转换既会擦掉缺陷（pair 0000 的 `state HumanDrivingMode { }` 空复合体在 fcstm 里变成普通 state），也会注入编译噪声。⭐ 这是 C-① 自身的代价，⛔ 不是不公平，但它必须披露 |
| 2 | 主臂有「被自己的门吃掉」的发现，X1 没有任何 gate | 主臂的「没报」里混有被结构门 / 归因层 / 角色制度 / 预算吃掉的；X1 的「没报」是纯粹没报 |
| 3 | ⭐ **主臂 prompt 有逐段覆盖义务，X1 没有** | 主臂：「**Cover every normative NL segment**」；X1：「read the model in full」。⚠️ 而 98 条台账**每条锚在一个 NL 段落上**——逐段扫描正是最大化该指标的策略。⛔ 这一栏在三栏表里**不存在**（表只枚举「不给的能力」，没有「不给的策略」）。⭐ 方向：**压低 X1**。见 §6 |
| 4 | 主臂多注入一份 schema format instructions | `responder.py` 把 `PydanticOutputParser.get_format_instructions()` 追加进 system prompt，X1 只靠 `with_structured_output`。⭐ 影响有限的实证：X1 **零 schema 失败**（0/324） |
| 5 | `EIS-0047-03` 的引入动机剔除 | 主臂一位「应命中而不计入」，X1 照常计入 |
| 6 | X1 判定覆盖更完整 | 主臂 20 位无逐格 argument（其中 **15 位在命中侧且不可复核**——⚠️ 方向其实是**抬高主臂**，登记原先归错了档） |

### 4.2 抬高 Δ 的（即：使 X1 看起来相对更差）

| # | 不对称 | 状态 |
| --: | :-- | :-- |
| 1 | 判定误差单向低估基线 | 判定者顺台账字面找对应，X1 只有散文 → 措辞不同可能误判成没报 |
| 2 | 判定非盲 | 判定组知道自己在判基线臂 |
| 3 | matched/unmatched 划分机制不同 | X1 全人工、主臂机械匹配器。⚠️ **方向未定，取保守假设** |
| 4 | ⛔ `basis_superseded_by_ruling` 漏渲染 | §3.1，已修，影响 12 位 |

⛔ **不得给出「两者大致抵消」这类未经量化的结论。** ⭐ 但可以确定一件事：**§4.1 的六条与 §4.2 的四条方向相反，而实测 Δ 已经是 $-16$pp**——即若把 §4.1 的偏差校正掉，Δ 会**更负**。

## 6. ⛔ 最强的一击，以及它现在的处境

独立稻草人审查给出的最强攻击（跑格**前**提出）：

> 你的方法第一阶段被指示「覆盖每个规范性 NL 段落」，你的基线被指示「通读模型」。然后你针对一个每条都锚在 NL 段落上的真值测召回。你报告的差距里有未知比例是「覆盖扫描 vs 整体阅读」的差距——而能弥合它的那个子句只有一句话长、不泄漏任何东西、且不含你三条 contribution 中的任何一条。

⭐⭐ **实测结果使这一击的方向反转**：它原本预警「Δ 被虚高」，⛔ 而实测 Δ 是**负的**。也就是说，**在基线处于这个劣势的情况下，它仍然高出主臂 16pp**。⭐ 补上那一句只会让基线更高。

⛔ **所以「你削弱了基线」这条反驳自动失效**，⭐ 但代价是另一个问题变成了主问题：**八阶段循环 + 谓词体系在这个指标上不如一次提示。**

## 7. ⛔ 本文件不做的事

1. ⛔ **不改主臂任何数字**：$355/588 = 60.4\%$ 一位未动，588 冻结完全成立。
2. ⛔ **不解释 Δ 为负的成因**——那需要 §5 的多报侧归并、`loss_stages.py` 的损失分解、以及对「主臂的门吃掉了什么」的定量分析。⚠️ 在那之前，⛔ 不得给出任何机制性断言。
3. ⛔ **不声称统计显著**：本语料只有 8 个独立 NL 簇，低于 `metrics_at_k.ratio_gate` 的门槛 10。措辞上限是「在本语料上观察到 Δ = −16.0pp」。
4. ⛔ **不对 C-① 下结论**——⭐ C-① 有第二个轴（真值封存 / 结果完整性），且 `hit` 只是它主轴的一部分（主结论已由 B1 事前登记锁定为「能力形状」而非单一数字）。⚠️ 但这一结果显然要求 R1/R2 重新评估 C-① 的强度与证据设计。
