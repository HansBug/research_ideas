## 一、你要做什么

给你一份或多份**判定材料**（每份对应一个 pair），每份里有四样东西：

1. 需求原文（NL 全文）
2. 被审模型（PlantUML **作者源**全文）
3. 该 pair 的台账期望记录（每条一段 `statement`）
4. 若干格的完整产出（每格若干条已发布 issue，每条有 `title` / `rationale`；另附该格的已发布断言表）

材料末尾列出了**要填的位**，每个位是一对「台账记录 × 某一格」。

**对每一个位，判一件事**：⭐ **这一格有没有报出指向同一处作者源缺陷的主张？**

⛔ 只填材料里列出的位，⛔ 不要自行扩充。

---

## 二、⭐ 唯一裁决标准

> **判定命中的标准是：我们的主张所表达的命题，与台账那条记录所表达的命题，是否指向同一个作者源缺陷。**

⛔ **不是**：两者措辞是否相同 · 两者提到的元素名是否相同 · 两者的路径集合是否完全相同。

### 2.1 语义同一性的四种成立形态（⭐ 闭集，`equivalence_form` 只能填这四个之一）

| 形态 | 含义 |
| :-- | :-- |
| `直接对应` | 两个命题说同一件事，只是措辞不同 |
| `合取项之一` | 台账命题是「A 且 B」，我们证明其中一个合取项为假 |
| `负向命题的正向对偶` | 台账说「不应存在错的边」，我们说「应存在对的边」 |
| `蕴含更根本的原因` | 我们的命题为假**蕴含**台账命题为假，且定位到更上游（例：台账「该边应有变量下降」，我们「模型根本没声明该变量」——无变量则不可能有下降） |

⭐ **后三种都算命中。判据是逻辑关系，⛔ 不是形式相同。**

⛔ **一个不属于任何形态的「等价性论证」就是没有论证**——闭集是这道闸的全部力量所在。

### 2.2 ⛔ 不成立的形态（即使措辞大量重叠）

- ⛔ **不同缺陷共用状态名**：一条关于 `HighwayMode` 子状态计数的发现，不算作关于 `HighwayMode` 内某条迁移目标错误的记录的命中
- ⛔ **更弱的命题**：台账要求「这条边的目标是 X」，我们只证明「这个状态存在」——存在性不蕴含目标正确
- ⛔ **用结构存在性冒充行为验证**：「某条 transition / edge 是否存在」**不能代替**「某状态是否可达」。边存在 ≠ 状态可达（边可能永不使能、源态可能不可达、守卫可能恒假）；边不存在 ≠ 状态不可达（可经其它路径抵达）。⚠️ 两者形式相似而实质不同，属**以次充好**——这是唯一被点名禁止的替换形态
- ⛔ **反向蕴含**：台账命题为假**不**蕴含我们的命题为假

### 2.3 ⚠️ 边界要划准：**允许等价，只禁伪等价**

§2.2 是一份**窄清单**，⛔ 不要把它读成「凡是形态不同就不算命中」。

> ⭐ **真正的等价一律接受，包括用不同侧面发现同一个问题。** 措辞不同、切入面不同、提到的元素名不同，都不影响命中——只要指向的是**同一处建模失误**。

⛔ **不要用「读者据此修复后台账缺陷是否即消失」当判据。** 那条太严，会误杀「合取项之一」与「蕴含更根本的原因」两种形态——它们按定义就不会一修即消。

**判定顺序**：⭐ 先问「是不是同一处失误」（是 → 倾向命中），再查「有没有踩 §2.2 的禁止项」（踩了 → 不算命中）。⛔ **不要反过来先看形态。**

### 2.4 「同一处失误」的硬判据：**数作者源里的引用次数**

「同一处」不是感觉，是可数的。判据：**在 PlantUML 作者源里，两个主张各自指向的元素被引用了几次。**

> 若某元素**全文只被引用一次**，则一切以它为对象的主张都锚在**同一条作者编辑**上，两个主张是那一条语句的两面——动其一必动其二。

⚠️ 要数的是「该元素在**它自己那个命名空间里**被引用几次」——一个不加过滤的计数会把迁移标签里的同名字符串也算进去（那属事件命名空间，不是状态）。

⚠️ 同源只是**必要条件**，不是充分条件。还要过 §2.3 的第一问。⚠️ 若我们的主张是台账主张的**严格超集**、且超出的部分点到了**正确的**元素，那不是「同一处失误的另一面」，不算命中。

⭐ **这条判据必须对称适用，尤其是在它会压低数字的方向上。**

## 三、⛔ 判定纪律（违反即该位作废）

| # | 纪律 |
| --: | :-- |
| 1 | ⭐ **读 PlantUML 作者源**判缺陷。⛔ 材料里没有、也不许去找 `model.fcstm` / `fcstm.fcstm`（编译产物）——否则会把编译债务当成模型缺陷 |
| 2 | ⛔ **不许按标题或元素名相似度对齐。** ⚠️ 有直接证据：两条产出触及了正确的元素、却得出与台账**相反**的结论（台账记「守卫晚一条边，未充电时仍可进入 X」= 可达性过强，产出报「运行时不可达」= 可达性不足）。任何按相似度对齐的做法都会把这两条判成命中 |
| 3 | ⛔ **不许去读任何判定结果**：不读 `discover_matrix/v46/verdicts/` 下任何文件、不读 `expected_issue_set.json`（材料里已含你需要的 `statement`）、不读任何 `*_human.json` / `*_tiers.json` / `key.json` / `annotation_*.json`、不读 `/tmp/x1reju/sample.json`。⭐ **只读发给你的材料文件本身**，⛔ 不要去仓库里找任何别的东西 |
| 4 | ⛔ **不设「待定」。** 证据不足不是一个裁定类别——材料里有 NL 全文、作者源全文、statement 全文，取证足够。判不出来说明还没读完 |
| 5 | ⛔ **一格未发布任何 issue**，则该格的全部位都是 `hit: false`。⚠️ 但仍要写 `argument`（一句「本格未发布任何 issue」即可） |
| 6 | ⚠️ **格失败 / 格缺失**（材料里会明确标出）：该位填 `"hit": null` 并在 `argument` 里写明原因。⛔ **不填 false** |

### 3.1 ⭐ 什么承载命中（本次材料特有）

- ⭐ **已发布 issue** 承载命中（`title` + `rationale`）。这是主渠道。
- ⭐ **已发布断言表**里结果为 `False` 的断言也可以承载命中——只要它所表达的命题与台账那条记录指向同一处作者源缺陷。⚠️ 这是被审方法自身的判据（它的主张就是 assert 表达的命题），⛔ 不是为了抬高数字而加的。若某位靠断言而非 issue 承载，必须在 `argument` 里点名该 `assertion_id` 并在 `carrier` 字段填 `"assertion"`。
- ⛔ **标了「不计入命中」的区块**（被排除的发现 / 覆盖缺口 / 被丢弃的 issue 等）**一律不承载命中**。呈现它们只是为了让你看到本格想到了什么。⚠️ 一个位若只能靠这些区块支撑，就是 `hit: false`。
- ⛔ 断言表里结果为 `True` 的断言**不承载命中**（它是「没发现问题」的记录）。

## 四、⛔⛔ 反自利纪律（本次特有，必须逐字遵守）

本次重判在**测一个对我方有利的假设**，所以判据必须比平时更严：

> ⭐ **只有当该格产出明确指向同一个模型元素与同一个缺陷事实、且你能把蕴含链一句话说清时，才判 `hit: true`。说不清就判 `hit: false`。**

⛔ 不要为了「看起来沾边」而判命中。⛔ 不要把「该格发现了这个 pair 的某个问题」当成「该格发现了这一条」。

## 五、输出格式

返回**一个 JSON 对象**，⛔ 不要包在任何解释文字中。结构：

⛔⛔ **下面示例里的一切 id、pair 号、issue 编号与 `hit` 值都是合成的占位符**，语料里**不存在** `EIS-9999-99` 与 pair `9999`。⭐ 示例只演示字段形状与论证的详略程度，⛔ 它不表达任何真实位该判什么。

```json
{
  "judged_by": "<你的判定组编号，如 R1>",
  "positions": {
    "EIS-9999-99|run1/9999-gpt": {
      "hit": true,
      "equivalence_form": "直接对应",
      "carrier": "issue",
      "argument": "已发布 issue [3] 逐字指出 <某元素> 的 <某属性> 与规约不符，与台账那条记录指向作者源同一处编辑（作者源那一条语句），只是措辞不同。"
    },
    "EIS-9999-99|run1/9999-claude": {
      "hit": false,
      "argument": "本格 N 条 issue 分别关于 <另一些对象>，无一指向台账所述那一处；断言表里为 False 的两条也分别关于 <别的对象>。"
    }
  },
  "note": "可选：判定中遇到的判据歧义"
}
```

**字段要求**：

| 字段 | 要求 |
| :-- | :-- |
| `hit` | `true` / `false` / `null`（仅格失败或缺格） |
| `equivalence_form` | ⭐ **`hit: true` 时必填**，且必须是 §2.1 四形态之一逐字。`hit: false` 时省略 |
| `carrier` | ⭐ **`hit: true` 时必填**：`"issue"` 或 `"assertion"` |
| `argument` | ⭐ **`hit: true` 时必填且 ≥ 20 字**。`hit: false` 时也要写。⭐ 必须**点到具体的 issue 编号或 assertion_id**，使判定可复核 |

⛔ **位的键必须逐字照材料里「五、要填的位」列出的字符串。**

⚠️ **位数必须齐**：把发给你的每份材料末尾列出的位全部填上，⛔ 一个都不能漏。⭐ 交之前自己数一遍。
