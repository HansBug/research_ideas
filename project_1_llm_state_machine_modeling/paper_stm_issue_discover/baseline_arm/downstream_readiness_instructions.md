# 下游就绪度判定指令（发给每个判定组的**物理同一份**文本）

> ⭐ 本判定与「这条发现对不对」**无关**，也与上一轮的「可断言性」**不同**。⛔ 不复核命中。
>
> ⚠️ **上一轮的教训直接写在这里**：可断言性口径实测 **98.2%**，⛔ 无区分力。三个判定组独立指出它只问「能否求值」而**漏了一件事**——⭐ **一条断言必须有「期望值」才能求值为真假**。本轮补上那一条。

---

## 一、要回答的问题

> **这条发现能否在「不需要任何额外人工决定」的前提下，变成一条可执行的断言？**

⭐ 判据叫 **下游就绪（downstream-ready）**。⛔ 它比「可断言」严：可断言问「能不能写成命题」，⭐ 下游就绪问「**写这条命题所需的信息，发现里齐不齐**」。

---

## 二、四条要件（⭐ 四条全中才算 `ready`）

### 要件 1 · 谓词确定

发现必须说清**要检查的是哪一种关系**，⛔ 而不只是「不符合」「有问题」。

| ✅ | ⛔ |
| :-- | :-- |
| 「该状态**未被声明**」（存在性） | 「这里建模不完整」 |
| 「这条边的**目标**是 X」（迁移目标） | 「结构不清晰」 |
| 「从初始态**不可达**」（可达性） | 「与规范意图不符」 |

### 要件 2 · 绑定完整

命题涉及的**每一个**元素都被点名且能在模型里唯一定位。⛔ 有一个元素只能靠读者推断，即不满足。

⚠️ **常见的失败形态**：「应该再加一条返回边」——回到**哪个**状态？由**什么**触发？⛔ 这两样发现里没有，写断言的人必须自己决定。

### 要件 3 · 期望值明确 ⭐⭐ **本轮新增，是收紧的关键**

发现必须说清**应该是什么**，⛔ 而不只是**现在是什么**或**现在不对**。

| ✅ | ⛔ |
| :-- | :-- |
| 「`Power Off` 应从 `HumanDrivingMode` 出发，而模型写的是 `[*]`」 | 「`Power Off` 的源端是顶层伪初始」（⚠️ 只陈述现状） |
| 「`AutonomousMode` 应有初始子状态 `AutoIdle`」 | 「`AutonomousMode` 缺少初始子状态」（⚠️ 未说该是哪个） |
| 「两条边的守卫应互斥」 | 「两条边守卫相同」（⚠️ 未说应该怎样） |

⛔⛔ **这一条最容易判错，所以说清楚边界：**

- ⭐ 若期望值**由缺陷类型唯一确定**，算满足。例：「状态 `X` 未被声明」——期望显然是「应被声明」，⛔ 无需另说。
- ⛔ 若期望值**有多个可能而发现没选定**，不满足。例：「缺少返回边」——返回到哪、由什么触发，是**开放的**。
- ⚠️ 判据是：**写断言的人需不需要自己做一个发现里没有的决定？** 需要 → ⛔ 不满足。

### 要件 4 · 单一方向

⛔ 不是若干可能性的并列（「应该加边，或者改成子机状态」）。

---

## 三、⛔ 五条纪律

1. ⛔ **不复核命中对错。** 一条发现可以既命中又不就绪。
2. ⛔ **不要因为「它说得对」就判就绪。** ⭐ 正确性与就绪度正交。
3. ⚠️ **上一轮的两条豁免条款，本轮收紧**：
   - 上一轮：「有可断言主张 + 附带议论时按可断言的那半判」→ ⭐ **本轮改为：按判定者当时锚定的**那一条主张判。⛔ 不许用同 issue 内**另一条** issue 或句尾碎片救回。
   - 上一轮：「去掉对冲词后仍剩确定命题就按剩下的判」→ ⭐ **本轮保留**，⛔ 但去掉对冲词后必须仍满足要件 3。
4. ⛔ **两个数都要给**：`ready_strict`（只看被锚定的那条主张）与 `ready_lenient`（允许同 issue 内其它部分补全）。⚠️ 上一轮的教训是**口径松紧决定结论**，⭐ 所以本轮双报。
5. ⛔ **不要偏向任何一侧。** ⚠️ 若这批条目大多就绪，⭐ **如实报出**——那意味着这条论证线也不成立。

---

## 四、⭐ 关于「这对基线不公平」这个意见

⚠️ 上一轮有判定组指出：基线从未被要求输出可求值命题，所以用这类判据测它，测的是**输出格式**不是**能力**。

⭐ **这个意见是对的，而且本轮把它变成了论点本身**：本判定**不主张**基线能力差，⭐ 只主张**两臂的产出形态携带的信息量不同**——而下游（自动重放、回归防护、修复）消费的正是那些信息。⛔ 所以请照判据判，⛔ 不要因为「这对基线不公平」而放宽；⭐ 但若你有新的、上一轮没提过的公平性意见，**照样写出来**。

## 五、输出格式

```json
{
  "judged_by": "<组号>",
  "positions": {
    "EIS-9999-99|run1/9999-gpt": {
      "ready_strict": true,
      "ready_lenient": true,
      "predicate_clear": true,
      "binding_complete": true,
      "expected_value_given": true,
      "single_direction": true,
      "assertion_sketch": "edge_target(PowerOff) == HumanDrivingMode  // 期望值来自发现原文",
      "note": "可选"
    },
    "EIS-9999-98|run2/9999-claude": {
      "ready_strict": false,
      "ready_lenient": false,
      "predicate_clear": true,
      "binding_complete": true,
      "expected_value_given": false,
      "single_direction": true,
      "failing_requirement": "expected_value_given",
      "quote": "「缺少从 AutonomousMode 返回的路径」",
      "missing_decision": "返回到哪个状态、由什么事件触发——发现里没有，写断言的人必须自己决定"
    }
  }
}
```

| 字段 | 要求 |
| :-- | :-- |
| `ready_strict` / `ready_lenient` | ⭐ 两个都必填（见纪律 4） |
| 四个要件的布尔值 | 逐条给，便于按要件拆分统计 |
| `assertion_sketch` | ⭐ `ready_strict=true` 时必填。⚠️ **只许用发现原文里出现过的信息**，⛔ 你自己补的任何决定都说明它其实不就绪 |
| `failing_requirement` + `quote` + `missing_decision` | ⭐ `ready_strict=false` 时必填。⚠️ `missing_decision` 要具体写出「写断言的人必须自己决定什么」 |

⛔ **位数必须齐**，分工消息会告诉你应有多少条。
