# Track A raw-first proposal: baseline pairs 0000-0019

This is an independent proposal layer for the X1v2 baseline non-K
re-review. It is not a pane5 final adjudication and must not be used as the
published decision set without the required independent review and arbitration.

The canonical artifact is
[`track_a_0000_0019.json`](./track_a_0000_0019.json). Its `reports` array
preserves the exact raw `issue`, `where`, `reason`, and `basis` fields, the raw
JSON pointer and SHA-256, the complete archived NL and PlantUML hashes, and a
dense relation list containing every expected ledger ID. Each relation digest
is SHA-256 over the canonical JSON list of `{expected_id, relation}` values.

The companion
[`track_a_0000_0019.manifest.json`](./track_a_0000_0019.manifest.json) records
all unique input file hashes, the proposal hash, builder hash, scope, and the
provider-free recomputation command.

The raw-only scope evidence is preserved in
[`raw_scope_probe_0000_0019.json`](./raw_scope_probe_0000_0019.json). It scans
the 162 baseline raw records without opening proposals or decision artifacts;
it records the 512 raw findings, the 155 requested-range candidates, the empty
classification-field set, absent raw `basis` fields, and raw/path pair-ID
metadata mismatches.

## Blind boundary

The builder reads only the v3 inventory, baseline raw method records, the
archive-relative `reference/x1v2_input_closure` NL/PlantUML files, and
`reference/ledger.json`. It does not read the frozen v2 decision layer, old
labels, Track B, other reviewer conclusions, or call a provider, method, or
Judge pipeline. The semantic annotations are explicit proposal entries in the
builder; relation values are not inferred from keyword or string similarity.

Process disclosure: after the proposal had been materialized, a broad parent-
session search exposed text snippets from a review directory. Those snippets
were not used to create, regenerate, or validate this proposal, but the event
means this session cannot be presented as proof of zero process-level exposure;
a later final adjudication must retain this disclosure.

## Coverage and evidence gap

The machine-readable scope gate is `OPEN_EVIDENCE_GAP`. This is a provider-free
raw-first proposal artifact, not a final decision layer.

The raw finding objects contain `issue`, `where`, and `reason`, but no `basis`
field. Every one of the 155 retained rows therefore records
`raw_basis_field_absent_in_record`; the proposal's raw `basis` value is `null`,
rather than an invented basis.

The JSON is intentionally conservative about scope membership. The allowed
raw/source inputs do not encode which reports belonged to the frozen pre-v3 K
set. Filtering the pair-range candidate universe would therefore require
reading a forbidden old-label artifact. The proposal retains every raw report
in the requested pair range so a possible non-K report is not silently lost.
This is recorded in `scope.missing_evidence` and is not a claim that every
retained candidate was pre-v3 non-K. It must be resolved by a permitted,
independently documented scope manifest before these proposals enter final
233-row adjudication.

## Recompute

From the repository root:

```bash
python3 project_1_llm_state_machine_modeling/paper_stm_issue_discover/scripts/evaluation/build_track_a_baseline_ni_proposal.py \
  --archive-root project_1_llm_state_machine_modeling/paper_stm_issue_discover/final_results/v60_current_vs_x1v2_baseline \
  --inventory project_1_llm_state_machine_modeling/paper_stm_issue_discover/final_results/v60_current_vs_x1v2_baseline/derived/manual_adjudication_v3_baseline_ni/inventory.json \
  --output project_1_llm_state_machine_modeling/paper_stm_issue_discover/final_results/v60_current_vs_x1v2_baseline/derived/manual_adjudication_v3_baseline_ni/proposals/track_a_0000_0019.json
```

The command rewrites the JSON and its manifest deterministically apart from
the generated timestamp. The validator must verify the report IDs, raw text,
source hashes, exact 145-ID closure, and every relation digest before any
downstream merge.

The provider-free validator is
[`validate_track_a_0000_0019_proposal.py`](../../../../../scripts/evaluation/validate_track_a_0000_0019_proposal.py).
Its result is required to be `PASS`; it does not read legacy labels or reviewer
conclusions.
