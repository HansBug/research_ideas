## 历史 raw-audit 结果

旧 raw-finding 口径下，方法整体 hit@1 为 226/435（51.95%），X1v2 为 154/435（35.40%），方法 hit@3 为 91/145（62.76%），baseline 为 68/145（46.90%），方法三轮全中为 59/145（40.69%），baseline 为 35/145（24.14%）。这些数仅用于解释旧报告如何形成，不能解读为最终效果。

旧 raw-finding 口径下，方法在 L2 上 hit@1 为 82/117（70.09%），baseline 为 22/117（18.80%）；在 D2×L2 上为 73/102（71.57%），baseline 为 19/102（18.63%）。由于大量支持命中的 finding 最终是 D0，这些差值不能证明 release-only 方法领先。

旧 judge 接收了 953 条 raw finding，其中 566 条 ledger-unmatched；这不是方法的最终 emission 分母，因为它包含 D0、未聚类 facet 和语义重复。严格 release-only 的诊断回放约为 276 个 D1/D2 clusters、121 个 ledger-unmatched、precision 约 56.16%，但该回放仍受旧 judge 与失败 pair 影响，只能用于 v27 诊断，正式数字必须重判。

## Finding 质量与 W/D/L

方法内部共记录 W2 562 条、W1 529 条、W0 5 条；D2 326 条、D1 32 条、D0 713 条，另有 25 条 D 未知（来自失败或不完整记录）；L2 399 条、L1 178 条、L0 519 条。accepted 为 292 条，confirmed 为 179 条；这些都是过程与审计分布，不是最终 release issue 数。最终 release issue 只取 D1/D2 `report_issue_clusters`，accepted、confirmed 和 raw finding 均不得替代该分母。

W2 的最低证据合同是：对应 EvidenceGoal 已被编译，断言或专用 formal program 在确切 FCSTM 上真实运行，产生 terminal counterexample，并保存 artifact hash、assertion/program hash、后端观察、终值和 source-causality receipt。没有真实运行证据的 finding 只能是 W1 或 W0；W2 不由模型口头声称产生。

D 分级由独立 D judge 产生，D2/D1/D0 及理由、最强 defeater、grounding 和必要的 typed domain obligation 都随 finding 保存。D0 不能从审计记录中删除，但必须从最终发布、hit、FP 和 precision 中截住；D1/D2 且只有 W1/W0 的问题仍作为兜底发布并明确证据缺口。

## 失败与重试

方法 162 格中，7 格是 local execution timeout，2 格是 mixed failure，2 格是 schema-invalid；这些均为非 provider 错误，已经原样落盘并计入使用成本，不进行静默重试或把它们改记为 provider failure。独立 judge 最终有 49 个 pair 成功、5 个 pair 失败；失败 pair 为 0010、0029、0032、0047、0055，失败原因分别保留在 raw judge JSON 中，因此这些 pair 的覆盖位置按 0 处理。v5 对困难 pair 的成功结果 0022、0025、0053 已纳入本报告；v5 的 provider 504 retry 只在 typed provider/transport failure 上免计前序 attempt，其他 schema、输出结构、内部或本地错误均计费。
