## 最终 release-only 结果

Sol semantic judge 下，方法整体 hit@1 为 136/435（31.26%），X1v2 为 179/435（41.15%）；方法 hit@3 为 70/145（48.28%），X1v2 为 80/145（55.17%）；方法三轮全中为 19/145（13.10%），X1v2 为 40/145（27.59%）。因此当前 v26 release-only 结果不能声称整体超过 X1v2。

方法在 L2 上 hit@1 为 37/117（31.62%），X1v2 为 26/117（22.22%）；在 D2×L2 上为 29/102（28.43%），X1v2 为 21/102（20.59%）。L2 与 D2×L2 领先，但不足以弥补整体 release-only 缺口。

最终 release emission 中，方法 305 条、ledger-unmatched 135 条、precision 170/305（55.74%）；X1v2 512 条、ledger-unmatched 327 条、precision 185/512（36.13%）。D0、未聚类 facet 与内部诊断均未进入这些分母。

## Finding 质量与 W/D/L

方法内部共记录 W2 562 条、W1 529 条、W0 5 条；D2 326 条、D1 32 条、D0 713 条，另有 25 条 D 未知（来自失败或不完整记录）；L2 399 条、L1 178 条、L0 519 条。accepted 为 292 条，confirmed 为 179 条；这些都是过程与审计分布，不是最终 release issue 数。最终 release issue 只取 D1/D2 `report_issue_clusters`，accepted、confirmed 和 raw finding 均不得替代该分母。

W2 的最低证据合同是：对应 EvidenceGoal 已被编译，断言或专用 formal program 在确切 FCSTM 上真实运行，产生 terminal counterexample，并保存 artifact hash、assertion/program hash、后端观察、终值和 source-causality receipt。没有真实运行证据的 finding 只能是 W1 或 W0；W2 不由模型口头声称产生。

D 分级由独立 D judge 产生，D2/D1/D0 及理由、最强 defeater、grounding 和必要的 typed domain obligation 都随 finding 保存。D0 不能从审计记录中删除，但必须从最终发布、hit、FP 和 precision 中截住；D1/D2 且只有 W1/W0 的问题仍作为兜底发布并明确证据缺口。

## 失败与重试

方法 162 格中，7 格是 local execution timeout，2 格是 mixed failure，2 格是 schema-invalid；这些均为非 provider 错误，已经原样落盘并计入 method 使用成本。Sol judge 最初缺失的 `0009`、`0013`、`0056` 全部是 provider/upstream failure；修复 relay 错误分类后，失败请求在同一 judge 进程内原地退避重发，前序 provider attempt 免计费，最终成功 attempt 正常计费，现已完成 54/54 pair。非 provider 的 pair-wide shape failure 会转入逐个 ledger-emission 关系的原子 LLM judge，不允许以全 miss 或不可判结果补洞。
