# gpt-5.6-luna 全量 x3 对照实验报告（v26-dnorm）

本报告记录 paper1 新方法 v26-dnorm 与 X1v2 baseline 在同一 gpt-5.6-luna profile、同一第二版台账、同一 54 个 eligible pair（排除 NL04 的 6 个 pair）、每个 pair 每臂三轮上的对照结果。这里的 hit 与 false positive 由独立语义 judge 依据“同一位置、同一性质”判定，不使用关键词、substring、编辑距离、embedding 或其他文本捷径；judge 失败格保守记为未命中。

## 结论

方法整体 hit@1 为 226/435（51.95%），X1v2 为 154/435（35.40%），绝对提高 16.55 个百分点；方法 hit@3 为 91/145（62.76%），baseline 为 68/145（46.90%）；方法三轮全中为 59/145（40.69%），baseline 为 35/145（24.14%）。

方法在 L2 上 hit@1 为 82/117（70.09%），baseline 为 22/117（18.80%）；在 D2×L2 上为 73/102（71.57%），baseline 为 19/102（18.63%）。这说明提升不是只来自 D2×L2，整体、L2 和 D2×L2 三个口径均明显领先。

方法发出 953 条 finding，其中 566 条被判为 false positive，precision 为 387/953（40.61%）；baseline 发出 447 条，其中 269 条为 false positive，precision 为 178/447（39.82%）。方法绝对 precision 高 0.79 个百分点，false-positive rate 为 59.39%，baseline 为 60.18%；因此当前主要收益是覆盖率，误报率只小幅改善，不能把结果表述为已经解决 false positive。

## Finding 质量与 W/D/L

方法侧共记录 W2 562 条、W1 529 条、W0 5 条；D2 326 条、D1 32 条、D0 713 条，另有 25 条 D 未知（来自失败或不完整记录）；L2 399 条、L1 178 条、L0 519 条。accepted 为 292 条，confirmed 为 179 条；confirmed 是 accepted 的严格子集，要求同时满足 D2、W2 和安全源归因，不能把 accepted 数直接当作 confirmed 数。

W2 的最低证据合同是：对应 EvidenceGoal 已被编译，断言或专用 formal program 在确切 FCSTM 上真实运行，产生 terminal counterexample，并保存 artifact hash、assertion/program hash、后端观察、终值和 source-causality receipt。没有真实运行证据的 finding 只能是 W1 或 W0；W2 不由模型口头声称产生。

D 分级由独立 D judge 产生，D2/D1/D0 及理由、最强 defeater、grounding 和必要的 typed domain obligation 都随 finding 保存。D2×L2 的提升不能替代整体 coverage，也不能把 D0 结果从统计中删除；高 D 但 W1/W0 的问题仍作为兜底发布并明确证据缺口。

## 失败与重试

方法 162 格中，7 格是 local execution timeout，2 格是 mixed failure，2 格是 schema-invalid；这些均为非 provider 错误，已经原样落盘并计入使用成本，不进行静默重试或把它们改记为 provider failure。独立 judge 最终有 49 个 pair 成功、5 个 pair 失败；失败 pair 为 0010、0029、0032、0047、0055，失败原因分别保留在 raw judge JSON 中，因此这些 pair 的覆盖位置按 0 处理。v5 对困难 pair 的成功结果 0022、0025、0053 已纳入本报告；v5 的 provider 504 retry 只在 typed provider/transport failure 上免计前序 attempt，其他 schema、输出结构、内部或本地错误均计费。

## 审计边界与可复现入口

完整结构化指标、逐条台账表和 judge 状态见本报告同名子目录；raw 运行目录在本机 `runs/paper1/luna-full-x3-20260819-v1/`，其中保留 method、baseline、judge-v3/v4/v5、失败 receipt、逐次 usage、attempt 和 SHA-256 审计索引。聚合脚本与 judge 脚本分别见 [aggregate.py](../pipeline/witness_search_prototype/experiments/luna_full_x3_20260819/aggregate.py) 与 [semantic_judge.py](../pipeline/witness_search_prototype/experiments/luna_full_x3_20260819/semantic_judge.py)。

本轮结果支持的论文表述是“在同一 gpt-5.6-luna、同一第二版台账和本次 54-pair 口径下，typed obligation + executable witness 方法显著超过 X1v2，尤其改善 L2”；不能表述为跨模型、跨台账或所有状态机上的普遍保证。当前主要短板是 false positive 仍高、D0 数量较大、5 个 judge pair 失败以及 concurrency/fork/join/region 表达面仍有限，这些应进入 limitation 和后续消融，而不是从结果中隐藏。
