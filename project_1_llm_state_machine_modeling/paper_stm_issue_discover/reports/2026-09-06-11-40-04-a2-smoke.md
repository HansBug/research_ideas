## 4. 空流与 schema 修订

5 个调用以 `No generations found in stream` 失败：`0004` 的一路 grounding 和 D，`0009` 的契约和双路 grounding。失败记录没有首个 generation、响应 ID 或可用 usage，原始 SSE 事件不在该审计层中。能证明的是 LangChain 未收到可形成 generation 的流；现有记录不能唯一判定是服务空流、网络中断还是适配器忽略了上游事件。[clm-transport]

本地调用链核对发现，LangChain 的 `generate_from_stream()` 在无 generation 时抛普通 `ValueError`；`utils.agent.runtime._retryable_transport_error()` 不将此错误识别为 transient transport，外层异常又因配置了响应 schema 而标记 `structured_output_invalid`。因此虽然配置 `transport_retries=8`，上述五次都只有一次尝试、没有 transport retry 记录；不能将它们写成“八次重试耗尽”或“Pydantic schema 不兼容”。本次未改变共享 runtime，也未冷启动重跑任何 smoke 格。[clm-transport]

另外有 3 项真实 schema 修订，分别发生于 `0004/0024/0034`，均通过同一次节点调用的定向反馈修正后保留完整结果。例如 `0004` 曾使用 `reachability + dead_end` 不允许的枚举组合。该类结构错误与上述五次空流分开统计。[clm-schema]
