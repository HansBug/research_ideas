## 3. 远程启动与 tunnel

以下是原启动脚本的完整关键配置，可在指定远程 tmux 工作区作为一个 Bash 脚本执行；参数为 `qwen38` 或 `muse`。Muse 的生产实现继续保留在 [utils/llm/serving_muse.py](../../../../utils/llm/serving_muse.py)，先将该文件传到授权共享根，不能只复制参数而遗漏 adapter。官方配方与偏差说明见[初始部署调查](./2026-09-06-11-53-00-serving-evidence.md)。[clm-env]

```bash
#!/usr/bin/env bash
set -euo pipefail
E1_ROOT=${E1_SHARED_ROOT:?Set the authorized remote shared root}
E1_LAUNCH=(-m sglang.launch_server)
case "${1:?qwen38 or muse}" in
  qwen38)
    E1_PREFIX="$E1_ROOT/conda-envs/e1-qwen38-27b"
    E1_SNAPSHOT="$E1_ROOT/hf/hub/models--Qwen--Qwen3.8-27B/snapshots/1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0"
    E1_ARGS=(--served-model-name qwen3.8-27b --context-length 1000000 --reasoning-parser qwen3 --tool-call-parser qwen3_coder
      --default-chat-template-kwargs '{"reasoning_effort":"low"}'
      --json-model-override-args '{"text_config":{"rope_parameters":{"mrope_interleaved":true,"mrope_section":[11,11,10],"rope_type":"yarn","rope_theta":10000000,"partial_rotary_factor":0.25,"factor":4.0,"original_max_position_embeddings":262144}}}')
    export SGLANG_ALLOW_OVERWRITE_LONGER_CONTEXT_LEN=1
    ;;
  muse)
    E1_PREFIX="$E1_ROOT/conda-envs/e1-muse30b"
    E1_SNAPSHOT="$E1_ROOT/hf/hub/models--meta-models--Muse-Glimmer-30B/snapshots/a4e59da52a7bc87ae7251dd5545c0dd437c44b68"
    E1_ARGS=(--served-model-name muse-glimmer-30b --context-length 131072 --reasoning-parser muse --tool-call-parser muse)
    E1_LAUNCH=("$E1_ROOT/serving_muse.py")
    test -f "${E1_LAUNCH[0]}"
    ;;
  *) exit 2 ;;
esac
test -d "$E1_PREFIX/conda-meta"
test -f "$E1_SNAPSHOT/config.json"
test -z "$(nvidia-smi -i 4,5,6,7 --query-compute-apps=pid --format=csv,noheader,nounits)" || { echo 'GPU occupied'; exit 3; }

export PATH="$E1_PREFIX/bin:$CUDA_HOME/bin:/usr/bin:/bin"
export LD_LIBRARY_PATH="$CUDA_HOME/lib64:$CUDA_HOME/lib:$E1_PREFIX/lib"
export HF_HOME="$E1_ROOT/hf" HF_HUB_OFFLINE=1
export XDG_CACHE_HOME="$E1_ROOT/cache" TMPDIR="$E1_ROOT/tmp"
export SGLANG_CACHE_DIR="$E1_ROOT/cache/$1-sglang"
export CUDA_CACHE_PATH="$E1_ROOT/cache/$1-cuda"
mkdir -p "$TMPDIR" "$SGLANG_CACHE_DIR" "$CUDA_CACHE_PATH"
cd "$E1_ROOT"
exec "$E1_PREFIX/bin/python" "${E1_LAUNCH[@]}" --model-path "$E1_SNAPSHOT" \
  --host 127.0.0.1 --port 8100 --tp-size 4 --mem-fraction-static 0.92 \
  --max-running-requests 64 "${E1_ARGS[@]}"
```

## 4. 本地 profile 与真实工作流

凭据只在权限 600、Git ignored 的根 `.llmconfig.yml`，不使用 `.env`。完整字段形状见[配置样例](../../../../.llmconfig.example.yml)。四款最终配置在总报告 §2，Luna/Sonnet 输出为 128,000；两开放模型显式 `output_budget_mode: remaining_context`。后者省略请求 cap 是经 SGLang 调度器源码及真实调用核验的模式，不是依赖未知默认值。保持完整输入，不能将整个 context 当成非空输入之外的额外输出额度。[clm-runtime]

以下 method 共用 runtime 探针仅验证 required function tool，使用原有合成 pump 任务。它不修改真实 method 的 prompt 或 schema。保留 outcome、逐调用 audit、raw usage/finish 和异常，不能仅判断 `succeeded`。[clm-runtime]

```python
import json
from pathlib import Path
from pydantic import BaseModel, ConfigDict
from utils.structured_runtime import PublicStructuredRuntime

class PumpIssue(BaseModel):
    model_config = ConfigDict(extra="forbid")
    issue: str
    source_transition: str
    missing_guard: str
    counterexample: list[str]

out = Path("runs/e1-new-runtime-probe")  # new local directory
out.mkdir(parents=True, exist_ok=False)
runtime = PublicStructuredRuntime("gpt-5.6-luna", out, transport_retries=0, streaming=True)
try:
    result = runtime.call(
        kind="adapter-smoke", schema=PumpIssue,
        system_prompt="Identify only concrete requirement violations.",
        prompt="Requirements: a pump may start only when the safety interlock is closed. "
               "It must stop when an emergency event occurs. Source transitions: "
               "Idle --> Running : start; Running --> Idle : emergency. "
               "Identify the concrete issue and a counterexample. Do not invent extra requirements.",
        artifact_id="runtime-tool", retry_cell_on_provider_error=False,
    )  # no run output override; budget comes from the verified profile
    (out / "outcome.json").write_text(json.dumps(result.to_dict(), indent=2) + "\n")
finally:
    runtime.close()
```

普通 factory 可用 `create_chat_model(load_llm_registry().require(profile), streaming=True, max_retries=0)`；baseline 使用此入口。Luna 普通/baseline 省略 reasoning，method 显式 none；Sonnet provider default，Qwen low、Muse high，均不得用 AA max/xhigh 分数替代当前档位。structured runtime 首字节/read idle 300s、单请求 600s、零 transport retries 的阶段/外层为 3630/3660s；baseline 原测试 wire 的 timeout 为 null，E2 须分别冻结。[clm-runtime]

## 5. 请求与结果的核心校验

以下离线片段接受一个**已另行取得的本地 Responses 请求与解码后 SSE**，不依赖某个 ZIP 或 run ID。使用已安装 SDK 的 SSE decoder，保留 failed/incomplete，核对实际序列化上限，不以审计名义值推断 HTTP 参数。HTTP headers/响应状态与压缩格式必须另保留；gzip 原字节先按真实 Content-Encoding 解压后解析。[clm-check]

```python
import hashlib
import json
from pathlib import Path
from openai._streaming import SSEDecoder

request_path = Path("/path/to/local/request.body")
response_path = Path("/path/to/local/decoded-response.body")
request = json.loads(request_path.read_bytes())
assert request["stream"] is True
assert request["model"] == "gpt-5.6-luna"
assert request["max_output_tokens"] == 128000
events = [e.json() for e in SSEDecoder().iter_bytes(iter([response_path.read_bytes()]))
          if e.data != "[DONE]"]
terminals = [e for e in events if e.get("type") in
             {"response.completed", "response.failed", "response.incomplete", "error"}]
assert terminals, "empty stream or early EOF is not completed"
for event in terminals:
    response = event.get("response", {})
    print(event["type"], response.get("model"), response.get("usage"),
          response.get("error"), response.get("incomplete_details"))
print(hashlib.sha256(request_path.read_bytes()).hexdigest())
```

对 method 每格核对 prepare、contract_extraction、contract_completion、discovery_grounding、execute_batch、d_adjudication、validate_d、publish，以及内部每个 LLM stage 的 result/audit。核对 `errors`、`audit_errors`、schema 修正与 provider 重试、降级解释和 eligibility，按 `model_call_id` 去重 usage。reasoning 已包含在 output/completion，不再次相加；缺失 usage 记缺失。Sonnet 的证据义务降级和 Muse 的旧六轮结构耗尽必须分类，不因顶层 eligible 相同而合并。[clm-check]

并发复验核心是 `ThreadPoolExecutor(max_workers=16)` 对固定完整合成请求运行 32 次，使用 SDK 的 streaming/tool parser，保存每次原始事件、HTTP 状态、首 SSE/首有效 chunk、chunk 间隔、终态和 usage；两次 warmup 与计时 batch 分开。按最终 profile 发请求，开放模型无 cap 字段，required `PumpIssue` function/tool、stream usage 开启，推理/采样与表中一致。必须解析参数并核对 task 内容；schema-valid 占位符不能算内容通过。真实方法不使用这个合成 schema。[clm-check]

```python
import json
import math
from pathlib import Path

rows = [json.loads(line) for line in Path("/path/to/local/requests.jsonl").read_text().splitlines()]
rows = [r for r in rows if not r.get("warmup") and r.get("concurrency") == 16]
assert len(rows) == 32
assert all(r["status"] == "completed" and r.get("done_received") and
           r.get("schema_valid") and not r.get("placeholder_present") and
           r.get("finish_reason") == "tool_calls" and r.get("usage") for r in rows)
latencies = sorted(r["seconds"] for r in rows)
print({"requests": len(rows), "p95_seconds": latencies[math.ceil(.95 * len(rows)) - 1]})
# Batch wall time must come from the measured batch start/end, not sum(latencies).
```

16K 输入须用**对应模型的远程 tokenizer/chat template 或 provider usage**复核，不能拿 tiktoken 估计代替。容量测试另以并发 1、每长度两次，实际输入至少达到官方窗口约 0.9：Qwen 原生目标 235,929、扩展 900,000；Muse 117,964 tokens。保持完整输入和可完成输出；模板与工具开销另记录，不裁剪任务。记录实际计数、finish、tool/schema、截断、服务器窗口和 KV 配置。此负载证明已测试容量，不能证明长距离理解、持续 SLA、16 个完整 method 或 16 个最大窗口同时驻留。[clm-check]
