### A2. ref 翻转率实验 ⭐ 零人工判定

**要回答什么**：把为 pair X 生成的整套断言，拿去在**同一份 NL 的参考模型**上重新求值。
在错误模型上为 False 的断言，应当在参考模型上翻成 True。三个指标：

| 指标 | 定义 | 它证明什么 |
| :-- | :-- | :-- |
| **翻转率** | `False@buggy` 中在 ref 上变 True 的比例 | 判别效力 |
| **残留 False** | 在 ref 上仍为 False | 要么断言写错，要么参考模型也有该问题 |
| **参考侧误报** | ref 上 False 但 buggy 上 True | 断言方向搞反 |

**为什么值得做**：判定方法学里记着一条改判——`EIS-0029-05` 从 2/6 改判为 **0/6**，
理由是产出断的那条「在**参考模型上同样为 False**，无法区分合规与不合规」
（见 [../discover_matrix/docs/protocol/verdict_methodology.md](../discover_matrix/docs/protocol/verdict_methodology.md)
「全人工也不行，而且已经出过错」一节）。
**那一轮全人工扫了 132 个位、只逮到这 1 例；ref 翻转率能把这项检查自动化到全部断言上。**
它同时也是 §6.2 那条「不具判别力的谓词」问题的通用检测器：
`variable_declared` 在任何模型上都为真，ref 翻转率会把它整批打出来。

**⚠️ 原先登记的风险已实测，结论是：参考模型不是阻塞。**

以下为本次核实结果，不是转述：

| 事实 | 实测 |
| :-- | :-- |
| 参考模型在不在仓库里 | **在**。`Experiment Results.xlsx / STM Results` 第 **D 列**（表头 `PlantUML`），60/60 行非空；`Dataset.xlsx / Dataset` 也有同一份，按 model name 键入 |
| 每个 pair 能否定位到它 | **能**。每个 pair 的 `source_meta.json` 里 `source_cells.reference_plantuml` 直接给出单元格（如 `D2`） |
| 完整性能否校验 | **能**。`pairs.jsonl` 每行带 `reference_plantuml_sha256` |
| 有几份不同的参考模型 | 原始 sha 有 **11** 个，但其中 `0009` 与同 NL 的另 5 个只差**空白字符**，规范化后**恰好 10 份**（每 NL 一份），扣掉越界的那份 NL 后**在用 9 份** |

**因此真正未测的只剩一件事：这 9 份参考模型能不能过 PlantUML → DSL 编译链。**
参考模型是**人写**的，写法分布与 LLM 生成的 54 份不同，编译失败率未知；
且 v46 §7.5 已证明这条编译链有损（表示债务 46.5%），
**参考侧的编译损失会直接污染翻转率**——ref 上残留的 False 可能只是编译损失，不是断言写错。

**大致成本**：小。参考模型已在本地，断言已在 v46 产物里（生成 8793 条、支撑已发布 issue 的 1555 条）。
需要的是一次**纯求值**运行（不调 LLM）+ 一个编译成功率预检。**零人工判定**。

**依赖**：编译链（`../pipeline/representation/`）；v46 的逐格断言产物。

### A3. 命中形态的构成

**要回答什么**：命中判据认可**四种等价形态**——直接对应、合取项之一、负向命题的正向对偶、
**蕴含更根本的原因**。最后一档最宽。355 个命中位按四形态拆开各多少？
**若相当比例靠最宽那一档，这个数的性质就变了。**

判据里写了「按哪种形态判的」，但**是自由文本**，需回读归类。

**大致成本**：中。568 条判据的回读与归类，一人一天量级；可先用脚本按关键词粗分再人工校。
⚠️ 按〈用户记忆〉「机械代理只能定位不能裁定」——**脚本只许定位，最终归类必须人读原文**。

**依赖**：`../discover_matrix/manual_review/`；判据文本格式。

### A7. 响应性 / 持续性义务的人工普查

**要回答什么**：有界模型检查这一族在 v46 里几乎没有读数——台账侧只引用 4 次，
`response_within` 在 324 格中**零生成**。三个候选原因**指向相反的行动**：

1. 建模边界不含不变式（$M$ 无 `Inv`），所以 `invariant` 最自然的用法出界；
2. 语料确实少这类义务；
3. **生成侧从未识别这类句式**。

**判别方法 v46 已写死**：人工通读这 9 份需求文本，找出全部「响应性 / 持续性」义务，
再看它们在台账侧与产出侧各被表达了多少。

**为什么现在做不了**：没做。

**大致成本**：小到中。9 份 NL 的逐句人工标注。

**依赖**：无。

⛔ **在这件事做完之前，论文不得主张有界模型检查在本任务上必要，

## 3. B 组：需要新运行

### B1. 朴素基线 ⭐ v46 §9 列为第一项

**要回答什么**：同样两个执行模型、同样 54 个 pair，**不走这 8 阶段循环，一个提示直接让它列出
不符之处**，在这 98 条台账记录上是多少？**没有这个数，60.4% 没有参照系。**

**为什么现在做不了**：还没做。

**⚠️ 成本的真正大头不是算力，是判定。** v46 报告把它记为「一次小规模运行」，
这对**算力**是对的（324 次单提示调用 vs v46 的 3621 次多阶段调用），
但基线产出同样需要**一整轮 588 位的命中判定**，而 v46 那一轮判定
（568 位带逐位判据 + 288 簇五类裁定）是本项目最贵的人工投入。

三条可能的减负路径，**下一轮必须先选定一条并写进事前登记**：

| 路径 | 做法 | 代价 |
| :-- | :-- | :-- |
| 全量判定 | 基线也判 588 位 | 与 v46 判定同量级 |
| 缩网格 | 基线只跑 1 轮或子集 pair | 失去 `@k` 三口径；且子集选法本身要防「按问题最明显挑」的偏差 |
| 分层复用 | 走 `verdict_tiers.py` 的 A/B/C 三层，只对 C 层人工 | 需先验证三层在基线产出上的适用性——基线产出**形态不同**（自由文本，无断言），A/B 层可能整体失效 |

⚠️ 无论走哪条，**基线与主方法的判定必须同口径、同判定者、且横向对齐**——
按〈用户记忆〉「判定层是独立误差源」，同形态判出两种结果是单向低估的来源。
`../discover_matrix/adjudication_recheck.py` 已实现「同形态判出两种结果须为 0 对」的检查。

**依赖**：判定口径不变；一份基线 prompt（**必须与主方法同等用心地写**——
故意写差的基线是稻草人，审稿人会看出来）。

### B2. 循环各阶段的消融

### 5.2 ⚠️ T1 / T2 两层实验设计与 v46 现状冲突，需要重想

**原设计**（v35 时期提出，动机是省成本）：把「吃人工判定的」与「不吃的」分开，
让广度长在不吃判定的那一层。

| 层 | 范围 | 格数 | 指标 | 人工判定 |
| :-- | :-- | --: | :-- | :-- |
| T1 广度 | 全部 54 pair，1 模型 × 1 轮 | 54 | 断言数、需求覆盖率、ref 翻转率、残留 False、scope gate 触发分布 | **零** |
| T2 深度 | 18 pair，3 模型 × 3 轮 | 162 | `hit@1/@3/@all`、按层、按谓词、`over@k` | 有 |

理由：54 = 9 NL × 6 生成器，两维度含义不同。**9 份 NL** 承载「对需求的泛化」，
**6 个生成器** 承载「对缺陷分布的泛化」；对需求锚定的方法，第一维重要得多。
所以砍的时候**保 NL 广度、采样生成器**。

**⛔ 冲突：v46 已经跑完 324 格全量了。** 于是：

- **T1 的动机（省判定）已经失效**——54 格是 324 格的子集，全量已有。
  T1 若还有意义，只能是**换个指标口径**（ref 翻转率等零判定指标），而不是换个网格规模。
- **T2 的形态必须重想**——18 pair × 3 模型 × 3 轮 = 162 格，比已有的 324 格**更小**。
  拿它当「深度层」是倒退。
- 真正需要 T1/T2 分层的场景，是**下一轮引入新变量之后**（新模型、新阶段配置、消融臂），
  此时全量重跑的代价才重新出现。

### 5.4 表示债务 46.5% 的归属，需要导师裁定

它**既不是被评审模型的缺陷，也不是方法的误报**，而是工具链的损失。三种处置各有后果：

1. 从多报侧分母中扣除——但那等于把工具链缺陷藏起来，且扣除后 precision 会显著虚高；
2. 计入误报——但会低估方法在**作者原文**层面的准确性；
3. **单独成类报告**（v46 的做法）——代价是读者必须理解中间表示的存在。

⚠️ 这个数字**不宜外推**（一条链、一个语料、一个检测器）。论文里应当主张的是**审查动作**
——评审入口若是中间表示，就必须做这项扣除——不是这个具体数字。

**这一项不需要新实验，需要一次裁定。** 裁定结果会影响 C2b 的优先级。

### 5.5 fork/join 表示能力边界：零新增实验的四层写法

导师点名要的 finding，**不需要任何新运行**，材料 v46 已全部具备：

1. **量化边界**：10 份 NL 中 1 份有 11 处并发 + 17 处计时提及，另 8 份 0/0，
   第 9 份 0 并发 / 3 计时 → 真实语料约 **11% 的需求族落在 $M$ 表示能力之外**。
2. **最有意思的一条**：不排除它会发生什么——`0018` 的 `hit@1` = 12/18 = **66.7%**，
   **高于当时全量均值**。把超出表示能力的需求族放进来，方法**不会表现差，
   它会在错的东西上得高分**：可表达的部分照常命中计分，并发义务从未形成、分母里根本没有它们。
   → **表达力边界如果不显式声明，评测会系统性高估方法覆盖面，且高估方向与直觉相反。**
3. **机制**：与 `wellformedness` 那条同源——义务只能从「元模型可表达」与「NL 可绑定」的**交集**里长出来。
4. **设计含义**：这类方法必须**显式声明并强制**表示能力边界，而不是事后发现。

**落点**：把 scope gate 作为**方法的组成部分**呈现，而不是实验的免责声明——
从「我们排除了打不过的样本」变成「我们提供了一个**可先验判定的边界机制**，
并量化了真实语料落在边界外的比例」。

⚠️ 但**不得反过来说「这些模型没有并发问题」**：上游论文记录的最大一类语义问题恰恰是缺正交区（18 条）。
