## 1. 定位与问题

R5.7.1 要解决的问题是：论文如何从 `<NL, STM_0>`、修复目标、候选 `STM_k` 和评价证据，走到“方法有效”的可审计主张链。当前阶段仍不运行 repair loop、不调用真实 LLM、不生成 `STM_k`、不报告 Better STM 成功率 [src-status][clm-no-effectiveness-yet]。

R5.7.1 的核心产物是 [../experiment_design/evaluation_logic.md](../experiment_design/evaluation_logic.md)。它把 GitHub PR #139 中 Q1--Q8 的讨论决策沉淀为长期实验设计纪律：claim 类型、分母纪律、A 层硬准入、conversion / repair gain 归因、客观指标位置、failure / partial / unknown / out-of-scope 报告和 R5.7.2--R5.7.5 接口 [src-eval-logic][clm-q1-q8-frozen]。

## 2. 核心结论

| 结论 | 当前写法 | 证据 |
|---|---|---|
| R5.7.1 只支持评价逻辑链和协议类主张 | 当前可写 task / scope、readiness、protocol / evaluation 与 limitation claim；repair effectiveness 必须等待 R6/R7/R8。 | [clm-no-effectiveness-yet] |
| `llms-emp` 分母必须双层报告 | 10 NL clusters × 6 LLM-generated `STM_0` = 60 pairs；cluster-level 是需求覆盖，pair-level 是 artifact repair attempt。 | [clm-denominator] |
| T0 是 scope 上限，不是成功分母 | T0 = 8 clusters / 48 pairs 只是 headline main 的 pre-eligibility 上限；T0.5/T1 进入 caveat / stress。 | [clm-t0-scope] |
| A 层是 artifact-level gate | A-pass 只说明可评价，不说明更好；A-fail 入 failure/readiness/limitation ledger，不进 Better STM 主统计。 | [clm-a-gate] |
| conversion readiness 不计 repair gain | raw -> canonical 的 PlantUML recovery、normalization、`.fcstm` inspect success 只能算 readiness；repair gain 从 canonical `STM_0 -> STM_k` 开始。 | [clm-no-repair-gain] |
| 客观指标只能 supporting evidence | parse ok、inspect ok、F1、场景通过率、diagnostics fewer、文本相似度或 token cost 都不能单独判 Better STM。 | [clm-metric-boundary] |
| 非成功状态必须入台账 | failure、partial、unknown、out-of-scope 不能静默删除；partial 是 caveat candidate，不等于失败。 | [clm-failure-ledger] |

## 3. Q1--Q8 决策摘要

| 议题 | 决策摘要 | 后续落点 |
|---|---|---|
| Q1 | A 层是单个状态机制品的可评价性门槛，不是数据源纳入门槛。 | R5.7.2 A 层；R7 eligibility。 |
| Q2 | claim 分五层：task/scope、readiness、protocol/evaluation、repair effectiveness、limitation/negative evidence。 | story claim 降级；R7/R8 写作。 |
| Q3 | `llms-emp` 采用 10 NL clusters × 6 LLM outputs 的嵌套样本结构。 | R5.7.3 指标分层；R7/R8 主结果表。 |
| Q4 | T0 主线、T0.5 tick/counter caveat、T1 supplementary stress 分开。 | scope / taxonomy / 主表附表。 |
| Q5 | raw -> canonical 不计 repair gain；canonical `STM_0 -> STM_k` 才可能计 repair gain。 | R6 change ledger；R8 归因。 |
| Q6 | objective metrics 只能 supporting evidence；Better STM 必须语义裁决。 | R5.7.3 objective metrics。 |
| Q7 | failure / partial / unknown / out-of-scope 全部入 ledger。 | R7/R8 failure / limitation 表。 |
| Q8 | R5.7.1 不越界；R5.7.2--R5.7.5 分别负责判定细则、指标、dry-run 和 handoff。 | staged PR 边界。 |

完整决策表见 [../experiment_design/evaluation_logic.md](../experiment_design/evaluation_logic.md) §10 [src-eval-logic][clm-q1-q8-frozen]。

## 4. 学术风险与禁止主张

1. 不得把 `16 converted / 44 partial / 0 blocked`、60/60 canonical / parse / inspect ok 写成 repair success；这些只支持 readiness [clm-current-status][clm-no-repair-gain]。
2. 不得把 T0.5 tick / counter caveat 写成 timed automata 支持；不得把 Digital Camera / T1 stress 写进 T0 主结果 [clm-t0-scope]。
3. 不得把 objective metric-only improvement 写成 Better STM；所有 Better STM 结论必须回到 `NL`、`STM_0`、`STM_k` 与 change ledger [clm-metric-boundary]。
4. 不得隐藏 failure、partial、unknown 或 out-of-scope；这些是论文 limitation 与方法边界的一部分 [clm-failure-ledger]。
5. 不得把 R5.7.1 写成方法效果已验证；真实 repair effectiveness 仍需 R6/R7/R8 [clm-no-effectiveness-yet]。
