# CONTINGENCY_L1.md — L1 轨（技术版图与对照系）五问的梯次配置方案

> **这份文件是什么**：L1 轨的五个必答问题（伞 PR [#179](https://github.com/HansBug/research_ideas/pull/179) §4.5 Q1–Q5），每一问都可能调研回来是好结果、中结果或坏结果。本文件在**调研开跑之前**把每一档长什么样、怎么确认落在这一档、落在这一档之后 story 与 contribution 各要怎么改、以及该档下的禁语，全部预先写死。
>
> **为什么要预先写**：档位是在看到结果**之后**才知道落在哪一档的，但「这一档该怎么办」若也等到看见结果之后再定，就无法区分「按预案处置」与「按结果调措辞」。⛔ 本文件的全部价值来自它写在结果之前，与代码同批 push（口径同根 [CLAUDE.md](../../../CLAUDE.md) §3.5.1「开跑实验前必须先 push」的事前登记纪律）。
>
> ⛔ **本文件不是 GUIDE。** L1 的执行规则（编制、分片、可接受结论形态、不可接受清单）唯一真源是 PR #179 §4，本文件不重述、不覆盖、不改写它，只对「回来之后」预置处置。另写一份 GUIDE 等于建第二真源（#179 §4.4 明令）。
>
> ⛔ **本文件不预设结论。** 每一档都标了先验概率（高 / 中 / 低），那只是排产用的粗估，⛔ **不构成任何一档已经成立的判断**，⛔ 也不授权提前按某一档改 story。改 story 的唯一触发条件是该档的「判据」栏被实际满足。
>
> **配套件**：L2 轨的同类方案在 `CONTINGENCY_L2.md`（另一路在写，本文件不涉及其内容）。L1 的实际产出物落点见 #179 §4.4：`related_work/landscape/`。

## 0.1 五档共用的约定

### 0.1.1 边界门在梯次里怎么用

建模对象是 $M = (S, E, V, Tr, A)$，⛔ 无时钟 $C$、无不变式 $Inv$、无正交区并发（#179 §4.0.2）。这条门约束的是**出处与对照**，因此在本文件里落成三条可执行判据：

1. **界内**：所引段落讲的对象是 FSM / HSM / EFSM 或其上的性质、迁移、事件消费、层次结构。→ 可作对照，可作出处。
2. **界外**：时间自动机（UPPAAL 系全部）、混成自动机、Petri 网、进程代数、正交区并发语义。→ ⛔ 既不作对照也不作出处。
3. **邻域**（本文件新增的一个**待裁定**类别）：对象既非 $M$ 也非上述界外形式主义，而是**另一种制品**——RTL / SVA、源代码、需求文本。它们的**方法形状**可能与本文高度相似（受限词表、形式化反馈回路），但制品不同。⚠️ #179 §4.0.2 字面只区分界内 / 界外，未处置邻域；本文件在 Q4 的 B 档里显式把「邻域可否作为 Related Work 定位段」升级为待裁定项，⛔ 在裁定之前，邻域一律**不作出处、不作 `60.4%` 的参照**。

⚠️ **同一篇论文可以部分可用**（#179 §4.0.2）：判据是「我们引的那一段」，不是整篇归属。所以每一档的行动里凡涉及界外系文献，都必须落到具体章节。

### 0.1.2 全档通用禁语（任何一档都不许说）

| ⛔ 禁语 | 为什么 |
| :-- | :-- |
| 「我们做了系统性综述 / 系统性映射研究」「据我们所知不存在 X」 | 本轮是 20–30 篇重点调查（#179 §4.2 #8）。只能写「在本轮覆盖的 CCF A/B/C 与 arXiv 近年工作中未见 X」并附覆盖范围 |
| 「我们优于 / 提升 / 相比之下更好」 | 没跑过对照实验（#179 §4.2 #7；[claim_evidence_map.md](../story/claim_evidence_map.md) C18 强度为 `无证据-占位`） |
| 不带 $\le$ 的 `60.4%` | [claim_evidence_map.md](../story/claim_evidence_map.md) §3 明文禁止；正文一律写 $\mathrm{hit@1} \le 355/588 = 60.4\%$，且三口径同报、与算力代价同报 |
| 「首个 / 首次」（任何一档） | 强度档由 R1 定，且四档上限是「首个」/「据我们所知未见」/「与既有工作不同」/「工程改进」（#179 §4.3）。本文件的任何一档都⛔ 不授权直接写「首个」 |
| 「我们调查了 N 篇文献归纳出词表」 | [paper_story.md](../story/paper_story.md) §13 已列为禁语（报锚定关系比报数量有说服力） |
| 以「改分母 / 改门 / 重跑」作为任何一档的行动 | ⛔ 588 冻结（#179 §7） |
| 把 `grep -li 'LLM' state_machine_types/*/desc.md` 的 296 命中当检索结果 | 抽查全部是我方在「对本研究的启发」里写的推测（#179 §4.5 Q5） |

### 0.1.3 story 锚点的稳定性声明

本文件对 [paper_story.md](../story/paper_story.md) 的每一处定位都写成 **§号 + 逐字片段**（#179 §9 第 4 条，⛔ 不用行号）。锚点取自 S1 冻结时刻的 `paper_story.md`；若 S1 之后 §号发生位移，以**逐字片段**为准重新定位，⛔ 不得因为 §号对不上就跳过该处修改。

## 1. Q1 · STM / 模型上的缺陷发现，技术路线分几类，各自做到哪一步

**候选类目**（#179 §4.5 Q1 给的起点，⛔ 不是答案）：① 模型检查（LTL / CTL / BMC）② 一致性与 conformance testing ③ 静态规约检查（OCL / well-formedness）④ 仿真与执行 ⑤ LLM 辅助评审 / 缺陷检测 ⑥ 变形 / 差分测试。

### A 档 · 版图清晰（先验：中）

| 字段 | 内容 |
| :-- | :-- |
| **情况** | 六个候选类目中 ≥5 类各自凑齐 **≥3 篇界内、读过正文、可具名**的代表作，包含最薄的类目 ⑤ |
| **判据** | 可数：逐类列出篇数，每篇在 `landscape/SUMMARY.md` 索引表的「正文读了没」列为是；每类能写出一句「它与 C-① 的差别在哪」 |
| **对 story 的影响** | §10「Related Work 定位」的四条轴按实际类目重排（当前四条轴与六类目**不同构**，A 档下必须选定一套并说明映射）；§4 的 G1/G2/G3 表每一栏点名该类的具名代表作，去掉稻草人风险 |
| **对 contribution 的影响** | C-① 强度上限可到「与既有工作不同」；⛔ 仍不得到「首个」——版图清晰恰恰意味着邻居多。C-②③ 不受影响 |
| **该档下的行动** | 每类出一张三列小表（输入 / 输出形态 / 需要什么前提），并逐类补一行「有没有把『什么算一条缺陷』定义清楚」——⭐ 这一列是 C-① 差异化的真正落点，比技术分类本身更有用 |
| **⛔ 该档下不能说什么** | ⛔ 不得因为版图齐整就写「本文覆盖了全部六类」；⛔ 不得把「我们同时用了结构 / 仿真 / BMC 三族」写成「我们统一了三条技术路线」——三族是求值机制，不是别人的技术路线 |

### B 档 · 主干成立、边缘类目证据不足（先验：高）

| 字段 | 内容 |
| :-- | :-- |
| **情况** | 4–5 类满 3 篇；1–2 类（最可能是 ⑤ 与 ⑥）只有 1–2 篇界内代表作 |
| **判据** | 同上可数；⚠️ 额外判据：对每个不足 3 篇的类，必须能回答「为什么不能并入相邻类」——答不上来说明是类边界划错了，应转 D 档处理 |
| **对 story 的影响** | §10 第 3 条轴「**LLM 辅助的缺陷检测 / 评审 / 规约生成**：与本文最近」需在括注里如实写「本轮覆盖内仅 N 篇」；§4 的 gap 表中由不足类支撑的那一栏，措辞从「既有工作 A/B/C 均无 X」降为「本轮覆盖内的该类工作未见 X」 |
| **对 contribution 的影响** | C-① 强度上限「与既有工作不同」；⚠️ 若不足的恰是类目 ⑤，则 C-① 与 C-③ 的**近邻风险未被排除**，两条的强度都只能挂在「本轮覆盖内」这一限定上 |
| **该档下的行动** | 按 §4.2 #1 逐条标注「仅 N 篇支撑」+ 写明不能并类的理由；把不足的类目列入 C3（覆盖）challenge 的必查项，要求它专门再跑一个 venue 族 |
| **⛔ 该档下不能说什么** | ⛔ 不得为凑够 3 篇而合并类目或挪动类边界——那种失真在成品上看不出来（#179 §4.2 #1 的原话）；⛔ 不得把「我们只找到 2 篇」写成「这一类工作很少」 |

### C 档 · 分类撑不住（先验：低）

| 字段 | 内容 |
| :-- | :-- |
| **情况** | ≤3 类满 3 篇；候选类目中有多个在**状态机类制品**上几乎不存在（例如 ⑥ 变形 / 差分测试） |
| **判据** | 可数；且对每个空类，检索过程可复现（关键词簇 / 入口 / 时间窗 / 命中数 / 筛除理由齐备） |
| **对 story 的影响** | §10 四条轴改为「按证据强度分层」：主干若干条 + 一节「本轮覆盖内证据不足以独立成类的方向」，逐条附检索过程；§4 的 gap 表**不再逐类点名**，改为按「三者不可兼得」（§4 `TODO-S2` 已给出的候选收窄措辞：「**需求侧锚定 + 可机械求值 + 可重放**，三者不可兼得」）组织，每一栏点名的是**能力组合**而不是技术类目 |
| **对 contribution 的影响** | C-① 强度落到「与既有工作不同」的下沿，且必须显式声明比较面是能力组合而非技术类目 |
| **该档下的行动** | 交付一份「版图 + 空白区」双栏图：有工作的区域给具名代表作，空白区给可复现检索过程。⭐ 空白区本身对 §4 的 motivation 有正面价值——它是 gap 存在的证据，不是调研失败 |
| **⛔ 该档下不能说什么** | ⛔ 不得把空白区写成「该领域无人做过」；⛔ 不得把「我们没找到」当成「不存在」（#179 §4.2 #8）；⛔ 不得因为类目少就抬高 C-① 的强度 |

### D 档 · 横切档：分类轴选错（先验：中，可与 A/B/C 任一并存）

| 字段 | 内容 |
| :-- | :-- |
| **情况** | 读到一定量之后发现，既有工作更自然地按「**判据从哪来**」（人写性质 / 从需求推出 / 从元模型推出 / 从参考实现推出）分，而不是按「用什么技术」分 |
| **判据** | 出现下述任一：同一篇论文同时落进 ≥3 个候选类目；某两类的成员集合重合度 > 50%；某类内部的成员在「需要什么前提」这一列上分裂成互不相干的两组 |
| **对 story 的影响** | §10 的轴整体改写；⭐ §4 的三条 gap（G1 判据不可复算 / G2 缺少定位与归因 / G3 无法回归）与新轴天然同构——G1 正是「判据从哪来」的下游后果，改轴反而让 §4 与 §10 首次对齐 |
| **对 contribution 的影响** | 对 C-① 是**利好**：按新轴，「判据来自需求的逐条义务」本身就是一个可辨认的位置，比「我们也做模型检查」有力得多。C-② 因此获得一条额外的定位论据 |
| **该档下的行动** | ⭐ 换轴，并在 `landscape/SUMMARY.md` 里同时保留旧轴的映射表（读者会按技术类目找工作）；⛔ 换轴必须在层 3 综合之前决定，不得在层 4 challenge 之后回头改 |
| **⛔ 该档下不能说什么** | ⛔ 不得把换轴写成「我们提出了一种新的文献分类法」——那是 survey 的贡献，本文不是 survey（#179 §4.2 #8）；⛔ 不得两套轴并列陈列让读者自己挑 |

## 2. Q2 · 有没有人做「NL 需求 ↔ 模型」的一致性检查

⭐ 离本文最近的一类，contribution ① 差异化的主战场。**要分清生成（NL→模型）与检查（给定 NL + 模型，判模型是否满足）**——⛔ 前者不算。

### A 档 · 检查侧确有其人（先验：低）

| 字段 | 内容 |
| :-- | :-- |
| **情况** | ≥3 篇界内工作做的是「输入 = NL + 一份**已存在**的模型，输出 = 该模型在哪些需求点上不符」，且**逐条可追溯到需求条目** |
| **判据** | 逐篇回答三问：输入里有没有一份别人给的模型（不是它自己生成的）？输出锚不锚在需求条目上（不是锚在性质公式上）？能不能逐条回放？三问全「是」才计入 |
| **对 story 的影响** | §4 `TODO-S2` 的收窄形状**直接被这一档决定**：三者不可兼得的表里，这些工作会占掉一整栏，必须逐篇写清它们缺哪一项；§10 需新增一条轴（当前四条轴里没有「需求↔模型一致性检查」这一条，只有末段那条尚未纳入的「**NL → 形式化规约**」，两者不是一回事，⛔ 不得合并） |
| **对 contribution 的影响** | ⚠️ C-① 与 C-③ 同时降档：C-① 上限压到「与既有工作不同」，C-③ 的差异化必须从「有没有证据链」改成「证据链的**锚点**与**可求值性**不同」。C-② 不直接受影响（它的承重在 L2） |
| **该档下的行动** | 对每篇做一张四列表：输入形态 / 义务提取是人工还是自动 / 判据锚在哪 / 可否重放。⭐ 重点查「义务提取」那一列——本文的 §5.3「**覆盖性来自构造，不来自运气**」若在这一列上与他人相同，差异化就必须整体移到别处 |
| **⛔ 该档下不能说什么** | ⛔ 不得把他人的工作说成「不做一致性检查」；⛔ 不得因为他们用的不是 LLM 就判定不可比——可比性由任务与输入输出形态决定，不由实现手段决定 |

### B 档 · 存在功能等价的两段式路线（先验：高）

| 字段 | 内容 |
| :-- | :-- |
| **情况** | 找到的不是「直接判 NL↔模型」，而是**两段式**：先把 NL 需求形式化成性质 / 结构化需求（LTL、NuSMV 模块、Behavior Tree 等），再对模型做模型检查。它**在功能上覆盖了同一件事**，但义务提取是人工或半自动，判据锚在性质公式上 |
| **判据** | 该类工作满足：输入含 NL；中间产物是一组形式化性质或结构化需求；最终判定由模型检查器 / 求解器给出。⚠️ 判别关键是「谁决定要检查哪些性质」——若是人写的，就落 B 档而不是 A 档 |
| **对 story 的影响** | ⭐ §4 `TODO-S2` 的候选收窄「**需求侧锚定 + 可机械求值 + 可重放**，三者不可兼得」在这一档下**必须重写第一栏**：两段式路线是「可机械求值 + 可重放 + 半锚定」，比 `TODO-S2` 里写的「反例轨迹……**不锚在需求条目上**（它锚在性质公式上，而性质从哪来仍是人工）」更强，因为它确实经过了需求。原措辞会被审稿人一句话反驳，必须改成「锚定的粒度与自动化程度」之别 |
| **对 contribution 的影响** | C-① 强度上限「与既有工作不同」；C-② 获得一条**正面**论据——两段式的瓶颈正是「性质从哪来」，而闭合词表回答的就是这个问题，⚠️ 但这条论据的力量取决于 L2 能否把词表的由来挂住，⛔ 不得在 L1 单独兑现 |
| **该档下的行动** | 建一张「两段式 vs 本文」的对照表，列：谁决定检查什么 / 需求条目到判据是否一一对应 / 未能形式化的需求怎么处理。⭐ 最后一列是本文的强项（覆盖缺口显式记录，见 §5.1 第 3 点「**它让测不了的东西显式暴露**」），务必查清他人怎么处理 |
| **⛔ 该档下不能说什么** | ⛔ 不得说两段式「不锚在需求上」——它锚，只是粒度粗；⛔ 不得说「他们需要人工写性质所以不自动」而不给出原文定位（#179 §4.2 #2 要求每条差异化各给一句原文定位）；⛔ 不得把两段式与纯生成侧工作混在同一栏 |

### C 档 · 检查侧空集（先验：低）

#### ⭐ C 档下「空集式交付」长什么样

一份 1–2 页的**参照系检索报告**（落点 `landscape/SUMMARY.md` 的一节，⛔ 不单开文件），含五块：

1. **四条门的操作化定义**：每条门写成一个可对着论文打勾的判据，附「什么情况算中、什么情况不算」的边界例。
2. **检索矩阵**：venue 族 × 关键词簇 × 年份窗 × 命中数，逐格填数。⛔ 空格必须标明是「没跑」还是「跑了 0 命中」，两者含义完全不同。
3. **逐条筛除记录**：把最像的前 N 个候选（建议 N ≥ 8）各写一句「它满足①②③④中的哪几条、缺哪一条」。⭐ 这一块是整份报告的重心——它证明我们**看过最接近的东西**，而不是没查到。
4. **结论句的受限形式**：「在本轮覆盖的 CCF A/B/C 与 arXiv 近年工作中，未见同时满足四条门的工作」+ 覆盖范围声明（venue 族、年份窗、检索入口）。⛔ 不得省略后半句。
5. **升级记录**：明写「是否跑朴素基线」已升级为 §6 导师议题，附我方倾向与理由。

#### ⭐ 为什么 C 档不是失败

1. **它是一个可复现的否定结果。** §9 第 2 条现在是一句自陈（「本文只报绝对量」）；C 档把它变成有检索证据支撑的陈述。审稿人问「你们查过没有」时，前者答不上来，后者有一张矩阵。
2. **它把导师议题从工程偏好变成被证据逼出来的必要动作。** #179 §6 要导师拍板「是否跑朴素基线」，而该 TODO 自陈成本是「一整轮 588 位判定，本项目最贵的人工投入」。⛔ 花这个成本需要理由，「我们查遍了近年 CCF A/B/C 与 arXiv 也没有可比对象」就是那个理由——⭐ C 档**产出的正是这个理由**。
3. **空集式本来就是三种可接受形态之一**（#179 §4.2 #3）。⛔ 把它读成「这一档就没办法了」是对合同的误读：不可接受的是「未找到但检索过程不可复现」（§4.2 #5），不是「未找到」。

## 8. 判断：最可能崩的一问

⭐ **Q4（断言 / 契约 / 可执行规约）**，理由三条，按分量排序：

1. **它的失败模式是「界内空、界外满」，而这一种最难处理。** Q3 若空，交付形态是清楚的（空集式报告，见 §3），且空集本身对导师议题有正面价值。Q4 不同：外检索大概率**会找到大量形状极像的工作**（受限词表 + 形式化反馈回路 + LLM），⛔ 但它们的对象是 RTL / 源代码，按 #179 §4.0.2 落在门外。于是执行者面临一个**两难**——写进去违反边界门，不写则 §14 会缺一行本该有的审稿风险（「这不就是把那套搬到状态机上吗」）。⛔ 两难本身在成品上看不出来：交出来的东西可能干干净净，缺的那一栏没人会注意。§4-B 档的「分两栏 + 升级待裁定」就是为这个准备的。

2. **起点池对它的贡献恰好为零，而其余四问都有起点池托底。** 复核见 §7：`baselines/` 0 / 91、`sources/` 0 / 787、`state_machine_types/` 8 / 679 里界内可用上限 ≤ 6 且全是 contract automata，Dwyer 一系全仓 0 个目录。⛔ 这意味着 Q4 的全部篇数都要靠 §4.1 层 1′ 的定向补近年产出，而层 1′ 是**并行三到五路里最慢的一环**（要下 PDF、提正文、做 bibtex）。在周三一天的窗口里，Q4 是唯一一个**没有免费捞的部分**的问题。

3. **它单独承载 contribution ② 的对照面，而 C-② 的根基同时压在 L2 上。** 若 Q4 落 C 档、L2 的 `predicate_provenance.md` 又挂不满，C-② 会同时**缺对照**与**缺根基**。⚠️ 这个组合的危险在于两轨各自看都只是「这一项弱一点」，合起来才是「这条 contribution 站不住」——⛔ 而两轨是并行的，谁都不会看见对方的弱项。§4-C 档因此明写了「⛔ 两轨的结论不得互相传染」与「必须在 R1 如实报告这个组合」。

**次高风险是 Q2**，但它的失败模式温和得多：Q2 最可能落 B 档（找到功能等价的两段式路线），后果是 §4 `TODO-S2` 的收窄措辞必须重写一栏——那是一次**可预期、可局部完成**的改写，⛔ 不威胁任何一条 contribution 的形状。

⛔ **Q3 不是最可能崩的一问**，尽管它最可能落在最差档：因为 Q3 的最差档**事前已经被定义成一种可接受的交付形态**（#179 §4.2 #3 + §2.5 Fallback「L1 参照系问题到 T+6h 无果 → 立即按空集式交付」）。⭐ 一个已经准备好接住的失败，不是风险；没人准备接的那个才是。
