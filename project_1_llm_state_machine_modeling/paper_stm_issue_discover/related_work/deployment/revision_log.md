## 4. 两条工程教训

1. **大文件单次写入会 stall。** 两个 subagent 连续在写盘时因 API stall 挂掉（调研全部完成），改为**分块小写（每块 ≤100 行）+ 换目标文件**后通过。判据：失败发生在「Now I'll write the file」之后——**不是能力问题，是单次输出体积问题**。
2. **`unwrap_markdown --check` 与 `CLAUDE.md` §2.2.2 冲突。** 后者要求独立公式用**单独成行**的 `$$`，前者判其需处理——**已有两份现存文档因此 FAIL**（`CLAUDE.md` 自己 pass 只因其 `$$` 写在代码围栏里当示例）。本 PR 改用行内公式绕开，未动仓库工具；**建议在仓库层面裁一次**。

### 5.1 第四次同类越界

用户 2026-08-13 再次纠正：**4×H200 只是「我们能做实验的规模上限」**——「更大的模型我也没法做了，仅此而已，**不是一定要顶着最强的上**，至于到时候选择什么，根据情况而定」。

而我把核验任务写成了「**487 GB 内最强开源模型是谁**」，把**可行域**问成了**该选谁**。§0b.1 已改为可行域表述。

**这是同一个动作的第四次**（前三次见 §5 末）：拿一个有限用途的事实去当承重结构或决策依据。⭐ **而本轮数据自己就否掉了「顶着最强上」**：总分最高的那几个在**幻觉净分**上灾难性（GLM-5.2 +4.4 vs Opus +37.1，比值 0.119；总分第 2 的 V4-Flash 是 **−14.3**，符号相反），而该项权重是 AA-LCR 的两倍、且直接对应本方法的核心失败模式。

### 5.2 第 24 条：比率跨了不同分母

我据 [open_weights_2025.md](./open_weights_2025.md) 的「AA v4.1.1 的 38 个条目里仅 12 个是实测、26 个是估计值」，在候选模型表上加了「须逐条回查、未查明前不得当实测引用」的警报。

⛔ **那个警报是错的。** 那 38 条是**该文件自己那张 2025 世代表**的统计，与候选表**几乎不重叠**（前者集中在 DeepSeek V3.x / Nemotron / 旧 MiniMax 等较早模型）。**不同分母，推不出候选表也有估计值。**

回查结论：候选表的 **27 条总分 + 27 个分维度值全部是 AA 实测，0 条估计值**（布尔位 `intelligence_index_is_estimated = false` 且 9 项成分齐全）。

⚠️ **这与仓库已记的「比率只能跨同类分母比」是同一个错**。判据很简单：**看到一个比率就先问它的分母是什么集合**，两个比率并列前先确认分母同类。


## 6. 表述权限的一处更正：调研结论不是禁令

**用户 2026-08-13 指出**：「不要否定那么狠，不要变成硬规矩，而是作为一个潜在的风险点标记下来」。

我此前把调研发现写成了「**禁止清单**」（`SUMMARY.md` §5 与 talk §8 各一份，共十余条 `⛔ 不得写`）。**那有两个问题**：

1. **超出权限。** 本轮只做调研，无权规定正文怎么写——那是 R1 与作者的事。
2. **把可带条件写的东西一刀切掉了。** 例如「工业单位没有算力基础设施」这条，反证是**一条**官方级材料（浪潮一体机官方页）+ **一处**对象错配；那足以构成**风险**，但不足以证明该句**不可写**——一个限定到具体组织层级、并预答一体机反例的写法是站得住的。

**已改为分两层的风险清单**：**事实层**（与措辞无关、写了就是错的：不存在的对象 · 改变语义的错引 · 混比 AA 版本 · 引 TB 分数不写脚手架）保持明确；**风险层**（可以写但有具体反证）逐条给出「**风险来自哪**」与「**若要写建议配什么条件**」。

⭐ 并顺带把一条判定从「已否」改回「**待测**」：「开源模型 + 本方法 ≈ SOTA」此前被我写在禁止清单里，**但它的四条反证都是间接的**（≤32B 幻觉净分 · 同档第三方 Δ · Konstantinou · 我方前沿负增益），⛔ **没有一条是在「开源模型 + 本方法」这个组合上直接测过的**——故正确状态是**待 N1b 数据**，不是已否。
