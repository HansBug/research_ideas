# N1a · 私域部署动机：五问总账

## 0. ⭐⭐⭐ 一句话结论

⛔⛔ **导师那一版的 story（⛔ 私域部署 → 必须小模型 → 打平 SOTA）在证据上不成立**，⛔ 三处断裂且互相加剧。⭐⭐ **但本轮找到了一个能被足够文献佐证、且更硬的替代切入角度**——⭐ 它由**三条互不相干的调研路径独立收敛**得到，⛔ 且免疫于杀死原版的那三刀。

## 2. ⛔ 为什么原版 story 不成立：三处断裂

⭐ 把它拆成三段：**P1** 某些场景不能用公有云 → **P2** 所以必须用小模型 → **P3** 所以我们的方法有价值。⛔ **只有 P1 有一手依据，⛔ 而论文卖的是 P3。**

### 2.1 ⛔ P1 本身只成立到一半，⛔ 且「必须私域」被证伪

⭐ 可立的是 **(a) 不能用未获授权的商用端点**（⭐ 五条独立路径）。⛔ **不可立**的是 **(c) 必须私域部署**，⛔ 四条反证：

| # | 反证 |
| :-: | :-- |
| **1** | ⛔ **DoD 自己**在 GenAI.mil 上跑 Gemini / Grok / ChatGPT 处理 CUI（IL5）；⛔ Azure OpenAI 已获 DISA **IL6（SECRET）**授权 |
| **2** | ⛔ Anthropic 官方逐字：「ITAR data **can** be processed in Claude via AWS Bedrock」 |
| **3** | ⛔ OpenAI `API Platform` 2026-01-09 已取得 **FedRAMP 20x Class C**——⛔ 连「商用端点一律不合规」都不成立 |
| **4** | ⛔⛔ **反直觉致命反例**：涉密制品放在**企业普通私有服务器**上，⛔ 仍然是「非涉密信息系统」，⛔ 照样违反《保密法》第三十一条(三)。⭐⭐ **也就是说：在唯一能闭环的那个法域里，⛔ 私域部署本身同样不合规**——⛔ 合规解是**涉密信息系统**，⛔ 那不是「本地跑一个 Qwen」 |

### 2.2 ⛔⛔ P1 → P2 是纯逻辑跳跃，⛔ 且加固 P1 会削弱 P2

⭐ 本地部署也能跑**大**模型；⛔ 要论证「必须**小**」，⛔ 得再加一个「单卡 / 无 GPU 集群」的前提。⛔⛔ **而 P1 里守得住的场景全是国防科工、军工资质单位、汽车 OEM——⭐ 恰恰是最不缺 GPU 预算的那一类主体。** ⛔ **动机越硬，「必须小」越站不住。**

### 2.3 ⛔ 守住 P1 的代价，⛔ 反噬我们自己的实验

⭐ 剩下最硬的四条依据**全在中国法域**，⛔ 而中国法域是唯一与「用 Qwen」不冲突的那一支：⛔ ITAR §126.1 Table 1 把 China 列为 policy of denial、⛔ EAR Country Group D:5 同样含 China——⛔ **用中国来源模型服务 ITAR 场景自相矛盾**。⛔⛔ 再加一刀：⭐ 我们的语料是 **BSN / CARA / Elevator** 这些公开西方数据集，⛔ **每一条都可以合法送进公有云**。

### 2.4 ⛔ P2 → P3 一个数都没有

⛔ 属 N1b，⛔ 硬依赖 M1。⚠️ 且已知同向证据全指向反面：⛔ 主臂 −15.82pp · ⛔ Stroebl 不可能性定理 · ⛔ 「裸能力差距 89 题 > 任何脚手架差距 35 题」。

## 3. ⭐⭐⭐ 推荐的切入角度：⭐ 三条独立路径收敛

⭐⭐ 本轮最重要的产出：⭐ **三路互不相干的调研，⛔ 各自出于完全不同的理由，⭐ 收敛到同一个替代动机。**

| 路径 | 它独立发现了什么 |
| :-- | :-- |
| ⭐ **MDE/RE venue 直翻** | ⭐⭐ 该社区**并非不用开源小模型**（⭐ 至少 3 篇用了，⭐ 含本地 Ollama 与 Qwen-14B），⛔ **但给出的理由是 transparency / reproducibility / accessibility，⛔ 不是保密** |
| ⭐ **法规族** | ⭐ 查完 9 本标准 + 5 族法规后**主动建议**：⭐ 把动机从法规改挂到**可复现性**（⭐ hosted API 有 provider drift，⭐ 需版本冻结与离线复现） |
| ⭐ **反方族** | ⭐ ICSE'26 Angermeir：⛔ **85 篇 0 篇完全复现**，⭐ **唯一 LLM 特异的失败因素就是模型弃用**，⭐ 且**逐字推荐开源模型作缓解** |

### 3.1 ⭐ 主动机：可复现性 / 透明性 / 可及性

⭐⭐ **这是我们投稿目标社区已经接受的标准答案**，⛔ 不是新造。⭐ 它免疫于杀死原版的全部三刀：⛔ 「可是 Azure OpenAI 有 IL6」**打不到它**（⭐ 复现性与合规无关）· ⛔ 「守得住的场景不缺 GPU」**打不到它**（⭐ 复现性与预算无关）· ⛔ 「你的语料本来就能上公有云」**打不到它**（⭐ 复现性与数据敏感度无关）。

⚠️ ⛔ **但要注意这是一个已被占据的位置，⛔ 不是空白。** ⭐ 好处是审稿人默认接受；⛔ 代价是它**不构成新颖性**——⛔ 只能当**方法选择的正当理由**，⛔ 不能当 contribution。

### 3.2 ⭐⭐ 支撑主张：⭐ 多阶段脚手架的适用区间**本来就是**能力较弱的模型

⭐ 三条独立证据同向（⭐ 详见 [verification_log.md](./verification_log.md) §V2）：

1. ⭐⭐ **同制品的 crossover**：Abdulkarim et al.（McGill，2026-03）做 NL → 状态机生成，⭐ Claude 3.5 Sonnet 上**单提示 0.7029 打败全部三个多阶段框架**（0.3052 / 0.5026 / 0.6336），⛔ GPT-4o 上**多阶段反超**（0.6559 vs 0.5431）。⭐ 作者逐字：多阶段「**may interfere with the inherent step-by-step reasoning process of reasoning LLMs**」。
2. ⭐ **Huang / Stroebl 与它不矛盾，⭐ 因为是两类不同干预**：⛔ **自我批判**（让模型判断自己对不对）⛔ 对弱模型更差；⭐ **多阶段分解**（给子任务脚手架）⭐ 对弱模型更好。
3. ⭐ **我们自己的数据**：⛔ 自我批判那部分吃掉 **79% token 而净收益 ≈ 0**。

⭐⭐⭐ **合起来的预测**：⛔ 砍掉自我批判环、⭐ 保留分解脚手架、⭐ 换到弱模型上跑——⭐ 那正是文献预测本方法生效的区间。⭐ 与 M1 已确立的设计原则一**同向**。

⭐⭐ **这才真正做到「避开和 SOTA 拼数值」**：⛔ 不是回避，⭐ 而是**对照组本来就该换**——⭐ 主张若是「这类干预在弱模型上生效」，⭐ 正确的对照就是**小模型裸跑 vs 小模型 + 我们的方法**，⭐ SOTA 只是背景刻度。

### 3.3 ⭐ 私域部署的正确位置：⛔ 降为顺带的应用价值，⛔ 不承重

⭐ 这与 Q3 的实测一致：⛔ **19 篇里没有一篇的实证结论依赖保密动机**——⭐ 保密永远与成本、算力、版本稳定性捆成 3–4 条并列理由，⛔ 抽掉它数字一个都不变。

## 4. ⛔ 三条必须一起带走的限定

1. ⛔⛔ **「可断言可追溯」与「私域部署」之间没有因果连接。** ⭐ 这是**两个独立卖点拼在一起**，⛔ **绑得越紧越可疑**。⭐ 建议**别绑**：⭐ 让它们各自成立。
2. ⛔⛔ **在把 −15.82pp 归因于「多阶段干扰」之前，⛔ 必须先排除我们自己的契约门 / 致命门吃掉了正确产出。** ⭐ Abdulkarim 自陈「the strict post-processor module **may suppress valid LLM outputs**」——⭐ 那正是本仓库 `CLAUDE.md` §11 那条纪律的外部案例。⛔ **故其 crossover 方向可信、⛔ 幅度不可信。**
3. ⛔ **保密动机在 MODELS / RE / REFSQ / SoSyM / REJ 尚未成为惯用论证**——⛔ **3,740 条题录只有 2 篇写出这条因果**，⛔ 唯一读到全文的那篇还是装饰。⛔ **审稿人不会默认接受它。**
