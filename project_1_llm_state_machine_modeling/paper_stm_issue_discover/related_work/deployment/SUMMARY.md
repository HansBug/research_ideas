## 2. ⛔ 为什么原版 story 不成立：⭐ 三段各有独立反证

⭐ 拆成三段：**P1** 某些场景不能用公有云 → **P2** 所以必须用小模型 → **P3** 所以我们的方法有价值。

### 2.1 ⛔ P1 只成立到一半，⛔ 且「必须私域」有反证

⭐ 可立的是 **(a) 不能用未获授权的商用端点**。⛔ **不可立**的是 **(c) 必须私域部署**：

| # | 反证 | ⭐ 来源数 |
| :-: | :-- | :-: |
| **1** | ⛔ **DoD 自己**在 GenAI.mil 跑 Gemini / Grok / ChatGPT 处理 CUI（IL5）；⛔ Azure OpenAI 已获 DISA **IL6（SECRET）** | ⭐ 4 |
| **2** | ⛔ Anthropic 官方：「ITAR data **can** be processed in Claude via AWS Bedrock」 | ⚠️ **仅 1** |
| **3** | ⛔ OpenAI `API Platform` 2026-01-09 取得 **FedRAMP 20x Class C** | ⚠️ **仅 1**，⛔ 且分册自标 **S 级 / 待人工核验** |
| **4** | ⛔⛔ **反直觉致命反例**：涉密制品放**企业普通私有服务器**仍属「非涉密信息系统」，⛔ 照样违反《保密法》第三十一条(三)——⭐⭐ **在唯一能闭环的法域里，⛔ 私域部署本身同样不合规** | ⚠️ **仅 1**，⛔ 含一步我方推论 |

⚠️ ⛔ **反证 2 / 3 / 4 各只有一条来源**（⭐ C3 指出），⛔ 不满足伞 PR §4.2 #1 的三条线；⛔ 反证 3 不得写成事实句。

### 2.2 ⛔⛔ P1 → P2 是纯逻辑跳跃，⛔ 且加固 P1 会削弱 P2

⭐ 本地部署也能跑**大**模型；⛔ 要论证「必须**小**」，⛔ 得再加「单卡 / 无 GPU 集群」的前提。⛔⛔ **而 P1 里守得住的场景全是国防科工、军工资质单位、汽车 OEM——⛔ 恰恰最不缺 GPU 预算。** ⛔ **动机越硬，「必须小」越站不住。**

### 2.3 ⛔ 守住 P1 的代价，⛔ 反噬我们自己的实验

⭐ 最硬的四条依据**全在中国法域**，⛔ 而那是唯一与「用 Qwen」不冲突的一支：⛔ ITAR §126.1 Table 1 把 China 列为 policy of denial、⛔ EAR Country Group D:5 含 China。⛔⛔ 再加一刀：⭐ 我们的语料是 **BSN / CARA / Elevator** 等公开西方数据集，⛔ **每一条都可合法送进公有云**。

### 2.4 ⛔ P2 → P3 一个数都没有，⛔ 且已有反向实测

⛔ 属 N1b，⛔ 硬依赖 M1。⛔ 且**同一任务家族已有人比过并给出统计结论**，见 §4.1。

## 3. ⛔ Q1 / Q2 的证据要点（⭐ 附 C3 的修正）

### 3.1 ⭐ Q1 = 无，⚠️ **两处独立自陈排除 + 一处同源**

- **IEC 61508-1:2010 §1.2 m)**：「does not specify the requirements for … **security policies or security services**」

⭐ **DIA 误读排查**：先验正确且**方向相反**——ISO 26262-8 §5.2 NOTE 2 使该章对不担安全责任的供应商**整章不适用**。

⚠️ ⭐ **一条可复用的教训**：核验中**搜索引擎摘要凭空编造了并不存在的 DO-178C §7.2.7–7.2.10 结构**来迎合提问。⛔ DO / ISO / IEC 系条款号**一律不得采信搜索摘要**。

### 3.2 ⭐ Q2 最强单条

**DFARS 252.204-7012 (a)** 的 `Technical information` 定义逐字含 "specifications, standards… engineering data… data sets"，⭐ 即**需求文档与设计模型本身**；⭐ 配 **NIST SP 800-171 Rev 2 §3.1.20** DISCUSSION 逐字点名 "software as a service"。

## 4. ⛔⛔ Q4 的两张表：⭐ 它们反对我们的选型

### 4.1 ⛔⛔⛔ 同一任务家族已有人比过，⭐ 在我们的目标 venue，⛔ 用的还是 Qwen

**Chou, Aydemir, Dalpiaz**, *A Comparative Study of Large and Small Language Models for Domain Model Extraction*, ⭐ **REFSQ 2026**（⭐ 详见 [verification_log.md](./verification_log.md) §V3，⭐ 一手全文核过）：

⭐ 摘要逐字：「We compare **GPT-o1, Llama3-8B, and Qwen-14B** with the rule-based **Visual Narrator** … **GPT-o1 outperformed the smaller language models**」。⛔ 统计部分：⭐ GPT-o1 在 validity 上显著优于 Llama3-8B（$p = 0.0029$, **$d = 2.343$**）与 Qwen-14B（$p = 0.0056$, **$d = 1.929$**）——⛔ **$d \approx 2$ 是极大效应量**。

⛔ **我们若主张平价，⛔ 就是在直接反驳一篇 REFSQ 论文，⛔ 而目前拿不出证据。** ⛔ 必须在 Related Work 正面处理，⛔ 躲不掉。

⚠️ ⭐ **一处精度修正（⭐ 对我们略微有利）**：⛔ 它摘要里的「Qwen-14B」**不是基础 Qwen**——⭐ 正文 §3 与脚注 3 逐字为 **DeepSeek-R1-Distill-Qwen-14B**（⭐ 「a 14-billion-parameter **distilled** model from the Qwen series」，⭐ 附 HF 链接）。⛔ 那是 **R1 蒸馏的推理模型**，⛔ 与 `Qwen3.6-27B` 这类通用 dense 模型**不同谱系、且早约两代**。⭐ 故「⭐ 连 Qwen 都对上」这句**要收回**——⛔ 威胁的方向与效应量仍成立，⛔ 但**不是同一个被测对象**。

⭐⭐ **但同一组检验埋着一个反向支点**：⛔ GPT-o1 对 Visual Narrator **不显著**（$p = 0.3543$）——⭐⭐ **连 GPT-o1 都没能在统计上打赢一个十年前的规则式工具**。⭐ 这削弱**「裸覆盖率数字」这条轴本身**，⛔ 而那正是我们正在输的轴。

⭐ **一条界限**：⛔ 它比的是**裸跑 vs 裸跑**（⛔ 无方法层）。⭐ 我们要主张的是**小模型 + 方法 vs 小模型裸跑**——⭐ 那是它没做的比较。⛔ 故它**不证伪我们**，⛔ 但**钉死了基线**。

### 4.2 ⛔⛔⛔ 我们准备搬进去的那一格，⭐ 脚手架收益已经归零

⭐ VerIbmc（[arXiv:2606.16886](https://arxiv.org/abs/2606.16886)）逐模型消融（⭐ 详见 [small_model_papers.md](./small_model_papers.md) §4.6）：

| Model | Basic | LLM-Only | Δ |
| :-- | --: | --: | --: |
| Llama-3.1-8B | 342 | 307 | **+35** |
| Qwen2.5-7B | 352 | 328 | +24 |
| GPT-OSS-20B | 424 | 409 | +15 |
| ⛔⛔ **Qwen2.5-32B** | 382 | 380 | ⛔ **+2** |
| GPT-OSS-120B | 431 | 428 | +3 |

⛔⛔ **`route_selection_and_v47_plan.md` 推荐的 `Qwen3.6-27B` 正落在这一档。** ⚠️ ⛔ **衰减并不单调**（⭐ Qwen2.5-32B 是反转点，⭐ 能力低于 GPT-OSS-20B 而收益远小于它）——⛔ 但**两种读法对我们都不利**：⛔ 若是能力律则 30B 已过拐点，⛔ 若是 Qwen 特有效应则我们用的恰好是 Qwen。

⭐⭐ **同一篇给出必要条件**：⭐ 设方法在小模型上的增益为 $\Delta$、⭐ 小模型与 SOTA 的裸能力差为 $G$，⛔ 则 story 成立需 **$\Delta \gtrsim G$**。⛔ VerIbmc 上 $\Delta_{\max} \approx 35$ 而 $G \approx 89$——⛔ **它做不到，⭐ 所以它用了「承认落后 + 绑定约束」而非宣称打平。**

### 4.3 ⛔ 「脚手架适用于弱模型」⭐ 只是假设，⛔ 不是结论

⭐ 核心证据 Abdulkarim et al.（⭐ 同制品 crossover，⭐ [verification_log.md](./verification_log.md) §V2 / §V4.1）**有两重同向污染**：⛔ 作者自陈「strict post-processor **may suppress valid LLM outputs**」，⛔ 且**基线 3-shot vs 多阶段 2-shot**（⭐ 赢的一方多拿一个示例）。⛔ **故连方向都只能算提示性。**

⛔⛔ **且存在反向证据**：⭐ Konstantinou 等在 **GPT-4o-mini 这个弱模型**上，⭐ 朴素提示胜过四条带执行反馈的流水线——⛔ **直接与「脚手架帮弱模型」相反**（⭐ C3 指出本条此前被漏报，⛔ 属选择性报告风险）。

## 5. ⭐ 三样非空产出

### 5.1 ⭐ 可用但不承重的替代动机：**开放权重**（⛔ 不是「小」）+ 可复现性

⭐ 依据：⭐ Angermeir et al.（ICSE 2026）逐字「The only factor directly linked to LLMs was the usage of **deprecated models**, an issue **exclusive to commercial models**」+「the hurdles towards deprecation for **open source models are higher**」。⚠️ ⛔ **这是比较性事实陈述，⛔ 不是建议句**——⛔ 不得写成「该文推荐开源模型作缓解」（⭐ C3 修正，⭐ 本文件此前误写过）。

⛔⛔ **两条硬限制**：

1. ⛔ **它只推得出「开放权重」，⛔ 永远推不出「小」。** ⭐ 可复现性与规模**无关**——⛔ Qwen3.5-397B / DeepSeek / gpt-oss-120b 在可复现性上与 27B **完全等价**，⛔ 且**同一厂商同时供 397B 与 27B**。⛔ 故若仍选小模型，⛔ 唯一实际理由变成「⛔ 我们在那儿才赢」——⛔ **那是回填动机**，⛔ 按 `CLAUDE.md` §3.5 第 4 条性质等同于口径迁就结果。
2. ⚠️ ⛔ **目标社区内逐字支撑只有 1 篇**（⭐ C3 回分册核对：⛔ Pan et al. 全文无任何选型理由陈述、⛔ Chou et al. 的动机段**明写 privacy** 方向相反）。⛔ **不满足三条线，⛔ 须标「仅 1 篇支撑」。**

⭐ **它能当什么**：⭐ 方法选择的正当理由。⛔ **不能当什么**：⛔ contribution（⭐ 它是社区默认答案，⛔ 不构成新颖性）。

### 5.2 ⭐⭐ 可执行的实验设计修正：⛔ 加一条**大开放权重臂**

⭐ 这是**分离「开放权重」与「小」的唯一手段**（⭐ C2 提出）。⭐ 建议 N1b 的臂改为：⭐ **大开放权重模型 + 方法 vs 同模型裸跑**（⭐ 检验方法本身）· ⭐ **小开放权重模型 + 方法 vs 同模型裸跑**（⭐ 检验脚手架衰减假设）。⛔ **SOTA 闭源只作背景刻度**，⛔ 不作主对照。

### 5.3 ⭐ 反向支点：⛔ 裸覆盖率轴本身可疑

⭐ 见 §4.1：⛔ 连 GPT-o1 都没在统计上打赢十年前的规则式工具。⭐ 这支持把差异化落到**产出形态**上。⛔⛔ **但 C2 判此路当前无解**，⭐ 见 §6 第 3 条。

## 6. ⛔ 必须一起带走的限定

1. ⛔⛔ **「可断言可追溯」与「私域部署」之间没有因果连接。** ⛔ 两个独立卖点拼在一起，⛔ **绑得越紧越可疑**。⭐ 建议**别绑**。
2. ⛔⛔ **在把 −15.82pp 归因于「多阶段干扰」之前，⛔ 必须先排除我们自己的契约门 / 致命门吃掉了正确产出。** ⭐ Abdulkarim 自陈的后处理门压制正是 `CLAUDE.md` §11 那条纪律的外部案例。
3. ⛔⛔⛔ **C2 判定「可断言可追溯」作为 contribution ⛔ 无解，⭐ 建议放弃**：⭐ 借来的证据（⭐ Mäder & Egyed / Infer / CheckEval）**没有一条测本方法**，⛔ 最强那条买的是**可靠性不是效度**；⛔⛔ 且主引文 **Baldur 的决定性一步逐字是 "when normalized for inference cost"**——⛔ **引 Baldur 即接受成本归一化**，⛔ 而在 **212.6×** 开销下这根柱子要用两个数量级换一个**为负**的发现率差。⭐ 建议改写成**声明式设计性质**，⭐ 明说下游收益未验证、⭐ 留待 project_4。
4. ⛔ **保密动机在 MODELS / RE / REFSQ / SoSyM / REJ 尚未成为惯用论证**——⛔ **MDE/RE 侧 1,455 条题录里只有 2 篇**写出这条因果（⚠️ ⛔ 此前误写为「3,740 条里 2 篇」，⛔ **分母混用**，⭐ C3 修正），⛔ 且**承重 0 条**。
5. ⚠️ ⛔ **EASA NPA 2025-07(A)** 逐字要求「**avoiding the double development and verification with AI tools**」——⛔ 直指 project_1 → 2/3 的闭环形态。⛔ 征求意见稿、⛔ 限航空域，⛔ 但方向不利，⭐ 建议预先处理。
