# N1a · 私域部署动机：结论

> 本文件只写**最终裁定与可用口径**。修订过程、已撤回的主张、六路 challenge 的逐条处置，见 [revision_log.md](./revision_log.md)。

## 0. 一句话结论

落 **B 档**。原设想的 story——「工业保密 → 必须私域部署 → 必须用小模型 → 小模型加本方法可打平 SOTA」——**只有第一段可用**。

| 环节 | 裁定 |
| :-- | :-- |
| 「真实项目材料不外发给第三方托管模型」 | **可写**，依据是观察到的产业实践（非法规强制） |
| 「我们在单卡 24 GB 级条件下评估」 | **可写**，有 10 篇文献先例、3 篇承重 |
| 「因此必须用小模型」 | ⛔ **不可写**——膝点置信区间 $[8\mathrm{B}, >120\mathrm{B}]$，跨度 ≥15 倍 |
| 「小模型 + 本方法可打平 SOTA」 | ⛔ **不可写**，且相关证据四条同向反对；移入 Limitations |

最终立足点是**单一**的：一个有文献先例的**显式部署条件陈述**，不附带任何关于「必须小」或「方法因此有用」的推论。

## 0b. 实验能力上限（2026-08-13）

**用户交底：本项目可用 4×H200 做实验。这只说明我们能跑多大的模型，没有其他含义**——它**不是**论文叙事的一部分，**不是**部署条件陈述，**不进** motivation。

**唯一用途**：给 N1b 的选型划可行域。4×H200 = 4 × 141 GB = **564 GB 标称**；权重预算 $564 \times 0.92 - 20 - 12 \approx 487$ GB（0.92 为 vLLM 默认 `gpu_memory_utilization`，20 GB 为 30K 上下文 KV 上界，12 GB 为激活 + CUDA graph + NCCL）。对应 4-bit 可容约 **854B 总参**。

实测体积对照（[open_weight_model_compute.md](./open_weight_model_compute.md) 的 HF 逐文件合计）：**可跑** `Qwen3.5-397B-A17B` 4-bit 224 GB（8-bit ~421 GB 亦可）· `DeepSeek 671B` 级 4-bit ~382 GB · `gpt-oss-120b` 64.6 GB；**跑不了** `DeepSeek-V3/V3.2` 原生 FP8 689.5 GB · `DeepSeek-V4-Pro` 1.6T · `Kimi-K3` 2.8T。

**一条随之作废的我方越界结论**：此前据「单卡 24 GB」推出的「必须小模型」「缺口闭合」整套分析，**其前提是我方自行构造的，不成立**——且用户已指出，判断「这条路能不能赢」本就不在本 PR 职责内。详见 [revision_log.md](./revision_log.md)。

**论文里的硬件披露与本节无关**：论文只需说「本地单节点部署」并给必要的复现参数（模型 + 量化档 + 上下文长度 + 采样参数），**不必点卡型**。

## 1. 五问的最终答案

### Q1 · 功能安全标准里有没有禁止外发的条款

**没有**，且不是「查不到」而是**标准自陈排除**（空集式结论）：

- **IEC 61508-1:2010 §1.2 m)**：「does not specify the requirements for … security policies or security services」
- **ISO/SAE 21434:2021 §1 Scope**：「does not prescribe specific technology or solutions related to cybersecurity」
- EN 50716:2023 Introduction 措辞与 IEC 61508 同源，**不计为第三条独立证据**

覆盖 9 本标准（IEC 61508-1/-3 · ISO 26262-2/-6/-8 · ISO/SAE 21434 · IEC 62304 · DO-178C/-330 · EN 50128/50716）+ 4 份邻接文件。**ISO 26262-8 的 DIA 机制管的是责任划分而非数据驻留**，且 §5.2 NOTE 2 使该章对不担安全责任的供应商整章不适用。

### Q2 · 真正可引的依据在哪一族

分两层，**混谈是本轮最容易犯的错**：

| 层 | 最强依据 | 能支撑什么 |
| :-- | :-- | :-- |
| **法条层** | **DFARS 252.204-7012 (a)** 的 `Technical information` 定义逐字含 "specifications, standards… engineering data… data sets"，即需求文档与设计模型本身；配 **NIST SP 800-171 Rev 2 §3.1.20** DISCUSSION 逐字点名 "software as a service" | 「不能用**未获授权的**商用端点」——**可立** |
| **产业实践层** | 三星禁用 ChatGPT 事件（CNBC）· ABB 自陈 "we cannot publish them" · CCS 2024 的 27 人访谈记录「因保密改用本地 Llama」 | 「真实材料不外发」——**可立，且这是 SE venue 实际接受的依据形态** |

⛔ **法条层推不出「必须私域部署」**：能引的只有「系统须有涉密资质」（资质不以自建为限）与「委托处理须核验签约」（云也能满足），两类都不以「私域」为判据。

### Q3 · SE 文献怎么引出这类动机，是不是承重

| 侧 | 承重情况 |
| :-- | :-- |
| **目标社区（MODELS / RE / REFSQ / SoSyM / REJ）** | 1,455 条题录、31 venue-年份里只有 2 篇写出这条因果，**三篇全文到手全部判装饰，承重 0 条** |
| **SE 期刊侧（TSE / TOSEM / EMSE）** | 7 篇承重，但**其中 5 篇仅摘要级判定** |

判定判据（19 篇 100% 一致）：**承重句在全文有下游**（会再被用于选型、消融、RQ 或可接受性论证）；**装饰句只出现一次就再不回来**。硬形态判据：**承重时数字会遍布 Methodology / RQ / 结论；只在 Setup 出现一次的基本不承重**。

⚠️ **没有一篇的实证结论依赖保密动机**——它永远与成本、算力、版本稳定性捆成 3–4 条并列理由。

### Q4 · 「小模型 + 方法学补偿」怎么讲圆

从读到正文的九篇里抽出**六种彼此正交的手法**，其中三种对本文相关。逐条给出处与判定：

| 策略 | 样本与年份 | 对本文的可迁移性 |
| :-- | :-- | :-- |
| **A** 承认落后 + 立刻绑定约束条件 | VerIbmc（[arXiv:2606.16886](https://arxiv.org/abs/2606.16886), 2026, arXiv preprint 无 venue）· Tai et al.（[arXiv:2507.08627](https://arxiv.org/abs/2507.08627), 2025） | **最高**。要点是**差距的绝对值留在原地，改变的是分母**——不是「只差 10 题」而是「在单机、无外部调用的前提下差 10 题」。⛔ **但有一条生死线前提**：我们的 SOTA baseline 也必须是云端才行；若朴素单提示在小模型上也跑出高分，约束就不构成差异。**故必须补一格「朴素单提示 + 部署条件内模型」** |
| **B** 非劣性替代优越性 | Su & McMillan（Automated Software Engineering, 2024）· Caumartin et al.（SANER 2025） | ⚠️ **中**。**15.82pp 过不了任何非劣性检验**，除非找到差距落进噪声底的分层子集。且「未拒绝原假设」≠「证明等价」——要用**正式 TOST 并预先声明边界值 δ** |
| **C** 把被牺牲的一侧真跑出来报数 | Kumar & Chimalakonda（[arXiv:2412.15676](https://arxiv.org/abs/2412.15676), 2024，⚠️ 是否发表待核验） | **可用**。它是全批**唯一**这么做的（把集中训练上界跑出来后再说「However, we choose FL because it offers privacy」），也是最能挡住「你在藏结果」的做法 |

**证据细节（VerIbmc 那张表的口径）**：它对**同一套三阶段流水线**做 `Basic`（完整）vs `LLM-Only`（跳过符号先验）消融，故其 Δ 的物理含义是**「符号先验这一个阶段的贡献」**，任务是形式化验证的不变式生成（后端 ESBMC v8.2，模型本地跑于 4×A6000）。逐模型 Δ：8B **+35** · 7B +24 · 20B +15 · 32B **+2** · 120B **+3**。⚠️ 其中 `+35` 的被减数 342 取自**三次运行的最好一次**（均值 336.0，σ=5.3），故**该值落在采样方差的乐观端**。

**关于 $\Delta \gtrsim G$ 这个条件（⛔ 两处限定不可省）**：

1. ⛔ **它是我方推论，不是文献结论。** VerIbmc 没有提出它；我方据其数据构造——若要主张「小模型 + 方法 ≈ 大模型」，则方法增益 $\Delta$ 须覆盖裸能力差 $G$。作者因此用了策略 A 而非宣称打平。
2. ⛔ **但 $G \approx 89$ 这个取值有一处偷换，须纠正。** 我方原文把 $G$ 定义为「与**云端 SOTA** 的裸能力差」，取的数却是 `431 − 342`——而那两端是 **GPT-OSS-120B** 与 **Llama-3.1-8B**，**两个都是开放权重、都跑在本地 4×A6000 上**。⛔ **VerIbmc 那张表里根本没有云端前沿模型**，故 89 是**开放权重家族内部的跨度**，不是「到云端 SOTA 的差」。该篇与前沿的比较是**跟别的系统**比（Clause2Inv 356 · LORIS 351 · LaM4Inv 338，三者 "require state of the art expensive frontier models run on external servers"），⚠️ 且**那是另一个口径**（赢它的两个工具只吃单循环标量整数程序，SV-COMP 可比子集缩到 43 题），**431 与 356 不可直接比**。
3. ⛔ **我们需要的那个 $G$ 不在这张表里。** 本文主臂是 `gpt-5.5` + `claude-opus-4-7`（54 pair × 2 模型 × 3 轮 = 324 格），**两个都是闭源前沿**。「部署条件内模型 → 主臂模型」的差距只能从别处取——benchmark 侧给的是 **AA Index 37.7 vs 63.1 = 25.4 分**（≤32B vs 前沿）。⚠️ **解题数与 Index 分单位不同，不可互换。**
4. ⛔ **它只对已放弃的 parity 主张适用。** 本轮已把主张改为「部署条件内模型 + 方法 vs **同模型裸跑**」（见 §4），该主张只需 $\Delta > 0$，**不需要 $\Delta \gtrsim G$**。故不得再用「$\Delta \gtrsim G$ 过不了」去否定策略 A 与 C。

**一条从同表重算出的结构观察（我方新得）**：89 分跨度里 **82 分（92%）发生在 8B → 20B 之间**（342 → 424），而 **20B → 120B 只有 +7**（424 → 431）。即**绝大部分能力跨度落在部署包络之内**。推论：**在包络内挑对模型的影响，几乎等于整个 8B→120B 的全部差距**——故正确动作是「在包络内挑最强的」，而非「必须小」。⛔ 但同表也警告不能按参数量挑：**Qwen2.5-32B（382）比 GPT-OSS-20B（424）差 42 题**，包络内「越大越好」同样不成立。

## 2. 可以写进论文的学术口径

以下五条是本轮确定下来、可直接进正文的表述形态。⛔ 括注里的限定不得省略。

### 2.1 部署条件（本轮的核心产出）

> 我们在**单卡 24 GB 级**这一部署条件下评估本方法。

**为什么这个形态可用**：它是**显式部署条件**，不是经验断言。故它不需要全称量化（不声称所有工业单位都只有 24 GB），**反例不构成反驳**；与实验科学「我们在 X 条件下测量」同构，无人要求证明 X 是唯一条件。

**三条依据**：

1. **NVIDIA 10-Q**（报告期止 2026-04-26，SEC EDGAR）逐字：「No shipments of Data Center Hopper products to China occurred during the quarter」「we were effectively foreclosed from competing in China's data center computing/compute market」。
2. **工信部工信厅通信〔2026〕14 号**逐字承认「针对中小企业在算力获取、应用落地和能力提升中的难点」，并推荐「训推一体机」。
3. **10 篇文献先例、3 篇承重**——最强是 **Weyssow et al., TOSEM 2025**，把单卡 24 GB 贯穿 §3 独立成节、§4 方法论开篇、模型池筛选、ICL 样本数直到结论句；**REFSQ 2026 更窄到 6 GB**。

⛔ **硬条件**：不得同时兼享「工业界普遍状况」的修辞。该断言无法证实——工业单位实际算力查无严谨来源（四大中文库全部不可用 · 国产一体机官方材料不公布显存与卡数 · 军工方向零篇可引学术文献）。**而「数据结构性不可得」本身，正是「为什么陈述条件而非调查现状」的方法论正当理由。**

### 2.2 不外发假定

> 我们**假定**真实项目材料不外发给第三方托管模型。

依据是**观察到的产业实践**（Q2 产业实践层三条），⛔ **不是法规强制**。

### 2.3 开放权重的可复现性理由

> Angermeir et al.（ICSE 2026）逐字：「The only factor directly linked to LLMs was the usage of deprecated models, an issue exclusive to commercial models」「the hurdles towards deprecation for open source models are higher」。

⛔ **这是比较性事实陈述，不是建议句**——不得写成「该文推荐开源模型作缓解」。⚠️ 该文 DOI `10.1145/3744916.3773207` 是**死链**（错源在上游预印本版权块），只引 [arXiv:2510.25506](https://arxiv.org/abs/2510.25506)、不写 DOI、录用状态标待确认。

### 2.4 能力差距必须逐维度报

⛔ **不得用总分单一比值代表「小模型能力」。** ≤32B / 前沿的比值高度不均：

| 维度 | 比值 |
| :-- | --: |
| AA-LCR（长文档推理） | **0.97**（30B 档 1.06，反超） |
| IFBench（指令遵循） | ≈0.97 |
| GPQA Diamond | 0.90 |
| **AA Index 总分** | **0.60** |
| HLE | 0.42 |
| $\tau^3$-Banking（工具调用） | 0.40 |
| CritPt（研究级物理） | 0.04 |
| **AA-Omniscience（幻觉净分）** | ⛔ **变号** |

按 0.60 去估具体任务表现会严重误判。相关维度的选择依据必须**独立于分数**：本方法的负载是「读约 30K token 长上下文 → 定位与推理 → 产出严格 schema 结构化输出」，这由实现决定（splitter system prompt 实测 95,589 字符；五个 LLM 调用全走 schema 约束 `tool_use`）。

⛔ **幻觉净分那一格必须报，且它对本文不利**：前沿 +37～+43，而 ≤32B 开放权重**全部为负**（Qwen3.6-27B −20.0 · Muse Glimmer-30B −32.9），即幻觉多于正确回答。**本方法的产出正是「报告缺陷」，幻觉直接变成多报。**

### 2.5 成本口径

⛔ **不得写「我们实测成本高 212 倍」。** `212×` 是**裸 token 计数的上限**：它由 input token 主导（`review_assertions` 一块 input 27.76M / output 仅 0.50M，98% 是反复重读），而 95,589 字符的 system prompt 逐调用逐字相同、被裸计数在 3621 次调用里各算一遍。

本仓库自己的 `run_telemetry.py` 逐字写着：「`cache_read_input_tokens` 在本仓库的 provider 配置下常为 0，**不代表没有缓存，只代表 provider 没报**。为 0 的字段不得写成「无缓存」」「**`output_tokens` 才是模型实际生成量，跨代比较应以它为准**」。

**正确做法**：以 `output_tokens` 为主口径，裸 token 比只作上限附注。

| # | ⛔ 不得写 | 理由 |
| :-: | :-- | :-- |

| 3 | ⛔ **归因前必须先自查契约门 / 致命门** | 把 −15.82pp 归因于「多阶段干扰」之前，须排除我方门吃掉了正确产出。**外部可引案例已找到**：ExtractBench 显示打开强 schema 约束后 Valid JSON 从 51% 掉到 37%，一个 schema 从 26/42 掉到 0/42 |
| 4 | ⚠️ **本目录一切以 `60.4%` / `76.2%` 为前提的推论都带未标注前提** | G1 正在重标台账，分母可能变。**G1 完成前不得据此锁定路线** |
| 5 | **一个可主张的显式空白** | 「只能本地部署、而本地只有 X」这句完整表述，本轮检索内**无人写全**。须按伞 PR §4.2 #8 附覆盖范围 |

**N1b 实验设计建议**（若开）：单点 + 上界对照——部署条件内模型 + **同模型裸跑**为唯一合法对照，前沿闭源用现有 v46 结果作背景刻度（零新成本）。⛔ 原「两端」设计作废：21B vs 8B 只差 2.6 倍，两端之差不构成可分辨的量。

⚠️ **候选模型未定**。`gpt-oss-20b` 四榜一致偏弱（AA-LCR 33.3/51.0 · SOB 两项全场最低 · LongBench Pro 44.66）；`Muse Glimmer 30B`（Meta，29.6B dense，Apache-2.0，官方 `K-Quant-17GB` 自陈 targeting 24 GB，AA-LCR 80.0 高于 Claude Opus 5 的 75.7）但**按本目录判据 17 + 7 = 24 > 21.1 装不进**，且其 AA-LCR 优势**依赖 thinking 开启**（Qwen3.6-27B 关掉从 73 掉到 64）——⛔ **而本方法五个调用全走 schema 约束 `tool_use`，thinking 是否可用须先查实现**。

**最高 ROI 的后续动作**：在 **LEDGER**（[arXiv:2606.13100](https://arxiv.org/abs/2606.13100)，代码 MIT / 数据 CC-BY-4.0）上自己跑候选模型。它是**唯一同时测「≈100K 长上下文 + 严格 JSON schema + 数值落地」的公开榜**，几乎就是本文任务形状；一次可同时解掉「候选选谁」与「本文任务形状上的 $G$ 是多少」。
