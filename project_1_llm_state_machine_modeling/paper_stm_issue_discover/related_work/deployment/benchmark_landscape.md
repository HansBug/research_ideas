# 开源大模型 benchmark 表现与能力维度

> 本文件服务 [SUMMARY.md](./SUMMARY.md) §18 与 §20——它决定必要条件 $\Delta \gtrsim G$ 里的 $G$。开放权重侧的逐模型细表另见 [benchmark_open_weights.md](./benchmark_open_weights.md)。
>
> **核验日期**：2026-08-13。⛔ **本文件所有分数均为第三方独立实测**（主要是 Artificial Analysis），⛔ **不是厂商自报**（唯一的厂商自报组见 §6）。

## 0. 一句话结论

**差距高度不均，⛔ 不能用单一比值代表「小模型能力」**：≤32B 开放权重 / 前沿在**总分**上是 **0.60**，⛔ 但在**长文档推理**上是 **0.97**（且 30B 档有反超）、在**指令遵循**上约 **0.97**，而在**工具调用**上只有 **0.40**、**研究级推理 0.04**、**幻觉净分直接变号**。

⛔ **两条方法论警告比任何单个分数都重要**：**四个常被引用的 benchmark 已事实退役**（§2）· ⛔ **「结构化输出 / JSON schema 遵循」业界没有现成刻度尺**（§4）。

## 1. 一条可复用的硬判据：⛔ 怎么判断一个 benchmark 还能不能用

> ⛔ **唯一可靠判据是「榜上最新模型的发布日」，⛔ 不是页面是否打得开。**

⚠️ 实测：本轮 9 个入口里 **7 个是 SPA 壳**（⛔ HTML 直读全为空）；**其中三个页面完全正常、无任何停更标识，实际已冻结 4–16 个月**。

附带一条取数经验：Artificial Analysis 的图表数值**不在 HTML 文本里**——⛔ WebFetch 会因超 10 MB 上限失败；可行路径是 `curl` 取页面后**解析内嵌的 Next.js RSC payload**（本轮由此解出 **563 条模型全量记录**）。同理 ARC Prize 的数据在旁挂端点 `/media/data/leaderboard/{v1,v2,v3}.json`；SWE-bench 在页面内嵌 `<script type="application/json" id="leaderboard-data">`（4.16 MB）。

## 4. ⛔ 结构化输出 / JSON schema 遵循：**业界没有现成刻度尺**

三种方式**独立确认** Artificial Analysis 上不存在该指标：

1. **方法论页**：⛔ 无任何 JSON / schema / 结构化输出的表述。
2. **评测总目录页**（25 个评测全列）：⛔ **无一项**针对结构化输出。
3. **底层数据字段**：⛔ 563 条记录的全部字段里，与格式相关的**只有一个 `ifbench`**（⚠️ `global_mmlu_lite_json` 只是结果的 JSON 序列化，非指标）。

**最接近的替代是 IFBench**（Allen Institute，**58 条可验证的域外约束**，**程序化校验、非 LLM 判分**）。⛔ **但其约束是词法要求**——样例是「包含 kaleidoscope 一次、nebula 两次…」这类关键词出现次数与编号列表，⛔ **不涉及 JSON schema 一致性**。且它**已在 v4.1 被移出 Index**。

**IFBench 参考值**：前沿最高 **Grok 4.3 (medium) 83.3%**；≤32B 开放权重最高 **Nemotron Cascade 2 30B A3B 80.4%**——**只差 2.9 个百分点（≈0.97）**。

⛔ **两条后果**：

1. ⛔ **仓库那条「GLM-4.7 结构化输出取值准确率 0.830 > GPT-5.4 0.825」在找到一手来源前不得引用**——⚠️ C5 已核出其**一手来源断链**，而现在又知道**业界没有这个 benchmark**。
2. **这是实质缺口，⛔ 也是机会**：该维度**只能自建评测**——而本方法**本来就在做 schema 约束下的结构化产出**，且手上已有 588 位判定与五类多报分类。

**≤32B 档的绝对位置**：最高是 **`Qwen3.6-27B` (Reasoning) 37.7**（27.8B dense，Apache-2.0）· 次高 **Muse Glimmer (high) 35.1**（30B，Meta，2026-08-10）· 第三 Gemma 4 31B (Reasoning) 29.7 · 第四 Gemma 4 26B A4B 26.1。**开放权重不限参数的最高是 Kimi K3 (max) 59.7**（2800B / 104B 激活）。

### 5.1 三条判读

1. **差距高度不均，⛔ 不能用单一比值代表「小模型能力」。** 长文档推理（**0.97**，且 30B 的 Muse Glimmer **反超** Opus 5）与指令遵循（**≈0.97**）几乎追平；⛔ 而工具调用（**0.40**）、研究级推理（**0.04**）是断崖。**按 0.60 的总分比值去估计具体任务表现会严重误判。**
2. ⛔ **AA-Omniscience 上差距是变号的，⛔ 不是变小的。** 前沿 **+37 到 +43**，而**所有 ≤32B 开放权重模型全部为负**——即**幻觉多于正确回答**。**这是质变而非量变**；对以「不能凭空编造模型元素」为核心失败模式的状态机建模任务，**这一项比总分重要得多**。
3. **幻觉率可靠训练改善，⛔ 但净分转正仍需远超 32B**。AA 自己的观察：`Qwen3.6-27B` 相比 `Qwen3.5-27B` **幻觉率从 80% 降到 48%** 而准确率基本不变。

## 6. AA-LCR 方法论（本研究最相关的那一项，⛔ 故单列）

| 项目 | 内容 |
| :-- | :-- |
| 题目数 | **100 题**，人工撰写 |
| 文档规模 | **30 个文档集 / 234 份文档 / 2,979,757 tokens**，平均每集 **99,325 tokens** |
| 单题上下文 | **10k–100k tokens**（cl100k_base 计数） |
| 文档类型 | 公司文件 63 · 政府咨询 11 · 行业报告 8 · 法律 6 · 营销 6 · 学术 5 · 调查 1 |
| 评分 | **开放式作答 pass/fail**；由另一 LLM 判定是否与官方答案等价；取平均通过率 |
| 判分模型 | **GPT-5.6 Luna (medium)** |
| 准入门槛 | 模型须支持 **≥128K 上下文** |
| 难度校准 | 2024 年中前沿 <50%；**人类验证者首次作答正确率仅 40–60%** |
| **防作弊设计** | 出题时**只对弱模型试测**（GPT-4o-mini · Llama-3.1-70B · Gemini 1.5 Flash），⛔ **故意不用前沿模型**，避免针对性选择 |
| 覆盖 | **494 个模型**有分 |
| 数据集 | HuggingFace `ArtificialAnalysis/AA-LCR` |

**一条反直觉发现**：AA-LCR 上**非推理大上下文模型可以打败推理模型**，⛔ 且**前沿旗舰并不领先**——Claude Opus 5 (max) 只有 **75.7%**，⛔ **低于一个 30B 开放权重模型**（Muse Glimmer 80.0%）。当前 top 5：Muse Spark 1.2 83.3 · Kimi K3 82.7 · Muse Spark 1.1 81.3 · Gemini 3.5 Flash 81.0 · MiniMax-M3 80.3。
