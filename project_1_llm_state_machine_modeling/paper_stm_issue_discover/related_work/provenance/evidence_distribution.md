# 证据为什么厚薄不均 —— 对「词表是照着案例反推的」的正面回应

> **这份文件回答一个指控，⛔ 不是一份统计报告。** 19 行分级表在 [predicate_provenance.md](./predicate_provenance.md)，语料扫描的三条发现在 [corpus_scan_findings.md](./corpus_scan_findings.md)。
>
> **档位标记**：§1 §2 §4 的数字为【实测】（由 [tools/analyze_evidence_distribution.py](./tools/analyze_evidence_distribution.py) 与 [corpus_scan_findings.md](./corpus_scan_findings.md) 复算）；§3 的**解释**为【AI 建议·待确认】，⛔ 但每条都附了反证条件。

## 0. ⛔ 先把指控说准，⛔ 否则回应打空

弱证据谓词是这样一条指控的入口：

> ⛔ 「19 条谓词里有几条几乎没有上游依据。⭐ 这些是不是照着 54 个 pair 的期望缺陷**反推**出来的？⭐ 若是，那所谓『闭合词表』就是**为这批案例定制的**，⛔ 评测结果不能外推。」

⛔ **这个指控不能靠『我们没有』来回应** —— 自述动机不可查证。⭐ 能回应它的只有两样东西：**分布的形状**（拟合会留下特定形状），与**逐格的出处或理由**。

⭐ 指控还有一个**弱形式**与一个**强形式**，回应方式不同：

| 形式 | 内容 | ⭐ 由什么回应 |
| :-- | :-- | :-- |
| **弱形式** | 「每条谓词都是为了抓某个案例缺陷而加的」 | ⭐ §1 的定量反证（⛔ 这一条被直接证伪） |
| **强形式** | 「⭐ 大部分谓词有正当来源，⛔ 但**弱的那几条**是补上去凑案例的」 | ⭐ §3 的结构性解释 + §4 的逐格交代 |

## 1. ⭐⭐ 定量反证：案例用量与证据量是**负相关**

【实测】若弱形式成立，每条谓词都因「能抓住某个案例缺陷」而入选；⭐ 案例缺陷是真实缺陷的样本，⭐ 于是**案例用得越多的谓词，真实系统里也该越常见** —— 相关性应当**显著为正**。

⭐ 实测三个口径**全为负**：

| x（案例侧） | y（上游侧） | rho |
| :-- | :-- | --: |
| 台账断言数（案例期望缺陷用到它多少次） | 界内真实系统 | **−0.562** |
| 台账断言数 | 文献 | −0.133 |
| 已发布支撑数（v46 制品上实际断言多少次） | 界内真实系统 | **−0.457** |

⭐ 两端对照比相关系数更直观：

| | 界内真实系统 | 台账断言 |
| :-- | --: | --: |
| `invariant` | **41** | ⭐ **0** |
| `persists_until` | 23 | 3 |
| `response_within` | 17 | 1 |
| | | |
| `reaches` | 3 | **28** |
| `initial_target` | 2 | **26** |
| `cardinality` | 2 | **20** |
| `containment` | **0** | **19** |

⭐⭐ **有界模型检查族**（3 条）扛着 **60.4%** 的真实系统证据，⛔ 却只占台账断言的 **2.0%**。⭐ 其中 `invariant` 最极端：**41 个独立真实系统**支撑，⛔ 而我们的案例台账**一次都没用到它**。

⛔ **反推词表不会留下一条自己一次都用不上的谓词**，⛔ 更不会把六成证据压在两成不到的用量上。⭐ 弱形式指控与这个分布不相容。

⚠️ **这一节能证伪的只有弱形式。** ⛔ 它挡不住强形式（「⭐ 主体有出处，⛔ 弱的几条是凑的」）—— ⭐ 那要靠 §3 与 §4。

## 2. ⭐ 分布的形状：族间差 10 倍

【实测】

| 族 | 谓词数 | 台账断言 | 占比 | 界内真实系统 | 占比 | 真实系统/谓词 |
| :-- | --: | --: | --: | --: | --: | --: |
| 有界模型检查 | 3 | 4 | 2.0% | 81 | 60.4% | **27.0** |
| 结构 | 10 | 120 | 60.9% | 39 | 29.1% | 3.9 |
| 仿真 | 6 | 73 | 37.1% | 14 | 10.4% | 2.3 |

⭐ 这个形状需要一个**与案例无关**的解释。⛔ 若解释不出来，「弱的那几条是凑的」仍然站得住。

## 3. ⭐⭐ 解释：厚薄跟着**义务类型**走，⛔ 不跟着我们的案例走

### 3.1 ⭐ 主解释（⭐ 实测，⛔ 非猜想）：行为义务 vs 建模义务

⭐ 这不是为本文件新造的说法 —— ⭐ 它是[语料穷尽扫描](./corpus_scan_findings.md)**发现 2** 的实测结论。把 313 个界内案例、310 篇独立论文扫完后，义务的**类型**出现了干净的分裂：

> ⭐ 真实控制系统的需求文本谈的是「**系统必须怎样**」（⭐ 行为义务），⛔ 不谈「**模型必须声明什么**」（⛔ 建模义务）。

⭐ 而两端恰好按这条线排开（⛔ 下列为语料侧裁定前计数，⭐ 用于看**排序**）：

| 谓词 | 独立真实系统 | 义务类型 |
| :-- | --: | :-- |
| `invariant` · `persists_until` · `response_within` | 66 · 57 · 34 | ⭐ 行为义务 |
| `guard_distinguishable` | 25 | ⭐ 行为义务 |
| `initial_target` · `event_consumed` · `containment` · `event_declared` | 5 · 3 · 2 · 2 | ⛔ 建模义务 |
| `variable_delta_after` | **0** | ⛔ 建模义务 |

⭐⭐ **这是需求文本这一文体的性质，⛔ 与我们选了哪 54 个 pair 毫无关系。** ⭐ 发现 1 进一步排除了「扫描力度不够」：多路独立做了穷尽情态词 grep（`must / shall / should / required / only / exactly / never / always` 及中/德/印尼语对应词），报告的是「⭐ 长得像这几条谓词的句子有 30 余处，⛔ 它们**全部没有义务语气**」—— ⛔ 不是没找到，是**这类文本不谈这件事**。

⛔ **反证条件**：若在真实控制系统的需求文本里能找到成规模的建模义务陈述（「模型**必须**为每个复合态声明默认初始子态」这类），本解释即被推翻。⭐ 两轮 24 路穷尽扫描没有找到。

### 3.2 ⭐ 由此，② 类谓词的薄不是缺陷

⭐ 6 条 **② 元模型定义性**谓词（`event_declared` `variable_declared` `state_declared` `edge_declared` `action_declared` `effect_declared`）正是**建模义务**的典型。⭐ 「模型里用到的事件必须被声明」**不需要外部文献背书 —— 它就是元模型的定义**。

⭐ 发现 3 给了这条判断经验佐证：⭐ 它们由定义支撑，⛔ **本来就不该向领域频次索取背书**。⭐ 于是「`event_declared` 只有 3 源」不是欠账，⛔ 而是**问错了问题**。

⚠️ ⛔ **但这条不能滥用。** ⭐ 判据是「⭐ 判据能否只由元模型定义推出」，⛔ 不是「⭐ 找不到出处就归 ②」。⛔ 六条的逐条理由列在 [predicate_provenance.md](./predicate_provenance.md) §② 类的逐条理由，⚠️ 且标为待人工确认。⛔ `containment` 曾被考虑提到 ②，⭐ 被否 —— ⭐ 理由见下。

### 3.3 ⭐⭐ 两条 ③ 失败于**同一个结构**：它们需要外部参照物

⭐⭐ 这是本轮最值得记下的一条 —— ⭐ **两个互不相识的裁定者，各自独立地把两条 ③ 的失败归到了同一处**：

| 谓词 | 裁定者逐字 | 出处 |
| :-- | :-- | :-- |
| `containment` | 「`containment` 的『**正确**』需要**外部规约作参照**，⛔ 而语言层良构性规则**天生给不出**『这个子态该挂在谁下面』，⭐ 所以这条轴上很可能**不存在**同口径的文献出处。」 | [SUMMARY.md](./SUMMARY.md) §4.5.2 |
| `cardinality` | 「本谓词的特征**不在『比较是精确的』**，⭐ 而在 **N 的出处是需求文本**。」（⛔ 15 条候选的 N 全部来自语言 / 元模型 / 作者策略） | [SUMMARY.md](./SUMMARY.md) §4.1 |

⭐⭐ **共同结构**：这两条谓词的「正确」都不能由模型自身判定，⭐ 必须拿**需求文本**当参照物。⛔ 而前两轮翻的材料 —— 语言规约、元模型、良构性规则目录、检查器规则集 —— **按构造就是无参照物的**：它们只回答「⭐ 模型自身是否合法」，⛔ 不回答「⭐ 模型是否符合某份外部规约」。

⛔ **所以这两条不是「找不到」，是在一类天生不可能包含它的材料里找。**

⭐⭐ **这个解释可证伪，且它预言了证据该在哪** —— ⭐ 跨制品一致性、需求可追踪性、模型-规约符合性、工业模型缺陷实证。⭐ §4 记录了按这个预言做的定向检索及其结果。

⚠️ ⛔ **不得把这条解释用成免责声明。** ⭐ 它同时意味着一件对我们不利的事：⭐ 若定向检索**找到了**出处，则「⛔ 不存在同口径出处」这个说法作废，⛔ 必须改口。⭐ 两种结果都要如实写。

### 3.4 ⭐ 这个解释顺带解释了「暴露格恰好是这两条」

⭐ §4 的机械判据（**③ 类** ∧ **台账断言进入前 1/3**）独立地把暴露收敛到 `containment` 与 `cardinality` **两格** —— ⭐ 而 §3.3 的结构性解释**事先**就指出这两条共享同一个失败机制。⭐ 两条互不相干的路径指向同一对谓词。

⛔ 若暴露格是**散落**的（⛔ 每族零星几条、⛔ 彼此无共同结构），「凑案例」的嫌疑会大得多 —— ⭐ 因为拟合不会挑出一个有共同结构的子集。

## 4. ⭐ 逐格交代：两条 ③ 各自的处置

⛔ **本节在定向补强轮结束后填。** ⭐ 补强的对象与理由：

| 谓词 | ⭐ 按 §3.3 预言应当去哪找 | 本轮做了什么 |
| :-- | :-- | :-- |
| `containment` | 跨制品一致性规则集 · 工业模型缺陷实证 | 开采 Torre 的 **119 条 UML 一致性规则**（⭐ 跨图一致性 = 拿一份制品当另一份的参照物）· Lange & Chaudron 的**工业模型缺陷频次** · UML 模型异味 / 缺陷分类学 |
| `cardinality` | 需求侧的枚举完整性 | SCR 的 **mode class partition**（「每个状态恰属一个 mode」）· mode confusion 一系（Leveson / Rushby）· `MECE mode partition` · `mode completeness` |

⛔ **若补强仍为空，⭐ 落稿表述已经备好**（[SUMMARY.md](./SUMMARY.md) §4.1 已给出 `cardinality` 的完整句）：只主张证据支持得住的那一层（⭐ 「对作用域内元素计数并与预期值比对是这类元模型的常规良构性手段」），⛔ 把差额（⭐ **N 的出处是需求文本**）明写成新颖点。⭐ 于是坏消息转成**第二档贡献声明**，⛔ 而不是继续当欠账。

⭐ `containment` 的两条出路（[SUMMARY.md](./SUMMARY.md) §4.5.2）：① 把主张削弱为「层次归属是语义承重结构，因此挂错会改变行为」（⭐ 三条独立来源够用）；② 明确承认其依据来自界内语料而非文献。⛔ **不得用宽泛语义句冒充检查出处。**

## 5. ⛔ 本文件**不**主张的东西

⛔ 以下几条容易被读进来，⭐ 但都不成立，⛔ 不得写进论文：

1. ⛔ **不主张「证据薄的谓词也有充分依据」。** ⭐ ③ 类就是 ③ 类，⛔ 在 Limitations 明写，⛔ 不删谓词（588 冻结）。
2. ⛔ **不主张「负相关证明了词表是对的」。** ⭐ 它只证伪了指控的**弱形式**，⛔ 不证明任何正面命题。
3. ⛔ **不主张「② 类比 ① 类更强或更弱」。** ⭐ 三类不是强度序（[method_provenance_policy.md](../../discover_matrix/docs/protocol/method_provenance_policy.md) §一.4）。
4. ⛔ **不把「找不到出处」等同于「不存在出处」。** ⭐ §3.3 给的是一个**带反证条件的结构性解释**，⛔ 不是存在性否证。
5. ⛔ **不报任何比例。** ⭐ `sources/` 的收录标准与被测属性重合（⛔ 在因变量上选样），⛔ 分母不合法。
