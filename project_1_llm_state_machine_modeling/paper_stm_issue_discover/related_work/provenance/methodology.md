# L2 的调研方法：编制、判据、以及为什么这样做

> **这份文件回答「结论是怎么得来的」**，⛔ 不给任何结论。结论在 [predicate_provenance.md](./predicate_provenance.md)（Q1）、[c3_differentiation.md](./c3_differentiation.md)（Q2）与 [corpus_scan_findings.md](./corpus_scan_findings.md)（语料层发现）。
>
> ⭐ 它存在的理由：本轨的结论**大量依赖 subagent 的判断**，⛔ 而「几十路 agent 说了什么」本身不是证据。⭐ 使这些判断可审计的，是下面这套编制与判据。

## 2. ⭐⭐ 物理拆分做在**语料层**，⛔ 不是文档层

⛔ [CONTINGENCY_L2.md](../CONTINGENCY_L2.md) §0.1 要求把材料切开，理由是实测：**约定式隔离（禁读名单 / 「读到此为止」）合规率 0/2，物理拆分 2/2**。⛔ **「我不去看后果那部分」是约定，不是隔离。**

⭐ 本轮的落法比切文档更彻底：

1. ⭐ 每路提取 agent **只拿到一个分片文件**，⛔ 它看不到全局。
2. ⛔ 它的 prompt 里**既没有各谓词缺多少源，也没有任何数量指标** —— 逐字写着「本任务**没有数量指标**，提交 0 条和提交 20 条同样合格」。
3. ⭐ 结果：**提取者根本不知道哪条谓词证据稀薄，也就无从为它凑数。**

⚠️ **二轮定向扫描确实告诉了 agent 要找哪 7 条谓词**（否则无法定向），⛔ 但同样没给数量目标，⭐ 且额外写了「你这一路交 0 条是完全正常、完全合格的结果」，并要求把**拒收的边缘案例逐条记进 `notes`**。⭐ 那份拒收清单（14 万字符）才是「这类义务确实稀少」这个结论的证据主体。

## 3. ⭐⭐ 裁定层是独立误差源：逐条从严，⛔ 且不是关键词匹配

⛔ 裁定者的立场被写死为**怀疑者**，⛔ 不是复核者：「⚠️ **不确定时一律判不通过**」「⭐ 审稿人只要抽查到一条出处是错的，会连带削弱另外几条」。

### 【实测】裁定结果

| 批次 | 送审 | ACCEPT | 存活率 |
| :-- | --: | --: | --: |
| 界内语料 · 首轮 | 299 | 132 + 改判 7 | ⭐ **44%** |
| 界内语料 · 二轮 | 16 | 3 + 改判 1 | ⭐ **25%** |
| 来源 C+D 文献 | 见 [predicate_provenance.md](./predicate_provenance.md) | — | — |

⛔ **首轮的主要失败模式（129 条 `REJECT_NARRATIVE`，43%）**：

| 失败模式 | 裁定者的逐字判据 |
| :-- | :-- |
| **把成就动词与副词当模态** | 「提取者反复把 `ensures` / `enforces` / `secures` / `allows` / `is designed as` / `immediately` 登记为义务词，⛔ 而这些词只描述作者的**设计达到了什么效果**」 |
| **看到 `until` 就盖章** | 「提取者事实上把『引文里有 until』当成了 `persists_until` 的判据，⛔ 而这些 `until` 全部出现在**动作时序走查**里」 |
| **把实现报告里的好性质当不变式** | 「死掉的 6 条内容形状确实都是 invariant 的形状，⛔ 但句子一律是**完成时/结果式的实现叙述**」 |

### ⭐ 裁定层自身的可靠性审计（双向，⛔ 不是单向找更多 ACCEPT）

⛔ 「裁定太严所以放宽」是**评测口径迁就结果**（根 [CLAUDE.md](../../../../CLAUDE.md) §3.5 第 4 条）。⭐ 正确的动作是**测裁定层本身**：

【实测】用一套机械正则（真模态 + 禁止式 + 中/印尼/德语义务词）复算裁定者自述的判别线，与裁定结果的一致率 **187/299 = 62.5%**。⛔ **这个数不说明裁定不一致** —— ⭐ 它说明裁定**不可被正则复现**：

- **74 条**机械上无硬模态，⭐ 裁定者仍判 ACCEPT（如「no car **is allowed** to enter」「the door **will only open if**」——⛔ 我的正则漏配，⭐ 裁定者读懂了）
- **38 条**机械上有硬模态，⛔ 裁定者仍拒（如「the automata **shall** be translated into a NuSMV program」——⭐ 主语是**研究流程**，不是被建模系统）

⭐ **结论：裁定层在两个方向都做了语义判断，⛔ 它不是关键词匹配器。**

### ⛔⛔ 一个必须记住的红旗：**提取者的自证套路本身可被证伪**

⚠️ 二轮裁定者发现：`why_not_narrative` 字段里反复出现一个论证 ——「**作者在同一段刻意把某句升格为强模态、别处都没有**」。⭐ 裁定者逐条回原文核对，**该论证在 3 处不成立**：

| 条目 | 提取者说 | ⛔ 回原文的事实 |
| :-- | :-- | :-- |
| S-5 | 作者刻意换成 `must` | ⛔ 同一清单的兄弟条目写的是 "**needs to** reduce" —— ⭐ 同为模态 |
| S-13 | 作者只在此处升格为 `has to` | ⛔ 同段另有 "These analyses **have to be** carried out" |
| S-6 | 作者刻意用 `should` 作对照 | ⛔ 兄弟条目讲的是**进入条件**、句式本就不同，⛔ 构不成对照 |

⛔ **这个套路专门用来抬置信度**（S-5 因此被标成 `high`）。⭐ 后续同口径提取时，它必须被列为**红旗措辞**：⛔ 不得凭该论述本身给分，⛔ 必须回原文复核。

### ⭐ 另一个机制性观察：**产出会漂向判据最松的谓词**

【实测】二轮 16 条里 `effect_declared` + `state_declared` 占 **11 条（69%）**，⛔ 而 `containment` 与 `variable_delta_after` **各 0 条**。⭐ 裁定者的解释：

> 「真实语料里层次归属与『执行后变量已变为某值』并不比效果声明罕见到这个程度；⭐ 更可能的解释是：这两条谓词的**判据紧、套不上去**，于是产出全部漂到了两条**判据最松**的谓词上。」

⛔ 由此该裁定者给出两道补充硬门（⭐ 已采纳，写进后续提取口径）：**(a)** 义务对象必须是**模型元素**（状态/变量/迁移），⛔ 不是被控物理量；**(b)** 必须有**迁移或进入锚点**，「during / in this mode」只能记 `invariant`。

## 4. 机械核验：⛔ 只做定位，⛔ 不做裁定

⭐ 按仓库纪律〈机械代理只能定位不能裁定〉，工具回答「这句话在不在那里」，⛔ **不回答**「它算不算义务」。

| 工具 | 【实测】结果 |
| :-- | :-- |
| [verify_quotes.py](./tools/verify_quotes.py) | ⭐ **315 / 315 逐字命中**摘录节，⭐ **0 条 `WRONG_SECTION`**（⛔ 没有一条拿我们自己写的转述节当外部依据） |
| [verify_citations.py](./tools/verify_citations.py) | ⭐ Q2 的 63 条引用：**OK 57 · TITLE_MISMATCH 2 · NO_USABLE_IDENTIFIER 2 · REACHABLE_URL 2**。⭐ 两条 `TITLE_MISMATCH` 逐条查过，⭐ **都是声称标题为解析标题的前缀，⛔ 不是幻觉**。⭐ **结论：零幻觉引用** |

### ⚠️ 两个工具缺陷，⛔ 已修，⭐ 留痕以免复发

1. ⛔ **`verify_quotes` 首版按 directory 建条目索引** —— ⚠️ 而 3 个目录各含 2 个界内条目，第二个被覆盖，⛔ 导致 3 条**合法**引文被误判 `NOT_FOUND`。⭐ 改为扫全文件所有条目的节：⭐ 节位合法性只取决于**节号**，⛔ 与条目无关。
2. ⛔ **`verify_citations` 首版 DOI 优先** —— ⚠️ 于是对 arXiv 论文拿 `10.48550/*` 前缀去查 **Crossref**，⛔ 而那是 **DataCite** 的地盘，必然查不到。⚠️ 叠加一个环境事实：**`export.arxiv.org` 的 API 在本机不可达**（12 s 超时），⛔ 而 `arxiv.org/abs/` 与 DataCite 都通。⭐ 改为 DataCite 优先 + abs 页兜底，⛔ 并在解析不到时退一步测 URL 可达性 —— ⭐ **「我们的解析器不认」与「这篇不存在」是两回事**，⛔ 混淆的代价是把幻觉审查变成噪声。

## 4.5 ⛔⛔ 自证式取证：⭐ 一条个案被泛化成全库机械排查

⚠️ 一路裁定者发现某条目引 `arXiv:2604.00275` 作**独立文献**，⛔ 而它在本仓库里登记为**种子语料来源**（`corpora/seed_library/sefm-llm-state-machine`，评级 `SS-A strict seed`）。⛔ 用被评测对象自身证明「这类检查在领域里常见」是**自证式取证**（根 [CLAUDE.md](../../../../CLAUDE.md) §3.5）。

⭐ 我把它泛化成了 [detect_self_citation.py](./tools/detect_self_citation.py)。⛔ **结果分三层，⛔ 后果完全不同，⛔ 不得一概而论**：

| 层 | 是什么 | 【实测】 | 处置 |
| :-- | :-- | --: | :-- |
| ⛔⛔ **seed** | `corpora/seed_library/` —— 本研究 NL+STM 对的**来源池** | **9 条**（`sefm-llm-state-machine` 7 + `designing-fsm-gpt4` 2） | ⛔ **剔除**：用自己的数据源证明自己的谓词该存在，是自证 |
| ⚠️ **baseline** | `baselines/` —— 本文定位为对照 / 相关工作的论文 | **7 条**（`sysmbench` 4 + `3gpp-extraction` 2 + `agentic-flow` 1） | ⭐ **保留但必须标注** —— ⭐ 引它说「该领域确实这么做」是正当的相关工作用法，⛔ 但不得混在独立文献里不作声 |
| ✅ **一般收藏** | `state_machine_types/` 等领域文库 | — | ✅ **无问题** —— ⭐ 一篇论文碰巧被我们收藏，⛔ 不使它变成「我们的」 |

⭐ **一处必须澄清的量级**：v46 的 54 pair **全部**来自 `llms_emp_feedback_final_*`（Wang et al., Internetware 2025），⛔ **不是**来自上述两个种子源 —— ⭐ 所以它与**被测数据**没有直接循环。⚠️ 但它们确实登记在我们的种子池里，⛔ **审稿人查得到**。

⚠️ **首版探测器过度触发，⛔ 这个教训值得记**：它拿目录里**全部文本**的 DOI 做匹配，⛔ 于是把 `DESC.md` **参考文献列表**里的 Harel 1987 也算成「我们的」—— ⭐ 那是彻底的误报，⛔ **而误报会把真问题淹掉**（38 条命中里有 22 条是噪声）。⭐ 已改为只认该目录 `bibtex.bib` **第一条 entry** 的 title / doi / eprint。

## 5. ⛔ 计数口径

| 项 | 口径 |
| :-- | :-- |
| **计数单位** | ⭐ **互相独立的真实系统 / 独立文献**，⛔ **不是条目数**。⚠️ 否则同一篇论文摘三句就能自己满足「多源」 |
| **下限 / 上限** | ⭐ **≥ 3 个独立来源**为下限（policy §一.5）；⛔ **无上限**。⭐ 本轮另设 **≥ 6** 为目标档 |
| **领域多样性** | ⭐ N 个源须覆盖 $\min(3, N)$ 个以上不同领域；⛔ 若只在单一领域出现，**必须显式说明**并把主张限定到该领域 |
| ⛔ **不报比例** | ⛔ `sources/` 的收录标准恰好选中了要测的那个性质 —— ⛔ 任何 K/N 都是**在因变量上做选择**。⭐ **787 / 715 / 313 都只是库存量，⛔ 一个都不是分母** |
| ⚠️ **来源独立性的已知折扣** | ⚠️ C+D 的一路主动坦白：「12 条…⛔ 但**真正互相独立的研究组只有约 8 个**，其中 NASA Ames 两条与 York/Manchester 两条存在方法学与工具链上的相关性，⛔ **请勿把 12 当成 12 个独立观测**」。⭐ 这类折扣逐条记在 [predicate_provenance.md](./predicate_provenance.md) 的备注列 |

## 6. ⛔ 已知的方法局限（⚠️ 必须与结论一起读）

1. ⛔ **裁定层只有一遍，⛔ 无一致性系数。** ⭐ 每条只有一个裁定者，⛔ 没有第二人独立复判，⛔ 因此**测不出裁定者间一致性**。⭐ 本轮用「机械判别线复算」替代（§3），⛔ 但那测的是「是否可被正则复现」，⛔ **不是**「换个人会不会判一样」。
2. ⛔ **`abstract_only` 与 `metadata_only` 的条目未取全文。** ⭐ Q2 的 63 篇里有 22 篇（17 + 5）。⛔ 凡要写进论文的，必须重取一手原文逐条核。
3. ⛔ **两篇关键工作全文未取到**：SoSyM 2026（cookie 墙）、Li & Zheng IET Software 2025（付费墙）。⭐ 已写进 [c3_differentiation.md](./c3_differentiation.md) 的 Limitations 建议。
4. ⚠️ **提取与裁定都是 LLM。** ⛔ 本轨没有人工独立复核层 —— ⭐ 机械核验管住了「引文是否真实存在」，⛔ 但「这句话算不算义务」这一层，全链条都是模型判断。
