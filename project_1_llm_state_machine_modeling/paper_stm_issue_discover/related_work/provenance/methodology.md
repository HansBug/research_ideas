# L2 的调研方法：编制、判据、以及为什么这样做

> **这份文件回答「结论是怎么得来的」**，⛔ 不给任何结论。结论在 [predicate_provenance.md](./predicate_provenance.md)（Q1）、[c3_differentiation.md](./c3_differentiation.md)（Q2）与 [corpus_scan_findings.md](./corpus_scan_findings.md)（语料层发现）。

> ⭐ 它存在的理由：本轨的结论**大量依赖 subagent 的判断**，⛔ 而「几十路 agent 说了什么」本身不是证据。⭐ 使这些判断可审计的，是下面这套编制与判据。

## 2. ⭐⭐ 物理拆分做在**语料层**，⛔ 不是文档层

⛔ [CONTINGENCY_L2.md](../CONTINGENCY_L2.md) §0.1 要求把材料切开，理由是实测：**约定式隔离（禁读名单 / 「读到此为止」）合规率 0/2，物理拆分 2/2**。⛔ **「我不去看后果那部分」是约定，不是隔离。**

⭐ 本轮的落法比切文档更彻底：

1. ⭐ 每路提取 agent **只拿到一个分片文件**，⛔ 它看不到全局。
2. ⛔ 它的 prompt 里**既没有各谓词缺多少源，也没有任何数量指标** —— 逐字写着「本任务**没有数量指标**，提交 0 条和提交 20 条同样合格」。
3. ⭐ 结果：**提取者根本不知道哪条谓词证据稀薄，也就无从为它凑数。**

⚠️ **二轮定向扫描确实告诉了 agent 要找哪 7 条谓词**（否则无法定向），⛔ 但同样没给数量目标，⭐ 且额外写了「你这一路交 0 条是完全正常、完全合格的结果」，并要求把**拒收的边缘案例逐条记进 `notes`**。⭐ 那份拒收清单（14 万字符）才是「这类义务确实稀少」这个结论的证据主体。

## 3. ⭐⭐ 裁定层是独立误差源：逐条从严，⛔ 且不是关键词匹配

⛔ 裁定者的立场被写死为**怀疑者**，⛔ 不是复核者：「⚠️ **不确定时一律判不通过**」「⭐ 审稿人只要抽查到一条出处是错的，会连带削弱另外几条」。

### 【实测】裁定结果

| 批次 | 送审 | ACCEPT（含改判） | 存活率 |
| :-- | --: | --: | --: |
| 界内语料 · 首轮 | 299 | 132 + 改判 7 = **139** | ⭐ **46%** |
| 界内语料 · 二轮 | 16 | 3 + 改判 1 = **4** | ⭐ **25%** |
| ⭐ **界内语料 · 合计** | **315** | **143** | ⭐ **45%** |
| ⭐ **来源 C+D 文献** | **269** | **163** | ⭐ **58%** |

⭐⭐ **两批的严格度收敛，⛔ 而这不是设计出来的**：⭐ 语料层 **45%** 与文献层 **58%** 出自**不同的裁定者、不同的材料、互不通气**的两批 agent，⭐ 通过率量级一致。⚠️ 文献层略高是合理的 —— ⭐ 文献本来就是为「这类检查常见」写的，⛔ 而真实系统论文的语体不产生建模义务陈述（见 [corpus_scan_findings.md](./corpus_scan_findings.md) §发现 1）。

⛔ **文献层的拒收分布**：`QUOTE_DOES_NOT_SUPPORT` **43** · `TOO_GENERIC` **33** · `WRONG_PREDICATE` **17** · `OUT_OF_SCOPE` **2** · ⛔ 另 **9 条自证式取证剔除** + ⛔ **2 条改判目标不在 19 条词表内**（⭐ 后者本身是一个词表缺项信号，见 [SUMMARY.md](./SUMMARY.md) §4.5.4）。

⭐ **文献层的核心失败模式是「对应关系」而非「义务性」** —— ⭐ `TOO_GENERIC` + `WRONG_PREDICATE` 合计 **50 条**，⛔ 即「用宽泛类名把具体定义蒙过去」或「讲的是相邻但不同的事」。⚠️ 这与语料层的主要失败模式（叙述 vs 义务，129 条）**完全不同**：⭐ 两种材料的软肋不在同一处。

⛔ **首轮的主要失败模式（129 条 `REJECT_NARRATIVE`，43%）**：

| 失败模式 | 裁定者的逐字判据 |
| :-- | :-- |
| **把成就动词与副词当模态** | 「提取者反复把 `ensures` / `enforces` / `secures` / `allows` / `is designed as` / `immediately` 登记为义务词，⛔ 而这些词只描述作者的**设计达到了什么效果**」 |
| **看到 `until` 就盖章** | 「提取者事实上把『引文里有 until』当成了 `persists_until` 的判据，⛔ 而这些 `until` 全部出现在**动作时序走查**里」 |
| **把实现报告里的好性质当不变式** | 「死掉的 6 条内容形状确实都是 invariant 的形状，⛔ 但句子一律是**完成时/结果式的实现叙述**」 |

### ⭐ 裁定层自身的可靠性审计（双向，⛔ 不是单向找更多 ACCEPT）

⛔ 「裁定太严所以放宽」是**评测口径迁就结果**（根 [CLAUDE.md](../../../../CLAUDE.md) §3.5 第 4 条）。⭐ 正确的动作是**测裁定层本身**：

【实测】用一套机械正则（真模态 + 禁止式 + 中/印尼/德语义务词）复算裁定者自述的判别线，与裁定结果的一致率 **187/299 = 62.5%**。⛔ **这个数不说明裁定不一致** —— ⭐ 它说明裁定**不可被正则复现**：

- **74 条**机械上无硬模态，⭐ 裁定者仍判 ACCEPT（如「no car **is allowed** to enter」「the door **will only open if**」——⛔ 我的正则漏配，⭐ 裁定者读懂了）
- **38 条**机械上有硬模态，⛔ 裁定者仍拒（如「the automata **shall** be translated into a NuSMV program」——⭐ 主语是**研究流程**，不是被建模系统）

⭐ **结论：裁定层在两个方向都做了语义判断，⛔ 它不是关键词匹配器。**

### ⛔⛔ 一个必须记住的红旗：**提取者的自证套路本身可被证伪**

⚠️ 二轮裁定者发现：`why_not_narrative` 字段里反复出现一个论证 ——「**作者在同一段刻意把某句升格为强模态、别处都没有**」。⭐ 裁定者逐条回原文核对，**该论证在 3 处不成立**：

| 条目 | 提取者说 | ⛔ 回原文的事实 |
| :-- | :-- | :-- |
| S-5 | 作者刻意换成 `must` | ⛔ 同一清单的兄弟条目写的是 "**needs to** reduce" —— ⭐ 同为模态 |
| S-13 | 作者只在此处升格为 `has to` | ⛔ 同段另有 "These analyses **have to be** carried out" |
| S-6 | 作者刻意用 `should` 作对照 | ⛔ 兄弟条目讲的是**进入条件**、句式本就不同，⛔ 构不成对照 |

⛔ **这个套路专门用来抬置信度**（S-5 因此被标成 `high`）。⭐ 后续同口径提取时，它必须被列为**红旗措辞**：⛔ 不得凭该论述本身给分，⛔ 必须回原文复核。

### ⭐ 另一个机制性观察：**产出会漂向判据最松的谓词**

【实测】二轮 16 条里 `effect_declared` + `state_declared` 占 **11 条（69%）**，⛔ 而 `containment` 与 `variable_delta_after` **各 0 条**。⭐ 裁定者的解释：

> 「真实语料里层次归属与『执行后变量已变为某值』并不比效果声明罕见到这个程度；⭐ 更可能的解释是：这两条谓词的**判据紧、套不上去**，于是产出全部漂到了两条**判据最松**的谓词上。」

⛔ 由此该裁定者给出两道补充硬门（⭐ 已采纳，写进后续提取口径）：**(a)** 义务对象必须是**模型元素**（状态/变量/迁移），⛔ 不是被控物理量；**(b)** 必须有**迁移或进入锚点**，「during / in this mode」只能记 `invariant`。

## 4. 机械核验：⛔ 只做定位，⛔ 不做裁定

⭐ 按仓库纪律〈机械代理只能定位不能裁定〉，工具回答「这句话在不在那里」，⛔ **不回答**「它算不算义务」。

| 工具 | 【实测】结果 |
| :-- | :-- |
| [verify_quotes.py](./tools/verify_quotes.py) | ⭐ **315 / 315 逐字命中**摘录节，⭐ **0 条 `WRONG_SECTION`**（⛔ 没有一条拿我们自己写的转述节当外部依据） |
| [verify_citations.py](./tools/verify_citations.py) | ⭐ Q2 的 63 条引用：**OK 57 · TITLE_MISMATCH 2 · NO_USABLE_IDENTIFIER 2 · REACHABLE_URL 2**。⭐ 两条 `TITLE_MISMATCH` 逐条查过，⭐ **都是声称标题为解析标题的前缀，⛔ 不是幻觉**。⭐ **结论：零幻觉引用** |

### ⚠️ 两个工具缺陷，⛔ 已修，⭐ 留痕以免复发

1. ⛔ **`verify_quotes` 首版按 directory 建条目索引** —— ⚠️ 而 3 个目录各含 2 个界内条目，第二个被覆盖，⛔ 导致 3 条**合法**引文被误判 `NOT_FOUND`。⭐ 改为扫全文件所有条目的节：⭐ 节位合法性只取决于**节号**，⛔ 与条目无关。
2. ⛔ **`verify_citations` 首版 DOI 优先** —— ⚠️ 于是对 arXiv 论文拿 `10.48550/*` 前缀去查 **Crossref**，⛔ 而那是 **DataCite** 的地盘，必然查不到。⚠️ 叠加一个环境事实：**`export.arxiv.org` 的 API 在本机不可达**（12 s 超时），⛔ 而 `arxiv.org/abs/` 与 DataCite 都通。⭐ 改为 DataCite 优先 + abs 页兜底，⛔ 并在解析不到时退一步测 URL 可达性 —— ⭐ **「我们的解析器不认」与「这篇不存在」是两回事**，⛔ 混淆的代价是把幻觉审查变成噪声。

## 4.5 ⛔⛔ 自证式取证：⭐ 一条个案被泛化成全库机械排查

⚠️ 一路裁定者发现某条目引 `arXiv:2604.00275` 作**独立文献**，⛔ 而它在本仓库里登记为**种子语料来源**（`corpora/seed_library/sefm-llm-state-machine`，评级 `SS-A strict seed`）。⛔ 用被评测对象自身证明「这类检查在领域里常见」是**自证式取证**（根 [CLAUDE.md](../../../../CLAUDE.md) §3.5）。

⭐ 我把它泛化成了 [detect_self_citation.py](./tools/detect_self_citation.py)。⛔ **结果分三层，⛔ 后果完全不同，⛔ 不得一概而论**：

| 层 | 是什么 | 【实测】 | 处置 |
| :-- | :-- | --: | :-- |
| ⛔⛔ **seed** | `corpora/seed_library/` —— 本研究 NL+STM 对的**来源池** | **9 条**（`sefm-llm-state-machine` 7 + `designing-fsm-gpt4` 2） | ⛔ **剔除**：用自己的数据源证明自己的谓词该存在，是自证 |
| ⚠️ **baseline** | `baselines/` —— 本文定位为对照 / 相关工作的论文 | **7 条**（`sysmbench` 4 + `3gpp-extraction` 2 + `agentic-flow` 1） | ⭐ **保留但必须标注** —— ⭐ 引它说「该领域确实这么做」是正当的相关工作用法，⛔ 但不得混在独立文献里不作声 |
| ✅ **一般收藏** | `state_machine_types/` 等领域文库 | — | ✅ **无问题** —— ⭐ 一篇论文碰巧被我们收藏，⛔ 不使它变成「我们的」 |

⭐ **一处必须澄清的量级**：v46 的 54 pair **全部**来自 `llms_emp_feedback_final_*`（Wang et al., Internetware 2025），⛔ **不是**来自上述两个种子源 —— ⭐ 所以它与**被测数据**没有直接循环。⚠️ 但它们确实登记在我们的种子池里，⛔ **审稿人查得到**。

⚠️ **首版探测器过度触发，⛔ 这个教训值得记**：它拿目录里**全部文本**的 DOI 做匹配，⛔ 于是把 `DESC.md` **参考文献列表**里的 Harel 1987 也算成「我们的」—— ⭐ 那是彻底的误报，⛔ **而误报会把真问题淹掉**（38 条命中里有 22 条是噪声）。⭐ 已改为只认该目录 `bibtex.bib` **第一条 entry** 的 title / doi / eprint。

## 4.6 ⚠️ 一条小教训：⛔ 别用临时正则替代仓库已有的检查器

⭐ 交付前我用一段临时正则扫失效相对链接，⛔ 它报出 [../../TODO.md](../../TODO.md) 有一条 `...x.md` 死链。⚠️ **那是误报** —— ⭐ 那个字符串在**行内代码**里（`` `[X.md](...x.md)` ``），⛔ 它本身就是该 TODO 条目用来**举例说明误报**的。

⭐ 而仓库早有 [tools/check_md_links.py](../../../../tools/check_md_links.py)，⛔ 它专门修过三类缺口，**第三类逐字就是**「行内代码误报 —— 反引号里引用链接语法本身不再被当成真链接」。⭐ 换用它之后：`related_work/` **失效引用 0 条**。

⛔ **教训**：⭐ 现成的检查器修过的坑，⛔ 临时正则会一个个重踩。⚠️ **附带一条自嘲**：⛔ 我在写上面这一段时**自己写了个死链**（`tools/check_md_links.py` 的相对层级多算了一级）—— ⭐ 而它是被这个检查器抓到的。⚠️ 而该 TODO 条目自己写了这三类缺口的共同后果 —— 逐字：「**这三个缺口的共同后果是『零死链』被反复误读为『引用都有效』**」。

## 4.7 ⭐ 代码侧注释的泄漏审查（⛔ 按根 `CLAUDE.md` §3.5「审查范围是全部进入模型的文本」）

⭐ 本轮往 `predicates.py` 的词表定义点加了 **19 条 `#: universality:` 注释**。⛔ 按纪律必须审它们会不会泄漏：

| 审查项 | 【实测】结果 |
| :-- | :-- |
| ⭐ **会不会进 prompt** | ⛔ **不会。** 它们是 **Python 注释**，⛔ 不是 `Predicate` 的任何字符串字段 —— ⭐ 机械核对：19 条谓词的 `meaning` / `proves` / `strength` / `procedure` / `nl_index` / `nl_cue` 里**无一含 `universality` 字样** |
| ⛔ **有没有样本特定信息** | ⭐ **没有。** ⚠️ 机械扫出 `0001` / `0009` / `0049` / `0096` 四处数字命中，⛔ 逐条回原文核实**全部是 DOI 片段**（`10.1007/s10009-007-0049-7` · `10.1016/S0096-0551(01)00016-9`），⛔ 不是 pair id |
| ⭐ **内容是什么** | 三类归属 · 独立来源数与领域数 · 2 个代表来源（含 DOI/arXiv）· 该谓词的扣分项 · 指向证据表的锚点 —— ⭐ 全部是**关于文献的事实**，⛔ 无一条关于某个 pair |

⚠️ **为什么这条要单独审**：⛔ 按 §3.5.-1，泄漏可以表现为「不含任何台账标识符的**答案形状**」。⭐ 而 `#: universality:` 的内容恰好是「这类检查在领域里常见」这种**关于领域的一般事实** —— ⛔ 它不告诉模型任何一个具体样本该报什么。

## 4.7b ⭐⭐ 引用真实性核验：⛔ 抓到一处伪造 DOI，⭐ 其余 182 条无第二处

⚠️ ⛔ **这个缺口是敌意评审点出来的**：`verify_citations.py` 此前**只跑过 Q2 的 63 条**，⛔ 而 Q1 / C+D 的证据基**从未跑过** —— ⭐ 于是「零幻觉引用」这句话的覆盖面比读者会以为的小得多。⭐ 2026-08-12 已补跑全部 **183** 条外部证据（⭐ 108 个唯一 canonical key）。

| 结果 | 条数 | ⭐ 我的逐类裁定 |
| :-- | --: | :-- |
| ⛔ `DOI_NOT_RESOLVED` | **1** | ⛔⛔ **真问题**：`10.1109/32.503933` 在 Crossref 上返回 `Resource not found`。⭐ 真实 DOI 为 `10.1109/32.508311`（⭐ 题录逐字吻合：Heimdahl & Leveson, TSE 22(6):363-377, 1996）。⭐ 已修 |
| ⚠️ `URL_UNREACHABLE` | 9 | ⚠️ **不可独立核验**：⭐ 主要是 MathWorks / Stateflow 官方文档，⛔ 该站阻断自动访问。⛔ 不是伪造证据，⛔ 但也不构成已核验 |
| ⭐ `NO_USABLE_IDENTIFIER` | 12 | ⭐ **非缺陷**：⭐ 本地抽取全文路径（`/tmp/l2/recover/...`），⛔ 工具无从解析；⭐ 裁定时由裁定者直接读文件逐字核过 |
| ⭐ `TITLE_MISMATCH` | 2 | ⭐ **非伪造**：⭐ 一条是论文题名含副标题（`P: Safe Asynchronous Event-Driven Programming` vs Crossref 的 `P`），⭐ 一条是引了在线库名而 DOI 指向对应论文 |
| ⭐ `YEAR_MISMATCH` | 2 | ⭐ **非伪造**：⭐ 两条 `sim = 1.0`（题名完全一致），⭐ 预印本年 vs 出版年之差 |

⭐⭐ **结论**：⛔ 除那一处伪造 DOI 外，⭐ **没有第二处不可解析或题录不符的引用**。

⛔⛔ **但这件事的教训比结果重要**：⭐ 那个假 DOI **是随一条已通过对抗裁定的证据进来的** —— ⭐ 也就是说**裁定层不核验引用真实性**，⛔ 它只判「这句话是不是这个意思」。⭐ 两层职责不同、⛔ 缺一不可：

| 层 | 答什么 | ⛔ 不答什么 |
| :-- | :-- | :-- |
| ⭐ 机械核验（`verify_quotes` / `verify_citations`） | ⭐ 这句话在不在那里 · ⭐ 这个标识符解析得开吗 | ⛔ 它算不算义务 · ⛔ 它是不是这条谓词 |
| ⭐ 对抗裁定 | ⭐ 它算不算义务 · ⭐ 它是不是这条谓词 | ⛔ **这个 DOI 是真的吗** |

⛔ **两层都跑过，才叫核验过。** ⚠️ 本轮之前只跑了一层。

## 4.75 ⛔⛔ 新失败模式：**引文截断点系统性地落在原文自我限定处**

⚠️ 【实测】2026-08-12 补强轮的裁定抓到**两处互不相识**的同型缺陷 —— ⭐ 提交者的 `[…]` **恰好吞掉削弱己方主张的那半句**：

| 条目 | 被引到的部分 | ⛔ 被吞掉的紧邻下一句（⭐ 我已回原文逐字复核） |
| :-- | :-- | :-- |
| ⭐ OORTs Reading 7（`cardinality`） | 「⭐ …If not, then information has been **omitted** from the design」/「…information in the design is **extraneous**」 | ⛔ 「**If so, then make sure this combination makes sense**」/⛔「**If so, make sure that this split makes sense**」—— ⭐ 原文**明确允许**图上状态数不等于 N |
| ⭐ Heitmeyer TOSEM 1996（`guard_distinguishable`） | 「⭐ our tool found **57 Disjointness errors**」 | ⛔ 「**Although many of the 57 instances … are undoubtedly errors, a few probably are not**, since some detected events may be impossible」 |

⛔⛔ **两处的后果不同，⛔ 但机制相同**：⭐ 前者**直接推翻**了提交者的核心论证（「双向卡死 / 恰好相等」）；⭐ 后者只是须把「57 例确诊」降级为「57 例报出、作者判定多数确为错误」。

⭐⭐ **为什么必须单独立一条**：⛔ 这个模式**对机械核验完全免疫** —— ⭐ 被引的每一个字都是真的，`verify_quotes.py` 会全部判 `FOUND`。⛔ 它也不同于 [§3 已记的「自证套路」](#-一个必须记住的红旗提取者的自证套路本身可被证伪)（⭐ 那是提交者**为自己辩护的措辞**可被证伪）；⭐ 这一条是**引文边界的偏置**，⛔ 与措辞无关。

⭐ **可执行的对策**（⛔ 裁定者已自发做到，⭐ 应固化为要求）：⛔ 凡引文含 `[…]` 或止于句号前，⭐ 裁定者**必须把被省略处与紧邻下一句读出来**。⭐ 三位 `cardinality` 裁定者里，抓到 OORTs 那处的那位自陈逐字：「⭐ **转折点在于我没有停在提交者引到的地方**」。

⚠️ ⛔ **我自己也栽在这一处**：⭐ 那段全文当时就在终端输出里，⭐ 我读了却只引前半，并据此对外说过「双向卡死」。⛔ 这说明该对策**不是**给 subagent 的额外要求，⭐ 而是给**任何**引用者的。

## 4.8 ⛔⛔ 一个**同型复发**的流程缺陷：判例清单挂在「路」上，⛔ 而不是挂在「谓词」上

⚠️ 【实测】MAAB `db_0137` 在 2026-08-12 的补强轮被**第三次**提交给 `cardinality`。⛔ 它前两次都被拒过，⭐ 第二次那回本身就已经是「已拒条目的逐字重投」（[SUMMARY.md](./SUMMARY.md) §4.1 已记）。

⭐⭐ **根因这次查清了，⛔ 且它不是「提交者不认真」**：

| 路 | ⭐ 是否收到 `cardinality` 的判例清单 | 结果 |
| :-- | :-- | :-- |
| `new-cardinality` | ⭐ **收到**（prompt 里逐条列了「已试过且确认无效的方向」，含 `db_0137`） | ⭐ **主动挡掉两条 SCR 候选**，自陈逐字「⭐ 重复提交等于重复挨砍」 |
| `new-smell` | ⛔ **没收到**（它的 prompt 只点名了自己那 5 条谓词的目标） | ⛔ 提交了 `db_0137`，⚠️ 并顺手提交了一条不在自己点名清单内的 `initial_target` |

⛔⛔ **缺陷的形状**：判例清单**按路分发**，⛔ 而提交是**跨路溢出**的 —— ⭐ 一路完全可能为不在自己点名清单内的谓词提交证据（⭐ 上表右下角就是活例，⛔ 且那条提交本身是**诚实且合理**的）。⭐ 于是「⭐ 给负责该谓词的那一路发判例」这个做法**在结构上就挡不住重投**。

⭐ **正确形态**：⛔ 判例清单必须**挂在谓词上**，⭐ 任何一路只要**可能**为谓词 P 提交，就必须拿到 P 的全部既往判例。⭐ 工程上最省事的落法是把判例做成一份**按谓词索引的单一文件**，⭐ 所有检索路统一附上，⛔ 而不是在每路 prompt 里手写摘要。

⚠️ **这与 [rule_provenance.md](../../discover_matrix/docs/protocol/rule_provenance.md) 记的「⛔ 按文件名通配永远漏，⭐ 要按目录」是同型错误**，⭐ 也与根 `CLAUDE.md` §11 的「⛔ 按形态列举永远漏」同型：⛔ **凡是靠「我列全了」来保证覆盖的机制，都会在实际发生跨类溢出时失效。**

⭐ **一点公平话**：⛔ 第三次这一投的**主张形态**比前两次弱得多 —— ⭐ 提交者只主张「⭐ 计数并对该数值下判断是工业指南里的常规条目」这一存在性事实，⛔ 并明确自陈「⛔ 我不主张它支持『恰好为 N、N 取自需求文本』」。⭐ 所以它**未必**应当以「重投」为由直接拒；⭐ 该由裁定者按弱命题独立判。⛔ 但「⭐ 提交者不知道它被拒过两次」这件事本身仍是缺陷。

## 5. ⛔ 计数口径

| 项 | 口径 |
| :-- | :-- |
| **计数单位** | ⭐ **互相独立的真实系统 / 独立文献**，⛔ **不是条目数**。⚠️ 否则同一篇论文摘三句就能自己满足「多源」 |
| **下限 / 上限** | ⭐ **≥ 3 个独立来源**为下限（policy §一.5）；⛔ **无上限**。⭐ 本轮另设 **≥ 6** 为目标档 |
| **领域多样性** | ⭐ N 个源须覆盖 $\min(3, N)$ 个以上不同领域；⛔ 若只在单一领域出现，**必须显式说明**并把主张限定到该领域 |
| ⛔ **不报比例** | ⛔ `sources/` 的收录标准恰好选中了要测的那个性质 —— ⛔ 任何 K/N 都是**在因变量上做选择**。⭐ **787 / 715 / 313 都只是库存量，⛔ 一个都不是分母** |
| ⚠️ **来源独立性的已知折扣** | ⚠️ C+D 的一路主动坦白：「12 条…⛔ 但**真正互相独立的研究组只有约 8 个**，其中 NASA Ames 两条与 York/Manchester 两条存在方法学与工具链上的相关性，⛔ **请勿把 12 当成 12 个独立观测**」。⭐ 这类折扣逐条记在 [predicate_provenance.md](./predicate_provenance.md) 的备注列 |

## 6. ⛔ 已知的方法局限（⚠️ 必须与结论一起读）

1. ⚠️ **裁定层基本上只有一遍。** ⭐ 绝大多数条目只有一个裁定者，⛔ 没有第二人独立复判。⭐ 本轮用「机械判别线复算」测了它**不可被正则复现**（§3），⛔ 但那测的是「是否可被正则复现」，⛔ **不是**「换个人会不会判一样」。

   ⭐⭐ **一处更正（2026-08-12）**：本条上一版写「⛔ 因此**测不出**裁定者间一致性」—— ⭐ **现在测出来了一份**，⛔ 而且是白捡的：⭐ Q2 去重时发现 **8 篇被 ≥2 路各自判过**的论文里，**7 篇至少有一个轴判定不一致**。⛔ 这份数据的**性质要说准**：⭐ 全部分歧都是**相邻档**（`no`↔`partial`、`partial`↔`yes`、`*`↔`unclear`），⛔ **没有一处是决定性轴上的 `yes` vs `no`**；⭐ 且**在任何一路的判定下都是 0 篇三要素全中**。⭐ **所以头结论对分歧稳健，⛔ 逐篇分档不稳健** —— 逐条见 [c3_differentiation.md](./c3_differentiation.md) 开头〈更正 2〉。
