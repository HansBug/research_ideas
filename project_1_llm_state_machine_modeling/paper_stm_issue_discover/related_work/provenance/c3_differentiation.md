# Q2 · C-③ 差异化：LLM 之后的错误上下文与证据链

> **回答的问题**：contribution ③ 的证据链体系，在 LLM 之后还站得住吗、站在什么形状上。
>
> **档位标记**：全文除标注为【实测】者外，均为【AI 建议·待确认】。⛔ 本文件不给任何强度断言。

## 结论先说：⛔ **C-③ 的原形状撑不住，必须收窄**

⭐ **六路独立调研（63 篇工作）一致收敛**：

| 判定 | 结果 |
| :-- | :-- |
| ⭐ **三要素全中的强竞品** | ⭐ **0 篇** |
| ⚠️ **恰好中两项的** | **15 篇**，⛔ 且三种缺法都有实例 |
| ⛔ **「锚回需求」还能不能当卖点** | ⛔ **不能。** 它在 LLM 之后**已被做到**，⛔ 且不止一篇 |
| ⛔ **「有没有证据链」还能不能当卖点** | ⛔ **不能。** 用户口径本就是「前 LLM 时代肯定有人做过」，⭐ 而本轮确认 LLM 之后也有 |
| ⭐ **唯一空缺** | ⭐⭐ **(iii) 可被第三方独立重算的谓词求值记录** |

⛔ **由此，C-③ 的差异化重量必须整体迁移到 (iii)。** ⚠️ 一路的逐字判断：「⛔ **不能再以「锚回需求」或「锚到元素」为卖点**」。

⚠️ **同时，⛔ 不得写成「LLM 之后无人做到」** —— 一路被付费墙拦在摘要外（Li & Zheng, IET Software 2025），⭐ 它自己的判断是：「它的四个特征足以在读到全文前否掉『LLM 之后无人做到』这种断言」。⛔ 只能写成带覆盖范围声明的可证伪命题（伞 PR §4.2 #8）。

---

## 三要素的定义（⛔ 判定全部按此）

C-③ 承诺**每条报告项同时携带**：

- **(i) 需求原句锚点** —— 这条发现来自 NL 需求的**哪一句**
- **(ii) 模型元素锚点** —— 它绑在模型的哪个状态 / 事件 / 迁移 / 变量上
- **(iii) 可独立重算的求值记录** —— 用**哪条具名谓词、什么参数、求值为假**

---

## 【实测】战况：三要素逐项

| 要素 | ⭐ 做到它的最强工作 | 后果 |
| :-- | :-- | :-- |
| **(i) 需求原句锚点** | ⭐⭐ **MCeT**（arXiv 2508.00630, 2025）—— 每条 requirement-atom issue 绑一条原子需求；⭐ **Matei et al. 2026** —— 摘要逐字「maps that logic back to **verbatim narrative segments**」、方法节「Each ambiguity instance is mapped to its **exact location in the source narrative**」 | ⛔ **单独不可作新颖点** |
| **(ii) 模型元素锚点** | ⭐⭐ **SoSyM 2026**（DOI `10.1007/s10270-026-01388-4`）—— 依赖图顶点**就是 states 与 transitions**；⭐ **MODELS '24**（DOI `10.1145/3640310.3674079`）—— 形式规则违规消息点名具体 Actor / Block | ⛔ **单独不可作新颖点** |
| ⭐⭐ **(iii) 可独立重算的求值记录** | ⛔ **一篇都没有** | ⭐⭐ **差异化的全部重量在这里** |

⚠️ **(iii) 的两个「最接近」为什么都不算**：**SoSyM 2026** 的图遍历判据确定、可重跑、有双射证明，⛔ 但它**不是逐条报告项随身携带的求值记录**；⛔ 且其 LLM 通道摘要自陈 "produces both false positives and false negatives"。**N-Check**（ICSE 2024）的诊断从 UNSAT 因果证明算出、可重算，⛔ 但被分析对象是**规则集自身**，⛔ 完全没有系统模型、无状态/迁移可锚。

## 【实测】三条已知反例：⛔ 逐条给原文定位

⛔ 伞 PR §4.6 Q2 明令这三条必须正面处理。⭐ 三条**全部找到了原文定位**。

### ⓵ 反例：模型检查器的反例轨迹本身就是极强的上下文

⛔ **不可接受的应答**「反例轨迹不算上下文」—— **这是假的**。⭐ **真正的差异在上下文指向哪一端。**

⚠️ **本轮最大的威胁是 SynthTL（FMCAD 2024）**，⛔ 它把「需求侧那一跳」做掉了：culprit identification 用模型检查器**机械算出**哪些 sub-translation 导致规约在 DUT 上失败，而每个 sub-translation 的一端是输入 NL 的 **strict substring**。

⭐ **它缺的是 (ii) 与自包含的 (iii)**：报告项不带模型元素锚点 —— 修法出口逐字写成 "sub-translations / decompositions / **or the DUT, as appropriate**"，⛔ 到底哪个设计元素有问题**留给人判断**；且整条链的可信性依赖 "the oracle to inspect each node" 的人工签核。

### ⓶ 反例：已有文献把状态图改动反向映射回需求

⛔ **不可接受的应答**「没人做过」。⭐ **真正的差异落在输出单位，⛔ 不是含糊的「粒度」二字**：

| 工作 | ⭐ 输出单位（逐字） | 每项随身携带什么 |
| :-- | :-- | :-- |
| Nejati, FSE 2016 | 「an estimated **set** of impacted model elements」+ 按「a quantitative measure designed to predict **how likely** it is」排序 | ⛔ 一个 likelihood 分数 |
| Ben Charrada, 2015 | 「a **list** of requirements that are **sorted according to their likelihood** of being impacted」 | ⛔ 一个 likelihood 排名 |
| ProReFiCIA, 2025 | 「impacted ReqID: `<ID>` justification: `<text>`」 | ⛔ 一段 LLM 自由文本 |
| Kretschmer, 2021 | 模型内部的 repair 序列（⭐ 标题即 *within models*） | ⚠️ OCL validation tree（**可重算**，⛔ 但两端都在模型内） |

⭐ **可写的可证伪命题**：这一族的输出是「**集合 + 可能性排序**」，⭐ 每一项随身携带的是一个**分数**或一段**自由文本**；⛔ 不存在「一条发现 → 一句需求 + 一个模型元素 + 一次可重算求值」这种三元组。⭐ **这个说法不比优劣，只陈述输出形态**，且每一句都能指回上表原文。

⚠️ **另一条同族的、⛔ 更接近的**：SoSyM 2026 确有「模型元素 → 需求侧制品」的反向映射，⛔ 但**回指的对象是 use case**（分析级制品），⛔ **不到原句级**。

### ⓷ 反例：已有工作为报告项提供 provenance

⛔ **不可接受的应答**「我们的 provenance 更好」（伞 PR §4.2 #7 禁止把「不同」写成「更好」）。⭐ **真正的差异在 provenance 的两端是什么。**

⭐⭐ **MODELS '24 是全轮最有用的一条原文定位**，⛔ 因为它把三要素沿**两条通道**切得一刀见骨：

| 通道 | 逐字证据 | ⛔ 缺在哪 |
| :-- | :-- | :-- |
| **形式规则通道** | 违规消息是元素级的（RU8：「Actor "Azimuth_Thrusters" **must be connected to at least one use case**」），判据是形式表达式、可重算 | ⛔ **它是图内 well-formedness，两端都在模型侧**，⛔ 与需求原句无任何关系 |
| **LLM 通道** | 输出 schema 逐字只有两个字段：`{"diagram": "diagram1 or diagram2", "description": "..."}` | ⛔ `diagram` 的取值域是**字面的** "diagram1 or diagram2" —— ⛔ **连元素名都没有，粒度是整张图**；`description` 是自由散文 |

⭐ **它对 C-③ 的意义**：既有工作把**可重算判据**与**元素锚点**都做到了，⛔ **但报告项的两端都在模型侧**。⚠️ 并且：论文 §5.1.3 逐字说 LLM 请求里确实附了 system specification 作上下文，⛔ **但逐条 issue 没有指回规范任何一句的字段** —— ⭐ **有上下文 ≠ 有锚点**。

⚠️ **W3C PROV-DM 那一端**同理：它记录的是「哪个 activity 产出了这个 entity」（⛔ 工具内部谱系），⛔ 不是「需求原句 ↔ 模型元素」这种跨制品语义锚点。
