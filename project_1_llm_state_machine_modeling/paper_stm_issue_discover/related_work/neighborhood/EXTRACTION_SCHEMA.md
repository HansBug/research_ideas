# L3 卡片抽取 schema

⭐ 每篇成档的工作写一份 `cards/<slug>.md`，按本文件的 A–F 六节。⛔ 字段缺失一律写「**原文未提供**」，⛔ 不得留空、⛔ 不得脑补。

---

## ⛔ 三条通用纪律

1. ⭐ **每条断言标证据级别**：
   - **M**（Manifest）= 原文明写，⛔ **必须附逐字英文片段**
   - **S**（Supported）= 原文可直接推出，⭐ 说明从哪一段推的
   - **I**（Inferred）= 我方推断 —— ⛔ **标 I 的不得写成事实句**，要写成「看起来 / 推测 / 未明说」
2. ⭐ **「原文未提供」是一个有信息量的答案**，⛔ 比猜一个像样的答案有价值得多。
3. ⛔ **引用必须真实存在**。⚠️ 本仓库栽过一次假 DOI（`10.1109/32.503933`，Crossref 404）—— ⭐ 教训是**裁定层不核验引用真实性**，所以引用要由写卡的人自己核。

| 字段 | 说明 |

## B. ⭐⭐ LLM 应用形态（本轨核心，⛔ 抽得越细越好）

### B1 · 流水线阶段

⭐ 画成一条线，每个阶段标执行者：

```
[人] 提供 NL 需求 → [LLM] 抽取实体 → [确定性] 语法校验 → [LLM] 生成模型 → [求解器] 检查 → [LLM] 修复
```

⭐ 记 **阶段总数** 与 **其中 LLM 阶段数**。

### B2 · 每次 LLM 调用的角色

⭐ 从这个词表选（可多选，⛔ 不在表里的自己加并说明）：

`生成器` · `抽取器` · `分类器` · `翻译器`（形式化转换） · `评审者` · `修复者` · `规划者` · `裁决者` · `解释者` · `检索改写器`

### B3 · prompt 策略

`zero-shot` · `few-shot` · `CoT` · `self-consistency`（多次采样投票） · `RAG` · `工具调用 / function calling` · `结构化输出约束`（JSON schema / 语法约束 / 受限解码） · `角色扮演` · `多智能体辩论`

⭐ **prompt 是否公开**要单独记（→ D 节）。

### B4 · ⭐⭐ 循环与裁决者（⛔ 本轨最关键的一格）

| 子字段 | 取值 |
| :-- | :-- |
| 有无循环 | 有 / 无 |
| ⭐ **裁决者是谁** | ⭐ `sound oracle`（模型检查器 / 求解器 / 类型检查器） · `parser / 编译器` · `测试执行` · ⛔ `LLM 自评` · `人` · `确定性规则` |
| 终止条件 | 收敛 / 最大轮数 / 预算 / 人叫停 |
| 最大轮数 | 数字或「原文未提供」 |
| ⭐ 有无报告**循环的边际收益** | ⭐ 有则抄下逐轮数字 —— ⛔ 这直接对照我们「第 3–5 轮零收益」那条发现 |

### B5 · ⭐ 中间表示

| 子字段 | 说明 |
| :-- | :-- |
| 有无 | 有 / 无（⭐ 「无」= LLM 直接从 NL 产出终态制品） |
| 形态 | DSL / pattern catalogue / 缺陷类型学 / 谓词族 / 中间 IR / JSON schema |
| ⭐ **是否闭合** | ⭐ 闭合（从固定集合里选） / 开放（自由生成） —— ⛔ 这直接对照我们的 19 条闭合词表 |
| ⭐ **谁定的** | ⭐ 预编目录 / LLM 生成 / 人从目录里挑 / 从语料归纳 |

### B6 · 模型

⭐ 具体型号 + 版本 + 年份（`GPT-4o (2024-05)` 这样）。⚠️ **这一条很关键**：X1 已证明 SOTA 与上一代不是一个量级，⛔ 用旧模型得出的结论参考价值要打折。⭐ 有无多模型对照也记。

### B7 · ⭐ 确定性成分

⭐ 流水线里**不是 LLM** 的环节有哪些（parser / 语法检查 / 类型检查 / 模型检查器 / 求解器 / 模板引擎 / 图算法）。⭐ 这决定这套方法有多少「可信底座」，⛔ 也是我们「裁决者换成 sound oracle」那条设计原则的直接参照。

## C. 实验

| 字段 | 说明 |
| :-- | :-- |
| `baseline` | ⛔ **无 baseline 也要写「无」** |
| `dataset` | 名称 / 规模 / 来源 / ⭐ 分母怎么定的 |
| `metrics` | 指标定义，⭐ 尤其看有没有 `@k` 之类的多轮口径 |
| ⭐ `judged_by` | ⭐ **判定谁做的**：作者 / 第三方 / 自动脚本 / ⛔ LLM-as-judge。⭐ 有无标注者间一致性（$\kappa$ 或一致率） |
| `human_baseline` | 有 / 无 |
| `runs` | 跑几次、报均值还是单次、⭐ 有无方差 |
| ⭐ `adverse_results` | ⭐ **不利结果怎么处理的** —— ⭐ 我们自己刚拿到 −15.82pp，⭐ 别人怎么写这类结果是直接可借鉴的 |

### 状态口径（⭐ 与 `baselines/SUMMARY.md` 保持一致）

| Emoji | 含义 |
| :-: | :-- |
| 🟢 | ⭐ **可直接获取，且本轮已实际核验可访问** |
| 🟡 | 需联系申请或存在非公开获取流程 |
| 🟠 | ⚠️ 信息不清、仅有间接线索、⛔ **或入口存在但内容是空壳** |
| 🔒 | 难以取得或明确不可公开（工业私有数据等） |
| ⚪ | ⛔ 原文明确未提供 / 不存在 |

⛔⛔ **「仓库存在」≠「🟢」。** ⚠️ 实例：`baselines/` 里 FlowFSM 的 GitHub 仓库存在，⛔ 但只有 `README.md` 和 `.gitignore`，README 写着 source code will be shared later —— ⭐ 判 🟠，并钉了 HEAD `4ab9aa4e…`。⭐ **必须实际去取，不能只看链接在不在。**

## E. ⭐ 对 M1 的意义

三小节，⛔ 每节至少一条，⛔ 说不出就写「⛔ 无」：

1. ⭐ **可取之处** —— 具体到「哪个设计决定可以搬」
2. ⛔ **不可取 / 陷阱** —— ⭐ 尤其：它有没有踩我们已经踩过的坑（自我批判 loop / 自由生成断言 / 无 sound oracle）
3. ⚠️ **与我们的关键差别** —— ⛔ 说明为什么它的做法不能直接照搬
