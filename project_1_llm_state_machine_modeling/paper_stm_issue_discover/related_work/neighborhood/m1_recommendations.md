## 1. ⛔⛔ R1 · 拆掉自评 reviewer，⭐ token 改花在「换粒度重问」

### 1.1 我方实测：⛔ 修订机器在做什么

⭐ 工具 [`tools/measure_revision_drift.py`](./tools/measure_revision_drift.py)，⭐ 跑在 v46 全部 **324 格**上（⭐ 其中 **217 格**有 ≥2 次 `convert_assertions`，⭐ 分母 **6084 条**断言）：

| 修订机器实际在干什么 | 数字 | 强度 |
| :-- | --: | :-: |
| ⭐ 断言 `expression` **全程一字未动** | **90.7%** | M |
| ⛔ 编辑里**只改散文字段**（`description` / `rationale` / `failure_message`） | ⛔ **69%**（3106 / 4519） | M |
| ⛔ 碰了 `expression` 的编辑里**回到旧值** | ⛔ **35.8%**（506 / 1413） | M |
| ⛔⛔ **换谓词时换回一个已试过的** | ⛔⛔ **43.7%**（392 / 898） | M |
| ⚠️ 修订期间**净删除**断言 | ⚠️ **−236**（删 428 / 增 192） | M |

⭐⭐ 这解释了 X1 那条「⛔ **79% 的 token 换来覆盖净变化 ≈ 0**」：⛔ **不是没干活，⭐ 而是干的活九成在改散文、剩下的三分之一在兜圈子。**

### 1.2 ⭐ 外部的正面对照：⭐ 同样是「多花 token」，⛔ 花法完全不同

⭐ MCeT（MODELS 2025）把额外 token **全部**花在**换输入切分粒度重问同一份制品**上，⛔ **从不让任何视角去修另一个视角的产物**：

| | ⭐ MCeT | ⛔ 我们 v46 |
| :-- | :-- | :-- |
| 额外 token 花在 | ⭐ **换粒度重问** | ⛔ **LLM 自我批判修订** |
| 倍数 | 6.7× | ⛔ **212.6×** |
| 换来 | ⭐ 召回 **34.1% → 68.1%**（⭐ 翻倍） | ⛔ **−15.82pp** |

⚠️⛔ **一处必须更正的流传数字**：⭐ MCeT 常被引作「precision 0.58 → 0.81」，⛔ **那把自一致性的贡献高估约 2.5 倍**。⭐ 论文 §VI-A 自己就拆开了：⭐ 加两个视角是 **0.58 → 0.72**，⭐ **交叉核查**才是 **0.72 → 0.81**。⭐ 自一致性的净贡献只有 **+0.09**。

### 1.3 ⛔ 具体怎么改

1. ⛔ **`review_requirements` 与 `review_assertions` 两个节点删除或改形态。** ⭐ X1 实测两者**零收益**。
2. ⭐ **改成「换粒度重问」**：⭐ 同一份制品 + 同一批需求，⛔ 但**换需求切分粒度**（⭐ 整条 / 原子 / 子句）各问一遍，⭐ 结果取并再去重。
3. ⛔⛔ **绝对不要让某一轮的输出去修另一轮的输出。** ⭐ 这是 MCeT 与我们最大的形态差别，⛔ 也是我们 43.7% 谓词兜圈子的来源。

## 2. ⭐ R2 · 收敛判据下沉到谓词层

⭐ ETFA 2025 的循环是**固定 20 轮无条件跑满**，⛔ 没有任何东西决定要不要再来一轮。⭐ 实测：⭐ 最优版在**第 11 轮**达到，⛔ **第 12–16 轮零改动** —— ⭐ ≥25% 的轮次纯烧钱且无人察觉。

⛔ **但「本轮零改动」这个判据在我们身上不管用**：⭐ 我们只有 59.7% 的断言在全字段上稳定，⛔ 每轮都有改动（⭐ 大多是散文）。

⭐⭐ **正确的判据是谓词层**：⛔ 当某条需求的谓词选择**换回一个已经试过的谓词**时，⭐ 说明这一格已经在兜圈子 —— ⛔ 再修下去期望收益为零。⭐ 这与仓库 §12「⛔ 采样不确定性不能用来掩盖结构性失败」是同一条纪律的另一个落点：⭐ **失败签名重复即结构性死路**，⛔ 而「谓词集合重复」就是这里的失败签名。

⭐ **实现成本近零**：⭐ 每条需求维护一个「已试过的谓词集合」，⛔ 命中即停。⭐ 按实测，这会拦掉 **392 次**无效编辑。

## 3. ⭐ R3 · 让 LLM 判的对象必须是 context-free 的

⭐ MCeT 报了一组**受控对照**（⭐ 同一套流水线、⛔ 只换被判对象）：

| 被判对象 | precision |
| :-- | --: |
| ⭐ **requirement-atom**（⭐ 自包含的一句需求） | ⭐ **0.86** |
| ⛔ **diagram-atom**（⛔ 一条迁移，⛔ 正确性依赖周边上下文） | ⛔ **0.50** |

⭐ 作者的归因逐字：⛔ 后者「正确性依赖周边上下文」。

⭐⭐ **这条对我们有一个可证伪的预测**：⛔ 我们的**结构族**谓词（`state_declared` / `edge_declared` 等）判的是**自包含**的事实，⭐ 而**仿真族 / BMC 族**判的是**依赖执行上下文**的事实 —— ⭐ 于是**后者的多报率应当显著高于前者**。

⚠️ **强度 I（待验）**：⛔ 这是我方推断，⛔ 不是实测。⭐ 但**可以在 v46 的五类多报分类台账上直接验**，⭐ 成本很低。⛔ **验之前不得当结论用。**

## 4. ⭐⭐ R4 · 把 sound oracle 移到裁决端 —— ⛔ **零先例**

⭐ 这是 M1 已确立的第二条设计原则。⭐ L3 的调研结果是：

| 已深读的工作 | 循环 | ⭐ 裁决者 |
| :-- | :-- | :-- |
| MCeT（MODELS 2025） | ⛔ 无 | ⛔ **LLM 自评**（⭐ 角色扮演的「资深工程师」单向否决） |
| ETFA 2025（STPA + FSM） | ⭐ 有（20 轮） | ⛔⛔ **无裁决者** —— ⭐ 固定轮数跑满 |
| ProtocolGPT（IWQoS 2025） | ⛔ 无 | ⭐ **确定性规则**（20 次采样，⭐ 保留 >80% 的） |
| SpecGPT（SECON 2026） | ⛔ 无 | ⭐ **确定性 span 匹配**（θ = 0.75）+ 多数票 |
| ⭐ **我们 v46** | ⭐ 有 | ⭐ **两者并存**（⛔ 2 个 LLM 自评 + ⭐ 2 个确定性） |

⭐⭐ **没有一篇把 sound oracle 放在裁决端。**

⛔⛔ **ProtocolGPT 那一行尤其刺眼**：⭐ 它的被测对象是**可编译、可测试的 C 代码**（strongSwan / s2n-tls / openbgpd），⭐ 编译器、测试、AFLNet **全都在手边** —— ⛔ **却全部被放在循环外面**。⭐ AFLNet 只是下游消费者，⛔ 它的覆盖率**从不回流**。

⭐ **两面读法**：⭐ ① 这条路**确实没人走过**，⛔ 于是它对论文是真差异化；⛔ ② **也没人证明它可行** —— ⚠️ 零先例既可能意味着「没人想到」，⛔ 也可能意味着「试过不work 所以没发表」。⛔ **M1 要为后一种可能留退路。**

## 5. ⭐ R5 · 覆盖账的三个零件，⭐ 两个已有先例

⭐ 我们 C-③ 要的东西可以拆成三个零件。⭐ SpecGPT（SECON 2026）已经做到了前两个：

| 零件 | ⭐ 先例 | 怎么做的 |
| :-: | :-- | :-- |
| **①** 规约侧的**锚点** | ⭐ **有** | ⭐ 每条迁移的 `condition` / `action` **必须是规约原文的逐字片段** |
| **②** **可机械枚举的遍历单元** | ⭐ **有** | ⭐ 遍历单元从**章节树**机械导出，⭐ 每个窗口**恰好访问一次** |
| **③** ⛔ **把「规约说了而模型没有」记下来** | ⛔⛔ **无** | ⛔ 缺口只在**评分时**以 FN 形式存在于 210 人时的金标里 —— ⭐ **流水线自己不知道漏了什么** |

⭐⭐ **结论**：⛔ **不是先例，⭐ 但是两个可搬的零件。** ⭐ 有了 ① + ②，⭐ 加一份「每个窗口 produced / empty」的账本就是 ③ —— ⭐ 工程量不大。

⭐ **额外收获**：⭐ 「逐字片段」这个要求把「**这两条是不是同一个发现**」从语义判断塌缩成**词法重叠** —— ⭐ 那正是我们 574 位人工判定里最贵的一部分的**机械替代品**。

## 6. ⛔⛔ R6 · 不要走「按样本手调」那条路

⛔ ProtocolGPT 的 `code_filter.py` 里有一份**按协议手写的正则字典**（⭐ 5 个键对应 6 个被测协议），⭐ 里面是 `RTSP_Server_State` / `L2TP_LAIC_STATE` / `fsm_table` 这类**实现标识符**，⛔ 不是 RFC 术语。

⛔⛔ **而消融实验把它记为全文最大的单项增益：precision +41.02pp · recall +55.57pp。**

⭐ 按本仓库 §3.5 的抽象化自检（⭐「把措辞抽象化后问：它表达的是通用原则，还是这个样本的答案」），⛔ **这落在「样本的答案」那一侧**。

⭐⭐ **两面的教训**：

1. ⭐ **它在那个邻域通过了评审** —— ⚠️ 说明这个领域对「按样本调参」的容忍度比我们自己设的线**宽得多**。
2. ⛔⛔ **我们仍然不能做。** ⭐ 我们**不设 hold-out**（见 [method_provenance_policy.md](../../discover_matrix/docs/protocol/method_provenance_policy.md)），⭐ 于是**没有任何东西能替我们挡下这个指控**。

## 7. ⭐ R7 · ensemble 是多报抑制器，⛔ 不是召回提升器

⭐ SpecGPT 的 `LLM ensembles` = **5 个不同厂商各跑一遍**（⛔ 不是同模型重采样，⭐ 自一致性被它列为 future work），⭐ 用确定性 span 匹配 + 多数票聚合。

⭐ **相对最好的单模型**：⭐ precision **+12.77pp** · ⛔ recall **−2.12pp**。

⭐⭐ **即它几乎纯粹是个多报抑制器。** ⭐ 这对我们有直接意义：⭐ 我们的五类多报分类是个真问题，⛔ 而**加轮次提召回**与**加模型压多报**是两件事，⛔ 不要混为一谈。

⚠️ **一处必须打折**：⛔ SpecGPT **单趟无重复运行**，⭐ 于是那 5–22pp 的 ensemble 增益**无法与单次采样噪声分离**。⛔ 且 θ = 0.75 是**在评测集上调的**，⭐ 同一个算子**既产出又评分**（⭐ 撞上本仓库 §3.5 第 4、5 条）。

## 8. ⭐ R8 · 成本必须报，⚠️ 但没有同行数字可比

⭐ 第三方 N=86 的 LLM4MDE 映射研究逐字：⛔ `only 21 papers evaluate the computational or financial cost of their approach, whereas 65 do not`。

⭐ 我们手上有 **212.6×**。⭐ 在一个 **76% 不谈成本**的领域里，⭐ 报它是差异化；⛔ 但也意味着**找不到可比数字**。

⭐ **可比的只有两个零散点**：⭐ MCeT 的 **6.4–7.6× token**（⭐ 四模型齐报）· ⭐ 人工金标的量级 —— ⭐ SpecGPT **>210 人时**、⭐ ProtocolGPT **>72 人时 / 3 专家**、⭐ **我们 G1 是 33–49 人时**（⭐ 三者同量级，⭐ 我们最省）。

## 9. ⭐ 顺带：⛔ 不利结果怎么写（⭐ 三份现成模板）

⭐ 我们手上有 **−15.82pp** 要写。⭐ 三篇的写法都可直接借鉴：

| 来源 | 做法 |
