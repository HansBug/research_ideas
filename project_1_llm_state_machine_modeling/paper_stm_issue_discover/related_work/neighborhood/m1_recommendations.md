## 1. ⭐⭐ R1 · 拆掉自评 reviewer

### 1.1 ⭐ 外部给出了**受控消融**的数字

⭐ **LADEX**（EMSE 2026）把「结构良构性由谁检查」做成受控变量，⭐ 其余全同：

| 检查者 | 结构不合规率 | 额外调用 | 连带效果 |
| :-- | --: | --: | :-- |
| ⛔ **LLM 自评** | 21.80% → **18–19%** | ⛔ **约 +4 次** | — |
| ⭐⭐ **确定性算法检查器** | ⭐⭐ **0%** | ⭐ **1.87 次** | ⭐ **+16.95% 正确性 · +15.12% 完备性** |

⭐⭐ **在同一件事上，确定性检查器用更少的调用做到了 0%，⛔ 而 LLM 自评连一半都没降下来。**

### 1.2 ⭐ 我方实测：⛔ 修订机器在做什么

⭐ 工具 [`tools/measure_revision_drift.py`](./tools/measure_revision_drift.py)，⭐ 跑在 v46 全部 **324 格**（⭐ 其中 **217 格**有 ≥2 次 `convert_assertions`，⭐ 分母 **6084 条**断言）：

| 修订机器实际在干什么 | 数字 |
| :-- | --: |
| ⭐ 断言 `expression` **全程一字未动** | **90.7%** |
| ⛔ 编辑里**只改散文字段** | ⛔ **69%**（3106 / 4519） |
| ⛔ 碰了 `expression` 的编辑里**回到旧值** | ⛔ **35.8%**（506 / 1413） |
| ⛔⛔ **换谓词时换回一个已试过的** | ⛔⛔ **43.7%**（392 / 898） |
| ⚠️ 修订期间**净删除**断言 | ⚠️ **−236**（删 428 / 增 192） |

⭐⭐ 这解释了 X1 那条「⛔ **79% 的 token 换来覆盖净变化 ≈ 0**」：⛔ **不是没干活，⭐ 而是干的活九成在改散文、剩下的三分之一在兜圈子。**

### 1.3 ⭐ token 该改花在哪：⭐ **换粒度重问，⛔ 不是自我批判**

| | ⭐ MCeT（MODELS 2025） | ⛔ 我们 v46 |
| :-- | :-- | :-- |
| 额外 token 花在 | ⭐ **换输入切分粒度重问同一份制品** | ⛔ **LLM 自我批判修订** |
| ⛔ 让某轮输出去修另一轮输出？ | ⛔ **从不** | ⭐ **是** |
| 倍数 | 6.7× | ⛔ **212.6×** |
| 换来 | ⭐ 召回 **34.1% → 68.1%** | ⛔ **−15.82pp** |

⚠️⛔ **一处必须更正的流传数字**：⭐ MCeT 常被引作「precision 0.58 → 0.81」，⛔ **那把自一致性的贡献高估约 2.5 倍**。⭐ 论文 §VI-A 自己拆开了：⭐ 加两个视角 **0.58 → 0.72**，⭐ **交叉核查**才是 **0.72 → 0.81** —— ⭐ 自一致性净贡献只有 **+0.09**。

### 1.4 ⚠️ 一条外部独立复现的**警告**

⭐ SoSyM 2026 那篇逐字：⛔ **把规则注进检测 prompt 会造成隧道视野** —— `the LLM tends to **exclusively focus on these rules, thus ignoring other consistency aspects**`。

⭐⭐ **这是我们 `occupancy_after` 那次事故的外部独立复现**（⛔ 它的 `nl_cue` 把模型从 `edge_declared` 引开，⛔ 324 格里被问 **0.0%**）。⛔ 但他们的对策（⭐ 跑两遍取并集）**对我们不适用** —— ⭐ 成本已经 212.6×。

⭐ **RFSeek 给了第三个同向证据**：⭐ 把 prompt 从中性改成要求 `"precise and accurate FSM"`，⛔ **删掉了那条后来成为 RFC 官方勘误的边**；⭐ 而加一句「抽取所有迁移」**没有增加总数 —— 集合平移了**。⭐⭐ **即：措辞重新分配召回，⛔ 而不是增加召回。** ⭐ 这与我们「提问率 21.4% → 54.5% 而命中没动」是同一现象。

## 2. ⭐⭐⭐ R2 · §11 的准入判据要加第二问

⭐ 本仓库 `CLAUDE.md` §11 现在只有**一问**：⭐ **「这条约束能否只看字段值就唯一判定？」**

⭐⭐ **ATLAS 给出了第二问，⛔ 而它才是解释我们那次事故的那一条。** ⭐ 逐字：

| 层 | 逐字定义 |
| :-- | :-- |
| `R_struct` | ⭐ **prefix-checkable** structural obligations such as containment, field presence, ordering, and local typing patterns |
| `R_sem` | ⭐ graph-level or reference-level obligations that **require the completed artifact** |
| `R_log` | numeric, temporal, or solver-backed |

⭐ 准入政策逐字：⛔ **`only prefix-checkable structural fragments are sent to L1`**（⭐ L1 = 生成期约束解码）。

⭐⭐⭐ **这条判据机械地解释了 `named_elements` 那次事故**：⛔ 「这句话点名了几个要素」**既不是只看字段值可判的，⛔ 也不是看半成品可判的** —— ⭐ 你必须读完整个从句才能看出并列关系。⛔ **把它塞进生成期的门，⭐ 就是在逼实现者拿一个词法近似（有没有逗号）去顶替语义判断。** ⭐ ATLAS 禁止这一步，⭐ 并指出正确的出口：⭐ **推到「产物完成之后」那一层。**

⭐⭐ **建议 §11 改成两问**：

1. ⭐ **能不能只看字段值唯一判定？**（⛔ 否 → prompt + 评审端；⭐ 现有规则）
2. ⭐⭐ **能不能只看半成品判定？**（⛔ 否 → ⭐ **放到 `precheck_and_seal` 对封存后的产物判，⛔ 绝不做成 `convert_assertions` 里的内联 validator**）

⚠️ **一处必须标注**：⛔ **ATLAS 不过本轨的硬门 2**（⭐ AUTOSAR ARXML 是配置 / 架构制品，⛔ 不是行为模型）。⭐ 抽卡 agent 主动把它标为**破门条目并要求不得静默进分母** —— ⭐ 处置正确。⭐ **但上面这条分层判据与制品类型无关**，⛔ 故仍可用；⛔ **它要进论文则必须另行过门。**

## 3. ⭐ R3 · 收敛判据下沉到谓词层

⭐ ETFA 2025 的循环是**固定 20 轮无条件跑满**，⛔ 没有任何东西决定要不要再来一轮。⭐ 实测最优版在**第 11 轮**达到，⛔ **第 12–16 轮零改动**（⭐ ≥25% 轮次纯烧钱）。

⛔ **但「本轮零改动」这个判据在我们身上不管用**：⭐ 我们只有 59.7% 的断言在全字段上稳定，⛔ **每轮都有改动**（⭐ 大多是散文）。

⭐⭐ **正确的判据是谓词层**：⛔ 当某条需求的谓词选择**换回一个已试过的谓词**时，⭐ 这一格已在兜圈子 —— ⛔ 再修期望收益为零。⭐ 这与仓库 §12「⛔ 采样不确定性不能掩盖结构性失败」是同一条纪律：⭐ **失败签名重复即结构性死路**，⭐ 而「谓词集合重复」就是此处的失败签名。

⭐ **实现成本近零**，⭐ 按实测会拦掉 **392 次**无效编辑。

⚠️ **对照**：⭐ LADEX 平均只跑 **1.14 轮**，⭐ 5 轮上限只在 **703/12800（5.5%）** 的任务上触及 —— ⭐ 说明**有确定性检查器时，循环本来就该很短**。

## 4. ⭐ R4 · 把 sound oracle 移到裁决端 —— ⭐ **有先例**

| 工作 | 循环 | ⭐ 裁决者 |
| :-- | :-- | :-- |
| ⭐⭐ **PAT-Agent**（ASE 2025，CCF-A） | ⭐ 有（`K_max = 5`） | ⭐⭐ **纯 sound oracle**（PAT 模型检查器），⛔ **全流水线零 LLM 自评** |
| ⭐⭐ **Event-B Agent**（FSE 2026，CCF-A） | ⭐ 有（三层嵌套） | ⭐⭐ **双 oracle**（ProB + Rodin 证明器 / SMT），⭐ 逐字 `soundness is ensured by the verification pipeline rather than the repair rules` |
| ⭐ **ATLAS** | ⭐ 有 | ⭐ **复合 oracle**（xmllint XSD + SHACL 794 shapes + SMT 1005 assertions），⭐ 逐字 `an artifact is accepted only when the structural, semantic, and logic validators all pass` |
| ⭐ **LADEX** | ⭐ 有 | ⭐ **算法检查器 vs LLM 自评**（⭐ 受控消融，⭐ 见 R1） |
| ⭐ **RunVS**（SAC 2025） | ⭐ 有 | ⭐ **确定性规则**（⭐ 状态是否满足 φ 的成员判定），⭐ 循环内**零 LLM 调用** |
| MCeT | ⛔ 无 | ⛔ LLM 自评（⭐ 角色扮演「资深工程师」单向否决） |
| ETFA 2025 | ⭐ 有（20 轮） | ⛔⛔ **无裁决者** |
| ProtocolGPT | ⛔ 无 | ⭐ 确定性规则（20 次采样保留 >80%） |
| SpecGPT | ⛔ 无 | ⭐ 确定性 span 匹配（θ=0.75）+ 多数票 |
| ⭐ **SoSyM 2026** | ⭐ 有（三个循环） | ⭐ **三个裁决者，⛔ LLM 一个都不是**（⭐ 确定性规则检查 / ⭐ 人工接受门 / ⭐ 人挑修哪些） |
| ⭐ **我们 v46** | ⭐ 有 | ⚠️ **两者并存**（⛔ 2 个 LLM 自评 + ⭐ 2 个确定性） |

⭐⭐ **结论改了**：⛔ 首版说「零先例」是**基于 4 篇的错误结论**。⭐ 实际上**三篇 CCF-A/顶会工作把 oracle 放在裁决端且零 LLM 自评** —— ⭐ 这条路**走得通**。

⛔⛔ **但 ProtocolGPT 那一行仍然刺眼**：⭐ 它的被测对象是**可编译、可测试的 C 代码**，⭐ 编译器 / 测试 / AFLNet **全在手边** —— ⛔ **却全部被放在循环外**。⭐ AFLNet 只是下游消费者，⛔ 覆盖率**从不回流**。

### 4.1 ⭐ SoSyM 那篇给了一个**不同的形状**，⭐ 可能比 R4 更适合我们

⭐ 它的可信底座**不是**「把裁决者换成 oracle」，⭐ 而是 **「再开一条完全不含 LLM 的确定性检测臂，⭐ 两臂取并集」**：⭐ 人打 tag → `model2graph`（⭐ 带双射性证明）→ 图遍历，⭐ 零 LLM，⭐ 拿到 **0 误报 0 漏检**。

⭐ **我们有 `pyfcstm`，⭐ 可照这个形状开第二臂而不动现有链。** ⛔ **但两个致命前提**：

1. ⛔ **它的 reference 是另一个形式化制品，⭐ 我们的 reference 是 NL** —— ⛔ 它那套算法**在我们这里无法原样存在**，⭐ 能搬的只有**架构形状**。
2. ⛔ **跨视图链接靠人工打 tag**，⭐ 作者自认 `heavily depends on the quality and accuracy of the model annotations provided by the engineer`，⛔ **且把打 tag 的时间移出了度量范围** —— ⛔ 若我们开第二臂，**那条臂的成本不是零**。

## 5. ⭐⭐⭐ R5 · 第 0 轮质量决定天花板

⭐⭐ **PAT-Agent 是唯一给出逐轮数据的**（⭐ 且是抽卡 agent 从 artifact 里挖的，⛔ 论文正文没有）。主配置 Overall FPR：

```
.7500 → .7750 → .8750 → .9500 → 1.0000 → 1.0000
```

⭐ **第 3、4 轮各贡献 +7.50pp 与 +5.00pp，⭐ 合起来正好是总增益 +25.00pp 的一半。** ⭐⭐ **即：有 sound oracle 的循环在第 3–4 轮仍然在付钱** —— ⭐ 与我们**第 3–5 轮零收益**形成直接对照。

⛔⛔ **但结论是强条件的，⭐ 而这才是真正的发现。** ⭐ 去掉规划阶段后（⭐ 第 0 轮从 `.7500` 掉到 `.4750`），**同一个 PAT oracle、同样 5 轮预算**只拿到 **+12.50pp**，⛔ **且第 3、4 轮持平**，⭐ 终点 `.6000` 而非 `1.0000`。⭐ 在 UCS 子集上，**6 个模型配对里有 2 个五轮全程零增益**。

⭐⭐⭐ **结论**：⭐ **oracle 决定循环会不会兜圈子；⭐ 第 0 轮质量决定它能爬多高。** ⛔⛔ **换上 sound oracle 救不了一个弱生成器。**

⚠️ ⛔ **这直接改变 M1 的优先级**：⭐ 我们的第 3–5 轮零收益，⛔ **可能主要不是裁决者的问题，⭐ 而是第 0 轮（`split_requirements` 选谓词那一步）本身太弱** —— ⚠️ 与 X1 那条「⛔ **69 位根本没问**」（⭐ 选题阶段赤字 11.7pp）**指向同一处**。⭐ **先修第 0 轮，再动裁决者。**

## 6. ⭐ R6 · 让 LLM 判的对象必须是 context-free 的

⭐ MCeT 报了一组**受控对照**（⭐ 同一流水线、⛔ 只换被判对象）：

| 被判对象 | precision |
| :-- | --: |
| ⭐ **requirement-atom**（⭐ 自包含的一句需求） | ⭐ **0.86** |
| ⛔ **diagram-atom**（⛔ 一条迁移，⛔ 正确性依赖周边上下文） | ⛔ **0.50** |

⭐⭐ **可证伪的预测**：⛔ 我们的**结构族**谓词判的是自包含事实，⭐ 而**仿真族 / BMC 族**判的是依赖执行上下文的事实 —— ⭐ 于是**后者多报率应显著高于前者**。

⚠️ **强度 I（待验）**，⛔ 但**可在 v46 的五类多报台账上直接验**，⭐ 成本很低。⛔ **验之前不得当结论用。**

## 7. ⭐ R7 · 覆盖账的三个零件，⭐ 两个已有先例

| 零件 | ⭐ 先例 | 怎么做的 |
| :-: | :-- | :-- |
| **①** 规约侧**锚点** | ⭐ **有**（SpecGPT） | ⭐ 每条迁移的 `condition` / `action` **必须是规约原文的逐字片段** |
| **②** **可机械枚举的遍历单元** | ⭐ **有**（SpecGPT） | ⭐ 遍历单元从**章节树**机械导出，⭐ 每窗口**恰好访问一次** |
| **③** ⛔ **把「规约说了而模型没有」记下来** | ⛔⛔ **无** | ⛔ 缺口只在**评分时**以 FN 存在于 210 人时的金标里 —— ⭐ **流水线自己不知道漏了什么** |

⭐ **有了 ① + ②，⭐ 加一份「每窗口 produced / empty」的账本就是 ③。**

⭐ **额外收获**：⭐ 「逐字片段」把「**这两条是不是同一个发现**」从语义判断塌缩成**词法重叠** —— ⭐ 那正是我们 574 位人工判定里最贵那部分的**机械替代品**。

⚠️ ⭐ **RFSeek 给了 provenance 的另一种做法与它的边界**：⭐ 段落粒度、UI 可枚举，⛔ 但那是一条**两跳 LLM 断言链**（边 → 摘要段 → RFC 段落），⛔ **没有任何东西核验被引段落存在或支持该边**。⭐⭐ **正确措辞是「人可审计，⛔ 而非机器已验证」** —— ⭐ 我们写 C-③ 时要用得起这个区分。

## 8. ⭐ R8 · 加一条 per-case 下限

⭐ TSE 2026 那篇的判据：⛔ **一条推荐只有在「超过输入切片本身已有的相似度」时才算有意义。**

⭐⭐ **我们没有这样的 per-case 下限。** ⭐ 加上之后，⛔ **那些「只有我们能发现」的台账条目会从 −15.82pp 底下显形** —— ⭐ 现在它们被平均掉了。

⭐ **配套两条可直接抄的写法**：

1. ⭐ **双判定者区间报告**（`at least 601 … at most 751`）—— ⭐ 因为它的判定者同时是它的竞争者。⭐ **我们的 LLM 自裁决同理。**
2. ⭐ **regime-splitting 而不是含糊其辞**：⭐ 标题是问句 `Are LLMs the Answer?`，⭐ 答案是**「not always」**，⭐ 用**分区间**守住（⛔ ≤6 节点输 3.1×，⭐ >6 节点赢 1.69×）。

⚠️ ⭐ **一个反面模板**（⭐ 同样有用）：⭐ MODELS-C 2025 那篇把不利结论（`human models and operations represent **a better** source`）**降级成让步从句**（`even though …`），⭐ 再用一个**未量化的条件**反转（`nonetheless, **if instructed properly**, LLMs can represent a solution`）。⭐⭐ **我们若在没有实跑的情况下写「换个 prompt 就能修好」，⛔ 做的就是这第二种事。**

## 9. ⛔⛔ R9 · 不要走「按样本手调」那条路

⛔ ProtocolGPT 的 `code_filter.py` 里有一份**按协议手写的正则字典**（⭐ 5 个键对应 6 个被测协议），⭐ 内容是 `RTSP_Server_State` / `L2TP_LAIC_STATE` / `fsm_table` 这类**实现标识符**，⛔ 不是 RFC 术语。⛔⛔ **而消融把它记为全文最大单项增益：precision +41.02pp · recall +55.57pp。**

⭐ 按本仓库 §3.5 的抽象化自检，⛔ **它落在「样本的答案」那一侧**。

⭐⭐ **两面教训**：⭐ ① **它在那个邻域通过了评审** —— ⚠️ 该领域对此的容忍度比我们自己设的线宽得多；⛔ ② **我们仍然不能做** —— ⭐ 我们**不设 hold-out**，⛔ **没有任何东西能替我们挡下这个指控**。

## 10. ⭐ R10 · ensemble 是多报抑制器

⭐ SpecGPT 的 `LLM ensembles` = **5 个不同厂商各跑一遍**（⛔ **不是**同模型重采样，⭐ 自一致性被列为 future work），⭐ 用确定性 span 匹配 + 多数票聚合。

⭐ **相对最好的单模型**：⭐ precision **+12.77pp** · ⛔ recall **−2.12pp** —— ⭐⭐ **几乎纯粹是个多报抑制器。**

⭐ 这对我们有直接意义：⭐ **加轮次提召回**与**加模型压多报**是两件事，⛔ 不要混。

⚠️ **打折**：⛔ SpecGPT **单趟无重复运行**，⛔ 5–22pp 的增益**无法与单次采样噪声分离**；⛔ 且 θ=0.75 **在评测集上调**、⭐ 同一算子**既产出又评分**（⭐ 撞上 §3.5 第 4、5 条）。

## 11. ⭐ R11 · 成本要换算成可解释的单位分母

⭐ 第三方 N=86 映射研究逐字：⛔ `only 21 papers evaluate the computational or financial cost of their approach, whereas 65 do not`。

⭐ 我们手上有 **212.6×** —— ⛔ 但那是**一个光秃秃的倍数**，⭐ 既没有绝对量也没有单位。

⭐⭐ **Event-B Agent 的写法可直接抄**：⭐ 把总量钉到一个**可解释的分母**（⭐ 182.41 个证明义务），⭐ 再换算成**单位成本**（⭐ 0.24 分钟 / 证明义务），⭐ 与**人类专家**对比。

⭐ **可比的零散点**：⭐ MCeT **6.4–7.6× token** · ⛔ Event-B Agent 的修复机器吃掉 **93.66% 的 token**（⭐ 比我们的 79% 更极端，⛔ **但它买到了东西**）· ⭐ 人工金标量级：SpecGPT **>210 人时** · ProtocolGPT **>72 人时 / 3 专家** · ⭐ **我们 G1 是 33–49 人时**（⭐ 同量级，⭐ 我们最省）。

## 12.5 ⛔⛔ 一处必须防的误读：⭐ 「反馈信号取自模型语义」**不等于**「oracle 在裁决端」

⭐ 我先前把 *A Formalism-Aware Reward Loop*（MODELS 2026）当成 R4 的旁证。⛔ **那是错的。**

⭐ 它的确定性评分器接在**奖励端**：⭐ 反馈**不进上下文、⛔ 推理时模型看不到任何反馈**（⭐ 压成一个标量走 GRPO 梯度）。⭐⭐ **那是第三个位置** —— ⭐ 与「裁决端」（⭐ 决定要不要再来一轮）和「求值端」（⭐ 我们现在的位置）都不同。

⭐ **邻域里唯一与我们同形态的**（⭐ 确定性裁决者 + 文本回灌 + 上下文内修订）是 BEF4LLM §5 那个 refinement loop：⭐ 裁决者 = **XSD validator**，⭐ 回灌 = 实际报错 + 一份静态常见错误清单，⛔ **最大轮数 = 1** —— ⚠️ **而一轮之后 17 个 LLM 里仍只有 1 个 validity > 90%。**

⚠️ ⭐ **它还预警了一个与我们同形的坑**：⛔ **聚合归一化会让强分量掩盖弱分量** —— ⭐ 契约门若只报过/不过而不分解到具体未满足义务，⛔ 修订轮就学不到弱项。⭐⭐ **这与我们「79% token、覆盖净变化 ≈ 0」高度同形。**
