# L3 · 邻域工作调研 —— 结论

⛔⛔ **防火墙**：本目录的一切是**方法素材**，**不是论文证据**。任何一条要进论文必须回 [L1](../landscape/) / [L2](../provenance/) 的门重走（理由见 [README.md](./README.md) §3）。

**问的问题**：近年学术工作里，LLM 具体是怎么被搭进针对行为类模型制品的流水线里的 —— 几个阶段 · 循环的裁决者是谁 · 中间表示什么形态 · 实验怎么做 · 有没有能拿来用的资产。

**两条硬门**：**基于 LLM**（LLM 是方法核心组件）· **行为类模型制品**（制品必须是模型）。**不设** $M = (S,E,V,Tr,A)$ 边界门，但逐条标注。⭐ 另有一条用户裁定的范围门：**只算纯自动的 LLM 方法**，⛔ 人在回路的不进 ① 档。

⚠️⚠️ **读本文件里任何 ① 档数字之前，必须先读 [design_evidence.md](./design_evidence.md) §9（模型代次轴）。** ⛔⛔ **前八节的分级只回答了「对照是否受控」，⭐ 完全没回答「论文里用的 LLM 是哪一代」** —— ⭐ 而后者独立地决定这条证据对我们（主臂 `gpt-5.5` 2026-04 / `claude-opus-4-7` 2026-04）还有多少参考价值。

⭐ §9 的三条结论直接改写本文件的读法：

1. ⛔ **九个决策点里只剩 2 个有「同代 ①」支撑**（⭐ 同代 = 主结果模型距主臂 ≤6 个月），⛔ 其余 7 个为零。
2. ⛔⛔ **规律 2（「LLM 自评当裁决者收益近零」）在代次约束下不成立** —— ⭐ 它的全部支撑都是 mini 档模型（GPT-4.1-Mini · O4-Mini · GPT-4o-mini）。⭐ 这**抬高**而非降低「拆掉两个自评 reviewer 跑同网格」的优先级。
3. ⭐⭐⭐ **最耐久的证据不是 ① 档受控对照，⭐ 而是「在当代模型上仍然存在的失败模式」** —— ⛔ ① 档对照多在测「加了 X 从 a% 升到 b%」，⭐ 而那个 `a%` 基线本身就是某一代模型的能力。

## 前置 · 读这份文档之前需要知道的

⚠️ 本文档是**一半文献调研 + 一半自我诊断**。前半自包含；⛔ **后半的主语是「我们」**，故先交代「我们」是什么。

### 我们在做什么（三句话）

1. 输入是**一段自然语言需求**与**一份状态机模型**（模型由 LLM 从该需求生成，可能有缺陷）。
2. 我们让 LLM 把需求拆成原子条目，**为每条从一个固定的 19 条谓词词表里选一个**，写成**可机械求值的断言**，再拿 `pyfcstm` 在模型上求值。
3. 求值为假的断言 ⇒ **一条「发现」**。衡量的是：**台账里预期的缺陷，有多少被这样发现出来。**

| 词 | 含义 |
| :-- | :-- |

| **断言** | 由一条谓词 + 具体参数构成的、**可机械求值**的检查语句 |
| **台账** | ⚠️ **两个所指**：① 本文档里的**检索台账**（[search_ledger.md](./search_ledger.md)，记查了哪些门）；② **缺陷台账**（每个样本预期该被发现哪些缺陷的真值表，98 条）。下文出现「台账」而未限定时指 ② |

| **位** | 判定的最小单位 —— **一条台账条目 × 一个格**。⚠️ 「69 位没问」= 69 个这样的组合，**不是 69 个人** |
| **`hit@1`** | 单轮命中率 = 命中位数 / (台账条目数 × 轮数)。**60.4% = 355/588** |
| **第 0 轮** | 循环开始**之前**的那次初次产出（我们这里是 `split_requirements` 选谓词那一步） |
| **sound oracle** | 判定**可信且不会误判为真**的机械裁决者（模型检查器 / 定理证明器 / 求解器）。⛔ 与「LLM 自评」相对 |
| **裁决者** | 循环里决定**要不要再来一轮**的那个东西 |
| **降级** | 阶段失败时**不抛异常**，而是把已拿到的部分封存、把未满足的义务记成结构化诊断，让这一格带着残缺产物落盘 |
| **真空** | 一条断言在**无意义的前提下**通过（如前件恒假）—— 通过了但什么也没证明 |
| ⚠️ **邻域** | **两个所指**：① 本轨的名字（「邻域工作调研」）；② 边界三档之一（`界内` / `邻域` / `界外`，见 [README.md](./README.md) §2.1） |
| **pp** | 百分点（percentage point）。与「%」表示的相对变化不同 |

## 2. 结论 ① · 「对行为模型做验证」是 2/86

拿第三方 **LLM4MDE 系统映射研究**（EMSE，[`10.1007/s10664-026-10921-4`](https://doi.org/10.1007/s10664-026-10921-4)，⭐ N=86）的复现包做 S1 自己没列的交叉（⭐ 工具 [`tools/analyze_s1_corpus.py`](./tools/analyze_s1_corpus.py)）：

| MDE 任务 | 全部 | 其中行为类制品 |
| :-- | --: | --: |
| Model Generation | 62 | 13 |
| Model Completion / Repair | 12 | 3 |
| ⭐⭐ **Model Validation** | **11** | ⭐⭐ **2** |
| Model Transformation | 10 | 1 |
| 其余四类 | 12 | 1 |

那 2 篇是 **MCeT**（⭐ 时序图）与 **On Augmenting Scenario-Based Modeling**。行为类制品总共 **15/86**。

⭐⭐ **两面读法**：我们做的事**确实是少数派**（⛔ 11/86 做验证、其中只有 2 篇是行为模型）；⛔ **但不是空白** —— ⚠️ **「据我们所知未见」这类话仍然不能随便写**。

⚠️ **口径限制**：S1 的范围是 **MDE 框架下**的工作、2022 起、五个库。⛔ 它**看不到**协议状态机那一带（⭐ A3 单独捞到 5 篇，⭐ 全是界内 FSM）。⭐ **所以 2/86 是「MDE 口径下」，⛔ 不是全世界。**

## 3. 结论 ② · 有效的检索轴是制品词（⚠️ **本节末尾自己修正过一次**）

A5 做了一次**干净的对照**（⭐ DBLP `stream:` × `year:` 全普查，⛔ 不靠关键词）：

| venue 族 | 论文数 | 过两门的命中 |
| :-- | --: | --: |
| ⛔ **LLM 专门 venue**（FORGE · AIware · LLM4Code · NLBSE） | **347** | ⛔ **1** |
| ⭐ **建模 venue**（MODELS + MODELS-C） | 664 | ⭐ **5**（⭐ 3 篇在主会） |

⭐⭐⭐ **即：把「LLM」当检索轴几乎没用，把「行为模型制品」当检索轴才有用。**

⚠️ ⭐ **连 MDE Intelligence 也只是部分兑现**：它确实是 LLM4Modeling 最集中的地方，⛔ **但它的制品压倒性地是结构类**（⭐ 类图 / 领域模型 / 元模型 / 特征模型）—— 行为类制品**要到 2025 年（第 7 届）才出现，且只有 2 篇**。

### 3.1 ⛔但「往领域 venue 花力气」这半句，⭐ **A9 实测把它也否掉了一半**

我派 A9 去扫工业自动化与协议时**明确预判**：⭐「⛔ 这一路的界内率应当明显高于其它路」。⛔⛔ **实测不成立**：

| 路 | 界内率 |
| :-- | --: |
| A9（工业自动化 + 协议） | **14 / 86 = 16.3%** |
| A3（IEEE Xplore 通扫） | **17 / 105 = 16.2%** |

⭐⭐ **持平。** ⭐ A9 给了三条可核算的原因：

1. ⛔ **工业侧的主流制品是「代码」不是「模型」** —— 那 25 行里 `界内` 只有 4 条，而「⚠️ 制品偏代码」有 13 条（⭐ ST / LD / FBD 代码生成）。
2. ⚠️ **我给的场地表含 ICRA / IROS**，⛔ 捞出 17 篇**行为树**（⭐ 全 `邻域`）—— ⛔ 单独抬了分母（⭐ 剔掉后 20.3%，⛔ 仍非「明显」）。
3. ⭐⭐ **界内真正富集的地方不是场地，而是「FSM」这个词本身** —— 富集出来的几篇（TDSC · ISQED · arXiv）全是**主题查询与引文追踪**捞到的，⛔ 不是场地切法捞到的。

⭐⭐⭐ **修正后的结论**：⭐ **有效的检索轴是「制品词」，⛔ 既不是「LLM」也不是「场地」。** ⭐ 「往建模 venue 花力气」成立是因为**建模 venue 里制品词密度高**，而不是因为 venue 本身。

⚠️ ⛔ **A9 还登记了一个必须知道的覆盖缺口**：DBLP 的 `journals/cep` 与 `journals/isatrans` **stream key 根本不存在**（⛔ 空查询也 `total=0`）—— 所以 **Control Engineering Practice 与 ISA Transactions 本轮实际未被有效覆盖**，⛔ **那 6 个 0 不得当事实读。**

## 4. 结论 ③④ · 关于循环与裁决者

### 4.1 已成档工作的裁决者分布

| 裁决者类型 | 篇数 | 谁 |
| :-- | --: | :-- |
| ⭐⭐ **纯 sound oracle 裁决**（⭐ 有循环 + 零 LLM 自评） | ⭐ **2** | PAT-Agent · Event-B Agent |

| ⭐ **确定性 + 人** | 1 | SoSyM 2026（⛔ **三个裁决者 LLM 一个都不是**） |

| ⛔ 无循环 | 2 | TSE 2026 · RFSeek |
| ⚠️ **原文未提供** | 1 | MODELS-C 2025 —— ⛔ 卡片明令 **不得据此推断「它没有循环」**，⭐ 摘要沉默不是证据 |

### 4.4 ⭐⭐⭐ 裁决者的位置有一条**阶梯**，⛔ 而「换 oracle」只爬了中间一级

⭐ 把 28 张外部单篇卡按「**约束在哪一步生效**」排开，⭐ 得到一条清晰的阶梯（⛔ 越靠上越有效）：

| 位置 | 做法 | ⭐ 实测 |
| :-- | :-- | :-- |
| ⭐⭐⭐ **构造端** | ⭐⭐ **把满足性从「检查式」改成「构造式」** —— ⭐ 约束编成 FOL 塞进 0/1 整数规划由求解器解，⛔ **让不合规的解在搜索空间里根本不存在** | ⭐⭐ **零迭代 · 零 LLM 自评 · 零修复调用，⭐ 约束一致性 96.6–100%** |
| ⭐⭐ 裁决端 · 确定性 | 求值器 / parser / 求解器判过不过 | ⭐ 我们的 `precheck_and_seal` 在这一级 |
| ⭐ 裁决端 · 词法规则 | ⛔ 名字等号比较这类 | ⚠️ 把语义判断做成词法判断（⭐ 仓库 §11 那条纪律的外部实例） |
| ⛔ 裁决端 · **LLM 自评** | ⛔ 让模型判自己 | ⛔⛔ **本轮又拿到两个负收益实例**（⭐ 一个专为压多报而设的 LLM filter，⛔ 结果 precision 是四条策略里**最差的 0.2038**，⛔ 比完全不过滤低 **0.59**） |
| ⛔⛔ **无裁决者** | 固定轮数跑满 | ⛔ ETFA 2025 |

⭐⭐⭐ **对 M1 的含义**：⛔ **「把裁决者换成 sound oracle」只是从第 4 级爬到第 2 级** —— ⭐ **首选目标应当是第 1 级（构造端）**，⛔ 至少对**结构族那 10 条谓词**而言（⭐ 它们判的是「这个元素声明过吗」这类，⭐ 本来就可以做成构造期约束而非事后检查）。

⚠️ ⛔ **一条必读的反面证据**：⭐ 朴素的**逐元素多数投票会把一致性打崩** —— ⛔ 实测把一致性从 93–96% 打到 **51–71%**（⛔ 某小模型上 **−43.3pp**）。⭐ 若我们考虑加 self-consistency 投票，⛔ **这是必须先读的。**

### 4.5 ⭐⭐⭐ 另一条：⛔ 即使有 oracle，⭐ 反馈不定位照样不收敛

⭐ **ERTS 2026**（⭐ 与 SoSyM 那篇同一工具、同一组作者、⛔ 两条正交的加法）**把裁决者换成了真 sound oracle**（⭐ TTool 模型检查器，⭐ 在裁决端，⛔ LLM 从不裁决）。

⛔⛔ **循环仍然不收敛**：⭐ Table 1 六格逐格给了轮数 × token × 成本 × 残余量 —— ⛔ **5/6 格撞满 20 轮上限**；⭐ 语法轴 6/6 清零，⛔ **安全轴只有 1/6 全满足**；⛔ 最贵一格 **224,078 token / \$1.19 / 26 分 40 秒**，⛔ **仍剩 6 条未满足**。⭐ 作者两处逐字写 `we cannot conclude`。

⭐⭐⭐ **失败主因是作者自己认的**：⛔ 回灌只给「**哪几条性质没满足 + 那张状态机图**」—— ⛔ **不给反例路径、不定位到具体元素。**

⭐⭐ **所以 M1 的第二条设计原则不能写成「把裁决者换成 sound oracle」** —— ⭐ 必须加后半句：⭐⭐ **「并把 oracle 的反例证据翻译成定位到具体元素的可执行反馈」。**

⚠️ ⭐ **一格可直接搬的降级规则**：⭐ 撞上限时**存档 + 两段式打分 + 交最好那版 + 在界面上告知「保证已失效」** —— ⭐ 那正是仓库 `CLAUDE.md` §10 缺的「降级产物该选哪一份」。

⛔⛔⛔ **而更基础的一层是：⭐ 我们的判定对象是「这份状态机是否忠实于这份 NL」—— 没有判定过程。** ⭐ 本目录另一张卡早就写清楚了（逐字）：

> ⛔ **我们没有这样的 oracle……⭐ 这就是为什么我们不得不引入 LLM 裁决者，⛔ 也是为什么它们零收益 —— ⭐ 缺的不是更好的 reviewer prompt，⛔⛔ 缺的是一个可反复调用的判据。**

⚠️ **本表只覆盖 15 篇，⛔ 而 [cards/](./cards/) 里有 28 张外部单篇卡（⭐ 唯一外部工作 32 项）** —— ⭐ 任何比例都不得用 15 当分母而不声明。

⛔⛔ **首版在这里写过「我们是唯一一个『有循环 + 循环里挂着 LLM 自评裁决者』的」—— ⭐ 那是错的，⛔ 且被本目录自己的一张卡直接推翻。**

⭐ 跨视图漂移那篇（[`cards/stateful-multiagent-crossview-drift.md`](./cards/stateful-multiagent-crossview-drift.md)）：⭐ **有循环**（逐字 `capped at 40 loops to prevent critic-hallucination gridlock`），⭐ 第二层裁决者是 **LLM Validator Agent**（⭐ 独立实例，⛔ 仍是 LLM 判 LLM），⛔ 且生产者**不能推翻**裁决。⭐⭐ 它甚至给这个坑起了名字：`Critic-Hallucination Paradox`。

### 4.3 ④ · 但 oracle 救不了弱生成器

PAT-Agent 是唯一给出逐轮数据的（且是从 artifact 里挖的，⛔ 论文正文没有）：

```
主配置：      .7500 → .7750 → .8750 → .9500 → 1.0000 → 1.0000
去掉规划阶段： .4750 → …………… → 第 3、4 轮持平 …… → .6000
```

主配置里**第 3、4 轮贡献了总增益的一半**（⭐ +7.50pp / +5.00pp of +25.00pp）—— ⭐⭐ **有 oracle 的循环在第 3–4 轮仍然付钱**，⭐ 与我们**第 3–5 轮零收益**形成直接对照。

⛔⛔ **但去掉规划阶段后，同一个 oracle、同样预算只拿到 +12.50pp，⛔ 且第 3、4 轮持平。** ⭐ 在 UCS 子集上，**6 个模型配对里 2 个五轮全程零增益**。

⭐⭐ **一个自然的读法是：oracle 决定循环会不会兜圈子；起点质量决定它能爬多高。**

⛔⛔ **但这一步是推断，⛔ 不是论文的结论。** ⚠️ 消融**去掉的是「规划阶段」**，而规划阶段不等于「第 0 轮质量」—— 去掉它可能**全程都变差**，⛔ 不只是起点变差。论文没有把这两种解释分开。

⭐ **对 M1 的正确表述**：这条**够格成为一个待验假设**，⛔ **不够格成为「先修第 0 轮」的充分理由** —— 要么先设计一个能把两种解释分开的测量，⛔ 要么把它与「改裁决者」并列试。

⚠️ ⭐ **一条同向的旁证**（但不是同一个机制）：X1 测出「⛔ **69 位根本没问**」（⭐ 选题阶段赤字 11.7pp）—— 那也落在起点那一侧。⛔ **两者是否同一机制没有证据**，⭐ 只能说方向一致。

## 5. 结论 ⑤ · 我们的修订机器实际在做什么

工具 [`tools/measure_revision_drift.py`](./tools/measure_revision_drift.py)，⭐ 跑在 v46 全部 324 格（⭐ 217 格有 ≥2 次 `convert_assertions`，⭐ 分母 6084 条断言）：

| | 数字 |
| :-- | --: |
| 断言 `expression` **全程一字未动** | **90.7%** |
| ⛔ 编辑里**只改散文字段** | ⛔ **69%**（3106 / 4519） |
| ⛔ 碰了 `expression` 的编辑**回到旧值** | ⛔ **35.8%** |
| ⛔⛔ **换谓词时换回一个已试过的** | ⛔⛔ **43.7%** |
| ⚠️ **净删除**断言 | ⚠️ **−236** |

这**刻画**了 X1 那条「79% token 换净变化 ≈ 0」的形状：⛔ 不是没干活，而是九成在改散文、剩下的三分之一在兜圈子。

⚠️ ⛔ **注意这是同一现象的更细粒度重述，⛔ 不是因果解释。** ⭐ 「改散文吃掉了那 79% token」这一步**数据里没有** —— ⛔ 我们测的是编辑**次数**分布，⭐ 不是 token 分布。

⚠️⛔ **这个结论差点被我自己的判据粒度掩盖**：初版只用全字段逐字节哈希，⛔ 得抵消率 **1.0%**，⭐ 于是判「外部那条 drift 假设不成立」。⛔ **那是假阴性** —— 换到谓词粒度是 **43.7%**。⭐⭐ **判据太严与太松同样危险。**

### 5.1 三条外部独立同向证据

| 来源 | 现象 |
| :-- | :-- |
| ⭐ **ETFA 2025** | 最优版在第 11 轮，⛔ **第 12–16 轮零改动**；且观察到「后期正面改动多在撤销前期负面改动」（⭐ 命名为 **drift / migration**） |
| ⭐ **SoSyM 2026** | 逐字：⛔ `the LLM tends to **exclusively focus on these rules, thus ignoring other consistency aspects**` —— ⭐⭐ **我们 `occupancy_after` 那次事故的外部复现** |

⭐⭐ **三者共同指向：⛔ 措辞重新分配召回，而不是增加召回。** 与我们「提问率 21.4% → 54.5% 而命中没动」完全同型。

## 6. 结论 ⑥ · 闭合词表在语义层的最硬证据

⭐ **AutoSpec** 的一组对照（⭐ 同一流水线内）：

| 约束类型 | 词表 | 召回 |
| :-- | :-- | --: |
| 独立约束 | 有闭合枚举 | 16.7% |
| ⛔ **依赖型约束**（跨字段 / 时序） | ⛔ **完全开放生成** | ⛔⛔ **0.0%** |

⛔⛔ **但这两行同时变了两个东西**：⭐ **词表开闭** 与 ⭐ **约束类型**。⚠️ **「依赖型约束本来就更难」是一个未被排除的平行解释** —— ⛔ 论文没有做「依赖型约束 + 闭合词表」那一格。

⭐ **所以正确的说法是**：它是一条**旁证**，⛔ **不是受控证据**。⛔ 引用时必须带上这个限定。

⚠️ ⭐ **另外两个数的分母原文未给** —— ⛔ `0.0%` 可能是 0/3 也可能是 0/300，⭐ 意义差很远。

### 6.1 「闭合 + LLM 自动选」有没有先例：⭐ **有，⭐ 但都比我们小一个量级**

| 工作 | 闭合集合 | 谁选 |
| :-- | :-- | :-- |
| ⭐⭐ **Event-B Agent** | 7 类规则目录 + **原子修复函数库** | 类由确定性模式匹配选，⭐⭐ **函数由 LLM 选并填参** |
| ⭐ **PAT-Agent** | 元素类型 + **3 类断言** | ⭐ **LLM 自动填** |

⭐⭐⭐ **RunVS 那一行值得单独看：它是我们的精确镜像。** ⭐ 逐字：`we do not require the user to provide the set of predicates … instead discover these predicates using a large language model` · `The predicate with the highest information gain is selected`。

⭐⭐ **即「LLM 该放在词表的哪一端」在文献里存在一个被论证过的相反选择** —— 我们把人放在造词表端、LLM 放在选类端；它反过来。⭐ **这是至今最干净的一条对照。**

⚠️ ⛔ **但不要拿它的谓词条数与我们的 19 条比**：它的「谓词」是**程序分析 / SyGuS 意义上的原子谓词**（对程序状态求值的布尔表达式，如 `ncrit <= 1`），⛔ **不是我们那种「对模型提问的检查算子」** —— 同名不同物。

⚠️⛔ **首版在这里算错了一个数**：⭐ 那个「4 类函数」是 Event-B Agent 的**使用分布**（⭐ of successful invocations）—— ⛔ **不是「有几种可选」**；⭐ 函数库规模**原文从未给**。⭐⭐ **所以「我们的 19 条比它们大一个量级」失去了分母，⛔ 已撤回。**

⚠️ ⭐ **这不是「我们的词表太大」的结论**，⛔ 那要等 G1 重标后才能判（⭐ 现台账**变量维与时序性质几乎为空**，⚠️ 可能是台账的问题）。⭐ **但它是一个必须回答的问题。**

## 7. 结论 ⑦ · 我们不知道 60.4% 里有多少是真空的

⭐ **TLA+-Bench** 对**同一批 300 个输出**用四种判定口径打分：

| 口径 | 通过率 |
| :-- | --: |
| config-aware | 18.7% |
| default | 10.0% |
| ⭐ **substantive**（⛔ 非真空） | **4.0%** |
| ⭐⭐ **mutation-surviving** | ⭐⭐ **1.7%** |

⚠️⛔ **「11 倍」跨了一次 prompt 变更，⛔ 不是纯口径效应。** ⭐ 论文逐字：⭐ 后三档是**同一批 300 份输出只换判定规则**，⭐ 那是 **6 倍**（10.0% → 1.7%）；⛔ **第一档是重新采样**（把接口名塞进 prompt 再问一遍）。⭐⭐ **可用的数是同批口径效应 6 倍。** ⭐ 另一处（⭐ 逐模型，⛔ 首版只取了两个高的 parse 值）：⭐ Claude **87% / 16%**（5.4×）· ⚠️ **Gemini-2.5-pro 63% / 10%**（6.3×）· ⭐ GPT-5 **89% / 4%**（22.3×）· qwen **29% / 1%**（29×）。⭐⭐ **虚高 5.4–29 倍。**

⭐⭐⭐ **两个探针都不需要金标** —— 只需要制品与断言本身：

1. ⭐ **substantive**：⛔ 这条断言是不是在无意义的前提下通过的
2. ⭐ **mutation-surviving**：往制品里注入一个缺陷，⛔ 这条断言还通过吗

作者自陈：⛔ **`overstates genuine capability by roughly 2.5 times`**。

⛔⛔ **我们的 `hit@1 = 60.4%` 从未做过这两个探针。** ⭐ 这是一条**成本很低、可立刻做**的自检。

| # | 空缺 | 含义 |
| :-: | :-- | :-- |
| **1** | ⛔ **变量维**：一份逐字 `this paper **ignores node attributes**`，⭐ 另一份逐字 `data objects **omitted** … outside the scope` | ⭐⭐ **我们 `variable_declared` / `variable_delta_after` 从未作 primary，⛔ 不能归因为「词表漏了一类」** —— ⭐ **邻域一份都没有**。这是**开放机会**，但同时意味着**没有外部依据可挂** |
| **2** | ⛔ **时序性质**：最接近的只是行为**相似度**，⛔ 不是行为**性质** | 与 L2 已记的 `response_within` 缺口**是同一个问题的两面**，⛔ 不是两个独立问题 |
| **3** | ⚠️ **反方向：我们对 pragmatic 维 0/15 覆盖**（⭐ size / density / connector interplay / partitionability） | 看起来与任务定义正交，⚠️ 但正交性不彻底 |
| **4** | ⛔⛔ **`nl_evidence` 零先例**：三份**全部**把判据锚在参考模型 / 元模型 / XSD 上，⛔ **没有一份拿「NL 原文哪一句」当真值** | ⭐⭐ **这既是我们的真新意，⛔ 也说明 G1 得自己定口径** |

⭐⭐⭐ **一句必须先引的原话**：其中一份逐字写着 `automated comparison of a graph model with the natural language description **may be unreliable**` —— ⭐⭐ **那是审稿人会拿来打我们的原话，⭐ 最好我们先引它、再说我们怎么处理。**

### 9.5.3 ⚠️ 一处必须对齐的口径

⛔ 「**只用到 15/19**」这个说法有两个不同口径：⭐ **「从未作为 primary」** 是 4 条（`variable_declared` · `variable_delta_after` · `response_within` · `invariant`）；而 L2 的「台账断言数」列里**只有 `invariant` 是 0**。⭐⭐ **两个数不能互换引用，⛔ G1 需先对齐。**

## 10. 两个对 G1 的直接裁定

### 10.1 ⛔⛔ **反向合成金标不能用来扩我们的 54 pair**

⭐ **LLM-FSM**（arXiv 2602.07032）给了一条诱人的路：造受控 FSM → ⭐ LLM 写成带语境的 YAML → ⭐ 转 NL 规约 → ⭐ 参考实现与 testbench 由同一 YAML 合成。若可行，我们就不必做 G1 那 33–49 人时的人工重标。

⛔⛔ **但它的 §3.7 四条人工准则，⭐ 逐字把我们要处理的三件事全清洗掉了**：

| 我们要处理的 | ⛔ 它的准则做了什么 |
| :-- | :-- |
| ⭐ **歧义** | ⛔ 准则 ③ 要求 `unambiguous mapping` —— ⭐ **歧义被当成缺陷主动剔除** |
| ⭐ **遗漏** | ⛔ 准则 ①② 要求 `no missing or spurious` —— ⭐ **遗漏被系统性清零** |
| ⭐ **隐含约定** | ⛔ prompt 强制 `lists every signal using the exact YAML names` —— ⭐ **隐含约定被消灭** |

⭐⭐⭐ **裁定：它构造的恰好是我们处理对象的补集。** ⭐ **合成技法可搬**，⛔ **拿它扩语料不可以** —— 那会**系统性且不可见地把任务变简单**。⛔ 若真要用，⭐ 必须补一步「反向脏化 + 把注入记录当真值」，⚠️ **而这一步本轮未见有人做过**（⛔ 28 张外部单篇卡上的「未见」不等于「不存在」）。

⚠️ 另记两处：⛔ `correct-by-construction` **只覆盖 YAML→RTL 那一环**（⭐ 原文逐字 `relative to the input FSM`）；⛔ 造数据的 `gpt-5` **也在 18 个被评测模型里且原文未讨论**（按仓库 `CLAUDE.md` §3.5 会判 C）。

### 10.2 变异注入这条路**可以搬形状，⛔ 不要搬类目**

⭐ **Simulink 修复 trace 数据集**（我们已取到本地完整副本，⭐ 10 文件 / 162,663,460 B，⭐ md5 全部实算）给了一份 **16 条闭合变异算子**，⭐ 分两族（⭐ 参数型 8 条 / ⭐ 结构型 8 条）+ ⭐ **4 档组合式难度模板**。

⭐⭐ **它的方法论价值高于类目本身**：⛔ 缺陷由**确定性注入器**造 → ⭐ **ground truth 白盒 → ⭐⭐ 分母争议一次性消失**（对照我们正在 G1 重标的 98 条人工台账）。

⛔ **但类目不要搬**：那 16 条是**块级**算子（⭐ Gain Block Deletion · Signal Tag Transposition …），⛔ 与我们的**语义级** issue 零对位。

⚠️ ⛔ **一条反面教训**：它的「变异条数」难度轴**实测几乎无效**（⭐ tier1 69.8% / tier2 79.7% / tier3 76.0% / tier4 72.9% —— ⛔ **非单调，极差仅 9.9pp**）；真正起作用的是**基础模型本身**（⭐ 43.3% vs 93.4%，⭐ 极差 **50.1pp**）。⭐⭐ **G1 若要设难度分档，不要按「缺陷条数」设。**

### 10.3 顺带一条支持仓库 `CLAUDE.md` §10 那条纪律的外部数据

那 192 次运行里，⛔ **`Time = 600` 精确命中 79/192 = 41.1%**（⭐ 某模型高达 68.8%）—— ⭐ **即四成格撞墙钟预算**。与我们 v44 的 **22/35 格降级**同量级。

⭐⭐ **正确读法：「四成格撞预算是这类流水线的常态而非异常」** —— 这支持仓库 `CLAUDE.md` §10「除两类外一律降级不许抛」那条纪律。⭐⭐ **而且我们的降级带结构化诊断，⛔ 他们只留一个 `600`** —— 这是可以写进论文的方法学优势。

⚠️ ⛔ **该数据集本身有一处必须记的事**：⭐ **它的 Zenodo 记录已被删除** —— ⛔ DOI 解析后 **HTTP 410**，`removal_reason` 逐字 **`test-record`**，`removal_date` **2026-05-03**。我们持有本地完整副本并已实算 md5，⛔ **但无法与官方校验和交叉验证**。制品本身是**连续 / 混成 Simulink 块图，⛔ 无 Stateflow → 标 `界外`**；它进 L3 的唯一理由是**资产可实物取用**。
