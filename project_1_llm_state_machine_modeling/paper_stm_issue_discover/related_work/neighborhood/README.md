# L3 · 邻域工作调研：LLM 在行为类模型制品上到底怎么被用

## 0. 一句话

⭐ 本目录回答一个**工程问题**，不回答学术定位问题：**近年的学术工作里，LLM 具体是怎么被搭进针对行为类模型制品的流水线里的** —— 几个阶段、每次调用干什么、有没有循环、循环的裁决者是谁、实验怎么做、有没有放出能拿来用的资产。

⛔ **它的服务对象是 M1（方法重构），不是论文。** 见下面 §3 的防火墙。

⚠️⚠️⚠️ **口径已变（2026-08-14）** —— [issue #189](https://github.com/HansBug/research_ideas/issues/189) 把 paper1 的问题从「**NL 对齐**」改为「**NL 满足性**」，并立 $L \times W \times D$ 三轴（层级 / 见证 / 规范性，其中 $D$ 兼作前置门）。⛔⛔ **本轨的结论**（[SUMMARY.md](./SUMMARY.md) · [design_evidence.md](./design_evidence.md) · [m1_recommendations.md](./m1_recommendations.md)）**已就地迁移**，⭐ 映射真源是 [CRITERIA_MIGRATION.md](./CRITERIA_MIGRATION.md)。⭐ 该表登记了 **三条反而升值** 与 **一条方向反转**（结论 ⑥ 现在是**对新设计走向不利**的一条待答问题，⛔ 不再是支持我们的旁证）。⭐⭐ **卡片的外部事实底座（§A–D，11,707 行）不受影响** —— 全轨 63 处 §E 命中里，与新口径直接冲突的**只有 1 处**，已改。

## 1. 为什么要做这一轨

X1（[#184](https://github.com/HansBug/research_ideas/pull/184)）跑完之后有两个结论把方法重构推成了必选项：

1. ⛔ **自我批判型 loop 看不到正收益** —— 修订机器吃掉 79% 的 token 而覆盖净变化 ≈ 0。
2. ⛔ **赤字在两处而非一处** —— 「根本没问」（选题）69 位、「问了没答对」（断言构造）52 位。

⭐ 于是 M1 要做的不是小修，而是**重新设计流水线的形状**。⛔ 而在重新设计之前，我们对「别人的流水线长什么样」只有 L1 §3.2 那张 7 行表 —— 那张表是 L1 顺手做的副产品，⚠️ 样本量不足以支撑任何「普遍如何」的判断。

## 2. 两条硬门（都必须满足）

| # | 硬门 | 判据 | 为什么是硬门 |
| :-: | :-- | :-- | :-- |
| **1** | ⛔ **基于 LLM** | LLM 是**方法的核心组件**（生成 / 抽取 / 判定 / 修复 / 规划中至少一环）。⛔ 只把 LLM 当被评测对象、或只在 related work 提一句的不算 | 〔用户明确裁定 2026-08-13〕逐字：「**基于 LLM 是刚需，不然对我们来说没有方法层面的意义，只有实验层面的意义**」。⭐ 非 LLM 的检查器（模型检查器 / OCL / SLDV）有成熟 oracle 与 benchmark，⛔ 但它们的流水线形态对「LLM 该被放在哪一环」这个问题给不出答案 |
| **2** | ⛔ **行为类模型制品** | 状态机 / statechart / UML-SysML 状态机 / 协议状态机 / 活动图 / 时序图 / BPMN 与工作流 / LTS / Event-B / CSP / Petri / 时间自动机 / Stateflow。⛔ 制品必须是**模型** —— 纯代码、纯文本需求、纯测试用例不算 | ⭐ 制品的**结构性**决定了流水线能不能做机械求值。⛔ 代码上的 LLM 工作汗牛充栋但形态不可迁移：代码有编译器和测试当 oracle，行为模型没有 |

### 2.1 ⛔ 本轨**不设** $M = (S,E,V,Tr,A)$ 边界门

⚠️ 仓库其它文献轨（L1 找对照、L2 挂出处）都要过一道边界门：⛔ 禁时间自动机 / Petri / 进程代数 / 正交并发。⭐ **L3 不设这道门。**

⭐ **理由**：边界门是**主张门**，不是**阅读门**。它存在是因为「拿界外对象的文献给界内谓词挂出处」不成立 —— ⭐ 而 L3 既不挂出处也不找对照。伞 PR §4.0.2 自己的表已经写明「Limitations 里提及界外工作 ⛔ **不必过门** —— 那是在划边界，不是在挂出处」。

⭐ **但每条必须标边界**，三档：

| 标记 | 含义 |
| :-- | :-- |
| `界内` | FSM / HSM / EFSM / UML 状态机（⛔ 无时钟、无并发区） |
| `邻域` | 活动图 / 时序图 / BPMN / 协议状态机 / LTS |
| `界外` | 时间自动机 / 混成 / Petri / 进程代数 / 正交并发语义 |

## 3. ⛔⛔ 防火墙：L3 产物不得直接进论文

⭐ **本目录下的一切内容标记为「方法素材」，⛔ 不是「论文证据」。**

⛔ 任何一条要进论文（Related Work / Motivation / 差异化陈述 / 出处），**必须回到 L1 或 L2 的门重走一遍** —— 过边界门、过出处轴、过对抗裁定。

⚠️ **这条不是形式主义。** 伞 PR §4C.5 明写「**M1 决定 contribution 的形态**」，⭐ 即 L3 → M1 → contribution 这条通路真实存在。⛔ 若不设防火墙，未过门的材料会经由方法设计洗进论文的主张，⛔ 而那正是本仓库 §3.5 列为 C 级的那类问题。
