## 0. 这份文件为什么单开

前面的 [SUMMARY.md](./SUMMARY.md) 与 [m1_recommendations.md](./m1_recommendations.md) 犯过同一类错误**四次**：把「某篇论文做了什么」直接读成「我们该怎么做」。四次都是数字对、推理不对。

所以本文件换判据：**只认受控对照**——论文只改了一个设计因素、其余保持不变、并给出两侧的数。其余一律降级，且降级后**不许用来支撑设计决策**。

### 0.1 分档

| 档 | 定义 | 能支撑什么 |
| :-: | :-- | :-- |
| **①** 受控对照 | 只改一个设计因素，给出两侧数 | **可以支撑设计决策** |
| **②** 端到端对照 | 换了整套方法 | 只能说「这套 vs 那套」，不能归因到某因素 |
| **③** 仅设计理由 | 有道理无数字 | 只能当假设 |
| **④** 单点观察 | 一个例子 / 一次运行 / 无对照 | 不能推广 |
| ⛔ **含人在回路** | 数可能很好，但方法不是纯自动 | 不进 ①，单列附录 |

〔用户明确裁定〕**只算纯自动的 LLM 方法**。判据：若「决定要不要再来一轮」「修复」「接受产物」三个动作中任何一个由人执行，不得进 ①。⚠️ 注意「人做了评测标注」不算人在回路（那是评测装置）；「人参与方法的执行循环」才算。

### 0.2 ⛔ 另一条硬约束

〔用户明确裁定〕**不做变异测试、不造新语料、不造修复模型——就在现有 54 个样本上做。** 所以每条建议额外标一个字段：**能否在不新增制品的前提下落地**。

## 2. 四条规律（只挂 ① 档，每条带分母与反例）

### 规律 1 · 把可机械判定那一层的裁决权从 LLM 手里拿走交给确定性检查器，在准确性维度上单调正收益，且常同时降成本

⚠️⛔ **本条已按 §9 重写。首版写「4 条 ① / 4 篇」，⛔ 逐条回原文核后只剩 1 条干净 ①。** ⭐ 但**规律本身站得住** —— ⭐ 理由要从经验换成解析，见下。

**⭐ 方向（解析命题，⛔ 不需代次折扣）**：健全检查器在**自己的谓词上**假阴率**按构造恒为 0**；LLM 检查器在**任何模型档位**都 > 0。⭐⭐ **这不是靠对照测出来的，是定义决定的** —— ⛔ 所以它不随模型代次失效，⭐ 这也是本规律唯一能在同代 ① 为零的情况下存活的原因。

**⚠️ 量级（纯经验，⛔ 同代 ① 为零）**：唯一一条干净 ① 是同一 10 个候选的一致性 **51.23–71.47% → 96.63–99.08%**（AbsCon，⛔ GPT-4o-mini / GPT-4o = 2024-05，**落后 23 个月**）。

⛔⛔ **首版另外三条支撑逐条撤回或改述**：

| 首版写的 | 核后实况 | 处置 |
| :-- | :-- | :-- |
| 结构不合规 **21.80% → 0%** | ⛔ **那个 0% 是定义出来的**。LADEX v3 §5.4 逐字：`accepted as that variant's output only if it passes the critique check` —— ⭐ 而 `Alg-*` 变体的 critique **就是**那个结构检查器。⛔ **换任何模型都是 0%** | ⛔ **准确性侧信息量为零**；⭐ 信息全在成本侧（**1.87 vs 4.65** 次调用），⭐ 那部分是真 ① |
| XSD 通过 **0% → 100%** | ⛔⛔ **卡里没有任何 0% 的 XSD 数据点。** ⭐ 唯一的 0/100 型配对是 `GPT-5` 无约束 **50%** → `32B + ICM-RAG` **100%** —— ⛔ **跨模型且跨方法，两个因子** | ⛔ **降为 ②**，⛔ 不得归因到确定性检查器 |
| precision **+41.02pp** / recall **+55.57pp** | ⛔ ProtocolGPT。⭐ 而本文件 §7.5.3 边界 3 自己判它 `⛔ 故与 SECON 并列进附录，⛔ 不进正表`（⭐ 依据：已释放制品的 `chat_loop()` 是 `while True: query = input("👉 ")`，⛔ **决定下一轮问什么的是人**）。⚠️ 且该增益全部来自 `code_filter.py` 里一份**按协议手写的实现标识符字典** | ⛔⛔ **撤回**（⭐ 违反用户裁定的「只算纯自动」硬门；⭐ 同时中 §3.5 的特判判据） |

⭐ **分母因此从 4 篇降到 1 篇**（量级侧）。⛔ 跨制品覆盖的说法（活动图 / ARXML / Mermaid / 协议 FSM）随之撤回。

⛔⛔ **两个必须一起报的反例**：

1. **成本维在有对齐检查时方向反转**：逐字 `when alignment checking is present, algorithmic structural checks have the opposite effect, requiring, on average, 1.73 times more calls`（⚠️ 括注的「某模型上 3.07×」**全库查不到出处**，⛔ 暂标待核）。**机制**：算法检查器看不到共因，同一缺陷在 critique 里出现两次。
2. **加确定性成分 ≠ 加任何检索都有用**：某篇只加 embedding 检索，P/R 从 **35.83/24.14 降到 22.63/19.24**。

**适用条件**：四条的判据**全部只看制品自身、不需外部真值**。

### 规律 2 · LLM 自评当裁决者时收益落在「几乎为零到小效应」区间，且伴随可测的误杀

**支撑**：3 条 ① / **仅 2 篇**——本文件分母最薄的一条。21.80% 只压到 18.34/19.48%（花 4.17–4.65 次调用换 2–3pp）· 加交叉核查 FP 428→217 但 TP **1096→938**（**误杀 14.4% 的真 issue**，recall −2.9pp）· 对齐层调用倍数换 correctness 0pp / completeness +2pp（⚠️ 首版写 **4.5×**，⛔ 卡里是 **3.87×**，⭐ 以卡为准）。

⛔ **反例**：在更强的表述上有反例——某篇在一个数据集上 3/6 组 correctness 显著改善，另一篇净 precision **+0.09 也是正的**。

⭐⭐ **所以只能写到「几乎为零到小效应 + 可测误杀」，⛔ 不能写成「零收益或负收益」。** 我此前写成后者，超出了证据。

**适用条件**：三条的模型档位全部偏低。而其中一篇自己给了代次威胁证据：某推理模型裸跑的召回已接近弱模型上整套方法。

### 规律 3 · 迭代收益在很早的轮次见底，而见底位置由生成端质量决定、不由轮数上限决定

**支撑**：3 条 ① / 3 篇，覆盖 40 + 180 + 726 个评测单位。完整臂第 4 轮触顶（**第 3、4 轮合计 +12.50pp = 全部 +25.00pp 增益的一半**）；删掉规划阶段后同一 oracle、同一 5 轮预算只买回一半并在**第 3–4 轮平掉**；某子集上两个配置**5 轮全零**。另一篇最优版本在第 **11** 轮、第 **12–16 轮零改动**。第三篇第 **5–8 个候选**见底，小模型继续加会退化。

⛔ **反例**：「见底」无反例，⚠️ 但「**几轮**见底」跨篇不一致（R4 / 第 11 轮 / 第 5–8 个候选）——**我们的「第 3 轮」不可外推**。

**适用条件**：三篇的「一轮」含义不同（反例引导修复轮 / 无裁决者盲改写轮 / 互不可见独立采样），成本结构也不同（其中一篇明写候选可并行，串行修订链不能）。

### 规律 4 · 判定口径的选择对结论的影响，量级与「换方法」同阶甚至更大

**支撑**：2 条 ① / 2 篇，最薄，且其中一篇未经同行评审。同批 300 份产出：**10.0% → 4.0% → 1.7%（6×）**；同批的语法门 vs 语义门膨胀 **5.4×–22.3×**。另一篇同批产物一致性 96.6–100% 而对参考图 F1 只有 68–80%。

⛔ **无反向 ①**。⚠️ 但这可能是发表偏置——不改变结论的口径变更没理由被写出来。

⚠️⛔ **一处必须挡住的直引陷阱**：那个「11×」的第四档是**重新采样**的（把配置名告诉模型再问一遍），与上三档不同批。**同批口径效应是 6×**，摘要把 6× 与 11× 并列给出。

## 3. ⭐⭐⭐ 一条比上面四条规律更要紧的事实

**11 条「可直接照做」的实验设计，共同前提在同一处不成立：它们的裁决装置我们都没有。**

| 谁 | 它的裁决装置 |
| :-- | :-- |
| LADEX | B-Match（确定性迹语义 + 嵌入）+ **已对人类共识校准的 L-Match**（Cohen $\kappa$ = 0.916 / 0.888，P/R/F1 = 96.59/95.60/96.03）+ 专家 GT |
| PAT-Agent | 用户给的**期望验证结果**（VALID/INVALID **双侧钉死**） |
| Event-B Agent | Rodin **机械导出**的证明义务 |
| TLA+-Bench | TLC（全可达状态空间） |
| ⭐ **我们** | ⛔ **只有人写的台账** |

⭐⭐ **含义**：搬别人的实验设计**不会降低成本**——两侧的数仍要靠人工逐位判定。所以「照做某个消融」这件事的真实代价是**又一轮 588 位人工判定**，不是「改几行代码」。

### 3.1 而且：同任务形状的四篇，**无一有机械裁决装置**

任务形状 = 「拿一份自然语言文本去检查一份形式化制品、产出缺陷列表」。全库 **3 篇同形 + 1 篇部分符合**：

| 篇 | 裁决装置 |
| :-- | :-- |
| **MCeT**（MODELS 2025，⭐ 全库唯一完全同形） | ⛔ **零 sound oracle，全程 LLM 自评**。唯一确定性组件（parser）只切原子不判对错；「这条 issue 是不是幻觉」由**另一次 LLM 调用**判。评测端两位作者亲判 1524 条，前 20% 双人 $\kappa$ = 0.79，**其余 80% 分工单判无二审** |
| **LADEX 的对齐路**（EMSE 2026） | ⛔ **只能是 LLM**（作者明写这是设计空间唯一选项）；⭐ 评测端三重且校准过 |
| **RFSeek**（arXiv 2025，方向镜像） | ⛔ **零机械裁决**，唯一验证是人在 UI 里自己判；⚠️ provenance 是 **LLM 断言的、未被机器核验** |
| **Internetware 2025**（部分符合，须打折） | ⛔ 名义上有「模型 vs 需求」一类，⚠️ 但**操作化成与人建参考模型算 F1**，实际是 model-vs-model；两类由**人判**，无 $\kappa$ |

⭐ 全库唯一在这个形状上有确定性裁决装置的是一篇歧义检测工作，⛔ **而它靠「多次生成看散不散」，只测稳定性不测正确性** —— **一致的错也是一致的**（作者两次明写 `not as a proof of semantic correctness`）。

⭐⭐⭐ **这是 L3 最硬的一条结论**：**「拿 NL 去机械裁决一份形式化制品」这件事，全库没有先例。** 我们没有 oracle 不是实现疏忽，是这个问题至今没有人解决。

### 4.5 ⛔⛔ 受限解码：⭐ 这条路我们不在上面，⛔ 而它也不是「错误的路」

⚠️ 本节存在的唯一理由是：⛔ **我先前把 ATLAS 对受限解码的一条警告，误写成「我们正落在它警告的那一侧」。** ⭐ 为免后人重复这个误解，把前因后果写清。

#### 什么是解码，谁在做

⭐ LLM 每一步输出的**不是一个词**，⭐ 而是**整个词表上的一个概率分布**（约十万个 token）。⭐ 把这个分布变成一个具体 token 的那一步叫**解码**。

⭐⭐ **它在推理引擎里**（vLLM / llama.cpp / 服务商的推理栈），⛔ **不在模型权重里，也不在我们的应用代码里**。⭐ 循环是：前向一次 → 得分布 → 解码器挑一个 token → 拼上 → 再前向。⭐ 取最大、按温度采样、top-p 截断，⭐ 全是**解码策略**。

#### 受限解码是在这个循环里插一刀

⭐ **在解码器挑之前**，先用一个自动机（⭐ 从 JSON schema / 正则 / 语法编译出来）算：⭐ 哪些 token 接上去之后输出还有可能走到合法终态。⛔ 不满足的**概率直接置零**，⭐ 再在剩下的里按原策略采样。⭐ ATLAS 的形式化：

$$M_t = \{y \mid \delta(s_t,y)\neq\bot \land \mathrm{ReachAccept}(\delta(s_t,y))\}$$

⭐⭐ **结果是语法上百分之百合法** —— ⛔ 不是「大概率合法」，⭐ 而是非法路径根本不给采。

⭐⭐ **谁能做**：⛔ **只有跑推理循环的那一方。** ⭐ 自部署（vLLM + outlines / xgrammar、llama.cpp 的 GBNF）能做；⭐ 调 hosted API 只有服务商开了口子才能做。⭐⭐ **这是基础设施层的能力，⛔ 不是 prompt 技巧** —— ⭐ 在 prompt 里写「请输出合法 JSON」与受限解码是两件完全不同的事。

#### 那条副作用怎么来的

⭐ 关键在**重归一化**。⭐ 置零后剩下的概率和不到 1，⭐ 要重新归一化。⭐ 而在任何「可以提前收尾」的语法里（⭐ JSON 对象可少写可选字段、⭐ 数组可少几个元素），⭐ **闭合符号在几乎每一步都合法**，⭐ 因为它们直接通向接受态；⛔ 而「继续加内容」那条路要经过更多步、⭐ 每步还要再过一次掩码。⭐ 于是每次重归一化都把一点质量往「现在收尾」挪，⛔ **累积下来输出系统性偏短**。

⭐ ATLAS 逐字：`L1 enforcement changes the model's token distribution and **can over-favor short valid completions**`；⭐ 缓解手段它自称 `engineering controls rather than formal guarantees`。

⚠️ **上面那段机制推导（闭合符号吃到额外质量）是重建，⛔ 不是 ATLAS 逐字写的。** ⭐ 它写的只有结论。

#### ⛔ 我们不在这条路上

⭐ 我们的做法是：⭐ 调 hosted API → ⭐ 拿完整输出 → ⭐ **事后**用 Pydantic 校验 → ⛔ 失败则把解析错误回灌、**原地重试**。

⭐⭐ **与受限解码机制不同**：⛔ 受限解码是**逐 token 掩码**（⭐ 所以有重归一化偏差）；⭐ 我们是**事后校验 + 整体重来**（⛔ 没有逐 token 干预，⭐ 也就没有那个偏差）。

⛔⛔ **所以 ATLAS 那条警告套不到我们身上。**

#### ⛔ 但它也不是「错误的路」——⭐ 三条事实

## 9. ⭐⭐⭐ 第二个轴：论文里用的 LLM 是哪一代

### 9.0 这一节为什么必须存在

⛔⛔ **前八节的分级只回答了「对照是否受控」，⭐ 完全没回答「用的是哪一代模型」。** ⭐ 这两件事独立，⛔ 而漏掉后者会系统性地把旧证据当新证据用。

用户原话：**「你已经多次将 2 年前以上的模型得到的 paper 结论来丢给我让我被误导了」**。

⭐ 判据很直接：一篇 2024 年用 `GPT-4` 的 ① 档受控对照，**方法学上无懈可击**，⛔ 但它测的能力区间在 2026-08 已经不存在。⭐ 对我们（主臂 `gpt-5.5` 2026-04-23 / `claude-opus-4-7` 2026-04-16）而言，**它的参考价值可能低于一篇 2026 年的 ③ 档设计理由**。

**参照点**取主臂较早者 `claude-opus-4-7` = **2026-04**，使代际差不被高估。**分档**：A 同代 ≤6 月 · B 近一代 7–16 月 · C 隔代 17–28 月 · D 两代以上 ≥29 月或无法 pin。

**工具**：[tools/model_recency.py](./tools/model_recency.py)，配 5 个回归测试。⛔ 它是**候选集生成器，不是判定器** —— ⭐ 它把三类假阳性钉在注释里（我方型号污染 · 卡间互引 · 论文内部跨代），⛔ 判定必须回卡与原文。

### 9.2 ⛔⛔ 规律 2 在代次约束下不成立 —— 本节最重要的一条

**规律 2 的全部三条支撑，主结果模型都是厂商家族里的最弱档**：

- LADEX 用 GPT-4.1-**Mini** 与 O4-**Mini**（2025-04，落后 12 个月）
- MCeT 主结果用 GPT-4o-**mini**（2024-07，落后 21 个月），⭐ 且论文自己给了理由，逐字：`GPT-4o-mini is selected as it is a lightweight, cost-efficient, and fast LLM`

⛔ **没有一条来自 2025-11 之后，⛔ 也没有一条来自任何厂商的旗舰档。**

⭐⭐ **而 MCeT 自己给了代次威胁的直接证据**，逐字（§VI-C）：

> `This is because the LLM's reasoning attempts a fine-grained evaluation, similar to the MCeT approach`

**即 DeepSeek-R1 裸跑（无任何方法）的 holistic 召回 50%，⭐ 而 GPT-4o-mini 上整套 MCeT 是 68.1%（裸 holistic 34.1%，成本 6.7×）。** ⭐ 严格说：**一次代次跨越（2024-07 → 2025-01）吃掉了该方法 34.1pp 增益里的约 16pp（≈47%）**，⛔ 不是全部。**限定**：RQ3 只有 8 张图，且按主结果 per-case precision 分层抽的。

⭐⭐⭐ **含义**：「LLM 自评当裁决者收益近零」是在 mini 档模型上测的。⭐ 我们用 frontier。**这条两个方向都说不通**：

- 可能 frontier 上自评**更有用**（⭐ mini 模型的评审能力本身就不够）
- 也可能 frontier 上**更没用**（⭐ 裸输出已经够好，没有 headroom）

⛔ **数据与两者都相容，⛔ 所以它是未定的。** ⭐ 而且它是**纯能力命题**，⛔ 方向可能反转而不只是量级变化 —— ⭐ 更强的 critique 抓到更多真违规，收益会**上升**。

⭐⭐ **这不降低而是抬高「拆掉两个自评 reviewer 跑同网格」的优先级** —— ⭐ 因为文献在这件事上给不出任何一边的证据，⛔ 只能自己测。

### 9.3 ⭐⭐ 规律 3 为什么反而是代次鲁棒性最强的

⭐ 不是因为它的模型新（**它一条 A 档都没有**），⭐ 而是因为 **PAT-Agent 自己做了一次能力轴检验**：

1. 它的**停机条件就是被测指标**（FPR）—— ⭐ 饱和是结构后果，⛔ 不是能力上限
2. 它**内部跨 6 个配对**覆盖 round-0 从 **.4250 到 .7500** 的能力区间，⭐ **六条曲线形状全部一致**

⭐⭐ **推论**：模型变强 → round-0 起点更高 → **见底更早**。⛔ 即循环会变得**更快**多余，⛔ 不是更有用。

### 9.4 ⛔⛔ 语料里**没有**可用的「一次代次跨越值多少」的测量 —— ⭐ 但有一个方差地板

⚠️⛔ **本节相对上一版整体重写。** ⭐ 上一版把这张卡当成「语料里对代次效应的直接测量」并据此下了一个比值结论；⛔⛔ **该结论已撤回，⭐ 因为它在该论文自己的样本量（n=32、每格单跑）下不显著。** ⭐ 撤回的依据是本节新增的显著性检验与噪声地板。

### 9.5 ⭐⭐⭐ D2 取到表了：⛔ 是零效应，⛔ 不是反向 —— ⭐ 而原文把自己的表读错了

⚠️⛔ **本节相对上一版整体重写。** ⭐ 上一版据原文那句 `indicating that modern LLMs are able to perform finite-state reasoning directly in RTL without explicitly reconstructing the FSM structure in YAML`，⛔ 判「D2 的唯一同代证据是反向的」。⭐⭐ **取表之后该判定撤回。**

#### ⭐ 它是干净的 ①，⭐ 而且结构上就是我们的形状

⭐ §3.8 逐字：臂 1 `the model generates SystemVerilog directly from the NL specification`；⭐ 臂 2 `the model first produces an fsm2sv-compatible YAML FSM, which is compiled to RTL and evaluated using the same criterion`。

⭐⭐ **即 LLM → 闭合 schema 的结构化中间物 → 确定性编译器 → 最终制品**，⭐ 对照臂是 LLM 直接写最终制品。⭐ 同 spec · 同判据 · 同模型集 · 同分母（Easy 334 / Med 333 / Hard 333 / 合计 **1000**）· `Pass@1`。⭐⭐⭐ **唯一变的设计因子就是闭合中间表示的有无。**
