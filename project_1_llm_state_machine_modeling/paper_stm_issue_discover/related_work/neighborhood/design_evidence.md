# 设计证据总账 —— 九个决策点上文献到底测过什么

⛔⛔ **防火墙**：本目录是**方法素材**，不是论文证据。任何一条要进论文必须回 [L1](../landscape/) / [L2](../provenance/) 的门重走。

## 0. 这份文件为什么单开

前面的 [SUMMARY.md](./SUMMARY.md) 与 [m1_recommendations.md](./m1_recommendations.md) 犯过同一类错误**四次**：把「某篇论文做了什么」直接读成「我们该怎么做」。四次都是数字对、推理不对。

所以本文件换判据：**只认受控对照**——论文只改了一个设计因素、其余保持不变、并给出两侧的数。其余一律降级，且降级后**不许用来支撑设计决策**。

### 0.1 分档

| 档 | 定义 | 能支撑什么 |
| :-: | :-- | :-- |
| **①** 受控对照 | 只改一个设计因素，给出两侧数 | **可以支撑设计决策** |
| **②** 端到端对照 | 换了整套方法 | 只能说「这套 vs 那套」，不能归因到某因素 |
| **③** 仅设计理由 | 有道理无数字 | 只能当假设 |
| **④** 单点观察 | 一个例子 / 一次运行 / 无对照 | 不能推广 |
| ⛔ **含人在回路** | 数可能很好，但方法不是纯自动 | 不进 ①，单列附录 |

〔用户明确裁定〕**只算纯自动的 LLM 方法**。判据：若「决定要不要再来一轮」「修复」「接受产物」三个动作中任何一个由人执行，不得进 ①。⚠️ 注意「人做了评测标注」不算人在回路（那是评测装置）；「人参与方法的执行循环」才算。

### 0.2 ⛔ 另一条硬约束

〔用户明确裁定〕**不做变异测试、不造新语料、不造修复模型——就在现有 54 个样本上做。** 所以每条建议额外标一个字段：**能否在不新增制品的前提下落地**。

### 1.1 ⛔⛔ D2 与 D3 零证据 —— 这是本轮最重要的发现

**D2**：全库 **14 项**有闭合中间表示、**5 项**有开放的，⛔ **没有一篇把同一集合做成两个臂**。最接近的反面材料（某篇的开放生成依赖型约束 recall **0.0%** vs 闭合容器的 msg-type **92.8%**）是**同系统不同元素类的表现差**，判 **④**。

⚠️ 我此前把它写成「闭合词表在语义层最硬的外部证据」，**那是错的**——它同时变了词表开闭与约束类型两个因素，且不是同一个集合的两个臂。

**D3**：五种选类形态各有实例（LLM 自动选 · 确定性算法选 · 人按对象挑 · 阶段硬编码 · 不选全量施加），⛔ **但每篇内部固定**。唯一那条 ① 的两侧**都是确定性算法、既无 LLM 也无人**。

⭐ 「闭合词表 + LLM 自动选」有 **4 个先例**，但集合规模都远小于我们的 19：**5** 个事件符号 · **3** 类断言 · **3** 类 error_class · **6** 桶。另一篇是两段式（确定性 pattern matching 选 7 类之一 → LLM 从原子函数库选并填参）。

⭐⭐ **含义**：我们那两条设计（19 条闭合 + LLM 自动选）**在文献里既没有支持也没有反对**。改它或不改它，都不能引外部证据；只能自己做对照。

## 2. 四条规律（只挂 ① 档，每条带分母与反例）

### 规律 1 · 把可机械判定那一层的裁决权从 LLM 手里拿走交给确定性检查器，在准确性维度上单调正收益，且常同时降成本

**支撑**：4 条 ① / 4 篇，跨活动图 / ARXML / Mermaid / 协议 FSM 四种制品。结构不合规 **21.80% → 0%**（同时调用少 2.49×）· XSD 通过 **0% → 100%** · 同一 10 个候选一致性 **51.23–71.47% → 96.63–99.08%** · precision **+41.02pp** / recall **+55.57pp**。

⛔⛔ **两个必须一起报的反例**：

1. **成本维在有对齐检查时方向反转**：逐字 `when alignment checking is present, algorithmic structural checks have the opposite effect, requiring, on average, 1.73 times more calls`（某模型上 3.07×）。**机制**：算法检查器看不到共因，同一缺陷在 critique 里出现两次。
2. **加确定性成分 ≠ 加任何检索都有用**：某篇只加 embedding 检索，P/R 从 **35.83/24.14 降到 22.63/19.24**。

**适用条件**：四条的判据**全部只看制品自身、不需外部真值**。

### 规律 2 · LLM 自评当裁决者时收益落在「几乎为零到小效应」区间，且伴随可测的误杀

**支撑**：3 条 ① / **仅 2 篇**——本文件分母最薄的一条。21.80% 只压到 18.34/19.48%（花 4.17–4.65 次调用换 2–3pp）· 加交叉核查 FP 428→217 但 TP **1096→938**（**误杀 14.4% 的真 issue**，recall −2.9pp）· 对齐层 **4.5× 调用换 correctness 0pp / completeness +2pp**。

⛔ **反例**：在更强的表述上有反例——某篇在一个数据集上 3/6 组 correctness 显著改善，另一篇净 precision **+0.09 也是正的**。

⭐⭐ **所以只能写到「几乎为零到小效应 + 可测误杀」，⛔ 不能写成「零收益或负收益」。** 我此前写成后者，超出了证据。

**适用条件**：三条的模型档位全部偏低。而其中一篇自己给了代次威胁证据：某推理模型裸跑的召回已接近弱模型上整套方法。

### 规律 3 · 迭代收益在很早的轮次见底，而见底位置由生成端质量决定、不由轮数上限决定

**支撑**：3 条 ① / 3 篇，覆盖 40 + 180 + 726 个评测单位。完整臂第 4 轮触顶（**第 3、4 轮合计 +12.50pp = 全部 +25.00pp 增益的一半**）；删掉规划阶段后同一 oracle、同一 5 轮预算只买回一半并在**第 3–4 轮平掉**；某子集上两个配置**5 轮全零**。另一篇最优版本在第 **11** 轮、第 **12–16 轮零改动**。第三篇第 **5–8 个候选**见底，小模型继续加会退化。

⛔ **反例**：「见底」无反例，⚠️ 但「**几轮**见底」跨篇不一致（R4 / 第 11 轮 / 第 5–8 个候选）——**我们的「第 3 轮」不可外推**。

**适用条件**：三篇的「一轮」含义不同（反例引导修复轮 / 无裁决者盲改写轮 / 互不可见独立采样），成本结构也不同（其中一篇明写候选可并行，串行修订链不能）。

### 规律 4 · 判定口径的选择对结论的影响，量级与「换方法」同阶甚至更大

**支撑**：2 条 ① / 2 篇，最薄，且其中一篇未经同行评审。同批 300 份产出：**10.0% → 4.0% → 1.7%（6×）**；同批的语法门 vs 语义门膨胀 **5.4×–22.3×**。另一篇同批产物一致性 96.6–100% 而对参考图 F1 只有 68–80%。

⛔ **无反向 ①**。⚠️ 但这可能是发表偏置——不改变结论的口径变更没理由被写出来。

⚠️⛔ **一处必须挡住的直引陷阱**：那个「11×」的第四档是**重新采样**的（把配置名告诉模型再问一遍），与上三档不同批。**同批口径效应是 6×**，摘要把 6× 与 11× 并列给出。

## 3. ⭐⭐⭐ 一条比上面四条规律更要紧的事实

**11 条「可直接照做」的实验设计，共同前提在同一处不成立：它们的裁决装置我们都没有。**

| 谁 | 它的裁决装置 |
| :-- | :-- |
| LADEX | B-Match（确定性迹语义 + 嵌入）+ **已对人类共识校准的 L-Match**（Cohen $\kappa$ = 0.916 / 0.888，P/R/F1 = 96.59/95.60/96.03）+ 专家 GT |
| PAT-Agent | 用户给的**期望验证结果**（VALID/INVALID **双侧钉死**） |
| Event-B Agent | Rodin **机械导出**的证明义务 |
| TLA+-Bench | TLC（全可达状态空间） |
| ⭐ **我们** | ⛔ **只有人写的台账** |

⭐⭐ **含义**：搬别人的实验设计**不会降低成本**——两侧的数仍要靠人工逐位判定。所以「照做某个消融」这件事的真实代价是**又一轮 588 位人工判定**，不是「改几行代码」。

### 3.1 而且：同任务形状的四篇，**无一有机械裁决装置**

任务形状 = 「拿一份自然语言文本去检查一份形式化制品、产出缺陷列表」。全库 **3 篇同形 + 1 篇部分符合**：

| 篇 | 裁决装置 |
| :-- | :-- |
| **MCeT**（MODELS 2025，⭐ 全库唯一完全同形） | ⛔ **零 sound oracle，全程 LLM 自评**。唯一确定性组件（parser）只切原子不判对错；「这条 issue 是不是幻觉」由**另一次 LLM 调用**判。评测端两位作者亲判 1524 条，前 20% 双人 $\kappa$ = 0.79，**其余 80% 分工单判无二审** |
| **LADEX 的对齐路**（EMSE 2026） | ⛔ **只能是 LLM**（作者明写这是设计空间唯一选项）；⭐ 评测端三重且校准过 |
| **RFSeek**（arXiv 2025，方向镜像） | ⛔ **零机械裁决**，唯一验证是人在 UI 里自己判；⚠️ provenance 是 **LLM 断言的、未被机器核验** |
| **Internetware 2025**（部分符合，须打折） | ⛔ 名义上有「模型 vs 需求」一类，⚠️ 但**操作化成与人建参考模型算 F1**，实际是 model-vs-model；两类由**人判**，无 $\kappa$ |

⭐ 全库唯一在这个形状上有确定性裁决装置的是一篇歧义检测工作，⛔ **而它靠「多次生成看散不散」，只测稳定性不测正确性** —— **一致的错也是一致的**（作者两次明写 `not as a proof of semantic correctness`）。

⭐⭐⭐ **这是 L3 最硬的一条结论**：**「拿 NL 去机械裁决一份形式化制品」这件事，全库没有先例。** 我们没有 oracle 不是实现疏忽，是这个问题至今没有人解决。

## 4. ⛔ 在「54 pair、不新增制品」约束下还剩什么

### 4.1 能落地（不新增制品）

| 做什么 | 挂哪条证据 | 代价 |
| :-- | :-- | :-- |
| **拆掉两个 LLM 自评 reviewer 跑同网格** | 规律 2 · LADEX RQ4（⭐ **论文自己把「不加对齐评审」列为 `preferred` 选项**） | ⛔ 一轮 588 位人工判定 |
| **删掉 `split_requirements` 里「选谓词」那一半，跑同网格** | 规律 3 · 某篇删规划阶段后同一 oracle 只买回一半 | 同上 |
| **把契约门报错从「只说过不过」升级成「推荐修法」** | D5 的 ①：RF **.7701 → .8665（+9.64pp）**（⭐ 两侧都有反例，变量只是有没有推荐修法） | ⛔ 改 prompt + 一轮判定 |
| **按报错文案形态分组比命中** | D5 的 ①：点名缺失元素类型近满分（8/8 · 2/2 · 9/9 · 30/30），要求判断合理性近零（**0/6 · 1/13 · 12/45**） | ⭐ **零成本，用现有记录** |
| **两个模型交叉换角色跑一轮** | D7 的 ①：6 个模型配对第 5 轮 FPR 极差 **.6750 → 1.0000** | ⭐ 近零成本 |
| **把已声明元素清单确定性注入 prompt** | D6 的 ①：XSD **0% → 100%** | ⛔ 改 prompt + 一轮判定 |
| ⭐⭐ **报「两代次命中集合的对称差」而不只报净变化** | D8：某篇逐字 `changed back and forth between TRUE and FALSE for several iterations` | ⭐⭐ **零成本，我们现在只报净变化 ≈ 0，没拆开「没修好」与「修好的与新引入的相抵」** |

### 4.2 ⛔ 不能落地（要新增制品，已剔除）

| 做什么 | 为什么剔除 |
| :-- | :-- |
| 抗变异探针 | 要造变异体。⭐ 且独立复核已查明：它的外部出处**变异的是被检性质不是模型**，「往模型注入变异」在原文是**明写的 future work**；其数字在**它自己发布的数据里复算不出来**（论文 5/300，实测 2/300，且 `reproduce.py` 硬编码 `survivors = 5`） |
| 「修掉缺陷再验」替代方案 | 要造修复模型 |
| 反向合成扩语料 | 要造新语料。⭐ 且它的四条人工准则逐字把**歧义 / 遗漏 / 隐含约定**全清洗掉了 |
| 构造端 ILP | ⭐ 只在结构族部分成立；⛔ 仿真族 6 条 + BMC 族 3 条**不是线性约束**；⛔ 且 concretization **只能减不能补**，对「根本没问」那批结构上无效 |
| 非真空探针 | ⛔⛔ **极性反了**：我们这套实现里**命中 = 断言为 False**，所以空真通过不会抬高命中数，⭐ 它让需求被判满足、**期望缺陷直接丢掉**。仓库自己 `capability.py` 逐字：`the requirement is reported satisfied and **its expected issue is lost**`。⭐ 即它测的是**漏检**，不是虚报。⚠️ 且适用面只剩 **223 / 30607 = 0.72%** 的谓词调用（纯存在性谓词占 **64.3%**，根本没有前件） |

⚠️ **但非真空那一族里有一条可以在 54 pair 上做、且不新增制品**：**False 归因**——对一条 False primary 跑它的 `presupposes()`，若某个预设也为 False，则这条 False 由「元素缺失」解释而非需求关心的那件事解释。`presupposes()` **已存在且从 `field_specs` 自动派生**，零 LLM 调用。

### 4.3 ⭐ 顺带一件应当直接写进方法的事

反空真机制**这套实现里已经有八道，全是事前拦截**（拒绝把 root 绑给 target · 拒绝 transient 主体 · 0 分支时 raise · 未声明 scope 时 raise · 把 `simulate`/`states` 从命名空间移除 · 未解析引用门 · 重言式 invariant 条件的层级感知检测 · combo 降级拦截），各自都拦到过真实事故。

⭐ **正确的呈现方式是把这八道列成一张方法表并说明各自拦到了什么**，⛔ 不是新加一个指标——事后去测一个事前已被封堵的东西，期望值接近 0。
