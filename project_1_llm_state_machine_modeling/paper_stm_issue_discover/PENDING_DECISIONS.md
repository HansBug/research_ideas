### 前因

伞 PR §4.0.2 立了一道**边界门**：本文的建模对象是 $M = (S, E, V, Tr, A)$，⛔ 无时钟、无不变式、无正交区并发。这条边界**同时约束文献检索**，理由逐字是「拿界外对象的文献给界内谓词挂出处，本身就不成立」——时间自动机里「每个 location 必须配 invariant」是关于**另一种数学对象**的规范，它证明不了我们的 $M$ 上有同样的义务。这条论证成立。

但 L1 在做梯次方案时撞上一类**§4.0.2 字面没有处置**的东西，暂称**邻域**：对象既不是 $M$、也不是那些被明确排除的形式主义，而是**另一种制品**——RTL（SVA 断言生成）、源代码（不变量合成）。它们的**形状与 contribution ② 高度相似**：把规约模式做成有限词表、交给自动化去挑、在已有制品上求值。

⚠️ **这不是假想的边角情况**，它落在 L1 五问里最可能崩的那一问上：

| 事实 | 数字 | 复算 |
| :-- | :-- | :-- |
| `baselines/` 匹配 `assert\|contract\|ocl\|invariant` 的目录 | **0** / 91 | `ls -d baselines/*/ \| grep -icE 'assert\|contract\|ocl\|invariant'` |
| `sources/` 同上 | **0** / 787 | 同上 |
| `state_machine_types/` 同上 | 8 / 679，逐个核为 **7 contract automata**（其中 1 个标题含 UPPAAL、1 个 real-time）**+ 1 个 Petri 网** | 见 [related_work/CONTINGENCY_L1.md](./related_work/CONTINGENCY_L1.md) §7 |
| ⟹ **界内可用上限** | **≤ 5 篇** | 8 − Petri 1 − UPPAAL 1 − real-time 1 |
| 全仓 `specification-pattern\|dwyer` 目录 | **0** | —— |

⭐ 也就是说：**contribution ② 的对照面，在三个语料库里几乎是空的，而邻域是满的。** L1 把这个失败形态命名为「**界内空、界外满**」，并判它是五问里最可能崩的一问。

### 这一条为什么必须你定

⛔ challenger 明确指出 **L1 不得自裁**，而且指出 L1 现在的写法**其实已经自裁了，只是裁向了更严的一侧**。它的论证我认为成立：

> §4.0.2 的禁令**之所以成立，是因为出处是规范性义务**。而 `60.4%` 的量级背景**不主张任何规范性**——没人说 RTL 上的 recall 对 $M$ 有约束力，它只是一个带不可比性声明的数字。Q3-B 本来就允许「对象不同 + 执行者不同 + 缺陷集来源不同」三重不可比；**为什么第四种不可比（形式主义不同）必须是绝对禁止，而不是清单上的第四行？**

#### (b) 邻域能否作 **Related Work 的定位段**

### ⭐ 已调研（2026-08-11），下面是调研后的结论

⛔ **先说一个会被静默执行成「零应答」的坑。** L1 预案给的默认值是「邻域只在 `paper_story.md` §14 风险表出现一行」。⚠️ **但 §14 是内部文档的一节，论文里没有 §14。** 严格照默认值执行的结果是：**论文正文对「这不就是把 SVA 那套搬到状态机上吗」这条质疑一个字都不回**。默认值兜住了**备案**，⛔ 没兜住**应答**。

#### ⚠️ 调研推翻了我原先给的一条差别

我原以为「检查极性相反」（我们是需求为参照、模型为被怀疑对象）是一条能覆盖整个邻域的差别。⛔ **不成立**：

> **nl2postcond**（Endres 等，**FSE 2024**，DOI 10.1145/3660791）的极性与我们**完全一样**，且在 Defects4J 上命中 **64 个真实历史缺陷**——NL 意图 → 形式化断言 → 在既有制品上求值 → 判该制品有问题。

调研方判这条反驳「**致命，成立**」，于是把「极性相反」**收窄到只对 RTL 分支成立**。对 nl2postcond 只剩三处差别，⭐ **其中只有一条站得稳**：它**不记覆盖缺口**——表达不了的意图直接不产出，因而分母不闭合。这是**可核对的结构性差异**，不依赖谁做得更好。

另有两条打击：**NL2LTL**（AAAI-23）把「有限模板 + 自动选型」在 NL→LTL 上做过了；**Tagliaferro 等**（arXiv 2604.18228）的 compatibility filtering 是我们「覆盖缺口」的**同构物，而且比我们早**。⛔ 所以论文不得写「他们没有这个概念」，只能写处置方式不同（他们**过滤掉**，我们**留在分母里记成缺口**）。

#### (c) 邻域的**数值**能否作 `60.4%` 的量级背景

### ⭐ 已调研（2026-08-11）：`60.4%` **没有真正的参照系**，而且缺口是**结构性**的

⛔ **这不是「没查到」，是「不存在同口径的对象」。** 筛查约 **83 篇**（~102 条查询串，四路并行），三级分类：**A 级 1 篇（且不能当参照系）· B 级 12 篇 · C 级约 70 篇**。

#### ⭐ 一条几乎无例外的规律

> **凡是对象为状态机的检查类工作，都只报 precision 侧（检出多少、其中多少条对）；凡是报了召回的，对象都不是状态机。**

三方独立检索撞到同一堵墙：经典自动化线（Egyed TSE 2011 等）报的是 soundness / 运行时间 / 原始违规计数；LLM 线要么对象不是状态机、要么是生成侧；mutation 线的变异算子成熟但**用途全是评估测试集充分性**。

⭐ **1999 年 OOPSLA 就有完全同任务同对象的人工版本**（Travassos 等，OORT 垂直阅读技术第 3 条逐字是 "State Machines Diagrams with respect to Textual Requirements Description and Use-cases"），但那次研究只报「平均报告 11 个缺陷」，且论文自陈「no control group……只为探索可行性，不评估有效性」。**27 年来没有人给这个任务算过召回。**

#### A 级唯一条目——⛔ 但它不能当参照系

**On the consistency of state machines, use cases and block diagrams using dependency graphs and Large Language Models**（Sultan, Apvrille, Coudert，**SoSyM 2026**，CCF B，DOI 10.1007/s10270-026-01388-4，Open Access）。调研方**取到全文并逐字核对了表格**。其 graph-based 通道四门字面全中（有 `Missing` 列即 false negative，且全为 0）。

⛔ **四条理由各自独立地否掉它作参照系**：n = 3 且**模型是作者自己设计的**（论文自陈有 confirmation bias 风险）；缺陷类只有 logical dependency 一类；参照物是 UCD 一张图而非自然语言需求；检测器是**确定性图双射比较、答案先验已知**——论文自己把这节叫 "practical illustration"。

⚠️ 同一篇的 **LLM 通道反而落 B**：它明确放弃 FN 统计（"we observed the presence of false negatives"），只有 precision 侧。

#### B 级最接近的一篇：⭐ 而它就在我们自己库里，且被旧口径低估了

**MCeT: Behavioral Model Correctness Evaluation using Large Language Models**（Ahmed 等，**MODELS 2025**，pp. 84–95）——**结构上的孪生，只缺门 2**（对象是 UML 顺序图，不是状态机）。任务描述几乎逐字对应我们：给定需求文本 + 已有行为图，输出 issue 列表。

| 检查方式 | 精度 | FBench recall |
| :-- | --: | --: |
| Holistic（**baseline**，直接问 LLM） | 0.58 | **34.1%** |
| Combined MCeT-A | 0.72 | **68.1%** |
| Combined MCeT-X | 0.81 | 65.2% |

⚠️ **它已经在 `baselines/mcet/` 里，评级 🟠，理由写「这是行为模型评估器，不是状态机生成器」**——那是按**旧的 NL→STM 生成口径**打的分。⭐ **在 issue-discover 这条新故事线下它是最近的可比对象，本地评级明显低估，应重估。**

⭐ **缺口真实性的正面证据**：调研方做了 MCeT 的**前向引用检索**（5 篇引用），**没有任何一篇把它扩到状态机**；作者自己在 limitation 里说 "may not generalize to other types of behavioral models" 并列为 future work。**这说明缺口不是我们没搜到。**

#### 方案（调研后重估）

| 方案 | 好处 | 坏处 / 代价 | 工作量 |
| :-- | :-- | :-- | :-- |

| ③ 引邻域（SVA / 代码侧）数字 | —— | ⛔ 现已**不必要**：MCeT 是界内近邻（行为模型），比跨到 RTL 干净得多 | —— |

⭐ **我的建议：② —— 而且这条比我原先的建议更好。** 原先我倾向「谨慎允许邻域数字进 Discussion」，⛔ **现在不需要了**：MCeT 是**同任务、同指标族、同为行为模型**的对象，只差「顺序图 vs 状态机」这一门，比跨到 RTL 近得多。⭐ **N-2 那条对 §4.0.2 的修订提案因此可以不提**——问题被一个更近的对象解决了。

⛔ **三条陈述规矩，缺一不可**：
1. **只说同一指标族，不说方向。** ⛔ 两个数不可比大小——分母成分不同（人工评分者主观 issue vs 事前冻结台账）、对象不同、计数单位不同（issue vs 判定位）。

## 🔴 A3 · PSSM 一致性测试套件跑不跑

### 前因

19 条谓词里的 **6 条仿真类**（`occupancy_after` / `event_consumed` / `stays_in` / `terminates` / `reaches` / `variable_delta_after`），其最正当的规范出处是 **PSSM**（Precise Semantics of UML State Machines）——它定义 run-to-completion、事件池、deferred event、completion event 的执行语义。

⚠️ **本仓库从未读过它**（全库仅 3 处提及，无任何提取）。

L2 硬化时查实了一个关键事实：**PSSM 带一套 normative 机器可读的一致性测试套件**（`ptc/18-11-06`，列在 Normative Machine Readable Documents 下），并继承 UML 2.5.1 的合式性约束。

### 为什么它是双刃的

| | |
| :-- | :-- |
| ⭐ **好处** | 它是本轮**唯一**能让「我们的求值程序是否忠实于公认语义」这个问题**被第三方机械复核**的东西。引一段散文只能说「我们照着规范做的」；跑规范自带的套件是可验证的。 |
| ⚠️ **风险** | 它是 **P-驳斥档的引信**。跑一遍就可能发现**我们的仿真语义与规范不一致**。 |
| ⛔ **坏消息的分量** | 那意味着 6 条仿真谓词的真值是用**语义上不正确的程序**算出来的。暴露面已量化：**已发布支撑 187 / 1555 = 12.0%**（`occupancy_after` 104 + `reaches` 38 + `event_consumed` 19 + `terminates` 18 + `variable_delta_after` 6 + `stays_in` 2），台账断言 73/197 = 37.1%，primary 22/86。⛔ 而 588 冻结禁止重跑。 |

### ⚠️ 一个已经写死的陷阱

L2 预案原先有一句「查了一天 PSSM、已挂条数一条没涨」的挫败提示 —— 它的本意是提醒执行者别对已挂条数抱期望（PSSM 背书的是**求值程序**，不是**义务**，所以确实不涨条数）。但 challenger 指出：

> ⛔ **这句话会让执行者压缩这块投入 —— 而那恰好压缩掉唯一能发现方法级错误的动作。**

硬化时已写死「⛔ 不许因不涨条数被砍，未做须显式记录」。

### 方案

| 方案 | 好处 | 坏处 / 代价 | 工作量 |
| :-- | :-- | :-- | :-- |
| **① 跑** | ⭐ 唯一可第三方复核的判据；⭐ 若通过，6 条仿真谓词的 P 栏从 (b) 升到可执行验证 | ⚠️ 可能带回坏消息，且 588 冻结下**无法靠重跑修复**，只能量化 + Limitations 明写或升级导师 | 取件 + 跑套件，半天 |
| ② 不跑，只引散文 | 无风险 | ⛔ P 栏只能停在「引了一段规范」；⚠️ **不跑不等于问题不存在，而审稿人可能会跑** | ~2h |
| ③ 跑但不披露不利结果 | —— | ⛔ **不可接受**，学术不端 | —— |

⭐ **我的建议：① 跑。** 两条理由：

1. **不跑不等于问题不存在。** 若我们的仿真语义真的与规范有出入，那 12% 的支撑本来就是错的 —— 早发现比被审稿人发现好。
2. ⚠️ **但你要先接受一个可能的结局**：跑出来不一致，而 588 冻结下我们**改不了**，只能量化暴露面 + 在 Limitations 明写，或者把「是否解冻重跑」升级为导师议题。⛔ 这个结局的心理准备要在跑之前有，不能跑出来再纠结。

⚠️ 另一条 L2 查到的减分项：SQJ 2023 的批评指出 **RTC 步与事件池不在机器可读套件内**，所以那两个触发面**跑套件也暴露不了**，只能逐字读正文。即：跑套件能覆盖一部分，不是全部。

## 🟡 B1 · §7 主结论要不要重排

### 前因

`paper_outline.md` §7（结果）现在的内容是：三口径 + 双模型 + 逐轮极差 + 上界性说明 + 扣除阶梯 + 算力表，而硬约束第 4 条 **⛔ 禁止给任何相对性 claim**（不能说高、不能说好、不能与任何东西比）。

学术评审的原话判断：

> **读完这一小节，读者不知道作者想让他相信什么。** 一个报了数字却禁止一切解读的结果小节，审稿人会写「the headline result supports no claim」。

⭐ **而出路已经在材料里，只是排序错了。** `claim_evidence_map.md` **自己的强度分级**给出了答案（我逐行复算过）：

| claim | 内容 | 强度 | 出处 |
| :-- | :-- | :-- | :-- |
| **C7** | `hit@1 ≤ 60.4%` | `实测-中`——「数字本身是实测，但**只能作上界**，且**无外部对照**」 | `claim_evidence_map.md` 强度行 |
| **C10** | **双峰分布** | ⭐ `实测-强`——「**分布是直接计数**」 | 同上 |
| C11 | 能力归属：单模型专属仅 11.2% | `实测-中` | 同上 |

**C10 是整张表里评级最高的实测 claim，而它现在排在头条数字后面第三位。**

### 关键事实：分布形状类主张不需要对照系

我复算了这两组数（与官方 `355/588` 闭合）：

| 双峰分布（命中位数 → 记录数） | 0→**23** · 1→4 · 2→6 · 3→8 · 4→7 · 5→13 · 6→**37** |
| :-- | :-- |
| 合计 | 98 条记录，加权命中 355 ✅ 与 `hit@1` 闭合 |
| 两模型 | 都命中 64 / 仅 claude 9 / 仅 gpt 2 / 都未命中 23 |
| **单模型专属** | **11 / 98 = 11.2%** |

⭐ 由此能下的结论是：**方法的行为不是「普遍有六成把握」，而是「会的很会（37 条满格）、不会的完全不会（23 条零命中）」，且不会的那部分是方法的边界、不是执行模型的边界（单模型专属仅 11.2%）。**

⛔ 这条主张**自洽、可复算、不需要任何 baseline**。

### 方案

| 方案 | 好处 | 坏处 / 代价 | 工作量 |
| :-- | :-- | :-- | :-- |
| **① 维持现状**（`60.4%` 作主结论） | 不动 | ⛔ §7 没有一个它能下的结论；⛔ 主结论压在评级较低且双重受限的 C7 上 | 0 |
| **② 重排**：主结论改为能力形状，`60.4%` 降为该形状的汇总量 | ⭐ §7 有了一个**不依赖朴素基线**的结论；主结论换到全表评级最高的 C10 上；⛔ 且不需要任何新实验 | 需要重写 §7 的组织方式；⚠️ 头条数字降位，读者第一眼看到的不再是那个百分比 | 文字工作，R1 阶段 ~2h |
| ③ 两者并列 | 折中 | ⛔ 「并列」等于没有主结论，问题原样保留 | —— |

⭐ **我的建议：②，而且这是 B 档里我最想说服你的一条。** 它是**零实验成本**地让结果节从「报了个数」变成「说明了一件事」，而且**它降低了 [A2](#a2) 不跑基线的伤害**——如果主结论本来就不依赖对照系，那没有对照系就不再是致命伤。

⚠️ 一个附带建议（成本极低）：§7.1 现在有扣除阶梯（扣 10 位 → 58.7%、扣 51 位 → 51.7%，我复算过），但**没有说明为什么方向是单向的**。补一句「**所有已识别偏差同向（向下）**」，`≤` 就从「作者承认数字不可靠」变成「作者做了单向误差分析」。⛔ 同时必须写明 51.7% **不是**已证下界（扣除项枚举未论证穷尽、命中侧对称审计未做）。
