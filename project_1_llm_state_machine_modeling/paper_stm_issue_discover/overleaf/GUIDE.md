# F1 Overleaf Engineering Guide

## Purpose and boundaries

This is a portable IEEE conference project for the SANER 2027 Research Track **double-anonymous submission manuscript**. `main.tex` is the only English submission entry and the authoritative language. `main-zh.tex` is an internal Chinese companion marked as not for submission. F1 contains only generic, visibly marked `PLACEHOLDER`/`TODO` text, layout fixtures, and placeholder bibliography records; it contains no Paper1 claim, definition, method, study design, result, contribution, research question, real citation, data assertion, or asset. The user-authorized fixture prose is ordinary paper-style text, with `(THIS IS PLACEHOLDER TEXT, PLZ FULFILL IT WHEN WRITING.)` at the start of each visible section/abstract; it is not scientific content and must be replaced or removed in a later, separately approved writing goal.

## Ownership and layout

`main.tex` and `main-zh.tex` are the two roots. `config/` contains shared packages, language switches, the future results interface, and manifest metadata. `sections/index.tex` is the sole chapter-order source; the two roots must never duplicate that order. Every abstract, section, appendix, placeholder figure, placeholder table, and end-matter interface has a paired `.en.tex`/`.zh.tex` file with matching `SYNC-ID` comments; each visible fixture paragraph has its own paired block ID. Figures belong only in `figures/`; table sources belong only in `tables/`; `references.bib` is shared and currently contains only clearly marked placeholder records. No Paper1 content is placed in those directories during F1.

## Official template protection

The protected vendor tree is `template/official-original/`, extracted byte-for-byte from `template/source/IEEEtran-1.8b-ctan.zip`. The archive is the canonical IEEEtran distribution (version 1.8b, dated 2015-08-26) linked by the IEEE template page and distributed through CTAN. The provenance record documents the IEEE policy/template URLs, the Overleaf IEEE Official Template page, the CTAN download URL, retrieval date, archive SHA-256, license notices, and the WAF limitation encountered when retrieving the IEEE binary endpoint. `template/MANIFEST.sha256` inventories both the archive and every extracted file.

The vendor tree is read-only: do not delete, rename, reformat, patch, or add files. `IEEEtran.cls` and `IEEEtran.bst` at the project root are byte-identical work copies mapped to `official-original/IEEEtran/IEEEtran.cls` and `official-original/IEEEtran/bibtex/IEEEtran.bst`. `tools/validate-template-integrity` checks archive hash, extracted inventory, protected set, and both work-copy identities on every `make check`. To upgrade, add a new versioned archive/tree and provenance entry, review the diff, then switch the work-copy mapping; never overwrite historical vendor material. Our roots, sections, configs, scripts, and docs are separate self-owned files and never modify the official samples.

## Overleaf and local round trip

Upload this directory as one project without changing its paths. In Overleaf set `main.tex` as the root for the submission PDF; select `main-zh.tex` only for the internal companion. Download the source zip, extract it into a new empty directory, and run `make clean && make all && make check`. Both roots use `\\documentclass[10pt,conference]{IEEEtran}` and standard Overleaf `pdfLaTeX`; no shell escape, system fonts, absolute paths, `../` imports, symlinks, external server, or repository-outside resource is permitted. Clean builds must not use pre-existing aux/bbl/toc caches. Cloud Overleaf execution is not a credential-free CI step; local clean source-zip validation is reported as `OVERLEAF_PORTABLE_LOCAL_VALIDATION` and must not be described as a cloud run.

## Bilingual synchronization

English controls later scientific content and page budget. Each semantic paragraph/claim block gets one stable `% SYNC-ID: id` in each language. The ID sets, order, labels, citation keys, equation identifiers, figure/table inputs, and numeric macro uses must match exactly. Chinese may use natural syntax but may not add or omit a claim, evidence item, number, citation, limitation, modality, or ordering. `config/results.tex` is the only future numeric interface; later macros require a canonical in-repository JSON/TSV path, field or JSON pointer, snapshot hash, and verification commit. Canonical facts outrank prose. `tools/validate-bilingual` is deterministic and provider-free; semantic equivalence and visual naturalness remain human review gates.

## Writing-phase admission

After the user approves a section plan, freeze canonical fact/evidence sources before writing. Do not import talks, stories, issues, experiment archives, or old LaTeX drafts without explicit authorization and source verification. Every substantive block must record claim, evidence, number, citation, limitation, and epistemic strength against its `SYNC-ID`. Historical drafts remain references, never silent sources. F1 has no selected headline, title, abstract, contribution, or narrative.

## SANER/IEEE constraints (verified 2026-09-01)

The current SANER Research Track page requires original unpublished English PDF submissions, the IEEE Conference Proceedings format, a maximum of 10 pages with up to 2 additional pages for references only, electronic submission through EasyChair, and full double-anonymous review. The dates page lists abstract submission on Mon 21 Sep 2026 AoE and paper submission on Fri 25 Sep 2026 AoE. `Data Availability` is expected after Conclusions: a later manuscript must provide an anonymous artifact/data link and access method, or explain why sharing is not possible/suitable, including the post-acceptance intention when relevant. It is not correct to omit the section merely because sharing is optional. Appendix, Data Availability, and any AI disclosure count toward the 10-page body allowance; only references may use extra pages. Do not use `compsoc`/`compsocconf`, `geometry`, `titlesec`, `setspace`, margin/font/spacing overrides, compressed bibliography, negative spacing, or any other page-limit hack. Artifact sharing is encouraged but not mandatory and must be anonymous when used.

First-party sources: [SANER home](https://conf.researchr.org/home/saner-2027), [Research Track call](https://conf.researchr.org/track/saner-2027/saner-2027-papers), [dates](https://conf.researchr.org/dates/saner-2027), [SANER AI text policy](https://conf.researchr.org/attending/saner-2027/Guidelines+for+Artificial+Intelligence+%28AI%29-Generated+Text), [IEEE templates](https://www.ieee.org/conferences/publishing/templates.html), [IEEE Author Center](https://conferences.ieeeauthorcenter.ieee.org/write-your-paper/authoring-tools-and-templates/), and [IEEE Overleaf template](https://www.overleaf.com/latex/templates/ieee-conference-template/grfzhhncsfqn). The SANER AI page says substantive AI-generated text, figures, images, or code must be disclosed in acknowledgments with the system and sections identified; grammar/editing assistance is generally outside that requirement but disclosure is recommended. F1 makes no AI-use or Data Availability fact statement. A later writing PR must recheck the live policy.

## Data Availability and AI disclosure

`sections/10-data-availability.{en,zh}.tex` is a paired, normal section interface and must remain after Conclusions and before references. F1 contains only a deferred comment and no link, promise, or availability claim. A later writing PR must choose one truthful status from the live SANER call (anonymous access, a reason for non-sharing, and any post-acceptance intention) and count the section within the 10-page body budget.

AI disclosure is not a numbered Section 11. `sections/endmatter/acknowledgment.{en,zh}.tex` is a paired, unnumbered `Acknowledgment` interface selected by the single `\\ifshowaiack` switch in `config/common.tex`; it is false by default, so F1 PDFs contain no empty acknowledgment. If substantive AI-generated text, figures, images, or code is used, the live SANER/IEEE policy requires an anonymous acknowledgment naming the actual system and model/version, affected sections, purpose/extent, and human verification/responsibility. Grammar/editing assistance is usually outside the mandatory category but remains recommended for truthful disclosure. Double-anonymous submissions must not include identity, funding, or ordinary thanks. The final wording is generated from the author-side log and current policy, never from this scaffold.

The chosen later authoring boundary is low-degree assistance only: authors freeze claims, evidence, numbers, citations, limitations, modality, and conclusions first; `shuorenhua` may review Chinese clarity and naturalness; `academic-humanizer` may review English academic clarity and evidence-matched strength; authors accept each change and remain responsible. These tools may not choose research questions, generate or alter data/results/evidence, invent citations, make scientific decisions, or disguise substantive use as editing. Any use affecting research design, code, analysis, or adjudication is method provenance and must be reported as such. Keep an author-side log with system, model/version, date, purpose, sections, level, input/output revision, human verification, and accepted range. Recheck the live SANER/IEEE policy before submission; if use exceeds this boundary, upgrade disclosure rather than reusing a grammar-only statement. Skills are local author tools, never build dependencies, and are not copied into `overleaf/`.

## Anonymity and assets

Submission source and PDF must omit author names, affiliations, email, ORCID, ordinary identity-bearing acknowledgments, funding, identifying footnotes, personal/repository links, local paths, DOI/copyright/camera-ready blocks, and identifying PDF metadata. The requested camera-ready handoff values are kept only in the ignored `../author-info.private.md` file outside this project root and must never be copied into the double-anonymous source zip. If the live AI policy requires disclosure, the only permitted acknowledgment is the anonymous, factual AI-use statement described above; with no qualifying use, the conditional end matter remains disabled. Self-citations must remain third person or be anonymized when required by the live call. Do not claim that an artifact is public until redistribution licensing and an anonymous URL are verified. Figures should prefer language-neutral PDF/vector assets; raster assets use PNG; SVG shell conversion is not a dependency. Tables with text require language pairs, while purely numeric shared tables require the same frozen canonical values.

## Skills and later polishing

The local authoring skills are `$shuorenhua:shuorenhua` (source: https://github.com/MrGeDiao/shuorenhua) and `$academic-humanizer` (source: https://github.com/AIScientists-Dev/academic-humanizer). They were verified readable on 2026-09-01 from the local skill installations. They are author tools, never Overleaf dependencies. F1 does not invoke them on paper content. In every later substantive writing PR: freeze each `SYNC-ID` semantic block from canonical sources; audit the full relevant `SKILL.md` and references; use shuorenhua for Chinese and academic-humanizer for English; preserve every number, citation, claim, limitation, modality, causal strength, and responsibility; record skill version/hash, input revision, changes, and review result; then rerun bilingual semantic-equivalence and truthful SANER AI-policy checks. Neither skill may be used to evade disclosure.

## Placeholder fixtures and enforcement

The F1 builds intentionally render roughly two to three pages of ordinary generic placeholder paragraphs plus paired cross-column `figure*` and `table*` fixtures, additional single-column figure/table fixtures, and two clearly marked `PLACEHOLDER` BibTeX records. These fixtures test layout, pairing, and bibliography plumbing only; their labels, rows, captions, prose, and records must be replaced before submission. `tools/validate-content-boundary` rejects non-placeholder citation keys and unmarked figure/table content; it permits an abstract only when the visible placeholder marker is present.

## Enforcement and review

Run `make clean && make check` before and after every change. The check invokes template-integrity, bilingual, anonymity, format-policy, portability, and clean English/Chinese builds, then verifies non-empty PDFs, extractable text, metadata, page count, and absence of unresolved references/citations. Validators never edit files, call a provider, or depend on private state. Generated PDFs and TeX auxiliaries belong only under ignored `build/` and must never be committed. Human gates remain: venue/source accuracy, bilingual semantic equivalence, anonymous-word false positives, natural layout, and future claim/evidence correctness.

Each F1 PR must report the branch/base, commit, source URLs and hashes, all gate commands/results, local source-zip boundary, and three independent reviews: template/venue, build/portability, and bilingual/scope. Reviewers inspect current files and command output rather than relying on summaries. Any P0/P1 is fixed and rechecked by the responsible reviewer. The PR remains unmerged. `NO_METHOD_RERUN`, `NO_JUDGE_RERUN`, and `NO_RESULT_MUTATION` are explicit F1 invariants.
