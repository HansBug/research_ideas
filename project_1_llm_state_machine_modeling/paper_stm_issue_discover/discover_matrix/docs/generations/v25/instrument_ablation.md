## 一 · 预注册：用干净装置重判 v24（对**判定装置**的单变量实验）

**写于两位标注者开始之前，结果未知。** 本代次刚因「预测在前」不成立撤销过一次归因，所以这次把预期写死在数据之前，并指明**哪个观测能证伪它**。

### 实验设计

| | v24 原判定 | 本次重判 |
| :-- | :-- | :-- |
| 被判对象 | v24 的 66 格产物 | **同一批，逐字节相同**（冻结在盘上） |
| 样本 | `sample_id = 975ca6a5135cf732` | **同一个** |
| 判据文件 | `docs/protocol/hit_criterion.md`（含真实语料实例） | **`docs/judges/hit_criterion_for_judges.md`**（实例全部合成） |
| 指令边界 | 「读到『### 输出格式』」，装置限制节在 ⛔ 之上 | 「读到第一个 `## ⛔`」，泄漏节已移到 ⛔ 之下 |
| 读取控制 | **黑名单**（枚举十来项，漏了三处） | **白名单**（只允许 sample + 判据文件） |
| 输出示例 id | 真实（`C001-I01` / `PAIR-A-REC-02`） | 不存在的占位（`C999` / `PAIR-Z-*`） |

**唯一变化是判定装置。** 产物、样本、标注者角色设置全部不变。

### 预注册预期

#### 主预期：`hit@1` **下降或不变**

理由：泄漏的形态是**告诉标注者某些命题该判什么**（[docs/protocol/hit_criterion.md](../../protocol/hit_criterion.md) §3 的四种形态各配一个真实语料实例并给出命中裁定；§4.5 逐字引用一条已发布 issue 与对应台账 primary，并列出两读法各自的命中/不命中）。预装答案的方向是**指向命中**，因为那些实例全是"这算命中"的正例。

去掉它 → 命中判定失去外部支撑 → **`hit@1` 应下降或不变，不应上升**。

#### 副预期

| 量 | 预期 | 理由 |
| :-- | :-- | :-- |
| `κ_label` | **下降** | 泄漏是**共享**的外部锚点，两位标注者读同一份实例 → 人为提高一致性 |
| `fabricated` | 不定 | 泄漏的实例是命中正例，与虚构判定无直接关系 |
| `boundary` | 不定 | 同上 |

### 证伪条件（写死，不得事后调整）

| 观测 | 结论 |
| :-- | :-- |
| `hit@1` **上升 > 噪声底** | **主预期被证伪** —— 泄漏的方向与我判断的相反，需重新分析泄漏机制 |
| `hit@1` 变化 ≤ 噪声底 | 泄漏**未实际影响**判定，v24 数字站得住（但装置仍该修，已修） |
| `hit@1` 下降 > 噪声底 | 主预期成立，**v24 报告的覆盖率须就地下调** |
| `κ_label` **上升** | 副预期被证伪 —— 一致性提高不是泄漏造成的 |

**噪声底**：v24 逐轮 `hit@1` 极差 **7.4pp**（v23 为 2.9pp）。按仓库三级判据，取 max = **7.4pp**。

#### ⚠️ 我原先写「缺对照」，那是错的 —— 对照已经在数据里

原文：「噪声底是同一装置下重复运行的方差，而本次是同一运行、不同装置……严格说缺一个同一装置重判的对照来测判定方差。」

**那个对照已经有了**：每个条件下都有**两位**标注者，他们的分歧就是**同装置下的判定方差**。

| 条件 | 标注者 | 同装置内分歧（覆盖侧位） |
| :-- | :-- | :-- |
| 泄漏装置 | `A_leaky` 110/204、`B_leaky` 110/204 | **4 个位** |
| 干净装置 | `A_clean`、`B_clean` | 待测 |

**所以正确判据是：跨条件位移 vs 两个条件各自的组内分歧。**

    跨条件位移 ≤ max(组内分歧)        → 不可归因
    max(组内分歧) < 位移 ≤ 2×         → 弱信号位移 > 2× max(组内分歧)           → 可作装置效应讨论

📌 **我把已有的对照忽略了** —— 「两位标注者」这个安排同时提供了方差估计，而我只把它当成一致性检查。这与本代次几次机械代理失灵同型：**手上有数据而我以为没有。**

（`hit@1` 的逐轮极差 7.4pp 仍会并列报出，但它测的是**运行**方差，与装置无关，不作本次判据。）

### 无论结果如何都要做的事

1. 两组数字**并列**报（泄漏装置 / 干净装置），不替换
2. 泄漏装置下的标注已归档在 `onepass_sample/archive_v24_leaky/`，附泄漏证据清单
3. v24 的两条已发布 comment 按 §3.6 就地更正，注明「本代次的覆盖率数字在泄漏装置下产生」

### 一条自我提醒

我在写这份预注册时**不知道**结果。若结果与主预期一致，那不构成"我预测准了"的功劳 —— 方向本来就是从泄漏形态直接推出的，几乎不可能反。**有价值的是它被证伪的那种情形**，那说明我对泄漏机制的理解是错的。

## 二 · 结果（跑后填写，判据未改动）

预注册见本文件第一部分。**两条预注册预期都被否证，且方向相反。**

### 1. 装置隔离本身：从约定改为物理拆分后合规率 0/2 → 2/2

第一次尝试（指令与维护记录同文件、用 `## ⛔` 分节 + 「只读到此为止」）：**两名标注者都读了全文**，其中一位诚实披露它因此看到了一条 issue 的标题与命中结论、以及一条争议裁定，并指出自己约 14 条判断可能受影响。两份标注全部作废（见 `onepass_sample/contaminated_v25/WHY_CONTAMINATED.md`）。

物理拆分后（指令进 [docs/judges/onepass_instructions.md](../../judges/onepass_instructions.md)，往轮判定进 [docs/judges/onepass_maintenance.md](../../judges/onepass_maintenance.md)）：**两名标注者都明确披露未读白名单外任何文件。**

📌 **「读到哪为止」是约定，「不在文件里」才是边界。** 这是同一类泄漏的第四次，前三次修的都是「哪些内容不该读」，第四次修的是「读到哪」—— 四次都是约定。

### 2. 消融结果

| 量 | 值 |
| :-- | --: |
| 判定位 | 204 |
| 泄漏装置组内分歧（两标注者） | **4** |
| 干净装置组内分歧 | **1** |
| **跨条件位移（逐位）** | **2** |
| 其中 未中→命中 | 2 |
| 其中 命中→未中 | 0 |
| 判定（2 ≤ 4） | **不可归因** |

    leaky  保守合并 hit@1 = 108/204 = 52.9%
    clean  保守合并 hit@1 = 110/204 = 53.9%

#### 两条预注册预期的实测对照

| 预注册 | 理由 | 实测 | 判定 |
| :-- | :-- | :-- | :-- |
| `hit@1` **下降或不变** | 泄漏的例子全是「这算命中」的正例 | **+1.0pp（2 位上升）** | 方向相反，但**不可归因** |
| `κ_label` **下降** | 泄漏是两位标注者的共享锚点 | 组内分歧 **4 → 1**，一致性**升高** | **明确否证** |

📌 **「泄漏把两位标注者拉到一起」这个机制被否证。** 去掉泄漏后他们反而更一致。

#### 结论：v24 已发布的覆盖数字**不需要下调**

2 位位移对 4 位标注者噪声。按预注册的 falsification 条件（位移 ≤ 组内分歧上界 → 不可归因），**泄漏对覆盖侧没有可测影响。**

### 3. ⚠️ 这不是单变量消融，但混淆项的上界实测为零

干净臂同时改了两件事：① 移除泄漏；② 修 `boundary` 优先级缺陷（原优先级链使 `boundary` 永不可用，两位标注者**独立**发现了这一点）。

第二个变量能否解释那 2 位位移？实测：

| 标注者 | `boundary` 归属改变的 issue | 其中**改判为 `hits`** 的 |
| :-- | --: | --: |
| A | 15 | **0** |
| B | 6 | **0** |

**零。** `boundary` 修正只在 `boundary` ↔ `grounded-extra` 之间移动，而两者都不是命中 —— **它在结构上动不了 coverage。** 混淆项存在但上界为零，消融结论成立。

### 4. ⛔ 同一批数据暴露的更重问题：多报侧的 `fabricated` 不可测

| 装置 | `hits` | `grounded-extra` | `boundary` | `fabricated` | `duplicate-of` |
| :-- | --: | --: | --: | --: | --: |
| leaky A | 134 | 65 | 9 | **7** | 0 |
| leaky B | 132 | 63 | 18 | **2** | 0 |
| clean A | 133 | 58 | 24 | **0** | 0 |
| clean B | 132 | 71 | 12 | **0** | 0 |

两位干净装置标注者**独立**给出同一理由：样本**不含模型源文**（`.fcstm`），因此「该主张在模型上不成立」这一判定所需的证据够不着，按指令的「宁可漏判虚构」一律记 `grounded-extra`。两人都主动声明 **`fabricated` 只能读作下界 0，不携带信息**。

#### 这对已发布数字的影响

v23 / v24 发布的多报率（**7.2%–9.2%**，且当时已标注为下界）建立在**确实指派了 `fabricated` 的标注者** 之上。而现在两位标注者独立认为，在这个样本上该指派**没有证据支持**。

📌 **准确的表述是：多报率无法从一个不含模型源文的样本上测得。** 这不是「数字偏低」，而是 **该量在当前样本构造下没有定义**。要测它必须把 `.fcstm` 放进样本 —— 而那会同时把大量答案带进来，需要独立的隔离设计。

### 5. `duplicate-of` = 0 是与 `boundary` 同型的优先级缺陷（两标注者独立指出）

`duplicate-of` 排在优先级链最后，而任何重复项按内容必然同时属于前四类之一 —— **严格执行「选更靠前的」使它永不可用。** 我上一轮只给 `boundary` 开了例外，没给它开。

⚠️ **但双计本身仍可检出**：同一 unit 内重复的 `hits:` 别名即是。两位标注者都点出了具体位置（`C005`/`C006`/`C027`/`C028`/`C049` 各双计一条；`C031` 三计、`C032`/`C054` 四计；`C016`/`C060` 双计）。所以这是**分类口径缺陷**，不是测量能力缺失。

### 6. 两位标注者独立指出的判据缺陷（待处理）

| 缺陷 | 影响 | 两人是否一致 |
| :-- | :-- | :-- |
| `duplicate-of` 优先级不可达 | 分类口径，不影响 coverage | **一致** |
| `fabricated` 在无源文样本上不可判 | 多报侧**无定义** | **一致** |
| 一条 issue 同时陈述两条台账 → 另一条被记未命中 | **系统性低估** coverage | **一致**（都点名 `C059` / `C061`） |
| 命中判据 §5 的读法 A / 读法 B 开关决定 6–10 条的归属 | 该块归属不由标注者判断决定 | **一致** |

📌 **四条都是两位独立标注者各自提出、内容一致。** 这比任何单人 review 都强 —— 它们是判据的真缺陷，不是判定分歧。
