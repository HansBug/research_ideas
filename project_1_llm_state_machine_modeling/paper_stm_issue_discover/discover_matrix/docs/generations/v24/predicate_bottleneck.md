# 逐谓词诊断：瓶颈在**需求形成面**，不在谓词表达力，也不在并发边界

⚠️ **本文档经历了两次诊断更正，两次都是我猜错、独立裁定纠正。** 保留推理链是为了记住错在哪：

| 版本 | 我的诊断 | 结论 |
| :-- | :-- | :-- |
| v1 | 补谓词表达力（三个瓶颈谓词太弱） | **错** —— 同一谓词在命中组也出现 |
| v2 | fork/join/正交区边界（46.1% vs 56.9%） | **错，且方向相反** —— 34 条里只有 1 条越界且是命中，剔除后数字**下降** |
| **v3（当前）** | **需求形成面只有 NL 一个来源** | 独立裁定给出，且在 12/12 上完美分离 |

在废止 hold-out 带划分、把全部 34 条记录 / 204 个判定位纳入之后，第一次能做逐谓词分解。**这份分解在
按带划分时不可能得到** —— 那时可报带只有 2 条记录、跨 2 个谓词。

数据源：`verdicts/v23_blind_merged.json`（两位独立盲判者，κ = 0.980），逐谓词按 `primary_predicate`

## 二、瓶颈是三个谓词，占 62% 的单元

`state_declared` (38.1%) + `initial_target` (42.9%) + `edge_declared` (45.2%) = **42 / 68 单元
（61.8%）、126 / 204 位**。全体 `hit@1` 51.5% 基本由它们决定。

⚠️ **不要把 100% 那四行当成能力证据**：`cardinality` / `effect_declared` / `guard_distinguishable`
各只有 2 个单元、6 个位，`occupancy_after` 4 个单元。6 个位上的 100% 与 42 个位上的 38% 不可直接比较。
它们只说明「这些谓词没有暴露出问题」，不说明「它们很强」。

## 三、一个假设，及它为什么值得先验证

三个瓶颈谓词恰好是概念上**最简单**的「存在性声明」检查。最简单的最弱，这本身是线索。

区别在于断言的对象：

| 组 | 断言什么 | 需要什么前置知识 |
| :-- | :-- | :-- |
| 100% 组（`occupancy_after` / `cardinality` / `guard_distinguishable`） | 模型里**已有元素的性质** | 定位该元素 |
| 瓶颈组（`state_declared` / `edge_declared` / `initial_target`） | 某个东西**缺失** | **先知道「本该有什么」** |

**要断言缺失，必须先从 NL 正确枚举义务。** 所以假设是：

> 瓶颈在 NL 义务枚举，不在谓词表达力。若成立，该改的是 splitter / 需求抽取阶段，不是谓词词表。

### 已做的第一轮验证：假设的**朴素形式被否证**

查 13 条「两臂三轮全未命中」记录所在格的需求抽取数：0018 → 48、0038 → 48、0048 → 50、0032 → 22。
**需求抽取数并不低** —— 不是「义务完全没被抽出来」这种朴素失败。

所以假设需要收窄为：义务被抽出了，但**没有被转成能证伪它的断言**，或转出的断言选错了谓词 / 锚点。
下一步验证应当查这 13 条对应的 NL 句是否有需求覆盖、该需求是否有断言、断言的谓词与锚点是什么。

## 四之二、真正的解释：需求形成面缺一个模型内在来源

裁定给出的解释是**完美分离**的，且比边界假设深得多。

`wellformedness` 12 条的命中/漏检由一件事决定：**有没有一句 NL 点名了那个缺失元素。**

| | NL 是否点名 | 例 |
| :-- | :-- | :-- |
| **4 条命中** | **全部有** | `0035-01`「The microwave starts in the **DoorShut** state.」；`0043-02`「first transitions to the **PumpState** substate」 |
| **8 条漏检** | **全部无** | `0032` 三句 NL 从不点名默认子态；`0047` 说「There are three region」但不点名初始子态；`0038-06` 的 `nl_evidence` 字段逐字写着「无需 NL 作 oracle」 |

机制在 pipeline，不在边界。`discover/prompts.py` 第 7 行：

> The current FCSTM and inspect diagnostics are orientation evidence only. … **never turn a tool
> warning into a requirement.**

即**方法没有任何模型内在的需求来源**。一条 `layer_basis` 自陈「模型自身即可判定，不需要 NL 也不需要
参考模型」的记录，**按构造不可能被形成为需求** —— 除非 NL 恰好提供了锚点。

📌 **所以 `wellformedness` 层测的是需求形成面的一个洞，不是检测失败。** 这两种说法蕴含完全不同的修法：

- 「方法检测不出合式性缺陷」→ 去改谓词或断言
- 「方法的需求来源只有 NL，纯模型内在的合式性缺陷没有形成路径」→ 去改需求形成阶段

**我原来的诊断（补谓词表达力）指向了错的那个。**

### 一条另有根因的漏检

`EIS-0000-02` **有** NL 锚点（NL 第 5 句），但 prompt **主动禁止**该发现：

> If the model exposes one combined event for a natural-language conjunction or disjunction, use that
> exact declared event and state the representation limitation; **do not invent separate atomic
> events.**

这是 prompt 政策造成的自伤漏检，不是锚点缺失。它与 [docs/protocol/ground_truth_limitations.md](../../protocol/ground_truth_limitations.md)
§5 已记录的「可绑定性」偏差同一机制，**现在被量化为整整一层的 8/12**。

### ⚠️ 但「给方法一个模型内在需求来源」本身需要裁定，不能直接做

那条禁令不是疏漏，它防的是「模型照抄工具诊断」。若允许 `UnspecifiedInitial` 这类编译器合成物直接
变成需求，则**发现者等于在转述 pyfcstm 的诊断**，而不是自己发现 —— 那是归因问题，会直接影响能力主张
的含义。

两种可能的正确处置互相排斥，必须先裁定：

1. **放开需求来源** → 但须区分「工具已报的」与「方法自己推出的」，且能力主张只能记后者
2. **收窄层定义** → 承认 pyfcstm 已标记的合式性缺陷不是 discover 的能力目标（它们在上游已被检出），
   把这一层从能力分母移出

## 五、对下一轮的直接含义

**v24 在设计上无法提升覆盖率。** v23 → v24 的唯一实质改动是 `_occupies` 的窗口起点修复，而
`occupancy_after` 的 `hit@1` 已是 100%（12/12）—— 修它不可能提升覆盖。其预期效果相反：把「本该 True
的假 False」变回 True → **少发布发现** → 多报下降，且 `hit@k` **可能小幅下降**（部分命中是靠那些假
False 达成的，`docs/findings/predicates/defects_registered.md` 已警告）。

所以 v24 是**正确性 / 有效性运行**，不是能力运行。这必须写在 v24 报告最前面，否则「指标没涨」会被读成
方法失败，而它实际是「修掉了一个让指标虚高的缺陷」。

### 能力工作的对象已经改变

**不是三个瓶颈谓词。** §四之二 的裁定表明：8/12 的 `wellformedness` 漏检源于**需求形成阶段没有模型
内在来源**，谓词层根本没被调用（实测 `initial_target` 在 `0032` / `0047` 两格调用 **0 次**）。改谓词
对一个从未被调用的谓词无效。

但 §四之二 末尾那个抉择**必须先裁定再动手**：放开需求来源会让发现者变成 pyfcstm 诊断的转述者，那是
归因问题而非工程问题。**在裁定回来之前不改 prompt** —— 无诊断改 prompt 正是前几代次反复发生的事，
而这次连「改哪一层」都还没定。

### 已确认的两种失效模式（修法相反，不可混治）

查 13 条「两臂三轮全未命中」记录在 run1/claude 格的断言层实况：

| 模式 | 条数 | 特征 | 例 |
| :-- | --: | :-- | :-- |
| **A：谓词从未被调用** | 6 | 义务没走到断言层 | `0032-01`（`initial_target` 0 次）、`0047-01/02`（0 次）、`0000-02`（`stays_in` 0 次） |
| **B：谓词调用了却没抓到** | 7 | 断言做了但锚点/参数错 | `0038-03`（`edge_declared` **6 次**）、`0048-02/03`（`initial_target` 1 次） |

A 要改需求形成，B 要改锚定引导。**把两者当成一个问题去改 prompt，必然一边失效。**

### 第三个信号：整格产出量差异极大

`0048` 三轮 `satisfied` = 16/19/16 而 `issue` = 1/1/1 —— 断言跑了十几条**全部返回「没问题」**，而台账
说那里有 5 条缺陷。对比 `0047`：`satisfied` = 1/6/4，**几乎什么都没查**。

这是两种不同的失败：`0048` 是判错，`0047` 是没判。**逐格产出量必须与命中率并列看**，否则会把「没查」
读成「查了没发现」。

## 六、⛔ 已作废：「attribution 门在吃发现」这个候选根因

**裁定结论：门错杀 0 条，上限已算出为 0。** 详见 §七。本节保留是因为它记录了我怎么被一个混淆变量
带偏，以及两个机械代理如何在两个方向上同时失灵。**不要引用本节的任何推论。**

原文如下（结论已废）：

追 `0047`「几乎什么都没查」时发现它并非没查。`runs/paper1/matrix-v23/run1/0047-claude` 的产出是
`satisfied=1` / `issue=1` / **`excluded_findings=1` + `excluded_observations=4`** —— 7 个结局里 5 个
被排除。而那条 `excluded_findings` 是：

```
attribution_status: representation_debt
title: REQ-003 并发不变式失败,证据依赖编译器插入的 UnspecifiedInitial(representation_debt)
rationale: ... 其证据(active(UnspecifiedInitial))落在编译器为处理并发缺失而插入的伪状态上,
           attribution 标注为 representation_debt、source_level_claim_allowed=false
```

台账 `EIS-0047-02` 逐字是「CollisionAvoidanceSystem 有三个子状态却没有初始子状态，进入它时落到合成的
UnspecifiedInitial」。**看起来是同一个缺陷** —— 若成立，则方法找到了它、断言了它、判 False 了，
**在发布前被门拦掉**。

那与 §四之二 的「需求未形成」是**不同的失效阶段**，可能是并列的第二个根因。

### 怀疑的机制

attribution 门似乎无法区分两种情形，因为两者表征相同（「证据落在 `UnspecifiedInitial` 上」）：

| 情形 | 该不该排除 |
| :-- | :-- |
| 投影**制造**了缺陷（`EIS-0043-02`：摊平正交区才产生的前提） | 该排除 |
| 投影**暴露**了作者的遗漏（`0047`：作者确实没写初始边，合成态只是症状） | **不该排除** |

若该区分缺失，「作者漏写初始边」这类真缺陷会被系统性吃掉 —— 而它恰是 `wellformedness` 层的主要形态。

### ⛔ 我为此做的两个机械筛都失灵了，不得采信

| 筛法 | 结果 | 为什么不可用 |
| :-- | :-- | :-- |
| 格级共现 | 13 条里 11 条所在格有 `representation_debt`/`unattributed` 排除项 | **格级共现 ≠ 逐记录匹配**。`0048` 的排除项是「AutoFocus 未到达 choice1」这类可达性失败，与 `EIS-0048-02`（Join2 无初始子态）不是同一命题 |
| 元素级重叠 | 仅 1 条重叠 ≥3 | **两个方向都错**：`EIS-0047-02`（语义最清楚）只得 1，因为我把 `UnspecifiedInitial` 当噪声滤掉了 —— 而它正是唯一鉴别性 token；排第一的 `EIS-0047-01` 匹配到「正交并发意图无法表达」，与其缺陷（PlantUML 全局名解析致同名态合并）关系存疑 |

📌 **教训：过滤"噪声" token 时，最鉴别性的那个可能正在里面。** 我滤掉 `UnspecifiedInitial` 的理由是
"它到处都出现"，而它到处出现恰恰因为它是这类缺陷的统一标记。

**重叠高的不一定对，重叠低的不一定错** —— 这个筛只能给裁定者列候选，不能排序，不能计数。已交独立裁定
逐条读原文判定。

## 七、⚠️ 我的第三个假设也被推翻 —— 这次是被一个**算出来的 0**

7 个 pair `hit@1` 79.6% / `hit@3` 86.1%，均已过 70%」，两组差 59.8pp。**独立裁定推翻了它。**

### 硬上限反证（决定性，且是我没做的那一步）

> **接纳全部 64 条 `excluded_findings` 为已发布，13 条漏检中新增命中 = 0。**

任何相关系数都不能推翻一个算出来的 0。逐条追溯的结果：

| | 条数 | 为什么不算命中 |
| :-- | --: | :-- |
| 行为类（`occupancy_after` / `reaches` / `invariant`） | **63 / 64** | 台账那 8 条的 primary 全是**声明类**。命题不同，且方向是**反向蕴含**（缺初始 ⇒ 运行到不了，不是反过来），按 [docs/protocol/hit_criterion.md](../../protocol/hit_criterion.md) §4 明确不算 |
| 声明类 | 1 / 64 | `run3/0038-gpt` 的 `edge_declared(ChargedFlash, Charged_true, Junction3)` 与 `EIS-0038-03` 的 primary **逐字节相同** —— 但**仍不是门吃掉的**：同 REQ 的兄弟断言 attribution 为 `safe`，该格实际已发布 `ISSUE-chargedflash-chargedtrue-no-junction3-flow`。命题出去了，盲判仍记 0 → 转**盲判复议** |

### 混淆机制：同一变量被测了两次

**门只对行为类断言开火，命中只由声明类断言产生。** 哪些格写行为类、哪些写声明类，是同一个上游选择
的两个投影 —— 所以 −0.716 不是因果链。

直接反例最致命：

| pair | R4.5 debt code 集合 | 门开火 | `hit@1` |
| :-- | :-- | --: | --: |
| `0029` | `composite_source_activation_dispatch`, `composite_source_external_reentry`, `missing_explicit_initial`, `opaque_state_body`, `opaque_transition_label` | **0 次** | **93.3%** |
| `0032` | **完全相同的 5 条** | **16 次** | **41.7%** |

debt 画像逐条相同、结局相差 51.6pp。**门是否开火不由制品的表示债决定。** 另：0006/0029/0035/0043
全部带 `missing_explicit_initial`（即全都有 `UnspecifiedInitial`），门一次不开，`hit@1` 依次
72.2%/93.3%/100%/100%。

### 门排得对，且它正是那 4 条命中的产生机制

`nodes.py` 的 `_omission_placeholder_only` 豁免（证据全为 `omission_surrogate` **且**谓词为声明类 →
`status = safe`）**已上线并实际开火 25 次，全部落在 0029 / 0035 / 0043** —— 恰好就是 `wellformedness`
层命中 6/6 的那三格。

> 同一段代码、同一种 `UnspecifiedInitial` 证据：0029/0035/0043 里需求形成了 `initial_target` 主张，
> 门放行、发布、命中；0032/0047/0048 里那个谓词**从未被调用**，门连开火的机会都没有。

`EIS-0047-02` 与那条 `excluded_findings` 也**不是同一命题**：后者是 `invariant` +
`coverage_obligation.domain: concurrency`，主张三子区可同时激活；`UnspecifiedInitial` 在其中只是 False
的**见证物**，不是断言主语。接纳它等于一边宣布 `EIS-0043-02` 越界、一边把同类并发主张计入能力。

⛔ **`−0.716`、`79.6%`、`59.8pp`、`61.4%` 一律不得发布。**

### 需求形成与门不是并列根因，是**上游断流、下游无水可拦**

门只能处置已经产生的 False。那 8 条里 6 条谓词从未被调用、2 条被锚成了 True —— **没有 False 送到
门口**。所以 §六 把它列为「并列的第二个根因」是错的，已作废。

### 📌 这条判据我下次必须先做：**先算上限**

裁定给出的「若要主张门错杀，最低证据线」三条里，第 2 条就是我跳过的那步：

1. 逐条命题同一性人工裁定（不是重叠数排序）
2. **算出上限** —— 接纳全部排除项后的命中增量。**若增量为 0，主张自动失败**
3. 活体激活分布（不是回测分布）

我做了 1 的机械代理版（两次都失灵）、跳过了 2、没到 3。而 2 是**最便宜且最决定性**的一步。
**提出「某个门吃掉了发现」这类假设时，第一步永远是算接纳它全部产出后的增量上限。**

## 八、裁定采纳的方案与下一轮的三条独立通路

### pyfcstm 一条都没报，而且是**我们自己的表示层**把它消音的

这是本次裁定最重要的事实核查。实测 `pyfcstm inspect`（普通档 + `--enable-verify` 满档）对 0032 / 0038
/ 0047 / 0048：**`INIT` 家族诊断全部为 0。**

pyfcstm 确有两条正对该缺陷的诊断码（`W_INITIAL_UNCONDITIONAL_MISSING`、`W_COMPOSITE_INIT_INCOMPLETE`）。
它们没开火的原因在 `plantuml_source_lowering.py` 的 `prepare_missing_initial_helpers`：投影**无条件**
插入

```
state UnspecifiedInitial named "Unspecified initial";
[*] -> UnspecifiedInitial;
```

这条无守卫初始边**恰好满足**上述两条诊断的开火条件。**缺陷在 pyfcstm 看到模型之前就被投影补掉了。**

反事实证明：把 0048 的 FCSTM 里含 `UnspecifiedInitial` 的行删掉（还原作者真实结构）后重跑：

```
3  W_INITIAL_UNCONDITIONAL_MISSING
  -> Composite state '...fork1' has no unconditional [*] entry transition.
  -> Composite state '...Join2' has no unconditional [*] entry transition.
  -> Composite state '...Fork2' has no unconditional [*] entry transition.
```

📌 **所以不是「上游已检出、重复无价值」，而是「我们把它静默修掉了，pyfcstm 因此失明」。**

### 采纳方案 3：公理化的模型内在义务源

「never turn a tool warning into a requirement」这条禁令**保留，一字不改** —— 它防的是真问题。但它被
**过度适用**了：pipeline 目前只有两个义务来源（NL、被禁的工具诊断），缺第三个 —— **UML / FCSTM 合式性
公理**。

「每个含子态的复合态必须声明默认入口」既不是 NL 句子，也不是工具告警，它是**建模语言的语义要求**，
落在 CLAUDE.md 已写死的 project_1 边界内（「核心关注层次结构、形式化语义、语义一致性」）。

**从公理形成需求不是转述编译器** —— 本案有压倒性支撑：**编译器没说过这句话**。方法要报出它，只能自己
从公理加模型结构推出来，这就是「方法自推」的定义。

不构成泄漏或特判的三条按构造成立：

1. **公理是全称模式，不含任何标识符**：$\forall C \in \mathrm{Composite}, |\mathrm{children}(C)| \ge 1 \Rightarrow \exists c.\ \mathrm{initial\_target}(C, c)$。元素由**模型自己**通过实例化提供
2. **见到任何样本之前冻结，60 个 pair 共用一份** —— 激活分布可查，它在已命中格与未命中格上**都**实例化
3. **数量预注册且极少（≤ 6 条）**，每条附标准出处，**不允许运行后追加** —— 追加一条即一次特判嫌疑

### 「工具已报 vs 方法自推」的操作化：诊断消融臂

不靠 prompt 里写一句「请注明来源」。三层，全部可被 reviewer 独立核验：

| 层 | 做法 | 判据 |
| :-- | :-- | :-- |
| **1（决定性）** | 把 `inspect_digest["diagnostics"]` 置空后重跑同格 | 发现仍出现 → **方法自推**；消失 → **工具转述** |
| 2 | 沿用已有 `attribution_status` 分层（`omission_surrogate` vs `carrier`，1712 元素上精确可分） | 不新造字段 |
| 3 | `hit@k` 拆 `NL-anchored` / `axiom-anchored` 两栏，**永不合并成一个数** | 读者自判公理侧贡献 |

第 1 层应做成**每代次固定的消融臂**，而不是一次性检查。按事实核查，6 条 `UnspecifiedInitial` 类记录
在消融下**必然存活**（诊断里本来就没有它们），所以对本案零成本。

## 九、多报侧的最大一类：产出方与判定方用**不同的名字匹配规则**

⚠️ **动机披露**：本节的发现路径是「查 `fabricated` 集中在哪些类别」，即从失败分析出发。按
[docs/protocol/rule_provenance.md](../../protocol/rule_provenance.md) 的纪律，据此改 prompt 需要说明为什么它不是特化 —— 见本节末。

### 现象

两位标注者的 `fabricated` 里，**第一大类在两人间稳定一致**：模型声明了 `OperateState`，而 issue 报
「缺 `Operate`」。A 计 6/18（33%），B 计 8/23（35%）。

（⚠️ 我的正则分类器按标注者的 `why` 措辞归类，两人措辞不同，**所以整个分布不是精确统计**；只有
「第一大类是什么」这一点在两人间稳定。）

### 机制：一个双侧规则不对称

| 侧 | 规则 | 出处 |
| :-- | :-- | :-- |
| **产出方** | 按**字面名**判缺失 | `prompts.py:40`：「A substate the sentence names by name … so **when the model declares nothing under that name** the requirement should assert the absence」 |
| **判定方** | 按**归一化**判 | `docs/generations/v25/retired_onepass_prompt.md`：「标识符 vs 散文 … **归一化后再判**，不要因为字面不同就说 NL 无依据」 |

**两边都在正确执行自己的规则。** 谓词实测确认它不归一化：

    state_declared('...0032.OperateState')  = True     ← 确实声明了
    state_declared('...0032.Operate')       = False    ← 虚构的来源

于是 NL 说 `Operate`、模型声明 `OperateState` 时，产出方被指令报缺失 → 谓词返回 False → 发布
「缺 `Operate`」→ 判定方归一化后判虚构。

### ⚠️ 我这次测试里的一处自身错误，记下来防止过度主张

我同时查了 `state_declared('IdleState')` 得 False，一度以为也是同类。**那是我的查询错了** ——
`IdleState` 嵌在 `IdleRegion.IdleState` 下，我用了扁平前缀。所以本节的实证只有 `OperateState`
一条，不是六条。

### 为什么这不是特化

改法是「产出方在断言缺失前必须按与判定方同一条规则归一化」。它的表述**完全不提任何具体状态名、
pair 或缺陷**，且：

1. **它修的是两条规则之间的不一致**，而不是某个样本的答案。不一致本身可从两份文件的措辞直接读出，
   不需要看任何运行结果
2. 它的效果方向是**降低多报**（精度），不是提升命中（召回）—— 不能用来把覆盖率推过 70%
3. 激活面是「NL 用散文名、模型用带后缀标识符」的全部配置，与样本无关

📌 **但披露仍然必要**：我是从失败分析发现它的。若评审认为这构成污染，正确处置是让一位盲态执行者
独立比对产出方与判定方的两份 prompt、看是否能自行发现该不一致 —— 那是可构造的检验（同
[docs/protocol/rule_provenance.md](../../protocol/rule_provenance.md) 的做法），而不是我事后论证。

## 十、⚠️ 我又把符合预期的数字当成了证据 —— 这次是效率侧

### 我说过的话，以及它为什么错

v24 的 run1 落盘后我算了单轮对比，得 issue/格 **−16.0%**，并说「预测方向被实测确认」。

**那句话下得太早。** 正确的下一步是先测**噪声底**：

| 量 | v23 **代次内**极差（三轮，同一代码同一 prompt） | v23→v24 run1 之差 | 可归因？ |
| :-- | --: | --: | :-- |
| 谓词调用/格 | 6.7% | **−11.7%** | 约为噪声 1.8 倍 → **弱信号** |
| **issue/格** | **20.5%** | **−16.0%** | **差小于噪声 → 不可归因** |

而最刺眼的一条是 `event_consumed`（**根本没被本次修复触及**）：

    v23/run1  33      v23/run2  12      v23/run3  38      v24/run1  9

代次内极差 **26**，比「v24 的 9 与 v23 run1 的 33 之差」还大。**所以那个 −73% 完全在代次内方差范围内。**
若我按最初的读法，会把它当成「修复产生了意外的下游效果」去追一整轮。

### 这与「先算上限」是孪生判据

| 判据 | 防的是 |
| :-- | :-- |
| **先算上限** | 「某个门吃掉了结果」类假设 —— 接纳全部后增量为 0 则假设自动失败 |
| **先测噪声底** | 「某个改动产生了效果」类主张 —— 差小于同条件下的自然波动则不构成证据 |

两者都是**在昂贵的因果论证之前的一次廉价算术**，而我两次都跳过了它、直接去论证一个符合预期的数字。

### 固化为流程

任何跨代次的量化对比，**必须同时给出该量在代次内的方差**，且：

1. 差 < 代次内极差 → 写「**不可归因**」，不得写成效果
2. 代次内极差 < 差 < 2× → 写「**弱信号**」，须并列给出方差
3. 差 > 2× 代次内极差 → 可作为效果讨论，但仍须给方差

⚠️ 代次内方差必须用**完整轮**算（22 格），不能用进行中的轮 —— 半轮的格集不同，方差不可比。

### v24 双轮复算（run1 + run2 各 22/22）确认了同一结论

是效应本身小于波动。**v24 的效率侧不构成任何可报效果。**

## 十一、第四个假设也被推翻：「谓词签名要求 NL 未提供的参数」

### 假设怎么来的

裁定给了一个我没回答的对照：`EIS-0035-01`（6/6）与 `EIS-0047-02`（0/6）用**同一谓词族、同一类证据**，
输入里同样有 `UnspecifiedInitial`。我查了四条记录的 primary 表达式与 NL：

| 记录 | 命中 | `child` 参数 | NL 点名了它？ |
| :-- | --: | :-- | :-- |
| `EIS-0035-01` | 6/6 | `DoorShut` | ✅ 逐字「The microwave starts in the **DoorShut** state」 |
| `EIS-0043-02` | 5/6 | `Region1` | ✅（以为 —— 见下，实为 ❌） |
| `EIS-0047-02` | 0/6 | `Frontend` | ❌（以为 —— 实为 ✅） |
| `EIS-0032-01` | 1/6 | `AcceleratingState` | ⚠️ NL 说「Accelerating **or** Cruising」，二选一 |

于是我写下：**`initial_target(composite, child)` 需要一个 `child`，而 NL 必须点名它** —— `0047` 的 NL
没说进入三个区时该到哪个，所以没有合理的 child 可填。

### 机械检验推翻了它，且方向相反

对全部 12 条 `wellformedness` 逐条核 primary 关键参数是否出现在该 pair 的 NL 里：

| 组 | NL 点名了关键参数 |
| :-- | :-- |
| 命中率 ≥50%（4 条） | **2/3** |
| 命中率 <50%（8 条） | **6/7** |

**低命中组的点名率反而更高**（86% vs 67%）。`0047-02` 的 `Frontend`、`0048-02` 的 `Join1`、`0048-03` 的
`Flash` **都在 NL 里**却全 0/6；`0043-02` 的 `Region1` **不在** NL 里却 5/6。

**假设不成立。**

### 📌 这是「整齐分布」陷阱的第三次

| 次 | 我看到的整齐 | 后来 |
| :-- | :-- | :-- |
| 1 | `wellformedness` 三个 @k 口径**完全相等**（33.3%）→ 判为「零方差 = 结构性能力边界」 | v24 出现 **4 条混合**，零方差不成立 |
| 2 | `layer_basis` 的矛盾**恰好覆盖该层全部 12 条且只覆盖这一层** → 判为真矛盾 | 它是 `LAYER_BASIS[stratum]` **查表常量**，整齐是必然 |
| 3 | 四条对比**恰好**按「NL 有没有点名」排开 | 12 条上不 generalize |

**小样本里的整齐是廉价的，而我每次都把它当机制证据。**

而这次假设的形成过程与前几次一模一样：**看几条样例 → 看出模式 → 写下机制**。唯一的进步是**这次我在写下
之前跑了检验**，所以它没进报告。但**形成过程没变** —— 进步在流程，不在判断。

### 对下一轮的价值

排除了一条路。目前已被推翻的假设：

    1. 谓词表达力不足                      同一谓词也在命中组
    2. fork/join 边界                      只 1 条越界且在命中侧，剔除后数字下降
    3. attribution 门吃发现                接纳全部被排除项，增量 = 0
    4. 需求形成面缺模型内在来源（部分）      「12/12 完美分离」在 v24 为 3/5/4 混合
    5. 谓词签名要求 NL 未提供的参数         低命中组点名率反而更高

**五条全部推翻。** 而裁定给的那个对照（同证据、同谓词、一边 6/6 一边 0/6）**仍然没有解释**。

⚠️ **下一步不应再提假设。** 五次的共同形态是「从少数样例归纳机制」，而它连续失败。应改为：
**先建立一个能区分候选机制的观测，再看数据落在哪边** —— 而不是先有机制再找支持它的数据。

## 十二、换成观测法后的第一个实质结果：问题**全在断言生成之前**

上一节承诺「不再提假设，改为先建立能区分候选机制的观测」。本节是那个观测。

### 观测设计

对 12 条 `wellformedness` 逐条追四阶段，判据是**该记录的 primary 断言是否出现在该阶段**：

    ① review-requirements     需求阶段
    ② convert-assertions      转换阶段
    ③ precheck-and-seal       **封存阶段**（进入最终脚本）
    ④ release-results         执行结果

匹配用**谓词名 + 关键元素**双重条件，不只匹配谓词名。

### 结果：近乎完美的两分

| 记录 | 命中 | 封存阶段有该断言 |
| :-- | --: | --: |
| `EIS-0000-01` | 6/6 | **6/6** |
| `EIS-0029-02` | 6/6 | **6/6** |
| `EIS-0035-01` | 6/6 | **6/6** |
| `EIS-0043-02` | 5/6 | **6/6** |
| `EIS-0048-01` | 1/6 | **6/6** ← 唯一例外 |
| `EIS-0038-06` | 2/6 | 1/6 |
| `EIS-0047-02` | 0/6 | 1/6 |
| `EIS-0032-01` | 1/6 | **0/6** |
| `EIS-0000-02` | 0/6 | **0/6** |
| `EIS-0047-01` | 0/6 | **0/6** |
| `EIS-0048-02` | 0/6 | **0/6** |
| `EIS-0048-03` | 0/6 | **0/6** |

**断言进了封存脚本 → 命中（4 条 6/6 与 5/6）；断言没进 → 不命中（5 条 0/6）。** 唯一例外是 `0048-01`。

### 这不是「机制」，是问题位置的定位

上面那个两分**几乎是同义反复** —— 断言写出来就命中、没写就不中。它的价值不在解释，在**排除**：

| 环节 | 是否是瓶颈 |
| :-- | :-- |
| 断言执行 | ❌ 写进封存脚本的都跑了 |
| attribution 门 | ❌ 已由「增量 = 0」独立排除 |
| 判定 | ❌ 三份判定交叉一致 |
| **断言生成之前** | ✅ **全部问题在此** |

而「断言生成之前」包含两个子环节（需求形成 / 需求→断言转换），本观测**不能**区分它们 ——
因为凡是没进封存的，在转换阶段也没有（②与③的列几乎相同）。

### ⚠️ 顺带纠正我上一步的误读

我先用**只匹配谓词名**的度量，读出「`0048-02/03` 断言写了 6/6 却一次没跑」，并判为「一种全新的失效模式：
断言在 review 或 seal 阶段被移除」。

**那是错的。** 加上元素匹配后它们是 **0/6** —— `initial_target` 在那些格里被用于**别的**元素。
**没有"被移除"这回事，是根本没写。**

📌 这是同一节里**度量口径造成的假象**：谓词名匹配把"用了这个谓词"读成了"针对这个缺陷"。而我在上一步已经
写下了一个基于它的机制判断。**观测法不能免除度量口径的检查** —— 它只是把"猜机制"换成了"看数据"，
而看错数据同样会得出错结论。

### 唯一需要解释的那一条

`EIS-0048-01`：断言 **6/6 存在**却只 **1/6 命中**。它恰好是边界裁定判为「部分越界、primary 应由
`containment` 改写为 `initial_target`」的那条 —— 即**断言写的是被判越界的那一半**。

**这条是下一轮唯一有明确下一步的记录**：改台账 primary 后重判，看它是否变成 6/6。
