## 1. 要改什么（全部为一般性规则，不针对样本）

| 编号 | 规则 | 层次 | 外部依据 |
|:--|:--|:--|:--|
| P1 | 主张的主语若是编译器引入的对象（`object_type=lowering_variable` 等）则不发布，交给 C1 重表述 | 发布门 | 源级诊断不报告编译器临时量 |

| P3 | 触发器/守卫等 typed-set 比较回映射到作者标签后仍不一致才发布 | S3/S5 求值 | 比较必须在同一表示层 |
| P4 | lowering 解析 PlantUML 标签 `event [guard] / effect` 的方括号守卫；解析不了的成分不得当「缺失」 | lowering | PlantUML 状态图标签语法 |
| P5 | S2 存在性在作者层完整迁移集合（含复合态出边）上判定 | S2 求值 | UML 2.5.1 §14.2.3 复合态迁移覆盖子态 |
| C1.1 | 状态在块 B 内首次声明且被 B 外作用域引用 → 「被 PlantUML 归为 B 的子态」分歧发现 | 新增作者源审计 | PlantUML 前向引用声明规则；UML §14.2.3 区域归属 |
| C1.2 | 同名状态在 ≥2 个区域块中声明 → 全局标识符冲突 | 同上 | PlantUML 状态名全局唯一 |
| C1.3 | `state: Entry: X` / `Exit: X` / 与 NL 动作或信号同名的冒号描述 → 动作被写成描述文本 | 同上 | PlantUML 冒号行是描述，`entry/` `exit/` 才是动作 |
| C1.4 | 迁移标签事件槽含 `,`、` or `、`/`（非 effect 位）、换行、`[*]` → 多条件压成单事件 | 同上 | 标签语法一事件一槽 |
| C1.5 | 只有 `[guard]` 没有事件的迁移，且源为非复合态或其内部无终态 → 完成迁移永不触发 | 同上 | UML §14.2.3.8.3 completion transition |
| C1.6 | 无标签的非初始迁移，且同句 NL 含条件表达式 → 条件未承载 | 同上（依赖契约） | 契约要求条件，载体为空 |
| C1.7 | 同一区域多条 `[*] -->` 初始边 → 默认入口不唯一 | 同上 | UML §14.5.6.2 initial pseudostate 至多一条出边 |
| C1.8 | 无事件无守卫迁移构成环 → 零时间空转 | 同上 | UML run-to-completion 语义 |
| C1.9 | 仅有 stereotype 文本、块体为空的子机/复合态 | 同上 | 声明与结构不一致 |
| C2.1 | 句子抽为 endpoints 契约但含条件词元而无 guard/trigger 契约 → 不完备，走 completion 补抽 | 抽取完备门 | 义务不得被类型化丢失 |
| C2.2 | 主语为系统整体或含 whenever / at any time / in any state 的事件句 → 逐态消费覆盖契约 | 抽取类型化 | 全称量化义务 |
| C4.2 | 同格内下游性质报告与上游根因报告共享元素 → 折为子主张 | 发布 | 一根因一报告 |
| C4.3 | 同一建模决策（如「条件以事件承载」）在一格内合并为一条列表式报告 | 发布 | 一决策一报告 |
