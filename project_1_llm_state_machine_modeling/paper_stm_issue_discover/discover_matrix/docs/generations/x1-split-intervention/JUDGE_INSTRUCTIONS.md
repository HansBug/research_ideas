# 判定指令 · x1-split-intervention（发给每个判定组的物理同一份文本）

## 一 · 你要做什么

给你若干份**判定材料**，每份对应一个 pair，里面有四样东西：

1. 需求原文（NL 全文，未截断）
2. 被审模型（PlantUML **作者源**全文）
3. 该 pair 的台账期望记录（每条一段 `statement`，未截断）
4. **三份**模型产出，标为**产出 甲**、**产出 乙**、**产出 丙**（每条 issue 有标题、`attribution_status`、共同根因、涉及元素、论证；另列出四类「发现了但没发布」的条目）

**对每一条台账记录 × 每一份产出，判一个位**：⭐ **这份产出有没有报出指向同一处作者源缺陷的主张？**

该 pair 有 $N$ 条记录，就有 $N \times 3$ 个位要填。

⚠️ **甲 / 乙 / 丙 的含义在每个 pair 里是独立随机的**，⛔ 不要假设「甲」在不同 pair 之间是同一个东西，也不要试图推断它们各自是什么。三份产出地位完全对等。

## 二 · ⭐ 唯一裁决标准

> **判定命中的标准是：产出所表达的命题，与台账那条记录所表达的命题，是否指向同一个作者源缺陷。**

⛔ **不是**：措辞是否相同 · 提到的元素名是否相同 · 谓词名是否相同 · 路径集合是否完全相同。

### 2.1 语义同一性成立的四种形态（⭐ 闭集，`equivalence_form` 只能填这四个之一）

| 形态 | 含义 |
| :-- | :-- |
| `直接对应` | 两个命题说同一件事，只是措辞不同 |
| `合取项之一` | 台账命题是「A 且 B」，产出证明其中一个合取项为假 |
| `负向命题的正向对偶` | 台账说「不应存在错的边」，产出说「应存在对的边」 |
| `蕴含更根本的原因` | 产出的命题为假**蕴含**台账命题为假，且定位到更上游（例：台账「该边应有变量下降」，产出「模型根本没声明该变量」——无变量则不可能有下降） |

⭐ **后三种都算命中。判据是逻辑关系，⛔ 不是形式相同。**

⛔ **一个不属于任何形态的「等价性论证」就是没有论证。**

### 2.2 ⛔ 不成立的形态（即使措辞大量重叠）

- ⛔ **不同缺陷共用状态名**：一条关于某状态**子状态计数**的发现，不算作关于该状态内**某条迁移目标错误**的记录的命中
- ⛔ **更弱的命题**：台账要求「这条边的目标是 X」，产出只证明「X 存在」——存在性不蕴含目标正确
- ⛔ **用结构存在性冒充行为验证**：「某条边是否存在」**不能代替**「某状态是否可达」。边存在 ≠ 状态可达（边可能永不使能、源态可能不可达、守卫可能恒假）；边不存在 ≠ 状态不可达（可经其它路径抵达）。⚠️ 两者形式相似而实质不同，属**以次充好**——这是唯一被点名禁止的替换形态
- ⛔ **反向蕴含**：台账命题为假**不**蕴含产出命题为假

### 2.3 ⚠️ 边界要划准：允许等价，只禁伪等价

§2.2 是一份**窄清单**，⛔ 不要读成「凡是形态不同就不算命中」。

> ⭐ **真正的等价一律接受，包括从不同侧面发现同一个问题。** 措辞不同、切入面不同、元素名不同，都不影响命中——只要指向的是**同一处建模失误**。

⛔ **不要用「读者据此修复后台账缺陷是否即消失」当判据。** 那条太严，会误杀「合取项之一」与「蕴含更根本的原因」。

**判定顺序**：⭐ 先问「是不是同一处失误」（是 → 倾向命中），再查「有没有踩 §2.2 的禁止项」（踩了 → 不算命中）。⛔ 不要反过来先看形态。

### 2.4 「同一处失误」的硬判据：数作者源里的引用次数

「同一处」不是感觉，是可数的。判据：**在 PlantUML 作者源里，两个主张各自指向的元素被引用了几次。**

> 若某元素**全文只被引用一次**，则一切以它为对象的主张都锚在**同一条作者编辑**上，两个主张是那一条语句的两面——动其一必动其二。

⚠️ 要数的是「该元素在**它自己那个命名空间里**被引用几次」——不加过滤的计数会把迁移标签里的同名字符串也算进去（那属事件命名空间，不是状态）。

⚠️ 同源只是**必要条件**。还要过 §2.3 的第一问。若产出的主张是台账主张的**严格超集**、且超出的部分点到了**正确的**元素，那不是「同一处失误的另一面」，不算命中。

⭐ **这条判据必须对称适用，尤其是在它会压低数字的方向上。**

### 2.5 形态 ④ 的两个告诫

- **④ 容易被误判为不命中**：产出定位到更上游的缺失元素时，它**仍然**蕴含台账命题。
- **③ 与 ④ 同样容易被过度援引**。⭐ **说不清「产出为假如何蕴含台账为假」这条逻辑链，就不要判命中。** 元素重叠、区域相同、都提到同一个名字，**都不是**蕴含关系。

## 三 · 「没发布」的四类要分开看

材料里除了已发布 issue，还会列出：被归因策略排除的发现 · 被证据角色制度静默的观察 · 预算耗尽的覆盖缺口 · 被结构门丢弃的 issue。

⛔ **这四类一律不算命中**——它们没有被报出来。列出它们只是为了让你能在依据里区分「从没发现」与「发现了但没发布」，这个区别对后续分析有用。若某条台账记录在某产出里属于后者，请在 `note` 字段写明。

## 三补 · 若某份产出标着「该格运行失败」

材料里某份产出可能写着 **该格运行失败** 或 **该格未落盘**。这表示那一次运行崩了，什么都没报出来。

处理方式：该产出下的**每一条**台账记录都判 `hit: false`，`equivalence_form` 填 `null`，`argument` 写「该格运行失败，无任何已发布 issue」，`note` 写上材料里给出的失败类型。⛔ 不要跳过这些位、不要留空——它们必须出现在你的 JSON 里，否则统计会把「崩了」和「漏判了」混为一谈。

## 四 · 输出格式

对分给你的每个 pair，输出一个 JSON 对象；最后把它们合成一个数组，写到指定文件，并在回复正文里也贴一份。

```json
{
  "pair": "0005",
  "verdicts": [
    {"record_id": "EIS-0005-01", "arm": "甲", "hit": true,
     "equivalence_form": "直接对应",
     "argument": "产出 [2] 主张 ... 与台账 ... 指向作者源第 N 行同一条迁移；该元素全文仅被引用一次。",
     "note": ""},
    {"record_id": "EIS-0005-01", "arm": "乙", "hit": false,
     "equivalence_form": null,
     "argument": "该产出只报了 ...，属 §2.2「更弱的命题」：存在性不蕴含目标正确。",
     "note": "该主张出现在 coverage_gaps 里，属发现了但预算耗尽未发布"},
    {"record_id": "EIS-0005-01", "arm": "丙", "hit": false,
     "equivalence_form": null, "argument": "...", "note": ""}
  ]
}
```

字段要求：

- `hit`：`true` / `false`。⛔ 不允许 `null`——拿不准也要给一个，并把不确定点写进 `argument`。
- `equivalence_form`：命中时必须是四种形态之一的**原文字符串**；不命中填 `null`。
- `argument`：必须**具体**——指名产出的第几条、台账的哪一句、以及蕴含链。⛔ 「语义相近」「都提到了 X」不是论证。
- 每条台账记录 × 每份产出（甲/乙/丙）都要有一行，⛔ 一条都不能漏。**包括标注「不进能力分母」的记录**（它们照判，我在后面统计时再筛）。

## 五 · 纪律

1. ⛔ **不要试图推断甲 / 乙 / 丙 各自是什么、也不要在 `argument` 里猜。** 你不知道这个实验在比什么，这是设计使然。
2. ⛔ **三份产出必须用完全相同的严格度判。** 若你发现自己对某一份更宽容，停下来重判。⭐ 这是本次判定最重要的一条。
3. ⛔ 不要因为一份产出的 issue 更多就倾向判它命中更多；**逐条对台账记录判，不做整体印象打分**。
4. ⛔ 不修改任何仓库文件。
5. 拿不准时，`argument` 里写清不确定的点，⛔ 不要为了给出标签而编一条蕴含链。
