# 补充：删掉第二支之后，「缺 `nl_parent`」支的激活面（自量，先于复审结论）

第一轮 review 判门的第二支会造成整格隔离，我删掉了它。但**删掉一支不改变另一支的量** ——
所以自己先量。

## 历史分布（v21 + v22 全部 containment 绑定）

    自前缀 · 缺 nl_parent    302        ← 门会拒
    跨层                     178        ← 门放行
    自前缀 · 有 nl_parent      0        ← 该字段 v23 才教，历史必然为 0

    若门原样上线：会被拒的格 42，其中 22 格的被拒条数 > 5（修复预算），单格最多 40 条。

## 但「条数 > 预算」不等于「超预算」

门**一次把全部 findings 整体抛出**（`nodes.py` 的 `raise ValueError(... list(step_findings))`），
不是逐条。所以 40 条会在**一轮**里全部反馈，生产者只需一次修订就能全改。预算消耗取决于
**能否一次改对**，而不是 findings 的条数。

v22 的修订分布（同一格多版计数）：`rev1 68 / rev2 59 / rev3 33 / rev4 17 / rev5 11 / rev6 7 /
rev7 1 / rev8 1 / rev9 1` —— 多数格 2~3 轮收敛，最多 9 轮。

## 所以真正的风险是什么

不是条数，是**生产者会不会填 `nl_parent`**。历史里这个字段出现 **0 次**（v23 才教）。v22 未接线
的理由逐字是「被要求补一个从未被描述过的字段，耗尽修复预算，整格被隔离」—— 我做了前置件的一半
（教了字段），但**没有活体证据表明生产者会照做**。

代码 review 的 I-2 指出同一件事：这道门从未在回路里被测过。

## 处理

**开跑前先单格试跑**，而不是直接铺 66 格。两份 review 都建议了这一步，选格标准是自前缀
containment 最多且**不消耗 hold-out 资格**（已跑过或已烧毁的格）。

单格试跑要看的是：① 生产者第一轮填不填 `nl_parent`；② 若不填，被门拒后第二轮填不填；
③ 几轮收敛、有没有触发隔离。**这三条只有活体能答**，回测给不出 —— 本代次已三次撞上这一点。

⚠️ 这段自量是**回测**：它测的是「按历史行为，门会拒多少」，即误伤面。改动 1（修 prompt 矛盾）
明确把生产者推向 NL 锚点即跨层，活体分布下自前缀占比应显著下降 —— 所以 42 格 / 22 格是**上界**，
不是预测。按 §3.5 条款 3，这组数不能用来判规则性质。
