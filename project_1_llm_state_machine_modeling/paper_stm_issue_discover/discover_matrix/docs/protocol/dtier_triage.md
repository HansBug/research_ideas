# D 档三方判读 → 台账分拣口径

本文定义：三个独立判读臂各自给出 D 档判定后，**如何把一条台账 / 候选条目分到「抛弃 / 保留 / 需人裁」**。它是永久口径 —— 改它等于改这一轮重标注的研究规则。

- D 档本身的定义与判定程序**不在本文**：见 [issue #189](https://github.com/HansBug/research_ideas/issues/189) §1.3.3 与 `D_PROTOCOL.md`（gist [0a3a085a](https://gist.github.com/HansBug/0a3a085a68b7e9d9966e5b1a21606f65)）。本文只管**聚合规则**。
- 本轮的全量判定结果落在 [manual_review/relabel/dtier_rulings.json](../../ledger_v2/provenance/relabel/dtier_rulings.json)；争议条目的人工 meta review 落在 [dtier_meta.json](../../ledger_v2/provenance/relabel/dtier_meta.json)。

## 1 · 四个档位与它们的攻击面

判读结果有四种粗档。⛔ 其中 `A0` **不是 D 的一档**，它是判定相 A 的第 0 步出局口 —— 这条区分是本文全部规则的基础。

| 档 | 含义 | 反驳打的是什么 | 出处（逐字定义见 issue #189 §1.3.3 出处表） |
| :-- | :-- | :-- | :-- |
| `D2` | 有一条可陈述的被违反义务，且拿不出站得住的反驳 | —— | IEEE 1044-2009 的 **defect** |
| `D1` | 存在一种与结构事实相容的第二种称职读法，两种读法都站得住 | **推理**（undercutting） | Pollock 1987 定义 (2.5) |
| `D0` | 作者可正当地说「这就是设计」；或根本没有可陈述的被违反义务 | **结论**（rebutting） | CMU/SEI-2015-TR-005；IEEE 1044 Table A.1 的 `Not found` |
| `A0` | 三个出局口：`FALSE_POSITIVE` 误报 · `NOT_A_DEFECT_CLAIM` 非主张 · `OUT_OF_SCOPE` 越界 | **证据**（undermining） | 同上，undermining 一条 |

`A0` 三出口的判据（`D_PROTOCOL.md` §3 的 A0 表）：

| 判断 | 出口 |
| :-- | :-- |
| 结构事实指不出或在 `stm0.puml` 上不成立 | `FALSE_POSITIVE` |
| 主张的对象不是作者源制品（例如主张参考模型 / 评测真值本身有问题） | `NOT_A_DEFECT_CLAIM` |
| 落在界外范围（时钟变量 / 不变式 / 正交区并发语义） | `OUT_OF_SCOPE` |

⛔ `OUT_OF_SCOPE` 的后果按 `D_PROTOCOL.md` §P3 逐字为「既不算缺陷也不算误报」—— 它与 [nl_scope_rule.md](./nl_scope_rule.md) 的 `00x8` 永久排除是同一条边界，⛔ 不得记为「方法未能检出」。

## 2 · D1 是内容属性，不是流程状态

⚠️ 这一条容易搞混，且搞混会直接把分拣做错。

`D1` 说的是**这段内容本身就是模糊的** —— 多种读法都成立**就是它的本体特征**。人工裁决是它的**后果**，⛔ 不是它的定义。

由此得两条操作后果：

1. ⭐ **`D1` 的条目要保留、要进工作单**，因为「这里有两读」本身是一个关于制品的真实发现。⛔ 不得因为「机器没定下来」就抛弃。
2. ⛔ **但它不能被当成已经定下来的缺陷** —— 呈现时必须把那个第二读法一起给出，否则读者看到的是一条被剥掉了争议的断言。

## 3 · 存在性断言不可投票

⛔ `D1` 是一个**存在性**断言（「**存在**一种站得住的第二读法」），⭐ 而存在性断言不能用多数票聚合。

若 1 臂拿出了带锚点的 `alternative_reading`、另 2 臂没找到，⛔ 那不构成 2:1 否决 —— ⭐ 另两臂「没找到」不能反驳「它存在」。反过来 `D2` 与 `D0` 都是全称 / 否定性断言（「找过且没找到推翻者」/「作者可正当地说这是设计」），⭐ 它们可以投票。

⚠️ 但「存在性成立」需要那份 `alternative_reading` 真的立得住，而这一点机器只能核形式。故本口径的做法是：**任何有 `D1` 票的条目都进人工视野**，由人读那份第二读法判它站不站得住；⛔ 不用锚点门把它筛掉。

⛔ 不用锚点筛掉的理由是 `D_PROTOCOL.md` §7.2 自己记下的陷阱：`DIFF-0005-02` 那条理由**站得住却无合法写法过门**（它诉诸的东西既不在 `nl.txt` 也不在 `stm0.puml`），与仓库 CLAUDE.md §11 的 `named_elements` 事故同型 —— 把语义判断实现成词法判据，于是没有任何合法写法能通过门。

## 4 · 分桶规则（机械，只看票面）

先把四档二分：`D2` / `D1` → **留**，`D0` / `A0` → **弃**。设三臂中判「留」的票数为 $k$，出现的不同粗档数为 $m$，`D1` 票数为 $n_1$。

| 桶 | 判据 | 处理 |
| :-- | :-- | :-- |
| `auto_keep` | $k = 3$ 且 $n_1 = 0$ | ⭐ 机械落决议：**保留**，进工作单 |
| `auto_drop` | $k = 0$ | ⛔ 机械落决议：**抛弃** |
| `auto_d1` | $k = 3$ 且 $n_1 = 3$ | ⭐ 机械落决议：**按 `D1` 入账** —— 「这段内容两读并立」本身已是三方共识，⛔ 不需人在两读之间选 |
| `ambiguous` | $k = 3$ 且 $1 \le n_1 \le 2$ | ⚠️ **保留**，但「是否两读并立」三方未达成一致，须人裁 |
| `leaning` | $0 < k < 3$ 且 $m < 3$ 且 $n_1 \ge 1$ | ⚠️ 给**推荐**，待人认可 |
| `chaotic` | $m = 3$，或（$0 < k < 3$ 且 $n_1 = 0$） | ⛔ **留空**，待人裁 |

⭐ `chaotic` 的第二支判据是本口径的关键设计：**无人称模糊、却仍跨越留/弃线**。那说明分歧不在「模糊到什么程度」，而在**「到底有没有一条被违反的义务」** —— ⛔ 这更可能指向判读材料不足，而不是内容难。故这一类**优先看**，它同时在诊断判读装置本身。

⚠️ 反过来 `leaning` 要求 $n_1 \ge 1$：有人指出了模糊，分歧就**可解释**（一方看见了第二读法、另一方没看见），此时给推荐是有依据的。

## 5 · 人工与脚本的分界

⛔ 这条分界是硬的：

| 谁做 | 做什么 |
| :-- | :-- |
| **脚本** | 分桶（§4 的票面判据）· `auto_keep` / `auto_drop` 的决议文案 · **逐字引出**三臂原话 |
| ⭐ **人工（meta reviewer）** | **全部 429 条**的推荐档位、一句话理由、展开理由、主要分歧点、建议重点关注处 |

⚠️⚠️ **2026-08-14 分界移动过一次，⛔ 是收紧不是放宽。** 原先只要求争议三桶由人工归纳，无争议两桶的文案允许脚本从「该条自己的 NL 原句 / 领域义务 / 设计意图理由」拼出。⭐ 用户裁定改为**全部 429 条都要人工写**：⛔ 无争议的条目虽然不需要人做动作，但读者只看到一个 ✅ 而不知道它凭什么成立，⚠️ 那与「没有 meta review」在信息量上没区别。

⛔ 任何条目的归纳都不得由脚本生成。理由：脚本能做的只有拼接与计票，⛔ 而「这两读的分歧点在哪」「为什么推荐这一侧」需要读懂三臂各自的 `basis` 并判断谁的理由更站得住 —— 那是判断，不是聚合。脚本若代劳，产出的是**看起来像结论的模板文本**，⛔ 比留空更坏。

人工归纳的落点是 [dtier_meta.json](../../ledger_v2/provenance/relabel/dtier_meta.json)；工作单里的对应段落必须标明它是人工归纳而非计算结果。

## 6 · 已知限制

1. ⛔ **判读装置资格受限**：三臂均为 LLM 单轮判读，无判定者间一致性系数。issue #189 §6 明载 Massey 等（RE 2014）的资格限制**直接适用于 D1 判定** —— 无领域资格的判定者做不了 nocuous / innocuous 区分。故 `ambiguous` 桶的最终裁决必须由人做，⛔ 三臂只提供「哪里有两读」这个事实。
2. ⛔⛔ **两个分母不许混：三臂统计用 `380`，工作单条目数用 `323`。**
   - **`380`** = 进过三方 D 档判读的条目（`EIS` 99 + `INS` 189 + `DIFF` 77 + `VU` 15）。⭐ 只在算**三臂一致率、票面分布、分桶比例**时用它。⛔⛔ **它没有去重** —— 其中 57 条被重叠分析判定为「与另一条是同一个问题」。
   - **`323`** = ⭐ **工作单条目数 = 380 − 57**（§2 台账 99 + §3 候选 224，后者 = `VU` 15 + `DIFF` 77 + `INS` 132）。⭐ 凡是「有多少条要人处理 / 有多少个裁决区 / md 里有多少个块」，一律用这个数。
   - ⛔ **`429` 这个数已作废**（旧口径 = 380 + `UM` 49）：`UM` 一族已于 2026-08-16 [整批撤出工作单](../findings/um_residue_ruling.md)，⛔ 不再有任何 `UM-` 块，也不再有 `UM-` 的 meta review。
   - ⚠️ 历史上还出现过 `269` / `220` / `319` / `324` / `281` 几个数，⛔ **一个都不是当前口径**。⭐ 完整账目、每个数的来历、以及 2026-08-16 因混淆 `380` 与 `323` 而两次改错的经过，见 [DEDUP_ACCOUNTING.md](../../ledger_v2/provenance/relabel/DEDUP_ACCOUNTING.md)。⛔⛔ **动任何与条目数有关的代码或统计前先读那一页。**
   - ⭐ 数据落点：范围内 323 条在 [dtier_rulings.json](../../ledger_v2/provenance/relabel/dtier_rulings.json)（meta review 在 [dtier_meta.json](../../ledger_v2/provenance/relabel/dtier_meta.json)）；被判重复移出的 57 条在 [dtier_rulings_deduped_out.json](../../ledger_v2/provenance/relabel/dtier_rulings_deduped_out.json)（含宿主与理由）。⛔ 守门测试 `test_the_dedup_is_not_undone` 双向钉住：既防丢条目，也防重复回潮。
3. ⚠️ **本轮 schema 的 `grounding` 枚举不含空串**，故 `A0` 出口条目被迫填 `none`，造成 82 条违 G6。经核 **100% 是 A0 出口条目、无一条是判读者判错**；`D_PROTOCOL.md` §3 已据此补两条规则（枚举须含空串 · G6 加前置条件）。⛔ 这是 CLAUDE.md §13「多道门的审计单位是交集」的一个实例，记录在此以免后人误读那 82 条。
4. ⚠️ **`dsh` 臂在 `D2` 上系统性偏高**（42% vs 另两臂 33–34%），差异**集中在 `D2` ↔ `D1` 一处**，而 `D0` 与三个 A0 出口三臂几乎完全一致。⭐ 但 `dsh` 当少数派的频次（31%）低于 `claude`（39%）—— ⛔ 故它是**方向性偏移**，不是随机离群。分桶规则对此的处置是：`D2+D2+D1` 与 `D2+D1+D1` 都进 `ambiguous` 由人裁，⛔ 不按多数径直判 `D2`。

## 6.5 · 初始迁移标签的判别器：看**谁产生它**

⚠️ 这一条是 2026-08-14 逐条 meta review 时**修正过一次**的，⛔ 修正前后都记在这里。

UML 2.5.1 规定初始伪态的出迁移**不得带 trigger 或 guard**、但**允许 behavior（effect）**；而 PlantUML 的 `:` 之后只有一个**无类型的自由文本槽**。⛔ 于是「那个标签是不是违规」取决于把它读成什么，而源里没有任何记号能定死它 —— 这是 `D1`（两读并立）最常见的形态。

⛔ **判别器的初版是错的**：按「名词性事件名 ⇒ trigger / 祈使动作短语 ⇒ effect」划分。⚠️ 它在 `Start Mission`（被归入事件）与 `Start Monitoring`（被归入动作）上是**任意的** —— 两者都是「Start + 名词」。

⭐ **现行判别器：看这个标签命名的东西由谁产生。**

| 判据 | 读法 | 后果 | 例 |
| :-- | :-- | :-- | :-- |
| **环境产生**（机器在等的外部刺激，环境里有生成者） | trigger 读法强 | `D2-lit`（违反二值条款） | `Power On` · `Possible collision detected` · `Start Mission`（操作员指令） |
| **机器执行**（机器自己做的动作） | effect 读法强 | `D1`（两读并立） | `Activate Pump` · `Start Monitoring` · `Start Braking` · `Enter Autonomous Mode` |

⭐ 两条配套判据：

1. ⭐ **「该事件全模型无生成者」是支持 `D1` 的证据，⛔ 不是支持 `D2` 的**。无生成者说明它不像一个 trigger —— ⚠️ 直觉容易反过来（「等一个没人发的事件 ⇒ 卡死 ⇒ 缺陷」），但那正是把 trigger 读法当成既定前提。
2. ⭐ **同文件对照能定案**：若同一文件里存在**裸**初始边（无标签），说明作者知道两种写法的区别，⇒ 带标签那条更可能是刻意的 trigger ⇒ `D2`（`INS-0030-01` / `INS-0050-01` 即此）。⛔ 反之若全文只有这一处用法、别处从不这么写，则没有证据表明作者懂这个区别 ⇒ `D1`（`EIS-0056-02` 的 `[Decrease UAV Count]` 即此：23 行里除三个 `[*]` 外只有那一处 `[...]`）。

## 6.6 · ⛔ 标签不能替代核查：引用一条判例之前，先确认它存在

⚠️ 2026-08-16 实测事故。`EIS-0010-05`（NL「when power off, it will transit to final state」，作者源只有 `:19 HumanDriving --> AutonomousFinal : Power Off`）被推荐为 `D1`，理由写的是「按主 session **判例 15** 应判 D1」。

⛔ **那条判例不存在。** `docs/protocol/` 下只有 [rulings/wellformedness_attribution.md](./rulings/wellformedness_attribution.md) 一份裁定；[precedent.py](../../../archive/r10_ledger_v1_and_v46/scripts/precedent.py) 管的是**命中判定**（某条产出算不算命中台账记录），不是 D 档。⭐ 「覆盖一半状态空间」这个说法的真实出处是 `EIS-0040-01` 的 **claude 臂措辞** —— ⛔ 一个臂的用语被升格成编号裁定，再拿去推翻 2:1 多数。

⛔⛔ **更实质的错误不是引错出处，是用标签替代了核查。** dsh 的第二读法写着「自动驾驶子态可经 `:15`/`:16` 接管边回 `HumanDriving` 再断电」；⭐ 回源只需看那两条边的源状态 —— **都是 `AutonomousActive`**，而条目点名的 `AutonomousIdle` 与 `Autonomous` 都没有接管边。⚠️ B1 要求第二读法**与结构事实相容**，此读法对三个态里的两个是事实性错误，推翻者根本不存活。⛔ 一次 grep 就能推翻的东西，被「这是某某型」这个标签挡住了。

⭐ **执行规则：**

1. ⛔ 引用任何判例、裁定、规则编号之前，**先确认它在仓库里存在**并读它的原文。⚠️ 三方臂的 `basis` 里出现的说法是**论证**，不是**裁定**；把它当裁定引用即为伪造出处。
2. ⛔⛔ **推荐与三方多数相反时，必须回作者源逐条验第三臂的结构断言。** ⭐ 少数意见能推翻多数，靠的只能是事实或成文规则，⛔ 不能靠「这一类我们一般怎么判」。
3. ⛔ 断言两条条目「同形态、应并条同判」之前，**两份作者源都要看过**。⚠️ 同一事故里我写了「`EIS-0010-05` 与 `EIS-0030-02` 同形态」——⛔ 实际上 `0030` 的 `Autonomous` 是真复合态、接管边挂在复合态上，`0010` 是平级兄弟态，两者结构不同（两条最终都是 `D2`，但路径不同）。
4. ⭐ 本轮据此复核了**全部 20 条逆多数推荐**，改判 8 条：`EIS-0010-05` `EIS-0030-02` `INS-0002-03/04/05` `INS-0054-01` `INS-0004-02` `INS-0027-04` 归 `D2`，`EIS-0019-01` 归 `D1`。
