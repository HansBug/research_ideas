# 命中判据：语义同一性优先于标签一致

> **现行协议说明（2026-08-23）**：正式 Judge 唯一口径是
> [issue #195 同步入口](./semantic_judge_protocol.md)。主 hit 仅由
> `VALID_KNOWN + FULL_MATCH` 产生；`PARTIAL_MATCH` 只算 supported；W/D/L、谓词、
> exact locus/property/scope/direction 均不是 match gate。下文记录台账早期形成过程与
> legacy 人工判据，其中“四种形态闭集”“数引用次数硬判据”和机械 exact-field 层不再是
> 现行 FULL 定义，不能用于覆盖 #195 的适度宽语义或替代公共制品审计。

本文件是 Discover effectiveness 实验中「一条已发布 issue 是否命中某条 expected issue」的**裁决原则**。它是长期规则，不是某一轮的施工状态；施工进度与 review 状态在对应 GitHub PR / issue 中维护。

⚠️ “已发布 issue”的唯一边界由 [final_output_metrics_policy.md](./final_output_metrics_policy.md) 定义：方法侧只允许 `D1/D2 report_issue_clusters` 进入命中判定，`D0`、`D_UNRESOLVED`、raw finding 和未聚类 facet 均不进入。本文只回答进入该边界后的语义同一性，不另设统计分母。

> **谓词口径边界**：本文件还会引用台账建立期的 `eval_assert` 和旧底层原语。它们是
> 评测侧历史编码，不是当前公开谓词表。当前运行实现迁移后，命中仍按语义同一性判定，
> 但新断言只能引用 `four-family-19-core.v1`，没有适用谓词的义务仍按 W1 记录。

相关：[README.md](../../README.md)、[ground_truth_limitations.md](./ground_truth_limitations.md)（分母的已知缺口）、Issue [#166](https://github.com/HansBug/research_ideas/issues/166)（expected issue 台帐）、Issue [#170](https://github.com/HansBug/research_ideas/issues/170)（谓词设计）、PR [#169](https://github.com/HansBug/research_ideas/pull/169)（Discover 验收）。

## 1. 唯一裁决标准

**判定命中的标准是：我们的 assert 所表达的命题，与台帐那条 expected issue 的 `eval_assert` 所表达的命题，是否指向同一个作者源缺陷。**

不是：
- 两者用的谓词是否相同
- 两者的 `evidence_family` / `required_function_families` 是否相同
- 两者的路径集合是否完全相同

## 2. 为什么不看 family 标签

Issue #166 的台帐建立于当前谓词体系**之前**。那时 19 个谓词的定位尚未形成，`required_function_families` 是当时对「需要哪类证据」的粗略标注，用的是 `relation` / `structure` / `effect` 这套早期口径。

台帐 47 条 E1 的 `eval_assert` 全部调用当时的底层查询原语（`transition_exists` 22 次、`transitions` 11 次、`states` 9 次、`initial_child` 6 次、`effect_deltas` 2 次、`path` 2 次），**没有一条使用模拟**。而当前 Discover 产出的是 19 个封闭谓词的调用，其 family 由谓词表查得。

**两套标签之间存在信息代差，不是同一码事。** 因此 family 不一致本身不构成未命中的理由，也不构成方法论问题。这一点已经裁决：代差是预期的。

## 3. 语义同一性的四种成立形态

以 matrix-v18 的 10 条命中为实例，同一性可以合法地以下列任一形态成立：

| 形态 | 含义 | 实例 |
| --- | --- | --- |
| **直接对应** | 两个命题说同一件事，只是谓词不同 | `EXP-0029-GC-001`：台帐「该触发下只应一条迁移且目标是 `lane_change`」，我们「该触发下到不了 `lane_change`」 |
| **合取项之一** | 台帐命题是 `all(...)`，我们证明其中一个合取项为假 | `EXP-0000-IT-001`：台帐要求两个运行模式都有 `Power_Off → FinalState`，我们证明 `HumanDrivingMode` 那一半没有 |
| **负向命题的正向对偶** | 台帐说「不应存在错的边」，我们说「应存在对的边」 | `EXP-0029-IT-001`：台帐 `not transition_exists(cruise, dist_to_exit_2, FinishState)`，我们 `occupancy_after(cruise, dist_to_exit_2, exit_hwy)` |
| **蕴含更根本的原因** | 我们的命题为假蕴含台帐命题为假，且定位到更上游 | `EXP-0006-EA-001`：台帐「攻击完成边应有变量下降」，我们「模型根本没声明 `uav_count`」——无变量则不可能有下降 |

后三种都算命中。判据是逻辑关系，不是形式相同。

## 4. 不成立的形态

以下不算命中，即使路径大量重叠：

- **不同缺陷共用状态名**：一条关于 `HighwayMode` 子状态计数的发现，不能算作关于 `HighwayMode` 内某条迁移目标错误的 expected issue 的命中
- **更弱的命题**：台帐要求「这条边的目标是 X」，我们只证明「这个状态存在」——存在性不蕴含目标正确
- ⛔ **用结构存在性冒充行为验证**：**「某条 transition / edge 是否存在」不能代替 `reaches`。** 边存在 ≠ 状态可达（边可能永不使能、源态可能不可达、守卫可能恒假）；边不存在 ≠ 状态不可达（可经其它路径抵达）。两者形式相似而实质不同，属**以次充好**。这是本节唯一被点名禁止的替换形态，也是 §3 的四种合法形态之外最容易混进来的一种。

- **反向蕴含**：台帐命题为假**不**蕴含我们的命题为假

## 4.1 ⚠️ 边界要划准：**允许等价，只禁伪等价**

§4 是一份**窄清单**，不要把它读成「凡是形态不同就不算命中」。本仓库的立场是：

> **真正的等价一律接受，包括用不同侧面发现同一个问题。** 谓词不同、切入面不同、措辞不同、绑定的元素名不同，都不影响命中——只要指向的是**同一处建模失误**。

**不要用「读者据此修复后台账缺陷是否即消失」当判据。** 那条太严，会误杀 §3 已认可的「合取项之一」与「蕴含更根本的原因」两种形态——它们按定义就不会一修即消。正确的问法是：**两者陈述的是不是同一处建模失误。**

判定顺序：先问「是不是同一处失误」（是 → 倾向命中），再查「证据形态有没有踩 §4 的禁止项」（踩了 → 不算命中）。**不要反过来先看形态。**

## 4.2 「同一处失误」的硬判据：**数作者源里的引用次数**

「同一处」不是感觉，是可数的。判据：**在 `stm0.puml` 里，两个主张各自指向的元素被引用了几次。**

> 若某元素**全文只被引用一次**，则一切以它为对象的主张都锚在**同一条作者编辑**上，两个主张是那一条语句的两面 —— 动其一必动其二。

⛔ **不要用「有没有独立 `state` 声明」当判据。** 它看起来等价，实际是引用次数的一个粗劣近似：一个元素可以既无独立声明、又被多条边引用，那时两个主张锚在不同编辑上。⛔ **也不要用「修复它能否同时消除本条」当判据** —— 那条太严，理由见上一节。

**这条判据必须对称适用，尤其是在它会压低数字的方向上。** 实例：`0037` 的三个死端叶各被引用 **1 次**（第 9/16/23 行的检测边），故「这三个叶不该是直接子」与「这三条边不该指向它们」同源；而 `0014` 的 `Entry` **作为状态**同样只有第 25 行一处（第 7 行的 `Entry/Accelerate` 是迁移标签，属事件命名空间——所以这条判据要数的是「该元素在**它自己那个命名空间里**被引用几次」，一个不加过滤的 `grep -c` 会给 2）（`Entry: Emergency Stop`，一条语句同时隐式声明了状态、又没声明 entry 动作），故「多出虚假子状态」与「缺 entry 动作」同样同源。两者结构逐点同型，**判定必须一致**；只在抬高头条数字的那一侧适用同一条判据，正是 [CLAUDE.md](../../../../../CLAUDE.md) §3.5 条款 4「评测口径迁就结果」所禁止的。

⚠️ 同源只是**必要条件**，不是充分条件。还要过 §4.1 的第一问：两个主张陈述的是不是同一处失误。`0037` 上这一问答不过 —— 模型点名的多余子是**四个**（含 `Inactive`），而 `Inactive` 是台账 `reaches` 断言的 source、被台账认定为正确，模型给的修法会把它一并搬走或删掉。那是**严格超集**，且超出的那个是正确元素，不是「同一处失误的另一面」。

## 4.5 ⚠️ 已知判据歧义：伪状态的**运行代理**式主张（未裁定，双读法都报）

### 现象

19 谓词闭词表无法把结构主张绑定到**瞬时伪状态**（`Junction*` / `Join*` / `fork*` / `choice*`）。产出方于是改用**下游可占据后继**作运行代理。

机械过滤器（**故意过宽**）在 v23 命中 **14 / 249 = 5.6%**；逐条回读原文后确认 **7 条为真**，7 条为假：

| 假阳类别 | 条数 | 例 |
| :-- | --: | :-- |
| **拒绝**用代理（不是使用） | 2 | `0050` 的 `ISSUE-M004-front-distance-missing`：「不能由路由变量或仅以事件名代理替代」 |
| 动作声明作**行为需求**的结构代理（与伪状态无关） | 2 | `0035` 的 `REQ-012`/`REQ-018`：以 `during`/`entry` 动作声明代理「显示 cooking time」 |
| 无代理成分 | 3 | `0050` 的 `ISSUE-M005-MissingAutoFinal` |

⚠️ **过宽是有意选的方向**，不是疏漏。这个数只用于算上限，而**在上限计算里过度包含是安全方向**——上限变松不会低估歧义影响，漏包含才会。**精确性在上限计算里是错误的优化目标。**

典型（`run3/0038-gpt` 的 `ISSUE-chargedflash-chargedtrue-no-junction3-flow`）：

> `REQ-011` 要求 ChargedFlash 在 `Charged_true` 条件成立时进入 `Junction3`；**由于 Junction3/Join2 是瞬时伪状态，断言以其后续可占据结果 Fork2 为运行代理**，但 primary 结果为 False。

对应台账 `EIS-0038-03` 的 primary 是 `edge_declared(ChargedFlash, Charged_true, Junction3)` —— **结构主张**。

### 歧义所在

一条 issue 的「命题」该读成哪个？

| 读法 | 判定 | 依据 |
| :-- | :-- | :-- |
| **A：读它引用的 `requirement`** | **算命中**（形态 ①，同一命题、不同谓词） | `REQ-011` 逐字要求的就是台账那个命题 |
| **B：读断言的字面主张** | **不算**（§4「更弱的命题」） | 「运行时到不了」是「边不存在」的更弱形式（边不存在 ⇒ 到不了，反之不成立） |

两种读法都有正当依据，**本文件此前未规定走向**。

### 处置：双读法都报，不单方面裁定

**上限已算**（顺序固定为「先算上限 → 再逐条人工裁定 → 再看活体激活分布」，且后两步只在增量非 0 时做）：

    读法 B（当前，盲判所用）          105/204 = 51.5%
    读法 A 上限（7 条人工确认）        115/204 = 56.4%    +4.9pp 读法 A 上限（14 条机械候选）       118/204 = 57.8%    +6.4pp   ← 工具默认报这个

两重过宽叠加（候选过滤器过宽 **＋** 该格该轮全部未命中位都算命中），所以 +6.4pp 是很松的上限。工具默认报最松的那个，理由同上：上限宁松勿紧。

涉及的位集中在 `EIS-0018-03` 与 `0038` 的四条记录。

⛔ **这两个 pair 都属 `00x8` 家族，自 v46 起永久不进网格也不进分母**（[nl_scope_rule.md](./nl_scope_rule.md)）。因此本节的双读法义务在 v46 及之后**没有可作用的对象**——不是被忽略，是分母里已无涉及该歧义的记录。下一代次若有新的伪状态代理式主张落进分母，义务自动恢复。

📌 **两条理由使「现在不裁定」是正确处置：**

1. **连最松的 +6.4pp 都不足以让任何结论翻转**（57.8% 仍远低于 70% 目标）。走向必须在它可能影响达标之前写死 —— 一条判据若等到能改变结论时才定，就再也无法证明它不是为结论而定的。
2. 但增量非 0，所以歧义本身必须记录，否则下一代次会重复同一次争论。

**规则（从本版起生效，且仅在分母内存在该歧义时适用——见上）**：报告中凡涉及覆盖率，**必须并列给出两读法的数**，并标明盲判所用读法。不得只报对自己有利的那个。若将来某一读法使结论翻转，**必须先由独立裁定给出走向、并说明为什么该走向不是为了达标**，再使用。

### 工具侧强制

`full_tables.py` 的 `proxy_reading_bound()` 在**每份表里强制并列输出**这两行，无法通过配置关掉 ——否则「必须并列报」只是一句话，而话是会被忘的（本目录已有先例：一条策略写在文档里但没有归属地，下一代次就漂了）。

## 5. 已知的机械判据风险面（需人工复核的部分）

自动判据（`build_gist.py` 的 `expected_verdicts`）用路径重叠近似语义同一性：

- 台帐 `eval_assert` 含 `event=` 时（**20 / 47**）：要求触发器精确绑定 + 至少一个状态重叠，**不检查 family**
- 不含 `event=` 时（**27 / 47**）：要求期望的每个状态都匹配（容忍一级父子）**且 family 交集非空**

第二支存在代差风险：那 27 条里有 **10 条要求 `relation`**，若系统用 `containment` / `state_declared`（family = `structure`）检出同一缺陷，family 交集为空而被判未命中。这 10 条分布在 9 个 pair：`0008 0009 0010 0018 0020 0038 0047 0049 0058`（category：TR 5、IT 4、GC 1）。

**处理方式**：机械判据的结果不是终局。凡出现下列情形，必须按 §1 人工复核并在运行记录中写明理由：

1. 判为未命中，但该格确实发布了关于同一缺陷的 issue
2. 判为命中，但两个命题经 §4 检查其实不是同一缺陷
3. 台帐条目走无-trigger 分支且 family 不一致
