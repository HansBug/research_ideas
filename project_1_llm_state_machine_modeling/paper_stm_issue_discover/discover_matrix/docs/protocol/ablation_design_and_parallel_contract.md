# A1/A2 消融设计与并行施工公约

本公约于 2026-09-06 制定，适用于 Paper1 的 A1、A2 消融实现、公共接线、合流与实验交接。**A1/A2 的实施者和 reviewer 均须遵守；任何一方不得自行改变公共接口、消融边界或默认 full 行为。** 文档约定不等于开关已实现、测试已通过或真实运行已获授权。

## 1. 背景与制定原因

1. 2026-09-04 导师讨论收口了检查信息与谓词机制的消融问题；后续明确 A2 是关闭整个谓词机制，不是谓词 subset。来源见[正式讨论纪要](../../../../talks/2026-09-04-导师-paper1大纲收口与消融基线口径.md)和[大纲 RQ4/RQ5](../../../story/paper_outline.md#outline-5-2)。
2. [P1 #203](https://github.com/HansBug/research_ideas/pull/203) 将当前 method 收敛为四类 12 条连续编号谓词：`S1-S5 / G1-G3 / R1-R3 / V1`。v61 保留原 19 条运行身份和原始、派生结果，不重跑、不改写；历史映射只在 evaluation 与记录侧，不能回流为 method 别名。十格 smoke 的结论与具体异常以[中文分析](../../../reports/2026-09-05-22-18-46-p1-twelve-predicates-smoke-cn.md)为准，不作为端到端质量等价证明，也不因本公约顺手修订方法。
3. 2026-09-05 导师讨论及 09-06 用户补充把多模型比较明确为同 backbone 的 `LLMx + 方法 vs LLMx`。谓词的作用从“定义引导具体主张”和“执行结果检查、拦截错误主张”两方面解释；A2 检验二者的联合效果，不另拆子机制实验。E1/E2 的依据与范围见[伞 PR #179 §4.4、§4.5](https://github.com/HansBug/research_ideas/pull/179)，该轮正式纪要按[导师讨论文库](../../../../talks/README.md)规则另行归档，本公约不替代原始讨论。
4. 检查信息不只出现在 prompt，也被确定性候选生成与内部 D 校验读取；谓词不只提供 W2，其 `true` 回执还会排除候选。两路实现又会共同触及 CLI、runner、prompt/schema 和运行记录。先分别改完再处理冲突，可能留下信息泄漏、关闭不彻底或 full 行为改变，因此先固定共同约定，再并行施工。

本文件只保存稳定设计与要求。实际 owner、子 PR 编号、施工状态、review 结论和合流进度由伞 PR 与子 PR body/comment 维护；具体模型、预算、批次与运行身份由各次事前登记维护。本公约不替代[方法说明](../../../method/README.md)、[谓词出处政策](./method_provenance_policy.md)或既有评测协议，不新增方法、数据集、subset 消融或成本叙事。

## 2. 实验问题与统一入口

| 条件 | CLI 值 | 检验内容 | 模型范围 |
| --- | --- | --- | --- |
| 完整方法 | `--ablation none`，也是不传参数时的默认值 | 保持当前完整方法行为，作为匹配对照 | 沿用 `--profile`；多模型名单由 E1 敲定 |
| A1 | `--ablation no-inspect` | 前置确定性检查事实及其派生信息的增量作用 | 仅 `gpt-5.6-luna` |
| A2 | `--ablation no-predicates` | 整个谓词机制对 hit、precision 和报告量的作用 | 仅 `gpt-5.6-luna` |

以上是待实现接口的统一约定，不是已可运行的命令说明。`--profile` 与 `--ablation` 分别表示模型和方法条件；只增加一个三值枚举，不增加两个可任意组合的布尔开关，不提供双消融或 subset 模式。CLI、运行记录与统计使用同一拼写；计划中已有的 `no-predicate` 只表示 A2，不另实现为别名或第四种条件。非法值及尚未实现的条件必须在调用 provider 前报错，不得静默回退为 full。

A1/A2 各为 54 pair × 3 round = 162 个运行单元，合计 324；每个条件仍对应 145 条台账与 435 个 expected-issue/round 单元。54 pair 来自 9 个 NL 簇，每簇 6 个制品。E2 的多模型范围不扩展 A1/A2；A2 也不等于仅接收 NL/作者 PlantUML 的 baseline。

## 3. 消融的关闭与保留边界

| 处理层 | A1：no-inspect | A2：no-predicates |
| --- | --- | --- |
| 作者输入与转换 | 保留 NL、PlantUML、FCSTM、canonical/source inventory、source trace 与 working contract 的映射职责 | 同 full |
| 前置分析上下文 | 不消费 `reference_inspection_facts`、`inspection_equivalent_facts`、`verify_facts`、`smt_facts` 及其派生信息；其中 SMT 规范化输入事实不冒称求解结果 | 保留与 full 相同的前置分析上下文 |
| NL 契约与语义定位 | 保留任务、语义规则、两路 grounding 与正常补全机制；去掉依赖被关闭事实的说明 | 保留契约、语义规则、两路 grounding 和 NL 到模型元素的定位；移除谓词专属说明与字段要求 |
| 确定性候选生成 | 禁用依赖被关闭事实的候选、补充契约、预检和抑制规则；保留仅依赖作者源、转换追踪和正常语义定位的处理 | 保留现有源/契约/inspect 事实支持的语义候选；撤掉专门为谓词执行增加的探测与候选，不再选择或填写谓词参数 |
| 谓词机制 | 保留当前 12 条词表、路由、谓词参数绑定、编译、后端执行和真实回执 | 整体关闭词表引导、路由、谓词类型化参数绑定、编译、执行、执行回执及其过滤作用 |
| 内部候选筛选 | 保留内部 D 阶段与受限纠错，但其 dossiers、引用目录和确定性校验不能读取被关闭事实 | 保留普通语义筛选与纠错；不再要求或解释谓词计划、执行结果与回执 |
| 发布与独立评测 | 保留来源归属、正常模型定位、语义发布门、去重归并和独立评测 | 保留相同职责；没有谓词执行不等于候选自动成立或自动无效 |

### 3.1 A1 的信息隔离

原输入可完整保存在审计记录中用于 provenance，但“已归档”不等于“算法可消费”。A1 必须在 method 侧形成受限视图，同时约束 LLM 与确定性消费者，不能只删除 grounding prompt 中的几段 JSON。检查范围包括 artifact/source-role 摘要、case report 中检查相关状态、working-contract 附带诊断、补全/纠错 prompt、frontier、domain invariants 和 D 阶段校验。

不能把关闭表示为“检查已通过”“零诊断”或“空结果已证实”；不能在 `inspection_facts=None` 时从 ModelIR、native API 或另一份文件重建同一前置检查事实，再继续用于发现。允许为解析、稳定引用与来源定位保留必要模型结构，但不能把完整检查投影换个名字补回 prompt。A1 仍允许候选专属的谓词后端按原逻辑读取模型并求值，其新产生的真实回执属于保留的谓词机制，不属于被关闭的前置上下文。

### 3.2 A2 的机制隔离

区分普通语义绑定与谓词参数绑定：前者回答“这条 NL 义务对应哪个模型位置”，后者回答“给哪个谓词填哪些合法输入”。A2 保留前者、撤掉后者。不得只将 `predicate_id` 置空后继续编译执行，也不得生成伪造的 failed/unsupported 回执来冒充整机制关闭。

谓词要求必须从实际发给模型的 system/user prompt、响应 schema/field description、补全与纠错反馈一并去除；不能让 LLM 先照常填谓词字段，再由程序丢弃。这里“其余 prompt 不变”指仅删除被消融机制专属内容，不借机改写普通任务说明、增加示例或调整发现策略。full 的既有 schema 与 prompt 不随之清理。

`frontier.py` 混合了语义候选、inspect 派生检查和谓词导向处理，不能整块禁用。包括 source divergence 在内的现有源码语义检查，按依赖保留；如果某函数同时产出语义候选与谓词计划，应只断开后者。也不能将被撤掉的编译、求值或过滤逻辑换名为“语义检查”继续执行。两路在实现前均须在子 PR 中列出相关 producer/consumer 函数的保留、禁用或最小拆分及依据，不能用样本 ID 决定分支。

## 4. 公共接口与并行施工纪律

### 4.1 先共同接线，再并行实现

公约作为伞分支的文档提交；公共代码另作可独立审查的小提交，不混入文档提交。公共接线通过 provider-free 验证并进入伞分支后，A1/A2 从同一个公共代码提交分支。公共部分只做枚举、参数传递、记录身份和必要分派，不预建通用插件框架、不复制整套流水线；两路专属设计与测试准备可提前并行。

下表 method 代码路径相对于 [paper_stm_method 包](../../../method/src/paper_stm_method/)；当前调用链与阶段职责见[方法说明](../../../method/README.md)。

| 范围 | 责任边界 |
| --- | --- |
| `cli.py`、`orchestration/contracts.py`、runner 的公共参数/worker/manifest/resume/summary | 由伞侧指定一个公共 owner 统一接线；A1/A2 不各造一套字段或分派 |
| `semantics/workflow.py` 的公共 prompt/schema 选择入口、混合 frontier 的调用边界 | 公共 owner 维护共同接口；A1/A2 分别提供专属行为与测试，不同时重构共享正文 |
| A1 的输入投影、inspect 消费者、相应回归 | A1 负责；不得全局修改共享 loader/context 的默认行为而波及 full 或 judge |
| A2 的无谓词 prompt/schema、候选准备、语义证据记录与相应回归 | A2 负责；不得清理 full 的 registry、后端或正常发布逻辑 |
| E1 的 profile/供应商适配与全量模型准入 | E1 负责需求与适配；涉及同一 runner 入口时由公共 owner 协调，不借接入修改方法语义 |
| evaluation 的新记录兼容与统计 | 复用既有消费者；共享字段一次约定，不为消融另造判定协议 |

上表是职责规则，具体人员和实际修改文件集合只在 PR 中登记。修改共享函数签名、枚举、schema 或输入可见性前，必须先更新共同约定并通知另一方；受影响接线在约定完成前不合入，不以“最后解决 Git 冲突”代替设计协调。需要给 A1/A2 共用的修正先进入公共基点，两边同步；不得各复制一个近似版本。

### 4.2 运行身份只扩展一套

`ablation` 是唯一方法条件字段，从 CLI 传入 `run_experiment`、worker 和 cell，写入 manifest、cell、summary 以及失败/终止记录，并参与 `run_contract_hash` 和 resume 校验。复用既有 run ID、来源、输入和配置字段，不再维护可相互矛盾的开关组合。每种条件记录实际使用的 prompt/schema hash；A2 可记录软件携带的 registry 版本，但不得据此声称本次调用或执行了谓词。

公共 owner 一次确定受影响记录的 schema 版本、读写规则和兼容测试；历史无 `ablation` 字段的已知记录只按原版本作 full 的只读解释，不批量回写，不默认满足新实验的 resume 或匹配对照要求。跨模型、跨条件或不兼容输入/配置的 resume 必须在复用任何 cell 前拒绝。主动关闭的步骤显式记录 `disabled_by_ablation`；对于 `execute_batch` 等混合阶段，只标记被关闭的子步骤，不能连带跳过仍需保留的语义处理。A2 的谓词执行回执列表为空，不制造执行错误，也不能只因关闭就把全部 cell 判为 ineligible。

### 4.3 合流规则

两路必须使用隔离的工作树、分支和输出目录。进入合流前同步公共基点，复核共享函数、prompt/schema、记录字段及统计消费者；文本无冲突不代表语义兼容。合流后重跑第 7 节的完整条件检查，核对无未解决索引项、冲突标记、覆盖 sibling 内容或新纳入的 runs 文件。原有测试失败单独列出，不冒称全套通过；本次新增的失败必须解释和处理。

## 5. full 不变与 E1/E2 交接

### 5.1 本次开关改造不得改变 full

行为对拍的改造前锚点是 P1 合入提交 `87e969b291156b98e2762967f0aa1439fbd4ddaa`，不是重新运行 v61。对相同 fixture/replay 输入，比较改造前 full、改造后默认入口和显式 `none`：实际 system/user prompt、响应 schema、模型请求参数与调用顺序、候选及其顺序、路由、执行输入/回执、筛选和最终发布结果均应一致。验收不得只看最终报告条数或只看 prompt 常量 hash。

只允许运行时间、路径、run/source identity、新增条件字段和记录 schema 版本等不参与方法决策的记账差异；排除项逐字段列明，不能忽略整个 stage、candidate 或 receipt。差异若影响模型输入、确定性处理或发布，修复开关实现，不能用“模型随机性”解释确定性差异，也不靠重跑 ours 兜底。此对拍证明本次软件改造的 full 行为未变，不证明随机模型输出相同或当前 12 条实验等价于 v61。

### 5.2 模型接入与匹配对照

E1/E2 与 A1/A2 是模型选择和方法条件两个维度。模型切换覆盖所有属于 method 的 LLM 节点，外部 judge/人工裁定协议保持固定；共享转换产物固定来源与 hash。同 backbone 的 baseline/ours 核验实际推理、采样、输出和重试配置，不能只比较 profile 名称，不能为某个条件暗中改 prompt 或增加预算。

改造前 `run_experiment` 的全量运行门硬编码 Luna。E1 负责为经验证、登记的其他 profile 明确准入方式，保留显式 live/full-live 门、完整输入与三轮约束；A1/A2 不顺手放宽模型范围。供应商适配可以改变传输层，若影响 Luna 的有效请求、语义输入或 full 行为，须重新通过相关共同验收，不能将其混入消融效应。

A1/A2 共用同一份匹配的 Luna 完整方法对照：若 E1 最终名单包含 Luna，且 E2 的输入、当前方法语义、模型身份、配置和轮次匹配，可引用 E2 的该项新结果；否则在运行前登记一份独立匹配对照，由一个负责人组织并供两路共用，不各跑一份。对照只读引用原 run ID/hash，不复制改写为不同来源；v61 不作为当前 12 条消融的匹配主臂，原始与派生归档始终不变。

A1/A2 的施工不等待 E1/E2 整体结案；匹配对照来源必须在正式运行前落定，不能等看到结果后挑选。两路正式运行使用同一已验收的方法语义基线，优先使用共同合流代码版本；后续接入或公共修改若改变这条基线，先明确影响、更新登记与验收，不静默混成一个批次。E2 是否结案与某一项 Luna 对照能否交付是两件事。

## 6. 运行、评测与记录要求

1. **先登记后运行。** 各批次在 `discover_matrix/docs/generations/<批次>/preregistered.md` 固定条件、输入/台账 hash、方法与 registry、实际模型/profile、prompt/schema、推理与输出配置、重试、eligibility、对照引用和分析计划，代码与登记先推远端。具体型号、部署和预算以 E1 交接及批次登记为准，本公约不提前锁定 E2 名单。运行前须完成代码正确性与实验公平性 review，并获得明确真实调用授权。
2. **不因消融丢格。** 主动关闭不属于失败；缺失绑定、内部预算或非致命 backend 问题按仓库规则降级并保留产物。provider 或无法满足 schema 的终止失败保留诊断、尝试记录和未完成状态，不能用空结果冒充正常完成、缩小分母或冷启动重试掩盖结构性问题。
3. **复用评测，不改标准。** 指标定义沿用[大纲 §5](../../../story/paper_outline.md)及[独立评测入口](../../../evaluation/README.md)，报告 FULL `hit@1/@3/@all`、L 分层、report precision、报告/无效报告数和 D2/D1-only 敏感性结果。方法内部 D 阶段是候选筛选，不代替独立事实与缺陷裁定；新报告重新裁定，人工确认实际范围如实记录。未裁定、失败与降级单列，不把未裁定部分静默移出分母后宣称全量 precision。
4. **结论与问题对应。** A2 不以 W2 缺失作为效果指标；hit、precision 的变化方向不是完成门槛。“定义引导 + 执行约束”不拆分贡献比例，不由 pass 回执数直接推算误报数。保留九个 NL 簇与三轮重复的相关性，分析以案例内描述性配对为主，不外推为所有模型的消融结论。“precision 暴跌”或人工确认量“几何增长”不是实测事实，不新增人工工时或价格结论。
5. **原件与说明分开。** smoke prompt/raw output、细粒度审计和中间产物只留本地 gitignored runs 目录，提交前用 `git check-ignore` 与暂存清单核验；中文 smoke 结果及风险分析放[论文 reports](../../../reports/README.md)，不放 runs。正式事前登记与已验收的可复算归档按既有 generations/final_results 规则保存，不将“smoke 不入 PR”扩大为正式证据不保存。秘密配置、密钥和私有裁定执行材料不进入公开制品。

## 7. 验收场景与开工条件

公约及实现均以以下三个真实或准真实场景检查；文档 dry-run 只验证规则能否指导操作，不能冒充实现测试或真实模型结果。复用[既有阶段 fixture](../../../pipeline/evidence_discovery/tests/test_input_closure_and_staged_flow.py)与[执行/断点续跑测试](../../../pipeline/evidence_discovery/tests/test_execution_contracts.py)，不新增独立实验框架。

| 场景 | 必须检查的路径与通过条件 | 明确失败反例 |
