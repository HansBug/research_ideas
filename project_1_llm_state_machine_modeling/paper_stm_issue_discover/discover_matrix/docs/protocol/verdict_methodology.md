# 命中判定方法学：三层判定与审计口径

> **评测侧边界**：本文判定的是冻结台账与发布结果的语义同一性。文中的旧谓词名和
> 台账断言编码只用于历史复核，不定义当前四族 19 谓词；当前方法契约见
> [`pipeline/evidence_discovery/METHOD_PRINCIPLES.md`](../../../pipeline/evidence_discovery/METHOD_PRINCIPLES.md)。

本文件固定「一个运行结果是否命中某条 expected issue」这件事**由谁判、依据什么判、如何被复核**。它是判定的规范来源；工具实现在 [verdict_tiers.py](../../../archive/r10_ledger_v1_and_v46/scripts/verdict_tiers.py)，命中的语义标准在 [hit_criterion.md](./hit_criterion.md)。

## 一、为什么不是「全人工」也不是「全自动」

### 全自动做不到

台账的陈述是散文，而同一个缺陷可以被合法地编码成不同的谓词与绑定。[hit_criterion.md](./hit_criterion.md) §3 列了四种成立形态，其中**只有第一种（直接对应）是机械可判的**。

实测（v35，132 判定位）：按 (谓词, 绑定, 真值) 完全相等判定，只复现人工 89 条命中里的 **28 条**。

| 判据 | 命中 | 相对人工 | 假阳 |
| :-- | --: | --: | --: |
| 完全等值 | 28 | 31.5% | 0 |
| 扩到匹配台账**任一**已记断言 | 28 | 31.5%（无提升：多数记录只有 primary 一条可机械判定的断言） | 0 |
| **＋视界约定（当前 A 层）** | **34** | **38.2%** | **0** |
| 人工 | 89 | 100% | — |

**视界约定**：台账表达式常常不写 `within_cycles` / `bound` / `release` —— 台账记的是**主张**，而主张跨视界成立。产出多出且仅多出这些键时算相等；台账写了的每个键仍须逐字相等，台账写了而产出没写的键一个都不许缺。这不是本模块新造的放宽：既有的 `test_ledger_expectations_survive_predicate_changes.py` 早就用同一约定 —— 它对台账未写明 `within_cycles` 的断言扫 1..5 并要求全部一致。

### 全人工也不行，而且已经出过错

v35 那一轮，我在 132 位上犯了两处**作用域误判**：

| 记录 | 原记 | 实为 | 错因 |
| :-- | :-- | :-- | :-- |
| `EIS-0032-01` | 3/6 | **0/6** | 台账 primary 是 `initial_target(OperateState.AccelerateRegion, …)`，产出是 `initial_target(<root>, OperateState)` —— composite 不同 |
| `EIS-0029-05` | 2/6 | **0/6** | 台账 primary 是 `containment(AutonomousMode, AutonomousMode.FinishState)`，产出断的是 `state_declared(UrbanMode.FinishState)` —— 而这条在**参考模型上同样为 False**，无法区分合规与不合规 |

两处都是拿「同一个 pair、同一类谓词」的邻近性代替读台账 statement。**而这两处恰好都是 A 层判 0 而人工判命中** —— 分歧本身就是警报。

### 所以分工是

**A 层负责检索与自动确认，人只做判断，而机器与人的分歧变成一道必须书面交代的闸。**

## 二、三层的确切定义

### A 层 —— 确定性，无人参与

> issue 命中记录 $R$ $\iff$ 该 issue 引用的某条断言，其 (谓词, 绑定) 与 $R$ 的某条**已记真值**的台账断言完全相等，且其实测真值等于台账记的那个值。

三条执行细节，每条都有实测教训：

1. **只看已发布 issue 引用的断言。** 被排除的发现不算命中 —— 它没有进入产物。v35 的 `EIS-0000-02` 正是这个形状：`stays_in` 取到了正确的 False，被归因门排除，那一位是未命中。
2. **台账的 `measured` 是字符串 `"False"` 而非布尔 `False`。** 不归一化会让 `False is "False"` 恒假 —— 实测踩过：一次复测把 91 条全报成「台账与实现不一致」，真实答案是 0 条。
3. **绑定按键排序后比较**，参数书写顺序不参与判定。

**实测性质：假阳 0，假阴 55（v35，A ⊆ 人工）。** 这是 A 层输出可以被直接采信的唯一理由。

⚠️ **38% 不是覆盖率主张，是审计下界。** 把 A 层当全部判定会把 `hit@1` 报成 26%。

### B 层 —— 人工判编码等价

A 层未确认的每一位，工具打印一张对照：

- 台账 primary 的表达式与期望真值
- 该格**全部已发布**断言的 (谓词, 绑定, 真值)
- **逐项差异**：谓词 / 每个绑定键 / 真值，哪一项不同

人只回答一个问题：**这两种编码是不是同一个命题。** 不检索、不猜绑定 —— 这正是 v35 两处误判发生的环节，把检索交给机器就消掉了那个失误面。

### C 层 —— 分歧闸

| 情形 | 处置 |
| :-- | :-- |
| 人判命中，A 层未确认 | **必须**点名 [hit_criterion.md](./hit_criterion.md) §3 四种形态之一，并写出等价性论证 |
| A 层确认，人判未命中 | 两者之一必错，**不得并存**，就地解决 |
| A 层未确认，且无人工判定 | **该位未判**，不得静默算作未命中 |

四种形态是闭集，逐字取自 §3：`直接对应` / `合取项之一` / `负向命题的正向对偶` / `蕴含更根本的原因`。**一个不属于任何形态的「等价性论证」就是没有论证** —— 闭集是这道闸的全部力量所在。

最后一行同样重要：一个只判了一半的审计文件与判完的**在形状上无从区分**，所以未判位必须报错而不是默认为 0。

## 三、审计输出口径

每一位都记「由谁判定、依据是什么」，不只是 yes/no：

```json
{
  "record_id": "EIS-0000-01",
  "cell": "run1/0000-claude",
  "layer": "wellformedness",
  "hit": true,
  "decided_by": "tier_a",
  "tier_a": {
    "matched": true,
    "assertion_id": "AST-REQ-007-1",
    "predicate": "terminates",
    "bindings": {"source": "…", "trigger": "…"},
    "result": false,
    "expected": false
  }
}
```

人工判定的那一位额外带：

```json
  "decided_by": "human",
  "comparison": { "ledger_primary": "…", "candidates": [{"assertion_id": "…", "differs_in": ["谓词 A vs B", "…"]}] },
  "human": {
    "equivalence_form": "蕴含更根本的原因",
    "argument": "台账要求该边有变量下降，产出证明模型根本未声明该变量——无变量则不可能有下降",
    "cited_assertion_ids": ["AST-REQ-009-0"]
  }
```

发布时**必须**同时给出：

1. `hits_by_decider`：A 层判了多少位、人工判了多少位。读者据此知道有多大比例可被脚本复算。
2. 每条人工命中的形态名与论证，逐位可查。
3. `gate_problems` 为空 —— 非空则该轮判定未完成，数字不得发布。

## 四、口径的边界与已知局限

1. **A 层不完备是结构性的**，不是实现缺陷：`all`/`any` 复合表达式、位置参数、以及台账 `measured` 为空的断言都无法机械判定。v35 有 24 条 primary 属这类。
2. **A 层不判「不成立」。** 它只确认命中；未确认不等于未命中，必须过 B 层。这个不对称是有意的 ——反过来（自动判未命中）会把「不同但等价的编码」全部误杀，实测那是 55 位。
3. **人工判断的可复核性靠论证而非靠人。** 论证与对照表一起进审计文件，任何人可以对着台账原文与产出断言复核该论证是否成立。这是把「相信判定者」换成「检查论证」。
4. **不做棘轮。** 把人工接受过的等价编码回写台账、使其下一代次进 A 层，会逼近「台账迁就结果」。若将来要做，必须给每条 accepted encoding 附**独立于该次运行的蕴含论证**，且在下一次开跑前冻结。当前不做，A 层覆盖率就停在实测值。

## 五、工作流程

```bash
# 1. A 层 + B 层对照表（无人参与）
python -m verdict_tiers --generation matrix-v36 > /tmp/v36_tiers.json

# 2. 人工只判 needs_human 那些位，写成 {"<record_id>|<cell>": {...}}
#    A 层已确认的位不需要碰

# 3. 合入并过 C 层闸；非零退出即该轮判定未完成
python -m verdict_tiers --generation matrix-v36 \
    --verdicts /tmp/v36_human.json --audit /tmp/v36_audit.json
```
