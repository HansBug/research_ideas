## 二、这个测量为什么是决定性的

**占位符的存在不区分命中与漏检 —— 9 条入口类记录 9 条全有**（4 命中 / 5 漏检）。

因此「pyfcstm 已经报了这个缺陷」对**两侧同样成立**。这排除了一种此前隐含的读法（「命中的是方法自己推出的、漏检的才依赖工具诊断」），并直接推出：

> **当前 `wellformedness` 层的 4 条命中，同样是 pyfcstm 已经标记的缺陷。**

## 三、裁定

**采用路线 2，判据落在子类而非整层：**

> 凡「机器证据是投影在其主张 scope 内合成的占位符（`UnspecifiedInitial` / `InvalidInitial*`）」的期望缺陷，**移出发现能力的分子与分母**，单列为「上游可检出」。

后果（必须与数字一起报，不能只报结论）：

| 项 | 值 |
| :-- | --: |
| 从 `wellformedness` 能力口径移出（**两者都算**） | **9 / 12** |
| 其中**当前命中**的 | **4**（`0035-01` 6/6、`0043-02` 5/6、`0038-06` 2/6、`0048-01` 1/6） |
| 其中当前漏检的 | 5（`0032-01` 1/6 + 四条 0/6） |
| **只算 `UnspecifiedInitial`（不含 `InvalidInitial*`）** | **6 / 12**（命中 3 / 漏检 3） |
| 留在能力口径内（严口径 9/12 下） | `EIS-0000-01`、`EIS-0029-02`、`EIS-0000-02` |

### 双份口径逐条

| 口径 | 记录 |
| :-- | :-- |
| `UnspecifiedInitial`（作者**什么都没写**） | 命中 `0035-01` `0043-02` `0048-01`；漏检 `0032-01` `0048-02` `0048-03` |
| `InvalidInitial*`（作者**写了但指错**，`nodes.py:3527`） | 命中 `0038-06`；漏检 `0047-01` `0047-02` |

📌 **两者性质不同**：前者是遗漏，后者是错误。若认为「作者写了入口只是指错」仍属方法应当发现的缺陷，则口径为 6/12；若认为凡由投影合成占位符标记者皆属上游已检出，则为 9/12。**报告必须并列两个数。**

📌 **本裁定同时做两件方向相反的事，两者都必须说：**

| 方向 | 内容 |
| :-- | :-- |
| **减少**方法可主张的绝对内容 | 移出 9 条记录 / 54 位，其中 **4 条是当前命中、共 16 个命中位** |
| **推高**百分比 | 被移出子集命中率 **16/54 = 29.6%**，低于全量均值 53.9%，故收窄后为 **94/150 = 62.7%** |

⚠️ **我最初只写了前者（「这是一次向下的修正」），那是片面的，已就地更正。** 后者是算术后果而非选择，但它使本裁定落在 `CLAUDE.md` §3.5「评测口径迁就结果」的形状上，因此：

1. 本裁定的提交（`e15d6b8f`）**早于**发现它会推高百分比的那笔账（见 [docs/generations/v25/coverage_levers.md](../../generations/v25/coverage_levers.md) §五）；
2. **53.9% 与 62.7% 必须永远并列报**；
3. 裁定须凭自身论证站住（工具已报 ⇒ 不是发现），**不得凭它对数字有利**；
4. 独立复算返回前，62.7% 不得用作任何结论。

而此前两次 src 尝试都是想**提升**这一层的覆盖率：方向从一开始就错了，因为这一层的分母本身就该收窄。

### 为什么不选路线 1

路线 1 要求「区分工具已报的与方法自推的，能力只记后者」。上表表明该区分在本层的**实际效果**是：**9 条入口类记录 9 条都属前者。****即路线 1 执行到底会得到与路线 2 相同的分子，只是多绕一圈**，且中间过程需要在 prompt 里描述占位符的语义 —— 而两次 review 已证明那必然滑向答案形状泄漏（见 [docs/generations/v25/synthesized_placeholder_proposal.md](../../generations/v25/synthesized_placeholder_proposal.md) 开头）。
