# 人类基线与断言构造链路 —— ⭐ 一个我们从未考虑的参照系

> **日期**：2026-08-12 · **来源**：断言构造 CoT 文献调查（76 条已核实引用）⭐ **一句话**：**形式化规约的人类基线是 47–50%（受训 + pattern 辅助），⛔ 而我们的主臂是 60.4%。**

## 一、⭐⭐ 人类基线：有对照实验，⛔ 而且很低

**Czepa 等人的对照写作实验**（$N = 215$，三位作者独立评分）：

| 条件 | 语义正确率 |
| :-- | --: |
| 受训参与者 **+ pattern 辅助**写形式化 | ⭐ **47–50%** |
| 不用 pattern，直接写 LTL | ⛔ **28–31%** |

⭐⭐ **pattern 把正确率翻倍，⛔ 翻倍之后仍有一半是错的。**

### 1.1 三个可直接用作论文开篇的引用（⭐ 均已核实原文）

1. **van Lamsweerde (ICSE 2000)**：「构建正确规约的**构造性方法基本不存在**」
2. **FormaliSE 2024 综述**：二十四年后仍称这个过程 **"usually manual"**
3. ⭐⭐ **Holzmann 的 dialtone 例子**：一条**平凡需求**的时序公式**被逐步修正四次仍有遗漏**——⭐ 这是我们 `DoorsClosing` 失败的**教科书版本**，⛔ 引它比引我们自己的例子更有说服力

### 1.2 ⭐ 参照系对比

| 参照系 | 我们（主臂 60.4%） | 差距 |
| :-- | :-- | --: |
| ⛔ SOTA LLM 裸跑（当前论文用的） | 76.2% | ⛔ **−15.8pp** |
| ⭐ **受训人类 + pattern 辅助** | **47–50%** | ⭐⭐ **+10~13pp** |
| ⭐ 人类不用 pattern 直接写 LTL | 28–31% | ⭐ **+约 30pp** |

⚠️ ⛔ **必须同时报 SOTA 对比**——⛔ 藏起来就是选择性报告。⭐ 但「受训人类」是**形式化方法领域的标准参照系**，⛔ 不是临时换的对手。

## 二、⭐⭐ 「正确的 family」本身不是单值的

**Menghi 等人**在 436 条需求上：

| | 条数 |
| :-- | --: |
| 无法表达 | 66 |
| **有歧义** | **102** |
| ⛔ **作者们都认为不含歧义、却仍给出不同的 pattern 组合** | ⛔ **156** |
| ⭐ **合计存在解读层面分歧** | ⛔⛔ **59%** |

⛔ **用单人（或单 LLM）标注的台账去评判「family 选对了没有」，上限受这个分歧率约束。**

⭐ **可直接用于 54 pair 重标的事前登记预测**：⛔ 若两个独立标注者的一致率**远高于 ~41%**，⛔ 多半说明**标注指南在无形中限定了答案**。

## 三、⚠️ 两处对我方先前判断的修正

### 3.1 ⛔ 倾斜分布是**常态**，⛔ 不是病态

⛔ 我方先前把 `edge_declared` 被问 **0.0%** 判为异常。⭐ 四项独立研究一致显示这类体系**天然倾斜**：

| 体系 | 倾斜 |
| :-- | :-- |
| Dwyer | ⛔ **79% 用 Global scope** |
| FRET | ⛔ 8 个 scope **只用了 4 个**；**3 个 timing 从未被使用** |
| EARS | ⛔ Optional Feature 在 30 次机会中**被选中 0 次**，⛔ 两个衍生体系**直接删了它** |

⭐ **修正后的判据**：⛔ 不看分布均匀度，⭐ 看「**台账里有记录的 family，被问率是否 > 0**」。⭐ 这是**第三条独立证据**支持「⛔ 别急着补谓词」（前两条：③ 类上界仅 1.7pp；174 位里 83.9% 落在已实跑过断言的记录上）。

### 3.2 ⚠️ 一个具体的实现坑

⛔ **Salamah 等人**证明：把复合命题**朴素代入** pattern 模板在 **FIL 上成立、⛔ 在 LTL 上不成立**（⛔ 跑了 **300 万+ 测试用例**才补上）。

⛔ **推论**：「LLM 填字段 → 确定性编译成谓词调用」这一步**不能假设套模板就对**——⭐ **每条编译规则需独立验证**。

## 四、⛔ 已核实为**不存在**的常见误引

`DeepSVA` · `TratorLLM` · "Why Don't Developers Write Assertions" · Autili 的「96 个 pattern」——⛔ **均不存在**。⭐ Dwyer 的「8 vs 55 个 pattern」⛔ 不是矛盾：是 **11 条 LTL 映射条目 × 5 scope**。

## 五、⭐ 与我们自己数据的交叉印证

⭐⭐ **脚手架类型决定符号**（Huang et al. ICLR 2024 完整表）：

| 模型 | 自我纠正后的变化 |
| :-- | --: |
| **Llama-2** | ⛔ **−27.5pp** |
| **GPT-3.5** | ⛔ **−34.0pp** |
| GPT-4 | −2.0pp |
| GPT-4-Turbo | −1.0pp |

> ⭐ **信息供给型脚手架利好弱 backbone；⛔ 自我批评型脚手架对弱 backbone 伤害最大。**

⭐⭐ **这与我们自己的 ROI 数据独立吻合**：

| 我们的组件 | 类型 | 实测 |
| :-- | :-- | :-- |
| 两个 reviewer + 修订回路 | ⛔ **self-critique** | ⛔ 第 3–5 轮**恰好零位**；79% token、覆盖净变化 ≈ 0 |
| `precheck_and_seal` | ⭐ **information-supplying** | ⭐ **0 token，性价比最高**（删 1191 条不可执行断言） |
| `convert` 契约重试 | ⭐ **information-supplying** | ⭐ **唯一净 +1118 条断言** |

⛔ 另两条（均已核实）：**多智能体辩论在等预算下输给 self-consistency**（83.0 vs 88.2 @ 9 responses）；**Self-Refine 的 CommonGen-Hard 增益在调优过的 baseline prompt 下消失**（81.8 → 75.1，⛔ 7× 成本）。

### 5.1 ⭐ v47 的设计原则

> ⛔ **不要问模型「这写得对吗」，⭐ 要告诉它「还有这些没查」。**

⭐ 这一条同时解释了：为什么 review loop 零收益 · 为什么 `precheck_and_seal` 性价比最高 · 为什么干预实验里「加结构扫描」在修掉措辞冲突后**立刻 0→4/6**。

### 5.2 ⛔ 对导师建议 (2) 的修正

⛔ 「小模型 + 我们的框架 ≈ SOTA 裸跑」——⛔ **若框架保持现状（self-critique loop），Huang 的 Llama-2 行预测 −27.5pp**。⭐ **正确做法：先把框架从 self-critique 改成 information-supplying，再谈小模型。** ⚠️ 待读：**Stroebl et al. 的 impossibility result**——⭐ 被点名为「能直接杀死一个不当 pivot」的东西。
