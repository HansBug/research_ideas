### 4.5 ⛔ 一个必须知道的方法学限制

⛔⛔ **目前无法把「reviewer 的判断」与「多抽一个样本」分开**：匹配 ordinal 后 **review 修复与机械重抽无法区分（Fisher $p = 0.18$）**。

⭐ 另一个反直觉发现：**34.4%「revise 后没变好」⛔ 不是生产者不照办**——照办率在该子集里**更高**（94.6% vs 88.3%）。断言侧 **10/10 是缺陷性要求**；需求侧 **70% 的「没变好」轮次根本没提任何先前标记的 id**——⭐ reviewer 修好了旧缺陷又发现了真的新缺陷，⛔ 而 findings-count 看不见。

⚠️ **限制**：命中是人工裁决的，⛔ 逐轮命中无法机械重建。「边际 = 0」只在**机械可判定范围内**成立；配对比较在需求侧给出 63.6% favoring more rounds（$p = 0.058$）——⛔ **干净答案需要消融重跑**。

⭐ **可砍**：断言评审回路 −25.8% · 五条回路预算 5→1 −40.4% · 两个 reviewer −52.5%。⛔ **不能砍**：`precheck_and_seal`（**0 token**、删 1191 条不可执行断言）· `convert` 契约重试（**唯一净 +1118 条断言**）。⛔ **数据缺口**：173 次 splitter 调用 token 无记录（124 次是该格首次 split），失败多为 `named_elements` 校验器。

⚠️ **证据级别 S / I**：⛔ 「63% 集中在三类」是**逐位人读归类**得出的，⛔ **无落库脚本、无第二判者、无成文码本、归类者未盲于臂身份**；⛔ 而且当初逐位读的是 `matrix-v46-full` 的散文，⛔ 那 6 个被 `v46r` 替换的 pair 上读到的是**旧产出**。⭐ 稳妥表述是「我们读了这 86 位，其中**大量**属于以下三类」，⛔ **不给精确百分比**。

⭐ **三类「PlantUML 表层语法把真实结构藏起来」的缺陷**，⛔ 而 X1 在这三类上**系统性读错**：

| 机制 | X1 的错法（判定散文逐字） |
| :-- | :-- |
| 前向引用把兄弟态**钉成子态** | 「把四个**逐一列为平级复合态**」 |
| 缺 `[*]` 时投影补 `UnspecifiedInitial` | 「说的是**终态不是初始子状态**」 |
| 自由文本标签被熔成单一事件名 | 七条 issue「**唯独没有一条**」 |

**51/86（59%）落在满格池**（6/6 稳定），⛔ 0 位落在零命中池。⚠️ 代价：**同一转换步骤贡献主臂 46.5% 的多报**（`REPRESENTATION_DEBT`）。

## 八、⭐ 架构重构的方向

⛔ **不建议「把 loop 做得更好」**——干预实验已证明在现有链条上加扫描不奏效。

⭐ **建议分成两条路径**：

```
                 ┌─ 路径 A · 逐点核对（⭐ 保留，这是我们赢的地方）
   NL + 模型 ──┤    NL 段 → Requirement → 谓词 → 断言 → 求值
                 │    覆盖：存在性 / 归属 / 默认进入点 / 效应
                 │
                 └─ 路径 B · 全局扫描（⭐ 新增，⛔ 不经过 NL 切分）
                      直接对模型跑结构性质：可达性 · 死端 · 吸收态
                      · 边完整性 · 守卫互斥性
```

⭐ **路径 B 不从 NL 出发**，⛔ 所以绕开「NL 里没这句话」这个死结；⭐ 产出仍是形式断言，⛔ C-② / C-③ 完整保留。⚠️ ⛔ **必须与 R3 一起做**，否则重复干预 v1 的结局（提问率翻倍、命中不动）。

⭐⭐ **作者提出的更激进方案（待验证）**：**先用类似朴素基线的方式通读发现，再把发现转成形式断言**。⭐ 数据强支持——X1 在关系型上 83–95%、主臂 31–37%；主臂在单点结构上 78–96%、X1 51–67%。⭐ **两者能力双向解离，合起来才是完整覆盖。**

| :-- | :-- |
