### 2.1 分母本身的三个问题

1. ⛔ 台账**只用到 15/19 个谓词**；`variable_declared` / `variable_delta_after` / `response_within` / `invariant` **从未作为 primary 出现**——⛔ 变量维与时序性质在台账里几乎是空的。
2. ⛔ **11 条记录（66 位）连 primary 谓词都没有**——⛔ 原理上无法谓词分层。
3. ⛔ `edge_declared` 在 324 格里被问 **0.0%**——⭐ 干预实验查明**根因不是 splitter 疏忽**，见 §三。

## 三、根因：⛔ 闭合词表自己在教模型不要用 `edge_declared`

⭐ 干预实验（30 格三臂，事前登记跑前 push）分离出：

> `occupancy_after` 的 `nl_cue` 逐字写着「**`edge_declared` 只用于关于制品含有什么的主张**」，⛔ 而**同时**宣称自己是**事件驱动行为的默认选择**。

- **干预 v1**（只追加四条结构扫描）：⛔ 仍得 **0**
- **干预 v2**（按 `CLAUDE.md` §13 解决那处措辞冲突）：⭐ **立刻 4/6**

⭐ 那段文本**只渲染进 splitter / reviewer prompt，⛔ 从不进入求值**——⭐ 所以这是**机械可证、可直接修复、且独立于任何命中计数为真**的系统性供给缺口。

### 3.1 干预实验的另一半：⛔ 提问必要、远不充分

| | |
| :-- | :-- |
| 提问率 | 21.4% → **54.5%** |
| 命中 | ⛔ **3/14 → 3/14（没动）** |
| ⭐ 但 treated 臂内 | asked 位 **3/6 = 50%**，⛔ unasked 位 **0/5** |

⛔ 功效硬限制：14 位下即使预登记的强效应也只到 $p = 0.054$。

## 五、⭐ 主臂真正强的地方（86 位独有命中）

⭐ **63% 是三类「PlantUML 表层语法把真实结构藏起来」的缺陷**，⛔ 而 X1 在这三类上**系统性读错**：

| 机制 | X1 的错法（判定散文逐字） |
| :-- | :-- |
| 前向引用把兄弟态**钉成子态** | 「把四个**逐一列为平级复合态**」 |
| 缺 `[*]` 时投影补 `UnspecifiedInitial` | 「说的是**终态不是初始子状态**」 |
| 自由文本标签被熔成单一事件名 | 七条 issue「**唯独没有一条**」 |

**51/86（59%）落在满格池**（6/6 稳定），⛔ 0 位落在零命中池。⚠️ 代价：**同一转换步骤贡献主臂 46.5% 的多报**（`REPRESENTATION_DEBT`）。

## 八、⭐ 架构重构的方向

⛔ **不建议「把 loop 做得更好」**——干预实验已证明在现有链条上加扫描不奏效。

⭐ **建议分成两条路径**：

```
                 ┌─ 路径 A · 逐点核对（⭐ 保留，这是我们赢的地方）
   NL + 模型 ──┤    NL 段 → Requirement → 谓词 → 断言 → 求值
                 │    覆盖：存在性 / 归属 / 默认进入点 / 效应
                 │
                 └─ 路径 B · 全局扫描（⭐ 新增，⛔ 不经过 NL 切分）
                      直接对模型跑结构性质：可达性 · 死端 · 吸收态
                      · 边完整性 · 守卫互斥性
```

⭐ **路径 B 不从 NL 出发**，⛔ 所以绕开「NL 里没这句话」这个死结；⭐ 产出仍是形式断言，⛔ C-② / C-③ 完整保留。⚠️ ⛔ **必须与 R3 一起做**，否则重复干预 v1 的结局（提问率翻倍、命中不动）。

⭐⭐ **作者提出的更激进方案（待验证）**：**先用类似朴素基线的方式通读发现，再把发现转成形式断言**。⭐ 数据强支持——X1 在关系型上 83–95%、主臂 31–37%；主臂在单点结构上 78–96%、X1 51–67%。⭐ **两者能力双向解离，合起来才是完整覆盖。**

## 九、⛔ 台账本身的问题（⭐ 独立于上述全部）

| 项 | 现状 |
| :-- | :-- |
| 生成者 | ⛔ **5 个 LLM agent**，⛔ **人类校验 0 条** |
| 双盲复审 | ⛔ 12/60 = 20%，$\kappa$=0.750 且是**二元 case 级** |
| 只过正则从未二读 | ⛔ **32 条** |
| ⛔ **读了 fcstm 投影写的** | ⛔ **41/98 条** |
| 时序 | ⛔ 台账 07-31 **晚于**方法产出 07-27 |

⚠️ **人工全量重标的方向判断**：⛔ 它**大概率扩大差距**（补进的多是关系型/行为型条目，⭐ 正是 X1 强的那一类）。⭐ **但仍必须做**——⛔ 「ground truth 零人类校验」是论文的必答题，⛔ 且作者怀疑**现有台账偏浅**，⭐ 若能挖出更深的缺陷，反而可能成为方法的新增长点。

## 十、⭐ 敏感性：baseline 的分数对设计有多敏感

⭐ 10 个单维度变体 × 54 pair × 2 模型 = **1074 格，零失败**；⭐ 噪声底（gpt 6.7% / claude 1.0%）由 v2 的三轮给出。

| 发现 | 内容 |
| :-- | :-- |
| ⛔ **fcstm 输入** | 产出 **+29%**、命中 **96%**——⛔ **「主臂读有损表示」这条辩护死了**。⚠️ 但 18% 的 issue 是关于编译注入的 `R45RouteToken`，⛔ 故不能把 baseline 搬到 fcstm |
| ⭐ **删全部 field description** | 只移动 +1.3%/+2.4%（**噪声内**）——⭐ 独立确认 claude 沉默来自**臂身份文本** |
| ⚠️ **v3 的因果解释要削弱** | 加更丰富的 description **降低** claude 13.6%——⭐ v3 的 +22% 是**措辞效应**，⛔ 不是信息量效应 |
| ⛔⛔ **没有任何公平改动能拉低 baseline** | 两个最大降低项（`b1-terse` −20%、`b3-nodomain` −11%）⛔ 都不公平；⭐ 而 `b2-noquantitycue` 是反例——那句公平该留的话**本身在降低** baseline |
| ⛔ **temperature 无法对齐** | `claude-opus-4-7` 对 `temperature` 返回 **400**——⛔ 两臂在该维度**根本无法对齐**，⭐ 须进 Threats |
