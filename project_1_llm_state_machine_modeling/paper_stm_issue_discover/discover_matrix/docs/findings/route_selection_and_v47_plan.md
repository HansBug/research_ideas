# 路线裁定与 v47 最小改动集

> **日期**：2026-08-12 · **依据**：本轮九路独立调查（含两路 codex 交叉验证）⭐ **一句话**：**我们的 loop 是自我批判型的，⛔ 而自我批判型脚手架在文献里、在我们自己的 ROI 数据里、在一条已发表的不可能性定理里，都是负收益。**

## 一、⛔ 小模型路线（导师建议 2）的裁定：**动机成立，⛔ 但它修不了我们的问题**

三方证据同时反对「小模型 + 我们的框架 ≈ 大模型裸跑」：

| # | 证据 | 内容 |
| :-- | :-- | :-- |
| ① | ⭐ **我们自己的根因调查** | ⛔ −15.8pp 里 **81.2% 是「问题从未被提出」**（`split_requirements`）——⭐ **流水线拓扑缺陷，⛔ 不是模型能力缺陷**。换弱模型只会让「想到该问什么」更差 |
| ② | ⭐ **我们自己的干预实验**（commit `b3b87383`） | ⛔ 强形式**已跑过并失败**：提问率 21.4%→54.5%，命中 **3/14 → 3/14，净 0**（McNemar $p = 1.0$） |
| ③ | ⛔⛔ **已发表的不可能性定理** | [Stroebl/Kapoor/Narayanan, arXiv:2411.17501](https://arxiv.org/abs/2411.17501) 逐字：*"no amount of inference scaling of weaker models can enable them to match the single-sample accuracy of a sufficiently strong model"*——⛔ **前提是验证器不完美，⛔ 而我们的验证器正是 LLM 审查者** |

### 1.1 ⭐ 但第 ③ 条同时给出唯一出路

> ⭐⭐ **把裁决者换成 sound oracle（`pyfcstm`）。**

⭐ 三个**正增益**案例（Lean 编译器 / SMT / Dafny verifier）**全是这个形状**；⛔ 纯 LLM 自我批判的循环**全是负增益**。

⚠️ ⛔ **冷水**：即使用完美 oracle，**SOTA prover 的自纠也只买到 +2.3pp**——⛔ 而我们需要 **+8 到 +18pp**。

### 1.2 模型侧：⛔ 一个流传的口径错误

| 说法 | 真相 |
| :-- | :-- |
| ⛔ 「差距只剩 6 分」 | ⛔ 那指的是 **GLM-5.1（355B+，不可单节点）** |
| ⭐ **真实的 ~30B vs frontier** | ⛔ **25 分**（Qwen3.6-27B 38 vs Opus 5 63） |

⭐ **但赤字不落在我们吃的能力上**：长上下文推理（AA-LCR）只差 **3.3 分**；⭐ **结构化输出取值准确率开权重反超**（GLM-4.7 **0.830** > GPT-5.4 0.825）。

⭐ 推荐 `Qwen/Qwen3.6-27B`（dense，单卡 BF16 **55.58 GB**，Apache-2.0）；30B 裸跑估计 **58–68%**（中性），锚在同形任务（放射报告错误检测：开源 79% vs GPT-4o 88%，⛔ 差 9pp 且 **$p = 0.50$ 不显著**）。⛔ 排除 `gpt-oss`（128K 是从 4K base 做 32× YaRN 外推）。

成本：C 臂 ~**\$5**，完整 2×2 **\$60–330**。⛔ **真正的成本是判定人力**（每臂一整轮 588 位判定）。

## 二、⭐⭐ 两个零成本可修的新缺陷（⭐ 已用真实 run record 实测）

### A · ⛔ 五个 LLM 调用的 schema **全把结论排在理由前**

⭐ **证据**：用 75 条记录的**流式 `partial_json`**（真实 token 生成顺序）确认——两个审查节点 **25/25 次都先吐 `"decision"`、后写 `rationale`**，⛔ 且 `content` 全部只含 `tool_use`、**零 `thinking` 块**。

⭐ 与 **Tam et al. (EMNLP 2024)** 点名的失效形态逐字对应：⛔ **结构化输出强制模型先给结论、再补理由，⛔ 等于禁掉了 CoT**。

⭐⭐ **这正好解释了「assertion 生成没形成 CoT」——⛔ 不是没写 CoT，是 schema 结构上不允许。**

**修法**：把 `rationale` / `analysis` 字段**排到结论字段之前**（JSON schema 的字段顺序影响生成顺序）。⭐ **预计 +6.8 ~ +9.2pp。**

### B · ⛔ `requirement_splitter` 的 prompt 把任务埋在中间

- system prompt **95,589 字符**，⛔ 开头是语法手册
- user prompt **末尾是 trace JSON**
- ⛔⛔ **模型生成前最后读到的不是任务**

⭐ 文献：任务放中间 vs 末尾最差差 **−88pp**；⭐ **末尾追加任务副本可恢复到 ±4pp**。

**修法**：在 user prompt **末尾追加一份任务陈述副本**。⭐ 成本近零。

## 四、⭐ 路线排序（⭐ 调查者建议，⭐ 我方同意）

> **δ（换 sound oracle）为主改动 → γ（词表自我抑制）为主发现 → β（放大 baseline 缺陷）为 discussion → α（小模型）降为 \$5 的次要 RQ**

⭐ **β 没死**：幻觉维已实测打平，⛔ 但**过度规定**（0.189 vs 0.316，⭐ **主臂少 40%**）与**可裁定性**（元素签名 2.17 vs 6.18）两维**未用尽**；⭐ 且 curl 停 bug bounty（确认率 >15% → <5%）是硬的**外部动机**。
