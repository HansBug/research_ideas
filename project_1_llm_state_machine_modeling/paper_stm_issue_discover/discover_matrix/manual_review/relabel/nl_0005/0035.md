### EIS-0035-01 ✅

**问题类型**：`element`（单元素） · `transition`（迁移） · `missing`（缺失） · `requirement`（需求文本）
- 归类依据（原文逐字）：生成侧用一个 <<initial>> 构造型代替初始伪态边，全模型没有 [*] --> 边

**问题描述**：NL 第 1 句明写『The microwave starts in the DoorShut state.』。生成侧用一个 <<initial>> 构造型代替初始伪态边，全模型没有 [*] --> 边；R4.5 因此在根状态合成 UnspecifiedInitial（attribution_exclusions 含 compiler:state:...UnspecifiedInitial 与一条 synthetic_transition），DoorShut 从上电起不可达。

- **补充证据（与本条是同一个问题）**：作者源全文 `[*]` 计数为 **0**——没有任何初始伪态边。作者改用 L2 `state DoorShut as "Door Shut" <<initial>>` 的**构造型**来表达「这是初始态」，但 `<<initial>>` 在 PlantUML 里只是视觉标注，不构成默认入口。后果：六个状态（DoorShut / DoorOpen / DoorOpenWithItem / DoorShutWithItem / ReadytoCook / Cooking）全部从根入口路径不可达——整台状态机没有起点，任何执行都无法开始。⚠️ 该族诊断的触发依赖投影插入的 `UnspecifiedInitial` 占位符，但方向是「补缺陷」而非「造缺陷」：删掉占位符后 pyfcstm 会改报 `E_INITIAL_TRANSITION_INVALID`，缺陷仍在，故判 intrinsic。修法是补一行 `[*] --> DoorShut`。
- **补充证据（与本条是同一个问题）**：八个被使用的事件（Cancel / Cooking_Time_Entered / Door_Closed / Door_Opened / Item_Placed / Item_Removed / Start / Timer_Expired）各自的**全部消费源状态都不可达**，因而消费它们的迁移永远不可能触发（itemis CREATE 的「Dead transition.
