## §A 只读材料的口径提醒

### §A.1 结构摘要锚在作者源，⛔ 不含投影合成元素

⛔ 各份工作单 §1.2 的全部数字来自**作者源 PlantUML**，⛔ 不含 `plantuml_source_lowering.py` 投影合成的 `UnspecifiedInitial` / `InvalidInitial*` / `FinalWait*` / `R45RouteToken`。谓词层的 `cardinality` 会把它们算进去，所以「作者写了 3 个子态」在谓词层可能是 4 或 7 —— 两个口径都对，但**不能混用**。

### §A.2 ⚠️ 参考模型不是正确答案

⚠️ 各份工作单 §1.4 给的参考模型来自作者 workbook 的 `STM Results!D` 列。⛔ 它**不是**正确答案 —— 语料里多处出现参考侧比生成侧更差的情形（例如 `0000` 的参考模型压根没声明 `autonomous_mode` 的状态体）。它只是「另一个人怎么建的」，用作对照，⛔ 不作为判据。

## §B §5 新增登记：三层结构与逐字段怎么填

### §B.1 三层结构（⭐ 先看这个再动笔）

⭐ 登记块按**三层**组织。三层不是三种详略，是三个**必须分开回答**的问题 —— ⛔ 把它们揉在一句话里，正是现台账出问题的地方（见下面 `basis` 一节）。

| 层 | 它问什么 | 字段 |
| :-- | :-- | :-- |
| ① 事实层 | ⭐ 你**看到了什么**（⛔ 只写现象，不下判断），在**哪一处** | `statement` · `generated_side` |
| ② 依据层 | ⛔ **凭什么**说它是缺陷 | `basis` · `nl_evidence`（+ 可选 `reference_side` · `layer`） |
| ③ 边界层 | ⛔ 它在 $M = (S, E, V, Tr, A)$ **内**吗 | `scope` |
| ④ 分类轴 | 并表统计用（⛔ 不是新的一层） | `direction` · `depth`（+ 可选 `primary_predicate`） |

| 必填 | 字段 | 一句话 | 留空的含义 |
| :-- | :-- | :-- | :-- |
| ⭐ 必填 | `statement` | ① 看到了什么、会怎样 | ⛔ 不许留空 |
| ⭐ 必填 | `generated_side` | ① 模型里哪一处（⭐ 优先写行号） | ⛔ 不许留空 |
| ⭐ 必填 · 勾选 | `basis` | ② 依据的**来源**，4 选 1 | ⛔ 不许留空 |
| ⭐ 必填 | `nl_evidence` | ② NL 段 id；NL 未明说就写 `无` | ⛔ 不许留空（⭐ 写 `无` 才算判过） |
| ⭐ 必填 · 勾选 | `scope` | ③ 界内 / 越界，4 选 1 | ⛔ 不许留空 |
| ⭐ 必填 · 勾选 | `direction` | ④ 8 类之一 | ⛔ 不许留空，归不进就选 `unclassified` |
| ⭐ 必填 · 勾选 | `depth` | ④ 表层 / 中层 / 深层 | ⛔ 不许留空 |
| ⚠️ 可选 | `reference_side` | ② 参考模型对应处 | ⭐ 留空 = 没看 / 参考侧无对应 |
| ⚠️ 可选 | `primary_predicate` | ④ 19 谓词之一 | ⭐ 留空 = 未判；写 `无` = 判过了、词表覆盖不到 |
| ⚠️ 可选 · 勾选 | `layer` | ② 台账 4 层之一 | ⭐ 留空 = 未判 |
| ⭐ 脚本推导 | `id` `pair` `group` `llm` `in_scope` `counts_as_defect` `boundary_ruling` `element_of_M` `expressible_with_closed_vocabulary` `layer_basis` `upstream` | 由 [newfields.py](./newfields.py) 的 `derive()` 算出 | ⛔ **一律不填** |
| ⭐ 合并时补 | `assertions` `assertion_count` `has_negative_control` `replay` `verdict` `homogeneity_*` `automatable` `decided_by` | 要跑断言器 / 要全库重算，本目录做不了 | ⛔ **一律不填** |

⭐ **必填 7 项里 4 项是勾选**（`basis` `scope` `direction` `depth`），真正要动笔的只有 `statement` / `generated_side` / `nl_evidence` 三项，而 `nl_evidence` 在 `basis = 模型自身` 时写一个 `无` 就够。

⭐ **勾了「越界·…」的条目只需填 ① 事实层两项 + `scope`** —— ⛔ 它不是缺陷，谈「缺陷方向」「依据强度」没有意义。[validate.py](./validate.py) 对越界条目不再要求 ② 与 ④。

⛔ **为什么不让你填 `element_of_M`**：它只是对 `generated_side` 已经点到的那一处做分类，不带新信息。台账里同一个 `direction` 会落到 3 到 5 种不同的 `element_of_M`（`guard` 方向就横跨 `Tr` / `A` / `S` / `E` / `V` 五种），手填只会引入噪声。⭐ `derive()` 改从你给的**作者源行号**反查那一行是状态声明、迁移还是状态动作 —— 那是确定性的。⭐ 所以 `generated_side` 里**带上行号**比写元素名更有用。

### §B.2 ① 事实层：`statement` 与 `generated_side`

#### `statement` ⭐ 必填

⭐ 写**你看到了什么、因此运行时会怎样**，⛔ 不是写「哪里不一样」。判据：读完这一句，另一个人能不能独立到作者源上复核它成立与否。⭐ 现有条目的写法是审阅 agent 的 `reason` 逐字，可以照那个密度写。

⛔ **这一层只写现象，⛔ 不写「凭什么」** —— 「NL 要求了 X 而模型没做」里的「NL 要求了 X」属**② 依据层**，请交给 `basis` + `nl_evidence` 去承载。⭐ 这样拆的好处很实在：同一个现象在依据被推翻后仍然成立，⛔ 而现台账把两者揉在一句话里，于是「依据够不够硬」根本无法单独复核（[README.md](./README.md) §7.2 记了 52 条 `nl_named` 全都有逐字引文、却没有任何字段记录那句引文是否说清了源状态与触发）。

⚠️ **写成一段，⛔ 不要换行**。回收器只把 `statement` / `generated_side` / `basis` / `nl_evidence` / `scope` / `direction` / `depth` / `reference_side` / `primary_predicate` / `layer` 这几个名字当作新字段起点，其余行都会并进当前字段 —— ⭐ 所以你可以在 `statement` 里放冒号、放引文，⛔ 但请别自己起一个像字段名的行。

#### `generated_side` ⭐ 必填

⭐ 指到**作者源 PlantUML 的具体一处**：优先写工作单 §1.3 的行号（写 `:12` 或 `第 12 行`），再附上那一行的元素名或原文片段。⭐ 缺失类缺陷写「（无此边）」这类否定描述也算合法 —— 台账里就有。

⛔ 带行号才能让 `derive()` 推出 `element_of_M`；只写元素名时，只有你同时填了结构族 `primary_predicate` 才推得出来。

### §B.3 ② 依据层：`basis` 与 `nl_evidence`（⚠️ 这一层最关键）

#### `basis` ⭐ 必填 · 勾选

⭐ 勾**一个**：你凭什么说工作单 §1.3 里的那个现象是缺陷。⛔ 四种依据的**强度不同**，⛔ 不许含糊过去。

| 取值 | 什么时候勾它 |
| :-- | :-- |
| `NL显式义务` | NL 里有一句**说清楚了**的义务（源状态 / 触发 / 目标 / 守卫 中该有的都有），而模型没做到。⭐ 这是最硬的 NL 依据，⛔ 必须给出段 id。 |
| `NL欠指定` | NL 里**有**相关句子，⛔ 但那句话把关键槽位空着（不写源状态 / 不写触发 / 并列项无连接词 / 无情态动词），因此它**支撑不起「模型违反了它」**。⭐ 仍然登记，⛔ 但结论只能写成「原文未规定，模型自行选择了一种读法」，⛔ 不得写成「违反」。见 [README.md](./README.md) §7.2 的七种欠指定形态。 |
| `模型自身` | ⭐ 不看 NL、不看参考模型，只读作者源就能判定（良构性）—— 如引用了未声明的元素、复合态无区域初始边、吸收态。⭐ `nl_evidence` 写 `无` 即可。 |
| `参考模型` | ⛔ **只有**参考模型那样建、生成侧没那样建。⚠️ 参考模型**不是正确答案**（§1.4 与 README §二.3），⛔ 故这一种依据**单独不足以**支撑一条缺陷；⭐ 选它等于说「本条待裁定」，请在 `statement` 里写明还缺什么才站得住。 |

⛔ **为什么要单列这一项，而不是靠 `layer` 表达**：台账的 `layer` 是按**缺陷种类**分的（缺失 / 凭空多出 / 与义务矛盾 / 良构性），却被同时当成**依据来源**的轴在用 —— ⚠️ 两者并不同构。⛔ 最直接的证据是：四层里**没有任何一个槽位**对应「依据来自参考模型」，而参考模型依据在语料里确实存在、且**不是正确答案**（见 §A.2 与 [README.md](./README.md) §二.3）。⛔ 于是这类记录只能被硬塞进四层中的某一层，塞进哪一层全看写的人怎么想 —— **依据强度就此丢失，且丢得不留痕迹**。⭐ 分开记之后，「这条依据够不够硬」才第一次成为可查询的字段。

⚠️ **`NL欠指定` 不是「弱一点的违反」，⛔ 是「不能说违反」。** 译者在 9 份 NL 上反复撞见同一形态：被引的句子把关键槽位空着 —— 不写源状态、不写触发 / 守卫、并列项无连接词、全篇零情态动词。⭐ 这种句子仍然值得登记（模型在原文沉默处自行选了一种读法，那本身可能是问题），⛔ 但结论只能写成「原文未规定」，⛔ 不能写成「模型违反了它」。七种形态的实例见 [README.md](./README.md) §7.2 的表。

⛔ [validate.py](./validate.py) 会检查这一层的自洽：勾了 `NL显式义务` / `NL欠指定` 必须给出本 pair 的段 id（否则 `E`）；`NL欠指定` 或 `参考模型` 与 `layer = nl_contradiction` 不能并存（`E`）；`模型自身` 与 `layer = nl_named` / `nl_contradiction` 不能并存（`E`）；勾了 `NL欠指定` 却在 `statement` 里写「违反」会报 `W`。

#### `nl_evidence` ⭐ 必填（⭐ 但「写 `无`」是合法答案）

⭐ 写本 pair 工作单 §1.1 那套**段 id**（同组 6 份共用一套编号，见各组的 `nl_XXXX/NL.md`），多个用逗号分隔，后面可以再跟一句逐字引文。

⛔⛔ **写 `无` 是有意义的答案，⛔ 不是偷懒** —— 它表示「NL 未明说，本条属模型内生问题」。现台账 **30 / 98** 条正是这种情况（合式性层按定义就不要求 NL 依据）。⛔ 但**留空**不等于 `无`：留空会被校验判成没填。

#### `reference_side` ⚠️ 可选

⭐ 参考模型（工作单 §1.4）里对应的那一处。⛔ **参考模型不是正确答案**（见 §A.2）—— 填它只是为了让后续复核有个对照。⭐ 留空完全可以。

## §C ③ 边界层：`scope`

⭐ 勾**一个**：这条主张成立与否，需不需要 $M = (S, E, V, Tr, A)$ **之外**的语义。

| 取值 | 判据 |
| :-- | :-- |
| `界内` | ⭐ 主张只涉及 $S$ / $E$ / $V$ / $Tr$ / $A$ —— 状态、事件、变量、迁移、动作与层次。 |
| `越界·时钟或不变式` | ⛔ 主张成立与否需要时钟变量 $C$ 或状态不变式 $Inv$：「N 秒后应当迁移」「该状态最长驻留 T」「进入时须满足某不变式」。 |
| `越界·并发或正交区` | ⛔ 主张需要并发语义：fork / join 伪状态、「两个区域是否同时活跃」、区间同步。 |
| `越界·其他` | ⚠️ 确属 $M$ 之外但不属上面两类。⛔ 请在 `statement` 里写清越在哪里 —— 这一档若堆积，说明边界定义本身需要复查。 |

⭐ **勾越界不等于白干。** 越界条目照常落盘 —— 「这份 NL 要求了 $M$ 之外的东西」本身是关于**语料**的事实，⛔ 丢掉它等于把边界问题伪装成「没人发现」。⛔ 但它**不计入缺陷统计**：`derive()` 会给它 `in_scope = False`、`counts_as_defect = False`、`boundary_ruling = out_of_scope`，[PROGRESS.md](./PROGRESS.md) 把它单列在「越界」栏而不是「新增」栏。

⛔ **判的是主张要不要那些语义，⛔ 不是文本里有没有那些词。** 一条迁移的标签恰好写着 `After (2 s)`，而你的主张是「这条边的目标不在本区域内」—— ⭐ 那是 `界内`：把时间标签整个删掉，主张照样成立。⚠️ 反过来，「两个区域应当同时活跃」即使一个关键词都不含，也是越界。⭐ [validate.py](./validate.py) 只在你勾了 `界内` 而 `statement` 命中越界词时报 `W` 提醒复核，⛔ 它不改判、不删。

## §D ④ 分类轴

### §D.1 `direction` ⭐ 必填 · 勾选

⭐ 取值就是台账 98 条 `REPORTABLE` 实际用过的 8 类，⛔ 不要造新取值。括号里是台账现有条目数 —— ⭐ **数字越小的方向越可能是台账的盲区，越值得看**。

| 取值 | 台账条数 | 指什么 |
| :-- | --: | :-- |
| `hierarchy`（层次归属） | 21 | 层次归属：谁该是谁的子态、复合括号有没有打开 |
| `reachability`（可达性与终止） | 18 | 可达性与终止：进得去 / 出得来 / 停得下 |
| `entry`（初始入口） | 18 | 入口：初始边、初始目标、进入某状态时落到哪 |
| `guard`（守卫与条件） | 17 | 守卫：条件写没写、写对没写对、能不能区分多条出边 |
| `effect_action`（效应与状态动作） | 10 | 效应与状态动作：entry / exit / 迁移效应 |
| `event`（事件与触发） | 4 | 事件：触发词缺失、拼错、被并成一个复合名 |
| `cardinality`（元素数量） | 4 | 基数：NL 点名了 N 个而模型给了 M 个 |
| `unclassified`（未归类） | 6 | 以上都归不进（⭐ 归不进本身值得在 statement 里说明） |

⚠️ 全 126 条台账里还有第 9 个取值 `pseudostate`（9 条），但它**全部落在 `00x8` 越界 pair** 上 —— 那 6 个 pair 的 fork/join 伪状态不在 $M$ 内，⛔ 故本轮不设该取值。

### §D.2 `depth` ⭐ 必填

⭐ 判据是**读懂它需要看几个地方**：一处 = 表层，两处之间的关系 = 中层，需要沿执行路径推理或跨多个状态比对 = 深层。

| 档 | 判据 | 示意（⛔ 非台账原文） |
| :-- | :-- | :-- |
| 表层 | 单点存在性 / 拼写 | 「`FinishState` 没有 `state` 声明」 |
| 中层 | 单点关系 | 「`InMotion` 有三个子态但没有区域初始边」 |
| 深层 | 跨状态推理 / 隐含冲突 / 运行时后果 | 「接管迁移只挂在一个子态上，自动模式其余每一处都把接管信号静默丢弃」 |

⛔ **台账没有 `depth` 字段** —— 它是本轮新引入的，所以上面三行是判据示意，⛔ 不是台账原文。⭐ 工作单 §2 每条下方的「⚠️ 深度存疑」只看断言形状（单存在性谓词 + 无佐证断言）机械提示，⛔ 同样不是裁决。

### §D.3 `primary_predicate` ⚠️ 可选（⭐ 写 `无` 本身就是发现）

⭐ 19 个封闭谓词里选一个能承载这条主张的。⛔⛔ **选不出来时写 `无`** —— 那说明**现有词表覆盖不到这个缺陷**，⭐ 而那正是方法重构（M1）要吸收的输入，⛔ 不是不登记的理由。现台账已有 **11 / 98** 条没有 primary 谓词。⭐ 写 `无` 时请在 `statement` 末尾补一句缺口在哪。

- **S 族**：`state_declared`、`variable_declared`、`event_declared`、`containment`、`initial_target`、`edge_declared`、`effect_declared`、`action_declared`、`guard_distinguishable`、`cardinality`
- **B 族**：`occupancy_after`、`event_consumed`、`stays_in`、`variable_delta_after`、`reaches`、`terminates`
- **P 族**：`invariant`、`response_within`、`persists_until`

⚠️ 已知谓词缺口（选谓词时留意）：`guard_distinguishable` 在单目标时空真返回 `True`；`initial_target` 看不到**带触发**的初始边；`variable_declared` 对投影的 `R45RouteToken` 按设计返回 `False`；「无事件、以 in-state 为守卫」的迁移形状**没有承载谓词**。

### §D.4 `layer` ⚠️ 可选

| 取值 | 台账条数 | 判据（⭐ 台账 `layer_basis` 原话） |
| :-- | --: | :-- |
| `wellformedness` | 27 | 模型自身即可判定，不需要 NL 也不需要参考模型 |
| `nl_named` | 52 | NL 点名了那个缺失或错位的元素 |
| `over_specification` | 6 | 生成方凭空多出，且造成可断言的负面后果 |
| `nl_contradiction` | 13 | 与 NL 的显式义务矛盾 |

⛔ 若你勾了 `wellformedness` 之外的任何一层，`nl_evidence` 就**不能**是 `无` —— 那三层按定义都要求 NL 逐字依据。[validate.py](./validate.py) 会把这种组合报成 `E`。

⚠️ **`layer` 与上面的 `basis` 不是同一个轴，⛔ 不要只填一个。** `basis` 说依据**来自哪里**（4 种来源），`layer` 是台账既有的分层，留着只为让新条目能与既有 98 条并表。⛔ 台账四层里**没有**「参考模型依据」的槽位 —— ⭐ 这正是本轮把 `basis` 单列出来的原因。已知对应关系：

- `模型自身` → ⭐ 通常落 `wellformedness`（模型自身即可判定，不需要 NL 也不需要参考模型）；⭐ 若主张的是「生成方凭空多出一个元素、且造成可断言的负面后果」，则落 `over_specification` —— ⭐ 那一层同样**不要求** NL 依据，`nl_evidence` 照写 `无`
- `NL显式义务` → ⭐ 视主张形态落 `nl_named`（NL 点名了那个缺失或错位的元素）或 `nl_contradiction`（与 NL 的显式义务矛盾）
- `NL欠指定` → ⛔ **不得**落 `nl_contradiction` —— 欠指定的句子不构成显式义务，谈不上与它矛盾
- `参考模型` → ⛔ 台账四层**没有**「参考模型依据」这一层 —— ⚠️ 这类记录只能被硬塞进某一层，依据强度就此丢失。⭐ 建议把 `layer` 留空（等于「本条待裁定」），⛔ 尤其**不得**记成 `nl_contradiction`：参考模型不是 NL

## §E §2 / §3 / §4 的通用读法

### §E.1 §2 现有 expected issue 逐条裁决

⛔ 裁决区留空由你填；自动风险标记只是**提示**，打了标记不等于该条不成立，没打标记也不等于它成立。

⭐ 若某份工作单的 §2 是 **0 条**，⛔ 那不等于「本 pair 没问题」—— 60 个 pair 里台账只覆盖 48 个，且覆盖了的也未必覆盖全。请直接从该份的 §3 与 §4 开始，把发现登记到 §5。

### §E.2 §3 候选新增 issue 的五个来源

本节把**已知但未入账**的线索集中在一处。⛔ 它们都没有经过人工确认，列在那里只是因为「有人说过这件事而台账没记」。裁决区留空。

| 小节 | 来源 | 优先级 |
| :-- | :-- | :-- |
| §3.1 | 两臂多报侧判为 `VALID_UNRECORDED` 的「真漏记」 | ⭐ 最高 —— 已过一轮独立复核，事实部分通常可直接采信 |
| §3.2a | 审阅 agent 判为 `problem` / `extra` / `uncertain` 却没进台账的 diff | ⭐ 高 |
| §3.2b | 判为 `correct` / `similar` 的 diff | 备查，不设裁决区 |
| §3.3 | 两臂产出中机械未匹配任何台账条目的 issue | ⭐ 中 —— 量大，按出现格数排序 |
| §3.4 | 已被判为「非缺陷」的多报簇 | 备查 —— 避免与既有裁定撞车 |
| §3.5 | 与台账同根、但匹配器未归并的簇 | ⭐ **「台账偏浅」的直接证据** —— 对应条目适合走「修正」 |

⚠️ **§3.2 的已知证据缺口**：当年**没有单独记录「为什么不收」**，只留下了该 diff 被判成什么。所以「排除理由」给的是它的 `verdict` 与判定者写的 `reason`，⛔ 不是一条真正的排除论证。

| 判定 | 怎么读 |
| :-- | :-- |
| `problem` | ⭐ 判定者当年**判为 problem**，却仍未进台账 —— 最值得优先看的一类。 |
| `extra` | ⭐ 判为 `extra`（生成方凭空新增）。⛔ 台账的 8 类分类学**没有 `extra` 的槽位**，整类 31 条 / 20% 被结构性漏掉（见 `docs/protocol/ground_truth_limitations.md` §3）。 |
| `uncertain` | ⚠️ 判为 `uncertain`（当年未决）。 |
| `correct` | 判为 `correct`（生成方在该点上正确）。 |
| `similar` | 判为 `similar`（与参考侧等价）。 |

⭐ §3.2b 的 `correct` / `similar` 列在工作单里是为了**自包含**：若你在 §4 发现某处确有问题，可以先查它是不是已经被人看过并判过没问题。要推翻的话，直接在 §5 登记新条目。

⭐ §3.3 的 X1 侧**全部已有多报侧裁定**（已归入 X1 的多报桶并给了 verdict）。⛔ 那些裁定是**另一轮**判定者做的，你可以推翻 —— 尤其 `NO_NL_BASIS`：它只说「NL 没有逐字依据」，⭐ 而合式性层的缺陷本来就不要求 NL 依据（台账自己有 30 条这样的记录）。⭐ **出现格数越多越值得看** —— 六格里出现五六次的主张，不太可能是单次采样噪声。

⛔ §3.3 的**主臂多报簇没有逐条回链到格**（`G*.jsonl` 只给 `cells_of_6` 计数、不给成员清单），所以那一栏**无法**标出哪些已被裁定 —— 需自行对照同一份工作单的 §3.4。⚠️ 全语料有 **102 条**主臂未匹配 issue 落在 6 个 pair（`0005` `0015` `0025` `0035` `0042` `0045`）上却**零多报簇**，即那 6 个 pair 的这一栏完全没有被裁定过。

⭐ §3.4 列的是两臂报过、但复核判为不成立的主张。⛔ 它们**不是**候选 —— 列出来是为了让你在 §4 发现同一形状时，能立刻看到「这条已经被判过，理由是这个」，避免重复劳动或与既有裁定冲突。

⭐ §3.5 这类最能说明问题：**同一个缺陷**，两臂用了另一种谓词或另一种措辞表述，台账那一条就没能覆盖。⛔ 它们不算新增缺陷，但**它们说明台账那一条的 statement 写窄了** —— 对应的台账条目适合走「修正」而不是「保留」。

### §E.3 §4 深度检查清单

⛔ 清单里的每一条都是**待核问句**，不是结论。机械判据写在每条下方，判错了就直接在「发现」里写「机械判错，理由 X」。⭐ 勾选 `[x]` 表示**已看过**；「发现:」留空表示看过但无发现。

⛔ **不在范围内的，一律不许记**：时钟 / 计时 / 秒级约束、不变式、正交区并发（fork/join、区域同时活跃）。project_1 的建模对象是 $M = (S, E, V, Tr, A)$，没有 $C$、没有 $Inv$、没有区分量。
