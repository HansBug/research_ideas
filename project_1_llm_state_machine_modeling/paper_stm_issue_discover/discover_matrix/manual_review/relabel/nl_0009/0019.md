**statement 原文**

> NL 3 虽然把 cruise 与 lane_change 写在同一个条件从句下（本身歧义），但两个目标互斥，模型必须给出可区分依据。生成侧对两个不同目标使用逐字相同的条件，FCSTM 投影中它们共享同一个 event dist_to_front_25_extra_lane_true 且均无守卫，形成不可区分的冲突目标。参考侧靠 cruise 无守卫消歧，0009/0049 靠互补守卫消歧，只有 0019 与 0029 没有消歧。

票面 `D1+D1+D0`：codex `D0` / claude `D1` / dsh `D1`。

- 第二种读法（claude 原话）：NL 3 本身就把 cruise 与 lane_change 写在同一条件从句之下（"can transition to cruise or lane_change based on the distance to the front vehicle (`dist_to_front<25`) and the availability of an extra lane (`extra_lane=true`)"），未给出任何区分依据；:12/:13 是对这句的逐字转写，非确定性是需求歧义的继承而非模型引入。而 UML 对同源冲突迁移的选择正是留白项：优先级规则只处理源处于不同层深的情形，同源冲突的选择属语义变体点。因此在两个同样合法的机动之间留一个非确定选择、把决策委托给下层规划器，是建模语言允许的抽象；「模型在此必须给出可区分依据」这条推理规则并不必然成立。
