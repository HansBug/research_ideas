### §5.2 逐字段怎么填

#### `statement` ⭐ 必填（① 事实层）

⭐ 写**你看到了什么、因此运行时会怎样**，⛔ 不是写「哪里不一样」。判据：读完这一句，另一个人能不能独立到作者源上复核它成立与否。⭐ 现有条目的写法是审阅 agent 的 `reason` 逐字，可以照那个密度写。

⛔ **这一层只写现象，⛔ 不写「凭什么」** —— 「NL 要求了 X 而模型没做」里的「NL 要求了 X」属**② 依据层**，请交给 `basis` + `nl_evidence` 去承载。⭐ 这样拆的好处很实在：同一个现象在依据被推翻后仍然成立，⛔ 而现台账把两者揉在一句话里，于是「依据够不够硬」根本无法单独复核（[README.md](./README.md) §7.2 记了 52 条 `nl_named` 全都有逐字引文、却没有任何字段记录那句引文是否说清了源状态与触发）。

真实样例（`EIS-0040-01`，`hierarchy` / `nl_contradiction`）：

> 自动驾驶激活期间无法断电，NL 第5句断电义务只覆盖一半作用域（参考两边都有）。

⚠️ **写成一段，⛔ 不要换行**。回收器只把 `statement` / `generated_side` / `basis` / `nl_evidence` / `scope` / `direction` / `depth` / `reference_side` / `primary_predicate` / `layer` 这几个名字当作新字段起点，其余行都会并进当前字段 —— ⭐ 所以你可以在 `statement` 里放冒号、放引文，⛔ 但请别自己起一个像字段名的行。

#### `generated_side` ⭐ 必填

⭐ 指到**作者源 PlantUML 的具体一处**：优先写 §1.3 的行号（写 `:12` 或 `第 12 行`），再附上那一行的元素名或原文片段。⭐ 缺失类缺陷写「（无此边）」这类否定描述也算合法 —— 台账里就有。

真实样例（`EIS-0042-01`）：`[*] --> Off : keyOff`

⛔ 带行号才能让 `derive()` 推出 `element_of_M`；只写元素名时，只有你同时填了结构族 `primary_predicate` 才推得出来。

#### `basis` ⭐ 必填 · 勾选（② 依据层 —— ⚠️ 这一层最关键）

⭐ 勾**一个**：你凭什么说 §1.3 里的那个现象是缺陷。⛔ 四种依据的**强度不同**，⛔ 不许含糊过去。

| 取值 | 什么时候勾它 |
| :-- | :-- |
| `NL显式义务` | NL 里有一句**说清楚了**的义务（源状态 / 触发 / 目标 / 守卫 中该有的都有），而模型没做到。⭐ 这是最硬的 NL 依据，⛔ 必须给出段 id。 |
| `NL欠指定` | NL 里**有**相关句子，⛔ 但那句话把关键槽位空着（不写源状态 / 不写触发 / 并列项无连接词 / 无情态动词），因此它**支撑不起「模型违反了它」**。⭐ 仍然登记，⛔ 但结论只能写成「原文未规定，模型自行选择了一种读法」，⛔ 不得写成「违反」。见 [README.md](./README.md) §7.2 的七种欠指定形态。 |
| `模型自身` | ⭐ 不看 NL、不看参考模型，只读作者源就能判定（良构性）—— 如引用了未声明的元素、复合态无区域初始边、吸收态。⭐ `nl_evidence` 写 `无` 即可。 |
| `参考模型` | ⛔ **只有**参考模型那样建、生成侧没那样建。⚠️ 参考模型**不是正确答案**（§1.4 与 README §二.3），⛔ 故这一种依据**单独不足以**支撑一条缺陷；⭐ 选它等于说「本条待裁定」，请在 `statement` 里写明还缺什么才站得住。 |

⛔ **为什么要单列这一项，而不是靠 `layer` 表达**：台账的 `layer` 是按**缺陷种类**分的（缺失 / 凭空多出 / 与义务矛盾 / 良构性），却被同时当成**依据来源**的轴在用 —— ⚠️ 两者并不同构。⛔ 最直接的证据是：四层里**没有任何一个槽位**对应「依据来自参考模型」，而参考模型依据在语料里确实存在、且**不是正确答案**（见 §1.4 与 [README.md](./README.md) §二.3）。⛔ 于是这类记录只能被硬塞进四层中的某一层，塞进哪一层全看写的人怎么想 —— **依据强度就此丢失，且丢得不留痕迹**。⭐ 分开记之后，「这条依据够不够硬」才第一次成为可查询的字段。

⚠️ **`NL欠指定` 不是「弱一点的违反」，⛔ 是「不能说违反」。** 译者在 9 份 NL 上反复撞见同一形态：被引的句子把关键槽位空着 —— 不写源状态、不写触发 / 守卫、并列项无连接词、全篇零情态动词。⭐ 这种句子仍然值得登记（模型在原文沉默处自行选了一种读法，那本身可能是问题），⛔ 但结论只能写成「原文未规定」，⛔ 不能写成「模型违反了它」。七种形态的实例见 [README.md](./README.md) §7.2 的表。

⛔ [validate.py](./validate.py) 会检查这一层的自洽：勾了 `NL显式义务` / `NL欠指定` 必须给出本 pair 的段 id（否则 `E`）；`NL欠指定` 或 `参考模型` 与 `layer = nl_contradiction` 不能并存（`E`）；`模型自身` 与 `layer = nl_named` / `nl_contradiction` 不能并存（`E`）；勾了 `NL欠指定` 却在 `statement` 里写「违反」会报 `W`。

#### `scope` ⭐ 必填 · 勾选（③ 边界层）

⭐ 勾**一个**：这条主张成立与否，需不需要 $M = (S, E, V, Tr, A)$ **之外**的语义。

| 取值 | 判据 |
| :-- | :-- |
| `界内` | ⭐ 主张只涉及 $S$ / $E$ / $V$ / $Tr$ / $A$ —— 状态、事件、变量、迁移、动作与层次。 |
| `越界·时钟或不变式` | ⛔ 主张成立与否需要时钟变量 $C$ 或状态不变式 $Inv$：「N 秒后应当迁移」「该状态最长驻留 T」「进入时须满足某不变式」。 |
| `越界·并发或正交区` | ⛔ 主张需要并发语义：fork / join 伪状态、「两个区域是否同时活跃」、区间同步。 |
| `越界·其他` | ⚠️ 确属 $M$ 之外但不属上面两类。⛔ 请在 `statement` 里写清越在哪里 —— 这一档若堆积，说明边界定义本身需要复查。 |

⭐ **勾越界不等于白干。** 越界条目照常落盘 —— 「这份 NL 要求了 $M$ 之外的东西」本身是关于**语料**的事实，⛔ 丢掉它等于把边界问题伪装成「没人发现」。⛔ 但它**不计入缺陷统计**：`derive()` 会给它 `in_scope = False`、`counts_as_defect = False`、`boundary_ruling = out_of_scope`，[PROGRESS.md](./PROGRESS.md) 把它单列在「越界」栏而不是「新增」栏。

⛔ **判的是主张要不要那些语义，⛔ 不是文本里有没有那些词。** 一条迁移的标签恰好写着 `After (2 s)`，而你的主张是「这条边的目标不在本区域内」—— ⭐ 那是 `界内`：把时间标签整个删掉，主张照样成立。⚠️ 反过来，「两个区域应当同时活跃」即使一个关键词都不含，也是越界。⭐ [validate.py](./validate.py) 只在你勾了 `界内` 而 `statement` 命中越界词时报 `W` 提醒复核，⛔ 它不改判、不删。

- `模型自身` → ⭐ 通常落 `wellformedness`（模型自身即可判定，不需要 NL 也不需要参考模型）；⭐ 若主张的是「生成方凭空多出一个元素、且造成可断言的负面后果」，则落 `over_specification` —— ⭐ 那一层同样**不要求** NL 依据，`nl_evidence` 照写 `无`
- `NL显式义务` → ⭐ 视主张形态落 `nl_named`（NL 点名了那个缺失或错位的元素）或 `nl_contradiction`（与 NL 的显式义务矛盾）
- `NL欠指定` → ⛔ **不得**落 `nl_contradiction` —— 欠指定的句子不构成显式义务，谈不上与它矛盾
- `参考模型` → ⛔ 台账四层**没有**「参考模型依据」这一层 —— ⚠️ 这类记录只能被硬塞进某一层，依据强度就此丢失。⭐ 建议把 `layer` 留空（等于「本条待裁定」），⛔ 尤其**不得**记成 `nl_contradiction`：参考模型不是 NL
