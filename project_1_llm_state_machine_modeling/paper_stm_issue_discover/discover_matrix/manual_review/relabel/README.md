# 人工全量重标工作区

54 份逐 pair 的工作单（按 NL 组分在 9 个 `nl_XXXX/` 子目录里，见 §3.0）+ 生成 / 回收 / 校验工具。目标是让作者**逐 pair 人工裁决**三件事：现有 expected issue 是否成立、是否偏浅、以及台账遗漏了什么。

**本目录不修改台账。** [expected_issue_set.json](../expected_issue_set.json) 保持冻结 —— 它是 v46 与 X1 两轮判定所依据的 ground truth，事后改它比改结果更严重。重标产物只落在本目录内；合并回台账是另一件事，需要单独的裁定与 PR。

## 一、为什么要重标

现有台账 98 条 `REPORTABLE`（原 126 条，扣 `00x8` 越界 27 条与 `EIS-0043-02` 的逐条边界裁定）的来路是这样的：

| 项 | 现状 |
| :-- | :-- |
| 生成者 | **5 个 LLM agent**（`<pair>-review.json` → `final_stratification.json` → `expected_issue_set.json`） |
| 人类校验 | **0 条** |
| 双盲复审 | 仅 12/60 = 20%，$\kappa = 0.750$，且是**二元 case 级** |
| 只过正则从未二读 | **23 / 98**（`decided_by = lexical`；全 126 条口径下是 32 条） |
| 证据读了 fcstm 投影 | **51 / 98** |
| 时序 | 台账 07-31，**晚于**方法产出 07-27 |
| 谓词覆盖 | 只用到 15/19；`variable_declared` / `variable_delta_after` / `response_within` / `invariant` **从未作为 primary**；**11 条无 primary 谓词** |

**核心怀疑：现有 expected issue 可能偏浅。** 文献也指出自动生成的断言容易偏浅。若能挖出更深的问题，那**不一定是坏事** —— 它可能成为方法的新增长点。

支持这个怀疑的两组既有数字：X1 朴素基线有 **13 条真漏记**（台账没记但确实成立），主臂只有 2 条；主臂**完全漏掉**而 X1 命中的台账条目有 **22 条**，反向只有 3 条。

## 二、三条硬边界（动手前先读）

### 1. 建模对象是 $M = (S, E, V, Tr, A)$

**无时钟变量 $C$、无不变式 $Inv$、无正交区并发。** 这是 [CLAUDE.md](../../../../../CLAUDE.md) 定死的 project_1 边界，不是本次可以放宽的口径。

具体到重标：

- **不许记**：fork / join 伪状态、「两个区域是否同时活跃」、秒级 / 毫秒时间约束、计时器、不变式。
- **仍要记**：NL 说「持续到 X 才离开」「先 A 后 B」这类**次序与保持**义务在模型上有没有**结构性**承载（缺边、守卫、层次）。那不需要时钟。
- 元素**名字**恰好叫 `fork` / `Timer` 的，仍在范围内 —— 判的是主张需不需要并发 / 时钟语义，不是名字。

越界的东西**照样登记**，只是不计入缺陷统计。⚠️ **但 2026-08-13 起，判读者不再负责标记它。**

旧形态是 §5 有一个「③ 边界层」字段 `scope`（`界内` / `越界·时钟或不变式` / `越界·并发或正交区` / `越界·其他`），由判读者四选一。这一轮把它删掉了，改成：**界外的发现照常写进 `statement` 自由文本，回收后由主 session 从自由文本人工分拣。**

理由是分工：判读者判**「这是不是缺陷」**，不判**「它属于我们框架的哪一格」**。后者要求他先掌握 project_1 的建模对象边界、还要能区分「主张需要时钟语义」与「文本里恰好出现了时间词」—— 那是一次协议层判断，判错的代价（把界内的东西勾成越界，于是它退出缺陷统计）比不判更大。而分拣本身并不着急：它可以在回收之后一次做完，那时主 session 手里有全部 54 份的文本，口径也统一。

配套后果，逐条写清楚以免以为丢了东西：

- `derive()` 不再产出 `in_scope` / `counts_as_defect` / `boundary_ruling`，三项进 `pending`，注明「回收后由主 session 从自由文本人工分拣」。
- [PROGRESS.md](./PROGRESS.md) 去掉「越界」栏，「新增」栏改成不分界内界外的登记总数。
- [validate.py](./validate.py) 去掉那道「勾了 `界内` 而 `statement` 命中时钟 / 并发词就报 `W`」的词法补网 —— 没有 `scope` 可比对了，而单纯提醒「这句话里有时间词」会把判读者又推回去做分类。
- 界外的东西**仍然必须写下来**。「这份 NL 要求了 $M$ 之外的东西」是关于**语料**的事实，丢掉它等于把边界问题伪装成「没人发现」。

### 2. `00x8` 六个 pair 永久排除

`0008` `0018` `0028` `0038` `0048` `0058` 的 NL 要求 fork/join 与秒级时间约束，忠实模型在 $M$ 中无法表示。它们**不生成工作单、不进网格、不进分母**，见 [nl_scope_rule.md](../../docs/protocol/nl_scope_rule.md)。

这与「不设 hold-out」是**两件事**，不得混谈：前者说的是有些**规约**本就不是本方法要建模的对象，后者说的是**不许因样本表现改分母**。把后者套到前者上，会得出「排除 `00x8` = 剔除不利样本」这个错误结论 —— 事实相反，被排除集里 `0018` 的 `hit@1` 高于全量均值。

### 3. 判断锚在**作者源**，不锚在投影

工作单 §1.2 给的 PlantUML 是被测的作者源。`plantuml_source_lowering.py` 的投影会合成 `UnspecifiedInitial` / `InvalidInitial*` / `FinalWait*` / `R45RouteToken` —— **作者从没写过这些**。

这不等于「读了投影的条目就无效」：缺陷在转换阶段暴露、中间表示如实反映、断言据此报出，**是方法按设计工作**，主张没有越界。但重标时必须能回答一句：**「这条主张在作者源上怎么表述？」** 答不上来的，就是被投影带偏了。

附带一个已登记的事实缺口：台账多条 statement 把某些诊断归给了 pyfcstm，实际那是本仓库自己的表示层做的（见 [ground_truth_limitations.md](../../docs/protocol/ground_truth_limitations.md) §5）。⚠️ 看到「pyfcstm 报了 X」的措辞，不要照抄。

## 三、怎么用

### 3.0 目录布局：一个 NL 一个 subdir

工作单按 **NL 组**分在 9 个子目录里，目的就是让你**一次处理完同一份 NL 的 6 个模型**：

```text
relabel/
├── HOWTO.md            ← 填写说明（54 份共用，与具体 pair 无关）
├── PROGRESS.md         ← 进度看板（带「NL 组」栏，按它排着做）
├── nl_0000/
│   ├── NL.md           ← 该 NL 的原文 + 中文严格翻译 + 逐段判读提示 + 整份观察（6 份共用）
│   ├── 0000.md         ← 工作单（唯一有填写区的文件）
│   └── 0010.md 0020.md 0030.md 0040.md 0050.md
└── nl_0001/ … nl_0009/  ← 共 9 组 × 6 = 54
```

⚠️ **分组判据是 NL 全文的 sha8，不是 pair id 的末位数字。** 两者在 8 组上恰好一致，在剩下两组上**交叉**：

| 目录 | 6 个 pair | 注意 |
| :-- | :-- | :-- |
| [nl_0002/](./nl_0002/) | `0002` `0013` `0023` `0033` `0043` `0053` | 含 `0013`，不含 `0012` |
| [nl_0003/](./nl_0003/) | `0003` `0012` `0022` `0032` `0042` `0052` | 含 `0012`，不含 `0013` |

若按末位数字分目录，`nl_0002/` 里会同时坐着两份**不同**的 NL，而该目录的 `NL.md` 只能对其中一半为真 —— 那正好复刻 §十 记的那起事故。判据由 [sources.py](./sources.py) 的 `_nl_dir_index()` 实现、由 `test_nl_grouping_follows_the_nl_text_not_the_last_digit` 钉住。

目录名取该组**最小的 pair id**，与 [translations/](./translations/) 下的译文 JSON 文件名一一对应（`nl_0002/` ↔ `translations/nl_0002.json`）。

### 3.1 一份工作单长什么样

开工要读**三份**：同目录的 `NL.md`（NL 侧材料，6 份共用）、根上的 [HOWTO.md](./HOWTO.md)（怎么填，54 份共用）、以及 `nl_XXXX/<pair>.md`（制品侧材料 + 唯一的填写区）。

| 节 | 内容 | 要不要填 |
| :-- | :-- | :-- |
| （开头） | 怎么填：8 条**回收判据**（勾选记号 / 取值在框后 / 单选 / 续行 / §4 清单 / §5 标题 / 留空 vs `无`） | 只读 |
| §0 | 本 pair 结论 | 做完再填 |
| §1 | 原料：§1.1 NL 原文与中文严格翻译（第一屏）/ §1.2 作者源 PlantUML（行号）/ §1.3 参考模型 PlantUML | 只读 |
| §2 | 现有 expected issue 逐条：`statement` 原文 + 参考侧 / 生成侧证据行 + 我方座标映射 + 自动风险标记 | 逐条裁决 |
| §3 | 候选新增 issue（五个来源，见下） | 逐条裁决 |
| §4 | 深度检查清单（逐 pair 点名真实元素） | 逐条勾选 + 写发现 |
| §5 | 新增 issue 登记（§5.1 真实样例 + §5.2 条件式座标系 + 登记块，见 §3.5 与 [HOWTO.md](./HOWTO.md) §B） | 按需填 |
| §9 | 孤儿填写区（材料变动时才出现） | 并回正文后删掉 |

⚠️ **只有 `<!-- FILL:BEGIN -->` 与 `<!-- FILL:END -->` 之间的内容是给人填的。** 其余部分重跑生成器会被覆盖。填写用 `~~~` 围栏包着，所以你可以在理由里自由粘贴 ``` 代码块。`HOWTO.md` 与 `NL.md` **没有**填写区 —— 填在那里的东西 [collect.py](./collect.py) 收不上来，且不会报错（由 `test_shared_pages_carry_no_fill_blocks` 钉住）。

### 3.2 §3 的五个候选来源

| 小节 | 来源 | 优先级 |
| :-- | :-- | :-- |
| §3.1 | 两臂多报侧判为 `VALID_UNRECORDED` 的「真漏记」 | 最高 —— 已过一轮独立复核 |
| §3.2a | 审阅 agent 判为 `problem` / `extra` / `uncertain` 却没进台账的 diff | 高 |
| §3.2a-2 | 上述 diff 里**生成侧写「—」或「不可能生成」**的 12 条 | 另一个物种，见 [HOWTO.md](./HOWTO.md) §D.2 |
| §3.2b | 判为 `correct` / `similar` 的 diff | 备查，不设裁决区 |
| §3.3 | 两臂产出中机械未匹配任何台账条目的 issue | 中 —— 量大，按出现格数排序 |
| §3.4 | 已被判为「非缺陷」的多报簇 | 备查 —— 避免与既有裁定撞车 |
| §3.5 | 与台账同根、但匹配器未归并的簇 | **「台账偏浅」的直接证据** —— 对应条目适合走「修正」 |

**§3.2 的一个已知证据缺口**：当年**没有单独记录「为什么不收」**，只留下了该 diff 被判成什么。所以「排除理由」给的是它的 `verdict` 与判定者理由，不是一条真正的排除论证。

### 3.3 §4 清单怎么读

每条都是**待核问句**，不是结论；机械判据写在下一行。判错了就在「发现:」里写「机械判错，理由 X」—— 那本身就是有用的记录。勾 `[x]` 表示**看过了**，「发现:」留空表示看过但无发现。

清单按八类组织，每类的标题下写着**台账在这一维有多空**，例如：`event` 方向全库只有 4 条、`variable_declared` 与 `variable_delta_after` 从未作为 primary、`response_within` / `invariant` 同样从未出现。越空的维度越值得挖。

### 3.4 什么该记、什么不该记

**该记**：

1. 在**作者源**上成立、且与 §2 已有条目不是同一缺陷的任何缺陷。
2. 现有条目**说浅了**的 —— 走「修正」并写出更强的 statement，不要新开一条。
3. 现有条目**说错了**的 —— 走「删除」并写明理由。台账错了就是错了，这正是重标的目的。
4. 座标系里**归不进**的缺陷 —— 落 `other` 并在 `statement` 里写清它是什么形状。**座标系覆盖不到本身就是发现**：它正是「我们的框架说不出什么」的直接证据（已知的一处缺口见 §3.5.2）。
5. 需要时钟 / 不变式 / 并发语义才成立的发现 —— 照常写进 `statement`，**不必**自己判它在不在 $M$ 内（§二.1）。

**不该记**：

1. 只在投影上成立的（§二.3）。
2. 与 §2 已有条目同根的 —— 走「并入现有条目」。
3. 「模型没用 submachine 语法 / 没加方括号」这类**记法形态**主张 —— $M$ 里没有「子机引用」与「守卫槽位」的区分量。但若形态错误**导致**了语义后果（例如守卫写进 trigger 槽使该边永不触发），那记的是**后果**，在范围内。

### 3.5 §5 新增区怎么填：一条登记回答三件事

**动手时看 [HOWTO.md](./HOWTO.md) §B**（操作版，由 [generate.py](./generate.py) 从 [newfields.py](./newfields.py) 的枚举现算，枚举一改它就跟着改），逐取值的判定测试则内联在**每份工作单**的 §5.2 —— 填表不必翻文件。本节是读者版：讲这套字段为什么长这样、以及一个从头填到尾的例子。

| 项 | 字段 | 形态 |
| :-- | :-- | :-- |
| ① 它是哪一类错 | `defect_locus` + 分支轴 + `defect_reference` | 可枚举，勾选 |
| ② 错在哪、错成什么样 | `statement` | 自由文本 |
| ③ 修好之后怎样才算 ok | `expected_after_fix` | 自由文本 |

① 是一套**条件式座标系**：先答 `defect_locus`（定位范围，4 选 1），它决定后面问哪些轴。

| 轴 | 字段 | 何时问 | 取值 |
| :-- | :-- | :-- | --: |
| 0 · 定位范围 | `defect_locus` | 总是 | 4 |
| A · 构件 | `defect_element` | 仅 `element` 支 | 7 |
| B · 限定词 | `defect_qualifier` | 仅 `element` 支 | 4 |
| D · 逻辑类型 | `defect_logic_kind` | 仅非 `element` 支 | 9 |
| C · 参照物 | `defect_reference` | 总是 | 3 |
| E · 性质模式 | （不设字段，作为 ③ 的句式骨架） | 可选 | 8 × 5 |

必填轴合计 27 个取值，**但任何一条记录只回答三到四个问题**：走 `element` 支是 locus → A → B → C，候选面 4+7+4+3 = 18；走逻辑支是 locus → D → C，候选面 4+9+3 = 16。判读者面对的从来不是 27 个选项，而是一次 4 选 1 加两三次不超过 9 选 1，每步一句机械判据。

`nl_evidence` 照旧必填（NL 未明说就写 `无`）；`property_pattern` 可留空。

#### 3.5.1 为什么换掉旧的三层字段表

旧形态是「① 事实层 / ② 依据层 / ③ 边界层 / ④ 分类轴」十个字段：`statement` · `generated_side` · `basis` · `nl_evidence` · `scope` · `direction` · `depth` · `reference_side` · `primary_predicate` · `layer`。**它不是从未存在过，也不是白做的** —— 依据强度（`basis`）与边界（`scope`）这两件事此前确实无处记录，那一版把它们变成了可查询的字段。

换掉它的理由只有一条，但这一条是致命的：**那张表把本轮工作的目的抵消掉了。**

本轮要回答的是「现有台账是不是偏浅，**有没有漏掉我们框架表达不了的缺陷**」。而旧表的分类轴全部来自我们自己的框架：

| 旧字段 | 取值从哪来 | 后果 |
| :-- | :-- | :-- |
| `direction` | 明写是「台账 98 条 `REPORTABLE` **实际用过**的 8 类」 | 没被用过的类**不在选项里** |
| `layer` | 台账自己的四层 | 同上；且它同时被当成「缺陷种类」与「依据来源」两个轴在用 |
| `primary_predicate` | 我们自己的 19 条封闭谓词 | 逼判读者按框架的词表归类 |
| `depth` | 本目录自造的三分，台账根本没有这个字段 | 判据「读懂它需要看几个地方」要人做语义判断，却被摆成必填勾选行 |
| `basis` | 本目录自造的四种依据来源 | 与 `defect_reference` 重合，而后者有文献出处 |
| `scope` | 本目录自造的界内 / 越界三档 | 把一次协议层判断压给判读者（§二.1） |

于是判读者**能选出来的类型，按构造就等于框架已经能说的东西** —— 问题本身被答案定义掉了。用这套字段复核台账内部一致性没问题；用它发现台账的盲区则不可能。

新座标系的每一个取值都挂着一条**可查证的外部依据**：Chow 1978 的 FSM 故障模型（构件 × 编辑操作的雏形）· Lackner & Schmidt 2015 的模型变异算子（deletion / insertion / property change 三分与一阶约束）· ODC 的 `Qualifier`（missing / incorrect / extraneous）· Heimdahl & Leveson 1996 的不确定性与不完备判据（可手算）· Baier & Katoen 的可达状态与终止状态定义 · UML 2.5.1 的迁移优先级与默认进入条款 · Dwyer 等 1999 的性质规约模式。逐条出处、每条的核验档位、以及**明确没有取到双全支撑的那几条**，全部记在 [defect_taxonomy.md](../../docs/protocol/defect_taxonomy.md)。

⚠️ 旧 `direction` 与新的 `defect_element` / `defect_logic_kind` 语义有重叠但取值不同，本轮**直接删除、不做映射**：旧值是自家词表，新值有文献出处，混用会污染出处链。台账既有条目仍带着它们自己的 `layer` / `direction`（渲染在 §2 的字段表里）—— 那是**台账的**字段，读它是为了裁决那一条，不是让判读者照它归类。

#### 3.5.2 已知缺口：entry / exit 动作次序表达不了

座标系有一处**明确的表达缺口**，工作单 §5.2 的取值表旁边就写着，免得判读者以为是自己选错了：

**entry / exit 动作的执行次序**没有取值。UML 与经典 statechart 对跨层次迁移的 exit / entry 次序都有成文规定，但两家不完全一致，而一份 PlantUML 制品并不声明它遵循哪一套 —— 判「次序错了」要先有一个语义裁定，那是协议层的事，不是判读者对着制品能解决的。硬设一个取值只会造出两人选法不一致的字段。

它落 `defect_locus = pair` + `defect_logic_kind = other` + 在 `statement` 里写清。若后续协议层裁定了采用哪套语义，这一条可以升格为正式取值。

⚠️ 另一处**不是**缺口、却容易被误当成缺口的：**非确定性（`nondeterminism`）与不完备性（`incompleteness`）不是并发问题**。它们定义在「同一状态、同一事件的一组出边守卫」上，完全落在 $M = (S, E, V, Tr, A)$ 界内，是 `defect_logic_kind` 的正当取值 —— 不要按「无正交区」的边界规则把它们排除掉。

#### 3.5.3 一个填好的完整例子

⚠️ **以下是示例，不是判读结果。** 它写在 README 里，不在任何工作单的 `FILL` 块内，因此 [collect.py](./collect.py) **不会**回收它 —— 该脚本只读 54 份 `nl_XXXX/<pair>.md` 的填写块。

例子特意用 **`0008`**：它是[永久排除](../../docs/protocol/nl_scope_rule.md)的越界 pair，**不生成工作单、不进网格、不进分母**，所以没有任何人会去重标它。这样既能用**真实的 pair、真实的作者源行号、真实的 NL 段 id**，又不会把答案先告诉任何一份工作单的判读者 —— 与 §5 样例「避开本 pair 所属 NL 组」是同一条纪律。

`0008` 的作者源前 10 行（真实内容）：

```text
  1 | @startuml
  2 | [*] --> TurnOn
  3 |
  4 | state TurnOn {
  5 | [*] --> fork1: After (2 s)
  6 | }
  7 |
  8 | TurnOn --> fork1
  9 | fork1 -down-> AutoFocus
 10 | fork1 -right-> DetLight
```

走 **element 支**的一条：

```text
### NEW-0008-01
defect_locus: [x] element
--- 上一行选了 element：填下面两项，跳过 defect_logic_kind ---
defect_element: [x] state
defect_qualifier: [x] missing
--- 以下四项两支都要填 ---
defect_reference: [x] language
statement: fork1 全文没有任何 state 声明（:5 首次出现，位置是 TurnOn 区域内部初始边的目标，因而被归到 TurnOn 的区域里；但 :8 :9 :10 又以它为源端连向 TurnOn 之外的顶层状态）。结果是同一个顶点既是 TurnOn 的子态、又向 TurnOn 之外发边，而模型里没有任何一处说明它到底属于谁。
expected_after_fix: fork1 有一行自己的声明，且该声明所在的层级与它的出边一致 —— 即从 TurnOn 内部出发的执行路径上，「fork1 属于哪个父态」这个问题有唯一答案。
nl_evidence: 无
```

三个轴各自在这条例子里承担了什么：

1. **`defect_locus = element`**：能指着 `:5` 一行说「就是它」—— 缺的是这个顶点自己的声明。
2. **`defect_element = state` + `defect_qualifier = missing`**：把它改对只需**一次编辑**（补一行 `state fork1`），改完之后状态声明的**条数变多** —— 这正是 `missing` 的判定测试。
3. **`defect_reference = language`**：不引用 NL 任何一句就能判定，故 `nl_evidence` 写 `无`。注意 NL 第 2 句确实点名了 `fork1`，但这条缺陷说的是「声明缺失」，而 NL 对「谁是谁的子态」一个字都没说。

走 **逻辑支**的一条（同一份材料里的另一件事）：

```text
### NEW-0008-02
defect_locus: [x] pair
--- 上一行选了 pair / global / other：跳过上面两项，填下面这一项 ---
defect_logic_kind: [x] unreachable
--- 以下四项两支都要填 ---
defect_reference: [x] language
statement: :5 已经在 TurnOn 内部给出一条通往 fork1 的初始边，:8 又给出 TurnOn --> fork1。控制一进入 TurnOn 就被 :5 的初始边带走，此后没有任何执行路径能走到 :8 那条边。
expected_after_fix: 每一条声明出来的迁移都至少有一条从初始态出发、能走到它的执行路径；具体到这里，:8 与 :5 之中只应留下一条。
nl_evidence: 无
property_pattern: Existence × Globally
```

⚠️ 两条讲的是同一份材料里 `fork1` 附近的事，**但不是同一条缺陷、也不落在同一支**：前者能指着一行说「就是它」，后者两处单看都合法、毛病在它们凑一起。现象相邻不等于座标相同。

#### 3.5.4 [validate.py](./validate.py) 在这一块上会报什么

这张表**列全**了。校验器在新增条目上只做两件事，两件都只看字段值 —— 语义判断一概不做（[CLAUDE.md](../../../../../CLAUDE.md) §11：只有能被完美判定的约束才允许做成会一票否决的门）。

| 情形 | 级别 | 判据类型 |
| :-- | :-: | :-- |
| 必填项缺失（`defect_locus` / `defect_reference` / `statement` / `expected_after_fix` / `nl_evidence`） | `E` | 确定性（非空） |
| 走 `element` 支却没给 `defect_element` 或 `defect_qualifier` | `E` | 确定性（条件式分支的必填一致性） |
| 走 `pair` / `global` / `other` 支却没给 `defect_logic_kind` | `E` | 同上 |
| 任一座标轴的取值不在枚举内 / 单值字段给了多个 | `E` | 确定性（枚举成员） |
| `nl_evidence` 引用了本 pair **不存在**的段 id | `E` | 确定性（段 id 集合是封闭的） |
| 填了**另一支**的轴（如选了 `element` 又填了 `defect_logic_kind`） | `W` | 确定性提示，不阻塞 |
| `defect_reference = requirement` 而 `nl_evidence` 写 `无` | `W` | 两个字段值，但「到底靠不靠某句 NL」要读文意 |
| `nl_evidence` 有内容但认不出本 pair 的段 id | `W` | 确定性提示 |
| 与另一条新增条目、或与本 pair 某条台账记录疑似重复 | `W` | 启发式，不自动判重 |

「填了另一支的轴」之所以只报 `W`：那多半是选完 `defect_locus` 忘了删，而**填多了不像填少了那样让记录不可用**。

按 [CLAUDE.md](../../../../../CLAUDE.md) §13 的要求，写出一个「满足全部门」的具体形状（由 [test_relabel.py](./test_relabel.py) 的 `test_a_shape_that_satisfies_every_gate` 机械钉住，该条目自身的 `E` 与 `W` 都必须为空）。⚠️ 与 §3.5.3 同一条纪律：形状仍取自永久排除的 `0008`，不得用任何**在评 pair** 的真实制品当样例 —— 那等于把座标该怎么勾的答案先发给该 pair 的判读者。

```text
defect_locus: element
defect_element: transition
defect_qualifier: extraneous
defect_reference: language
statement: :8 的 TurnOn --> fork1 是多出来的：:5 已在 TurnOn 内部给出通往 fork1 的初始边，控制一进入 TurnOn 就被它带走，:8 那条边此后没有任何执行路径能走到。
expected_after_fix: 删掉 :8 之后，从初始态出发仍能到达 fork1，且模型里不再有走不到的边。
nl_evidence: 无
```

这个形状能过全部门的原因逐条对上：五项必填都非空；走 `element` 支且 A、B 都给了；`defect_logic_kind` 空着（本支不问它，故不报）；`defect_reference = language` 与 `nl_evidence = 无` 一致，故连那条 `W` 也不触发。

### 7.1 `nl_contradiction` 里有 2 条 `nl_evidence` 为空

13 条 `nl_contradiction` 中有 2 条的 `nl_evidence` 是空串，而它们的 `layer_basis` 都写着「**与 NL 的显式义务矛盾**」。逐条复核后，**两条都是记账遗漏** —— 依据都躺在各自的 `statement` 正文里、没抄进字段。但两条的**待裁定点不同**：`EIS-0005-02` 的依据是从迁移拓扑**推断**出来的（故 `layer` 归属待裁），`EIS-0024-03` 引的是原文**逐字**一句（故 `layer` 站得住，待裁的是那一句本身欠指定）。下面分开写。

**`EIS-0005-02`**（pair `0005`，NL10 微波炉，`decided_by = lexical`，`direction = hierarchy`）：`nl_evidence` 与 `upstream.ledger_statements` **都是空的**。这是**记账遗漏** —— 依据躺在 `statement` 正文里（它逐句点了 NL 第 4/5/6/8 句），没抄进字段，于是机械检查（§6.3 的「`nl_named` / `nl_contradiction` 层却无 `nl_evidence`」）把它捞了出来。重标时应把 `nl_evidence` 补成对应段 id 并附原句。

**一个属实、且对判读有用的事实**：译者在不知道有这条记录的情况下独立确认，**该份 NL 全篇零处提及包含关系** —— 不出现 `composite state` / `substate` / `inside` / `within` / `contains` / `nested` 中的任何一个，唯一的 `inside` 是第 3 句「placing an item **inside** the microwave」（把物品放进炉腔），与状态层次无关。译者给这份 NL 的全局提示原话是：「本份 NL 的层次判读证据全部是**间接**证据；判读者需自行裁定「互为迁移目标」是否蕴含「不得互为祖先后代」—— **原文本身没有回答这个问题**」。

**2026-08-13 撤回本节此前的一个推论。** 旧版由上面那个事实推出「所以该记录的真实依据是 `reference_side` 写的『六个状态全部平级（扁平）』，是参考模型依据、不是 NL 矛盾」，并据此建议把 `layer` 降成 `wellformedness`。**这个推论不成立，两条理由都硬**：

1. **它是 non sequitur。** 该记录的论证根本**不依赖**包含关系词汇 —— `statement` 引的是 NL 第 4/5/6/8 句的**互斥性**（逐句复核属实：第 4 句 `From DoorOpenWithItem, the system can transition to DoorShutWithItem … or to ReadytoCook`、第 5 句 `opening the door transitions the system back to DoorOpenWithItem`、第 6 句 `the system returns to DoorShutWithItem` / `transitions to DoorOpenWithItem`、第 8 句 `the system transitions to DoorOpenWithItem, while if the timer expires, the system moves to DoorShutWithItem` —— 这四句确实把那两个状态当成由相反的开 / 关门事件到达的往返两端）。「NL 没写 `substate` 这个词」与「依据不在 NL 上」在逻辑上无关。另外 `reference_side` 是**每条记录都填了**的字段（REPORTABLE 98 条全部非空），它非空并不能说明谁是「真正的依据」。
2. **归 `wellformedness` 实质上是错的。** 四层嵌套本身完全良构；说它是缺陷，必须先知道那两个状态**应当**互斥 —— 而这个「应当」只能来自 NL 或参考模型，不可能「模型自身即可判定」。

**那么这条该怎么办**：`layer` 落 `nl_contradiction` 还是 `nl_named`，取决于判读者如何裁定「NL 把二者当互斥替代配置」是**显式义务**还是**从迁移拓扑推断出来的读法** —— 这一步原文没有回答，故本节**不预设结论**，只标为待裁定。若有人要改这条的 `layer`，论证必须建立在第 4/5/6/8 句上，不得再用「NL 零处提及包含关系」这个词汇缺失来推。

**`EIS-0024-03`**（pair `0024`，NL01 列车，`decided_by = batch5_spotcheck`，`direction = hierarchy`）：**独立复核结论：它与上一条同属记账遗漏，但待裁定点不同。** 该记录的 `statement` 逐字引了 NL 第 10 句「remains in the Approaching substate ... until it is ready to stop or decelerate」，而原文第 10 句确为「The system remains in the Approaching substate while nearing the destination, until it is ready to stop or decelerate.」—— **引文属实，省略号只略去了 while nearing the destination**。所以它的依据**确实落在 NL 上**，不是模型自身、也不是参考模型；`nl_evidence` 为空纯属**记账遗漏**：证据躺在 `statement` 正文里，没抄进字段，于是机械检查（§6.3 的「`nl_named` / `nl_contradiction` 层却无 `nl_evidence`」）把它捞了出来。

**但结论要连限定一起写**：NL 第 10 句只给了**驻留义务**，它**没有**给出离开 Approaching 的 trigger（触发）、guard（守卫）或目标状态 —— 译者对该段的判读提示逐字写着「无法映射到任何具体迁移；判读「缺失迁移」时本句不构成明确约束」。「这条边违反了它」这个结论还需要两步 NL 未提供的推导：其一，UML 下指向外层复合状态的迁移等价于该复合状态的自迁移，会重跑内部初始而把阶段重置回 `Accelerating`；其二，作者侧标签 `exit/Send` 的触发条件是什么，原文与模型都没说。故重标时：`layer = nl_contradiction` **站得住**，`nl_evidence` 应补成 `NL-L010` 并附原句，同时须标注该句**欠指定**（见下一节）。

### 7.2 52 条 `nl_named` 都有 `nl_evidence`，但被引的句子常常欠指定

先把话说准，免得下一轮读者读反：**这不是「台账把 NL 欠指定当成了违反」**。台账的分层设计**本来就区分**了哪一层需要 NL 依据 —— `wellformedness` 28 条里 24 条 `nl_evidence` 为空（98 条口径下为 27 条里 23 条）、`over_specification` 6 条里 5 条为空，**那是设计如此**，不是漏填：这两层按定义不靠 NL 判定。而 52 条 `nl_named` **一条不缺**，每条都逐字引了 NL 原句（形如「NL 第 N 句逐字含 "…"」，中位长度 127 字符）。

**真正的问题在别处：这 52 条的依据「够不够硬」，现台账没有任何字段记录。** 逐字引用只证明「NL 里有这句话」，不证明「这句话足以支撑一条违反判定」。译者在 9 份 NL 上反复撞见同一形态 —— 被引的句子本身把关键槽位空着：

| 欠指定形态 | 实例（均取自 [translations/](./translations/) 的 `note` / `translator_notes`） |
| :-- | :-- |
| **迁移不写源状态** | `nl_0000`：六条需求里四条（第 3、4、5、6 段）描述迁移，**没有一条写明源状态**，只写目标 —— 「从哪来」在这份 NL 里系统性缺失。`nl_0001`：三条迁移里两条未指明源状态，代词 `it` 一路指代 the basic braking device（装置本身）**而非某个具体状态**。`nl_0005`：第 2、3、6、8 句的后半句均未重述源状态，全靠上下文推断 |
| **不写触发 / 守卫** | `nl_0002`：第 3、4、5 句分别用 first / can also / Similarly 引入三个 substate，**三句都没有给出触发事件、守卫条件或源状态**，「何时切换」只有 `based on specific conditions` 这一空壳。`nl_0003`：**全篇未给出任何一条迁移的方向、配对与守卫**，只说 transitions between / depending on actions like…，故模型的环形迁移拓扑在本 NL 下既无正面依据也无反面依据 |
| **并列项无连接词** | `nl_0000` 第 5 段：`human steering cmd, brake pressed, in (auto final)` 三项**只用逗号并列**，是合取（and）、析取（or）还是顺序发生，无法判定。`nl_0009` 第 13 句：三个 `*_inactive` 条件之间是「且」还是「或」同样未明说 |
| **零情态动词** | `nl_0006`：**全篇没有一处使用情态动词**（无 can / will / must / should / may），四句全是一般现在时陈述句。后果是原文对「进入某状态后**能否离开**」始终沉默 —— 第 3 句说了进入 formation adjustment state，但全篇没有任何文字规定它之后必须、可以或不能离开 |
| **文字与守卫表达式不一致** | `nl_0009` 共 **6 处**（守卫数与目标数不匹配 · 同一表达式描述详略不一 · **单位口径冲突** · 状态名 `exit_urban` 悬空 · `respectively` 配对方向歧义 · 列举内部表达式缺失）。其中最硬的是**单位口径冲突**：`dist_to_front` 按**米**解读（25 米 / 15 米）、`dist_to_exit` 按**千米**解读（2 千米 / 0.7 千米），两者同属 `dist_to_*` 命名族、同为**裸数字**、全文未声明单位。**模型只搬运裸表达式，因此这一混用在模型层面完全不可见** —— 只比对表达式字符串会整个漏掉它，反过来也不能因为模型没有单位声明就判它违反 NL |
| **驻留义务无出口** | `nl_0004` 第 10 句（即 §7.1 那条 `EIS-0024-03` 引的句子）：`until it is ready to stop or decelerate` **未给出对应的 trigger、guard 或目标状态**；且 decelerate 在第 6、7 句已是**进入** Approaching 的动作，此处却成了**离开**的条件之一，原文未说明二者关系 |
| **信息密度过低** | `nl_0007`：全份仅 46 词三句，**对状态集、事件集、变量、迁移守卫、退出条件均无任何约束** —— 判缺陷时大量模型元素属于「NL 未规定」，不能记为违反 |

**这条建议 2026-08-13 落地过一次、同日又被换掉，两件事都要写清。** 落地形态是 §5 新增登记块的「② 依据层」字段 `basis`，其中一个取值就是 `NL欠指定`。换掉它的原因见 §3.5.1：`basis` 的四个取值是本目录自造的，与有文献出处的 `defect_reference` 重合。

**新形态怎么承载这件事**：`defect_reference` 只回答「判定这条缺陷成不成立，需不需要引用 NL 的某一句」（`language` / `requirement` / `other`），它**不**回答「被引的那一句够不够硬」。所以「该句欠指定」这个判断现在落在 `statement` 与 `expected_after_fix` 的自由文本里 —— 判读者要写成「原文未规定，模型自行选择了一种读法」，而不是「模型违反了它」。⚠️ 这是一次**有意的退让**：欠指定的强度此后不是一个可查询的字段，只能靠读文本。理由是本轮的首要问题是「台账漏了什么」，而不是「既有条目的依据分几档」；后者可以在合并回台账那一步再做成字段。

§2 对**既有** 52 条 `nl_named` 的裁决区仍然只有「保留 / 修正 / 删除 / 拆分」四档，判「该条依据欠指定」时请在「理由:」里写明，不要硬塞进四档里。

**原始建议（保留原文以便复核）**：在裁决区增加**一个可选标记**，让判读者能标出「**该条的 NL 依据欠指定**」—— 即「原文确实有这句话，但这句话没写源状态 / 没写触发 / 没写连接词，因此它支撑不起「模型违反了它」这个判定」。这个标记与「保留 / 修正 / 删除」**正交**：一条依据欠指定的记录不一定要删，它可能只是该降层（`nl_named` → `wellformedness`）或该改写 `statement`。现台账把「有 `nl_evidence`」与「依据成立」当成一回事，而这 9 份 NL 说明前者远弱于后者。

## 七点五、映射 240 个对象时撞出的两处结构性发现

把台账 99 条与候选 141 条逐一映射到新座标系之后，有两件事是**映射之前不知道、映射之后才显形**的。两条都由多批互不通气的判定者独立撞到，故记在这里。

### 7.5.1 座标系的真缺口只有一处：正交区域及其数量

240 个对象里映射不上的共 **86** 条。但**只有 12 条**是座标系本身给不出取值，且它们指向**同一处**：缺陷的对象是「正交区域（region）」或「区域的个数」，而维度 A 的 7 个取值里没有 region，类型学 §3.7 又明写正交区并发语义界外、「不得取为维度取值」。于是两条路都不通：落 `element = other` 等于把一个座标系明文声明界外的构件伪装成界内的「其他构件」；落 `defect_logic_kind` 也无对应取值。

| 来源 | 条数 | 例 |
| :-- | --: | :-- |
| 台账 | 4 | `EIS-0006-01` `EIS-0026-01` `EIS-0036-01` `EIS-0046-02` |
| 候选 `DIFF-` | 7 | `DIFF-0023-04` `DIFF-0033-02` `DIFF-0037-01` `DIFF-0043-06` `DIFF-0047-03` `DIFF-0056-03` `DIFF-0057-03` |
| 候选 `UM-` | 1 | `UM-0007` |

**为什么说它是真缺口而不是判读噪声**：三批判定者的输入互不相同（台账侧读 `statement`，`DIFF-` 侧读 `ref` / `gen` / `reason`，`UM-` 侧读未匹配 issue 的 `issue` / `reason`），彼此不通气，却在**同一个语义位置**上停住。另有 9 个 `UM-` 桶在其内部也含区域缺口的组，只因该桶的主卡点是登记单位而未计入上表 —— 若改按「桶内出现即计」的口径，区域缺口的覆盖面还要更宽。

**这一条与建模对象边界是一致的，不是矛盾**：[CLAUDE.md](../../../../../CLAUDE.md) 已把正交区并发语义排除在 $M = (S, E, V, Tr, A)$ 之外。所以它不是「类型学设计失误」，而是**边界的必然结果**：界外的东西按定义就没有维度取值。真正需要裁定的是另一件事 —— 这批材料里确实反复出现区域相关的主张，那么它们该由工作单的 `scope` 字段承接、还是该重新审视边界。**本节不预设结论**，只把它标为待裁定。

### 7.5.2 `DIFF-` 里混进了另一个物种：逐字否认制品有问题的记录

`DIFF-` 的 77 条候选里，有 **12** 条的 `gen` 字段逐字写着「—」或「(不可能生成)」。它们真正主张的是**参考模型 / 真值本身的有效性**（「参考侧含 NL 推不出的内容，任何 LLM 都无法复现，却会被计成漏检」），而不是一种缺陷形态。缺陷座标系的判定测试全部落在**作者源 PlantUML** 上，这类在制品内指不出任何一处，卡在轴 0。

**要紧的是别把它们算进覆盖率**：座标系没覆盖到它们，是因为它们本来就不在座标系要描述的对象集合里 —— **那不是缺口**。工作单 §3.2a-2 单列这一族并写明了这一点（由 `test_the_denial_species_is_separated_from_the_real_candidates` 钉住）。

判据是**字面**的（`gen` 去空白后为破折号 / 空 / 「无」，或含「不可能生成」），故读者能在页面上自行核对那行「生成侧：—」。相邻还有一族 `gen` 写「(生成方在第 2、4 句优于参考)」的记录（全语料 5 条），它们同样不指认制品缺陷，但「优于参考」是一句**相对评价**而非否认，字面判据吃不进来，故**未收进**这 12 条 —— 要处理那一族需要另立判据，记为待办。

## 十、一次材料事故：译文的判读提示曾把**别人的制品**当成你的

**这一节是判读者必须知道的事。** 若你在 **2026-08-13 之前**读过任何一份工作单的「逐段判读提示」或「整份 NL 层面的观察」，你读到的关于**被测制品**的事实**可能是假的** —— 请把当时基于那些提示形成的判断重新过一遍。

### 10.1 现象

提示里出现过这样的句子（逐字）：

- 「模型 `PumpControl` 内**不存在**任何以 `PumpState` 为目标的迁移」—— 而读到这句话的 `0013.md` 对应的制品里有 **7 条**（`0033` 6 条、`0043` 5 条、`0023` / `0053` 各 3 条）。
- 「$V$ 中**没有**任何此类变量，$A$ 中**也没有**对应的赋值动作」（指 UAV 数量递减）—— 而 `0016` 写着 `Attack Finished / Decrease UAV swarm count`，5 个兄弟里 **4 个**都有。
- 「`exit_urban` … NL 其余各句与**模型中均无此状态**」—— 而 `0019` `0029` `0039` `0049` `0059` **全部含** `exit_urban`。

**最有害的是「不存在」型断言** —— 它会把判读者的结论**直接反过来**：要么记下一条并不存在的缺陷，要么把自己读对的东西改掉。而这些句子印在一句免责声明底下：「提示只陈述原文这一句说了什么、没说什么，不含任何裁决」—— **声明恰恰在劝读者不要去核。**

### 10.2 根因：**NL 分组** × **制品断言**

一份 NL 对应 **6 个 pair**（同一份 NL 由 6 个 LLM 各生成一个制品）。[generate.py](./generate.py) 按 **NL 分组**取 `note` 与 `translator_notes`，于是同组 6 份工作单拿到**逐字相同**的文本。而译者写这些文本时锚在**编号最小那个 pair 的生成模型**上 —— 那句话对当事的 1 份为真、对另外 5 份基本为假。

分组口径是 **NL 全文 sha8**，**不是末位数字**：`nl_0002` 的组是 `0002 0013 0023 0033 0043 0053`，`nl_0003` 的组是 `0003 0012 0022 0032 0042 0052`，两组交错。

**归属已被机械钉死**：每一组的断言 **100% 命中该组编号最小那个 pair 的生成制品**，而对**参考模型** 4 组是 `0/N` —— 这排除了「译者写的其实是参考模型」这个善意解释。顺带说明本可避免：**同组 6 个 pair 的参考模型是同一份**，锚在参考模型上不会出事，锚在生成模型上则必然出事。

### 10.3 量级

| 口径 | 数 |
| :-- | --: |
| 受影响的 NL 组 | **8 / 9**（只有 `nl_0004` 干净） |
| 可机械核验的制品断言 | **79** 条 |
| 其中在**至少一个兄弟 pair** 上为假 | **68** 条（**86%**） |
| 带着关于自己制品的假事实的工作单 | **40 / 54**（**74%**）—— 8 组 × 5 个非当事 pair |

### 10.4 修法

**原则：`note` / `translator_notes` 只讲原文，一个字都不讲制品。** 这与 [TRANSLATION_SPEC.md](./translations/TRANSLATION_SPEC.md) 的本意一致（译者的职责是转述原文与标歧义），是执行时越界了。

1. **剥离**：9 份 JSON 共 **101 处**替换（89 + 11 + 1 三批，逐份 7 / 12 / 11 / 10 / 1 / 7 / 17 / 8 / 28），删掉所有「模型里有 / 没有 X」「$A$ 中无 Y」「不存在以 Z 为目标的迁移」「模型补出了…」「模型记作…」、文件名 `plantuml.puml`、以及原文未点名的标识符（`InitialState`、`FormationAdjustment`、`R45RouteToken` 一类）。
2. **保留**：一切**关于原文**的观察 —— 「原文未给该迁移的触发条件」「全篇无情态动词」「单位未声明」「这一句有两种读法」。剥离**不等于删光**：这些欠指定观察正是判读的核心材料，删了就把 §7.2 那七种形态一起删了。
3. **改成把核对权交回读者**：原本「模型中不存在 X」的地方，现在写「本句是否被满足须自行到 §1.2 逐行核对，本提示不代为回答」。
4. **声明同步**：工作单提示区新增一句「提示里也不含任何关于本 pair 制品的断言」，并指向 §1.2（作者源，带行号）与 §4（按本 pair 现算的清单）。只改数据不改声明会留下更糟的局面 —— 旧声明会继续劝读者不要去核。

### 10.5 落的门

[nl_zh.py](./nl_zh.py) 的 `artifact_leaks()` 在**装载期**检查，违反即抛 `NoteArtifactLeak`，工作单生成不了。按 [CLAUDE.md](../../../../../CLAUDE.md) §11，门里**只放能完美判定的约束**，故两条判据都只看字符串：

1. `note` / `translator_notes` 不得含 `模型` / `制品` / `生成侧` / `参考侧` / `作者源` / `plantuml` / `puml` / `fcstm`（ASCII 部分不区分大小写）。谈 UML 语义仍然可以 —— `UML` 不在表内。
2. 提示里出现的**驼峰或下划线标识符**，必须在**本份 NL 自己的 `en`** 里逐字出现过。这是同一文档内两个字段之间的确定性一致性检查；反过来 `dist_to_front` / `DoorOpenWithItem` 这类原文点了名的标识符**必须放行**，否则译文没法讲原文点了什么。

**两条判据都只作用于 `note` 与 `translator_notes`，不碰 `zh`** —— 译文必须逐字跟着原文走，原文若真写了「模型」就照译。

**门过了不等于合规。** 语义部分（不含上述词却仍在断言制品）靠 SPEC 第 8 条纪律与人工评审兜底。回归测试见 [test_relabel.py](./test_relabel.py) 的 `test_no_translation_note_mentions_the_artifact`（正面：现有 9 份必须干净）与 `test_artifact_leak_gate_actually_fires` / `test_artifact_leak_raises_at_load_time`（反面：门必须真的拦得住，且不许恒抛）。

### 10.6 这道门量过什么、没量过什么（不要把两者混为一谈）

**本节存在的理由**：本轮修复报告的初稿写过一句「误伤面已离线量化 —— 修前 9 份中 8 份命中（约 60 个位点），修后 0」。**那句话两处都不对**，就地更正如下（[CLAUDE.md](../../../../../CLAUDE.md) §3.6）。

| 量了什么 | 口径 | 实测 |
| :-- | :-- | --: |
| **查全**（门能抓住多少**已知**泄漏） | 对 `6fdc1c3f` 的 9 份**修前**译文跑 `artifact_leaks()` | **9 / 9 份命中，共 96 个位点** |
| **误伤面**（门会拒掉多少**本该通过**的文本） | —— | 见下 |

**数字更正**：修前是 **9/9 份、96 位点**，不是 8/9、60。`nl_0004` 语义上确是唯一干净的一份（§10.3 的 8/9 说的是**制品断言**这件事，那个数没错），但它的 `note` 里写了 `PlantUML`，词法门照样命中 2 处 —— **「语义干净的份数」与「词法门命中的份数」是两个量，不能互相顶替。**

**方法更正（这条比数字重要）**：上面那 96 个位点是在**已知脏**的文本上跑出来的，它量的是**查全**，不是误伤面。而「修后 0」更不能算证据 —— **剥离脚本本就是对着这道门迭代出来的**，用它的产物去证明门不误伤属于[自证式验证](../../../../../CLAUDE.md)（§3.5 第 5 条）。

**真正的误伤面要拿门没见过的、本该通过的文本来测。** 本轮做了一次这样的探针，但它有明确局限，不足以当作「误伤面已量化」：

- **语料**：9 份译文的 **`zh` 字段**，共 **55 段**。选它的理由是它**gate-naive** —— 剥离那 101 处改动**一个字都没碰 `zh`**（机械对拍：55 段全部逐字节未变），所以这批文本从未对着这道门迭代过；而按 SPEC，`zh` 与 `note` 一样是**只讲原文**的文本。
- **做法**：把两条判据原样套到 `zh` 上（门实际**不**作用于 `zh`，这里只是借它当语料）。
- **结果**：**4 / 55 段（7%）会被拒**。逐条看：`nl_0001` 段 1 与 `nl_0006` 段 1 命中禁用词「模型」，而那是因为**原文自己写着 `state machine model`** —— 这两条是**确凿的误伤**；`nl_0004` 段 8 命中 `plantuml`，它谈的是原文把 `Entry` 写成大写、与 UML / PlantUML 的关键字大小写不符，按「只讲原文」算也偏误伤；`nl_0003` 段 3 出现「模型侧」，那是**真命中**。即 **3 处误伤 + 1 处真命中**。**那 1 处真命中当时只被记下、没有修** —— 它在 2026-08-13 的第二轮全量核对里才被摘掉（见 [§11.5 第 6 条](#115--人工复核清单-改动任何一份译文后逐条过)）；上面这组数字说的是**修之前**的 `zh` 语料，今天重跑这个探针只会剩 3 处误伤。
- **推论**：这道门对「原文本身就在谈 model / PlantUML」这一类**合规**表述**确有误伤**，量级约 5%（3/55）。撞上时的正确做法是改写措辞（如「原文用语 `state machine model`」→ 说成「原文第 1 句给出的被建模对象名」），不是放宽门。

**这个探针不能被当成误伤面的定论**：① 语料是 `zh` 而不是 `note`，两者体裁不同；② `n = 55` 太小；③ 「哪几条算误伤」是我读出来的，不是机械判定。结论只能写成：**误伤确实存在、量级约 5%、成因单一（原文自己提到 model / PlantUML）**，而不是「误伤面已量化」。

## 十一、第二类材料错：提示**讲原文、但讲错了**

§十 剥掉的是「讲制品」。那一轮之后还剩**一类零机械覆盖的错**：提示确实只在讲原文，但把原文讲错了 —— 数字数错、范围说过头、位置指偏。危害形态与 §十 同类（提示被逐字印进 6 份工作单、旁边立着一句免责声明劝读者不要去核），只是对象从制品换成了原文。

### 11.1 量级（2026-08-13 全量核对）

| 口径 | 数 |
| :-- | --: |
| 逐条验算过的、关于原文的可核验断言 | **约 368** 条（手工计数，粒度见 §11.3） |
| 明确不实（数字或范围经验算为假） | **16** 条 |
| 过度解读 / 枚举不全（非假但不准） | **5** 条 |
| 受影响的 NL 组 | **6 / 9**（`nl_0001` `nl_0002` 全清） |
| 其中与**同一份 JSON 自己的别处**互相打架 | **8** 处 |
| 另查出 1 处**制品断言残留在 `zh` 字段**（词法门不覆盖 `zh`） | **1** 条 |

**最刺眼的一点：8 处矛盾意味着正确说法本来就在同一份文件里。** 例如 `nl_0000` 的整份观察一边写「`final state` 未出现于原文」，一边在下一段的状态指称表里列着 `final state`；`nl_0009` 的段 12 提示写「NL 其余布尔条件一律写作 `x=true`」，而同一份的「记法问题 B」写的是「**前十一句**一律 `x=true`」、段 13 提示写「三者均为裸标识符」。**不是不知道，是没对拍。**

### 11.2 修法

**原则：改准，不是删光。** 错的通常只是**数字或范围** —— 「`it` 出现 4 次」改成「3 次」、「全文未声明单位」改成「表达式侧不带单位、单位只在散文里给出」、「共 7 处」改成「共 7 类（合计 11 处）」。「全篇无情态动词」「无源状态」「单位未声明」这类欠指定观察是判读的核心材料，删掉等于把 §7.2 那七种形态一起删了（同 §10.4 第 2 条）。

**改完必须与同段其余句子再对拍一次** —— 上一轮的 I-A 正是在剥离制品断言时**新写出**一条关于原文的假事实，别修出第二处矛盾。

### 11.3 这一轮核了什么、没核什么（不要把两者混为一谈）

**核过的**：计数式（「三条迁移」「共出现 4 次」「共 9 处引号标签」）· 全称 / 存在式（「全篇无情态动词」「未出现于原文」「其余一律 `x=true`」）· 定位式（「第 N 句」「段 id」「第 1—5 段各一个尾随空格」）· 属性式（「该句未给触发」「单位未声明」「用的是单个 `&`」）。每一条都在该份 `en` 上重算过。

**没核的**（如实记，不要因为报告好看而略过）：

1. **歧义式断言**（「有两种读法」「读法 A / 读法 B」）约 60 余条 —— 不可验算，只抽查了「两种读法是否都能从字面支持」。
2. **重要性排序**（「最值得注意」「密度最高的四句」「最强的一处」）—— 主观，无判据。
3. **UML 领域断言**（「按 UML 即不含 substate」「UML 中 `X/Y` 即 trigger / action」）—— 靠领域常识核过，未回查 UML 规范原文。
4. **「未发现语法 / 拼写 / 数格错误」这 5 条否定式质量判断**（`nl_0001` `nl_0002` `nl_0003` `nl_0005` `nl_0006` 各一）—— 通读后同意，但这是对开放集合的否定，无法机械穷尽。
5. **`zh` 的翻译质量本身**（是否严格直译、是否替原文消歧）—— 本轮只核了 `zh` 里的**元陈述**（〔原文如此〕/〔译者存疑〕中的事实部分），没有逐句复核译文忠实度。**这项欠账已于同日补做**：55 段全量逐段核对，改掉 6 处 —— 见下方 §12。其中 4 处恰恰又是**元陈述讲错了原文**，说明本节第 5 条当初划的边界（「元陈述已核、译文未核」）本身也不牢。
6. **§11.1 那个「约 368」是手工计数**，粒度口径是「一个可核验的事实主张记一条」，换个粒度会得到不同的数；它用来说明体量，不要当精确统计引用。

### 11.4 落的门（只落了能完美判定的那一小块）

[nl_zh.py](./nl_zh.py) 的 `original_ref_errors()` 在**装载期**检查，违反即抛 `NoteOriginalRefError`。按 [CLAUDE.md](../../../../../CLAUDE.md) §11，**只有能完美判定的约束才许进 validator**，而「这句关于原文的话对不对」一般**不可机械判定** —— 所以**计数式与全称式一概不进门**。只有三个子类进得去：

1. **句号越界** —— 「第 N 句 / 第 N 段」的 N 必须落在 `[1, 段数]` 内。
2. **段 id 不存在** —— 提示里写的 `NL-M003` / `NL-L012` 必须在本份的段集合里（现役 2 处引用，`nl_0000`）。
3. **引文不逐字** —— 提示里双引号内的**纯 ASCII 片段**必须在本份 `en` 里逐字出现。

第 3 条要跳过两类**示意写法**，否则会误伤合规文本：含 `...` / `…` 的（`"either ... or"`、`"triggered by ..."`）与含**单个大写字母占位符**的（`"begins in X"`、`"the conditions A, B, and C"`）。**离线实测**：不跳过则 86 条 ASCII 引文里 **8 条被拒，8 条全是示意写法**（误伤率 9%）；跳过后 **0 拒**。跳过规则本身也是纯词法的，不需要任何语义解释。

**门当前实际校验的引用共 227 条**（引文 + 句号 + 段 id），全部通过。**门过了不等于合规** —— 上面那 16 条不实里，这道门**一条都抓不到**（它们全是计数式与全称式）。那部分只能靠 [TRANSLATION_SPEC.md](./translations/TRANSLATION_SPEC.md) 的**第 9 条硬纪律**与人工复核。

### 11.5 人工复核清单（改动任何一份译文后逐条过）

1. 提示里每一个**数字**（几条迁移 / 几个状态 / 出现几次 / 共几处），在 `en` 上**重数一遍**。注意区分「几类」与「几处」。
2. 每一个**全称 / 存在词**（「一律」「全篇」「只有」「唯一」「其余」「均未」「从未」），找**一个反例**试试；找得到就改范围，不要改成更含糊的说法。
3. 每一句「原文**未**给出 X」，先在 `en` 里搜 X 的散文形式 —— 常见错法是「表达式侧没给」被写成「全文未声明」。
4. 每一处**位置引用**（第 N 句 / 段 id / 行尾空格 / 编号写法），对着 `en` 点一遍（这一类现在有机械门兜底）。
5. **段内对拍**：同一份 JSON 里对同一件事的说法必须一致。固定对拍位点 —— `translator_notes` 的术语表 / 标识符总表 ↔ 各段 `note` 的引用；某段 `note` 说「原文未区分 X」↔ 另一段 `note` 却按 X 下了定论；分类统计（「共 N 处 + M 项」）↔ 正文实际列出的条数。
6. 顺带查 `zh` 里的〔原文如此〕/〔译者存疑〕—— **词法门不作用于 `zh`**，本轮就是在那里查出唯一一条残留的制品断言（`nl_0003` 段 3 曾写「应对照模型侧的 Accelerate Signal / Brake Signal / Stop Signal」，那三个标识符原文一个都没有）。该处已改为「须自行到 §1.2 逐行核对」。
7. 改完跑 `python3 -m pytest test_relabel.py -q`（装载期门会当场炸）与 `python3 generate.py`，再确认 54 份工作单的 diff 只落在提示区。

## 十二、第三类材料错：**译文本身**（`zh`）的忠实度

§十 与 §11 都在管 `note` / `translator_notes`。**译文本身此前一个判据都没有** —— 旧 §11.3 第 5 条如实记着：「`zh` 的翻译质量本身（是否严格直译、是否替原文消歧）本轮没有逐句复核」。装载期唯一的保障是 **`en` 逐字节等于 `nl.txt`**，它管的是英文一侧，与 `zh` 无关。

危害形态与前两类同级、但更直接：判读者要据 NL 判断「制品是否违反原文」，而 `zh` 与 `en` 并排印在工作单上。一处误译可以直接翻转结论 —— 把「原文未规定」译成「原文禁止」、把 `may` 译成「必须」、漏掉一个否定词，都会让判读者记下一条并不存在的缺陷。

### 12.1 量级（2026-08-13 逐段核对，全部 55 段）

| :-- | --: |
| 逐段核对的段数 | **55**（9 份 NL，无抽样） |

**6 处里只有 2 处是「翻译」错**（词义、条件连接词），另 4 处是 `zh` 里的**元陈述**〔原文如此〕/〔译者存疑〕**讲错了原文** —— 也就是 §11 那一类错，只是藏在词法门覆盖不到的 `zh` 字段里。这与 §11.5 第 6 条的预判一致。

1. `nl_0000` 段 4 —— `auto（自动）` 的括注偏向 `automatically` 一读；但紧跟的〔译者存疑〕把两读都写了，且中文「自动」本身兼容两读。

4. `nl_0004` 段 3 —— 「actions 用了复数，但其后只给出一项动作」：在该段〔译者存疑〕给出的两读下都成立，但还有第三读（`Emergency Stop` 与 `sends ... signal` 是两项并列动作），那一读下断言不成立。

6. `nl_0005` 段 5 —— `while` 取对比义（「而」），而〔译者存疑〕给出的**理由是「时间义会蕴含并发、超出本项目边界」**；那是拿评测边界去定原文读法，方法上站不住。未改的理由：两读都印在同一串 `zh` 里、读者可自行取用，且同份段 8 同构句确为对比义，结论本身是对的。
7. `nl_0007` 段 3 —— 括注写作「（不同 的）」，看似手误，实为逐词镜像原文错序的 `different of`（`different`→不同、`of`→的）；该意图未在任何地方写明。

### 12.3 落的门（只落了能完美判定的那一小块）

[nl_zh.py](./nl_zh.py) 的 `zh_literal_drops()` 在**装载期**检查，违反即抛 `ZhLiteralDrop`。按 [CLAUDE.md](../../../../../CLAUDE.md) §11，**只有能完美判定的约束才许进 validator** —— 「这句译得对不对」显然不可机械判定，故**一个字都不进门**。只有两条进得去：

1. **反引号表达式存活** —— `en` 里 `` `dist_to_front<25` `` 这样的整段必须在 `zh` 里逐字出现。反引号在本语料里**专用于**守卫表达式与标识符（SPEC 第 3 条），从不用于普通英文短语，所以没有例外解释空间。
2. **阿拉伯数字存活** —— `en` 里每一串阿拉伯数字必须**整串**出现在 `zh` 里。这条靠 **SPEC 新增的第 10 条** house rule 才成为可完美判定的（数字照抄，不许改写成中文数字）；英文数词（`three`）不在管辖内。

**数字必须按整串比对，不许用子串** —— `25` 里含 `2`，子串比对会让「2 千米 → 两千米」这种真丢失被同段的 `dist_to_front<25` 掩盖掉。这不是假想：写第一版门时就踩了，反面测试当场抓出来。

**离线误伤面**（在**改动前**的 55 段上跑）：反引号 **27** 处（去重后）、阿拉伯数字 **67** 处（去重后），两条**各 0 拒**。也就是说这道门对现役语料是**零成本**的，它只防未来。

**量过、但决定不做的两条**（不要因为「实测 0 拒」就以为可以加）：

| 候选 | 实测 | 为什么不做 |
| :-- | :-- | :-- |
| `en` 双引号标签必须原样出现在 `zh` | 9 处 / **0 拒** | 英文双引号**不像反引号那样专用于标识符** —— 本语料里 9 处恰好全是信号 / 动作标签，但双引号在英文里也可以引普通短语，那时「必须不译」就是错的。现役 0 拒说明它今天成立，不说明它**必然**成立 —— 后者才是进门的条件 |
| `en` 句数与 `zh` 句数一致 | 55 段 / **0 不等**（剥掉行首编号与〔…〕后） | 「不等即错」不成立：缩写（`e.g.` `Dr.`）、省略号、以及〔…〕内部若出现句号都会让计数偏移，而那些都不是翻译错。判定还依赖「剥行首编号」这一步启发式（`4when` 与 `4. ` 两种写法都要处理），启发式不是完美判定 |

两条都改为写进本节的**人工复核清单**（§12.4 第 4、7 条）。

### 12.4 人工复核清单（改动任何一份 `zh` 后逐条过）

按后果排序，前三条最会翻转结论。

1. **否定词**：`not` / `no` / `never` / `without` / `unless` / `neither` —— 逐个在 `zh` 里点到落点。反向也要查：`zh` 里的「不 / 未 / 无 / 没有」是否都对得上 `en`（注意「不同」「无缝」「无人机」是词的一部分，不是否定）。
2. **情态动词强度**：`may`（可以）· `can`（能够 / 可以）· `must`（必须）· `shall`（应当）· `should`（应该）· `will`（将）。**有无本身就是判读依据** —— `nl_0006` 全篇零情态动词是该份最重要的观察之一（原文因此对「进入某状态后能否离开」保持沉默），译文多补一个「可以」就等于改了判据。反向同样查：`zh` 里的「可以 / 必须 / 应」是否都有 `en` 依据。
3. **条件与时序连接词**：`if`（如果）· `when`（当…时）· `while`（对比义「而」/ 时间义「期间」）· `until`（直到）· `once`（一旦）· `after`（之后）· `before`（之前）· `unless`。**`while` 与 `until` 混译会改变驻留义务** —— `nl_0004` 段 10 两者同现（`remains ... while nearing ..., until it is ready`），那一段务必单独点。同一份 NL 内同一个连接词必须同一译法（上面第 2 处就是这么查出来的）。
4. **量词与范围**：`all` / `any` / `some` / `each` / `every` / `only` / `at least` / `both` / `either ... or`。顺带查双引号标签是否原样保留（这条**没有**机械门，见 §12.3）。
5. **标识符与表达式**：反引号整段与阿拉伯数字有机械门兜底；门**不覆盖**的是单个首字母大写的名字（`Cancel` `Start` `Send` `Idle` `Operate`）与不带反引号的散文名（`formation adjustment state`）—— 它们既不匹配驼峰也不匹配下划线，必须手点。
6. **歧义有没有被消解**：SPEC 第 2 条要求**保留**歧义。若原文有两读而译文只呈现一读，即使选的那读更可能对，也要么改回歧义写法、要么在同段〔译者存疑〕里把两读都写出来。**理由必须来自原文** —— 拿「这一读超出本项目边界」当理由是不成立的（见 §12.2 未改第 6 条）。
7. **有没有整句 / 整从句漏译**：把 `en` 的句号数（剥掉行首编号）与 `zh` 的「。」数对一遍。这条**没有**机械门（见 §12.3），只能手数。
8. **`zh` 里的〔原文如此〕/〔译者存疑〕按 §11.5 全套再走一遍** —— 它们是**关于原文的可核验断言**，受 SPEC 第 9 条管辖，而词法门（`artifact_leaks` / `original_ref_errors`）**一条都不作用于 `zh`**。本轮 6 处改动里有 4 处就出在这里。特别是：① 单句上的「多出 / 唯一 / 一律」要在全份找反例；② 不要把**全语料通例**写成某一句的异常；③ 不许出现 `模型` / `制品` / `plantuml` 这些词（`zh` 无门，全靠手查）。
9. **术语同份一致**：与 `translator_notes` 的【译法一致性】/【建模术语译法】小节逐条对拍（上面第 1、6 处都是这么查出来的）。
10. 改完跑 `python3 -m pytest test_relabel.py -q` 与 `python3 generate.py`，再确认 54 份工作单的 diff **只**落在译文行上（FILL / 深读清单 / 裁决行必须零改动）。

### 12.5 这一轮核了什么、没核什么（不要把两者混为一谈）

**核过的**：55 段**全部**逐段对着 `en` 读过一遍，并按 §12.4 的九类逐类扫过；情态动词、否定词、条件连接词、标识符、阿拉伯数字四类另外用脚本做了**机械对拍**（脚本只用于定位，判定由人下）。

**没核的**（如实记）：

1. **中文用词的自然度与地道程度** —— 按 SPEC「通顺度让位于忠实度」，本轮**刻意不改**任何仅仅拗口的句子（改动 2 之后的「它可以一旦变道完成就返回 cruise」就很拗口，但它比原译更准）。
2. **术语括注的中文选词是否最优** —— 「闸片夹紧」「编队调整」「子机状态」一类只核了「不误导」，未核「是否领域最通行译法」。
3. **UML 领域断言** —— 与 §11.3 第 3 条同样的缺口：`zh` 里的 UML 相关元陈述（如 `entry` 为小写关键字）靠领域常识核过，未回查 UML 规范原文。
4. **「两种读法都能从字面支持」这类判断** —— 不可验算，只逐条读过一遍是否成立。
5. **§12.1 的「49 无误」是我的判定，不是机械结论** —— 无人类第二判读者复核，也没有第二个 LLM 独立重判；因此这个数只能读作「一轮全量单人核对后未再发现问题」，不是「已证明无误」。
6. **`zh` 里〔…〕之外的部分与 `note` 的交叉一致性** —— 本轮做了术语与元陈述两类对拍，未穷尽（例如某段 `note` 说「原文未给触发」而 `zh` 的措辞是否暗示了触发）。
