## §5 新增 issue 登记

把 §3 采纳的、§4 查出的、以及你自行发现的缺陷登记在这里。⭐ 登记区默认给两条，不够就照格式往下加（`NEW-0005-03`、`-04` …，编号连续即可）。

⛔ 登记前先过三道门：① 它在 $M = (S, E, V, Tr, A)$ 内吗（⛔ 无时钟 / 无并发）？② 它在**作者源**上成立吗（⛔ 不能只在投影上成立）？③ 它和 §2 已有条目是同一个缺陷吗（是则回 §2 走「修正」，⛔ 不要在这里新开一条）？

⚠️ 下面所有样例都取自现有台账 [expected_issue_set.json](../expected_issue_set.json) 的**真实条目**，⛔ 一条都没有编。⭐ 但样例会**避开本 pair 所属的 NL 组**（本 pair 属 `NL10`）—— 同一份 NL 生成 6 个制品，拿兄弟 pair 的缺陷当格式样例等于把答案先告诉你。

### §5.1 字段表（⭐ 你只填第一层）

| ⭐ 必填 | `nl_evidence` | NL 段 id；NL 未明说就写 `无` | ⛔ 不许留空（⭐ 写 `无` 才算判过） |

⛔ **为什么不让你填 `element_of_M`**：它只是对 `generated_side` 已经点到的那一处做分类，不带新信息。台账里同一个 `direction` 会落到 3 到 5 种不同的 `element_of_M`（`guard` 方向就横跨 `Tr` / `A` / `S` / `E` / `V` 五种），手填只会引入噪声。⭐ `derive()` 改从你给的**作者源行号**反查那一行是状态声明、迁移还是状态动作 —— 那是确定性的。⭐ 所以 `generated_side` 里**带上行号**比写元素名更有用。

### §5.2 逐字段怎么填

#### `statement` ⭐ 必填

⭐ 写**缺陷是什么**，不是写「哪里不一样」。判据：读完这一句，另一个人能不能独立到作者源上复核它成立与否。⭐ 现有条目的写法是审阅 agent 的 `reason` 逐字，可以照那个密度写。

真实样例（`EIS-0040-01`，`hierarchy` / `nl_contradiction`）：

> 自动驾驶激活期间无法断电，NL 第5句断电义务只覆盖一半作用域（参考两边都有）。

⚠️ **写成一段，⛔ 不要换行**。回收器只把 `statement` / `generated_side` / `nl_evidence` / `direction` / `depth` / `reference_side` / `primary_predicate` / `layer` 这几个名字当作新字段起点，其余行都会并进当前字段 —— ⭐ 所以你可以在 `statement` 里放冒号、放引文，⛔ 但请别自己起一个像字段名的行。

#### `generated_side` ⭐ 必填

⭐ 指到**作者源 PlantUML 的具体一处**：优先写 §1.3 的行号（写 `:12` 或 `第 12 行`），再附上那一行的元素名或原文片段。⭐ 缺失类缺陷写「（无此边）」这类否定描述也算合法 —— 台账里就有。

真实样例（`EIS-0042-01`）：`[*] --> Off : keyOff`

⛔ 带行号才能让 `derive()` 推出 `element_of_M`；只写元素名时，只有你同时填了结构族 `primary_predicate` 才推得出来。

#### `nl_evidence` ⭐ 必填（⭐ 但「写 `无`」是合法答案）

⭐ 写本 pair §1.2 表里的**段 id**（如 `NL-L001`），多个用逗号分隔，后面可以再跟一句逐字引文。

⛔⛔ **写 `无` 是有意义的答案，⛔ 不是偷懒** —— 它表示「NL 未明说，本条属模型内生问题」。现台账 **30 / 98** 条正是这种情况（合式性层按定义就不要求 NL 依据）。⛔ 但**留空**不等于 `无`：留空会被校验判成没填。
