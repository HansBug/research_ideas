# 条目数的唯一权威口径：**323**

⛔⛔ **先记住一句话：`323` 是工作单的条目数；`380` 不是。** ⚠️ 2026-08-16 一天之内因为混淆这两个数改错了两次，一次让 5 条条目在 md 里彻底消失、一次把 56 条已去重的重复重新摆了出来。本文把账算死，⛔ 以后任何涉及「总数」的改动都必须先读这一页。

## 一、四个数，各是什么

| 数 | 含义 | 去重了吗 | 落在哪 |
| --: | :-- | :-- | :-- |
| **380** | 过了**三方 D 档判读**的条目 | ⛔ **没有** | [dtier_rulings_deduped_out.json](./dtier_rulings_deduped_out.json) 的 57 条 + [dtier_rulings.json](./dtier_rulings.json) 的 323 条 |
| 61 | 重叠分析判定「与另一条是同一个问题」的 `INS-` | — | `inspect_overlap` 的 `overlap_kind ∈ {ledger, candidate}` |
| **57** | 其中**真正的重复**（宿主仍在，或本轮重新归属后并入同伴） | — | [dtier_rulings_deduped_out.json](./dtier_rulings_deduped_out.json) |
| **323** | ⭐⭐ **工作单条目数 = 380 − 57** | ✅ **是** | [dtier_rulings.json](./dtier_rulings.json) · 54 份工作单的 `### <id>` 块 |

前缀分布（323 条）：`EIS 99` · `INS 132` · `DIFF 77` · `VU 15`。

## 二、61 → 57 是怎么来的

61 条里有 **5 条的宿主是 `UM-*`**，而 `UM-` 一族已于 2026-08-16 [整批撤出](../../docs/findings/um_residue_ruling.md)。

⚠️ 关键在于：`UM-` 一条 **= 一个 pair 的整张未匹配表**，所以「与 `UM-0050` 重复」只表示「落在那张表的某一组里」，⛔ **不表示它与另一条独立候选重复**。宿主撤掉之后，真正要回答的是：**这 5 条彼此之间有没有重复。**

逐条裁定在 [um_orphan_rehost.json](./um_orphan_rehost.json)，判据是 ⭐ **「一次修复是否同时消掉两条」**（⛔ 不看措辞相似度 —— 两条 issue 字面接近不等于陈述同一个缺陷）。结论：

| 条目 | 处置 | 依据 |
| :-- | :-- | :-- |
| `INS-0050-01` | ⭐ 自立宿主 | 根层初始边 `:3 [*] --> HumanDrivingMode : Power On` 带标签；与子态链问题没有共同修复 |
| `INS-0050-02` | ⭐ 自立宿主 | 子态链 `SubState1→2→3`（`:10`/`:11`）无触发、三个空壳子态被瞬时穿过 |
| `INS-0050-03` | ⛔ 并入 `INS-0050-02` | **同一条链的第四条边** `:12 SubState3 --> [*]`；⭐ 它自己引的就是同一个簇 `0050-3` 的同一句「四条边均无触发与守卫」。两条三方判读均 `D0+D0+D0`、推荐均「不采纳」，⭐ 合并不改变任何裁决结果 |
| `INS-0032-04` | ⭐ 自立宿主 | 原本独占 `UM-0032` 内一个组，无同伴可判重 |
| `INS-0056-01` | ⭐ 自立宿主 | 原本独占 `UM-0056` 内一个组，无同伴可判重 |

于是 `61 − 5 + 1 = 57`（5 条脱离原宿主、其中 1 条重新并入同伴）。

## 三、⛔ 三条硬规矩

### 1. 「找得到 / 对得上账」与「有独立裁决区」是**两件事**

⚠️ 这是两次改错的共同根因。

- **找得到** → 被并入项的 **id 必须印在宿主的补充证据行里**：`- **补充证据（\`INS-0050-03\`，与本条判为同一个问题）**：…`。⭐ 于是 `grep INS-0050-03` 找得到，「搜不到」与「不存在」不再混淆。
- **对得上账** → `323 = 380 − 57`，由 [test_relabel.py](./test_relabel.py) 的 `test_the_dedup_is_not_undone` 双向钉住。
- **有裁决区** → ⛔ **只有那 323 条**。被判重复的一条都不设，⚠️ 不拿去让人裁决。

### 2. ⛔ 「不重复出块」不等于「把证据删掉」

⚠️ 实测栽过：把 `INS-0050-03` 改成不出块之后，它的事实在 md 里一个字都不剩 —— 因为 `_supplements()` 当时只接在**台账**描述上，⛔ 没接在 `INS-` 宿主上。⭐ 被并入项的 `statement` 必须完整印进宿主块，⛔ 一个字都不许省。

### 3. ⛔ 判读结论与宿主不同时，**在宿主那一行点出来**，但仍然只裁一次

8 条并入项自己的三方推荐与宿主不同（例：`INS-0040-02` 推荐 `D1`，宿主 `EIS-0040-03` 推荐 `D2`）。⭐ 补充证据行会追加一句「⚠️ **它的独立判读与本条不同**：…」。⛔ 那是提示，不是第二个裁决区 —— 同一个问题只裁一次。

## 四、两次改错的经过（⛔ 别再走一遍）

| 版本 | 做法 | 后果 |
| :-- | :-- | :-- |
| ⛔ 第一版 | 按「已并入宿主」跳过全部 61 条 | ⚠️ 漏了「宿主自己被撤了」这一种：5 条既无块、也无宿主，**在整份 md 里一个字都不出现**；⛔ 而速览行还点名说它们「需你处理」，按 id 去搜搜不到（`INS-0050-01`） |
| ⛔ 第二版 | 改成「每条判读都出块」，让块数等于 `380` | ⛔⛔ 那是把块数对到了一个**未去重**的数上 —— 按构造必然把 56 条真重复重新摆出来。实测 `0010` 上同一个缺陷出现三次：`EIS-0010-03` + `INS-0010-01` + `INS-0010-02`，⚠️ 而后两条自己就写着「见 `INS-0010-01`」，补一条 `AutonomousFinal --> [*]` 三条一起消失 |
| ⭐ 现行 | 去重后 `323` 条出块；被并入项只印 id + 事实到宿主 | ⭐ 两个诉求同时满足：搜得到、账对得上、⛔ 且不会被要求裁决重复项 |

## 五、⭐ 改动前的自检清单

动任何与「条目数」有关的代码前，逐条回答：

1. 我要对齐的那个数，**去重了吗**？（`380` 没有；`323` 有）
2. 我让某条不出块，它的 **id 还搜得到吗**？它的**事实还印着吗**？
3. 我让某条出块，它会不会与已有条目**说的是同一个缺陷**？（判据：一次修复是否同时消掉两条）
4. 速览行点名的每一条，工作单里**真的有那个块吗**？
5. 改完跑 `test_the_dedup_is_not_undone` 与 `test_relabel.py` 全量。
