## 用途（⭐ 决定一切取舍）

译文给**人工判读状态机缺陷**用——⭐ 读者要拿它和 PlantUML 模型逐条比对、判断模型是否符合规约。⛔ **不是给人读着舒服用的。**

## ⛔ 八条硬纪律

1. ⭐ **严格直译**。⛔ 不意译、⛔ 不润色、⛔ 不调整语序求通顺、⛔ 不补原文没有的信息（⛔ 包括不补主语、不补量词、不补逻辑连接词）。
2. ⛔⛔ **保留原文的模糊性**。⚠️ 原文若有歧义，⛔ **译文必须同样有歧义**——⛔ 不许替它消歧。
   - ⭐ 例：`when power on, the system turn into human driving mode` 没说是"首次上电"还是"任意时刻上电"——⛔ 译文也不许挑一个。
3. ⭐ **状态名 / 事件名 / 变量名 / 守卫表达式一律保留英文原样**，⛔ 不翻译、⛔ 不加引号、⛔ 不改大小写。
   - ⭐ 例：`HighwayMode`、`dist_to_front<25`、`auto_finished=true` 原样。
4. ⭐ **建模术语保留英文并在紧跟的括号里给中文**：`simple state`（简单状态）· `sub machine state`（子机状态）· `orthogonal region`（正交区）· `substate`（子状态）· `pseudostate`（伪状态）· `guard`（守卫）· `trigger`（触发）· `composite state`（复合状态）。
   - ⚠️ **同一术语在同一份 NL 里译法必须一致。**
5. ⚠️ **原文的语法 / 拼写 / 数格错误照直译，⛔ 并在该句译文末尾加 `〔原文如此：<具体错在哪>〕`**。
   - ⭐ 例：`There are three region` → `本图中有三个 region（区）〔原文如此：region 未用复数〕`
   - ⭐ 例：`the system turn into` → `系统 turn into（转入）〔原文如此：turn 与主语 the system 主谓不一致〕`
6. ⛔ **句子编号、标点、空格照抄**。⭐ 原文行首是 `1.` 就写 `1.`，是 `1 ` 就写 `1 `。
7. ⚠️ **拿不准就标注，⛔ 不要蒙**：`〔译者存疑：<你的疑问>〕`。
8. ⛔⛔ **`note` 与 `translator_notes` 只能讲原文，⛔ 一个字都不能讲模型制品。**
   - ⭐ 允许写：原文这一句说了什么、没说什么、有几种读法、哪个槽位空着、用词与标点异常、术语在本份 NL 里怎么用。
   - ⛔ **禁止**写：「模型里有 / 没有 X」「$A$ 中无 Y」「不存在以 Z 为目标的迁移」「模型把它建成…」「模型补出了…」「模型记作…」「第 N 行是…」、任何制品文件名（`plantuml.puml` 一类）、以及任何**原文没有点名**的标识符（`InitialState`、`FormationAdjustment` 一类）。
   - ⭐ **理由（⛔ 不是洁癖）**：一份 NL 对应 **6 个 pair**，6 份制品各不相同，而译文按 NL 分组、被逐字印进 6 份工作单。⛔ 因此一句关于制品的话，对其中 5 份必然是假的。2026-08-13 的审计实测：79 条可核验的制品断言里 **68 条（86%）** 在至少一个兄弟 pair 上为假，波及 **40 份工作单**；⛔ 最有害的是「不存在」型断言，它会把判读者的结论直接反过来。
   - ⭐ **欠指定该怎么写**：「原文未给该迁移的触发条件」「全篇无情态动词」「单位未声明」这类**关于原文**的观察是判读的核心材料，⭐ **必须留**。⛔ 要剥掉的只是「拿制品当证据」的那半句。若某处非要读者去看制品才能定论，就写「⭐ 须自行到 §1.3 核对」，⛔ 不要代为回答。
   - ⚠️ **机械门**：[../nl_zh.py](../nl_zh.py) 的 `artifact_leaks()` 在装载期检查两条**词法**判据 —— ① 提示不得含 `模型` / `制品` / `生成侧` / `参考侧` / `作者源` / `plantuml` / `puml` / `fcstm`；② 提示里出现的驼峰或下划线标识符必须在本份 NL 的 `en` 里逐字出现过。⛔ 违反即抛 `NoteArtifactLeak`，工作单生成不了。⭐ 这两条只覆盖词法部分，⛔ 语义部分（不含上述词却仍在断言制品）靠本条纪律与人工评审，⛔ 门过了不等于合规。

## ⭐ 额外要求：**逐句给出判读提示**

⭐ 除译文外，对**每一句**再给一条 `note`，只写下面三类中**实际存在**的（⛔ 没有就留空）：

- ⭐ **该句对哪一类元素提出了要求**（⭐ 状态 / 迁移 / 事件 / 变量 / 层次 / 初始点）——⛔ 写的是「原文要求了什么」，⛔ **不是**「某一份制品里那个元素长什么样」（见第 8 条）
- ⚠️ **该句的歧义点**（⛔ 若有）——⭐ 这直接决定判缺陷时能不能算"违反"
- ⛔ **该句在建模对象边界之外的部分**（⛔ 本项目边界：$M = (S, E, V, Tr, A)$，⛔ **无时钟、无并发**）——⭐ 例如 `concurrent activation`、`orthogonal region` 的并发语义、秒级时间约束

## 输出格式（⛔ 严格 JSON，⛔ 写到指定文件）

```json
{
  "nl_id": "<给你的编号>",
  "sha8": "<给你的 sha8>",
  "segments": [
    {"seg": "1", "en": "<原文逐字>", "zh": "<中文严格翻译>", "note": "<判读提示，可为空串>"}
  ],
  "translator_notes": "<整份 NL 层面的观察：术语表、反复出现的歧义、原文质量问题>"
}
```

⛔ **`en` 必须与原文逐字节一致**（⭐ 含行首编号与尾部空格），⭐ 便于机械回填校验。
