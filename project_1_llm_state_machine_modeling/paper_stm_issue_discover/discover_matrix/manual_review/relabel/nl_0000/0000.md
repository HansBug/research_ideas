### EIS-0000-01 ✅

**问题类型**：`element`（单元素） · `transition`（迁移） · `other`（其他） · `requirement`（需求文本）
- `other` 说明：涉及多个：这一条捆了两次互不相同的编辑——把边的源端由伪初始改成运行态，以及把目标 `FinalState` 由普通命名状态改成终态伪状态。单取 `incorrect` 只能装下其中一次。
- 归类依据（原文逐字）：生成制品里 Power Off 的源端是顶层伪初始，任何运行态（HumanDrivingMode / AutonomousMode）都没有断电出边

**问题描述**：NL 第5句要求运行中的系统在断电时进入终态。生成制品里 Power Off 的源端是顶层伪初始，任何运行态（HumanDrivingMode / AutonomousMode）都没有断电出边；顶层同时存在 `[*] --> HumanDrivingMode : Power On` 和 `[*] --> FinalState : Power Off` 两条初始边，冷启动时给出 Power Off 会直接落到 FinalState（等于没开机就关机）；而 FinalState 只是普通命名状态、无出边，模型永远不会真正 terminate。此外这是**论文自己的语法修复阶段引入**的：workbook 列 I（Phase-I 原始生成）写的是 `HumanDriving --> FinalState : Power Off`（语义正确，但因嵌在 `state HumanDriving { ... }` 体内而结构违法，被记为语法幻觉 "transition does not connect two state"），列 Z（语法检查后）把源端改成 `[*]`，语义随之被破坏；列 AD（语义幻觉）为空、AG 语义 resolved 记 1.0，说明该注入缺陷未被后续语义检查捕获。对照 0030：同一份 NL 下 Phase-I 同样出现 `[*] --> FinalState : Power Off`，论文语义栏把它记为 "missing final state" 并改成 `HumanDriving --> [*] : Power Off`；同一缺陷形状在同一 NL 的两个 case 上一个被抓一个被漏，说明语义检查不可复现。

**问题类型**：`element`（单元素） · `trigger`（触发事件） · `other`（其他） · `requirement`（需求文本）
- `other` 说明：涉及多个：多个事件被塌缩成一个泛化标签，修复要删掉这条标签、再拆出多条边与多个触发，不是一次编辑。

### INS-0000-04 ✅

**问题类型**：`element`（单元素） · `trigger`（触发事件） · `extraneous`（多余） · `language`（语言规则）

**问题描述**：根复合态没有**无条件**默认入口：全文件根层的 `[*] -->` 只有两条，stm0.puml:2 逐字 `[*] --> HumanDrivingMode : Power On` 与 stm0.puml:14 逐字 `[*] --> FinalState : Power Off`，**两条都带标签**。UML 2.5.1 规定初始伪状态的出边不得带 trigger / guard，故这台机器没有无条件起点 —— 事件不来就不进入任何状态。⚠️ stm0.puml:8 ` [*] --> AutoNavigating` 确实是一条裸初始边，但它属 `AutonomousMode`（:7-:10 块内），不计入根层。⭐ 同型形态在同组另外三份制品上都已作为条目摆出（INS-0030-01 / INS-0040-01 / INS-0050-01），本条恢复后四份可横向对比。
