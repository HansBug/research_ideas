### §5.2 登记区

⭐ 直接在下面的块里填。⛔ 只有 `FILL:BEGIN` / `FILL:END` 之间的内容会被 [collect.py](../collect.py) 收走，块外写的东西重跑生成器就没了。

⭐ **下面五张表把五个勾选字段的取值全列在这里** —— ⛔ 填表不必再翻 [HOWTO.md](../HOWTO.md)（那一页仍是总说明，⭐ 想看「为什么这么分」再去读）。⚠️ **勾选行里的取值请保持英文原样**：校验器逐字比对，⛔ 在方括号里加中文会被判成非法取值。

⭐ ② 依据层 · `basis`（依据来源，⭐ 4 选 1，⛔ 必填）：

| 取值 | 什么时候勾它 |
| :-- | :-- |
| `NL显式义务` | NL 里有一句**说清楚了**的义务（源状态 / 触发 / 目标 / 守卫 中该有的都有），而模型没做到。⭐ 这是最硬的 NL 依据，⛔ 必须给出段 id。 |
| `NL欠指定` | NL 里**有**相关句子，⛔ 但那句话把关键槽位空着（不写源状态 / 不写触发 / 并列项无连接词 / 无情态动词），因此它**支撑不起「模型违反了它」**。⭐ 仍然登记，⛔ 但结论只能写成「原文未规定，模型自行选择了一种读法」，⛔ 不得写成「违反」。见 [README.md](../README.md) §7.2 的七种欠指定形态。 |
| `模型自身` | ⭐ 不看 NL、不看参考模型，只读作者源就能判定（良构性）—— 如引用了未声明的元素、复合态无区域初始边、吸收态。⭐ `nl_evidence` 写 `无` 即可。 |
| `参考模型` | ⛔ **只有**参考模型那样建、生成侧没那样建。⚠️ 参考模型**不是正确答案**（§1.4 与 README §二.3），⛔ 故这一种依据**单独不足以**支撑一条缺陷；⭐ 选它等于说「本条待裁定」，请在 `statement` 里写明还缺什么才站得住。 |

⭐ ③ 边界层 · `scope`（边界，⭐ 4 选 1，⛔ 必填）：

| 取值 | 判据 |
| :-- | :-- |
| `界内` | ⭐ 主张只涉及 $S$ / $E$ / $V$ / $Tr$ / $A$ —— 状态、事件、变量、迁移、动作与层次。 |
| `越界·时钟或不变式` | ⛔ 主张成立与否需要时钟变量 $C$ 或状态不变式 $Inv$：「N 秒后应当迁移」「该状态最长驻留 T」「进入时须满足某不变式」。 |
| `越界·并发或正交区` | ⛔ 主张需要并发语义：fork / join 伪状态、「两个区域是否同时活跃」、区间同步。 |
| `越界·其他` | ⚠️ 确属 $M$ 之外但不属上面两类。⛔ 请在 `statement` 里写清越在哪里 —— 这一档若堆积，说明边界定义本身需要复查。 |

⭐ ④ 分类轴 · `direction`（缺陷方向，⭐ 8 选 1，⛔ 必填，归不进就选 `unclassified`）—— 括号里的条数是台账现状，⭐ **数字越小的方向越可能是台账的盲区**：

| 取值 | 台账条数 | 指什么 |
| :-- | --: | :-- |
| `hierarchy`（层次归属） | 21 | 层次归属：谁该是谁的子态、复合括号有没有打开 |
| `reachability`（可达性与终止） | 18 | 可达性与终止：进得去 / 出得来 / 停得下 |
| `entry`（初始入口） | 18 | 入口：初始边、初始目标、进入某状态时落到哪 |
| `guard`（守卫与条件） | 17 | 守卫：条件写没写、写对没写对、能不能区分多条出边 |
| `effect_action`（效应与状态动作） | 10 | 效应与状态动作：entry / exit / 迁移效应 |
| `event`（事件与触发） | 4 | 事件：触发词缺失、拼错、被并成一个复合名 |
| `cardinality`（元素数量） | 4 | 基数：NL 点名了 N 个而模型给了 M 个 |
| `unclassified`（未归类） | 6 | 以上都归不进（⭐ 归不进本身值得在 statement 里说明） |

⭐ ④ 分类轴 · `depth`（深度，⭐ 3 选 1，⛔ 必填）—— 判据是**读懂它需要看几个地方**：

| 取值 | 判据 |
| :-- | :-- |
| `表层` | 一处即可：单点存在性 / 拼写 |
| `中层` | 两处之间的关系 |
| `深层` | 需沿执行路径推理、或跨多个状态比对；隐含冲突；运行时后果 |

⭐ ⑤ 可留空 · `layer`（归因层，⭐ 4 选 1）—— ⛔ 判据是台账 `layer_basis` 的**逐字原话**。⚠️ 勾了 `wellformedness` 之外的任何一层，`nl_evidence` 就**不能**写 `无`：

| 取值 | 台账条数 | 判据原话 |
| :-- | --: | :-- |
| `wellformedness`（良构性） | 27 | 模型自身即可判定，不需要 NL 也不需要参考模型 |
| `nl_named`（NL 点名） | 52 | NL 点名了那个缺失或错位的元素 |
| `over_specification`（过度指定且有害） | 6 | 生成方凭空多出，且造成可断言的负面后果 |
| `nl_contradiction`（与 NL 矛盾） | 13 | 与 NL 的显式义务矛盾 |

⭐ ⑤ 可留空 · `primary_predicate`（主谓词）—— 19 个封闭谓词，⭐ **写 `无` 本身就是发现**（说明词表覆盖不到这个缺陷；台账已有 **11 / 98** 条如此）。⛔ 中文是对官方 `meaning` 的翻译，⭐ 英文原话一并给出以便复核：

| 族 | 谓词 | 一句判据 | 官方原话 |
| :-- | :-- | :-- | :-- |
| S 结构族 | `state_declared` | 模型在该路径上声明了一个该种类的状态 | `the model declares a state at this path, of this kind` |
| S 结构族 | `variable_declared` | 模型以该名字声明了一个**作者自己的**变量 | `the model declares a variable of the author's own under this name` |
| S 结构族 | `event_declared` | 模型在该限定路径上声明了一个事件 | `the model declares an event at this qualified path` |
| S 结构族 | `containment` | 该子态是（或不是）该父态的子状态 | `this child is (or is not) a substate of this parent` |
| S 结构族 | `initial_target` | 进入该复合态时从该子态开始 | `entering this composite starts in this child` |
| S 结构族 | `edge_declared` | 模型声明了一条以该源、该触发、该目标构成的迁移 | `the model declares an edge with this source, trigger and target` |
| S 结构族 | `effect_declared` | 该迁移声明了对该变量、朝该方向的效应 | `this transition declares an effect on this variable, in this direction` |
| S 结构族 | `action_declared` | 该状态声明了一个 `entry` / `exit` / `during` 阶段的动作 | `this state declares an entry, exit or during action` |
| S 结构族 | `guard_distinguishable` | 共享同一源与同一触发的两个目标，⛔ 不会无法区分地同时可达 | `a shared source and trigger cannot reach two targets indistinguishably` |
| S 结构族 | `cardinality` | 该作用域恰好声明了这么多个非伪状态 | `this scope declares exactly this many non-pseudo states` |
| B 行为族 | `occupancy_after` | 从该状态施加该触发之后，系统身处该目标态 | `after this trigger from this state, the system is in this target` |
| B 行为族 | `event_consumed` | 在该配置下该事件确实被消费 | `in this configuration the event is actually consumed` |

| P 性质族 | `invariant` | 在界内该条件始终成立 | `within the bound this condition always holds` |
| P 性质族 | `response_within` | 该触发每次出现都在界内得到回应；`response` 填的是算作回应的**状态路径**，⛔ 不是表达式 | `` every occurrence of this trigger is answered within the bound; `response` is the state path that counts as the answer, not an expression `` |
| P 性质族 | `persists_until` | 该状态持续保持，直到该释放条件成立 | `this state holds continuously until this release condition` |
