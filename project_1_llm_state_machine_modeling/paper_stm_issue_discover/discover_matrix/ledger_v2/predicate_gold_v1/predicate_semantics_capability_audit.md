## Contract Findings

### CAP-R1-STEP-DISCONNECTED: Registry step is not consumed by the trajectory backend

Result: `FAIL`; severity: `HIGH`; resolution: `CONTAINED_BY_GOLD_PROTOCOL`.

run_trajectory chooses scenario.selected_step and never reads plan.inputs['step']; changing the schema field cannot select a different observation macrostep.

Gold impact: A Track B row cannot claim the plan-level step independently controls R1. A selected R1 proposal must freeze the same selected_step inside its source-provenanced scenario or be unsupported.

Containment: The gold protocol treats plan.inputs.step as redundant provenance only, requires selected_step in the immutable scenario, and rejects rows whose source-based selected step cannot be represented there. Frozen runtime is not modified.

### CAP-S6-ONE-EFFECT: Effect-set contract collapses to one effect

Result: `FAIL`; severity: `HIGH`; resolution: `CONTAINED_BY_GOLD_PROTOCOL`.

The backend rejects any effect tuple other than one string and then checks membership of that one parsed operation.

Gold impact: A row may select S6 only for one exact parseable effect; it cannot use S6 as evidence for a required set, ordered sequence, or composite effect obligation.

Containment: Track B marks multi-effect obligations unsupported or considers a clearly labeled non-exact proxy; exact S6 candidates carry exactly one typed effect. Frozen runtime is not modified.

### CAP-V1-GUARDS-HIDDEN: Runtime requires a guard multiset omitted from the registry contract

Result: `FAIL`; severity: `HIGH`; resolution: `CONTAINED_BY_GOLD_PROTOCOL`.

V1 backend rejects input unless supplied guards exactly equal the native choice-group guard multiset.

Gold impact: A proposal cannot present the registry-visible three fields as complete executable binding; it needs a source-provenanced complete guard multiset or must be unsupported.

Containment: Gold protocol requires explicit complete group guards as additional provenance, preserves the mismatch in the audit, and rejects exact V1 assignment when the complete native group cannot be independently bound. Frozen runtime is not modified.

## Boolean Boundary

A backend result counts only when the receipt is terminal `completed` with Boolean `true` or `false`. Invalid input, unsupported backend, timeout, worker failure, solver failure, and replay mismatch are not `false`.
