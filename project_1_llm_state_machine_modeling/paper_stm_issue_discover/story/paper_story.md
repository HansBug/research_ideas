## 1. Thesis

【AI 建议·待确认，但与导师定调不冲突】

给定一份自然语言需求 `NL` 与一份由 LLM 从该需求生成的状态机模型 `STM_0`，
**把「这个模型哪里不符合需求」变成一个可机械求值的问题**：
先把需求全覆盖地拆成一条条义务，再把每条义务转换成一个受限谓词逻辑上的断言，
在被评审模型上求值——为假者构成一条**带可执行判据与闭合证据链**的发现，
为真者构成**回归防护**。

一句话：**本文贡献的是一套谓词逻辑元模型与断言体系，而不是「我们发现了多少问题」。**

---

## 2. 解决什么问题

【AI 建议·待确认】

LLM 已经能从自然语言需求生成状态机式制品，但生成出来的东西**不能直接用**——
它可能漏掉需求点名的状态、把条件写成事件、把并列条件压成一个名字、
留下进不去的状态或没有默认入口的复合态。于是问题从「能不能生成」变成
**「怎么知道生成的这一份哪里不对」**。

这不是一个「跑个检查器」的问题，原因有三层：

1. **判据从哪来**：需求是散文，模型是图；「模型是否满足需求」不是一个现成的形式化判定问题，
   得先把散文里的义务抽出来，再决定每条义务用什么可判定的形式表达。
2. **表达什么才算表达对了**：同一条义务有多种操作化，其中一部分是**伪代理**——
   「某条迁移是否存在」冒充「某个状态是否可达」就是典型：边存在不等于可达（守卫可能恒假、
   源态可能不可达），边不存在也不等于不可达（可经其它路径）。形式相似而实质不同。
   【仓库裁定】该替换已被明令禁止，见
   [../discover_matrix/docs/protocol/hit_criterion.md](../discover_matrix/docs/protocol/hit_criterion.md)。
3. **行为性问题在图上没有定义**：PlantUML 是绘图记法，不定义执行语义——
   「从上电起 3 步内能否到达 X」在它上面不是难以回答，是问题本身没有定义。

## 3. 为什么这个问题有价值

【AI 建议·待确认】三条，按对审稿人的说服力排序：

1. **它是 LLM 建模落地的必经关口。** 控制系统的状态机模型下游要接模型检查、
   测试生成、代码生成；一个「看起来像状态机」的制品进入下游，错误会被放大而不是被发现。
   而人工逐份复核 LLM 生成的模型，成本与直接手写模型相当——那样 LLM 就没有意义了。
2. **它的产出形态决定了下游能不能用。** 见 §4。
3. **它是可累积的。** 断言一旦成立就可以反复求值。模型改一次，整套断言重跑一次——
   这是「一次性评审」变成「持续防护」的分界。

## 5. 我们的方法：核心洞察

### 5.1 受限谓词词表本身就是一次建模

【导师原话背书】**这是本文最核心的判断。**

不给 LLM 一个通用工具箱让它自己摸索，而是**先把「一个状态机模型可能在哪些方面不符合需求」
这件事建模一遍**，结果是一个 **19 个谓词的闭合词表**。【v46 实测】词表按求值机制分三族：

| 族 | 个数 | 回答什么 | 谓词 |
| :-- | --: | :-- | :-- |
| 结构 | **10** | 模型里写没写 | `state_declared`、`event_declared`、`variable_declared`、`edge_declared`、`containment`、`initial_target`、`effect_declared`、`action_declared`、`guard_distinguishable`、`cardinality` |
| 仿真 | **6** | 跑起来会怎样 | `reaches`、`occupancy_after`、`event_consumed`、`stays_in`、`terminates`、`variable_delta_after` |
| 有界模型检查 | **3** | 界内是否恒成立 | `invariant`、`response_within`、`persists_until` |

这个词表干了三件事，缺一不可【AI 建议·待确认】：

1. **它是一次领域建模**——把控制系统需求里反复出现的义务模式（可达、驻留、事件响应、
   效果方向、覆盖）固化成有限个可判定形式。
2. **它约束了 LLM 的输出空间**——LLM 不再自由发挥，只做「把这条义务映射到哪个谓词、
   绑哪些元素」这一件事。
3. **它让测不了的东西显式暴露**——义务无法用这 19 个谓词表达时，系统必须记为覆盖缺口，
   不许换个近似谓词蒙混过去。

### 5.2 ⚠️ 词表的由来：论文怎么写（承重结构）

【导师原话】

> 「**规则一定是从领域分析归纳出来的，应用在 54 个案例中**」
>
> 「**基于所归纳的规则，指导了 prompt 设计，这个逻辑能说通**」

【仓库裁定】由此确定的口径：**从领域分析、真实文献与技术资料调研归纳而来，应用于 54 个案例，
并据此指导 prompt 设计。**
⛔ **不表述为「从这批 pair 归纳」。**
⛔ **不在论文里解释留出集**——「为什么不留出」在本方法的论证结构里根本不出现。
工程侧四条配套要求见
[../discover_matrix/docs/protocol/method_provenance_policy.md](../discover_matrix/docs/protocol/method_provenance_policy.md)。

【v46 实测】已经挂上出处的两个示例可直接写进论文：

- **`stays_in`** ← UML 2.5.1 §14.2.3.9.1 的 run-to-completion 规则：一个在当前配置下不触发
  任何迁移的事件会被**丢弃**，而丢弃不改变配置。**所以「事件有没有被消费」与「机器有没有
  离开」是两个独立问题**——该谓词不能用前者近似后者。
- **`persists_until`** ← 时序逻辑中 until 的标准定义：`p U q` 只约束 `q` 首次成立**之前**的
  前缀；「整个区间上 `p` 或 `q` 恒成立」是一个严格更强的不同公式。有界情形取弱形式，
  界内既未释放也未违反的运行不算反例。

⚠️【v46 实测】**当前只有 15 处规则挂了出处注释，19 个谓词未逐条挂钩**——这是已登记的工程欠账。

### 5.3 断言由全覆盖的需求拆分转换而来，因而天然具备覆盖性

【导师原话背书】流程不是「让 LLM 读模型找问题」，而是**先读需求**：把需求原文全覆盖地拆成
义务，再逐条转换成断言。这条顺序有两个直接后果【AI 建议·待确认】：

1. **覆盖性来自构造，不来自运气**——分母是需求的义务集，不是模型的可疑点集。
2. **每条发现天生带上下文**——它知道自己来自需求哪一句、绑在模型哪个元素、
   用哪个谓词以什么参数求值为假。§4 的三条 gap 由此同时被填。

### 5.4 阶段化 + 定向反馈的循环

【v46 实测】八个阶段，每个产出阶段配一个审查者，不合格带**定向反馈**打回重写：

```
需求 + 模型 → ① 需求拆分 → ② 需求审查 ⟲ ①
            → ③ 断言转换 → ④ 静态预检 ⟲ ③ → ⑤ 断言审查 ⟲ ③
            → ⑥ 求值发布 → ⑦ 归因绑定 → ⑧ 结果裁决 → 发布 issue
```

⚠️ **循环发生在审查者与被审查者之间，不是重试**：审查者说清哪一条不合格、缺什么、
期望什么形状，被审查者据此修订。**这一点必须与「换个随机数再跑一次」明确区分**，
否则整个循环的贡献会被读成「多采样几次」。

⚠️ **⑥ 的求值不看需求也不看参考模型，只看被评审模型本身**，所以它的真值是客观的、可复算的。
求值层允许**拒答**：谓词无法给出可靠真值时返回拒答而不猜真假。

### 5.5 为真的那部分不是废料

求值为真的断言构成**回归防护**：它们记录了「这份模型在这些义务上是对的」。
模型改动后重跑，为真变为假即为回归。

⚠️【待定】这条目前是**方法性质的主张，不是实测结论**——v46 未统计防护面规模。
见 [claim_evidence_map.md](./claim_evidence_map.md) C13。

## 6. 任务边界

> 本节吸收了上一版独立的 `task_boundary.md`，去向说明见 [README.md](./README.md) §3.1。

### 6.1 任务定义

```text
输入：<NL, STM_0>
      NL    自然语言需求原文
      STM_0 一份由 LLM 从该需求生成的状态机模型（PlantUML）

产出：<已发布的 issue 清单,
       支撑每条 issue 的可执行断言,
       一条可回溯到 NL 原句与模型元素的证据链,
       求值为真的断言构成的回归防护面,
       未能表达的义务所对应的覆盖缺口>
```

**任务是发现，不是修复。**【导师原话】

### 6.2 输入与两条硬约束

| 输入 | 说明 | 纪律 |
| :-- | :-- | :-- |
| `NL` | 控制系统自然语言需求原文 | **义务的唯一来源**。需求层主张必须能引到具体哪一句 |
| `STM_0` | 被评审模型，PlantUML | **唯一的求值对象**。判定表示债务时必须回读它，不读编译产物 |
| 溯源元数据 | 取自上游数据表的哪一行哪一列、生成它的是哪个 LLM、原始文件 SHA-256 | 支撑可复现性 |

⛔【仓库裁定】**参考模型不是输入。** 上游论文作者为每份需求人工撰写的参考模型，
**只在人工标注缺陷台账时使用**；方法全程不接触它。这保证方法不是在「对答案」。

⛔【仓库裁定】**缺陷台账不是输入。** 台账只在评测侧使用，且只在图终止之后用于审计；
运行时不得进入任何 prompt、schema 或门。

### 6.3 产出

| 产出 | 不能做什么 |
| :-- | :-- |
| 已发布 issue | 不得发布无断言支撑的自然语言判断 |
| 可执行断言 | 不得自造谓词；不得用近似谓词替代无法表达的义务 |
| 证据链 | 不得只留结论不留调用原文 |
| 回归防护面 | 不得把「求值为真」读作「该处无缺陷」，只等于「在该操作化下未观察到违反」 |
| 覆盖缺口 | 不得静默换谓词蒙混过去 |
| 降级诊断 | 不得因配额耗尽而整格失败、丢弃产物 |

### 6.4 方法外

| 不做 | 归属 |
| :-- | :-- |
| 模型修复、多轮修复-确认、修复后回归确认 | 后续论文【导师原话】 |
| 一轮式 `NL -> STM` 初始生成 | 语料的来源方式，属上游论文；本文只作 related work |
| 证明某种建模语言 / DSL 更好 | 不是本文命题；中间表示是介质 |
| 完整 PlantUML / SysML round-trip 转换器 | 工程问题，且我们只需单向编译 |
| 时钟、不变式、正交区语义的验证 | 研究内容三 |
| 缺陷台账的自动构造 | 台账是人工标注的评测分母，不是方法产物 |

### 6.5 人类角色

| 环节 | 人类做什么 |
| :-- | :-- |
| 问题定义与范围 | 冻结建模对象 $M$、闭合谓词词表、claim 边界 |
| 缺陷台账标注 | 逐 pair 通读需求原文、被评审模型、参考模型三份材料 |
| 命中判定 | 逐位人工判定，并写下判据文字 |
| 多报侧裁定 | 逐簇按五类判定流程裁定；「回读作者源」一步**按定义不可机械复核** |
| **方法运行** | **无人在回路。** 不得在 run 中替换输入、干预中间产物或补写发现 |

⚠️【v46 实测】**判定层是独立误差源**：588 位与 288 簇全部由单一判定者人工裁定，
**无第二判定者、无一致性系数**。这是 §Threats 的必写项。

### 6.6 失败与不确定状态

【仓库裁定】方法不允许整格崩溃，只允许降级。以下状态都必须显式落盘并进入分析：
**拒答**（谓词无法给出可靠真值）、**覆盖缺口**（义务无法用闭合词表表达）、
**隔离项**、**降级**（内部配额耗尽时封存产物）、**不可判定**（判定侧证据不足）。

⚠️ **降级不是失败，是设计。** 反过来做（配额耗尽即整格失败）会让最难的样本系统性地从
数据里消失——而最容易耗尽配额的，恰恰是缺陷最硬的那些格。
【v46 实测】v46 有 **9 个降级格**（claude 1 / gpt 8），它们仍有产物、仍进统计。

⚠️【v46 实测】**拒答有一个已知副作用**：拒答文案会回灌进生产者的下一轮上下文，其中包含极性与
「把它发布出去」的指示。这是 `hit@1` 上界性的第二条通道，**尚未量化**。
同一机制在方法一节是设计优点、在结果一节是上界成因，**两处必须都写**。

## 8. 技术挑战

【AI 建议·待确认】

| 挑战 | 为什么难 | 本文怎么处理 |
| :-- | :-- | :-- |
| **义务的操作化可能是伪代理** | 同一条义务的多种形式化不等价（边存在 ≠ 可达） | 闭合词表 + 断言审查阶段 + 明令禁止的替换形态清单 |

## 11. 可以说的话

【v46 实测 + 仓库裁定】

- 我们研究「给定需求与一份从它生成的状态机模型，自动发现不符合之处」这一任务。
- 我们给出一个 19 谓词的闭合词表与一套需求义务到断言的转换方法，
  使每条发现都可机械求值、可回溯到需求原句与模型元素。
- 断言由需求全覆盖拆分转换而来，因而覆盖性来自构造；求值为真者构成回归防护。
- 可执行语义是必要的：按台账断言组的族构成，**26%–43%** 的已知缺陷需要行为证据表达（两口径）。
- 未被台账认领的产出逐条可裁定，其中最大一块（按条目 **46.5%**）不是模型缺陷也不是方法误判，
  而是评审入口的编译损失——这使「有些多报不是被评审对象的错」从一句 threats
  变成一个**可扣除的量**。

## 12. 要小心的话

- 「覆盖率」必须带 $\le$，且必须与算力代价一起给。
- 「必要性」只到这个强度：可执行语义必要；**有界模型检查的必要性本实验无法判定**——
  不是被证伪，而是这批语料没有提供足够深度的案例。
- 「回归防护」目前是方法性质，不是实测结论。
- 「表示债务占 46.5%」**不宜外推**——一条链、一个语料、一个检测器。
  论文里主张的应当是**审查动作**（评审入口若是中间表示，就必须做这项扣除），不是这个数字。
