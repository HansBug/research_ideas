# claim_evidence_map.md — claim 与证据对照

> 每条 claim 必须在此有证据、强度与允许 / 禁止的写法。
> **数字的唯一来源**是自包含实验报告
> [../../talks/2026-08-10-实验-v46全量矩阵双侧结论.md](../../talks/2026-08-10-实验-v46全量矩阵双侧结论.md)
> （下称「报告」，引用格式为「报告 §x.y」）。
> ⛔ 不得从本文件或其它 story 文件转抄数字后再传播——一律回报告核对。

## 1. 强度口径

| 强度 | 含义 |
| :-- | :-- |
| `任务界定` | 说明本文研究什么，不说明方法效果。 |
| `方法设计+实现` | 有设计论证与已运行的实现支撑，效果另由实测 claim 承担。 |
| `实测-强` | 有全量实测支撑，且判定链可追溯到逐条判据。 |
| `实测-中` | 有全量实测支撑，但存在已知的口径依赖、样本量限制或单向偏差。 |
| `实测-弱` | 数据存在，但结论对口径选择高度敏感，只能作为观察陈述。 |
| `方法性质-未测` | 由方法构造直接得出，但本轮未测量其规模。 |
| `推论` | 从测量结果推出的机制判断，存在未排除的竞争解释。 |
| `禁止` | 证据不支持，或已被定调否定。 |

## 4. Reviewer challenge 对照

| Challenge | 回答 |
| :-- | :-- |
| 这不就是让 LLM 报缺陷吗？ | 不是。闭合词表是一次领域建模，LLM 只做「义务 → 谓词调用」的映射；每条发现可机械复算。反面证据：把形式化工具裸给自主 agent 效果很差。 |
| 60.4% 相对什么？ | 无外部对照，如实写明；朴素基线是第一优先待补项。同时必须给算力代价。 |
| 分母是你们自己标的？ | 是人工标注，因此必须交代标注过程（谁标、何时标、是否在看过方法产出之后标、与判定是否同一人），并给出与上游论文问题清单的外部对照缺口。 |
| 多报这么多，precision 呢？ | 逐条读完后「误报」这个读法是错的：按条目最大一块（46.5%）是评审入口的编译损失，既不是模型缺陷也不是方法误判。给两套分母。 |
| 为什么要中间表示，直接在 PlantUML 上查不行？ | PlantUML 是绘图记法，不定义执行语义，行为性问题在它上面没有定义；而 26%–43% 的已知缺陷需要行为证据。同时如实给出编译损耗。 |
| fork/join 那份需求呢？ | 建模对象是 $M = (S, E, V, Tr, A)$，不含时钟与正交区；该需求的忠实模型在 $M$ 中无法表达，故其派生 pair 不在研究范围内。一句话，在问题定义处。 |
| 谁判的命中？可靠吗？ | 单一判定者，无第二判定者、无一致性系数；588 位中 20 位无逐位判据（15 位在命中侧，方向对我们有利）。全部如实写入 Threats，并列为待补。 |
| 有界模型检查那一族有用吗？ | 本实验无法判定——不是被证伪，而是这批语料几乎没有提供该深度的案例。 |
| 你们在这批 pair 上迭代方法，会不会过拟合？ | 实验的作用是判断改动是否有效；方法的每一条规则必须能只从领域资料独立推导，且这一点由「每条规则挂可查证外部出处、动机与出处分开记录」做成可核验事实。 |
