# task_boundary.md — 任务边界

## 1. 任务定义

```text
输入：<NL, STM_0>
      NL    自然语言需求原文
      STM_0 一份由 LLM 从该需求生成的状态机模型（PlantUML）

产出：<已发布的 issue 清单,
       支撑每条 issue 的可执行断言,
       一条可回溯到 NL 原句与模型元素的证据链,
       求值为真的断言构成的回归防护面,
       未能表达的义务所对应的覆盖缺口>
```

**任务是发现，不是修复。** 给定一份需求与一份从它生成的模型，自动发现该模型不符合需求之处，
并把每一条发现落成可机械求值的断言。

⛔ 修复不在本文范围内。理由是导师定调：「discover 部分单独成一篇文章」，
「repair 不会简单的，特别是要高质量 repair」——修复另立后续论文。
本文只在讨论一节**捎带提及**这些发现便于修复与回归确认，**不展开、不承诺效果、不给数据**。

## 2. 输入

| 输入 | 说明 | 纪律 |
| :-- | :-- | :-- |
| `NL` | 控制系统自然语言需求原文 | **义务的唯一来源**。需求层主张必须能引到具体哪一句 |
| `STM_0` | 被评审模型，PlantUML | **唯一的求值对象**。判定表示债务时必须回读它，不读编译产物 |
| 溯源元数据 | 取自上游数据表的哪一行哪一列、生成它的是哪个 LLM、原始文件 SHA-256 | 支撑可复现性 |

⛔ **参考模型不是输入。** 上游论文作者为每份需求人工撰写的参考模型，**只在人工标注缺陷台账
时使用**；方法全程不接触它。这保证方法不是在「对答案」。

⛔ **缺陷台账不是输入。** 台账只在评测侧使用，且只在图终止之后用于审计；
运行时不得进入任何 prompt、schema 或门。

## 3. 产出

| 产出 | 说明 | 不能做什么 |
| :-- | :-- | :-- |
| 已发布 issue | 每条挂在一个求值为假的 `primary` 断言上，并绑定它依赖的模型元素 | 不得发布无断言支撑的自然语言判断 |
| 可执行断言 | 只能取自 19 个谓词的闭合词表；带 `primary` / `supporting` 角色与覆盖键 | 不得自造谓词；不得用近似谓词替代无法表达的义务 |
| 证据链 | 稳定 ID 贯穿需求条目 → 断言 → issue；每阶段输入输出记内容哈希；每次 LLM 调用留完整 prompt 与原始响应 | 不得只留结论不留调用原文 |
| 回归防护面 | 求值为真的那部分断言 | 不得把「求值为真」读作「该处无缺陷」，只等于「在该操作化下未观察到违反」 |
| 覆盖缺口 | 某条义务无法用闭合词表表达时的显式登记 | 不得静默换谓词蒙混过去 |
| 降级诊断 | 内部配额耗尽时记录「哪条义务没走完、卡在哪」 | 不得因配额耗尽而整格失败、丢弃产物 |

## 4. 方法内外

### 方法内

1. 需求拆分：把需求原文切成一条条义务。
2. 需求审查：检查每条义务是否真有需求依据、是否可落成断言；不合格带定向反馈打回。
3. 断言转换：把义务落成闭合词表里的谓词调用。
4. 静态预检：机械检查绑定元素是否存在、参数是否合法；不合格打回。
5. 断言审查：检查断言是否真表达了那条义务、是否恒真恒假；不合格打回。
6. 求值发布：在被评审模型上求值（结构查询 / 仿真 / 有界模型检查）。
7. 归因绑定：把每个求值为假挂回它依赖的模型元素。
8. 结果裁决：决定哪些求值为假够格发布成 issue。

⚠️ **循环发生在审查者与被审查者之间**，靠定向反馈驱动，不是换个随机数重试。

### 方法外

| 不做 | 归属 |
| :-- | :-- |
| 模型修复、多轮修复-确认、修复后回归确认 | 后续论文 |
| 一轮式 `NL -> STM` 初始生成 | 语料的来源方式，属上游论文；本文只作 related work |
| 证明某种建模语言 / DSL 更好 | 不是本文命题；中间表示是介质 |
| 完整 PlantUML / SysML round-trip 转换器 | 工程问题，且我们只需单向编译 |
| 时钟、不变式、正交区语义的验证 | 研究内容三 |
| 缺陷台账的自动构造 | 台账是人工标注的评测分母，不是方法产物 |
| 运行时的人类裁决 | 见 §5 |

## 5. 人类角色

| 环节 | 人类做什么 |
| :-- | :-- |
| 问题定义与范围 | 冻结建模对象 $M$、闭合谓词词表、claim 边界 |
| 缺陷台账标注 | 逐 pair 通读需求原文、被评审模型、参考模型三份材料，人工标注已知缺陷 |
| 命中判定 | 逐位人工判定，并写下判据文字 |
| 多报侧裁定 | 逐簇按五类判定流程裁定，其中「回读作者源」一步**按定义不可机械复核** |
| **方法运行** | **无人在回路。** 不得在 run 中替换输入、干预中间产物或补写发现 |

⚠️ **判定层是独立误差源，必须如实写明**：v46 的 588 位与 288 簇全部由单一判定者人工裁定，
**无第二判定者、无一致性系数**。这是 §Threats 的必写项，不是可省的细节。

## 6. 失败与不确定状态

方法不允许整格崩溃，只允许降级。以下状态都必须显式落盘并进入分析：

| 状态 | 含义 |
| :-- | :-- |
| 拒答 | 谓词无法在该模型上给出可靠真值（不可判定或超出求解预算），返回拒答而非猜真假 |
| 覆盖缺口 | 义务无法用闭合词表表达 |
| 隔离项 | 某条义务反复不合格，隔离该项但保留可执行的同批项 |
| 降级 | 内部配额（修订次数、审查轮次）耗尽，封存已有产物并记下卡在哪 |
| 不可判定 | 判定侧证据不足，不能可靠裁定 |

⚠️ **降级不是失败，是设计。** 反过来做（配额耗尽即整格失败）会让最难的样本系统性地从数据里
消失——而最容易耗尽配额的，恰恰是缺陷最硬的那些格。v46 有 9 个降级格（claude 1 / gpt 8），
它们仍有产物、仍进统计。

⚠️ **拒答有一个已知副作用**：拒答文案会回灌进生产者的下一轮上下文，其中包含极性与
「把它发布出去」的指示。这是 `hit@1` 上界性的第二条通道，尚未量化。
同一机制在方法一节是设计优点、在结果一节是上界成因，**两处必须都写**。

## 7. 相对上一版改了什么、为什么

| 改动 | 为什么 |
| :-- | :-- |
| 任务定义从 `<NL, raw/source STM_0> -> Discover roots + Repair-Confirm chains + canonical export + closure/regression ledger` 收窄为 `<NL, STM_0> -> issue + 断言 + 证据链 + 回归防护 + 覆盖缺口` | paper1 收窄为 issue discover |
| 方法内八步改写为当前流水线的真实阶段 | 旧版的九步是 repair 生命周期，与实现已完全不对应 |
| 新增「参考模型不是输入」「缺陷台账不是输入」两条硬约束 | 实验公平性的核心事实，旧版没有写；它是审稿人第一个会问的问题 |
| 失败状态表从 `unsupported` / `untraceable` / `partial_repair` / `not_closed` / `over_repaired` / `regression_introduced` 改为拒答 / 覆盖缺口 / 隔离项 / 降级 / 不可判定 | 前四条是 repair 期状态；后者是当前流水线真实产出的状态 |
| **保留并强化**：「方法运行时无人在回路」 | 旧版已有，仍然有效，且现在有实跑证据 |
| **保留并强化**：失败必须显式记录、不得隐性删除 | 旧版精神保留，并升级为仓库根 §10「只有两种情况允许整格崩」的本地落法 |
| 删除 §7「不跑实验纪律」 | 旧版写「本文件不运行实验、不产生 run record」；324 格全量实验已完成，该条已过时 |
| 新增 §5 的判定层误差源提示与 §6 的拒答回灌提示 | 两者都是 v46 暴露的、必须进 Threats 的事实 |
