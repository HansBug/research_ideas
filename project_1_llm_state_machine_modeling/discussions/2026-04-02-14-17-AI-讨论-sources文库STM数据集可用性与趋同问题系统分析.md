## 1. 任务与覆盖范围

这份讨论稿面向 `project_1_llm_state_machine_modeling/sources/` 下的全部 `STM.md`，从“**这些材料是否适合作为状态机模型自动生成数据集**”的角度做一次全量复核。

### 1.1 版本绑定说明

本讨论稿**不是泛指某个模糊时期的 `sources/` 文库**，而是明确绑定到 [sources/SUMMARY.md](../sources/SUMMARY.md) 当前可追溯的 **149 篇收录版本**。

具体口径如下：

1. 以 [SUMMARY.md](../sources/SUMMARY.md) 的“当前收录统计”为准：`已收录论文 = 149`、`已完成 STM 梳理 = 149`、`⏳ 尚未提取 STM = 0`。
2. 这套 **149 篇** 的收录边界，对应 [SUMMARY.md](../sources/SUMMARY.md) “更新日志”中时间为 **2026-03-12 10:38:41** 的那一轮：`新增 10 篇，当前累计 149 篇`。
3. `SUMMARY.md` 自身后续还有一次 **2026-04-01 10:05:43** 的文档修改，但从 git 历史和正文内容看，这次主要是**回填/整理日志时间**，并没有把 `sources/` 的收录总量从 149 再改成别的版本。
4. 因此，本文中的所有统计、趋同簇、信息保留分级与总表跳转，默认都应理解为：**针对 `SUMMARY.md` 中“149 篇版本（版本时间锚点：2026-03-12 10:38:41）”的 `sources` 文库分析结果**。
5. 如果后续 `sources/` 新增论文、重写 `STM.md` 或调整 `SUMMARY.md` 总账，这份讨论稿就不再自动代表“最新版本”，而只代表上述时间锚点对应的文库快照。

本次覆盖范围与口径如下：

1. 共检查 **149** 个 `STM.md` 文件，覆盖 `sources/` 当前总账中的全部目录。
2. 其中 **93** 个文件含正例条目，共 **108** 条；另有 **56** 个文件为 `⚪ 未收获`。
3. “强趋同”采用严格口径：只有当控制对象、主要阶段链、关键 guard/触发、主要输出动作和收尾/恢复方式都基本同构时，才记为同一强趋同簇。
4. “信息保留”比较的不是整篇论文保留率，而是 `STM.md` 中“基于原文整理后的自然语言描述”相对于其所选控制逻辑证据块与对应 `paper_content.txt` 同主题内容的保留度。
5. 本文默认先把 `STM.md` 视作候选数据集条目，再进一步区分哪些可直接进主训练集、哪些应降采样、哪些更适合作 hard negative。

为了让后续回看成本最低，下面的总表统一给出三类跳转：

1. `STM.md`：先看当前条目怎么写。
2. `paper_content.txt`：再核对原始提取全文。
3. `bibtex.bib`：最后确认元信息。

## 2. 为什么要用“数据集视角”重看这些 STM

如果这些 `STM.md` 只是作为文献笔记，那么“能读、能概括”就够了；但如果它们要进入“自然语言到状态机模型自动生成”的训练/评测数据集，要求会立刻变严：

1. **样本多样性**：不能让若干重复模式把模型训练成“只会写联锁、电梯或应急交通灯”。
2. **语义保真度**：最终描述稿不能只剩一个通顺摘要，而要尽量保住状态、阶段、guard、异常、定时和恢复条件。
3. **粒度一致性**：整机级样本、构件级样本、协议级样本、教学子过程样本不能混成一锅。
4. **正负样本边界**：`⚪ 未收获` 不应简单视为“废料”，其中相当一部分其实是很好的 hard negative。
5. **数据集治理性**：每条样本都应能回答“为什么留、怎么留、留在主集还是降采样池里”。

因此，这份讨论稿不只判断 `STM.md` 写得好不好，还要回答：

1. 这条样本是否值得直接进入主训练集。
2. 如果值得，应该完整保留、清洗后保留，还是只做降采样补充。
3. 如果不值得做正样本，是否应转成负样本、背景样本或仅保留在检索库。

## 3. 分析标准与 emoji 口径

### 3.1 数据集处置角色

|---|---|---|---|

| `🧰 清洗后保留` | 确实有价值，但描述压缩偏大，或样本更偏构件级/语义级/方法嵌入式，需要补状态名、guard、定时值、接口语义或异常链。 | 进入“待清洗正样本池”；清洗后再决定是否进入主训练集。 | [《A methodology for formal analysis and verification of EAST-ADL models》](../sources/east-adl-formal-analysis/STM.md)（条目：BBW ABS brake-release logic under TA execution） |

### 3.2 信息保留分级

这里比较的是 `### 2. 基于原文整理后的自然语言描述` 对目标控制逻辑的保留程度。统计上先做了全量压缩比预筛，再用代表样本人工回看以校准边界，因此它是“**可操作的近似分级**”，而不是逐句逐 token 的形式精算。

| 分级 | 定义 | 常见损失 | 例子 |
|---|---|---|---|
| `🟢 A 高保留` | 主阶段链、关键 guard/触发、主要动作与收尾条件基本都还在，损失主要是措辞压缩和次级背景。 | 少量上下文或非核心解释被压缩。 | [《Automatic Water Level and Pressure Control System Prototype Design Using Programmable Logic Controller and Human Machine Interface》](../sources/automatic-water-level-and-pressure-control-system-prototype/STM.md)（条目：Fill-delay-drain-repeat tank cycle） |
| `🟡 B 较高保留` | 主控制链基本完整，但次级阈值、定时值、部分状态名或补充条件有缺失。 | 容易丢掉定时、数值阈值、次级分支。 | [《Application of PLC for Elevator Control System》](../sources/application-of-plc-for-elevator-control-system/STM.md)（条目：Level-Call Driven Elevator Motion） |
| `🟠 C 中保留` | 只保住主故事线，多个次级条件、异常分支、接口语义或显式状态组织被压缩掉。 | 常丢显式状态名、并发/分层信息、接口语义。 | [《HyTech: A model checker for hybrid systems》](../sources/hytech-hybrid-systems/STM.md)（条目：Thermostat hybrid automaton） |
| `🔴 D 低保留` | 更接近“可读摘要”而非“可直接建模描述”；若直接入库，模型容易学到概念而非可执行控制链。 | 大量 guard、细分阶段、恢复条件或数据源管理逻辑缺失。 | [《Formal specifications and analysis of the computer-assisted resuscitation algorithm (CARA) Infusion Pump Control System》](../sources/cara-infusion-pump-formal-spec/STM.md)（条目：Cuff Handler in Auto Control） |

下面不把例子继续塞进表格，而是直接展开写。所有例子都来自第 8 节“条目级全量总表”，目的是把 `A/B/C/D` 的边界讲清楚，尽量减少“只看定义还是容易主观”的问题。

#### 3.2.1 `🟢 A 高保留` 的详细例子

1. **[《Automatic Water Level and Pressure Control System Prototype Design Using Programmable Logic Controller and Human Machine Interface》](../sources/automatic-water-level-and-pressure-control-system-prototype/STM.md)**
   对应条目：`Fill-delay-drain-repeat tank cycle`
   跳转：[STM](../sources/automatic-water-level-and-pressure-control-system-prototype/STM.md) / [TXT](../sources/automatic-water-level-and-pressure-control-system-prototype/paper_content.txt)
   
   之所以判为 `🟢 A 高保留`，是因为整理稿几乎完整保住了原文的阶段推进链：`程序激活 -> 泵启动并注水 -> 到达高液位 -> 按定时器延时 -> 打开电磁阀排水 -> 回到低液位 -> 关闭电磁阀并重启泵 -> 循环直到停机`。这里最关键的触发点、高低液位、延时、阀门动作、循环复位关系，在整理稿里都还在。
   
   这一条的损失主要是实现层细节而不是控制语义本体。例如原文提到 `rung 0 / rung 2 / rung 3` 这类梯形图位置，以及 `start light / stop light` 这样的实现背景，但这些内容不影响把它还原为一个完整的离散控制链。因此它更像“几乎等价的控制叙述压缩”，而不是“主线还在但细节断层”的情况。

2. **[《Formal Modeling and Verification of the Functionality of Electronic Urban Railway Control Systems Through a Case Study》](../sources/formal-modeling-and-verification-of-the-functionality-of-electronic-urba/STM.md)**
   对应条目：`Tram-road level crossing protection sequence`
   跳转：[STM](../sources/formal-modeling-and-verification-of-the-functionality-of-electronic-urba/STM.md) / [TXT](../sources/formal-modeling-and-verification-of-the-functionality-of-electronic-urba/paper_content.txt)
   
   这一条被判为 `🟢 A 高保留`，核心原因是原文中的控制序列几乎逐步保留了下来：`初始状态（道路闪黄、指示器空白） -> D1 检测到电车 -> 道路连续黄 -> 道路红灯停止路面交通 -> 电车指示器放行 -> 电车驶离后恢复初始状态`。这条样本的价值在于，它不仅保住了“谁触发什么”，还保住了“路面信号”和“电车指示器”两个输出对象之间的联动关系。
   
   真正被压缩掉的，主要是“连续黄持续 4 到 10 秒”这个定时范围，以及“电车可按国家规则允许的最大速度通过”这类运行背景说明。也就是说，损失集中在参数与业务解释层，而不是状态转换主链层，所以仍应归入 `A` 而不是 `B`。

3. **[《Traffic Light Controller using Image Processing》](../sources/traffic-light-controller-using-image-processing/STM.md)**
   对应条目：`Image-based traffic signal timing allocation`
   跳转：[STM](../sources/traffic-light-controller-using-image-processing/STM.md) / [TXT](../sources/traffic-light-controller-using-image-processing/paper_content.txt)
   
   这条也可放在 `🟢 A 高保留`，原因在于整理稿完整保住了“图像比对结果驱动相位时长分配”这一控制逻辑主干：`采集路口图像 -> 与参考图像匹配 -> 根据匹配区间分配不同绿灯时长 -> 最高匹配区间转为长时间红灯`。对数据集来说，这已经足以支撑“输入条件分段映射到控制输出”的状态机/规则化建模。
   
   它仍有损失，但这些损失尚未伤到主逻辑框架。丢掉的是每个区间的精确数值映射，例如 `0-30% -> 90 秒绿灯`、`30-50% -> 60 秒` 等具体阈值表。如果目标是做高精度参数化控制模型，这些数值当然重要；但从“是否保住可执行控制骨架”的角度，这条整理稿仍然接近高保留。

#### 3.2.2 `🟡 B 较高保留` 的详细例子

1. **[《Application of PLC for Elevator Control System》](../sources/application-of-plc-for-elevator-control-system/STM.md)**
   对应条目：`Level-Call Driven Elevator Motion`
   跳转：[STM](../sources/application-of-plc-for-elevator-control-system/STM.md) / [TXT](../sources/application-of-plc-for-elevator-control-system/paper_content.txt)
   
   这条不是 `A`，而是更适合判成 `🟡 B 较高保留`。它确实保住了最关键的控制因果链：`呼梯 -> 电机正/反转 -> 上下运动 -> 限位开关反馈 -> 到站停机`。从“能不能用来教模型学会一个基本电梯运动控制逻辑”的角度看，这已经够用了。
   
   但它的问题也很明显：原文本身就比较短，而整理稿又进一步压缩成两句，导致“位置反馈如何参与控制”“目标层与当前位置的关系如何判断”“电机正反转的选择条件”这些都只剩概念，没有显式展开。换句话说，它保住了主控制链，却没有把隐含条件讲透，所以更像 `B` 而不是 `A`。

2. **[《Design & Control of an Elevator Control System using PLC》](../sources/design-amp-control-of-an-elevator-control-system-using-plc/STM.md)**
   对应条目：`PLC-based elevator car and door control`
   跳转：[STM](../sources/design-amp-control-of-an-elevator-control-system-using-plc/STM.md) / [TXT](../sources/design-amp-control-of-an-elevator-control-system-using-plc/paper_content.txt)
   
   这条被判为 `🟡 B 较高保留`，是因为整理稿清楚保住了三个主分支：`楼层移动与门控`、`门口有障碍物时不关门`、`超载时停机并保持开门`、`失电时就近平层并开门`。对电梯安全控制来说，这些都是重要而具体的动作链，说明整理稿并没有把样本压成纯简介。
   
   但它仍然丢掉了不少次级信息。例如原文还提到 `load cell` 的上下阈值逻辑、低负载持续一段时间会关闭风扇和额外照明、`oxygen sensor` 在供电故障且氧气下降时参与触发等。这些内容虽然不是主链中心，但对完整的安全模式管理很重要。主链保住了，参数和次级分支却缩掉了，所以落在 `B` 档最合适。

3. **[《Formal verification of autonomous vehicle platooning》](../sources/formal-verification-of-autonomous-vehicle-platooning/STM.md)**
   对应条目：`Leaving procedure for a platoon member`
   跳转：[STM](../sources/formal-verification-of-autonomous-vehicle-platooning/STM.md) / [TXT](../sources/formal-verification-of-autonomous-vehicle-platooning/paper_content.txt)
   
   这条整理稿已经把离队主链讲清楚了：`成员向 leader 请求离队 -> leader 授权 -> 车辆拉大间距 -> 达到最大间距后才切到 manual -> 离队`。同时，安全约束“非紧急情况下不得未授权离队”“达到最大允许间距前不得关闭自动控制”也被保住了，所以它显然不是 `C` 或 `D`。
   
   它没有进 `A` 的原因，在于一些关键的后续动作被压缩了。原文里还有“切到 manual 之后变道”“最后向 leader 发送 acknowledgement”这样的收尾动作，而整理稿把这部分简化掉了。也就是说，主要时序和关键 guard 还在，但完成态与收尾通信没有完全保住，因此更接近 `B`。

#### 3.2.3 `🟠 C 中保留` 的详细例子

1. **[《HyTech: A model checker for hybrid systems》](../sources/hytech-hybrid-systems/STM.md)**
   对应条目：`Thermostat hybrid automaton`
   跳转：[STM](../sources/hytech-hybrid-systems/STM.md) / [TXT](../sources/hytech-hybrid-systems/paper_content.txt)
   
   这条之所以是 `🟠 C 中保留`，是因为整理稿虽然保住了“温度到 3 度就关加热器、加热阶段满足 `1 < x < 3` 不变式、还能引入额外时间变量”这些主故事线，但对真正的混成自动机来说，这还远远不够。原文里除了离散切换，还有连续演化速率、差分约束、线性过近似、时钟与 stopwatch 的引入目的，以及要验证的时间性质。
   
   换句话说，整理稿对普通读者来说已经“能看懂温控器在干什么”，但对要恢复正式模型的人来说，很多真正构成模型骨架的连续动力学和验证语义已经被压缩掉了。这种“主线可懂、形式结构损失明显”的情况，正是 `C` 档的典型边界。

2. **[《Formal specifications and analysis of the CARA Infusion Pump Control System》](../sources/cara-infusion-pump-formal-spec/STM.md)**
   对应条目：`Pump manual/autocontrol modes`
   跳转：[STM](../sources/cara-infusion-pump-formal-spec/STM.md) / [TXT](../sources/cara-infusion-pump-formal-spec/paper_content.txt)
   
   这条整理稿保住了两个关键运行方式：`manual` 与 `autocontrol`，也保住了“自动控制时若发生泵故障则释放控制权，由 caregiver 处理”的主降级链。这让它仍然是一条可用的控制模式样本。
   
   但它只保住了“模式切换的故事”，没有保住“模式切换的具体组织”。原文里其实还涉及血压传感器数据如何经共享缓冲区进入 CARA、caregiver 如何设置目标血压与默认流量、模块间接口抽象为何这样设计等。整理稿把这些压缩成面向结果的叙述，因此更像“概括式模式摘要”，而不是“可直接转状态机的完整控制说明”。

3. **[《Time-Complemented Event-Driven Architecture for Distributed Automation Systems》](../sources/time-complemented-automation-architecture/STM.md)**
   对应条目：`Sorter1 control flow in a TCED sorting machine`
   跳转：[STM](../sources/time-complemented-automation-architecture/STM.md) / [TXT](../sources/time-complemented-automation-architecture/paper_content.txt)
   
   这条整理稿把最外层控制链讲清楚了：`主控分析扫描结果 -> 给分拣器发 ETA -> 本地时间表更新 -> 到时驱动 labeler/diverter`。如果只是想知道 Sorter1 大致怎么工作，这样的整理已经足够。
   
   但它丢掉的内容很多，而且这些内容恰恰是建模时最需要的：例如 `Thread A / Thread B` 的分工、printer/labeler/diverter 的模块分解、Petri 网中的 place/transition 级展开、`extend/retract` 动作何时由同步时钟触发、代理可用状态如何约束后续动作等。也就是说，主链还在，但中间真正的显式状态组织、并发结构和执行约束被压掉了，所以应判为 `C`。

#### 3.2.4 `🔴 D 低保留` 的详细例子

1. **[《Formal specifications and analysis of the computer-assisted resuscitation algorithm (CARA) Infusion Pump Control System》](../sources/cara-infusion-pump-formal-spec/STM.md)**
   对应条目：`Cuff Handler in Auto Control`
   跳转：[STM](../sources/cara-infusion-pump-formal-spec/STM.md) / [TXT](../sources/cara-infusion-pump-formal-spec/paper_content.txt)
   
   这条是 `🔴 D 低保留` 的典型例子。原文实际上给出了一个复杂的输入源管理与失效降级 EFSM：不同血压源的优先级、不同血压区间对应的采样频率、`3` 分钟内取不到有效值的回退规则、连续无效读数后的再次请求、`level 1 / level 2` 告警、记录写入、返回 manual 的条件，以及 `localTimer / iterations` 等变量。
   
   整理稿虽然保住了“根据 cuff 值调采样频率”和“无效时回退 manual”这两个大意，但大量关键细节被折叠了：失效分支的层级结构、不同 alarm 等级的区分、变量驱动的状态推进、一次无效和重复无效之间的处理差异都不见了。它更像“把复杂控制器读成一段说明文”，而不是“还能直接反推出接近原始控制链的自然语言”。因此这一条如果直接入主训练集，很容易让模型学到概念，而不是学到可执行结构。

2. **[《A methodology for formal analysis and verification of EAST-ADL models》](../sources/east-adl-formal-analysis/STM.md)**
   对应条目：`BBW ABS brake-release logic under TA execution`
   跳转：[STM](../sources/east-adl-formal-analysis/STM.md) / [TXT](../sources/east-adl-formal-analysis/paper_content.txt)
   
   这条被判为 `🔴 D 低保留`，不是因为它没有控制逻辑，而是因为原文里的“真正重要信息”大部分是形式语义层的：`Brake-by-Wire` 架构如何映射到 `ICM`，`TA` 如何有 `idle/read/execute/write` 这样的执行段，哪些动作是 urgent/atomic，clock reset 如何发生，触发条件分 time-triggered 和 event-triggered 两类，`read-execute-write` 语义如何落到具体 TA 结构上。
   
   整理稿只保住了一个很粗的故事：`滑移率 > 0.2 则释放制动，否则使用请求制动力；然后这个行为被接入 timed automaton`。这会让读者知道“这个系统大概在做什么”，但不足以恢复“这个控制功能在形式模型里到底是怎样执行的”。从数据集角度看，这已经接近“概念摘要”，因此只能给 `D`。

3. **[《A real-time semantics for the IEC 61499 standard》](../sources/iec61499-realtime-semantics/STM.md)**
   对应条目：`BFB execution control chart (ECC)`
   跳转：[STM](../sources/iec61499-realtime-semantics/STM.md) / [TXT](../sources/iec61499-realtime-semantics/paper_content.txt)
   
   这条同样属于 `🔴 D 低保留`。原文中关于 `ECC` 的核心价值，不只是“收到输入事件后检查条件并执行算法”，而是更细的执行规则：输入事件先采样数据、当前状态出边按 XML 顺序检查、到达目标态后算法按序执行、事件被概念性消费、然后继续传递性检查下一批条件；后文还进一步把 `b1` 的输入事件、资源保护、事件链与调度关系拉了出来。
   
   整理稿把这些压缩成了三句高层说明，导致显式状态组织、转移优先级、事件消费规则、递归转移检查、调度与资源语义这些对状态机恢复很重要的要素都几乎看不见了。也正因为如此，这类条目不适合直接当“高保真自然语言状态机描述”去训练，只能作为需要重写或重标注的低保留样本。

## 6. 面向状态机自动生成数据集的整体判断

### 6.1 这套 STM 现在最大的优点

1. **真实控制对象多**：不是泛泛的 UML/工具论文，而是大量具体控制对象，如联锁、电梯、交通灯、液位、泊车、医疗装置、起落架、车队等。
2. **绝大多数正例条目都写成了“可生成输出”的最终口吻**：这对做 `NL -> state machine` 的目标输出很友好。
3. **正负样本边界已经开始显化**：`⚪ 未收获` 文件可以直接转化为 hard negative，而不必简单丢弃。
4. **不少条目已经保住了核心 guard/动作链**：`A+B` 共 **79** 条，占正例条目的 **73.1%**，说明主体材料已经具备数据集基础。

### 6.2 现在最需要警惕的问题

1. **强趋同问题真实存在**：`🔁` 强趋同条目有 **28** 条，占正例条目的 **25.9%**。这不是“有点像”，而是足以污染训练分布。
2. **系统级、构件级、语义级样本混在一起**：例如 IEC 61499、EAST-ADL、ViTAL、部分 SysML/ECC/构件执行语义条目，并不是坏样本，但如果不打标签，会让训练目标粒度漂移。
3. **信息压缩不均匀**：`🟠 C + 🔴 D` 共 **29** 条，占 **26.9%**。这些条目如果直接进主训练集，模型更容易学到“摘要文风”而不是“状态机可执行描述”。
4. **异常/恢复链仍然偏少**：很多条目保住了 nominal path，但没有把 fault、degraded、manual takeover、recovery 条件完整保住。
5. **领域分布并不均匀**：交通灯、联锁、电梯、工业 PLC 占比较高，医疗、过程控制、真正的时间约束样本仍然偏少。

### 6.3 如果今天就拿它做数据集，我建议这样分桶

1. `主训练集`：优先从 `💎 核心保留` 中挑选，并对 `🔁` 强趋同簇做代表样本抽样。
2. `待清洗正样本池`：全部 `🧰 清洗后保留` 条目，优先补 guard、阈值、定时值、异常链、显式状态名。
3. `降采样补充池`：全部 `🪫 降采样保留` 条目，只用于增强鲁棒性，不作为主训练集主力。
4. `hard negative / background`：全部 `⛔ 不作正样本` 文件，尤其是连续控制、工具流程和综述型条目。

### 6.4 对后续标注和建库流程的直接建议

1. 在 `STM.md` 之外，为每条正例补一个轻量结构化标签：`system-level / subsystem-level / component-level / protocol-level`。
2. 对 `🟠 C` 和 `🔴 D` 条目优先回原文补四种东西：显式状态名、guard/阈值、定时值、异常/恢复条件。
3. 对 `🔁` 强趋同簇明确“代表样本”与“补充样本”清单，不再默认全部同权重进入主训练集。
4. 对 `⚪ 未收获` 文件增加 hard negative 标签，而不是只留下“未收获”四个字。
5. 后续如果继续扩库，应优先补那些当前样本稀少但对控制系统自动建模更有区分度的对象：医疗模式管理、故障退化、时间约束、协议/协调控制、复杂恢复链。

## 10. 最后的结论

如果站在“自动生成状态机模型的数据集”这个目标上看，这批 `STM.md` **已经不是从零开始**，但也**绝对还没有到“拿来即训”**的状态。

可以概括成三句话：

1. **好消息**：正例主体已经足够大，而且大多数条目已经写成了可供模型学习的目标输出口吻。
2. **坏消息**：强趋同和保留度不均匀问题都是真问题，不处理会直接影响训练分布与评测可信度。
3. **最现实的下一步**：不要继续只追求“新增更多 STM”，而要转向“治理现有 STM 的角色、保留度和重复度”。

换句话说，`sources/` 现在最缺的不是论文数量，而是**面向数据集的样本治理**。
