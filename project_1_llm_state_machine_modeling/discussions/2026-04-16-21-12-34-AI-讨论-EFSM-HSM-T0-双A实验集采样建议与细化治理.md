# `EFSM/HSM + T0 + 双A` 实验集采样建议与细化治理

## 1. 任务定位

这份 discussion 只回答一个收束后的问题：

1. 当 `project_1` 只考虑 `EFSM/HSM + T0 + 原文A + 描述A + 💎` 的候选池时，如何从中抽出 `60-100` 条最适合做实验的样本。
2. 抽样时到底该按什么维度分层，避免自然分布把实验集拉向少数高重复领域。
3. 如果后续要把这批数据再做细化版本，最值得继续补哪些原文侧信息。

本文默认绑定：

1. [sources/SUMMARY.md](../sources/SUMMARY.md) 中的 `EFSM/HSM + T0 + 双A` 候选采样子账。
2. [sources/manual_audit/EFSM_HSM_T0_DOUBLE_A_AUDIT_GUIDE.md](../sources/manual_audit/EFSM_HSM_T0_DOUBLE_A_AUDIT_GUIDE.md) 里的 6 个新增指标。

换句话说，本文讨论的不是“整个 `sources/` 文库怎么管理”，而是“在已经筛到很干净的一层候选池之后，实验集还应该怎么治理”。

## 2. 先给结论

### 2.1 核心结论

1. 这批数据**绝对不能**按候选池自然分布随机抽。
2. 最小抽样单元不应是“案例行”，而应是 `cluster_key` 对应的**控制图像簇**。
3. `60-100` 条实验集最稳的做法不是一次性做满，而是分成：
   - 一个主实验集；
   - 一个保留池；
   - 一个高风险或高归一成本池。
4. 对 `project_1` 目前的目标而言，最推荐的是 **`80` 条主实验集 + `20` 条 reserve** 的二层配置。
5. 若你现在只想先发一个更克制、更容易讲清楚的版本，那么 **`60-72` 条主实验集** 更稳；但这时更要严格按 `cluster_key` 和难度层控制配额。

### 2.2 为什么不能按自然分布抽

因为 `sources` 不是均匀生成出来的数据集，而是从真实论文里“搜出来、读出来、整理出来”的文库。它天然会有以下偏斜：

1. 某些领域特别高产，但控制图像高度重复，例如 `🅿️ / 🏢 / 🚆` 这类 PLC 门控、升降、存取、联锁链。
2. 同一类控制器可能在不同论文里换了对象名、传感器名、阈值名，但主控制骨架几乎同构。
3. `T0 + 双A` 过滤会天然偏向“证据写得清楚、容易整理”的样本，从而压低一些高价值但整理成本更高的边界型样本。
4. 如果不做人为分层，最后实验集会看起来很大，但其实只是在重复考模型对少数模板的适应能力。

所以，后续真正需要控制的不是“数量够不够”，而是“覆盖面是否扎实、难度层是否合理、趋同是否被压住”。

## 3. 这 6 个新增指标在抽样中的作用

新增的 6 列不是为了“多记点 metadata”，而是为了把实验抽样从“拍脑袋挑例子”变成“有治理结构的筛选”。

1. `cluster_key`
   - 解决“近同构样本扎堆”问题。
   - 它是主抽样键，不是装饰字段。
2. `scope_level`
   - 解决“整机级 / 子系统级 / 构件级混抽”问题。
   - 它决定实验集里的控制边界层次是否均衡。
3. `complexity_bin`
   - 解决“全是简单流程”或“全是重 HSM”问题。
   - 它负责构造难度梯度。
4. `evidence_compactness`
   - 解决“输入文本恢复难度不透明”问题。
   - 它区分这条样本是原文直说、局部拼接，还是明显重构出来的。
5. `hidden_time_risk`
   - 解决“表面是 `T0`，但实际埋着时间语义”的问题。
   - 它是当前主实验集的风险闸门。
6. `pyfcstm_fit`
   - 解决“样本离目标形式还有多远”的问题。
   - 它决定这条样本更适合放主集、挑战集还是 reserve。

简化说，后续抽样顺序应当是：

`cluster_key` 去趋同 -> `hidden_time_risk` 控主风险 -> `scope_level / complexity_bin / pyfcstm_fit / evidence_compactness` 做分层填充

## 4. 主实验集怎么抽

### 4.1 推荐目标规模

我建议不要把 `60-100` 看成一个松散区间，而是拆成三档版本：

1. `60` 条版
   - 适合先做第一版论文实验。
   - 要求非常严格地控趋同，基本按“一簇一例”为主。
2. `80` 条版
   - 最推荐。
   - 足够做分层统计和错误分析，同时还没有大到失控。
3. `100` 条版
   - 适合在主集稳定后扩展。
   - 不能简单往 `80` 条后面继续加同类样本，必须主要从 reserve 里补新的簇和新的难度档。

如果只能先做一个版本，我建议：

1. 主实验集固定为 `80` 条。
2. 另维护 `20` 条 reserve。
3. 再额外保留一小撮 `hidden_time_risk = 高` 的观察池，不放进主集。

### 4.2 主抽样单位：按 `cluster_key` 抽，不按案例行抽

这条最重要。

后续抽样必须默认按以下口径执行：

1. 先把候选池按 `cluster_key` 分组。
2. 每个组先选一个代表样本进入竞争池。
3. 只有当同一个 `cluster_key` 下确实存在**不同层次价值**时，才允许进第二条。

“不同层次价值”指的是：

1. 同簇里一条是 `构件 + 小/中`，另一条是 `子系统/整机 + 大`。
2. 同簇里一条是 `直述 + 直接`，另一条是 `整合/重构 + 轻归一/重归一`，能明显扩展难度。
3. 同簇里一条是 `EFSM`，另一条是 `HSM`，且不是仅靠命名差异造成。

如果只是：

1. 对象不同但主链一样；
2. 传感器或阈值换名但控制骨架一样；
3. 都是同一类 PLC 门控顺序控制的轻微变种；

那么默认最多留 `1` 条进主集，其余放 reserve 或直接不抽。

### 4.3 推荐配额不是按领域，而是按“建模维度”

主实验集优先按下面这些维度设 guardrail：

1. `状态机类型`
2. `scope_level`
3. `complexity_bin`
4. `evidence_compactness`
5. `pyfcstm_fit`
6. `hidden_time_risk`

领域只作为**上限约束**，不作为主分层轴。原因是：

1. 领域是表面分类。
2. 建模难度和控制图像不一定跟领域强绑定。
3. 真正影响 `project_1` 实验有效性的，是控制边界、复杂度、证据形态和目标形式距离。

### 4.4 推荐的主集 guardrail

以下不是死配额，而是很适合 `80` 条主实验集的目标区间：

1. `状态机类型`
   - `EFSM`：`48-52`
   - `HSM`：`28-32`
2. `scope_level`
   - `整机`：`12-18`
   - `子系统`：`32-40`
   - `构件`：`20-28`
3. `complexity_bin`
   - `小`：`12-18`
   - `中`：`32-40`
   - `大`：`20-28`
4. `evidence_compactness`
   - `直述`：`28-36`
   - `整合`：`24-32`
   - `重构`：`12-18`
5. `pyfcstm_fit`
   - `直接`：`20-28`
   - `轻归一`：`28-36`
   - `重归一`：`16-22`
6. `hidden_time_risk`
   - `低`：主力
   - `中`：保留一定占比
   - `高`：原则上不超过 `6-8` 条；更保守的做法是主集不进，只放 reserve

这背后的思路是：

1. `EFSM` 仍应略多于 `HSM`，因为它更贴近大批真实控制器描述，也更适合作为 `project_1` 第一版主战场。
2. `子系统` 应是主力，因为它既不像整机那么大，也不像构件那样太局部，通常最像“一个可被自然语言描述并建模的控制对象”。
3. `中` 档复杂度应最多，因为它最适合区分模型能力；全是小样本太水，全是大样本又不利于稳定实验。
4. `重构 + 重归一` 必须有，但不能主导；它们更适合作为难例层。
5. `hidden_time_risk = 高` 一定要压住，否则你的 `T0` 实验集会混进一批实际上更像 `T1+` 的样本。

### 4.5 领域上限约束

虽然不按领域做主分层，但仍要设上限。

建议：

1. 任一大领域默认不要超过主集的 `15%-20%`。
2. 强模板领域如 `🅿️ / 🏢 / 🚆` 应额外设硬上限。
3. 如果某个领域里 `cluster_key` 多样性很低，即使论文很多，也不能让它凭数量优势挤占主集。

更实际一点的规则可以写成：

1. 对高度模板化领域，主集默认不超过 `6-8` 条。
2. 同一领域里若多个样本落在相近 `cluster_key`，优先保留控制边界或复杂度更不一样的那个。
3. reserve 可以适当多留这些领域，用于后续鲁棒性分析，但主集不要堆。

## 5. 一个可直接执行的抽样流程

### 5.1 第一阶段：冻结主候选池

先只保留同时满足以下条件的样本：

1. `EFSM/HSM`
2. `T0`
3. `原文细节 = 🟢 A`
4. `描述细节 = 🟢 A`
5. `数据集角色 = 💎`
6. 六个新增字段已补齐

### 5.2 第二阶段：先做风险切分

把冻结池先拆成三层：

1. 主候选层
   - `hidden_time_risk = 低/中`
2. 观察层
   - `hidden_time_risk = 高`
3. 预备难例层
   - `evidence_compactness = 重构` 或 `pyfcstm_fit = 重归一`

这样做的目的不是把难例扔掉，而是先把“风险问题”和“难度问题”拆开。否则后面很容易把“难”与“非纯 T0”混成一类。

### 5.3 第三阶段：按 `cluster_key` 选代表

对每个 `cluster_key`：

1. 先选一条代表样本。
2. 代表样本优先级建议如下：
   - `hidden_time_risk` 更低者优先
   - `原文证据更稳` 者优先，即 `直述 > 整合 > 重构`
   - `pyfcstm_fit` 更贴近主目标者优先，即 `直接 / 轻归一` 优先于 `重归一`
   - 若以上接近，再选 `scope_level` 和 `complexity_bin` 对整体配额更有帮助的那条

### 5.4 第四阶段：按矩阵填充主集

不要按领域填，而按下面这张矩阵逐步填：

1. 先保证 `EFSM / HSM` 比例。
2. 再保证 `scope_level` 三层都有。
3. 再保证 `complexity_bin` 三层都有。
4. 再保证 `evidence_compactness` 和 `pyfcstm_fit` 不塌缩到单一档。
5. 最后用领域上限做约束修正。

更直白地说：

1. 先确保“每个重要桶里至少有人”。
2. 再挑各桶里最有代表性的。
3. 最后才看某个领域是不是已经太多了。

### 5.5 第五阶段：单独留 reserve

reserve 不是剩菜池，而是第二条防线。

建议 reserve 重点留：

1. 被 `cluster_key` 去重挤掉、但质量仍然很高的同簇次优样本。
2. `hidden_time_risk = 高` 但其余维度很好、将来可能转去 `T1` 集的样本。
3. `重构 + 重归一` 的高价值难例。
4. 某些领域主集已达上限、但仍有代表性的样本。

## 6. 如果要进一步细化数据，该怎么做

现有 6 个指标已经足够支撑“第一轮主实验集抽样”，但如果后面要把数据做成更成熟的公开 benchmark，我建议继续补下面这些信息。

### 6.1 最值得补的 6 类原文信息

1. `initial_state_explicitness`
   - 原文是否显式给出初态，还是需要从叙述反推。
2. `trigger_profile`
   - 迁移触发主要属于哪类：事件、阈值、命令、返回码、故障、timeout、周期检查。
3. `action_explicitness`
   - 原文是否明确说出状态进入/迁移后的动作或输出，而不是只写“进入某模式”。
4. `guard_variable_load`
   - guard 依赖几个关键变量、比较关系是否密集、是否存在编号条件表。
5. `recovery_chain_strength`
   - 是否有明确的异常、回退、恢复、人工接管、重试链。
6. `hierarchy_depth_hint`
   - 对 HSM 样本，层次到底是薄壳还是实质性多层。

这 6 类信息的价值在于：

1. 它们都直接影响“文本到状态机”建模难度。
2. 它们比纯领域标签更贴近实验本体。
3. 它们能帮助后续构造更稳定的 train/dev/test 分层和难例集。

### 6.2 细化时最该补的不是“更多样本”，而是“更好的切片”

如果未来要做第二版数据集，我更建议新增下面这些切片，而不是只往主集继续堆条目：

1. `纯 T0 核心集`
   - 只留 `hidden_time_risk = 低`
2. `T0 边界挑战集`
   - 主打 `hidden_time_risk = 中/高`
3. `直接映射集`
   - 主打 `直述 + 直接`
4. `归一化挑战集`
   - 主打 `整合/重构 + 轻归一/重归一`
5. `HSM 专项子集`
   - 专门验证层次状态机生成能力
6. `异常恢复子集`
   - 重点看 fault/fallback/recovery 链

这样做的好处是：

1. 每个子集的评价目标更清楚。
2. 论文里更容易讲“模型在哪一类输入上强、在哪一类输入上弱”。
3. 后续如果补 `T1/T2` 数据，也可以自然扩成一个系列 benchmark。

## 7. 参考公开数据集经验，最需要坚持的几条原则

虽然你现在不是在直接复刻某个公开 benchmark，但从现有公开数据集的经验看，下面几条非常值得吸收。

### 7.1 训练/验证/测试要按簇切，不要按行切

如果最终要做 split，默认应：

1. 先按 `cluster_key` 分组。
2. 再把簇分配到 train/dev/test。
3. 不要让同簇变体同时落在训练集和测试集。

否则最后测到的很可能只是模板记忆。

### 7.2 主集和挑战集要分开

很多公开 benchmark 的经验都是：

1. 主榜单用更稳定、更主流的样本。
2. 挑战集单独收更难、更脏、更边界化的例子。

你这里对应地就应该：

1. 主集优先 `低/中风险 + 直述/整合 + 直接/轻归一`
2. 挑战集再收 `高风险 + 重构 + 重归一`

### 7.3 不要让单一高产领域定义 benchmark

公开数据集只要被某个大类支配，最后就会变成“测这个大类的模板能力”。你的场景里最要防的就是：

1. 停车/车库/门控/升降 PLC 流程过量；
2. 某类 mission supervisor 因命名不同被重复抽入；
3. 同一种阈值控制或顺序控制换对象后重复计数。

### 7.4 reserve 很重要

经验上 reserve 的作用很大：

1. 发现主集里某一类样本过少时，可以快速补位。
2. 发现某些样本其实更像 `T1` 时，可以及时替换，不至于全盘重抽。
3. 后续论文 rebuttal 或扩展实验时，reserve 可以直接转成增量集。

## 8. 最后给一个简化版执行建议

如果你现在就要把这件事推进成一个可执行动作，我建议按下面这套来：

1. 先冻结 `EFSM/HSM + T0 + 双A + 💎` 候选池，并补齐 6 个新增字段。
2. 先按 `cluster_key` 去重，形成“簇代表池”。
3. 从 `hidden_time_risk = 高` 的样本里先剥出观察池，不急着进主集。
4. 先组一个 `80` 条主实验集，目标是：
   - `EFSM` 略多于 `HSM`
   - `子系统` 为主，`整机/构件` 不缺位
   - `中` 档复杂度最多，`小/大` 两头都保留
   - `直述/整合` 为主，保留少量 `重构`
   - `直接/轻归一` 为主，保留一部分 `重归一`
5. 再单独留 `20` 条 reserve，重点吸收：
   - 同簇次优高质量样本
   - 高风险边界样本
   - 难例层样本
6. 如果后续还要继续做精，优先补：
   - 触发类型
   - guard 变量负载
   - 异常恢复链
   - 初态明确性
   - 动作显式性
   - HSM 层次深度

一句话总结：

这批数据已经不缺“候选数量”，真正缺的是“基于控制图像簇和建模难度层的采样治理”。只要把这件事做对，`60-100` 条完全够支撑一版很扎实的 `project_1` 实验集。
