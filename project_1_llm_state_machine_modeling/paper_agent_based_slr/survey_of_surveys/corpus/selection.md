# A2a 语料选择协议

本文件规定 A2a 如何从原始候选进入全量候选账本、系统化候选池、主候选语料、替补 / 留出语料和边界池。所有机器表由 [../scripts/build_corpus_tables.py](../scripts/build_corpus_tables.py) 复算生成。

## 1. 五层语料定义

| 层级 | 中文名称 | 当前数量 | 作用 |
|---|---:|---:|---|
| L0 | 全量候选账本 | 438 | 保留前序候选摸排的候选分母，防止只凭直觉挑文献。 |
| L1 | 系统化候选池 | 293 | 标题、摘要或类型显示其可能是 SLR / SMS / MLR / tertiary 的二次研究。 |
| L2 | 主候选语料 | 120 | A2b 优先全文深读对象；A1 已有 13 篇入池候选默认计入。 |
| L3 | 替补 / 留出语料 | 40 | 用于替换 A2b 深读时被排除、全文失败或类型误收的条目。 |
| L4 | 边界 / 方法启发池 | 145 | 普通综述、路线图、taxonomy、愿景或系统性不足的条目。 |

## 2. 去重规则

去重优先级为：

1. DOI 规范化结果。
2. 规范化标题。
3. 标题 + 作者 + 年份 + venue 的人工复核。

生成脚本会把 DOI 和标题分别写入 `normalized_doi` 与 `normalized_title`，并检查主候选、替补和边界池之间互斥。

## 3. 系统化候选判定

条目进入 L1 至少需要满足一项：

1. 标题或元数据明确包含系统文献综述、系统映射、多声部综述、三级研究等信号。
2. 标题包含 `systematic`、`systematic mapping`、`mapping study`、`multivocal`、`tertiary` 或 `review of reviews` 等信号。
3. 来源表中的类型字段被标为系统综述 / 系统映射。

普通 `survey`、`overview`、`roadmap`、`taxonomy`、`vision` 若没有系统检索、纳排、编码和数据抽取证据，不进入 L1 主体，只进入边界池。

## 4. 主候选 120 规则

主候选由两部分构成：

1. A1 已完成全文文本级审计且 `eligible_for_statistical_synthesis=true` 的 13 篇，默认进入主候选，并保留既有 `review.md` 与 `evidence_chain.md`。
2. 前序系统化候选快照按 CCF 等级、年份、全文状态、引用量、主题多样性补齐到 120 篇。

主题补齐时至少覆盖：大语言模型 / 生成式 AI、软件测试与质量、需求工程、模型驱动工程、软件架构、开发者与生产力、安全 / 可靠性、教育 / 人因、经验软件工程方法学、自动化工具与证据链。

每条主候选必须有 `selection_reason`。

## 5. 替补与边界池规则

替补 / 留出语料从未进入主候选的 L1 条目中选取，要求与主候选保持尽量相似的 venue、年份、主题和综述类型分布。每条替补必须有 `reserve_reason`。

边界池收纳系统性不足但有方法启发或边界价值的条目。每条边界条目必须有 `boundary_reason`。边界池不能进入 A2b 主统计分母，除非后续全文核验证明其实际满足系统化二次研究条件并通过显式升级。
