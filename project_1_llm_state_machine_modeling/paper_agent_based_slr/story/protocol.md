# 当前阶段最小协议：审计优先证据工程方法

## 1. 协议目标

本协议定义当前阶段的最小方法边界。它不是最终实现、不是完整数据结构、不是用户界面设计，也不是 PRISMA 透明报告框架（Preferred Reporting Items for Systematic Reviews and Meta-Analyses, PRISMA）合规流程；它只规定后续设计、试运行、真实运行、评价和相关工作必须保留的输入、输出、研究者门控、证据类型和发现生命周期。

核心原则：**论文收集、维度模式驱动的论文分析、统计分析和研究发现形成必须分层；智能体只能在研究者批准的维度模式下辅助执行和提出候选信号，最终发现必须经过研究者裁决；每个关键环节都必须导出可审计制品，而不是只留下自然语言总结。**

术语写作遵守 [terminology_policy.md](./terminology_policy.md)：首次出现写“中文术语（英文术语 / 缩写）”，后续优先使用中文术语。

## 2. 证据类型

| 类型 | 来源 | 支撑对象 | 禁止误用 |
|---|---|---|---|
| 字段级内容证据（field-level content evidence） | 目标论文全文、元数据、图表、表格、制品链接、原文片段、缺失说明 | 字段值、统计分析、候选 / 最终领域发现 | 不能用过程日志替代；不能没有来源锚点就写强主张。 |
| 过程证据（process evidence / audit trail） | 人机交互、模式修订、批准、质疑、裁决、回填、提示、原始日志、脱敏记录、时间成本 | 方法发现、可审计性、成本、失败模式；其中质疑 / 裁决记录还提供候选发现进入最终状态的程序资格 | 不能作为领域事实的实质证据，不能替代目标论文内容证据。 |

## 3. 阶段契约

| 阶段 ID | 阶段 | 输入 | 输出 | 必需审计信息 |
|---|---|---|---|---|
| L0 | 主题 / 研究问题 / 范围 / 综述元模型设定 | 研究者问题意识、初始研究问题、领域范围、种子论文 | 主题说明、综述元模型、范围边界 | 研究者批准记录、版本、范围排除理由 |
| L1 | 脚手架挖掘 / 种子探测 | 既有综述、系统综述、系统映射研究、种子论文、L0 综述元模型 | 候选维度模式、发现启发式、证据呈现模式 | 来源、采纳 / 拒绝理由、不是目标证据池的声明 |
| L2 | 维度模式准备与批准 | L0 综述元模型、L1 候选模式、纳排标准 | 研究者批准的维度模式 | 字段定义、取值空间、缺失值语义、证据要求、批准记录 |
| L3 | 论文收集与概览 | 数据库、查询式、候选论文池、L2 维度模式 | 检索日志、筛选台账、全文状态、概览卡 | 查询式、命中数、排除理由、全文不可得记录、抽查记录 |
| L4 | 字段级证据抽取与模式演化 | 全文 / 元数据、已批准维度模式、概览卡 | 字段证据表、来源锚点、不确定性、修订 / 回填日志 | 页码 / 章节 / 引文 / 表格 / 制品锚点、字段置信、模式变更触发原因 |
| L5 | 统计分析 | 字段证据表、分析协议、覆盖率代理定义 | 分布、频次、交叉表、趋势、覆盖率代理、矛盾信号 | 分析协议、字段版本、纳入样本、统计限制 |
| L6 | 候选发现生成 | 统计分析、发现启发式、内容证据 | 候选发现台账、支持 / 反向证据草案、主张强度草案 | 发现类型、支持证据、反向证据、不确定性、范围 |
| L7 | 研究者质疑 / 最终裁决 | 候选台账、证据链、研究者质疑 | 接受 / 降级 / 拒绝 / 未解决发现、质疑日志、透明材料 | 质疑内容、补证、反例、降级理由、裁决人、时间、残余风险 |

## 3.1 横切过程证据集合

过程证据不是新的主流程阶段，也不改变 L0--L7 的阶段编号。它是横切 L0--L7 的审计数据包，记录综述元模型批准、维度模式批准、模式修订、回填、统计协议、质疑、裁决、交互轮次、人工修改、成本和脱敏状态。发布或用于方法发现前，必须经过 G6 过程证据边界门控。


## 3.2 审计制品链

S0-v2 后，方法不能只定义流程和门控，还必须定义可导出、可检查、可失败的审计制品链。后续设计和试运行至少应产出以下制品；若某项暂不能产出，必须记录阻塞原因和对论文主张的影响。

| 制品 | 上游来源 | 下游用途 | 最小验收 |
|---|---|---|---|
| 维度模式与修订 / 回填日志 | L0--L2，G1/G2 | 约束 L4 抽取，解释模式演化 | 有版本、触发原因、影响字段、受影响论文、回填状态和冻结理由 |
| 字段级内容证据表 | L4 | 支撑 L5 统计分析和 L6 候选发现 | 每个关键字段有来源锚点或缺失 / 不确定说明 |
| 统计分析表 | L5/G3 | 形成统计观察，不直接形成最终发现 | 记录字段版本、纳入样本、统计方法和限制 |
| 候选发现台账 | L6 | 进入 G4 质疑 | 记录发现类型、支持证据、反向证据、不确定性和主张强度 |
| 质疑 / 裁决 / 未解决日志 | L7/G4/G5 | 决定领域发现状态 | 记录质疑、补证、反例、接受 / 降级 / 拒绝 / 未解决和裁决理由 |
| 过程证据包 | 横切 L0--L7/G6 | 支撑方法发现 | 记录提示、运行、人工修改、成本、错误、脱敏和访问边界 |

## 4. 维度模式生命周期

维度模式是本方法的一等制品。每次模式变化至少记录：

| 字段 | 含义 |
|---|---|
| 模式版本 | 版本号。 |
| 变更触发原因 | 新论文类型、抽取失败、研究者发现遗漏、脚手架模式、审稿风险等。 |
| 拟议变更 | 新增 / 删除 / 合并 / 拆分字段、取值空间变化、证据要求变化。 |
| 批准记录 | 研究者批准人或裁决记录。 |
| 变更理由 | 为什么需要本次修订。 |
| 受影响字段 | 本次修订影响哪些字段或取值。 |
| 受影响论文 | 需要回填或复核的论文。 |
| 是否需要回填 | 是否需要回填。 |
| 回填状态 | 未开始 / 进行中 / 已完成 / 豁免。 |
| 冻结理由 | 模式稳定或暂时冻结理由。 |

最小规则：未经研究者批准的模式修订不能进入正式抽取；若模式修订改变已抽取字段语义，必须记录影响分析和回填状态。

## 5. 统计分析到研究发现的转移规则

统计分析与研究发现的关系必须满足：

```text
字段级内容证据 -> 字段证据表 -> 统计分析 -> 候选发现 -> 质疑 / 裁决 -> 最终领域发现
```

禁止直接执行：

```text
频次 / 分布 / 交叉表 -> 最终发现
```

候选发现升级为最终领域发现的最低条件如下。前四项提供领域主张真假与强度的实质支撑，第五项只提供程序资格和最终状态，不替代内容证据。

1. 支持性内容证据可回到来源锚点；
2. 反向证据 / 不确定性已被检查或显式标为未解决；
3. 范围与主张强度经研究者确认；
4. 若模式或统计协议变化会影响该发现，必须先完成必要回填或标记局限；
5. 最终状态由研究者裁决记录确认。

| 门控 | 位置 | 输入 | 决策类型 | 最小记录 |
|---|---|---|---|---|
| G0 | L0 后 | 主题说明、研究问题、范围、综述元模型 | 批准 / 修订 / 拒绝 | 版本、理由、排除范围 |
| G1 | L2 后 | 维度模式草案 | 批准 / 修订 / 拒绝 | 字段、取值、证据要求、批准记录 |
| G2 | L4 中 | 模式修订提案、影响分析 | 批准 / 拒绝 / 暂缓 / 要求回填 | 触发原因、影响论文、回填状态 |
| G3 | L5 前 | 统计分析协议 | 批准 / 修订 | 字段版本、统计方法、限制 |
| G4 | L6/L7 | 候选发现与证据链 | 质疑 / 接受候选 / 要求反向证据 | 质疑、补证、反例、主张强度变化 |
| G5 | L7 终段 | 修订后发现与证据链 | 接受 / 降级 / 拒绝 / 未解决 | 最终状态、理由、残余风险 |
| G6 | 横切 L0--L7，并在过程证据发布前 | 过程证据发布包 | 批准 / 脱敏 / 限制访问 | 同意、匿名化、脱敏、访问权限 |

## 7. 综述之综述边界

综述之综述在本方法中只承担脚手架挖掘 / 模式先验角色：

- 抽取对象：研究问题类型、分类 / 维度模式、发现模式、证据呈现模式、威胁与局限写法。
- 不抽取对象：目标领域最终结论，不作为目标系统综述语料的证据池。
- 禁止主张：不写 PRISMA 透明报告框架合规三级综述，不写完整覆盖。
- 可用方式：与种子探测并行作为启动来源；其模式必须经研究者采纳才进入可执行维度模式。

## 8. 试运行与学生过程数据边界

| 数据 | 目的 | 不能支撑 |
|---|---|---|
| 试运行 | 验证方法闭环、制品完整性、模式 / 回填可操作性、发现质疑是否能跑通 | 跨主题泛化、方法优于人工、目标领域最终结论 |
| 硕士生过程数据 | 评价使用者交互成本、理解难点、审计行为、提示 / 编辑过程、失败模式 | 目标领域系统综述发现的文献证据 |

后续如收集学生数据，必须提前冻结同意、匿名化、提示 / 原始日志脱敏、教学关系隔离、数据保存和访问权限。

## 9. 当前阶段不冻结的内容

1. 完整数据结构细节；由后续设计冻结。
2. 最终试运行主题、样本和场景数量；由后续试运行冻结。
3. 真实智能体实现、提供商和模型；由后续真实运行冻结。
4. 指标公式、阈值和统计协议；由后续评价冻结。
5. 相关工作最终写法；由相关工作深化。
6. 真实大语言模型调用；后续若调用必须 `source .env` 并保存运行记录。
