# 术语策略：S0-v2 智能体辅助系统综述论文

## 1. 目的与写作规则

本文术语容易与传统系统综述、系统映射研究、PRISMA 透明报告框架（Preferred Reporting Items for Systematic Reviews and Meta-Analyses, PRISMA）报告、自动筛选工具、大语言模型生成综述文本和通用智能体工作流混淆。本文件冻结当前阶段的术语口径，后续写摘要、引言、方法、协议、评价或 PR 评论 时应优先遵守。

**统一写法**：同一文档中，术语首次出现必须写为“中文术语（英文术语 / 缩写）”，例如“系统综述（Systematic Literature Review, SLR）”。首次定义后，除论文名、工具名、路径、命令、阶段编号和必要缩写外，一律使用中文术语，不再反复堆叠英文。

## 2. 核心术语

| 首次出现写法 | 后续默认写法 | 推荐口径 | 避免误读 |
|---|---|---|---|
| 系统综述（Systematic Literature Review, SLR） | 系统综述 | 按可追溯协议检索、筛选、抽取和综合研究证据的综述活动。 | 不等于普通文献摘要或自动生成报告。 |
| 系统映射研究（Systematic Mapping Study, SMS） | 系统映射研究 | 更偏领域结构、主题分布、研究类型和证据地图的系统化综述活动。 | 不等于无协议的论文分类表。 |
| 大语言模型（Large Language Model, LLM） | 大语言模型 | 可用于筛选、抽取、摘要、归类和候选线索生成的模型能力来源。 | 不等于最终研究裁决者。 |
| 智能体（agent） | 智能体 | 围绕任务、工具、提示和状态进行协作执行的软件代理。 | 不等于端到端无人自动系统综述专家。 |
| 研究者引导的智能体式系统综述支持方法（researcher-guided agentic SLR/SMS support approach） | 研究者引导的智能体式支持方法 | 研究者定义问题框架、批准模式、解释统计、质疑候选发现并裁决最终发现；智能体只辅助执行和生成候选信号。 | 不等于自动写综述，也不等于研究者只做末端签字。 |
| 审计优先证据工程方法（audit-first evidence engineering approach） | 审计优先证据工程方法 | 把综述元模型、维度模式、字段级内容证据、统计观察、候选发现、质疑 / 裁决和过程证据组织成可导出、可检查、可失败的证据工程链。 | 不等于只画流程图，也不等于声称证据链已经被实验证明有效。 |
| 综述元模型（review meta-model） | 综述元模型 | 帮助研究者声明主题、研究问题、范围、对象、关系、证据类型和发现类型的可配置工作模型。 | 不是作者预设的通用软件工程本体，也不是大语言模型自动生成的最终模型。 |
| 主题特定综述元模型（topic-specific review meta-model） | 主题特定综述元模型 | 研究者针对具体系统综述 / 系统映射研究主题实例化后的工作模型。 | 不等于可直接执行的抽取字段表；还需要投影为维度模式。 |
| 维度模式（dimension pattern / extraction schema） | 维度模式 | 综述元模型在单篇论文分析任务上的字段化、树状 / 类型化、可版本化投影，包括字段、取值空间、证据要求、缺失值语义和回填规则。 | 不是一次性平铺字段表，也不是提示词中的隐含检查清单。 |
| 模式演化（pattern-evolving） | 模式演化 | 维度模式随种子论文、脚手架、抽取失败、新类别和研究者理解深化而修订，并保留版本、影响范围和回填状态。 | 不表示智能体可以绕过研究者自行改模式。 |
| 综述之综述脚手架（survey-of-surveys scaffold） | 脚手架 | 从既有软件工程、AI4SE、模型驱动工程和 LLM4SE 综述、系统综述、系统映射研究中低成本抽取维度、发现和证据呈现模式。 | 不是目标系统综述语料，不进入领域发现证据池，不是 PRISMA 三级综述。 |
| 种子论文探测（seed-paper probing） | 种子探测 | 用少量种子论文压力测试候选维度模式是否可执行。 | 不代表完整语料结论，也不决定最终综述元模型。 |
| 概览卡（overview card） | 概览卡 | 对候选论文的初步元信息、范围、全文状态和粗粒度相关性记录。 | 不等于字段级证据对象，也不支撑最终发现。 |
| 字段级内容证据（field-level content evidence） | 内容证据 | 来自目标论文原文或元数据的可定位证据，如章节、页码、引文、表格、图、制品链接、缺失原因和不确定说明。 | 不是普通摘要，也不是过程日志。 |
| 字段证据表（evidence table） | 字段证据表 | 在研究者批准的维度模式下抽取得到的字段值与来源锚点。 | 不等于最终发现，也不等于统计结论。 |
| 统计分析（statistical analysis） | 统计分析 | 对字段证据表做频次、分布、交叉表、趋势、覆盖率、矛盾信号等描述性 / 归纳性分析。 | 不是最终研究发现。 |
| 统计观察（statistical observation / output） | 统计观察 | 统计分析的输出，如分布表、趋势或覆盖代理。 | 避免写成“统计发现”；若使用“发现”一词必须注明不是研究发现。 |
| 发现启发式（finding heuristic / finding pattern） | 发现启发式 | 指导智能体从统计观察和内容证据中提出候选发现的启发式，如缺口、趋势、共识、矛盾、成熟度。 | 不保证发现为真。 |
| 候选发现信号（candidate finding signal） | 候选发现 | 智能体基于统计观察、发现启发式和内容证据提出的待审计线索。 | 不是最终发现，不应进入摘要或结论。 |
| 目标领域研究发现（target-domain research finding） | 领域发现 | 基于目标论文内容证据、统计分析、反向证据、不确定性和研究者裁决形成的领域主张。 | 不能由过程证据或智能体输出直接支撑。 |
| 方法评估发现（method-evaluation finding） | 方法发现 | 基于试运行、学生过程数据、交互日志、成本、审计记录形成的关于方法本身的发现。 | 不能当作目标领域文献证据。 |
| 过程证据（process evidence / audit trail） | 过程证据 | 人机交互、模式修订、批准、质疑、裁决、回填、提示、原始日志、脱敏和成本记录。 | 只能支撑方法评估，不支撑领域发现。 |
| 研究者质疑（researcher challenge） | 研究者质疑 | 研究者围绕候选发现提出证据不足、反例、范围过宽、主张过强或模式不适配等质疑。 | 不是简单“人工通过”。 |
| 最终裁决（final adjudication） | 最终裁决 | 研究者将候选发现裁决为接受、降级、拒绝或未解决。 | 不是智能体自动决定。 |
| PRISMA 透明报告框架（Preferred Reporting Items for Systematic Reviews and Meta-Analyses, PRISMA） | PRISMA 透明报告框架 | 系统综述透明报告的常用框架。 | 本文当前只使用其透明报告思想；不声明合规。 |
| 透明材料（transparency package） | 透明材料 | 主张-证据映射、排除理由、模式修订、审计日志、类 PRISMA 材料等透明制品。 | 不等于自动生成最终论文，也不等于 PRISMA 透明报告框架合规。 |
| 审计制品链（audit artifact chain） | 审计制品链 | 至少包含维度模式与修订 / 回填日志、字段级内容证据表、候选发现台账、质疑 / 裁决 / 未解决日志和过程证据包。 | 不是可选附录；若无法导出，应降级方法主张。 |
| 最小闭环样例（minimum end-to-end dry-run） | 最小闭环样例 | 用少量种子论文跑通 L0--L7，展示模式修订、回填、统计观察、候选发现和最终裁决。 | 不证明泛化，也不证明优于人工。 |
| 风险到指标矩阵（risk-to-metric matrix） | risk-to-metric 矩阵 | 把强近邻威胁和审稿风险映射为来源锚点准确性、断链率、过强主张率、回填负担、质疑拦截率等评价方向。 | 不等于已冻结公式、阈值或最终结果。 |

## 3. 发现与分析状态

| 状态 | 定义 | 可写入论文的位置 |
|---|---|---|
| 统计观察 | 字段表上的统计观察，例如某类方法占比、制品可用性覆盖率。 | 结果表、分析材料；不能直接写成最终研究发现。 |
| 候选发现 | 智能体提出的可能发现线索。 | 方法、案例、审计过程；不能写成结论。 |
| 已质疑发现 | 已被研究者质疑并要求补证、反例或降级。 | 质疑日志、错误分析。 |
| 已降级发现 | 原主张过强，被缩小范围或降低强度。 | 结果 / 讨论中可写，但必须说明降级理由。 |
| 已接受领域发现 | 经内容证据、反向证据与研究者裁决接受。 | 可作为目标领域研究发现。 |
| 未解决发现 | 证据不足或冲突过大，暂不进入强结论。 | 局限、后续工作、未解决台账。 |
| 方法发现 | 关于方法可用性、成本、审计性、失败模式的发现。 | 方法评估结果；不能混入领域发现。 |

## 4. 人工门控术语

人工门控不是一句“人工审核”，必须至少包含：输入制品、决策类型、理由、版本变化、影响范围、后续动作、行动者 / 时间戳和资格后果。

| 门控 | 推荐名称 | 作用 |
|---|---|---|
| G0 | 综述元模型批准 | 批准主题、研究问题、范围和综述元模型。 |
| G1 | 维度模式批准 | 批准可执行抽取模式。 |
| G2 | 模式修订 / 回填门控 | 批准模式变更、影响分析和回填策略。 |
| G3 | 统计分析协议门控 | 批准统计分析输入版本、方法和限制。 |
| G4 | 候选发现质疑门控 | 质疑候选发现的证据、反例、范围和主张强度。 |
| G5 | 最终裁决门控 | 裁决接受、降级、拒绝或未解决。 |
| G6 | 过程证据边界门控 | 审批日志、脱敏、同意和发布边界。 |

## 5. PRISMA 与脚手架术语

| 术语 | 使用规则 |
|---|---|
| PRISMA 透明报告框架合规 | 禁止在检查清单未闭合前作为正向主张。 |
| 类 PRISMA 材料 | 可用于透明材料、流程图、排除理由台账；必须说明不是合规声明。 |
| PRISMA 透明报告框架启发 | 可用于说明受透明报告思想启发。 |
| 脚手架 | 只作为模式挖掘 / 模式先验；不写完整覆盖，不写三级综述。 |
| 目标证据池 | 目标领域系统综述的论文证据池；不包含脚手架，除非该综述本身是目标语料的纳入论文并按相同规则处理。 |

## 6. 禁止或高风险写法

| 写法 | 处理 |
|---|---|
| 智能体完全替代系统综述专家 | 禁止主张。 |
| 端到端无人自动产出合格系统综述 | 禁止主张。 |
| 首次自动化系统综述 / 首次智能体式系统综述 | 禁止主张。 |
| PRISMA 透明报告框架合规 | 未完成检查清单前禁止作为正向主张。 |
| 完整覆盖 | 禁止；只能写覆盖代理。 |
| 大语言模型定义综述元模型 | 改为“大语言模型可建议，研究者负责实例化和批准”。 |
| 大语言模型 / 智能体产出最终发现 | 改为“智能体产出候选发现，研究者裁决最终发现”。 |
| 统计分析给出最终发现 | 改为“统计观察启发候选发现；最终发现需要证据审计”。 |
| 过程证据支撑领域发现 | 禁止；过程证据只支持方法发现。 |
| 脚手架证明领域发现 | 禁止；它只提供模式先验。 |
| 试运行证明泛化 | 禁止；试运行只验证闭环可行性和制品完整性。 |
| 学生日志说明领域现状 | 禁止；学生日志只能评价方法过程。 |
| 研究者只是验证最终报告 | 改为“研究者拥有综述元模型、维度模式、质疑、裁决和过程边界”。 |

## 7. 中文写作要求

正式 Markdown 说明以中文为主。必要英文只在首次定义、论文 / 工具名、路径、命令、代码标识和缩写锚点中保留；不要整段英文堆叠。论文后续英文稿另行维护，不在当前阶段生成。
