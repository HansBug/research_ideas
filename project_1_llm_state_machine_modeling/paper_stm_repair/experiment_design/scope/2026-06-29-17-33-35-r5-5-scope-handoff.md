## 1. 定位

本文件把 R5.5 的 model scope handoff 落到 `experiment_design/scope/` 下，作为 R5.6 开工前的正式 scope 入口草案。它不冻结最终主实验协议、不选择最终样本上限，也不声明 repair loop 结果；它只冻结 R5.5 已能支持的实验对象边界和后续 R5.6/R5.7/R6 应遵守的 scope discipline [clm-scope-doc-role]。R5.6 已把该 discipline 收敛到 [../../story/model_scope.md](../../story/model_scope.md)。

## 3. 对 R5.6 的最低要求

R5.6 已在 [../../story/model_scope.md](../../story/model_scope.md) 继承并收敛以下最低要求；后续 R5.7/R6/R7 不得重新打开这些边界：

1. 正文主 claim 限定在 T0 离散 FSM/HSM/UML-SysML statechart artifacts；不能外推到 timed automata、hybrid automata 或完整 EFSM 覆盖 [clm-scope-main-claim].
2. T0.5 只能写作 timer-like caveat under event abstraction；Digital Camera / T1 只能写作 supplementary stress 或 limitation [clm-scope-caveat].
3. `condition_like_label_lowered_as_event`、层级 lowering、scope lifting、initial inference 都只是 R5.7 候选 / caveat；不能在 R5.6 中提前写成已确认 repair target [clm-scope-r57-candidate].
4. 60 raw pair 必须按 `10 unique NL clusters × 6 LLM outputs` 双口径报告，不能写成 60 个独立需求 [clm-scope-denominator].
5. conversion / normalization / `.fcstm` lowering 的收益不得计入 repair gain；R6 之前没有 `STM_k` 或 Better STM 主结果 [clm-scope-no-repair-gain].

## 4. 与 story / eligibility / protocol 的分工

- `story/` 负责论文叙事、claim gate 和哪些话不能说。
- `experiment_design/scope/` 负责实验对象边界、时间层级、系统族和 analysis role。
- `experiment_design/eligibility/` 后续再冻结具体 run / seed / failure handling 纳入规则。
- `experiment_design/protocols/` 后续再冻结真实 repair loop、对照、人工裁决和回滚协议。

若后续 R5.7/R6/R7 发现新证据与 R5.6 scope 冲突，应优先更新 [../../story/model_scope.md](../../story/model_scope.md) 或新增 superseding scope 文件，并在 [README.md](./README.md)、[../SUMMARY.md](../SUMMARY.md) 与 [../../story/task_boundary.md](../../story/task_boundary.md) 中同步指向新的 scope 真源 [clm-scope-sync-rule]。

## 5. 当前不能写的 scope claim

2. 不能写 Digital Camera / T1 支撑主线 T0 claim。
3. 不能写 R5.5 的 `converted / partial / blocked` 是 repair 效果。
4. 不能写 `condition_like_label_lowered_as_event` 已经是确认缺陷类型。
5. 不能写 57/60 可到 `.fcstm` 等价于 57/60 可进入主实验效果统计。
