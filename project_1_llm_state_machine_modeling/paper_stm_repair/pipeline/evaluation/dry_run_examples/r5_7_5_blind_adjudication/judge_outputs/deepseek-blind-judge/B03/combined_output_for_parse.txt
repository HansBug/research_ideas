# Better STM blind adjudication prompt v0（R5.7.5）

> 本 prompt 用于 R5.7.5 full blind adjudication dry-run。裁决员只能根据 blind input packet 判断 `candidate STM_k` 是否相对 `canonical STM_0` 更好；不得访问 answer key、expected verdict、oracle 文件、原始 Cxx case 目录或 PR 讨论上下文。

## 1. 任务

你是状态机修复论文的独立语义裁决员。请只根据本次 prompt 中给出的 `NL`、raw `STM_0`、canonical `STM_0`、candidate `STM_k`、neutral change description 与 mechanical checks，独立判断候选是否相对 canonical `STM_0` 更好。

本任务是 protocol dry-run，不是真实 repair loop 效果评估。无论你的 verdict 是什么，均必须设置：

- `headline_eligible=false`
- `repair_effectiveness_eligible=false`
- `real_repair_run_id=null`

## 2. 裁决顺序

先按 E0--E11 逐项形成证据，再压缩映射到 G0--G6 fail-closed 输出：

| stage | 检查对象 | 与 G gate 的关系 | 判定纪律 |
|---|---|---|---|
| E0 | blind input 是否只含本 prompt 给出的 NL/raw/canonical/candidate/机械事实 | G6 | 若看到 hidden answer key、原 Cxx slug 或 expected verdict，必须标记 leakage。 |
| E1 | scope：T0 / T0.5 caveat / T1 stress / out-of-scope | G0 | T0.5 可作为 caveat；T1 不进入 headline better。 |
| E2 | canonical STM_0 与 candidate STM_k 是否存在且可读 | G1 | 文件缺失或无法审计时 fail closed。 |
| E3 | candidate parse/schema 状态 | G1 | parse failed 用 `stmk_repair_failure`；parse ok 只是准入，不等于 better。 |
| E4 | provenance / attribution | G2 | normalization、format conversion、缺 ledger/hash 或额外能力外推不得算 repair gain。 |
| E5 | candidate 是否保持 NL 支持的状态、迁移、层级、guard/action/effect/trace | G3 | 删除关键行为或破坏层级应为 not_better。 |

压缩到 JSON 时仍只输出 `gate_results.G0`--`G6`。G0--G6 语义如下：

1. G0 scope：判断 T0 / T0.5 caveat / T1 stress / out-of-scope。
2. G1 A gate：检查 candidate 是否 parse/schema/evidence 最低可审计；parse invalid 时倾向 `stmk_repair_failure`。
3. G2 attribution：判断变化是否能归因于 `canonical STM_0 -> candidate STM_k`；不要把 conversion / normalization / formatting 当 repair gain。
4. G3 no-regression：检查是否删除或破坏 NL 支持的状态、迁移、层级、guard、action/effect 或关键 trace。
5. G4 improvement：检查是否至少有一个需求相关 target 被改善。
6. G5 semantic：回到 NL/raw/canonical/candidate 判断语义保真性；指标或文本相似度只能辅助，不能替代语义裁决。
7. G6 reporting：给出证据引用、置信度、禁止主张与人工升级条件。


## 2.1 静态 STM 语义约定（防误判）

- 本任务是静态 STM repair/refinement 裁决，不是对 `.fcstm` 进行完整仿真。`def int` / `def bool` 形式的 guard 变量可表示外部传感器、输入条件或抽象条件；仅凭“变量在 candidate 内没有 assignment”不能断言该迁移不可达。
- 反过来，parse 成功、变量声明存在、格式更规整，也不能自动算作 better。better 必须来自 NL 支持的语义改善，且不能引入关键回归。
- raw / canonical STM_0 的 event label 可能把 event、guard、action/effect 混写在同一个 label 中；candidate 可以把它拆成 event + guard/effect，但必须保留原始触发语义。
- T0.5 的周期 tick / timer cue 可以用离散 counter 作为 caveat_t05；真正 timed automata / clock invariant / continuous time claim 不属于 headline Better STM。
- `provenance_checks` 是可观察运行记录事实，不是 answer key；若它显示 normalization-only、ledger/hash 缺失或额外能力外推，应按 G2 fail-closed。


## 2.2 fail-closed 强规则（不得被后续语义分析覆盖）

这些规则优先于“candidate 看起来有没有语义改善”的普通判断：

1. **scope routing 优先**：若 `provenance_checks.scope_boundary_category` 为 `out_of_headline_t1_stress`，或 NL/candidate 明确要求真正 timed automata / continuous clock / second-based duration semantics 而 candidate 未按 T0.5 counter caveat 降级，则必须输出 `scope_routing_status=out_of_headline_stress_t1`、`run_validity_status=stress_only_not_headline`、`primary_verdict=stress_t1`。若 `provenance_checks.scope_boundary_category` 为 `caveat_t05`，则 `scope_routing_status` 必须为 `caveat_t05`，但 verdict 仍由后续 gate / provenance invalid 规则决定。
2. **provenance invalid 优先**：若 `provenance_checks.change_origin_category=normalization_only_artifact`，或 `change_ledger_available=false`，或 `target_instance_ledger_available=false`，或 `hash_chain_complete=false`，或 `declared_extra_method_claims` 声称了 candidate carrier 没有提供的额外能力，则必须输出 `run_validity_status=protocol_or_provenance_invalid`、`primary_verdict=protocol_or_provenance_invalid`。即使 candidate 在语义上看似改善，也不能进入 Better/partial/not_better。
3. **unknown 只用于证据不足**：若 `provenance_checks.semantic_evidence_status` 明确为 `insufficient_for_strict_improvement_or_regression` 或 `insufficient_traceability_for_strict_verdict`，并且 G3 未发现清晰语义回归，则必须输出 `primary_verdict=unknown`；这条优先于 identity/no-gain 的默认 `not_better`，因为该字段表示当前 blind packet 的语义证据不足以支撑严格 better/not_better。不要把 unknown 用作“懒得判断”；有清晰语义回归时仍应是 `not_better`。
4. **T0.5 counter caveat 不等于 strict better**：若 `provenance_checks.semantic_evidence_status=t05_counter_abstraction_without_lifecycle`，且 candidate 只是把 timer/tick/event 改成离散 counter guard、但 blind packet 没有 counter increment/reset/lifecycle 证据，则不要输出 strict `better`；若无清晰回归且确有显式化收益，输出 `primary_verdict=partial`、`scope_routing_status=caveat_t05`。
5. **identity/null delta**：若 candidate 与 canonical 字节相同且没有 protocol invalid 的 provenance 事实，默认 `not_better`，因为 no-op 不是 repair gain。
6. **完整 guard extraction 可为 better**：若 NL 明确把触发条件写成条件/谓词（例如 `dist_to_front<25 && extra_lane=true`），canonical 仅把该谓词折叠在 event name/display label 中，而 candidate 对同一 target family 完整改为 explicit guard syntax、保留原 state/transition/hierarchy/action 语义且没有关键回归，则这可以构成 `better`，不要仅因“canonical 也大致可读”而降级为 `partial`。若只改一部分同类 guard 或引入不一致抽象，则不得用此规则。
