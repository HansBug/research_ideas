### 4.2 现有工作为什么在 L2/W2 上不够好（1）

【导师直接表达·用户转述】大纲说现有工作在 L2 与 W2 上不够好，但没剖析为什么。用户的理解：普遍缺少一个可用于执行与检查、行为语义明确的介质来承担这两件事，所以 LLM for STM issue discovery 才做不好 L2/W2；由此顺理成章引出基于 FCSTM 转换的方法。学术依据要找到。

【AI 衍生建议】论证链可以写成三段，每段有现成文献：(i) PlantUML/UML 文本没有执行语义——UML 规范留有 semantic variation point，André 等（CSUR 2023）的综述列出几十种互不相同的状态机形式化，说明「从图到可执行」必须选定并实现一套语义；(ii) 规则式检查（Li 与 Zheng、Torre 等的规则目录）只在元素关系上操作，Baier–Katoen「不变式可由可达集判定、路径性质不能」给出它够不到 L2 的理论边界；(iii) LLM 审稿人读文本，可达性与守卫可满足性只能在推理里模拟——需补一两篇 LLM 多步图推理随规模退化的实证文献。W2 同理：没有可执行对象就没有可回放的求值。这一段放 §2 末尾，直接接方法总览。文献 (iii) 尚未核实，标【待补】。

### 4.3 FCSTM 的定位（2）

【导师直接表达·用户转述】两点。第一，「为什么用 FCSTM 而不用 Simulink 或 Sismic」是易被挑战的点，要说清我们工具的功能并与同类工具简要对比。第二，再次强调 FCSTM 纯粹是工程向的东西，用途是给 LLM 提供信息（模型检查信息与证据信息）；里面用的算法包括 BMC 要说清，它们是经典算法的实现，工具本身无创新，只是方法的工程实现方式。

【AI 衍生建议】对比表的列：能否从 PlantUML 自动投影、UML 式层次与 run-to-completion 语义、变量与守卫、可脚本化的静态检查 API、有界模型检查、到源行的来源映射。候选行：Stateflow（商业、MATLAB 绑定、语义与 UML 不同）、Sismic（Python 状态图，有仿真与契约，无有界模型检查、无源行映射）、SCXML 引擎、itemis CREATE/Yakindu、UPPAAL/SPIN/NuSMV（需人工翻译；UPPAAL 是时间自动机，模型类不同）。来源映射是别的工具都没有的一项，W1/W2 的定位与回执要靠它。算法层按 pyfcstm 实际实现写（M，读自 `pyfcstm/README.md` 与 `pyfcstm/verify/`）：静态检查是 `inspect_model()` 的图算法与诊断码；仿真是宏步执行的运行时；有界模型检查把 `.fbmcq` 查询编译为 Z3 求解的 SMT 公式，解码 SAT 迹并要求运行时回放通过后才报告结论；局部 SMT 算法把有界的逐元素事实翻成量词无关的线性整数/实数算术。写法上明确：这些都是经典技术的实现，论文不主张工具创新。§7.1 的调研结果里同类工具的核验状态一并给出。

### 4.4 谓词：数量、立场与消融（3、7、10；用户第二轮 2、5-3）

【导师直接表达·用户转述】三条互相衔接的意见。(3) 19 条谓词太多，实际用到的只有 8 条，要缩到大部分能发挥作用；谓词不求面面俱到，要能用到地方。谓词的意义要站在方法角度讲：因为方法有需要才设计谓词，关键是给 LLM 一个模板填空，而不是让它大海捞针——用户自己测过让 LLM 直接写基于 pyfcstm 的断言代码，效果不好，还是简单直白的断言好。(7) 可以去掉一些谓词，也可以做实验：给出不同配置与谓词子集组合做消融看效果。⚠️ 用户自述对这一条没完全理解，明确要求当面讨论；下文【AI 衍生建议】对第 7 条的解读是待确认的读法，不是共识。(10) 再次强调谓词为方法所需而设，不要求覆盖全领域；谓词的重要意义在于帮助消除模型幻觉，可以做一个消融：上游完全不变，只撤掉谓词与后端，看 hit 与 precision 怎么变，此时不必看 W2。

【用户明确决策】谓词怎么保留先不拍板；先全面、系统地分析此前审计数据里每一步的决策模式与理由，在本文记录并给初步分析结果（见 §8），再讨论。消融里「谓词内部切分子集」可做，但做不做看情况，要处理好它与「删除多余谓词」的关系。

【AI 衍生建议】对第 7 条的理解：谓词词表本身是 prompt 的一部分，不同词表配置会改变 LLM 的路由行为（仓库早期实测过「词表在教模型不要用某个谓词」），所以词表子集消融看的是词表对路由与命中的影响；它与第 10 条只差词表规模：第 10 条是词表为空，第 7 条是词表取子集。与「删除多余谓词」的关系：若删的是从未执行的 7 条，那么这个子集的消融在结果上是平凡的（它们本来就没产生回执），唯一可能的变化来自词表变短对 LLM 路由的影响；若删的是执行过但只产生 `pass` 回执的那些（S1、R1、R2、R4、G4），删除会改变过滤效果。因此建议第 10 条优先做；第 7 条先做离线上限估算（把只由某族支撑的报告拿掉重算 hit），上限为零的配置不真跑。对第 10 条结果的预期：撤掉谓词与后端后，hit 可能变化不大甚至略升，precision 会掉——v61 有 573 条 `pass` 回执（M）对应被判为已满足的义务与前置探测，它们现在拦住了一批不会成为发现的候选，这批回执就是「消除幻觉」能量化的地方。

### 4.5 消融与贡献归属（4；用户第二轮 5）

【导师直接表达·用户转述】可能需要消融，例如对开头的 inspection 做消融。更要紧的是系统分析 ours 里有多少问题是 FCSTM 发现的、其中 inspection 与 LLM 各贡献多少——这是消融的意义，也是这项工作的意义：如果问题全是 FCSTM 发现的，那 LLM 就没有必要了。要强调方法是 LLM 与 FCSTM 工具的综合，而不是一边被另一边挤压；失衡很容易被挑战。

【用户明确决策】目前能想到的消融三种：(1) 开头关闭 inspect 信息，只输入 `<NL, STM, FCSTM 形式的 STM>` 与转换追踪信息，不加 inspect 及其衍生信息，论证 inspect 的作用；(2) 直接关闭谓词系统，看谓词对 hit 与 precision 的影响；(3) 谓词内部切分子集。1 与 2 最好做；3 看情况。

【AI 衍生建议】来源四分解在 v61 数据上已经能先答一半（M，[evaluate_rq3_output.txt](../paper_stm_issue_discover/final_results/v61_source_divergence_vs_x1v2_baseline/derived/evaluate_rq3_output.txt)）：323 个命中单元按含子主张回执的口径分：**只由确定性分歧检查报告承载的 49 个**（15.2%；根报告口径为 50）、LLM 候选经谓词后端确认达 W2 的 137 个（42.4%）、LLM 候选绑定了谓词但回执未闭合的 36 个（11.1%）、纯 LLM 语义候选 101 个（31.3%），四类合计 323。一个单元可被多类报告命中，故按承载报告族计时 SEM 152、DIV 63、V4 52、S2 50、S3 36、G1 25、S5 20、S4 6、G2 1。四类都不为零，方法是合成。但这个分解回答不了「LLM 候选里有多少是被 inspect 事实喂出来的」，那要靠消融 (1)。落到论文里：§6 先给来源四分解，再给消融 (1)(2) 的结果。

### 4.6 基线多样化（5；用户第二轮）

### 7.1 前 LLM 时代的确定性 STM 检查方法能否作基线

取证 32 个方法/工具（`/tmp/survey_classic_baselines.md`；核验等级逐行标注：官方页/发行物/全文核验、CSUR 2023 综述二次核验、仅题录三级），另实测了 PlantUML 自带导出器，并查了既有 LLM 类工作用的基线。

**惯例事实（I，跨工具归纳；单条为 V/P/A 见原文件）。**

1. **没有任何前 LLM 工具同时接受「自由文本描述 + 已有状态机」并输出定位到元素的缺陷报告。** 32 行里吃自由文本的只有 CARL（TOSEM 2005，需求对需求）与 ARSENAL（NFM 2016，NL→LTL），两者都不接受已有模型；吃模型的（Hugo/RT、SDMetrics、Papyrus 校验、itemis CREATE、Stateflow、Umple、Sismic、SCXML 校验器、SCR、RSML）全部要求已形式化的制品且不读 NL。同时接受两路输入的三项——SPIDER（MoDELS 2005）、VARED（RE 2014）、FRET（NASA，活跃）——代价一律是把 NL 限制成模板或受控文法。SCR 与 RSML 是闭世界的：只拿一份形式制品与它自身对照，SCR 原文自述「based on static checks of components … rather than some form of reachability analysis」。André 等 CSUR 2023 全文里 natural language 只以「OMG 规范本身是自然语言写的、这是问题来源」的意义出现——在这条研究线里 NL 一直是被消除的对象，不是输入。
2. **检查深度双峰。** 绝大多数工具止于结构静态：SDMetrics 34 条状态机设计规则（伪状态良构、重名、多初态、空区域、无入边/无出边、悬挂端点）、Papyrus/EMF 的 UML 2.5 元模型 OCL 约束、Apache Commons SCXML `ModelUpdater` 的 11 类结构错误、Qt `qscxmlc` 的若干结构错误（两者都无 unreachable 检查）、Sismic `validate()` 仅 2 项、MagicDraw 出厂只有 No Incoming/Outgoing Transitions 两条。图级可达性只有 itemis CREATE 的 `vertex.MustBeReachable` 与 Stateflow 编辑期的 Unreachable state（语法级，不解守卫）；Umple 的 W067 实为入度为 0。守卫语义级可达性只有 Simulink Design Verifier 的 dead logic（商业）。deadlock 只有模型检查器一族（Hugo/RT 经 SPIN/UPPAAL，AnimUML 经 OBP2；vUML、TABU、PROCO、USMMC 已消失或不可运行；PROCO 的 tarball 实测仍可下载但依赖的 Coral 已消失，CSUR 2023 所列 11 个工具 7 个已不可获取）。非确定性没有工具直接检。
3. **PlantUML 自带导出器不可用作翻译桥（本人实测，plantuml 1.2026.7）。** `-tscxml` 把守卫整条塞进 `event` 属性、静默丢弃 entry 动作，且方向提示箭头 `-up->` 会同时写错迁移的源与目标（最小复现：`Hot -up-> Warm : cool` 导出为 `Warm --cool--> Hot`；本语料 5/60 含方向提示，含复合态 44/60，含真守卫 10/60）；`-txmi` 产出的是 UML 1.3 类图 XMI，`UML:Transition` / `StateMachine` / `Region` 各为 0。于是所有吃 UML2 XMI 的工具（Hugo/RT、SDMetrics、TABU）都读不到我们的输入，除非我们自己写导出器。PlantUML 自身 `-checkonly` 只查语法，CSUR 2023 原话：PlantUML「purely syntactic, and no analysis (simulation, verification) is possible」。不存在 PlantUML 状态图 linter。
4. **既有 LLM 类工作用的基线。** MCeT（MODELS 2025，与我们同形态、制品是顺序图）的基线只有单 prompt LLM 的 holistic check，没有任何确定性基线，理由原句「these formal verification techniques do not evaluate the model against the textual requirements description」；Sultan 与 Apvrille MODELS 2024 完全没有基线；SoSyM 2026 版把确定性依赖图方法与 LLM 并列，但作者自己定位为互补而非受控对照（不同制品、不同任务、无共同 ground truth）；Li 与 Zheng 用人类对照组；Laiq 的综述（arXiv:2509.24782）统计 14 篇行为建模 LLM 研究，rule-based checker 作评估器的只有 1 篇且是作者自己的规则。有确定性基线的全部是「从 NL 生成」类工作（Visual Narrator 等），无一是模型审查。

**对我方的建议（AI 衍生建议）。**

- 文献里不存在一个可直接跑在 `<自由文本, PlantUML>` 上的经典确定性方法；稳妥的写法是把这一事实本身写进 §2 与 §5.5——前 LLM 工具都要求已形式化制品并把 NL 排除在输入之外，MCeT 也因此没有设确定性基线。这同时是 §4.2「缺可执行介质」论证的一部分证据。
- 可行的确定性对照是**模型侧检查器**，两条路：(a) 我们自己的确定性层作纯工具臂（inspect + 分歧检查，不跑 LLM）——它在谱系上就是 SDMetrics/itemis/Stateflow 那一族的检查，且能直接跑在我们的输入上，零 API 成本；论文里把它的诊断码逐条对应到 SDMetrics 的规则类别与 itemis/Stateflow 的可达性检查，说明它代表了这一族的能力上界；(b) 外部工具作独立验证——用我们的适配器把规范化中间表示导出为 UML2 XMI，喂给 Hugo/RT（BSD-3，可下载，做静态检查与 SPIN 死锁）或 SDMetrics（v2.5 起免费，34 条规则）。(b) 回应了「不能全是自搭基线」，代价是写一个导出器并验证它不引入 §3 那类翻译缺陷；这两类工具都不读 NL，只能产出模型内部问题，其报告仍要过同一套裁定。
- PlantUML 导出器的缺陷本身可以进论文的 §4.2「为什么需要保留来源的适配器」：这是可复现的证据，不必当成主张来辩护。

### 7.2 人工裁定与参考问题集的惯例写法

取证 12 篇（全部读到全文，逐字引句；`/tmp/survey_annotation_wording.md`），覆盖 MCeT（MODELS 2025）、Sultan 与 Apvrille（MODELS 2024）、Li 与 Zheng（IET Software 2025，全文经仓库卡片转引）、Guo 等（ICSE 2024 代码精化）、PrimeVul（ICSE 2025）、InferROI（ICSE 2025）、Kang 等（ICSE 2022 静态告警）、Li 与 Yang（TSE 2024 静态告警演化）、Charoenwet 等（ISSTA 2024）、SysMBench（arXiv 2025）、PSMBench（NeurIPS D&B 2025）、Class Model Generation（MSSiS 2026）。

**惯例事实（I，跨论文归纳）。**

1. **人数与身份**：主流是「两名本文作者」（MCeT、Kang、Li 与 Yang、InferROI 的中间制品、PSMBench）；三人多数票只有 PrimeVul；外部招募评审只有 MSSiS 2026；Li 与 Zheng 用 5 名十年以上经验专家打分、参照集由 1 名 15 年经验工程师自建且与作者关系未声明。
2. **分歧解决**：几乎一律「讨论至共识」（MCeT、Kang、Li 与 Yang、PSMBench、InferROI）；第三作者仲裁只有 Guo 等；多数票只有 PrimeVul；MSSiS 用 OR 规则合并而非裁定。
3. **一致性统计**：12 篇里 6 篇报 Cohen's κ（MCeT 0.79、Kang 0.83、Li 与 Yang 0.96/0.82、Guo 0.675–0.888、PSMBench 0.82/0.78、MSSiS 0.773/0.684），其中 PSMBench 只在 10% 分层抽样上算，MCeT 只在 20% 校准子集上算、其余按人分工单判；6 篇不报任何统计——报与不报各占一半，不报统计不构成多数惯例。
4. **盲法**：12 篇里**没有一篇**声明标注者对输出来自哪一臂设盲；最接近的只是「评分者互不讨论」。
5. **单人措辞的谱系**：直说「the first author manually reviewed」（SysMBench）→ 加副词「conducted primarily by the first author」再以资深作者协助补强（ISSTA 2024）→ 无主语被动式「6 inconsistencies were erroneously identified」（MODELS 2024，全文无任何标注者陈述）→ 校准段双判、正式段分工单判（MCeT）。
6. **参照集来源**：承自先例（MCeT ← Ferrari 等）；人工自建 + 两页指南 + 抽样 κ（PSMBench）；人工标注取代启发式 oracle（Kang）；单名专家逆向工程自建（Li 与 Zheng）。

**对我方写法的建议（AI 衍生建议，措辞供用户按能站得住的事实选用）。** 常见、可接受、不用力过猛的形态是 MCeT/Kang 那一档：「由作者完成、讨论至共识、不提盲法」；κ 报不报各半（6/12），只有真实的双人独立标注数据才报，没有就不报也不补造。参考句式：台账——"The expected-issue ledger was constructed by the authors: each entry was drafted from the description and the PlantUML source with a citation to the sentence and the source line, then reviewed by a second author; disagreements were resolved through discussion until consensus."；裁定——"All reports from both arms were manually adjudicated by the authors under the protocol of §5.2–5.3 (validity, defect status, relation to the ledger); borderline cases were discussed to consensus." 两句都不出现 κ（未测就不写）、不出现盲法（同类论文也不写）、不出现工具名。若用户希望更保守，可用 ISSTA 2024 的「primarily by the first author, with a senior author assisting on ambiguous cases」形态。

### 7.3 状态机与行为模型论文的案例与数据集惯例

取证三组：LLM 时代的状态机 / 行为模型论文 22 篇（2023–2026）、前 2020 的经典案例族 16 个、公开数据集与 benchmark 15 个（`/tmp/survey_dataset_conventions.md`，55 条书目带 DOI；逐字引文均为原文英文，Access 标 FT/AB）。下列数字除注明 M 外都是论文自报（S）或跨论文归纳（I）。

**惯例事实。**

1. **案例数普遍很小（I）。** 同类 LLM 论文的评测对象多为 1–8 个系统：Abdulkarim 等 2026 用 8 个本科建模课系统（Printer、Dishwasher、Chess Clock、Bread Maker 等），de Biase 等 SoSyM 2024 用 2 个（ETCS-L3、医疗告警），Sultan 与 Apvrille 用 3 个系统（2 个取自欧洲项目，第 3 个 DPS 为作者自撰），Estivill-Castro 与 Hexel ENASE 2026 用 4 个（Microwave、Fischer、Elevator、Two-Phase Commit），Vyatkin 等 INDIN 2025 用 2 个，Carvalho 等 FAC 2016 用 4 个（含 Embraer 与 Daimler 提供的两例）。更大的集合只有三种来路：从文献挖掘重建（Wang 等 Internetware 2025：303 个来源重建 107 个 SysML 行为模型，其中状态机 36 张——正文另一处写 34，原文自相矛盾）、从工业标准正文裁切（Otto 等 WFCS 2025：PROFINET/OPC UA 共 95 张状态图）、或合成（LLM-FSM 1000 例 LLM 合成；Nguena Timo 等 60 个随机 FSM）。和我们任务形态最接近的 MCeT 用 76 个需求–图对，全部是 GPT-3.5 生成的**顺序图**（其中一例名为 `finite_state_machine.v0`，仍是顺序图），由两名研究者人工评分。
2. **规模怎么报（I）。** 最规范的写法是逐系统表：Abdulkarim 等的 Table I 给每个系统的 states/transitions/guards/actions/hierarchical/parallel/history（如 Printer 6/17/6/3/2/0/1，最大 W-UMPLE 17/41）；挖掘型语料报 $\lvert V\rvert + \lvert E\rvert$ 区间（Wang 等 11–90）；协议 benchmark 逐协议报 states/transitions（PSMBench 14 个协议共 108 states / 297 transitions）。我们的分布（M：状态 5–20 中位 8，迁移 5–70 中位 13.5，复合态中位 2，深度中位 2）与课堂系统、协议 FSM 同一量级，远小于文献里唯一的真实工业状态机（Walter 等 MODELSWARD 2019 的 Daimler AOLC：47 states / 256 transitions）。
3. **领域族跨时代复现（I；机械计数 M）。** microwave、elevator、vending/coffee machine、cruise control、pacemaker、TCAS、railway crossing、traffic light、ATM 是两代文献共用的例子族。对本仓库 91 篇 LLM 时代论文与 210 篇 UPPAAL 应用论文的机械计数（已修正 `grep` 静默跳过非 UTF-8 文件的低估）：pacemaker、cruise control、TCAS、railway crossing 在两组语料里都出现；elevator、microwave、coffee/vending、mine pump 在 210 篇真实验证应用论文里作为案例的命中为 0——它们是教学例，不是验证对象；microwave 在 LLM 语料里的 3 次命中没有一次是评测数据。我们的 9 份在册描述（M，读 `nl.txt`）落在轨道交通（车门发车、基础制动）、汽车（自动/人工驾驶模式 ×2、碰撞处理）、无人机集群、泵控制、微波炉、巡航类设备六个领域族，是这条研究线的惯常领域。
4. **状态机子集几乎不公开（S/M）。** ModelSet 的发布库经代理直接查询：5,120 个 UML 模型中含状态机的 127 个（2.5%），状态机图 152 张对类图 32,584 张；Lindholmen 给图片打了 `SM` 标签但不公布计数，且站点明令「不要用本数据集对 UML 在开源中的频率下早结论」；MAR 按记法不按图类型拆；SLNET 原文「Stateflow is out of scope and our metrics do not count the Stateflow-contents」。唯一纯状态机公开 benchmark 是 CoCoSim 的 77 个 Stateflow 模型（工具回归集，无 NL）；协议 FSM benchmark（PSMBench 14、RFCNLP 6、HERMES 3）配的是 RFC/3GPP 正文与扁平 FSM，无层次无守卫；SysMBench 151 个 SysML v2 场景来自教学材料，按状态机标签的计数只在附录图里。结论：**不存在把自由文本描述、层次化带守卫的状态机与缺陷参考集配成对的公开数据集**。以「领域无公开数据集」为自建正当性是既有论文的标准写法（Wang 等、Abdulkarim 等、Pudlitz 等都这么写）。
5. **代表性论证套路（I，16 种，逐字为据）。** 被普遍接受且不过火的：多领域 / 多对象枚举、难度跨度、标注者资质、显式纳入排除条件、领域无公开数据集、与既有 benchmark 同量级且明说不追求样本量（SysMBench 对 HumanEval 164、MermaidSeqBench 132）、few-shot 与测试件互斥的泄漏控制。站不住的：合成即代表而无论证（Nguena Timo 等 0 个真实系统却写 "The simulated data is representative of real data"）、完全不作论证（多篇无 threats 节）。threats 侧的集中形态：样本少且安全关键域数据敏感、单一制品类型、作者自建参考集主观、案例过简或出自课堂、平台与许可造成的选择偏差。

### 7.4 非旗舰模型的学术口径

取证 12 篇 LLM4SE 论文（全部 arXiv 全文逐句检索，引文逐字复制；`/tmp/survey_model_choice_wording.md`），加 3 份规范性文件；「当时旗舰」按厂商发布日推定，未逐条回查 `llm_model_landscape/`。

**惯例事实（I）。** 九种辩护形态，按出现频率：(1) 成本直述——TOSEM 2025（arXiv:2412.03905）"To manage costs, we selected the cost-effective GPT-4o-mini model"；FORGE 2025（arXiv:2502.06039）给出美元对比 "USD 28 … while testing all attempts on GPT-4 would cost USD 3080"；(2) 明知更弱但更实用的显式让步——arXiv:2410.16292 "Although the full model (GPT-4o) demonstrates better performance in this ranking, the fact that the mini version is approximately 30 times cheaper makes it a more practical solution"，这是唯一同时承认能力差距又给取舍依据的句式；(3) 流行度与能力/成本平衡——域建模论文 arXiv:2410.09854 "GPT-3.5-Turbo is one of the most popular LLMs and can provide its users with a good balance of capability and cost"；(4) 可获取性；(5) 运行约束淘汰（rate limit、显存、输出格式失败）；(6) 把小模型立为卖点（本地可部署）；(7) 多厂商覆盖作为威胁缓解；(8) 只说「可替换但结果可能不同」；(9) 单模型的标准威胁套话 "used only one model and one approach… findings may not generalize"。三个缺口：**没有一篇**给出「方法与模型无关、所以小模型也行」的实证支撑句，最接近的也只是承认威胁；建模类（MODELS/SoSyM）论文几乎不给选型理由；Claude/Gemini 小模型的辩护未检出。规范侧：EMSE 社区指南（arXiv:2508.15503）要求报告模型版本、配置与日期，并建议「include an open LLM as a baseline」，同时指出 ACM SIGSOFT 经验标准没有 LLM 专章；WSESE 2025（arXiv:2411.07668）要求写明版本、实验日期与温度等参数；ICSE 2024 NIER（arXiv:2312.08055）列出闭源模型的隐私、演化与复现三类威胁。

**对我方写法的建议（AI 衍生建议）。** 采用形态 (2)+(3)+(9) 的组合，不用形态 (1) 的价格数字（与 §4.8 一致）：在研究设计里写「两臂使用同一个中档模型 `gpt-5.6-luna`（写明版本标识、实验日期、温度等参数），选择它是取能力与成本的平衡；两臂共享模型，比较的是方法而不是模型」；在威胁里写「同系列存在更强模型，本文未在其上复跑，结论不外推到其他模型」。不要写「方法与模型无关」这类无实证的句子；也不要预设审稿人会问 why-not-flagship——同类论文里没有一篇为此专门辩护，只在威胁里承认。EMSE 指南的「开源模型作基线」一条对我们是一个潜在追问，可在威胁里点一句而不必补实验。

## 8. 谓词审计的决策模式与初步分析（AI 衍生建议）

用户要求在拍板缩减前，先系统分析此前审计数据里每一步的决策模式与理由。数据来自 [predicate_provenance.md](../paper_stm_issue_discover/related_work/provenance/predicate_provenance.md)（S）与 v61 归档的 `evaluate_rq3_output.txt`（M）。

### 8.1 当前 19 条是怎么来的：五种决策模式

旧词表 19 个键到当前 19 条的对照（crosswalk）只用了五种操作，每种都有明确理由：

| 操作 | 条目 | 理由（审计原文的归纳） |
| --- | --- | --- |
| 直接承接 `direct_reuse` | S2（边存在）、S6（效果挂接）、R1（事件消费）、R2（刺激后占据）、R4（区间保持）、V3（有界响应） | 旧命题本身单一、可执行，只换名 |
| 拆分 `split` | `initial_target`→S2；`action_declared`→S4 + R3；`guard_distinguishable`→S5 + V1 + V2；`reaches`→G1 + G2；`terminates`→G2 + G4 + V4 | 旧命题混合了不同极性或不同语义层（存在性可达与全称必达不可互推；静态槽位与轨迹内发生是两件事；终止混合了必达、协可达与进展） |
| 合并 `merge_derived` | 三条具名元素义务→S1；`persists_until` + `invariant`→V5 | 同一命题的种类参数化 |
| 新增 `newly_added` | S3（触发集相等）、G3（路由避开） | 旧词表没有精确的触发集比较与源–目标避开命题，从已映射的来源池补 |
| 退役 / 不承接 | `containment`（退役）、`cardinality`、`variable_delta_after`（不承接） | 父状态「正确性」需要外部需求参照、UML 规则导不出；NL 的任意 N 与 UML 固定 multiplicity 不同；后值义务未进最小 surface |

19 条的实现关系全部是 `IMPLEMENTATION_SUBSET`（后端只执行命题的一个受支持片段），状态全部为 `QUALIFIED_EXTERNAL; SPECIFIED_AND_TESTED; SOURCE_BOUND`。词表的形成逻辑是「按来源池的义务形状拆到极性与语义单一」，不看「会被用到多少」——19 条就是这么来的，也是导师说「面面俱到」的由来。

### 8.2 v61 上每条谓词实际在做什么

| 谓词 | 终止回执（violation / pass） | 绑定报告 | 有效绑定 | W2 报告 | 在流程里的实际角色 |
| --- | ---: | ---: | ---: | ---: | --- |
| S2 `transition_exists` | 396（246 / 150） | 148 | 101 | 102 | 主力：端点断言，既产发现也过滤 |
| S3 `trigger_set_equals` | 226（74 / 152） | 71 | 59 | 66 | 主力：多数回执是 `pass`，过滤为主 |
| S1 `element_exists` | 120（0 / 120） | 2 | 0 | 0 | 纯过滤：120 条候选全被证明元素存在 |
| G1 `may_reach` | 97（96 / 1） | 60 | 59 | 12 | L2 主力：不可达的健全反例 |
| V4 `deadlock_free` | 85（78 / 7） | 66 | 61 | 59 | L2 主力：死端探测 |
| R2 `state_reached_after` | 81（3 / 78） | 0 | 0 | 0 | 过滤 + 撤回：3 条 violation 因路由令牌整体撤回 |
| S5 `transition_guard_equals` | 33（33 / 0） | 97 | 82 | 22 | 守卫模态聚合的成员来源 |
| R1 `event_consumed` | 33（0 / 33） | 0 | 0 | 0 | 纯过滤 |
| S4 `state_action_attached` | 18（6 / 12） | 6 | 6 | 3 | 少量 |
| G4 `coaccessible_to` | 16（1 / 15） | 0 | 0 | 0 | 过滤为主 |
| R4 `state_retained` | 5（0 / 5） | 0 | 0 | 0 | 纯过滤 |
| G2 `must_reach` | 4（4 / 0） | 3 | 3 | 3 | 极少 |
| G3、R3、S6、V1、V2、V3、V5 | 0 | 0 | 0 | 0 | 本语料无适用义务，从未执行 |

合计 1114 条终止回执，541 条 `violation`、573 条 `pass`（M）。三点观察：

1. **「用到」有两种含义。** 绑定到已发布报告的 8 条（S1–S5、G1、G2、V4）是可能产生发现的谓词，其中 S1 的 2 条绑定无一有效；另有 4 条（R1、R2、R4、G4）从未绑定任何已发布报告，几乎只产生 `pass` 回执——它们不产生发现，但把 LLM 提出的候选判为「义务已满足」而拦在发布之前。导师说的「消除幻觉」指的就是这一半。按「绑定到已发布报告」计 8 条在用，按「绑定到有效报告」计 7 条（S1 退出），按「产生过回执」计 12 条。
2. **过滤量不小。** 573 条 `pass` 里 S3 152、S2 150、S1 120、R2 78、R1 33、G4 15、S4 12、V4 7、R4 5、G1 1；这些候选若没有谓词与后端就会以 W1 发布，其中有多少会被判无效，正是消融 (2) 要测的量。
3. **从未执行的 7 条**（G3、R3、S6、V1、V2、V3、V5）对本语料没有任何贡献，无论正向还是过滤；它们留在词表里只有一个作用——出现在 prompt 里供 LLM 选择。

### 8.3 缩减方案的三个候选（供讨论，不拍板）

| 方案 | 保留 | 理由 | 风险 |
| --- | --- | --- | --- |
| A · 按「产生过回执」保留 12 条 | S1–S5、G1、G2、G4、R1、R2、R4、V4 | 保住产生发现与过滤两种作用，删掉的 7 条在本语料确实无事可做 | 仍需解释为什么 R 族只有过滤作用；引言小例子绑的 R2 得以保留 |
| B · 按「绑定到有效报告」保留 7 条 | S2、S3、S4、S5、G1、G2、V4 | 正文最紧凑；7 条对应「绑定到有效报告」口径，导师说的 8 条对应含 S1 的「绑定到已发布报告」口径 | 删掉的 S1/R1/R2/R4/G4 承担了 251 条 `pass` 过滤（120+33+78+5+15）；删后 precision 可能下降，等于把消融 (2) 的一部分提前做了；引言小例子要换 V 族见证 |
| C · 正文列 8 条 + 制品列全表，不改实现 | 全部 19 条仍在注册表 | 数字一个不变，不需要重跑；正文按「核心词表 / 扩展词表」呈现 | 审稿人可能问「扩展词表为什么存在」；导师的「缩减」意图只在呈现层落实 |

两个事实约束任何方案：(i) 按使用情况删词，严格说是在评测集上调参，正文只能写成呈现选择或写明「删除后重跑」；(ii) 词表出现在 prompt 里，删词会改变 LLM 路由，所以 A、B 都要重跑才能出数字，而且它们各自就是消融 (3) 的一个配置。建议的路径：先做 §4.4 说的离线上限估算，看删掉候选集合对现有命中的影响上限；再在 A、B 之间选一个作为消融 (3) 的唯一配置跑一次，而不是跑一组。
