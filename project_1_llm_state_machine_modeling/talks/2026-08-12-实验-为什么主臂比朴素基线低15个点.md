## 零、背景与术语（⭐ 为不熟悉本项目的读者而写）

### 0.1 这个实验在问什么

第一篇论文的方法是：给定一份**自然语言规约**（NL）和一个**由 LLM 生成的状态机模型**（PlantUML），自动找出模型与规约不符的地方。我们的方法是一条**八阶段 LLM 反馈循环**（实际 11 个图节点、5 个 LLM 调用），它把 NL 拆成若干条 requirement，为每条 requirement 写出**形式化断言**（用一套 **19 个闭合谓词**），求值，把返回 `False` 的断言变成一条 issue。

**主臂的流水线（本文反复引用，⭐ 这里给出地图）**——11 个图节点，其中 5 个是 LLM 调用：

```
NL + 模型
  ①  split_requirements        ← LLM。把 NL 拆成若干条 requirement，每条绑定一个谓词
  ②  review_requirements       ← LLM。审查需求集，判 revise 则回 ①（预算 5）
  ③  convert_assertions        ← LLM。把每条 requirement 写成形式断言
  ④  review_assertions         ← LLM。审查断言脚本，判 revise 则回 ③（预算 5）
  ⑤  precheck_and_seal         ← 无 LLM。删掉不可执行的断言并冻结
  ⑥  evaluate                  ← 无 LLM。对模型求值每条断言，得 True / False
  ⑦  adjudicate + publish      ← LLM。把返回 False 的 primary 断言变成 issue
→ issues
```

⭐ **本文的核心结论关于 ①**：⛔ 一个缺陷若没有任何 requirement 的谓词去绑定它，⛔ 它在 ⑦ 处**结构上不可能被报出来**。

**X1 朴素基线**是为了做有效性对照而建的：**单次 LLM 提示**，输入同样的 NL + PlantUML，输出**自然语言描述**的问题列表。⛔ 没有断言、没有谓词、没有循环。

### 0.4 台账（ground truth）与判定

**台账**是 98 条 `REPORTABLE` 记录（126 − 27 条越界 `00x8` − 1 条逐条裁定 `EIS-0043-02` = 98）。⚠️ `00x8` 指 pair 编号末位为 8 的六个 pair：它们共用的那份 NL 要求 fork/join 与秒级时间约束，⛔ 落在本研究的建模对象边界（FSM/HSM/EFSM，⛔ 无时钟、⛔ 无并发）之外。`EIS-0043-02` 是逐条边界裁定剔除的单条。每条描述一个「模型与 NL 不符」的具体缺陷。

**判定**是逐位判断「这一臂在这一格有没有发现台账里的这条缺陷」，共 **588 位 = 98 × 3 轮 × 2 模型**。

**命中判据**是四种「语义同一性」形态的闭集：**直接对应 · 合取项之一 · 负向命题的正向对偶 · 蕴含更根本的原因**。两臂用的是同一份判据定义。

## 二、导师两条假设的裁定

### 2.1 「输入的 STM 模型稍微一复杂，其给出的结果一定有很多不符合逻辑的情况」

> ⛔ **不成立，而且方向相反。**

按综合复杂度三分层（42 个有台账的 pair）：

| 复杂度层 | pair | 位数 | 主臂 | X1 | **Δ** |
| :-- | --: | --: | --: | --: | --: |
| 低 | 16 | 228 | 67.1% | 80.3% | **+13.2pp** |
| 中 | 14 | 168 | 62.5% | 79.8% | **+17.3pp** |
| **高** | 12 | 192 | ⛔ **50.5%** | 65.6% | **+15.1pp** |

⚠️⚠️ **这张表的数字经独立复算后已更正。** 初稿写的是 65.4/66.7/49.0（主臂）与 Δ = +17.1/+10.1/+16.7，⛔ **形状与复算相反**（初稿是「中层增益最小」，复算是「低层增益最小」）。⭐ **位数 228/168/192 精确复现**（按 fcstm 综合 z 分数的 16/14/12 连续三分），⛔ 但命中率复不出初稿值，⛔ 且**原分层脚本不在仓库**。⛔ **因此本文不使用任何依赖「中层凹陷」的说法**——⭐ 唯一承重的结论是「**三层的 Δ 全为正、无反超点**」，⛔ 而这一点在两套数字下都成立。

⚠️ **另一处必须声明的度量切换**：分层用 **fcstm** 计数，⛔ 而下面的 Spearman 与三个单点反例用 **PlantUML** 计数——⛔ 两者在 `0039` 上分别是 26 与 66 条迁移。⭐ 已核两种表示的复杂度**排序高度一致**（状态 rho=+0.926、迁移 +0.896，$p<0.001$），⛔ 但绝对数不可混用。

#### ⚠️ 三条必须一起讲的边界（⛔ 别让结论显得比实际强）

1. ⭐⭐ **量程有限**：42 个有台账的 pair 上限是 **17 状态 / 29 迁移 / 层次深度 2**。⛔ **导师说的「稍微一复杂」若指几十状态、多层嵌套、正交并发的工业模型，本语料根本没有这样的样本**——该假设在那个量程上**既没被证实也没被证伪**。⭐ 这是最值得补的实验缺口。
2. **交互项功效不足**：cluster bootstrap 给出 $\Delta_{\text{高}} - \Delta_{\text{低}}$ 的 95% CI = $[-22.1, +18.4]$pp。⛔ **无法排除中等强度的负交互**——只是没有被观察到。
3. ⭐ **唯一朝导师方向的信号**：同一份规约内部按复杂度对半分，**7 族里 6 族的 Δ 收窄**（中位 −10pp，Wilcoxon $p$=0.094）。⚠️ 但收窄的终点是**趋近 0、⛔ 不是反号**，且最繁的那一族（NL09）Δ 反而**扩大**。

### 2.2 「直接 LLM 来执行任务，幻觉是没法控制的」

> ⚠️ **分裂裁定：作为「区分两臂的因素」⛔ 被否证；作为「绝对水平的判断」⭐ 成立，但它同时适用于我们自己。**

按 issue 级重算（⛔ 已发布报告里的表数的是**簇**，不是 issue）：

| 度量 | X1 | 主臂 |
| :-- | --: | --: |
| 产出 issue 数 | 1365 | 1105 |
| **事实性幻觉**（`FALSE_POSITIVE`，声称的事实不成立） | **4.8%** | 3.0% judged / **4.4%** imputed |
| **义务性幻觉**（`NO_NL_BASIS`，事实为真但规约从未要求） | **29.7%** | 19.4% judged / **28.3%** imputed |

⭐ **与本文 §4.2 的关系**：两者不冲突。本文的「splitter 主导」对应上表的 **A 类 133 位**；本文的「判定仪器 −4.07pp」测的是**材料对齐**的净效应，⛔ 而 B_published 的 3.401pp 测的是**已发布却被判未命中**的那 20 位——⭐ 两者口径不同、⛔ 不可相加。

### 5.2 ⭐⭐ 但重判实验证明：这个缺陷的净效应是**负的**

⭐ 我们做了唯一能定论的实验：**在与 X1 相同的判定材料下双向盲重判**。⭐ 全部产物已落库于 `baseline_arm/results/rejudge/`（样本清单 `sample.json` / `sample_ext.json`、逐位判定 `positions_final.json`、统计 `stats.json`、判定指令、脚本），⛔ 可逐位复核。

⚠️ **口径限定**：本实验**对齐的是判定材料**（完整 NL + 作者源 + 未截断三段 issue 文本），⛔ **判据文本时序那一支（§5.1 的两条亲命中条款）未单独测**。

| 方向 | 翻转率 | 95% CI |
| :-- | --: | :-- |
| miss → hit | 4/60 = **6.7%** | [2.6%, 15.9%] |
| ⛔ **hit → miss（反向对照）** | 5/45 = **11.1%** | [4.8%, 23.5%] |

> ⛔⛔ **净效应 = −4.07pp**，95% CI $[-11.10, +1.17]$。⛔ **对齐仪器后主臂从 60.4% 降到 56.3%，Δ 从 14.97pp 扩大到 19.0pp。**

⛔⛔ **这个 −4.07pp 有三条必须写出的折扣，⛔ 初稿一条都没写**（独立 challenge 查出）：

1. ⛔ **它是单臂的**：只重判了主臂，⛔ **X1 侧重判 0 位**。⭐ 所以它测的是「主臂在新条件下的判定漂移」，⛔ **不是两臂之差的校正**。
2. ⛔ **判定者被指令朝 `false` 引导**（「说不清蕴含链就判 miss」），⛔ 而 hit→miss 与 miss→hit 两个方向**同受此引导**，⛔ 于是**同向推负**。
3. ⛔⛔ **`analyze.py` 里硬编码的 5 条人工覆盖全在 miss 侧**——⛔ **不加这 5 条覆盖，净效应是 −0.76pp，⛔ 不是 −4.07pp。**

> ⭐ **所以正确的表述是**：⛔ **判定材料不对称的净效应在 −0.76pp 到 −4.07pp 之间，⛔ 方向为负但量级不确定**，⛔ 且 CI 含 0。⛔ **不能拿它当「差距其实更大」的证据。**

**为什么是负的**：仪器不对称确实造成主臂漏判，⛔ **但它同时造成误判为命中，而后者的基数更大（355 vs 233）**。原判定论证质量普遍偏低（**56.1% 的 miss 位共享逐字相同的论证**，仅 4.4% 点到具体 issue）——⛔ **这种低质量是双向出错。**

⭐⭐ **只做单向重判会得到 +2.64pp——比真值高 6.7pp 且符号相反。** ⭐ 审计者主动把反向对照从 20 补到 **45**，理由是它贡献 82% 的方差，⛔ 而欠采样反向恰恰偏向我方。

⭐⭐ **最重要的结构性发现**：主臂最弱的三类**零翻转**——`reaches` **0/8** · `edge_declared` **0/8** · `guard_distinguishable` **0/5**。⛔ 这三类占 233 个 miss 位的 **34%**。

> ⛔⛔ **这些低命中是真实能力缺口，不能用判定伪影解释掉。**

⚠️ 局限：补样 20→45 是看到第一阶段结果后决定的（⛔ 非预登记；预登记口径 −3.40pp $[-14.47, +2.45]$，方向一致）；判定者是新的 LLM 判定组而非原班人马。

### 5.7 ⛔⛔ X1 的臂身份泄漏：修掉后重跑两次，⛔ **都越界**——⭐ 泄漏确实改变了模型行为

#### 5.7.1 泄漏是什么

pydantic 把**类 docstring** 放进 `model_json_schema()` 的**顶层 `description`**，因而随 schema 进入生产者上下文。逐字泄漏内容：

- `NaiveIssue.__doc__`：「**基线**报出的一条不符之处。」
- `NaiveReview.__doc__`：「⋯**主臂**是**八阶段循环**、每阶段有 rationale⋯**X1 是单次调用**⋯」「主臂做了**五类多报分类**」「⛔ 它不是 **C-③**」

⭐ **边界**：⛔ **无缺陷内容泄漏**——无台账 ID、无分类学、无谓词名、无「该找哪一类问题」的暗示；`prompt/naive_v1.txt` 本身干净中立。⛔ 这是**需求特征污染**。

⛔ **为什么隔离测试放过了它**：`_schema_descriptions()` 本来就序列化整个 schema、⭐ **看得见**那段文本——⛔ 漏掉的原因是**禁词表里只有「谓词名 / 该找什么」这类词、没有臂身份词**。⛔⛔ 典型的「**扫对了地方、查错了内容**」。

## 六、⭐⭐ 台账本身的问题（⛔ 它威胁的不是 Δ，是两个绝对值的含义）

### 6.1 台账是 LLM 造的，**零人类校验**

```
60 份 → [5 个 LLM agent 逐对判定] 418 条 diff → [正则 + LLM 复核] 126 条 → 98 REPORTABLE
```

| 环节 | 覆盖 | 执行者 |
| :-- | :-- | :-- |
| 主审 | 60/60 pair、418 条 diff | 5 个 **LLM** agent |
| 双盲复审 | ⛔ **12/60 = 20%**，$\kappa = 0.750$ | 2 个 **LLM** agent |
| **人类校验** | ⛔ **0 条** | — |

⚠️⚠️ **一个必须讲清的措辞陷阱**：本仓库的「**人工 / manual**」，其对立面是**机械 diff**，⛔ **不是人类**。所以 `paper_story.md:266`「台账是人工标注的评测分母」⛔ **不能**当作人类把关的证据。

⛔ 另外四条：**32 条只过了正则、从未被二次读过**；**审阅 agent 判定时看得见旧台账的答案**（而旧 47 条也是 LLM 造的）；$\kappa=0.750$ 是**二元 case 级**（$n=12$）、⛔ 不是逐条一致性；⛔⛔ **时序上台账（07-31）晚于方法产出（07-27）**。

⭐ 仓库自己 `TODO.md:137` 逐字：「**若时序上晚于方法产出，60.4% 就不是覆盖率而是自相关。**」状态「未做」。

⚠️⚠️ **但这里必须避免一次过度自责——初稿直接采纳了那个条件句的后件，⛔ 那是错的。** 「自相关」要成立需要一条**信息通路**：台账构造过程**看到过方法产出**。⭐ 而 §6.1 给出的构造流程（NL + 作者源 + 参考模型 → 审阅 agent）**输入里并没有方法产出**。⛔ 已识别的真实循环是**台账看得见旧台账**，⛔ 不是**台账看得见方法产出**。⭐ **诚实的表述是**：⛔ 我们**没有保留**能证明审阅 agent 未接触方法产出的运行记录（`runs/paper1/audit-20260727-claudecode/` 已在 2026-08-11 重构中消失），⛔ **因此无法自证清白**，如实写入 Threats——⛔ 而不是断言它已经是自相关。

### 6.1.1 ⛔⛔ 台账有 41/98 条是**读着 fcstm 投影**写的

⛔ 这是一条**独立于循环性**的 ground truth 构造问题：**98 条 `REPORTABLE` 里有 41 条**的 `statement` 明确提及 **FCSTM 投影或转换器产物**。`EIS-0004-01` 原文逐字：

> 「R4.5 投影确认了这一点：FCSTM 里生成了 `state InvalidInitialtr_0002 named 'PlantUML initial target outside child scope: DoorsClosing'`」

⛔ **也就是说：台账的一部分不是纯粹从作者源产生的，⛔ 而是参考了主臂那一侧的中间表示。**

⚠️ **方向出人意料**：⭐ 实测该层的 DiD 仅 **+3.4pp 且不显著**——⛔ **两臂在这 41 条上都更差**，⛔ 并未表现为主臂增益。⭐ 所以它**不是**一个偏向主臂的泄漏，⛔ 但它**必须作为台账构造局限披露**：⛔ 一个部分参考了被测方中间表示的 oracle，⛔ 其独立性是有缺口的。

### 6.2 ⛔ 复杂模型上台账覆盖密度**倒挂 32%**

| | 最简 10 pair | 最复杂 10 pair | 倍数 |
| :-- | --: | --: | --: |
| 状态数均值 | 4.4 | 14.5 | **3.30×** |
| 迁移数均值 | 6.0 | 21.9 | 3.65× |
| **台账条目均值** | 1.20 | 2.70 | ⛔ 2.25× |
| **审阅 diff 总数** | 6.3 | 8.0 | ⛔ **1.27×** |
| **条 / 状态（密度）** | **0.273** | **0.186** | ⛔ **−32%** |

⛔⛔ **但这张表的读法必须精确，⛔ 否则会说错话。** 独立第二路复算得出：**台账条目数与复杂度显著正相关**（54 pair，`plantuml.puml` 源代理：状态 rho=+0.424 $p$=0.0014、迁移 +0.359 $p$=0.0076、非空行 +0.542 $p$=0.000023、brace 深度 +0.284 $p$=0.037；用结构化 FCSTM census 亦全为正）。

⭐ **两者不冲突，是两个不同的量**：条目数涨 **2.25×**，⛔ 而状态数涨 **3.30×**——⭐ 所以**条目数正相关成立，⛔ 但每状态的覆盖密度下降 32%**。

> ⛔ **可以说**：「台账在复杂模型上**池化覆盖密度**下降（条/状态 −32~−37%）」。⛔ **不能说**：「复杂模型的台账记录**更少**」——⛔ 那是错的，记录数反而**更多**。

⛔⛔ **而且连「密度下降」也必须带两条限定，⛔ 否则同样会说错**（独立复算）：**(1)** 密度下降**只在池化口径成立**——逐 pair 的密度与复杂度**无关**（Spearman $\rho = 0.045$，$p = 0.75$）⛔ 且非单调；**(2)** ⛔⛔ **密度随规模下降不是台账独有**：X1 是 0.861→0.431、主臂是 0.489→0.408，⛔ **两臂的产出密度也在下降**。⭐ 所以⛔ **不能断言台账系统性漏掉了复杂模型**——⚠️ 那更像「模型一大，任何单次审阅都被摊薄」的普遍现象。

⛔ **审阅是近似固定预算（每格 4–10 条），⛔ 不是按元素穷举。** 极端例：`0059`（17 状态，⭐ 与 `0007`/`0019`/`0029` **并列**状态数最多）⛔ **只有 1 条台账**，少于 `0026`（4 状态）的 3 条。**12/54 个 pair 台账完全空白。**

### 6.2.1 ⭐⭐ 循环性做了三条检验，⛔ 全部阴性，⭐ 其中一条**反向**

⛔ 我先前只说「循环性存在但无法定量」。⭐ 一路专项调查做了三条可证伪的检验：

**① 位点安慰剂检验（⭐ 最干净，也最有决定性）**——把作者源里的标识符分成三类：**Ld**（台账记为缺陷的位点）· **Ln**（审阅 agent 看过、⭐ 但判定为**无缺陷**的安慰剂位点）· **L0**（审阅 agent 从未写过的参照位点）。

⭐ **若循环性成立，X1 应当在 Ld 与 Ln 上（即审阅 agent「看过」的位点）相对主臂显著抬高，⛔ 而在 L0 上不抬高。** 实测：

| 对比 | X1 相对主臂的抬高倍数 |
| :-- | --: |
| **Ln**（安慰剂位点） | **3.00×** |
| **L0**（从未写过） | **3.12×** |
| **DiD** | ⛔ **−0.040（$p = 0.87$）** |

> ⛔⛔ **完全相同。这是「X1 什么都多说 3 倍」的形状，⛔ 不是「同源枚举」的形状。**

⭐⭐ **反倒是反方向显著**：`Ld vs L0` 的 DiD = **−0.773（$p = 0.005$）**——⛔ **主臂比 X1 更集中在真缺陷位点**。

⚠️ 词汇混淆已排除：1104 个作者源标识符中 **1093 个（99.0%）逐字出现在 `fcstm` 里**，⛔ 所以「主臂看不到那些名字」不成立。

**② 散文度分层**：全部代理的异质性 $p \ge 0.16$。⭐ 而且两处方向与循环性预测**相反**——`lexical`（台账最糙）Δ = +10.9 ⛔ **小于** `nl_review` 的 +17.2；双盲复审过的 Δ = +28.8 ⛔ **大于**未复审的 +11.0。⚠️ **但对照 CI 宽 ±25–40pp，检出下限约 38pp，⛔ 测不动**——⛔ 未检出 ≠ 不存在。

**③ 文本相似度中介**：⛔ **不可用**——调整的是**后处理中介**，且该中介近乎就是结果本身（中介调整谬误）；⛔ 且它无法区分「同一个程序」与「真找到同一个缺陷」。⛔ 只作描述性保留。

⭐ **一条附带的硬事实**：⛔ **台账不是任一程序产物的复刻**——X1 给 6 次机会（3 轮 × 2 模型）也只覆盖 **89.8%（88/98）**，**10 条从未命中**；两臂并集 99.0%。

> ⛔⛔ **结论必须改**：**循环性在本语料上没有被证实**，⛔ 而且位点安慰剂检验的方向是**反的**。⭐ 它仍应写进 Threats（**结构上不可识别**，见 §6.2.2），⛔ 但**不能**再说「它抬高了 X1」。

### 6.2.2 ⛔ 为什么循环性**结构上不可识别**

⭐ 循环性 = 台账**支撑集**的选择偏向。⛔ 而全部 588 位**都在支撑集内**——⛔ 它在样本内是**常数、无组内变异**，⛔ 所以任何组内比较都识别不了它。

⭐ **唯一能识别它的设计**：用**主臂的程序**（读编译产物 → 拆需求 → 逐条断言）另建一份**交叉 oracle**，循环性 = `oracle 程序 × 被测臂` 的**交互项**。⚠️ 检出下限约 14pp——⭐ 能判「是不是主因」，⛔ 判不了「是不是 3–5pp」。⛔ 已核实仓库里**没有第二份独立台账**。

### 6.3 ⭐ 循环性的形态（⛔ 与直觉不同，⚠️ 但见 §6.2.1：它未被证实）

⛔ 直觉的说法是「台账是 LLM 造的，所以 X1 作为同类 LLM 占优」。⛔ **这个推理有个洞：主臂也是 LLM。** 单纯的「LLM-findable」偏差**对两臂等价**，⛔ 不产生 Δ。

⭐⭐ **差别在于程序同构**：

| | 台账审阅 agent | **X1** | 主臂 |
| :-- | :-- | :-- | :-- |
| 输入制品 | **作者源** | `plantuml.puml`（与作者源逐字节相同） | `model.fcstm` **编译产物** |
| 读法 | **单次通读全模型** | **单次通读全模型** | 按 NL 段拆需求 → 逐条断言 |
| 输出 | **自由散文枚举差异** | **自由散文枚举差异** | 19 谓词形式断言 |

> ⭐⭐ **台账按构造就是「一个 LLM 单次自由通读作者源所能枚举出的差异集合」。X1 是同一个程序。** ⭐ 这才是循环性，而且它**是差异化的**。

⭐ **形态不对称可量化**（含任一机器标记的比例）：台账 statement **5.1%** · X1 产出 **0.1%** · 主臂产出 ⛔ **93.6%**。⭐ 判定者比对 X1 时是**同语域**，比对主臂时 93.6% 是**跨语域**。

⛔ **但「能力正交」是反对「循环性解释一切」的最强证据**——主臂在四个族上**整族胜出**：

| primary 谓词 | 主臂 | X1 | Δ |
| :-- | --: | --: | --: |
| `edge_declared` | 31.0% | 92.9% | +61.9pp |
| `reaches` | 31.2% | 89.6% | +58.3pp |
| **`event_declared`** | ⭐ **95.8%** | 62.5% | **−33.3pp** |
| **`containment`** | ⭐ **78.3%** | 51.7% | **−26.7pp** |
| **`initial_target`** | ⭐ **69.0%** | 51.2% | **−17.9pp** |
| **`effect_declared`** | ⭐ **100.0%** | 88.9% | −11.1pp |

⛔ **若 Δ 主要来自跨语域判定惩罚或台账循环性，主臂不该整族赢。**

> ⭐⭐ **`hit@k` 的分母不是「98 个难度可比的独立缺陷」，而是「一个 LLM 单次通读作者源所能枚举出的差异集合」。用它衡量出的能力，⛔ 系统性高估两臂在复杂、深层、欠规约场景下的表现。**

⭐ 这也正好解释了 §2.1 的发现：**主臂随复杂度显著劣化而 X1 不劣化**——⛔ 因为**台账在复杂模型上根本没跟着变难**。

## 九、这个实验证明了什么，⛔ 以及不证明什么

### ⭐ 站得住的三条

1. **在本语料上，$\Delta = +14.97$pp 未被任何已查缺陷抵消。** ⛔ 七路调查加两路 codex 交叉验证：**三个复杂度层 X1 全部领先**，**六个判定组符号全为正**，两臂幻觉率在 imputed 口径下**无法区分**。
   - ⚠️ **唯一未排除项**：§5.3 的臂身份污染（⛔ 方向未知、量级未估，⛔ 且落在**获胜臂**的 prompt 里）。
   - ⚠️ **判定仪器校正的点估计是 −4.07pp，⛔ 但 CI 含 0**（$[-11.10, +1.17]$）——⛔ **因此「校正后扩大到 19.0pp」只能作为敏感性分析，⛔ 不能当作加强证据。**
   - ⭐ **不对称的方向要分开说**：**资源投入**的不对称偏向主臂（212.6× token）；⛔ **制品与判定材料**的不对称偏向 X1（§0.3 主臂读编译产物、§5.1 主臂判定者只看标题、§6.3 台账与 X1 程序同构）。
2. ⭐ **赤字有两个成分，⛔ 不是一个。**
   - **(a) 大量缺陷从未被提问**（⭐ 机械可证）：`edge_declared` 对应 7 条台账记录，⛔ splitter 在 324 格里只写过 **1 格 2 条需求**；每格中位只用 19 个谓词中的 **6 个**；①+② = **81.2%** 的可归因 miss 是「问题从未被提出」。
   - **(b) 即使提问了，断言也可能构造错**（⛔ 决定性反例）：`reaches` 那 **11 位** splitter **确实写了该谓词**，⛔ 主臂仍只有 **2/11 = 18.2%**，X1 **11/11**。
   - ⛔⛔ **初稿只写了 (a)，并据此宣布「验证机器没问题」——⛔ 那是错的，已撤回**（§3.0.1、§3.0.2）。⛔ 「真值层错误率 0」是 `loss_stages.py` 自陈的**结构性空段**，⛔ 也不能作为支撑。
3. **两臂能力双向解离（⛔ 不用「正交」——那是零相关的意思，我们测的是族级双向解离）。** 主臂在**结构族具名点查询**上整族胜出（`event_declared` +33.3pp、`containment` +26.7pp、`initial_target` +17.9pp、`effect_declared` +11.1pp），X1 在**行为 / 可达 / 冲突族**上胜出。⛔ 这是互补，⛔ 不是一边通吃。

### ⛔ 不能说的五句

1. ⛔ **不能说「朴素 LLM 更强」。** 它强在**一个特定任务**上：**有 NL 做参照的比对**。⛔ 它做的是比对，⛔ 不是凭空推理。
2. ⛔ **不能说「形式化方法不如自由文本」**——⛔ 但也**不能**用「打平的那 345 位」来支撑它（⭐ 那个说法已在 §3.0.1 撤回）。⭐ 站得住的理由是别的：**主臂在四个结构族上整族胜出**（§6.3），⛔ 且真值层从未出错（⚠️ 尽管那是定义使然的空段）。
3. ⛔ **不能说「60.4% 和 75.3% 衡量了两臂的缺陷发现能力」。** ⛔ 分母是「一个 LLM 单次通读作者源枚举出的差异集合」，⛔ 不是「该模型的全部缺陷」。
4. ⛔ **不能说「复杂模型上我们更好」。** ⛔ 数据说的正相反，⛔ 而且本语料的复杂度量程（≤17 状态）根本够不到工业规模。
5. ⛔ **不能说「主臂用了盲判所以判得更严、X1 非盲所以判得更松」。** ⛔ v46 没有盲判制品（§5.3.2）；⛔ 而且「非盲」本身推不出方向。
6. ⛔ **不能说「问对了问题两臂就打平」。** ⛔ −1.45pp 是 +81.8 到 −33.3 的对冲（§3.0.1）；⛔ 两层的谓词构成 Cramér $V = 0.765$、近乎完全分离；⛔ 加谓词固定效应后 Δ|written = **+11.64pp（CI 不含 0）**。
7. ⛔ **不能说「台账的循环性抬高了 X1」。** ⛔ 位点安慰剂检验 DiD = −0.040（$p$=0.87），⛔ 方向反而是**主臂更集中在真缺陷位点**（DiD = −0.773，$p$=0.005）。⭐ 循环性仍写进 Threats，⛔ 但理由是**结构上不可识别**（§6.2.2），⛔ 不是「已证实」。
8. ⛔ **不能说「台账系统性漏掉复杂模型」。** ⛔ 条目数与复杂度**正相关**；密度下降**只在池化口径成立**，⛔ 且**两臂产出密度同样下降**。
9. ⛔ **不能说「有循环有谓词所以更可靠」。** ⛔ 假阳性平手；主臂在 **NL01（45.8%）与 NL09（43.8%）** 上的 FP 率⛔ 比 X1 高得多。

### ⚠️ 两个我无法消除的盲区

- ⛔ **判定者是同一个模型家族**（两臂皆是）。重判实验能测**材料不对称**，⛔ 测不掉这一条。
- ⛔ **台账零人类校验，且时序晚于方法产出。** ⛔ 我无法用现有数据消除它，只能如实写进 Threats。

## 十、五、⭐⭐ 三个改变结论的后续发现（⭐ 本节写于主体完成之后）

### 10.5.1 ⭐⭐ 我们一直在跟错误的对手比——**形式化规约有人类基线，⛔ 而它比我们低**

**Czepa 与 Zdun 的对照写作实验**（**SoSyM 2019**，$N = 215$，⚠️ 参与者为**选修课学生**，三位作者独立评分）：

| 条件 | 语义正确率 |
| :-- | --: |
| 受训参与者 **+ pattern 辅助**写形式化 | ⭐ **47–50%** |
| 不用 pattern，直接写 LTL | ⛔ **28–31%** |

⭐⭐ **pattern 把正确率翻倍，⛔ 翻倍之后仍有一半是错的。⭐ 而我们的主臂是 60.4%。**

| 参照系 | 数值 | ⚠️ 与我们的 60.4% 可直接相减吗 |
| :-- | --: | :-- |
| ⛔ SOTA LLM 裸跑（本文用的） | **76.2%** | ⭐ **可以**——⛔ 同任务、同分母、同判定链 |
| ⚠️ 受训人类 + pattern 辅助（Czepa） | **47–50%** | ⛔ **不可以**——⛔ 见下四条限定 |
| ⚠️ 人类直接写 LTL（Czepa） | 28–31% | ⛔ **不可以**——同上 |

⛔⛔ **这个比较必须带四条可比性限定，⛔ 否则它站不住——⭐ 而它是全文唯一一处我们赢的比较，⛔ 所以限定要写得比别处更足**：

1. ⛔ **任务不同**：Czepa 测的是**人手写形式化规约**；⭐ 我们测的是**在给定模型上发现与规约不符**。⛔ 两者共享「把非形式需求变成可判定命题」这一步，⛔ **但不是同一个任务**。
2. ⛔ **分母不同**：Czepa 的分母是**受试写出的每条规约**；⭐ 我们的分母是**一份 LLM 生成的台账**——⛔ 而本文 §6.3 自己说过那个分母「**系统性高估两臂在复杂、深层、欠规约场景下的表现**」。⛔ **拿一个被自己判为高估的数去减别人的数，⛔ 差值不可直接解读。**
3. ⛔ **人群不同**：Czepa 的参与者是**选修课学生**（⛔ 非工业形式化方法专家）。
4. ⛔ **评分不同**：Czepa 由**三位作者独立评分**语义正确性；⭐ 我们是 LLM 判定组按四形态语义同一性判命中。

⭐ **所以正确的表述是**：**在「把非形式需求变成可判定命题」这件事上，已发表的人类对照实验给出 47–50% 的正确率量级**——⭐ 它说明**这个任务本身对人也很难**，⛔ **而不是说「我们比人强 10~13pp」。** ⛔ **本文不主张后者。**


⭐ **这不是换对手来赢**——⭐ 它是形式化方法领域的标准参照系，⭐ 且有完整论证链：**van Lamsweerde (ICSE 2000)**「构建正确规约的**构造性方法基本不存在**」→ **FormaliSE 2024** 二十四年后仍称 **"usually manual"** → **Czepa** 量化了手工的正确率。

⚠️ ⛔ **但 SOTA 对比必须同时报，⛔ 藏起来就是选择性报告。**

⚠️ 同一路调查还带回一条限制我方的事实：**Menghi** 在 436 条需求上测出 **59% 存在解读层面分歧**（⛔ 其中 **156 条是「作者们都认为不含歧义、却仍给出不同 pattern 组合」**）——⛔ **用单人标注的台账评判「family 选对了没有」，上限受此约束。**

⛔ **一处对本文先前判断的修正**：本文 §3.2 把 `edge_declared` 被问 **0.0%** 当作异常。⭐ **两项**独立研究显示这类体系**天然倾斜**（Dwyer **80% 用 Global scope**（⚠️ 初稿作 79%）；FRET **3 个 timing 从未被使用**；EARS 的 Optional Feature 在 30 次机会中**被选中 0 次**且两个衍生体系直接删了它）。⭐ 修正后的判据是「**台账里有记录的 family，被问率是否 > 0**」，⛔ 不是分布均匀度。

### 10.5.2 ⭐⭐ 脚手架的**类型**决定符号——⛔ 而我们的是负收益的那一种

**Huang et al. (ICLR 2024) 完整表**（⚠️ 下列四数**全部来自 CommonSenseQA round-2**；⛔ **换 benchmark 会变**——GSM8K 上 GPT-3.5 是 −1.2 而非 −34.0），自我纠正带来的变化：

| Llama-2 | GPT-3.5 | GPT-4 | GPT-4-Turbo |
| --: | --: | --: | --: |
| ⛔ **−27.5pp** | ⛔ **−34.0pp** | −2.0pp | −1.0pp |

> ⭐ **信息供给型脚手架利好弱 backbone；⛔ 自我批评型脚手架对弱 backbone 伤害最大。**

⭐⭐ **这与本文 §八的 ROI 数据独立吻合**：

| 我们的组件 | 类型 | 实测 |
| :-- | :-- | :-- |
| 两个 reviewer + 修订回路 | ⛔ **self-critique** | ⛔ **第 3–5 轮恰好零位**；79% token、覆盖净变化 ≈ 0 |
| `precheck_and_seal` | ⭐ **information-supplying** | ⭐ **0 token，性价比最高** |
| `convert` 契约重试 | ⭐ **information-supplying** | ⭐ **唯一净 +1118 条断言** |

⛔ **另有一条已发表的不可能性定理**（Stroebl/Kapoor/Narayanan, arXiv:2411.17501）逐字：*"no amount of inference scaling of weaker models can enable them to match the single-sample accuracy of a sufficiently strong model"*——⛔ **前提是验证器不完美，⛔ 而我们的验证器正是 LLM 审查者。**

⭐ **该定理同时给出唯一出路**：把裁决者换成 **sound oracle**（⭐ 我们已经有一个：`pyfcstm`，⛔ 只是把它放在了求值端、⛔ 没放在裁决端）。⚠️ ⛔ 冷水：即使用完美 oracle，**SOTA prover 的自纠也只买到 +2.3pp**。

### 10.5.3 ⭐⭐ 两个零成本可修的新缺陷（⭐ 真实 run record 实测）

| # | 缺陷 | 证据 | 预计 |
| :-- | :-- | :-- | --: |
| **A** | ⛔ **五个 LLM 调用的 schema 全把结论排在理由前** | ⭐ 75 条记录的**流式 `partial_json`**（真实 token 生成顺序）：两个审查节点 **25/25 次都先吐 `"decision"`、后写 `rationale`**，⛔ `content` 全部只含 `tool_use`、**零 `thinking` 块** | ⭐ **+6.8 ~ +9.2pp** |
| **B** | ⛔ `requirement_splitter` 的 system prompt **95,589 字符**（⛔ 开头是语法手册），user prompt **末尾是 trace JSON** | ⛔ **模型生成前最后读到的不是任务**。任务放中间 vs 末尾最差差 **−88pp**；末尾追加任务副本可恢复到 ±4pp | 未量化 |

⭐ A 与 **Tam et al. (EMNLP 2024)** 点名的失效形态逐字对应：⛔ **结构化输出强制模型先给结论、再补理由，⛔ 等于禁掉了 CoT。**
