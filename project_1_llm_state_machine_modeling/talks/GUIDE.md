# project_1 Paper1 talks 维护指南

> 本目录同时保存导师记录、实验/调研 provenance 和 Paper1 交班 talk。默认入口见 [README.md](./README.md)；当前结果必须回到 [final-results v4](../paper_stm_issue_discover/final_results/v60_current_vs_x1v2_baseline/README.md)。

## 1. 与 `discussions/` 的区别

[discussions/](../discussions/) 可以记录 AI 内部推演、用户临时想法、方案草案和技术调研；本目录只记录**已经经过导师讨论、包含导师建议或正式路线决策**的内容。

如果某条信息只是内部猜测，不应直接写成导师意见；必须标明“内部推测”“待导师确认”或放回 [discussions/](../discussions/)。

## 2. 单篇记录命名

单篇导师讨论记录建议使用：

```text
yyyy-mm-dd-导师-主题.md
```

主题应简短稳定，例如：

```text
2026-06-04-导师-第一篇论文路线与E1E2定位.md
```

## 3. 单篇记录内容要求

每篇正式导师讨论记录至少应包含：

1. **讨论背景**：说明讨论发生前的上下文、相关 PR/issue/branch 和已有证据。
2. **讨论前判断**：简要说明原有 PR body 或内部讨论中的主要倾向。
3. **导师意见与路线更新**：必须清楚区分导师给出的建议、用户会后理解和 AI 整理补全。
4. **对论文 story 的影响**：说明研究问题、贡献、方法定位、实验设计如何变化。
5. **对后续工作的约束**：列出应做、暂缓、不要做的事项。
6. **上游链接与追溯入口**：列出 PR、issue、comment、目录或文档链接，便于后续 agent 继续追踪。
7. **执行摘要**：给后续 AI 一个快速入口，避免每次都通读所有上游材料。

## 3.1 来源等级与约束力区分纪律

新增或更新单篇导师讨论记录时，必须显式区分以下来源等级；若一条记录中出现多个等级，应在表格中增加“来源 / 约束等级”列，或在段落前使用对应标记。

| 等级 | 推荐标记 | 来源与含义 | 冲突处理 |
|---|---|---|---|
| 1 | 【正式定调】 / 【导师直接表达】 / 【直接要求】 | 导师在讨论中明确给出的方向、边界或否定意见；也包括用户明确说明“这是导师意见”的会后转述。 | 最高优先级；若与旧记录、AI 建议或用户早期理解冲突，以最新且明确的导师意见为准。 |
| 2 | 【用户明确决策】 | 用户在会后或 PR 讨论中明确要求沉淀为后续约束的研究决策，例如“全部归档，没商量”。 | 可覆盖 AI 执行建议和旧的内部计划；若后续导师直接意见不同，必须让位并新增/更新导师记录。 |
| 3 | 【用户会后理解】 / 【待导师确认】 | 用户基于导师讨论形成的理解、推断或拟向导师确认的 interpretation。 | 可作为下一轮默认工作假设，但不得写成导师已确认；与等级 1 或后续用户明确决策冲突时让位。 |
| 4 | 【AI 衍生建议】 / 【执行建议】 | 主 session、reviewer 或 subagent 基于上层约束推导出的 RQ、实验协议、写作措辞、PR 拆分、风险控制和执行路径。 | 最低优先级；可作为后续 PR 起点，但任何导师意见、用户明确决策或用户会后纠偏都可覆盖。 |

禁止把 AI 推测、reviewer 建议、主 session 补全或 implementation convenience 写成导师已经确认的事实。若某段同时包含多个等级，应拆成多个小节或在表格中列出“来源等级 / 当前约束力 / 待确认项”。

写作时尤其注意：

1. `【用户明确决策】` 不等同于导师已经确认；它是当前仓库执行的高优先级用户约束，但若后续导师明确反向定调，应立即更新记录并让位。
2. `【用户会后理解】` 和 `【待导师确认】` 不能单独支撑强论文 claim；它们适合沉淀为下一次导师确认问题或 R6/R7 默认假设。
3. `【AI 衍生建议】` 必须保留 rationale 和执行落点，不得伪装成正式学术结论。

## 4. 写作口径

1. 记录应尽量连贯可读，不写成零散问答体。
2. 允许引用上游 PR body / comment / issue，但本文件本身必须足够自包含。
3. URL 引用应可追溯，重要上游材料必须给出链接。
4. 对已有结论的覆盖关系要写清楚，例如“本次导师意见覆盖 PR #31 原先 Path-2/Hybrid 倾向”。
5. 若涉及术语定义、baseline、评价口径、样本选择、贡献定位，应写成后续 paper drafting 可以直接复用的句子。
6. 若某项建议是“暂缓/不做”，也必须写清楚理由，避免后续 agent 反复把它加回计划。

## 4.1 当前结果与历史边界

1. 当前 Paper1 只讨论 v60/current v4 与 X1v2 baseline v3；v46、v27、v2、旧人工裁定记录和旧 witness audit 只能保留在 historical/provenance 位置。
2. 当前 headline 只存在于 final-results v4 正式报告；talk 可以解释它，但不能建立第二套数字事实源。所有数字、单位、分母、路径和限定词必须能回链到 canonical JSON/TSV 或正式报告。
3. `current route decision` 只表示路线已选定，不表示实验结果；`provenance` 只表示可复用背景；`historical/superseded` 明确表示历史/已被覆盖，不可作为当前结果来源。
4. 默认阅读路径为 `talks/README.md -> 最终交班 talk -> final-results v4 report -> current v4 / baseline v3 / fair v4`。SUMMARY 只做导航，不重复 headline 表格。
5. 新增或更新流程性文本时，按 docs 场景先列 protected spans，再做保真回读；不得删除失败、限制、证据等级或责任主体来改善文风。

## 5. 优先级规则

本目录中的正式导师讨论记录对 project_1 后续工作具有高优先级。默认规则：

1. 晚近导师讨论记录优先于早期内部讨论。
2. 明确导师意见优先于 AI 推测。
3. 论文主线、贡献定位、实验边界和样本策略类意见优先于局部工程偏好。
4. 若后续用户明确更新导师意见，应新增记录或更新 [SUMMARY.md](./SUMMARY.md)，不要只在 PR comment 中留下不可发现的碎片。

## 6. 与根目录 `CLAUDE.md` / `AGENTS.md` 的关系

根目录 `CLAUDE.md` / `AGENTS.md` 给出全仓库通用规则；本目录规则只补充 project_1 正式导师讨论记录的组织方式。当两者冲突时：

1. 文件组织、链接格式、引用格式遵守根目录规则。
2. project_1 研究路线、论文 story、实验边界优先遵守本目录中最新导师讨论记录。
