## 零、背景与术语（不了解本项目的读者请先读这一节）

### 0.1 paper1 在做什么

给定一份**自然语言需求**（下称 NL）和一份**由 LLM 从该需求生成的状态机模型**，我们的方法要自己读出「这个模型哪里不符合需求」，并把每一条发现落成**可机械求值的断言**。建模对象是 $M = (S, E, V, Tr, A)$（状态、事件、变量、迁移、动作），不含时钟与并发区。

### 0.2 被对照的「主臂」：八阶段反馈循环

| 阶段 | 做什么 |
| :-- | :-- |
| ① 需求拆分 | 把需求原文切成一条条**义务**：「NL 第 4 句要求接管迁移存在」 |
| ② 需求审查 | 检查每条义务是否真有需求依据、能否落成断言；不合格**打回 ①** |
| ③ 断言转换 | 把义务落成**闭合谓词词表**（19 条）里的调用，如 `reaches(源, 目标, 步数)` |
| ④ 静态预检 | 机械检查绑定的元素是否存在、参数是否合法；不合格**打回 ③** |
| ⑤ 断言审查 | 检查断言是否真表达了那条义务、是否恒真恒假；不合格**打回 ③** |
| ⑥ 求值发布 | 在模型上真正求值（结构查询 / 仿真 / 有界模型检查） |
| ⑦ 归因绑定 | 把每个 False 挂回它所依赖的模型元素 |
| ⑧ 结果裁决 | 决定哪些 False 够格发布成 issue |

两处打回构成「反馈循环」——这也是「八阶段循环」这个称呼的由来。第 ⑥ 步求值时不看需求、不看参考模型，只看被评审模型本身。

**三条 contribution**（下文简称 C-①②③）：

- **C-①** 基于模型转换 + 形式化检查 / 仿真 / 验证的**错误发现方法**（即上面这条循环）
- **C-②** 基于归纳后谓词逻辑的**断言体系**（那 19 条闭合谓词）
- **C-③** issue **证据链体系**（每条发现带需求绑定、元素表、定位 trace）

### 0.3 语料

| 项 | 值 |
| :-- | :-- |
| 制品对（pair） | 每个 pair = 一份 `nl.txt` + 一份由某个 LLM 从它生成的状态机模型 |
| 总数 | 60 个，其中 6 个（编号末位为 8，记作 `00x8`）永久排除——那份 NL 要求 fork/join 与秒级时间约束，其忠实模型在 $M$ 内无法表示 |
| **进入实验的** | **54 个 pair** |
| 组成 | $54 = \mathbf{9}\ \text{份 NL} \times 6\ \text{个生成器}$——同一份 NL 由 6 个不同的 LLM 各生成一个模型（原为 10 份 NL，其中 1 份落在建模对象边界外，连同它的 6 个 pair 一并排除） |
| 独立性（重要） | ⚠️ 而 98 条台账记录**只落在其中 8 份 NL 上**。⭐ **做统计时的独立簇数是 8，⛔ 不是 54**——这决定了全部数字的统计意义，见 §9.2 |
| 模型形态 | ⚠ 作者源是 `plantuml.puml`（PlantUML 文本）；本项目另有一个转换步骤把它编译成 `fcstm.fcstm`（自研 DSL，供机械求值）。全文的 `model.fcstm` 与 `fcstm.fcstm` 指**同一份东西** |
| 两个执行模型 | `gpt-5.5` 与 `claude-opus-4-7`。两臂用的是**同样这两个**，下文表格里简写为 `gpt` / `claude` |

### 0.4 台账（ground truth）

**台账**是人工标注的「这份模型有哪些缺陷」的清单。标注对着**作者源** `plantuml.puml` 做，与任何方法的产出无关，标注时间早于本次两臂的任何一次运行。

| 步骤 | 条数 |
| :-- | --: |
| 台账原始记录 | 126 |
| 扣除 `00x8` 六个 pair 的记录（范围先验，与结果无关） | −27 |
| 再扣 1 条经独立边界裁定判为「表示层产物而非作者缺陷」的 | −1 |
| **进入分母的（下文称 `REPORTABLE`）** | **98** |

### 0.5 六个计数单位（全文反复出现，务必分清）

| 术语 | 含义 | 本次实验的规模 |
| :-- | :-- | :-- |
| **位** | 一个 (台账记录, 执行模型, 轮次) 三元组。问「这一格有没有报出这条缺陷」 | $98 \times 2 \times 3 = 588$ |
| **单元** | 一个 (台账记录, 执行模型) 二元组，跨三轮 | $98 \times 2 = 196$ |
| **issue** | 方法实际报出来的一条发现（逐条计数） | 主臂 1,105 / X1 1,365 |
| **认领 / 未认领** | 一条 issue 是否对应上了某条台账记录；未认领的进入「**多报侧**」 | 见 §6 |
| **簇** | 把同一 pair 六格里「说同一件事」的多条 issue 合成一条 | 主臂 288 / X1 212 |
| **去重组** | 把同一 pair 内指向**同一处根因**的多个簇再合并 | 主臂 124 / X1 188 |

### 0.6 三个覆盖率口径

| 口径 | 定义 | 分母 | 回答的问题 |
| :-- | :-- | :-- | :-- |
| `hit@1` | 命中的**位**数 ÷ 有效位数 | 588 位 | 一次运行的期望产出 |
| `hit@3` | **至少一轮**命中的单元比例 | 196 单元 | 这条缺陷在不在能力范围内 |
| `hit@all` | **三轮全部**命中的单元比例 | 196 单元 | 稳定性 |

**关于 `≤` 号**：主臂的 `hit@1` 在既有报告里一律写成 $\le 355/588$，因为台账本身有已知缺口（见 §2.2 末），那个数只能作为**能力上界**读。下文两臂对比的表格用 `=`，指「在这 98 条上实测得到的值」。**两种写法指同一个测量，不是两个数。**

### 0.7 多报侧的五类裁定

未被任何台账记录认领的产出，按既定分类学逐条人工裁定为五类之一：

| 类 | 含义 |
| :-- | :-- |
| 真漏记 | 确实是缺陷、NL 有依据，而台账漏记了——**唯一应补进台账的一类** |
| 表示债务 | 作者源里写了，但被 PlantUML → fcstm 的转换丢失。**既不是模型缺陷，也不是方法误判** |
| 无 NL 依据 | 事实成立、作者确实没写，但 NL 并不要求。属**过度规定** |
| 假阳性 | 事实不成立（元素其实存在，只是名字或形式不同） |
| 越界 | 依赖并发 / 不变式 / 时钟，落在 $M$ 之外 |

## 一、为什么要做这个实验

### 1.1 一个悬了很久的缺口

上一次实验（v46 全量矩阵）测出主臂的覆盖率是 $\mathrm{hit@1} \le 355/588 = 60.4\%$ [1]。**这个数字至今没有任何参照系**——60.4% 是好是坏，无从判断。

`experiment_design/next_round.md` §B1 把「朴素基线」列为下一轮的**第一优先项**，并逐字写明缺三样：**(1) 基线 prompt 本身 · (2) 自由文本产出如何进入现有判定链 · (3) 判定预算的分配决定** [2]。本次实验就是把这三样做掉。

### 1.2 要回答的问题只有一个

> **同样两个执行模型、同样 54 个 pair、同样 3 轮，不走八阶段循环，一个提示直接让它列出模型相对需求的不符之处，在那 98 条台账记录上是多少？**

### 1.3 一个必须先声明的立场

本文作者在实验开始前就知道：**期望的结果是基线的数字更低**。这一点写在事前登记的开篇，⛔ 不隐瞒 [3]。⭐ 之所以要写出来，是因为后文八轮判据的正当性完全取决于**判据是否独立于这个期望**——而这只有把期望摊开才能被检验。

## 二、对照臂怎么设计的

### 2.1 唯一共用项：同一份输入源头

〔用户明确裁定 2026-08-11〕逐字：**「真正两类共用的只有一条，那就是得是同一份输入源头，甚至是否都输入 fcstm / stm0 也是不必的，因为模型转换也是我们的方法的一部分。」「如果是有效性实验的话那三个都别用，就最朴素；如果是消融实验的话，那就三个各自消融各自的来看效果。」**

这条裁定的来历值得记：最初提的三条「公平性要求」——给同一份 `model.fcstm`、给证据链字段、给闭合谓词词表——⛔ **恰好就是本文的三条 contribution**。把它们给对照臂等于把贡献白送。

| 项 | 主臂（feedback loop） | X1 朴素臂 | 归属 |
| :-- | :-: | :-: | :-- |
| `nl.txt`（原始需求文本） | ✅ | ✅ | ⭐ **唯一共用项** |
| `plantuml.puml`（上游原始 stm0） | ⛔ | ✅ | ⚠ 见 §2.2 |
| `model.fcstm` / 中间表示 / 工作契约 | ✅ | ⛔ | **C-①**（模型转换是方法的一部分） |
| 19 条闭合谓词词表 / 断言 schema | ✅ | ⛔ | **C-②** |
| 证据链字段（元素表 / 需求绑定 / 定位 trace） | ✅ | ⛔ | **C-③** |
| 8 阶段循环（含三个审查 / 预检阶段与裁决，见 §0.2 的 ②④⑤⑧） | ✅ | ⛔（单次调用） | **C-①** |
| pyfcstm 的 parse / inspect / sim 任何输出 | ✅ | ⛔ | **C-①** |

### 2.2 一处必须披露的不对称：两臂读的不是同一份制品

⛔ **实验中途才查实**：主臂读 `pairs/<case>/fcstm.fcstm`（**编译产物**）+ trace + 契约；X1 读 `pairs/<case>/plantuml.puml`（**作者源**）。实测主臂源码树 `grep -rn 'plantuml\|\.puml'` **只有一处注释命中**——主臂从不看 PlantUML。⭐ 唯一真正共用的是 `nl.txt`。

⚠️ 这**不是**不公平：模型转换是 C-① 的一环，主臂只能看自己转换出的中间表示，那是方法自身的代价。⛔ 但它必须披露，因为**台账缺陷是按作者源标注的**。

⭐ **转换是否擦掉了缺陷——已逐条核查，答案是没有。** 98 条台账记录 × 42 对制品逐条对读：

| 类 | 条数 | 判据 |
| :-- | --: | :-- |
| A · 完全可见 | **79** | fcstm 上有与台账所述实质同形的声明 / 边 / 缺失 |
| B · 形态改变但仍可见 | **19** | 缺陷仍在，但表现为编译器注入的**自申报标记态** |
| **C · 被转换擦掉** | **0** | — |
| **D · 转换新造** | **0** | — |

机制：R4.5 转换把自由文本压成标识符时，**同时用 `named "<原文>"` 把原文原样带过去**，故以名字或标签为载体的缺陷一条未丢。B 类 19 条的主臂命中率 $70/114 = 61.4\%$，与整体 60.4% 几乎一致——⭐ 「编译改了形态」**没有**系统性压低主臂表现。

⭐ **但有一个更精确的不对称必须写进论文**：被编译擦除的缺陷类**在标注时根本无从与「正常」区分**。全语料有 4 处空复合状态括号（`state X { }`），转换后变成普通状态；而 126 条台账记录**没有一条**以它为对象。所以这 98 条**系统性偏向「能扛过编译的缺陷」**——`hit@k` 作为**已知缺陷集覆盖率**依然有效，⛔ 但它对「编译会擦掉的那一类」**完全无信息**。⚠️ 两臂在该类上不可比。

### 2.3 「最低限度」的下限判据

用户的目标有两层，⛔ 二者不可互换顺序：**① 在学术上说得通；② 在 ① 的前提下尽可能低配**。所以「低配」是**受 ① 约束的优化**。

⭐ 可判定的下限：**对照臂必须是「一个称职的实践者手上只有一个 LLM、没有我们的方法时，会真的这么做」的那个东西。**

⛔ **这两张表有一类东西枚举不到，必须先说清**：它们列的是**不给的能力**（词表、字段、循环），⛔ **没有「不给的策略」这一栏**。⚠️ 实际存在一条：主臂的 prompt 逐字要求「**Cover every normative NL segment**」（覆盖每个规范性 NL 段落），而 X1 只被告知「read the model in full」——⭐ 而 98 条台账**每条锚在一个 NL 段落上**，**逐段扫描正是最大化该指标的策略**。⛔ 所以「唯一共用项」⛔ **不等于**「所有不对称都已枚举」。

| ✅ 给了 | ⭐ 省了（合法的低配空间） | ⛔ 没省（省了就是稻草人） |
| :-- | :-- | :-- |
| 同两个模型、同 54 pair、同 3 轮 | 迭代 / 反馈 / 多轮修订（= C-①） | **完整输入**：全文，未截断 |
| 完整未截断的两份输入 | 三个审查阶段（= C-①） | **任务陈述的诚意** |
| 一次诚意的任务陈述 | 谓词词表 / 断言 schema（= C-②） | **推理空间**（见下） |
| 允许自由决定报几条 | 证据链字段（= C-③） | **模型档位**：同主臂两个模型 |
| schema 解析失败的原地重试 | 多样性采样 / best-of-n | **温度与采样参数**：同主臂 |
| 最小结构化输出 | worked example | **输出预算**：不设上限 |

**基线 prompt 全文**（11 行，`sha256 = 17e5067b…`）：

```
You are an experienced control-systems engineer reviewing a state machine model against the natural-language specification it was built from.

You are given two things, both complete and unmodified:
  1. The natural-language specification.
  2. A state machine model written in PlantUML.

Your task: identify the places where the model does not conform to the specification. Read the specification in full first, then read the model in full, then report what you find.

Report as many or as few issues as you actually find, and organize them however you judge best. For each issue, state what the non-conformance is, which part of the model it concerns, and why you consider it a non-conformance.

Write your findings in {content_language}. Return only the requested structured response.
```

**输出契约**：三个自由文本字段 `issue` / `where` / `reason` + 一个可选的 `analysis`。⛔ 无枚举、⛔ 无 validator、⛔ 无谓词措辞。

⭐ 两个字段各有目的，⛔ 不可合并：`reason` 是为**实验可分析性**（要对多报做与主臂同口径的五类分类，判定者必须知道它为什么认为那是问题）；`analysis` 是为**推理空间对等**（主臂是多阶段、每阶段有 rationale，X1 单次调用若必须直接填列表，跨 issue 的全局比对就没有落脚点）。

⛔ **`reason` 不构成 C-③**：分界线是「**谁来做归因**」，不是「有没有理由」。给基线一段散文理由，它的多报仍要人工读、人工分类；给它结构化四段链，才是把归因能力送出去。

### 2.4 prompt 冻结与事前登记

## 三、运行：324 格

### 3.1 网格

## 四、判定：588 位全人工

### 4.1 编制与口径

- **分母**：与主臂**完全同一**的 98 条 `REPORTABLE`（由权威实现 `metrics_at_k.REPORTABLE` 给出，并经逐条集合对拍）
- **位数**：$98 \times 2 \times 3 = \mathbf{588}$，⭐ 全部逐位人工判定，**无一位靠自动层兜底**
- **判据**：`hit_criterion.md` + `verdict_methodology.md`，⛔ 一字未改
- **编制**：6 个并行判定组 + 1 个复核组——⭐ 与主臂 v46 那轮的「八个并行判定组 + 一组回读原件复核」**同构**
- **判定指令**：⭐ 发给每组的是**物理同一份文件**——措辞漂移就是口径漂移

⭐ **三口径由同一份 `metrics_at_k.py` 算出**，同口径由机械而非记忆保证。

⚠️ **但「指令文件物理同一」⛔ 不等于「应用一致」**：判定组自报的**认领口径并不完全一致**（两组用「锚在同一条作者语句即算认领」的宽口径，一组用「实质复述台账命题」的严口径）；另有三处自报歧义，其中一处若改判即「该记录 1/6 → 6/6」。⭐ **注意方向**：这三处**若全部改判，X1 的数字会更高**——即判定组在这些位上取的是**压低 X1** 的一侧。

### 4.2 判定材料的防泄漏设计

⛔ 材料**不得含**三样：**主臂在同一位的判定结果**（判定者读到它会被锚定）· **台账的答案字段**（期望真值、断言表达式）· **四池归属**（由主臂结果算出）。三条由一条会失败的测试钉住。

⭐ 池归属只写进**兄弟目录**的顺序文件，⛔ 不在判定者的目录树里——⚠️ 初版把它写在材料上一层，独立审查者据此指出：判定者被指向该目录时一次 `ls` 就能看见它，而唯一约束判定者的那份指令并未点它的名（此处为综述该审查意见，⛔ 非逐字引文）。已修。

⛔ 材料**刻意不给** `primary_predicate` / `layer` / `direction`：X1 侧无谓词，给台账谓词名没有对照对象、只剩引导作用，而 `hit_criterion.md` §2 明写判据「不是两者用的谓词是否相同」。

### 4.3 查实并修掉的一个判定伪影

跨臂逐位对拍暴露：`EIS-0000-02` 的 5 位分歧上，**两侧在读不同的台账命题**。台账有一个 `basis_superseded_by_ruling` 字段，记着「本条原判据已被裁定**部分撤回**、换用了什么」，⛔ 而初版判定材料**没有渲染它**——于是 X1 判定组按**已撤回**的散文判命中，主臂判定者按改后的判据判未命中。

⭐ 全语料只有 **2 条**记录该字段非空，影响 **12 位 = 2.0%**。已修材料并由复核组重判：**8 命中 → 2 命中，6 位翻转，全部向下**（对 X1 不利），⛔ 无一位向上。

⭐ 错误机制清晰：原判组把台账读成「三条件压成单标签」∧「范畴错误」的**合取**，凡证明**前一个合取项**的都判「合取项之一」命中——⛔ 而前者正是被撤回的那半。

⚠️ **复核组自报了两处待裁定，⛔ 初稿把它们删掉了——而它们恰好能部分撤销这次「对主臂有利」的改判**：

1. **一条 issue 的「命题」取标题还是取 reason 全文？** 判 true 的 2 位**完全依赖 reason 里的附带论断**。⛔ 若口径改为只取标题，这两位应翻 false、该记录归零。
2. ⭐ **另一条记录的翻转可能反过来指向台账本身**：该模型内部确有一个匿名 final 伪状态，三格判定一致把它读作 NL 点名的那个 final 的实现；⛔ 而台账只认命名叶状态。⚠️ 若裁定认为匿名内部 final 足以充当，**需要重审的不是这三位，而是该台账记录换用后判据的存在性前提本身**。

⛔ **这次改判把 6 位移向对主臂有利的方向，而能部分撤销它的两条 caveat 被初稿丢掉了**——这是全篇唯一一处披露不对称朝**自利**方向倾斜的地方，故必须补回。

## 五、覆盖侧结果：基线更高

### 5.1 三口径

| 口径 | 主臂 v46 | **X1 朴素臂** | $\Delta$ = 主臂 − X1 |
| :-- | --: | --: | --: |
| `hit@1` | $355/588 = 60.4\%$ | $\mathbf{443/588 = 75.3\%}$ | **$-14.9$pp** |
| `hit@3` | $139/196 = 70.9\%$ | $\mathbf{160/196 = 81.6\%}$ | $-10.7$pp |
| `hit@all` | $95/196 = 48.5\%$ | $\mathbf{132/196 = 67.3\%}$ | $-18.8$pp |
| 按臂 `claude` | $184/294 = 62.6\%$ | $\mathbf{251/294 = 85.4\%}$ | $-22.8$pp |
| 按臂 `gpt` | $171/294 = 58.2\%$ | $\mathbf{192/294 = 65.3\%}$ | $-7.1$pp |

⚠️ **这两列不是召回率。** 分母是**人工整理的 98 条台账**，⛔ 不是缺陷总体——它们读作「**已知清单的覆盖比例**」。⭐ 而这张清单本身有一条已查明的系统性偏向（§2.2 末）：它**偏向「能扛过编译的缺陷」**，对被转换擦除的那一类**完全无信息**。

⛔ **在三个口径上，一次提示都高于八阶段循环。**

### 5.1.1 一条稳健性陈述：基线是**带着劣势**赢的

跑格**之前**，一位独立审查者提出过对本实验最强的公平性质疑（逐字）：

> 你的方法第一阶段被指示「覆盖每个规范性 NL 段落」，你的基线被指示「通读模型」。然后你针对一个每条都锚在 NL 段落上的真值测召回。你报告的差距里有未知比例是「覆盖扫描 vs 整体阅读」的差距——而能弥合它的那个子句只有一句话长、不泄漏任何东西、且不含你三条 contribution 中的任何一条。

⭐ **实测把这一击的方向反转了**：它原本预警「$\Delta$ 被**虚高**」，⛔ 而实测 $\Delta$ 是**负的**。也就是说，**基线在带着这个策略劣势的情况下仍高出 14.9pp**——⭐ 补上那一句只会让基线**更高**。

⚠️ 这不改变结论，⭐ 但它使结论**更稳健**：⛔ 「你削弱了基线所以它的数不算」这条反驳，在本实验上自动失效。

### 5.2 逐位分解：两臂**互有胜负**，不是一边宽松

两臂的判定表键格式逐字相同，可直接逐位并列：

| | 位数 | 占比 |
| :-- | --: | --: |
| 两臂都命中 | 269 | 45.7% |
| **仅主臂命中** | **86** | 14.6% |
| 仅 X1 命中 | 174 | 29.6% |
| 两臂都未命中 | 59 | 10.0% |
| 净差 | $+88$ | $\approx 15.0$pp ✅ 与 `hit@1` 的 $\Delta$ 闭合 |

⭐ **「仅主臂命中 86 位」是排除「X1 判定普遍宽松」的关键证据**：若 X1 判得松，我们会看到 `x1_only` 很大而 `main_only` 趋近 0。实际两臂各有 14.6% 与 29.6% 的独有命中——**这是能力正交的形状，⛔ 不是一边放宽的形状。**

### 5.3 X1 的命中与主臂**几乎不相关**

按主臂的四池（每条台账记录在主臂的命中位数）分布：

| 主臂池 | 位数 | X1 在该池的命中率 |
| :-- | --: | --: |
| 满格 6/6 | 222 | $171/222 = 77.0\%$ |
| 近满格 5/6 | 78 | $64/78 = 82.1\%$ |
| 不稳定 1–4/6 | 150 | $101/150 = 67.3\%$ |
| 零命中 0/6 | 138 | $107/138 = \mathbf{77.5\%}$ |

⭐ **满格池 77.0% 与零命中池 77.5% 几乎相同。** 即：主臂能否稳定命中某条缺陷，与 X1 能否命中它**基本无关**。⛔ 这直接反驳「基线只是把容易的那些捡了一遍」。

⚠️ **一处必须纠正的诊断逻辑**：曾把「满格池上 X1 独有命中 = 0」当作判定标准未放松的证据。⛔ **那是错的**——满格池按定义主臂全命中，`x1_only` 恒为 0，不含任何信息。⭐ 有信息的是上表的池内命中率与 §5.2 的 `main_only` 计数。

## 六、多报侧结果：精度也不在主臂这边

### 6.1 归并与口径

X1 产出 1365 条 → 762 条未被任何台账记录认领 → 按统一口径重认领 210 条 → **552 条 / 212 簇 / 188 去重组 / 50 pair**，闭合已机械校验。

⚠️ **主臂侧的对应链条材料里原本没有完整记录**：既有报告只给了「1,105 条已发布 issue」与归并后的「288 簇 / 124 去重组」，⛔ 中间那步（多少条未认领）是散文，未落数。本次从姊妹 clone 取回主臂逐格产出、用**它自己的匹配器**补算出 **755 条未认领**（§6.2）。⛔ 两臂的「条 → 簇」压缩比因此可比，但主臂的中间数是**我们补算的**，不是它原报告里的。

⭐ 认领口径选**宽**，理由是主臂匹配器的 docstring 逐字写着「Element overlap decides; the predicate only breaks ties」——它是命题盲与方向盲的，严口径正是它**不**做的事。⚠️ 该选择使 X1 的桶**变小**，⛔ 不是讨好我方的那一侧。

### 6.2 一个被我自己推翻的粗口径

曾用「命中效率」（每条 issue 换来多少命中位）作对比：主臂 $355/1105 = 0.321$、X1 $443/1365 = 0.325$，几乎相同。⛔ **这个量是错的**：它代数上等于 $\mathrm{hit@1} \times 588 / \text{issues}$，**从不问一条 issue 是否正确**；它的接近是**两个相反效应抵消**（X1 覆盖 +14.9pp、体量 +23.5%）。

⭐ 换成真实的精度度量立刻分开：

| | 主臂 v46 | **X1** |
| :-- | --: | --: |
| 未认领率 | $755/1105 = 68.3\%$ | $\mathbf{552/1365 = 40.4\%}$ |
| **已认领率** | $31.7\%$ | $\mathbf{59.6\%}$ |

⚠️ 主臂那个数**材料里原本没有**（v46 报告只有散文），是从姊妹 clone 取回逐格产出、用**它自己的匹配器**复算的。⭐ 同一条机械规则在两臂上跑三个变体（≥1 元素 / ≥2 元素 / 原始匹配器），**X1 每次都更低**。⚠️ 两个残余混淆方向相反、均已量化。

⭐ **表示债务对 X1 结构上不可能**：X1 的输入与作者源逐字节相同，而主臂读编译产物。⚠️ 即**主臂最大的一类多报（46.5%）整类来自它自己的转换步骤**。

⛔ **这里必须避免一次双重记账，初稿犯了这个错。** 初稿在此处写「不是方法的判断错误」——⚠️ 但 §2.1 拒绝把 `fcstm` 给对照臂的**唯一理由**恰恰是「模型转换是方法的一部分（C-①）」。⛔ **两者不能同时成立**：若转换是 C-①，它产生的债就是**方法的精度成本**，算账时不能净掉；若转换不算方法，那对照臂本来就该拿到 `fcstm`，§2.1 的不对称理由随之消失。

⭐ **本文取前者**：转换是 C-① 的一部分，故这 46.5% **计入主臂的账**。⚠️ 它仍是一条有用的**诊断**（主臂多报的主要来源是转换保真度而非判断力，那是可单独立项改进的方向），⛔ 但它**不构成对负担数字的扣减理由**。

⚠️ **凝聚度是决定性的一行**：主臂 **2.32** 条目/去重 vs X1 **1.13**。⭐ 故 X1 条目**更少**（212 < 288）但**不同根因更多**（188 > 124）——⛔ 两个分母指向相反方向，必须同报。

| 2 | 精度（已认领率） | 谁报的东西更准 | ⛔ 基线高（59.6% vs 31.7%），假阳性**平手** |
| 3 | 命中效率 | 每条 issue 换多少命中 | ⛔ **自我推翻**：该量从不问 issue 是否正确 |
| 4 | 转换擦除量化 | 主臂是否因读编译产物而先天不利 | ⛔ C 类 = 0，解释被推翻 |
| 5 | **可断言性** | 基线的发现能否写成可求值命题 | ⛔ X1 **98.4%** vs 主臂 **99.2%**，差 **0.8pp** |
| 6 | **下游就绪度** | 加上「期望值必须明确」这条 | ⛔ 基线组间跨度 **26.4pp** > 臂间差 17.3pp |
| 7 | **形态对照** | 把主臂断言渲染成散文再判，命中率会升吗 | ⛔ **设计错误**：目标信号不在样本空间里 |
| 8 | **文献佐证** | 「评判对散文更宽松」有文献支撑吗 | ⛔ 只能类比，且被我们自己的数据削弱 |

### 7.2 第五轮（可断言性）为什么失败

判据是三条**方法中立**的要件：**可定位**（点名的元素能唯一确定）· **可判定**（命题有确定真值）· **单一方向**（不是若干可能性并列）。⛔ 刻意不绑定任何谓词词表——否则是循环论证。

四个判定组（A1–A4）独立判完 X1 的 443 位，第五组（M1）判主臂抽样的 120 位，**四组独立给出六条批评，复核后全部成立**：

1. ⛔ **要件 1 零鉴别力**：443/443 全过。⭐ 另有独立证据把它钉死——多报侧全量实测**未定位条目 = 0/1365**，⛔ 基线的**全部**产出都可定位。
2. ⛔ **要件 3 几乎不可能失败**：判据的一条豁免条款把它系统性豁免了。
3. ⛔ **整个判定退化成要件 2 一条，而它分开的是「需求句」不是「两条臂」**——唯一失败的一族是某个 NL 句里的概念在模型侧无指称，⚠️ **任何方法报那句 NL 都撞同一堵墙**。
4. ⛔ **最致命的一条**：严口径测的是**输出格式**（基线从未被要求输出命题），宽口径测出 100% 则等于承认**基线的发现本身可形式化**——⛔ **两个方向都不支持用它论证主臂优势。**
5. ⛔ 豁免条款的**受益者恰是啰嗦的输出**：一个吐 6 条泛泛议论、其中 1 条碰巧精确的输出，与一个只吐 1 条精确命题的输出，**得分相同**。
6. ⚠️ 15.5% 的通过靠「动作集恰好为空集」——⛔ 若制品带任何部分标注，指标会摆动 **15pp**。

⭐ 顺带证伪了一句本打算写的话：**主臂不是 100%**（119/120），⛔ 「by construction 100% 可断言」不成立。

### 7.3 第六轮（下游就绪度）为什么失败

收紧点：上一轮只问「**能否**求值」，⛔ 漏了「**应该是什么**」——而一条断言必须有期望值才能求值为真假。

**两列的区别**：`ready_strict` 只判**判定者当时锚定的那一条主张**；`ready_lenient` 允许用同一条 issue 记录内的其它部分补全。⚠️ 上一轮的教训是**口径松紧决定结论**，故本轮强制双报。B1–B4 是四个独立判定组，各判约 110 位。

| | `ready_strict` | `ready_lenient` |
| :-- | --: | --: |
| 基线 B1 | 68.2% | 69.1% |
| 基线 B2 | **94.6%** | 98.2% |
| 基线 B3 | 80.4% | 89.3% |
| 基线 B4 | 80.9% | 81.8% |
| 基线合计 | 81.0% | 84.7% |
| **主臂** | **98.3%** | 98.3% |

⛔ 表面臂间差 17.3pp，**但两条硬伤各自足以否掉它**：

1. ⛔ **基线组间跨度 26.4pp > 臂间差 17.3pp**——噪声大于信号。
2. ⛔ **主臂判定组的自我否定**：「主臂的 issue 散文**不是自由文本**，它是『需求 R 要求 X，而 R 的谓词求值为 False』这个模板的自然语言渲染。R 是 splitter（§0.2 的阶段 ①）产出的、**带期望值的结构化需求**……所以主臂散文携带期望值**是流水线形状的必然结果**……**你测的仍然是产出形态**。」

⭐ **三个基线组独立给出同一诊断**：失败集几乎完全落在「**NL 自己没给期望值**」的需求上（「canceling **or** updating the cooking time」「three different state areas」），⛔ 方差由**需求文本**与**缺陷类型**解释。⚠️ 一组实测「35 条失败只由 **6 个台账条目**贡献」，另一组独立指出「110 条的**有效独立样本量只有 ~20**」——⭐ 两组各自对自己那 110 条说的，⛔ 不是同一批。

⭐ **一个被推翻的假设**：把主臂散文里 48 位含谓词调用的表达式引述**全部遮掉**再重判，**0 位翻转**——⛔ 主臂散文的信息量**不是**靠抄断言得来的。

### 7.4 第七轮是一个设计错误，必须记录

设计：把主臂的断言**向下渲染成散文**（去掉谓词名、路径、真值），让盲判组重判。若命中率上升，形态效应就被直接量出来了。⭐ 这本是八轮里唯一「内容固定、只变形态」的设计。

⛔ **但渲染组完成后指出：样本全是命中位，重判只能持平或下降，命中率不可能上升——判据在本样本上封顶了。** ⭐ 若「判定对散文更宽松」为真，它该表现为主臂**当前未命中**的发现换成散文后被判成命中，⛔ 而那批位一个都不在样本里。

⚠️ **这是「带着期望的结论去设计实验」的典型形态**：想测「散文更容易被判命中」，却只给了已经命中的位——**目标信号在样本空间里根本不存在**。

⭐ 渲染组另列四个漏洞：**底稿不同**（主臂发现是对 fcstm 写的，基线判定用 puml，23 位会撞上只存在于 fcstm 的转换产物）· **篇幅 +26%**（测的是长散文 vs 短散文）· **三段式布局本身是干预** · **渲染者非盲**。⛔ 盲判步骤未执行——按上述漏洞，执行它只会得到一个无法归因的数。

### 7.4.1 还有一轮口径「写好了但决定不执行」，⛔ 初稿把它整个吞掉了

第五轮失败后、第六轮启动前，曾另写过一份**更严**的判据（以「可重放性」为轴）。它自估效果时逐字写道：

> ⚠️ 预估收紧后 X1 会掉到「六成上下」——**那正好能把 `hit@1` 从 75.3% 压到 45% 左右。**

⛔ 随后**自我否决**，理由逐字：

> ⛔ **它仍然是同义反复的变体。** 主臂在收紧口径下会是 100%，⚠️ **而那是因为它的输出形态就是断言**。任何以「像不像断言」为轴的比较，产断言的一方必胜——**审稿人一句话就能打掉。**

⭐ 那份文件自己要求这件事必须公开：「⚠️ 时序也必须如实记录：本文件写在看到不利结果**之后**……⛔ 但『作者在结果不利后设计了一个更严的口径』这件事本身必须公开。」

⛔ **初稿没有公开它。** ⚠️ 而且它还预言了第六轮的失败方式——「若将来有人要执行本轮口径，⛔ **前提是先换分母**：分母必须是**全部产出**，⛔ 不是 443 个命中位」——⭐ 第六轮仍在 443 位上跑了，并部分因为被预言的那个理由失败。

### 7.5 第八轮（文献）：只能类比

15 条已核引用，4 个子命题 + 3 条反向证据。⚠️ **成色不齐**：其中 2 条仅读到摘要页、2 条本轮未亲核，⛔ 而后者之一正是 §6.2 的首位挂引。**诚实评级如下**：

- ⛔ **「基线的发现不可形式化」——死，被我们自己的数据杀掉**（98.4%）。
- ⚠️ **「尺子对散文更宽松」——文献里活着，但只在窄形式下**（最强的一条：同一评判、同一数据，**绑定错误被抓 98.3%、回答不完整只被抓 33.9%**），⛔ **但它解释不了我们的 14.9pp**。
- ⭐ **能站住的只剩交付形态陈述**：「基线的发现**尚未被**形式化，方法臂的**已经是**」——⚠️ 那是**关于谁做了那一步**，⛔ 不是关于谁**能**做。

⛔ **天花板是 threats-to-validity 一段。** ⚠️ 而且**文献中最大的反向证据不是预期的那篇**（⛔ 真正最重的两条威胁不在文献里，⭐ 在我们自己的数据里——§7.2 的 98.4% 与 §5.2 的能力正交），而是一项**针对该假设的显式反证实验**：剥掉标记、把提取出的散文重新评判，「分数没有实质变化，退化反映的是**真正更差的写作，不是评判偏见**」（⚠️ 原文为英文，此处为中译）。⭐ 唯一辩护是它对照的两侧**都是散文**，故它反驳的是「评判不喜欢标记」，⛔ 不是「评判对模糊 vs 精确用不同严格度」。

⚠️ 另一条：带对冲的回答评分低 25.6% ⇒ ⛔ 措辞只能说「对**不完整**的宽容」，绝不能说「对**对冲**的宽容」。

### 7.6 五个判据里，有两个收敛到同一个机制

> **任何形如「基线的产出缺少 X」的静态判据，只要 X 恰好是主臂的输出格式，方差就会被「需求文本的信息量」与「缺陷类型」吃掉——⚠️ 而那两样对两臂是共同的。**

⛔ **但「八次收敛到同一机制」是过度概括，初稿这么写是错的。** 逐轮对着该机制验：

| 轮 | 实际失败原因 | 符合该机制？ |
| --: | :-- | :-: |
| 1 `hit@k` · 2 精度 | **基线赢了**——是主结果本身，⛔ 不是「静态判据」 | ⛔ |
| 3 命中效率 | 该量代数退化（等于 $\mathrm{hit@1} \times 588/\text{issues}$）——**定义错误** | ⛔ |
| 4 转换擦除 | 混淆假设被实证推翻——是**核查**，⛔ 不是找优势的判据 | ⛔ |
| 5 可断言性 | 同义反复 + 判据退化 | ⭐ **是** |
| 6 下游就绪度 | 同义反复 + 方差被需求文本吃掉 | ⭐ **是** |
| 7 形态对照 | **抽样设计错误**，且⛔ **根本没出结果**（盲判未执行） | ⛔ |
| 8 文献 | 找不到直接证据，⛔ 不是一次测量 | ⛔ |

⭐ **诚实的版本**：**五个为找差异而设计的判据里，有两个收敛到「同义反复」这同一个机制**——而它们恰好是唯二做完独立判定的两轮（5 组 + 5 组、共 **1,006 位**判定）。

⛔ **并且必须纠正一处推理方向。** 初稿写「这个结论难被推翻，因为它是被我们自己反复的失败证实的」——⚠️ **那是反的**：**反复测不出差异，是仪器失效的证据，⛔ 不是差异不存在或不可测的证据**。第 3、4、7 轮按我们自己在 §11 里的定性分别是「定义错误」「不是判据」「目标信号不在样本空间里」——⭐ **一个结构上不可能探测到目标信号的轮次，对「这件事不可测」的贡献恰好是零**（它在两个假设下都必然失败，似然比为 1）。⛔ 把设计失误计入证据，等于用自己的错误加固自己的结论。

## 八、三件对主臂不利、必须主动摊开的事

### 8.1 主臂命中位里有一批建立在「名字敏感」的谓词上——量级取决于一条判据怎么读

⚠️ **先说形态**：主臂的断言点名了一个标识符，⛔ 而那个标识符**是发现模型自己从 NL 散文里造出来的**，模型里并无同名对应物。⭐ 问题在于——若该名字在模型里根本不存在，那条断言**对任何模型都平凡为假**，于是「它为假」就不携带信息。

两个独立判定组分别测出 **26.7%**（M1）与 **30.0%**（M2 的宽读法）。⚠️ **但 M2 同时给了严读法的 2.5%，二者差 12 倍**，分界在于：宽读法把「该名字在模型里没有可解析对应物」**单独**作为充分条件；严读法额外要求证明「有真实元素承担了该角色」。

⛔ **本文采严读法（2.5%）。⚠️ 这次口径选择的方向对我方有利，所以理由必须写得比别处更硬：**

⭐ **从 NL 取标识符正是「需求驱动」的证据，⛔ 不是缺陷。** 台账缺陷本身就是「**NL 点名了 X，而模型里没有 X**」这个形状——方法报 `state_declared("auto_final") = False` 在这种情形下是**正确的发现**，而不是空洞的命题。⛔ 宽读法只要求「该名字在模型里没有可解析对应物」，于是**把正确的缺失发现整批算成了空洞**。

⭐ **真正的假阳性只发生在一种情形**：模型用**别的名字**实现了同一个概念，而方法没认出来、仍报「X 不存在」。⚠️ 而这恰恰是严读法额外要求证明的——「**有真实元素承担该角色**」。⛔ 所以严读法测的才是这个问题，宽读法测的是另一件事。

⭐ 严读法下的 **3 条**是真问题，实例：把两个 NL 词并成一个标识符 `Accelerating_or_Cruising`，而模型**分开建模**且分开更合理；把 NL 里的一个**条件**造成了一个**状态名**。⚠️ 这三条确实空洞，⛔ 但它们是 120 位里的 3 位。

⚠️ **初稿采宽读法并据此推算过一个「扣除后的主臂 `hit@1`」——那是过度自我批评，已整段撤回**（记入 §11）。⭐ **主臂的数字是 $355/588 = 60.4\%$，本文不对它做任何扣减。**

#### 8.1.1 这条判据只在**一条臂**上量过，所以「有区分力」是断言而非测量

初稿写它「方法中立、对称适用，是唯一真正有区分力的量」。⛔ **前半句是设计意图，后半句不成立**：逐文件核过，该字段在**基线侧的 443 位里一位都没判过**，只有主臂的 120 位有。而它自己的登记写死的成立条件是**两臂之差 > 10pp**——⛔ 只有一臂的数，这个条件在原理上无法求值。

⚠️ **而且这一刀朝两边砍**：基线的元素名是从它拿到的 PlantUML 里**直接读出来的**，它可能得分**远好于**主臂（那样对主臂更糟）；也可能它同样从 NL 里造名字（那样这条就没区分力）。⛔ **我们不知道。** ⭐ 正确表述：**在主臂上按严读法测出 2.5%（3/120），基线侧未测，区分力未知。**

#### 8.1.2 同型的第二条通道

主臂判定组还指出**另一条空洞化通道**，⛔ 不被「名字敏感」覆盖：**判据不惩罚空洞**。形如 `edge_declared(source=<某个不存在的状态>, …) = False` 的断言——良构、可判定、单一方向，⛔ 但它说的不超过「那个状态不存在」，⚠️ 而同格另一条 issue 已经说过了。⭐ 即**派生 / 冗余命中会虚增计数**。⛔ 未量化。

⚠️ **它与 §8.1 的名字敏感不同**：那一条问「名字在不在」，⭐ 这一条问「**即便名字在、真值也对，这条发现是否只是另一条的推论**」。⛔ 两者都会虚增计数，⛔ 但只有前者被量过。

### 8.2 主臂的多报负担被自己的报告低估

⚠️ §6.6 记录的现象：主臂有 **102 条 issue 机械未匹配上任何台账条目**，它们分布在 **6 个 pair** 上，⛔ **却一个桶内簇都没形成**。

⭐ **为什么这对我方不利**：桶内成簇本是把「同一件事被反复报」折算成一条的机制；⛔ 零簇意味着这 102 条**各说各的**，⚠️ 也就意味着它们**全额计入多报负担**，⛔ 而报告在 §6.4 用的正是折算后的口径。⭐ 换言之，§6.4 里主臂「过度规定少 40%」这个数，⛔ **没有把这 102 条的分散性充分反映进去**。

### 8.3 判定非盲

判定组知道自己在判基线臂。⛔ **不做混臂盲判**，⚠️ 但原先给出的三条理由里有两条**站不住**——本仓库既有工具的文档逐字写着「缺省只报，不改」「双报是它的解药，不是修饰」「没有盲判就无法自查」。⭐ **诚实的表述是**：盲判在技术上可行、工具现成、零语料成本，⛔ **本代次因判定预算不做**，非盲记入 Limitations。⛔ 不得再说「因为与冻结冲突所以做不了」。

## 九、这个实验证明了什么

### 9.1 可以写进论文的

1. **主臂的 $\mathrm{hit@1} \le 60.4\%$ 现在有参照系了**，而参照系比它高 14.9pp。
2. **成本差异是数量级的**：1/212 的 token、1/11 的调用、7.2 分钟跑完 324 格、0 失败。
3. ⭐ **主臂最大的一类多报（46.5%）整类来自它自己的转换步骤**——⚠️ 这是一条有用的**诊断**：多报的主要来源是转换保真度而非判断力，那是可单独立项改进的方向。⛔ **但它计入主臂的账**（§6.3），⛔ 不是扣减理由。⚠️ 初稿在此做过一个「若保真度提升则领先从 17% 变 37%」的反事实推算，**已删除**——(a) 按上述记账原则不能净掉自己贡献的失效模式；(b) 那个反事实是**单边**的，而 §2.2 的 19 条 B 类恰恰证明同一个转换**已在改变缺陷的可见形态**，提升保真度会同时移动覆盖侧，方向未知。
4. ⭐ **八轮的失败模式本身**（§7.6）。

### 9.2 不能写的

1. ⛔ 不得说「我们找到的问题比普通 LLM 多」——**实测相反**。
2. ⛔ 不得说「基线的发现不可机械求值 / 不可定位」——**98.4% 可断言、100% 可定位**。
3. ⛔ 不得说「我们精度更高」——**假阳性平手**，已认领率基线更高。
4. ⛔ 不得声称统计显著——本语料只有 8 个独立 NL 簇，低于工具门槛 10。措辞上限是「在本语料上观察到 $\Delta = -14.9$pp」。
5. ⛔ 不得说「方法臂 by construction 100% 可断言」——**119/120**。

### 9.3 一个方法论结论【推论】

> **在「谁发现的缺陷多」这个问题上，形式化方法与自由文本 LLM 评审不可用单一覆盖率指标比较。**

⛔ **这个结论的强度必须限定**，初稿高估了它。⚠️ 三条限制：(a)「反复失败」里有三轮是**我方设计失误**，而失效的仪器对「不可测」的贡献为零（§7.6）；(b) 八轮里只有两轮有跑前写死的成立条件（§7 开篇表）；(c) 它是从 **1 个语料、8 个 NL 簇、2 个执行模型、1 种基线设计**外推的。

⭐ **今天站得住的窄版本是**：

> **在本语料与本台账上，任何形如「基线的产出缺少 X」的静态判据，其方差都被「需求文本信息量」与「缺陷类型」吸收，而这两者对两臂共同。**

⛔ **证据的边界要说准**：支撑它的是**两个独立判据、1,006 位判定**（第 5 轮可断言性 981 位 + 第 6 轮下游就绪度 25 位）。⚠️ 那 1,006 位判的是**产出形态**，⛔ **不是 `hit@k`**——⭐ 所以这个命题成立的范围是「**这类静态判据测不出两臂差异**」，⛔ **不能扩写成「覆盖率本身不可比」**。后者需要的证据我们没有。

⛔ 初稿还写过「X1 忠实地回答了一个我们其实不该问的问题」——⚠️ **该句已删**：它是一句**通用免责**，任何将来不利的对比都能被重新标注为「不该问的问题」。⭐ 我们挣到的是上面那个窄命题，⛔ 没有挣到「不该问」。

## 十、建议【推论】

### 10.1 论文的有效性主张整体转向「交付形态 + 成本」

⛔ 支点**不能**是「基线发现不了」或「基线的发现不可断言」——这两条实测都是假的。

⭐ 候选支点是：**方法交付的是一个已经形式化、可重放、可回归、可追踪的制品**。⛔ **但必须如实标注它当前的证据状态**：

| 属性 | 测过吗 | 状态 |
| :-- | :-- | :-- |
| 已形式化 | ⭐ 测过 | ⛔ **不分离两臂**：98.4% vs 99.2%（§7.2） |
| 可重放 | ⛔ **未测** | ⚠️ 曾写好一份判据文件后**自我否决**，理由逐字是「它仍然是同义反复的变体……任何以『像不像断言』为轴的比较，产断言的一方必胜——**审稿人一句话就能打掉**」 |
| 可回归 | ⛔ **未测** | 八轮里一次都没有 |
| 可追踪 | ⛔ **未测** | 同上 |

⛔ **所以初稿那句「这不是规避，而是有八轮实验支撑的方法论判断」不成立。** ⚠️ 八轮支撑的是「**覆盖率口径分不开两臂**」，⛔ 它**不支撑**「交付形态分得开两臂」——这两件事之间没有推理链，本文也没有提供。

⭐ **今天能说的只有**：覆盖率这条路走不通；**交付形态是下一个待检验的假设，我们尚未测量它**，且已记录了「以『像不像断言』为轴」这条路为什么测不出东西。⛔ 把待检验假设写成「有八轮支撑的判断」，正是有效性主张跑在证据前面的标准形态。

### 10.2 X1 的价值重新定位

⛔ 它不是「证明我们更强」的对照臂，⭐ 而是给出了**一个关于「这个对照该怎么设计」的负结果**。

⛔ **初稿写它「对审稿人更难攻击，因为它不依赖任何对我方有利的假设」——那句话本身就是一个假设。** ⚠️ 它至少依赖三个：8 个 NL 簇的负结果可外推 · 交付制品的可重放 / 可回归 / 可追踪价值真实存在（**未测量**）· 「本该怎么设计」已被确立（⛔ **无一轮测过**）。

### 10.3 §8.1 那几条「造名」建议在本次讨论就摊开

⚠️ 严读法下的 **3 条**（120 位中）是真问题：把两个 NL 词并成一个标识符 `Accelerating_or_Cruising`（而模型分开建模且分开更合理）、把 NL 里的一个**条件**造成了一个**状态名**。⭐ 在导师会上主动提出，与被审稿人查出来，是两件事。⛔ 而且它可修：判据（**真值能否在名字解析到真实元素后存活**）已经现成，可作为下一代次的门。

⛔ **但不要把它说成「三成的命中是空洞的」**——⭐ 那是宽读法的产物，而宽读法把**正确的缺失发现**也算了进去（§8.1）。

### 10.4 需要导师裁定的三件事

| # | 议题 | 我方倾向 |
| --: | :-- | :-- |
| 1 | 论文口径是否整体转向交付形态 + 成本 | ⭐ 倾向转向；但这会改变 RQ 与三条 contribution（§0.2）的强度档 |
| 2 | §8.1 的 30% 名字敏感率如何处置 | ⭐ 倾向本次摊开 + 下一代次加门；也可先补一轮严格复核确认量级 |
| 3 | ⭐ **有没有我们还没测、但应该测的东西** | ⚠️ 初稿把这条写成「是否继续找**拉低基线**的口径」——⛔ 那个提法把目标说成「移动一个数字」，且已附三条理由、无反面情形，只能收到橡皮图章。⭐ 改成现在的提法后它是真议题：**至少两样从未测过**——(a) §10.1 表里的可重放 / 可回归 / 可追踪；(b) §8.1.1 基线侧的名字敏感率（缺它则「区分力未知」）。⛔ 我方倾向不再加「静态判据」型的第九轮，⭐ 但上述两样属**补测缺口**，不同类 |
