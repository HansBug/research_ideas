## 4. 正式定调：第一篇论文从 `NL -> STM` 转向模型修正

### 4.1 直接要求与路线变化

以下内容属于 **【正式定调】**：

1. **第一篇论文不再是简单的 `NL -> STM` 状态机生成任务。** 讨论后，第一篇的核心贡献应从“生成一个状态机”转为“给定自然语言需求与已有状态机后，自动修正和改善状态机”。
2. **新的核心任务是 `<NL, STM_0> -> STM_k / Better STM`。** 输入应包含自然语言需求和一个 initial STM；输出是经过反馈驱动修正后的 improved STM。
3. **`NL -> STM_0` 阶段不应成为论文方法主贡献。** 该阶段与已有 prompt-based 或 multi-stage aggregation 方法相比没有足够显著变化，把它放入主线会削弱工作重心。
4. **方法 loop 应是无人化自动循环，而不是人在回路 agent loop。** 给定冻结输入和评价条件后，系统自动 check、feedback、repair、regression check；人主要在数据构造、评价审计和最终裁决中出现。
5. **已有 baseline 中可获取的真实 NL 与 STM artifact，可转为本任务输入。** 它们不再只承担 direct generation competitor 角色，而应成为 seed STM、格式转换目标、错误类型来源和 related work 证据。
6. **需要考虑多格式转换器。** 因为 prior work artifact 可能是 UML、SysML、PlantUML、Mermaid、表格、工具特定格式等，必须把能纳入 benchmark 的格式转换到内部可检查、可执行表示中。
7. **仍应弱化 `fcstm` / `pyfcstm` / DSL 名称。** 这延续 2026-06-04 导师意见：论文不要主打新 DSL，否则需要说服审稿人为什么接受一个新概念；应写成“语义增强、可机检、可执行状态机表示”。

### 4.2 新任务边界

```text
Outside method scope / seed construction:
  NL --prior work / weak prompt / old model / student / converter--> STM_0

Core method scope:
  <NL, STM_i> -> diagnostics / feedback / simulation -> repair -> STM_{i+1}
```

**【正式定调】**：论文贡献应聚焦 `STM_0 -> STM_k` 的自动修正过程。`NL -> STM_0` 只记录来源和可复现配置，不作为论文贡献，也不计入 repair-loop 的效果提升。

**【AI 衍生建议】**：后续实验报告中应把 seed construction 与 repair loop 分开统计，避免把 seed 生成质量、converter normalization 或人工清洗误计为自动修正能力。

### 4.3 为什么这个转向更稳

**【正式定调】**：`NL -> STM` 已经是 crowded baseline 区域。若继续主打生成，审稿人会优先追问 prompt、模型、direct baseline、公平比较，而不是关注我们的 check / feedback / simulation / repair-loop 机制。

**【AI 衍生建议】**：新的 story 更适合采用“executable feedback / refinement / repair”叙事：

1. existing works may generate behavior/state-machine-like artifacts；
2. practical use requires semantic consistency, executability, and traceable repair；
3. our work studies whether structured diagnostics and simulation feedback can improve an initial model;
4. the contribution is not a new DSL or a bigger prompt, but a feedback-driven refinement protocol with evidence.

## 5. 正式定调：语义增强表示的定位

### 5.1 直接要求

以下内容属于 **【正式定调】**：

1. 很多已有 STM artifact 偏描述性，缺少足够语义、形式化约束和可执行性，因此难以建立有效 feedback。
2. 为了支持 check / feedback / simulation / repair loop，需要增强状态机表示，使其至少能承载状态、迁移、事件、guard、action、变量、层次结构、diagnostics 和 scenario simulation。
3. 这种增强是第一篇方法得以成立的必要铺垫，但不应被包装成独立 DSL 贡献。
4. 主文应写“semantically enriched, machine-checkable and executable state-machine representation”，不要把 `fcstm` 名称放在主贡献位置。

### 5.2 AI 衍生建议

1. **术语建议**：优先使用 `semantically enriched state-machine representation`、`machine-checkable state-machine artifact`、`executable state-machine representation`。
2. **避免术语**：避免在 title、abstract、Introduction contribution 中使用 `fcstm`、`pyfcstm` 或 `new DSL`。
3. **实现落点**：工具名可放在 artifact / implementation / reproducibility section 中，作为实验载体，而不是 novelty claim。
4. **claim 边界**：不要写“完整形式化验证 / model checking”，除非后续真的引入相应性质、模型检查器和 soundness 边界；当前更安全的是“lightweight formal or static diagnostics”。

## 6. 正式定调：baseline 与数据的新角色

### 6.1 baseline 不作废，但角色重排

以下内容属于 **【正式定调】**：

| 来源 | 新角色 | 说明 |
|---|---|---|
| 可获取真实 NL + STM artifact 的 prior work | seed STM / 输入数据来源 | 将其 NL 与 STM 作为 `<NL, STM_0>` 输入，评测修正后的 `STM_k`。 |
| prior work 产物格式不同 | 格式转换目标 | 将可纳入 benchmark 的格式转换成内部可检查、可执行表示。 |
| 低配 prompt / 旧模型 | 可控噪声 seed | 构造质量较低但可运行的 `STM_0`，测试修正能力。 |
| 学生 / 人工初始建模 | realistic noisy seed | 模拟真实建模误差。 |
| Top-15 / Backup-15 控制系统 NL | benchmark source | 不再只服务 `NL -> STM` 生成，而是服务 `<NL, STM_0>` seed construction 与 repair evaluation。 |

### 6.2 AI 衍生建议：对照实验仍然需要

虽然 prior `NL -> STM` work 不再是唯一 direct competitor，但后续 evaluation 不应让 baseline 消失。建议至少保留：

1. **no-repair seed**：直接比较 `STM_0` 与 `STM_k`。
2. **regenerate-from-NL**：从 NL 重新生成一个新 STM，与 repair route 对比。
3. **LLM self-refinement without structured feedback**：看结构化 diagnostics / simulation feedback 是否有边际作用。
4. **可获得的 repair / refinement baseline**：若相关工作或工具可用，应纳入。
5. **converter-aware analysis**：区分 converter normalization 带来的质量变化与 repair loop 带来的质量变化。

## 7. AI 衍生建议：第一篇 RQ 与评价设计

本节是 **【AI 衍生建议】**，用于后续 story reframe PR 起步；不是导师逐字确认的最终 RQ。

| RQ | 问题 | 可能证据 |
|---|---|---|
| RQ1 | 初始 STM 的主要缺陷类型是什么？ | parse / semantic / guard / action / hierarchy / behavior 缺陷统计。 |
| RQ2a | 不同 feedback source 能发现哪些结构、语义或行为问题？ | diagnostics 类型、blocking issue、feedback source 分层统计。 |
| RQ2b | feedback 输入 repair loop 后，哪些问题能被稳定关闭，哪些会引入回归或振荡？ | 修复前后 valid rate、缺陷闭合率、rejected repair、oscillation / non-convergence。 |
| RQ3 | 仿真反馈能否发现静态检查难以发现的行为缺陷？ | scenario pass/fail、trace evidence、behavior mismatch、simulation-only defects。 |
| RQ4 | 自动修复循环是否让 STM 质量更好？ | `STM_0` vs `STM_k` 的组件级质量、可执行性、行为一致性、回归失败、过修 / 振荡。 |
| RQ5 | 不同 seed 来源对修正效果有什么影响？ | prior artifact seed、弱 prompt seed、旧模型 seed、学生 seed 的分层结果。 |
| RQ6 | 转换层带来的信息损失和适配风险是什么？ | 转换成功率、不可映射字段、转换后 diagnostics 分布。 |

建议操作化 `Better STM`：它指相对于同一 `STM_0`，在预定义评价维度上取得可审计改进的模型候选，包括 blocking diagnostics 减少、semantic / executable validity 提升、冻结场景与回归检查通过率提升、与 NL-grounded human adjudication 更一致。它不等价于完全正确模型，也不等价于完整形式化验证通过模型。

建议加入 repair acceptance / rollback protocol：每轮 repair 生成 candidate 后，必须重新执行 parse / semantic / design diagnostics、冻结 scenario suite 与 regression checks；只有相对当前 best model 无新增 blocking issue 且满足预设改进准则时才接受，否则 rollback 到当前 best。所有 rejected repair、oscillation、non-convergence 均应计入结果。

## 8. 第二篇论文：从 `sources` 文库转向 agent-based SLR

### 8.1 直接要求与路线变化

以下内容属于 **【正式定调】**：

1. 第二篇不必费力把 `sources/` 文库包装成传统综述、corpus paper 或 benchmark-source landscape paper。
2. 更有潜力的方向是把文库建设中的自动化流程上升为 **agent-based SLR**：研究如何自动化或 agent 化系统文献综述 / systematic mapping 中的检索、筛选、全文抽取、编码、综合和报告环节。
3. 评价不应与人类最终发表的 SLR 硬比胜负，而应聚焦可追踪性、事实准确性、幻觉控制、筛选一致性、coverage proxy、成本与效率。
4. 这个方向可以考虑 EMSE，但需要后续补足 SLR 方法学、相关自动化工具、benchmark、人工审计与 replication package。

### 8.2 SLR 背景

SLR 即 systematic literature review，软件工程中的经典方法学入口是 Kitchenham & Charters 2007 [1]。SLR 通常围绕明确 research question，通过系统化、可审计的检索、纳排、质量评价、抽取、综合和报告流程来整合证据。Systematic mapping 更偏构建分类框架、刻画领域覆盖和统计研究分布，代表入口包括 Petersen et al. 2008 [2] 与 Petersen et al. 2015 [3]。PRISMA 2020 [4][5] 主要是 reporting guideline，可作为透明报告参考，但不能在未满足 protocol、search ledger、screening log、exclusion reasons 和 checklist 的情况下声称 PRISMA-compliant。

### 8.3 AI 衍生建议：第二篇更安全的 story

本节是 **【AI 衍生建议】**。

更保守的 story 可写为：

> 本文研究带 human audit gates 的 agent-based SLR：将传统软件工程 SLR / systematic mapping 中的检索、筛选、全文抽取、编码、综合和报告环节组织为 agent-executed workflow，并在 protocol approval、gold / silver audit、disagreement adjudication 与 final claim review 处保留人工审计门，用可追踪性、事实准确性、幻觉控制、筛选一致性和成本效率评价其可靠性。

不应写成：

- agent 可以完全替代人类 SLR 专家；
- 端到端无人自动产出合格 SLR；
- 自动 SLR 完全无幻觉或完全覆盖；
- 本文首次自动化 SLR；
- 未完成 checklist 前声称 PRISMA-compliant。
