## 执行摘要

一次完整实验：**54 pair × 2 模型 × 3 轮 = 324 格**，324 格全部落盘、零耗尽、零崩格；
其中 **9 格（2.8%）带降级诊断落盘**，低于事前登记的 10% 阈值。

| | 结果 |
| :-- | :-- |
| **覆盖侧** | `hit@1` **355/588 = 60.4%**（v37 46.6%，+13.8pp）｜`hit@3` **70.9%**｜`hit@all` **48.5%** |
| **算力** | output token 9.91M → **17.44M（1.76×）**；每百万 token 命中位 27.6 → **20.4（−26%）** |
| **多报侧** | 288 条目 / 124 处不同内容；**净增量 2 条**（其一与台账记录部分交叠） |
| **最大成分** | 按条目计 **134（46.5%）** 不是**被评审制品**的缺陷，是我们自己的编译损失；**按去重计则为 30（24.2%）**，去重后最大的是断言侧过度规定（67，54.0%） |
| **最要紧的保留** | `hit@k` 只能作为**上界**读，真实下界未知 |

三句可以直接进论文的话（**【AI 衍生建议】**，措辞待定）：

1. 方法在一个已知不完整的分母上取得 60.4% 的单轮覆盖率。⛔ **但算力同时涨了 1.76×、
   单位算力命中效率降了 26%——`+13.8pp` 不能整体归因于方法改进。**
2. 未被台账认领的产出里，**按条目计**占比最大的一块归因于评审入口本身：断言锚在编译产物上，
   而作者在源制品里已逐字写过。**按去重计**则是断言侧过度规定最大。两个口径不矛盾，
   差异来自编译损失被反复重述（条目/去重比 4.47 vs 1.78）；**只报一套会得出错误的整改优先级。**
3. 相对台账的净增量只有 2 条，且两条本身都不稳定（2/6 与 3/6）。方法当前的价值不在
   「找到台账外的新缺陷」，而在「把台账内的缺陷**成规模地**覆盖出来」（`hit@3` 70.9%）
   ——**稳定性（`hit@all` 48.5%）仍是待改进项**。

⛔ **能力与稳定性是两个独立问题，且体量相当**：23 条记录零命中（能力缺口）、
25 条落在 1–4/6（稳定性缺口）。两者都要处理，优先级见 §五。

## 关键术语

本文自包含所需的全部术语。**「模型」一词在本文中不使用**——两侧各有专名：

| 术语 | 定义 |
| :-- | :-- |
| **制品** / 被评审制品 | 被检查的那个状态机，即 `<NL, STM_0>` 中的 `STM_0`。它是**被测对象** |
| **评审侧** / 检测器 | 我们的流水线（LLM + 谓词求值），它读制品并发布 issue。它是**被度量的方法** |
| **作者源** | 制品的原始 PlantUML（路径见本节末）。**判缺陷读它** |
| **编译产物** / IR | 作者源经 R4.5 编译得到的 `model.fcstm`，谓词在它上面求值。**它不是判缺陷的依据** |
| **pair** | 一份 `<NL, STM_0>`，四位编号如 `0010` |
| **臂** | 一个 LLM profile（`claude-opus-4-7` 或 `gpt-5.5`） |
| **格** | 一次运行单元 = (pair, 臂, 轮)。全网格 54 × 2 × 3 = 324 格 |
| **台账** | 预期缺陷总账，人工构建的缺陷真值集。它是**能力分母** |
| **判定位** | (台账记录, 臂, 轮) 三元组，共 588 个。每位判 1（命中）或 0 |
| **义务** | 从 NL 句子或形式化本身推出的一条「制品应当满足什么」的要求 |
| **primary 谓词** | 一条台账记录用来判定的主谓词，取自 19 个封闭谓词词表 |
| **同质簇** | 多报侧的第一层合并：**同一条 issue 在 6 个格里的重复出现**合并为一簇。所以「簇出现在 6 格中的几格」是有意义的量（§3.6 用的就是它） |
| **条目 / 去重** | **条目** = 簇数（288）。**去重** = 不同 `merge_key` 数（124），`merge_key` = `(pair, 根因)`——它是第二层合并：**同一 pair 内、根因相同的不同簇**再并为一处。两层合并的对象不同，这正是两套分母存在的原因 |
| **`def`** | FCSTM 的变量声明关键字。路由变量 `R45RouteToken` 是编译器注入的，不是作者写的 |

三个指标各回答一个不同的问题：

| 指标 | 定义 | 回答什么 |
| :-- | :-- | :-- |
| `hit@1` | 命中位数 / 588 | **一次运行的期望产出** |
| `hit@3` | 三轮中至少命中一次的 (记录, 臂) 数 / 196 | **该缺陷是否在能力范围内** |
| `hit@all` | 三轮全部命中的 (记录, 臂) 数 / 196 | **稳定性** |

`hit@3` 高而 `hit@all` 低 = 能力够、稳定性不足；两者都低才是能力问题。

台账记录的四个 `layer`：`nl_named`（NL 点名了缺失/错位的元素）、
`nl_contradiction`（制品与 NL 直接冲突）、`wellformedness`（合式性缺陷，
不从任何 NL 句子推出，须看制品本身）、`over_specification`（制品比 NL 多要求了东西）。

制品文件位置：`paper_stm_repair/selected_seed_examples/llms_emp_feedback_final_<pair>/`
下的 `stm0.puml`（作者源）、`model.fcstm`（编译产物）、`fcstm_meta.json`（编译债务码）。

## 二、覆盖侧（expected issue）

### 2.1 整体结果

| 口径 | v37 | **v46** | 差 |
| :-- | --: | --: | --: |
| `hit@1`（单轮命中率） | 274/588 = 46.6% | **355/588 = 60.4%** | **+13.8pp** |
| `hit@3`（三轮至少一次） | 106/196 = 54.1% | **139/196 = 70.9%** | **+16.8pp** |
| `hit@all`（三轮全中） | 77/196 = 39.3% | **95/196 = 48.5%** | **+9.2pp** |
| claude `hit@1` | 132/294 = 44.9% | 184/294 = 62.6% | +17.7pp |
| gpt `hit@1` | 142/294 = 48.3% | 171/294 = 58.2% | +9.9pp |

**算力对照（必须与上表同读）**：

| | v37 | v46 |
| :-- | --: | --: |
| output token | 9.91M | **17.44M（1.76×）** |
| 节点耗时 | 50.8 机时 | 88.4 机时 |
| 每百万 output token 命中位 | 27.6 | **20.4（−26%）** |

📌 **口径**：分子是本网格的命中位 355，分母是本网格的 output token 17,444,117
（逐条 LLM 调用记录求和），**分子分母同源**。

⛔ **单位算力的命中效率是下降的。** `+13.8pp` 有相当部分是多花算力换来的，
不能整体记到方法改进头上；本代次也没有做逐项消融。

**采样噪声底**：逐轮 `hit@1` 为 59.2% / 60.7% / 61.2%，三轮极差 2.0pp。
+13.8pp 远大于代次内可观察到的轮间离散，因此不太可能由轮间采样波动单独解释；
但 `n = 3` 且未计入 NL 族聚类那一层，**这不是一个方差检验**。

### 2.2 ⛔ `hit@k` 是上界，不是点估计

命中侧尚未做与多报侧对称的表示债务审计。已量化的扣除项：

| 扣除 | `hit@1` |
| :-- | --: |
| 报告值 | 355/588 = **60.4%** |
| 扣掉仅靠「变量未声明」成立的 10 位 | 345/588 = 58.7% |
| 扣掉引用了「变量未声明」的全部 51 位 | 304/588 = 51.7% |

理由：PlantUML **无变量声明语法**，作者变量在全语料为 **0/60**，因此
`variable_declared` 的 `False` 在本语料上**不具判别力**——它对缺陷模型与忠实模型同样为假。
355 个命中位中 **51 位（14.4%）** 在判据里引用了它，其中 **10 位（2.8%）** 不依赖其它事实。
这 51 位**全部落在 588 分母内**，故上表的 345 与 304 与 355 同源。

📌 **355 的构成**：人工判定表共 574 条，其中 346 条判为命中；这 346 条里有 6 条属被剔出分母的
`EIS-0043-02`，故**分母内带逐位判据的命中 340 条**；另有 **15 个命中位无人工条目**（§2.3）。
`340 + 15 = 355`。上界筛查只覆盖那 340 条，所以 51 是下界。
⚠️ 另有 15 个命中位无逐位 `argument`（§2.3），**从未被这套筛查覆盖**，因此 51 是下界。
**第二条通道尚未量化**：谓词拒答时的文案会进入生成者下一轮的上下文。实例：`predicate_api.py:1524` 的 `UnsupportedEvidence` 原文
「`variable 'uav_count' is not observable in the simulation state. If the NL requires a
quantity this model has no variable for, **assert that variable's existence as a
`precondition`** and make this assertion depend on it.`」出现在 `run1/0006-claude` 的
`findings` 里，而 `EIS-0006-02` 是 6/6。它交出的不是元素名（那是生产者自己先绑的），是**极性**与
**「把它发布出去」的指示**。

**因此可写的只有 `hit@1 ≤ 60.4%`，真实下界未知。**

⚠️ **本文其余各处仍以 60.4% 作为标称值书写**（表格、分层、对比），这是为了让各处口径一致、
便于交叉核对。**但凡对外表述，一律带上界符号**：论文里不得出现不带 ≤ 的 60.4%。

### 2.3 判定覆盖的缺口

588 位中 **20 位**有机器判定、但人工判定表里没有逐位 `argument`（其中 15 位判为命中、
5 位未命中），**不可逐格复核**。

⛔ 这不是一条孤立的记录：那 15 个不可复核的命中位**计入了 355**，因此它是 §2.2
「只能作上界读」的第三个来源。

### 2.4 分层分析

#### 按层（`layer`）

| 层 | 记录 | `hit@1` | `hit@3` | `hit@all` |
| :-- | --: | --: | --: | --: |
| `nl_named`（NL 点名了缺失/错位元素） | 52 | **70.5%** | 80.8% | 59.6% |
| `nl_contradiction` | 13 | 51.3% | 69.2% | 34.6% |
| `wellformedness`（合式性） | 27 | **48.1%** | 57.4% | 35.2% |
| `over_specification` | 6 | 47.2% | 50.0% | 41.7% |

**学术结论【AI 衍生建议】**：`nl_named` 与 `wellformedness` 的 `hit@1` 相差 **22.4pp**，
量级远超全局轮间极差（2.0pp）；但**分层样本量只有 6–52 条，未单独估计层内方差**，
所以这是一个强提示而非检验结论。一个可能的机制是——**当前流水线是 NL 驱动的**：从 NL 句子形成义务，再落成断言。NL 点了名的缺陷
自然能形成义务；而合式性缺陷（命名作用域塌缩、缺省入口、不可达）**不是从任何 NL 句子推出来的**，
它们要靠看模型本身发现。这条流水线只有 NL 驱动一个入口，于是制品侧缺陷系统性偏弱。

⚠️ **但这个机制与同节谓词表的解释在本数据上不可分离**：谓词表下方说 `reaches` 低是因为
「它承载的那类缺陷本身难」，而 `reaches` 正是合式性层的主力谓词。「缺少制品驱动入口」与
「合式性缺陷本身更难」共用同一批数据，**两者当前无法区分**。

能分离它们的实验是明确的：**加装制品驱动巡检入口后重测该层**——这同时也是 §5.1 第一条
建议的验证判据。

#### 按 $M$ 元素

| 元素 | 记录 | `hit@1` |
| :-- | --: | --: |
| `E`（事件） | 6 | 77.8% |
| `S`（状态） | 26 | 72.4% |
| `A`（动作） | 18 | 67.6% |
| `Tr`（迁移） | 45 | **51.9%** |
| `V`（变量） | 2 | **8.3%** |

`Tr` 是最大的一类（45/98）也是偏弱的一类。`V` 只有 2 条且几乎全灭——与 §2.2 同源：
PlantUML 无变量声明语法，变量类义务在这条链上本就难以成立。

#### 按 primary 谓词

## 三、多报侧（unexpected issue）

### 3.1 这一侧在问什么

模型发布的 issue 里，**未被任何台账记录认领**的那些，是什么？
朴素读法是「误报」。但逐条读完之后，这个读法是错的。

全部 304 个同质簇的去向：

| 去向 | 条数 | 含义 |
| :-- | --: | :-- |
| 桶内（多报侧分母） | **288** | 下面五类裁定的对象 |
| 台账已承载 | 14 | 内容已被现有台账记录覆盖，按定义不属意外发现 |
| 真阴性 | 2 | 断言在冻结制品上求值为 True——模型满足义务，正确地不产出 issue |
| **合计** | **304** | 闭合由生成器断言，对不上即拒绝重建 |

### 3.2 五类裁定：定义

| 类 | 定义 | 关键判据 |
| :-- | :-- | :-- |
| ✅ **真漏记** `VALID_UNRECORDED` | 事实为真、作者源确实没写、义务有出处、台账未记 | 四条**全中**才算 |
| ⚙️ **表示债务** `REPRESENTATION_DEBT` | 事实为真，但**作者在 `stm0.puml` 里已经写了**，是 PlantUML → FCSTM 编译丢的 | 必须回读作者源并给行号 |
| 📄 **无 NL 依据** `NO_NL_BASIS` | 事实为真、作者也确实没写，但 **NL 没有要求它** | 属过度规定 |
| ❌ **假阳性** `FALSE_POSITIVE` | **事实为假**——主张与制品相反 | 与「无 NL 依据」的唯一分界就是事实真假 |
| 🚫 **越界** `OUT_OF_SCOPE` | 主张的对象超出 $M = (S, E, V, Tr, A)$ | 时钟、不变式、正交区并发 |

⛔ **没有第六类，也不设「待定」**——证据不足就去取，不构成裁定类别。

### 3.3 判定链路

判定必须**按顺序短路**，颠倒会系统性判错。每一步排在那个位置都有理由：

```
零步：内容是否已被现有台账记录承载？
      → 是：不属意外发现，移出桶（14 条）

①   事实在 model.fcstm 上客观为真吗（含 action，须读全文）？
      → 否：❌ 假阳性
      ▸ 排第一：事实为假时，后面所有问题都没有意义

②   主张的对象在 M = (S, E, V, Tr, A) 内吗？
      → 否：🚫 越界
      ▸ 排在 ③ 前：越界主张不必再去回读作者源

③   作者在 stm0.puml 里表达过这个义务吗（不只是名字不同，是有没有写）？
      → 是：⚙️ 表示债务   ← 必须给作者源行号
      ▸ 排在 ⑤ 前：作者写过，就不必再问 NL 有没有依据
      ▸ 这是最容易被跳过、代价也最大的一步——跳过它，编译损失会被整批记成制品缺陷

④   同一缺口是否已由本 pair 另一簇以正确范畴承载？
      → 是：📄 无 NL 依据
      ▸ 排在 ⑤ 前：已有正确表述时，换个范畴再报一次不构成新发现

⑤   NL 有依据吗？（按层选来源：NL 层主张要逐字 NL；合式性主张的义务来自形式化本身）
      → 否：📄 无 NL 依据
      → 是：✅ 真漏记
```

**`0014-4`（2/6 格）**
`EmergencyStopping` 的状态名被编译成 `EmergencyStopping\n[PlantUML body] Obstacle Detected`

所以 `0036` 落债务而 `0014-4` 落真漏记。

**`0010-2`（3/6 格）**
接管迁移只挂在一个子态上（`model.fcstm:17/18` 的 `AutonomousActive -> HumanDriving`）。
而 `Autonomous`（`:9`）本身是可被占据的叶态，`AutonomousIdle`（`:10`）也不消费该事件。

brake pressed, in (auto final)`——⚠️ 句末确有 `in (auto final)`，引用时不得截断。

裁定成立的依据是把三项读作**并列的触发条件**而非作用域限定：同 NL 组的 `0040:12` 与
`0050:17` 分别把它写成 `||` 与 `or`，即作者自己就把第三项当成第三个析取触发。按这个读法，
该句未对接管迁移施加源态限定；参考模型也挂在模式一级，同 NL 组 6 个作者里有 4 个
（`0000:13`、`0030:16`、`0040:12`、`0050:17`）挂在模式一级——这是该 NL 的通行读法。

⚠️ 若改读作「仅在 auto final 时接管」，本条不成立。**该读法之争应在论文里写明**，
不能只呈现有利的一侧。

⚠️ **两点必须一起说**：
1. `0010-2` 与 `EIS-0010-04` 在 `AutonomousFinal` 那一半上有交叠，论文若引本条，
   净增量应只记 `Autonomous` + `AutonomousIdle` 那一半。
2. **两条净增量本身都不稳定**（2/6 与 3/6）。也就是说，全部净增量都落在
   「偶尔能发现」而非「稳定能发现」的区间里。

### 3.6 稳定性

**174/288（60%）的簇只出现在 6 格中的 1 格**，多报的长尾以单次采样噪声为主。

⚠️ 但**重复的那部分不是均匀分布的**：它几乎全部集中在表示债务（条目/去重比 4.47，
对比无 NL 依据 1.78）。也就是说，长尾是噪声，而反复出现的那一小撮是**系统性的编译损失**。

| 相对台账的净增量是 2 条 | 288 条目过四条判据 | 中，两条中一条部分交叠，且两条都只有 2/6 与 3/6 |

### 4.2 「表示债务」这个构造是本轮最有价值的产出

⚠️ **现象本身不是新的。** 既有文献已有名字：CEGAR 的 spurious counterexample [1]、
program representation fault [2]、MDE 的 semantics preservation / state machine flattening [3]。
术语 *representation debt* 本身检索未见占用，但**不应把现象当作新发现**。

本轮的新处只在一件事上：**把它做成评测归因侧的可扣除量**——从一句 threats 段落，
变成给定一条评审链、一个语料、一个检测器就能算出的比例。

三点限定（不写会被误读）：它不是过近似（under-approximation）造成的伪反例；
不是工具 bug；落点在**评测归因**这一环，不在建模或验证环节。

论文里应当主张的是**审查动作**，不是这个具体数字——
「一条链、一个语料、一个检测器」的测量不宜外推。

### 4.3 必须一起说的五条局限

1. **`hit@k` 是上界**（§2.2），命中侧的对称审计未做。
2. **54 个 pair 不是 54 个独立样本**，是 9 份 NL × 6 份制品；族间离散度大，
   报到 0.1pp 不代表该精度。
3. **两代基线的判定构成不同质**，且 v37 未做多报侧裁定，两代 precision 不可比。
4. **判定层本身是独立误差源**：588 个判定位与 288 个簇全部由单一判定者人工裁定，
   **无第二判定者、无一致性系数**（Cohen $\kappa$ 一类）；多报侧第 ③ 步按定义不可机械复核。
5. **20 位不可逐格复核**（§2.3），其中 15 个命中位计入了 355。

## 五、对后续工作的约束【AI 衍生建议】

本节全部为基于上述测量的执行建议，**未经导师确认**。

### 5.1 应做

- **补一条制品驱动的巡检入口**。§2.4 与 §2.5 是同一份数据的两个切面（因此不是独立佐证），但两者在同一方向上收敛：
  合式性层弱 22.4pp、零命中的 23 条集中在合式性谓词上，而当前流水线只有 NL 驱动一个入口。
- **收断言侧的过度规定**。去重后占比最大的是 `NO_NL_BASIS`（54.0%），
  且 `N-SPLIT` / `N-CTX` / `N-FORM` 三个子类合计 67 条目——都是 prompt 侧可收敛的。
- **降低方差**。25 条记录处在「能找到但找不稳」，`hit@3` 与 `hit@all` 差 22.4pp。
- **收需求集规模**。中位 15 条、**最大 99**；按末次修订计超 60 条的 13 格里 **4 格降级，
  且全部落在 gpt 臂**。`convert_assertions` 与 `split_requirements` 合计占节点耗时 88.1%，
  且随需求条数线性增长——这既是算力涨 1.76× 的主因，也是降级的主要来源。

### 5.2 暂缓

- **不要据 §2.4 的谓词表做词表选型**。谓词与缺陷类型共线，要做必须先做消融。
- **不要把净增量 2 条当作方法的卖点**。当前价值在稳定覆盖台账内缺陷，不在扩充台账。

### 5.3 不要做

- 不要在报告里只给一套多报侧分母（§3.4）。**理由**：两套分母给出不同的主要矛盾，
  只报一套会把整改资源投到错误的地方。
- 不要把 `hit@k` 写成点估计或区间估计（§2.2）。**理由**：已知扣除项只给出上界方向，
  下界取决于尚未做的对称审计，写成区间等于宣称了一个并不掌握的下界。
