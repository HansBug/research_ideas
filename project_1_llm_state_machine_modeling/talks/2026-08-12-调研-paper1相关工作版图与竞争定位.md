## 3. ⭐⭐ 最重要的一件事：唯一的竞争者，以及它比预想的更硬

### 3.1 它是谁

**MCeT**（Ahmed, Song, Chen, Wei, Zheng；**MODELS 2025**, pp. 84–95；DOI `10.1109/MODELS67397.2025.00014`）。⭐ **本轮读了全文。**

**它做的事与本文逐项对应**：输入 = 需求文档 + **一份别人给的**行为模型 → 需求切成 atomic items、图切成 atomic interactions → **双向逐条比对** → 输出 issue 列表，每条锚回需求原子。

⛔ **差别不在任务上，在制品上**（它是 UML 序列图）。

### 3.2 ⛔ 它自称 first，⚠️ 而且说了四遍、限定词逐级脱落到零

| 位置 | 逐字原文 | 限定词 |
| :-- | :-- | :-- |
| Abstract | `we propose MCeT, the first fully automated tool to evaluate the correctness of a behavioral model, sequence diagrams in particular, against its corresponding requirements text` | ⛔ 无 LLM-based；⚠️ 有软化语 "in particular" |
| §I 引言 | `MCeT is the first LLM-based approach to evaluate a behavioral diagram model against free-style requirements texts` | ⭐ 四个 |
| §I 贡献 (1) | `We propose the first automated behavioral model evaluation approach…` | ⛔ 丢 LLM-based |
| ⛔⛔ **§IX 结论** | `To the best of our knowledge, MCeT is the first approach to perform fully automated evaluation of a behavioral model against its requirements.` | ⛔⛔ **一个都没有** |

⚠️ **结论节那一版没有任何限定，而结论恰是审稿人与后续引用者最常摘的位置。**

### 3.3 ⛔ 「我们的制品不同」这条防线，被它自己的文本掏空

| 逐字原文 | 位置 | 后果 |
| :-- | :-- | :-- |
| `In our current approach, we process sequence diagrams in PlantUML, however, the technique can be easily adapted to process any other modeling language.` | §III | ⛔ **作者自陈技术可轻易适配任何建模语言** |
| behavioral diagram 的定义含 **state changes** 与 **responses to external events** | §I | ⚠️ **状态机落在它自己的定义之内** |
| `we aim to expand our study into other types of behavioral models as part of our future work` | §VII | ⚠️⛔ **本文要做的事，被它在正文里点名为 future work** |

### 3.4 ⭐ 唯一真实的挡板，⛔ 但它是对冲不是收回

§VII External Validity 自陈 `our approach may not generalize to other types of behavioral models`。⚠️ 那是对**实验外部效度**的对冲，⛔ **不是对首创主张的收回**，⚠️ 且它与「易于适配」在同一篇里互相矛盾 —— ⛔ 引用它等于把两句话一起端上桌。

### 3.5 ⭐ 我们与它的真实差别只剩三条

| 差别 | MCeT | 本文 |
| :-- | :-- | :-- |
| **制品** | UML 序列图 | 状态机 $M = (S,E,V,Tr,A)$ |
| ⭐ **裁决怎么来** | ⛔ **LLM 自报的 Yes/No**（有 JSON 信封与 atom 定位，⚠️ **不是散文**），真伪再由**两名论文作者**人工判定（$\kappa = 0.79$） | ⭐ **断言在制品上求值** |
| ⭐ **可否重放** | ⛔ prompts / 源码 / 输入 / 人工真值（散文态）已公开，⚠️ **但「135 条离散 issue 的切分」与「两名作者的逐条判定」都没公开** → 第三方可**重跑**，⛔ **不能独立复算任何一条 issue 的真伪** | ⭐ 断言可由第三方在制品上独立复算 |

⚠️ **一条必须知道的细节**：MCeT 的召回分母 **135 全文没印**，只能由三个百分比反推（`46/0.341 = 134.9`、`92/0.681 = 135.1`、`88/0.652 = 135.0`）。⭐ 而且这不是偶然遗漏 —— 它的第二个分母（14）同样只能反推。⛔ **该篇的体例就是只印分子与百分比。**

### 3.6 ⛔ 这意味着什么

⭐ **C-① 的新颖性强度上限是「与既有工作不同」** —— ⛔ 本轮覆盖范围内不支持更高档位。⚠️ 而按结论节那一版读，**连这个上限都可能偏高**。

⚠️ **注意区分两种强度**：⭐ **有效性强度**（我们的方法效果如何）⛔ **文献永远给不出它** —— 它由 X1 自建对照回答。⛔ 不得用 L1 的新颖性结论去顶替有效性强度。

## 5. Q2 · NL ↔ 已有模型的一致性检查 —— ⭐ 界内 0 篇

判据是两问：① 输入里有一份**别人给的**模型？② 输出锚在**需求条目**上？

### 5.1 ⭐ 两问全中的只有 2 篇，⛔ 都在邻域

| 篇目 | 制品 | 它怎么做的 |
| :-- | :-- | :-- |
| **MCeT**（MODELS 2025） | ⚠️ UML 序列图 | 见 §3 |
| **Requirements Satisfiability with In-Context Learning**（RE 2024，DOI `10.1109/RE59067.2024.00025`） | ⚠️ 文本化的 design practice 清单 | 逐条对 **8 条 GDPR 需求**给满足 / 不满足判定，用「需求取反」提升不满足侧 |

### 5.2 ⭐⭐ 离界内最近的一篇，⛔ 但它不是检查侧

**`Completion of SysML state machines from Given–When–Then requirements`**（SoSyM 23(6):1455–1491，DOI `10.1007/s10270-024-01228-3`）。⭐ **本轮读了全文。**

⭐ 它是本轮**唯一**「界内状态机 + 需求逐条可追溯**且把追溯物化成模型元素**」的工作 —— 用 SysML 标准 `«satisfy»` 关系从生成的迁移指向需求条目，另有独立追溯图承载，粒度一对一。⭐ **在「有没有证据链」这件事上，它比我们更「物化」**（追溯进了模型，不是外挂记录）。

⛔ **但它的 `«satisfy»` 只从「已生成的模型片段」指向需求** —— ⚠️ **失败的需求没有任何模型元素，因此没有链接、也没有任何反向记号**。⭐⭐ **那是一份成功清单，不是覆盖账。**

⭐⭐ **它是「带静默闸门的生成器」，⛔ 不是检查侧工作**（见 §7 的详细证据）。

### 5.3 ⭐ 两段式路线确凿存在且近年密集，⛔ 但「谁决定检查什么」几乎全是人写

⚠️ 所谓两段式 = 「NL 需求 → 形式化性质 / 结构化需求 → 对模型做模型检查」。

| 篇目 | 链路 | ⭐ 谁决定检查什么 |
| :-- | :-- | :-- |
| Identifying and fixing ambiguities（SoSyM 23(6)） | NL → FORM-L → 仿真 | 规则 + 人（⭐ **自陈不可全自动**） |
| Post-Hoc Formal Verification（RE 2024） | 人工形式化成契约 → 演绎验证 | **人写** |
| Spacecraft Operational Designs（MODELS 2023） | 工程师写性质 → 模型检查 | **人写** |
| PAT-Agent / Event-B Agent / CIR-CVN | NL → CSP# / Event-B / Petri → 检查 | LLM 自动，⛔ **多数界外** |
| **GWT 补全**（见 §5.2） | Gherkin 模式 → 需求方案知识库 → 三道检查后补全 | ⭐⭐ **预编的 pattern catalogue** |
| Dwyer 模式族 | 人从目录挑一条 + 填 placeholder | **人写**（目录只降低书写成本） |

⭐ **7 例中 4 例人写、2 例 LLM 自由生成、1 例预编目录。** ⛔ 本轮覆盖内**未见**「闭合谓词词表 + 对模型逐条机械求值」这一形状。

## 6. Q3 · `hit@1 ≤ 60.4%` 的外部参照系 —— ⛔ 0 条四门全中

四条门：① 在**已有模型**上找缺陷（非生成）· ② 对象是状态机类制品 · ③ 有 recall / coverage 数值 · ④ **口径可复现**（分母是什么、谁认定、是否人工植入）。

### 6.1 最像的几条，各缺哪一门

| 候选 | ① | ② | ③ | ④ | ⛔ 缺的那条为什么不能弥补 |
| :-- | :-: | :-: | :-: | :-: | :-- |
| **SoSyM 2026** graph 通道 | ✅ | ⛔ | ✅ | ⛔ | 见 §6.2 |
| **SoSyM 2026** LLM 通道 | ⚠️ | ⛔ | ⛔ | — | ⛔ **状态机图从未进入它的检测 prompt**（§5.1.3 逐字列出送进 LLM 的只有 spec + 用例图 + 块图；结果表也只有这两类行） |
| **MCeT** | ✅ | ⛔ | ✅ | ⚠️ | ⛔ 序列图与状态机**不共享缺陷分类学**（消息顺序 / 参与者缺失 vs 状态缺失 / 守卫错误 / 层次语义） |
| 生成侧组件级 P/R | ⛔ | ✅ | ✅ | ⚠️ | ⭐ **元素召回 ≠ 缺陷召回**（分子分母都是模型元素） |
| 人工检视实验（1996–2006） | ✅ | ⛔ | ✅ | ⚠️ | 对象（设计文档整体）· 执行者（人）· 年代 三重不同 |

### 6.2 ⭐⭐ SoSyM 2026 值得单独说 —— ⛔ 它曾被判为「四门字面全中」

**`On the consistency of state machines, use cases and block diagrams using dependency graphs and LLMs`**（Sultan, Apvrille, Coudert；**SoSyM 2026**；DOI `10.1007/s10270-026-01388-4`）。⭐ 本轮读了出版方全文 40 页。

⛔ **门② 不成立，两条互相独立的理由**：

1. ⭐ **形式主义本身越界。** Definition 3 逐字：`TransDescr is the set of transition descriptions d = ⟨after, guard, actions⟩ where: – after ∈ N constrains the delay before firing t.` ⭐⭐ **`after` 是迁移描述三元组的第一个分量，⛔ 不是可选注解** —— 每一条迁移都携带触发前的延迟约束。⚠️ 另有 send / receive 信号同步参与依赖边构造。
   - ⚠️ **这一条差点被漏掉**：顶层定义写的是「状态机图是一个有向图 $(S, T)$」，看起来干净；⛔ **时间约束藏在下一层的 `TransDescr` 里**。⭐⭐ **判形式主义必须展开到叶子。**
2. ⭐ **缺陷谓词落在跨视图对应关系上**，⛔ 不是状态机内部。

⛔ **门④ 也不成立，⭐ 而这条最硬**：结果表的 `Missing = 0` **没有配套的期望缺陷总数**，⛔ 论文从未事前列出该期望集有几条。⚠️ ⛔⛔ **而同一篇文档在评另一个通道时逐字写着**：

> `is subjective and time-consuming to exhaustively identify undetected inconsistencies, we have empirical evidence of their existence`

⭐⭐ **同一份文档里，「穷举未检出项」被认定为主观且不可行，却在另一张表上把 Missing 填成了 0。** ⛔ 这不是精度问题，是**分母不存在**：⚠️ 没有独立的期望缺陷清单，「0/23」与「0/未知」无法区分。

⚠️ 另有三条独立削弱：三个测试模型是**作者自造**（逐字 `These three models, we have designed`）· $n = 3$、单系统、单缺陷类 · 检测器是确定性图比较，⭐ **`@k` 这一维不存在**。

### 6.3 ⭐⭐ 三种「不可换算」—— ⛔ 各自独立，不是同一条的三种说法

⭐ 这是 Q3 最有价值的产出：**外部数字失效有三个互不相同的原因**。

| 不可换算 | 实例 | ⛔ 为什么不能弥补 |
| :-- | :-- | :-- |
| ⛔ **precision 不能反推 recall** | SoSyM LLM 通道逐字 `not false negatives`；另一篇硬件侧工作逐字 `because the real number of bugs is unknown, it is not possible to compute a proper Recall` | ⛔ 缺 FN 项，⚠️ 分母是**不同集合** |
| ⛔ **元素召回不是缺陷召回** | 生成侧的组件级 P/R（states F1 0.90 / guards 0.23 / actions 0.00） | ⭐ 一个能复现 90% 状态的生成器，对「这个模型里有哪些**错**」**一个字都没说** |
| ⛔ **相对差不是绝对覆盖** | 人工检视实验的「某读法比另一读法多检出 15.6% 已植入缺陷」 | ⛔ 两技术之比，⚠️ 不是任一技术的绝对覆盖率 |

⚠️ **三条各自的支撑都很薄**（分别 2 篇 / 1 篇 / 1 篇）。⭐ **类型**成立，⛔ 但**普遍性**没有分母支撑 —— ⛔ 不得写成「这是该任务族的结构性状况」。

### 6.4 ⭐ 这份「没找到」的真正用途

⛔ **它不用于主张空集、不用于主张首创、不用于论证 60.4% 足够好。**

⭐ 它回答一个具体质询：「**你们为什么不和已有工作比，而要自己造一个基线**」。⭐⭐ **而回答它的是那 16+ 条逐条筛除记录，⛔ 不是矩阵里那些 0** —— 每条候选缺哪一门、那一门为什么不能换算，才是答案。

⚠️ **合法的结论句式**（⛔ 后半句不得省略）：「**在本轮覆盖的 CCF A/B/C 与 arXiv 近年工作中，未见同时满足四条门的工作**」+ 覆盖范围声明。

## 7. Q4 · 闭合词表交给自动化 —— ⛔ 界内 0 篇

### 7.1 界内有什么

**(i) 性质规约模式目录：6 篇**（Dwyer 1998/1999 · PROPEL 2002 · Prospec 2003 · Autili TSE 2015 · Menghi TSE 2021）。

⭐⭐ **它们都不是「闭合词表交给自动化」，⛔ 原因很一致**：
- **集合闭不闭？** ⚠️ 至多算「有限」而非闭合 —— Menghi 明写 *not intended to be exhaustive or static*；另一份 2023 年的目录明写 *preliminary catalog*，⭐ 并自陈「几乎没有关于时序规约质量属性的既有定义」。
- ⭐⭐ **「给定一条义务，选哪个模式」由谁做？** —— ⛔ **一律是人**。PROPEL 用问题树引导人选、PSPWizard 用菜单、PsALM 用结构化英语，⭐ **自动化承担的是选完之后的公式实例化**。

**(ii) 标准化可执行语义 / 静态约束：5 项**（SCXML · PSSM · OCL · EVL · 一份 2023 年 CSUR 综述）。⛔ 它们根本不在回答「把一条义务映射成哪条断言」这个问题，⭐ 给的是**全量求值**的良构规则集。

### 7.2 ⭐⭐ 邻域的形状极像 —— ⛔ 但方向相反

⚠️ 硬件与代码侧近年有一片密集工作：受限词表断言生成 + 形式化反馈回路 + LLM（AutoSVA · AssertLLM · Spec2Assertion · AssertionForge · SpecAlign · ProofLoop · SpecGen · Daikon）。⛔ 制品是 RTL 或源代码，**界外**。

⭐⭐ **两条对本文直接有用**：

1. **邻域主流方向与本文相反。** ⭐ 一篇代码侧工作的摘要**明确**把「predefined templates or grammar 限制了表达真实行为」列为**要克服的局限** —— ⛔ 它们追**表达力**；⭐ 本文反向用**受限表达力换可判定性**。⚠️ ⛔ **这只是方向陈述，不得写成孰优孰劣**（无对照实验）。

### 9.1 ⭐⭐ Reinpold 值得单独警惕

⛔ **在「可机械求值」这条本文自认最硬的轴上，最近的对照系不是 MCeT，是它** —— 它的**真值侧就是机械求值的**。

### 9.2 ⭐ 外部量化背书
