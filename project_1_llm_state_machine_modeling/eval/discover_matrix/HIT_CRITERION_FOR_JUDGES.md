# 命中判据（交给判定者的版本 —— 实例全部合成，不含任何语料内容）

> ## 为什么有这个版本
>
> `HIT_CRITERION.md` 是判据的**维护版本**，它的四种形态各配一个**真实语料实例**（带 `EXP-` / `EIS-` /
> `ISSUE-` 标识符与真实状态名）。那些实例是判据最有用的部分 —— 抽象定义几乎无法据以判定，实例才划出
> 边界。
>
> **但实例必然来自往轮判定，因为判据本身就是从往轮争议里长出来的。** 于是维护版本**不能**交给判定者：
> v24 的公平性 review 查明它被两份指令承诺「不含任何分组信息」，而该承诺为假。
>
> 📌 **这不是「疏忽把答案写进了判据」，而是「判据的可用性依赖实例，而实例就是答案」。** 同一类泄漏漏了
> 三次，因为每次修的是「这个实例」，结构性张力一直在。
>
> 本文件的解法：**实例全部用合成占位名**（`Sys.*`），保留可用性、不携带答案。

## 1. 唯一裁决标准

判定的是**语义同一性**：两个命题是否说同一件事。**不看** family 标签、不看谓词名是否相同、不看元素名
是否字面重合。

## 2. 语义同一性成立的四种形态

| 形态 | 定义 | 合成例 |
| :-- | :-- | :-- |
| **① 直接对应** | 两个命题说同一件事，只是谓词不同 | 期望「该触发下只应一条迁移且目标是 `Sys.Ready`」；产出「该触发下到不了 `Sys.Ready`」—— 同一件事，一个从声明侧说、一个从运行侧说 |
| **② 合取项之一** | 期望命题是 `all(...)`，产出证明其中一个合取项为假 | 期望「两个模式都应有到终态的边」；产出「模式 A 那一半没有」 |
| **③ 负向命题的正向对偶** | 期望说「不应存在错的边」，产出说「应存在对的边」 | 期望 `not transition_exists(Sys.a, cond, Sys.Wrong)`；产出 `transition_exists(Sys.a, cond, Sys.Right)` 为假 |
| **④ 蕴含更根本的原因** | 产出命题为假**蕴含**期望命题为假，且定位到更上游 | 期望「该边应有变量 `Sys.n` 的下降效果」；产出「模型根本没声明 `Sys.n`」—— 无该变量则不可能有下降 |

## 3. 不成立的形态

| 形态 | 说明 | 合成例 |
| :-- | :-- | :-- |
| **不同缺陷共用状态名** | 元素重叠不是蕴含关系 | 一条关于 `Sys.Mode` **子状态计数**的发现，不算作关于 `Sys.Mode` **内某条迁移目标错误**的命中 |
| **更弱的命题** | 存在性不蕴含目标正确 | 期望「这条边的目标是 `Sys.X`」；产出只证明「`Sys.X` 存在」 |
| **反向蕴含** | 方向错了 | 期望命题为假**不**蕴含产出命题为假 |

## 4. 两条同等重要的告诫

- **形态 ④ 容易被误判为不命中** —— 产出定位到更上游的缺失元素时，它**仍然**蕴含期望命题。
- **四种形态同样容易被过度援引**，尤其 ③ 与 ④。**说不清「产出为假如何蕴含期望为假」这条逻辑链，就不要
  用 `hits:`。** 元素重叠、区域相同、都提到同一个名字，**都不是**蕴含关系。

## 5. 已知判据歧义：伪状态的**运行代理**式主张

闭词表无法把结构主张绑定到**瞬时伪状态**（junction / join / fork / choice）。产出方于是改用**下游可占据
后继**作运行代理。

**合成例**：期望是「应存在边 `Sys.a --e--> Sys.J`」（`Sys.J` 是伪状态）；产出说「从 `Sys.a` 触发 `e` 后
未到达 `Sys.J` 的下游后继 `Sys.b`」。

| 读法 | 判定 |
| :-- | :-- |
| **A：读它引用的 requirement** | 算命中（形态 ①） |
| **B：读断言的字面主张** | 不算（§3「更弱的命题」） |

**本轮按读法 B 判。** 两读法的数都会在报告里并列给出，所以你按 B 判不会使另一读法的信息丢失。

## 6. 终局判定保留给人

任何机械匹配器都会在「触及了正确元素却得出**相反**结论」上判错。若你对某条不确定，**在依据里写明不确定
的点**，不要为了给出一个标签而编一条蕴含链。

---

## ⛔ 本文件的维护纪律

1. **实例必须全部合成**（`Sys.*` 占位名）。新增实例时不得从语料复制。
2. **不得出现** `EIS-` / `EXP-` / `ISSUE-` / `PAIR-` 前缀，不得出现四位数字 pair 编号，不得出现语料里的
   真实状态名 / 事件名。
3. 维护版本 `HIT_CRITERION.md` 继续保留真实实例（它对维护者有用），但**永不进入判定者的必读清单**。
4. 两份文件的**原则部分必须同步**；若维护版本新增一条形态，本文件须同步补一个合成例。
