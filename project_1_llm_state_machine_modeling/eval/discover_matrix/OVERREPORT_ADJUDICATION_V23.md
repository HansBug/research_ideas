# 多报核验（v22 数据，82 个唯一命题）

## 为什么重做

已发布口径说「已发布 239 条，台账外 160 条」，而「160 条台账外」被读成方法的精度问题。上一代次
自查已标出两条缺陷：**约 97 条从未逐条核过 NL**，且**判未命中与判「有据额外」用了两套标准**。

本轮把 239 条按 `round_variance.py` 的签名去重为 **82 个唯一命题**，三批派独立

⚠️ **去重口径更正**：我写的是「按（谓词 + 具名元素集）」，实际有效的只有**元素集**这一个分量。
`_issue_signature` 的谓词分量是
`sorted(predicates)[0] if len(predicates) == 1 else None` —— **只在该 issue 恰好引用单一谓词的需求
时才有值**，而 82 个项的该字段**全是 `None`**（一条 issue 常合并多条需求，涉多个谓词）。

这不是函数缺陷，是我**误读了返回值语义**：文档写「The predicate and elements a published issue rests
on」，实现对多谓词情形返回 `None`；两者不矛盾，我按前者理解、按后者使用。

而 `_match` 的注释说明这个设计本就如此：**「Element overlap decides; the predicate only breaks
ties」** —— 谓词只是打破平局用的，不是身份主分量。所以「按元素集去重」并不比「按谓词+元素集」弱多少。

**82 这个计数与三分判定结果（53/12/17）不受影响**，受影响的是口径描述，以及**无法按谓词定向重核**
那 12 条 `boundary`（本想找出其中的 `occupancy_after` 项验证末帧伪影，因谓词字段为 `None` 而做不到）。

📌 教训：**把一个函数的返回值当成它文档所说的东西，而没验证实际取到了什么。** 验证成本是打印一个
字段。
核验者对着 **NL 原文 + 模型原文**做三分判定。

⚠️ 去重键最初我自己写了一个（锚在断言表达式的精确文本上），得 231 个唯一命题且 **0 个跨三轮复现** ——
后者本该立刻让我停下。改调已有的校准签名函数后得 82 个，其中 12 个三轮全现。**当去重结果显示「几乎
没有重复」时，先怀疑键。**

## 三批全量结果

| 类别 | part1 (28) | part2 (28) | part3 (26) | 合计 (82) | 占比 |
| :-- | --: | --: | --: | --: | --: |
| `grounded` | 17 | 21 | 15 | **53** | 64.6% |
| └ 其中实为**台账命中** | 15 | 21 | 12 | **48** | 58.5% |
| └ 真正台账外的新有据发现 | 2 | 0 | 3 | **5** | 6.1% |
| `boundary`（时钟 / 并发） | 8 | 2 | 2 | **12** | 14.6% |
| **`fabricated`（虚构）** | **3** | **5** | **9** | **17** | **20.7%** |

**82 条名义「多报」里，48 条（58.5%）根本不是多报** —— 它们精确指认了台账已记录的同一缺陷（同一模型
行、同一 NL 句）。真正的虚构 17 条 = 20.7%。

### 逐批虚构率差异（11% / 18% / 35%）的成因：pair 构成，不是核验者严格度

| pair | 命题 | 虚构 | 率 |
| :-- | --: | --: | --: |
| `0000` / `0006` / `0035` | 4 / 6 / 7 | 0 | **0%** |
| `0029` | 12 | 1 | 8.3% |
| `0018` | 20 | 3 | 15.0% |
| `0043` | 9 | 2 | 22.2% |
| `0048` | 3 | 1 | 33.3% |
| `0038` / `0047` | 10 / 5 | 4 / 2 | 40.0% |
| `0032` / `0050` | 3 / 3 | 2 / 2 | **66.7%** |

pair 间跨度 **0% → 67%**，远大于批间差异。两个跨批次的 pair 中 `0038` 给出 part2 50% vs part3 33%
（n=4 / n=6，同量级，不足以判定严格度不同）。所以 part3 的 35% 主要因为它拿到了高虚构率的那批 pair。

### ⚠️ 一个我自己的设计缺陷：批间零重叠，一致性无法计算

三批按 item 切分、**批间没有任何重叠 item**，所以核验者间一致性（Cohen $\kappa$）根本算不出来。

**我刚为覆盖侧做了全量盲判并算出 $\kappa = 0.883$，转头在多报侧就设计了一个无法算 $\kappa$ 的
方案。** 正确做法是留一部分重叠 item 分给两个核验者。

part3 的核验者自己也点出了内部不一致：「同一发现在另一轮的另一种表述我判了 `boundary`，两者归类不同
**完全来自措辞差异**，这本身值得复核」。这类分歧在有重叠设计下会被量化，现在只能作为已知风险记录。

## 这是同一个发现被三次触到

| 入口 | 结果 |
| :-- | :-- |
| 全量盲判 | 10 个位从「未命中」翻成「命中」 |
| 多报核验 part1 | 15 条从「多报」翻成「命中」 |
| 多报核验 part2 | 21 条从「多报」翻成「命中」 |

三个独立核验、三个不同入口，都指向**原分类系统性地把命中判成了「未命中 + 多报」**。根因就是上一代次
自查里的那条：同一批发现被两套标准判成相反结论。

## 我亲自裁定的一条：`OV054` 暴露真值歧义，不是虚构

核验者判它 `fabricated`，理由之一是「同一句 NL 在另一个 pair 的台账里是按顺序读法解释的」——
**那正是「用台账当 NL 的权威解释」，本仓库明令禁止的形态。**

读 NL 与模型原文后：

```
NL 11:  "In the Fork2 state, which is part of the Join2 substate, ..."
模型:    12: pseudo state Join2      ← 伪状态不能有子状态
         25: state Fork2             ← 声明在根层
         42: Join2 -> Fork2          ← 只是一条迁移
```

| 读法 | NL 11 的意思 | 该模型 |
| :-- | :-- | :-- |
| **顺序**（台账 `EIS-0018-02` 用的） | Join2 先进入 Fork2，再分出两支 | ✅ 满足 |
| **包含**（`prompts.py:17` 要求的） | Fork2 **在 Join2 之内** | ❌ 违反 |

`prompts.py:17` 原文：「substate、inside、within、**belongs to**、contains 这类措辞是结构义务…
**不得把一条到达某状态的迁移当作该状态被所需父状态包含的证明**」。「part of」与「belongs to」语义同一。

按包含读法，该发现事实正确，且它同时指出 `Join2` 是伪状态 —— 伪状态不能有子状态，所以包含要求在这个
模型里**结构性不可满足**。两半是逻辑相连的，不是两个独立主张。

**但我不判它 grounded**：那等于用管线自己的 prompt 规则去证成管线自己的发现，是自证。

**裁定：`ambiguous_ground_truth`（真值歧义）。** 同一句 NL 的两种读法分别被台账与管线 prompt 采用，
而这条歧义**同时影响两个 pair**。它需要外部裁定，不能由产出方或判定方单方面解决。

## 对目标另一半的影响

「没有太多太明显的 unexpected item」这半，在正确分类下：

## 一格把三条线索扣在一起：命中依据本身部分虚构

某可报 pair 的 gpt 格，本轮出 4 条 issue，全部是「缺失类」主张（缺三类检测事件、缺激活前上下文态）。
三条独立观察同时落在它身上：

| 观察 | 结论 |
| :-- | :-- |
| 全量盲判 | 该记录该臂原判三轮全 0 → **盲判三轮全 1**（形态 ③/④） |
| 多报核验 | 该 pair 虚构率 **40%**，其中两条被判虚构的正是「缺三类分类事件」 |
| 核验者理由 | NL 2 是三类碰撞的**析取**，模型用单一事件是忠实编码；要求拆三个是 NL 之外的追加约束 |

**同一批发现，覆盖侧判命中、多报侧判虚构。**

这不是矛盾 —— 两个问题不同：

- 覆盖侧问「它是否蕴含台账那条缺陷」→ **是**（无非活动态与检测事件，则条件激活不可能成立）
- 多报侧问「它对着 NL 站得住吗」→ **部分不站**（NL 没要求拆三个事件）

### 但它意味着一件要紧的事

**`hit@1` 91.7% 里有一部分是靠一条自身部分虚构的发现命中的。**

报告不能只报 91.7%，必须同时说明这一格的命中依据在多报侧被判为部分虚构。这是「覆盖与多报共用分子」
那条规则的实例 —— 而这次共用的**不是分类，是同一条发现文本**。

### 附带确认：该格的预算耗尽未影响可报记录

该格有 6 条 `revision_budget_exhausted` 缺口，但**全部锚在另一个 NL 句**（`NL-L003`），而该可报记录
依据的是 NL 第 2 句。所以预算耗尽是真实代价，但**不是**这条记录的代价。

这一条必须查而不能假设：若缺口恰好落在可报记录所依据的 NL 句上，`hit@1` 的分子就是被门挡出来的，
而不是被方法找出来的。

## ⚠️ C 级：划分本身不闭合 —— 至少 23 条 issue 被双计

发布后由第 6 步根因分析纠出，我独立复算确认。

### 事实

用仓库自己的**冻结机械匹配器**（`round_variance.py` 的 `_issue_signature` + `_match`，判定逻辑
早于 v21、不随判据变化）回溯 82 个多报项：

| 量 | 值 |
| :-- | --: |
| 多报项 | 82 |
| 机械匹配到某台账条目 | 25 |
| **其中该轮人工判定恰为 `1`（纯双计）** | **23 = 28.0%** |
| 机械匹配但人工判 `0`（覆盖侧偏严候选） | 2 |

实例：`OV001` 的 `claim_title` 与 `run1/0000-claude` 的一条 issue 逐字相同，该 issue 机械匹配到
`EIS-0000-01`，而 `EIS-0000-01[claude] = [1,1,1]`。

### 根因：两个匹配器切同一批 issue，无人检查是否同一刀

已发布的 `台账命中 79 / 台账外 160` 划分，覆盖侧用**人工判定表**、多报侧用**机械匹配的补集**。
两个不同的匹配器切同一批 239 条 issue，而 `metrics_at_k.validate()` 里**没有任何校验**确认
`hit-evidence ∩ 台账外 = ∅`。

`correctness_table.py` 与 `round_variance.py` 里的逐条 `if _match(...) else` 天然互斥穷尽 ——
**但发布数字不走那条路**，所以漏洞在两条路的接缝上。

### 与根因分析的数字差异

它报 39/82 = 47.6%，我复算得 **23/82 = 28.0%**。两个数指向同一个真问题，幅度差近一倍。
我按 `claim_title[:60]` 精确匹配、且只在该 pair-arm 的三轮内检索；它可能放宽了匹配范围。
**此处采用我能复算的那个**，差额需它给出逐条清单后才能裁定。

### 连带更正：三个入口不是同一个发现

本文件上文与已发布 comment 都写过「全量盲判 10 个位 / 多报 part1 15 条 / part2 21 条 —— 同一个
发现被三次触到」。**不成立**：

| 入口 | 实际性质 |
| :-- | :-- |
| 全量盲判 10 个位 | **覆盖侧漏判**（判定者偏严） |
| 多报侧的主体（23 条） | **划分错误（双计）** |

**两者修法不同**：双计要靠**单遍标注在结构上消除**（一次标注、两侧派生），漏判要靠**判定者与
指令质量**改善。合并叙述会导向错误的修法 —— 这是本轮「归因错误」的又一实例，且我此前把它当成
了本轮最强的三重独立确认。

### 修法（下一代次，不消耗 hold-out 资格）

判定单元改为 **(格, 轮)**，每个 item 含该 pair 全部台账条目 + 该格该轮**全部**已发布 issue
（带稳定 `issue_uid`）。判定者对**每一条 issue** 恰好给一个标签：

```
hits:<EIS-id> | grounded-extra | boundary | fabricated | duplicate-of:<issue_uid>
```

派生：覆盖侧 `H(记录,臂,轮) = 1 ⟺ 存在 issue 标 hits:<该记录>`；多报侧 `over@1` = `fabricated` 计数。

**这样不变量 1（`hit-evidence ∩ 台账外 = ∅`）靠构造成立，不靠检查。** 且同一份判据、同一批判定者
自动满足 —— 因为两侧不再是两个任务。
