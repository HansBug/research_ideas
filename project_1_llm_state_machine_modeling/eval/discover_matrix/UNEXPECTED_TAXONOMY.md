# 意外发现裁定分类学：五类的定义、判定标准与典型例子

**进入意外发现桶的产出，必须落入且只落入下面六类之一。没有第七类，也不设「待定」。**

## ⛔ 先做零步：这条产出真的属于意外发现吗？

**内容已被现有台账记录承载的产出，按定义就不是意外发现，根本不进这个桶。**

判据：台账中存在一条记录**与本条同根**——由同一处建模失误导致，哪怕表现面不同。
判「同根」的硬判据见下方专节。命中者移入
[unexpected_verdicts/ledger_accounted.jsonl](./unexpected_verdicts/ledger_accounted.jsonl)，
并在那里记录其 `disposition`（真漏配 / 冗余复述 / 同根但该格未建立记录 / 报的是已退役判据）。

⚠️ **这一步曾被错误地做成第六个裁定类别 `MERGE_INTO_LEDGER`。** 那是分类错误：
它回答的是「这条产出该不该在桶里」，与其余五类回答的「这条产出是什么」不是同一个问题，

### ⛔ 判「同根」的硬判据

> **在作者源 `stm0.puml` 上问：争议元素的存在是否完全依赖于台账所指的那条语句？**
> **仅被那一条引用（改它则元素消失）→ 同根；还被别的语句引用（改它元素仍在）→ 不同根。**

**机械判据**：`grep -c "\b<元素名>\b" stm0.puml`。

⚠️ **基准必须是作者源，不是 `model.fcstm`。** 「同根」问的是两条发现是不是同一处**建模失误**，
而建模失误发生在作者写字的地方。R4.5 下沉会把隐式状态**物化成独立声明**——
0037 的三个叶在 `model.fcstm:25-27` 有独立 `state` 行，但那是编译器加的，作者没写。

⚠️ **不要用「有没有独立 `state` 声明」当判据**，也**不要用「修复它能否同时消除本条」**——
前者在 `model.fcstm` 上恒为真，后者会误杀 [HIT_CRITERION.md](./HIT_CRITERION.md) §3 已认可的
「合取项之一」与「蕴含更根本的原因」（它们按定义就不会一修即消）。**要数引用次数。**

v46 的两个反向实例，同一判据、同一基准：

| | `0037-1` ✅ 同根（移出桶） | `0007-1` ❌ 不同根（留在桶里，判 `NO_NL_BASIS`） |
| :-- | :-- | :-- |
| 争议元素 | `FrontendCollision` 等三个死端叶 | `InitialState` |

⚠️ **该判据经过一次对抗性复核的攻击并存活**：复核员曾主张应以被测的 `model.fcstm` 为基准
（那里三叶有独立声明 → 不同根 → 翻转作废）。若改用编译产物基准，`0007` 的 `InitialState`
在 `stm0.puml` 里同样没有 `state` 行，两 pair 的判定会一起反转；
而按「引用次数」判则两者结论都不变。**判据的价值在于它对基准的选择不敏感地给出一致答案。**

⚠️ **移出桶 ≠ 该格记命中。** 那是独立的逐格判定，判据在
[HIT_CRITERION.md](./HIT_CRITERION.md)，与本分类学无关。v46 的 13 条里只有 1 条
（`0037-1`）对应格位原判未命中并被补回。

「待定」曾短暂存在过 5 条，全部因为判定者手里的证据包不含迁移表 / 动作块 / 比较符。
那不是判据不足，是**取证不足**。**证据不足不构成一个裁定类别**；取不到证据就去取，取到了就裁。

## 〇之一、⛔ 一切计数都必须给**两套分母**

> **条目数**（原始簇数）与**去重数**（去掉同质 / 趋同后的实际不同内容数）**必须同时报**。

**去重单元定义**：`(pair, 根因)`。同一个 pair 内、指向**同一处建模失误或同一处编译损失**的簇，
合并计为 1 个；**不同 pair 即使缺陷类型相同也不合并**——那是不同制品上的不同实例。

实现：每条簇带一个自解释的 `merge_key` 字段（如 `0029-零作者变量`、`0017-三碰撞检测塌缩`），
去重数 = 不同 `merge_key` 的个数。⛔ `merge_key` 不许用 `0029-A` 这类无意义编号。

**为什么这条是硬要求**：同一处缺陷会以不同谓词、不同命名、不同 roll-up 粒度反复产出。
只报条目数会把「一个缺陷被报了 12 次」读成「12 个缺陷」。实测：
`0029` 一个 pair 的 12 条变量类簇讲的是同一件事（该制品作者变量数为零）；
`VALID_UNRECORDED` 的 23 簇归并后只有 **4 条根因**——
**论文里能说的是 4，不是 23。**

⚠️ **条目/去重比本身是可分析的数据**，不只是修正因子。比值高有两种解释，必须分辨：
- **该缺陷天然会被多个谓词命中**（如「零变量」会让每个 `variable_declared` 断言都为假）
  —— 这是缺陷的属性，不是产出的毛病。
- **产出侧在重复报同一件事** —— 这是产出质量问题，应计入多报分析。

### ⛔ ③ 的子判据：合取 / 析取分岔（此前缺失，导致 22 个同形簇按判定组分裂）

事实为真、且作者源含该文本时，看**融合的逻辑连接词**：

| 作者写法 | 拆开是不是正确修法 | 落点 |
| :-- | :-- | :-- |
| **析取**（`\|` / `\|\|` / 散文 "or"） | 是——融合后无法只凭其一激活 | ⚙️ `REPRESENTATION_DEBT`（`D2`） |
| **合取**（`&` / `&&` / 散文 "and"） | 否——拆开会把 AND 变 OR | 📄 `NO_NL_BASIS`（`N4` / R-CONJ） |
| **`variable_declared` 族** | 不适用 | ⚙️ `REPRESENTATION_DEBT`（`D1`），**不受连接词影响**——PlantUML 无变量声明语法，与融合结构无关 |

**这条子判据优先于 ⑤。** 不写死它，同一份 NL 下六个制品的同形簇会按判定组分裂：
实测 0019/0039 判债务、0029/0049/0059 判无 NL 依据，而作者守卫写法**六份完全同形**。

⚠️ **⑤ 问的是「该 NL 义务」，不是「断言字面索要的那个元素」。** 两者不同：作者写了
`extra_lane=true`（NL 义务已表达），但没写名为 `extra_lane_true` 的事件（断言字面所求）。
按后者读会把几乎所有簇都判成「作者没写」。

**短路顺序是有意的**：⓪ 是否属本桶 → 事实 → **仪器** → 边界 → 范畴与去重 → 归属（作者 vs 编译）→ NL。
把归属放在范畴之前会漏掉 `N3`/`N4`；把 NL 放在归属之前会把编译债务混进 NL 判断——
两种颠倒都实际发生过。

## ✅ 1. `VALID_UNRECORDED` —— 真实的台账漏记

### 定义
事实在编译产物上为真，**且作者源本身就缺该元素**，**且 NL 有明确依据**，**且台账未记**。
这是**唯一**应当补进台账的类别，也是方法相对台账的净增量。

### 判定标准（四条全中）
1. 事实在 `model.fcstm` 上客观为真（含 action，须读全文）。
2. `stm0.puml` 里作者**没有**以任何形式表达该义务（不只是名字不同，是根本没写）。
3. `nl.txt` 有逐字依据，且该依据**不是**统称词 / 语境状语 / 语义注解。
4. `expected_issue_set.json` 中无任何记录覆盖同一缺陷（含换谓词、换说法的情形）。

### 加强判据（推荐做，能显著降低误判）
**查同 NL 组的其他 pair**：若多数作者把这件事写对了，说明它是该 NL 的通行读法而非过度指定。

### 典型例子

**`0017-1`（8 簇同源，该 pair 台账 0 条）**
> 事实：制品事件只有 `collision_detected` 与 `Collision_avoided`，NL 2 点名的三种具体检测一个都没有。
> 作者源 `stm0.puml:4,9,14` 三处都只写泛化的 `collision detected`——**作者本人塌缩了三种刺激**。
> NL：NL 2 逐字并列「a possible frontend collision, rear-end collision **or** collision with pedestrian is detected」。
> 加强判据：同一份 NL（md5 `a53ac335`）的 6 个作者里 **4 个**把三者写成可分刺激
> （0007、0037、0057 分立三事件，0027 显式析取）→ 可分是通行读法。

**`0023-7`（6 簇同源，台账 0 条）**
> 事实：`PumpControl` 内三个子状态之间**零迁移**，模型连一个 `event` 都没声明，无从触发子态切换。
> NL：NL 4 / NL 5 均以「can transition to」要求运行期可切换。
> ⚠️ 措辞刻意写成 **Tr/E 层**（`E=∅`、`V=∅`、非初始迁移数 = 0）。
> 若写成「三个并发区的默认入口」就依赖区语义，会按 R-REGION 落入 `OUT_OF_SCOPE`。

**`0014-4`（同族漏记）**
> 事实：`EmergencyStopping` 内无任何 `enter`/`during` 动作，NL 要求发出的信号被吞进状态名描述串。
> 作者源 `stm0.puml:26` 写 `EmergencyStopping: Obstacle Detected`——PlantUML **描述行**，不是动作。
> 对照 0054:18 作者写 `do/Send Obstacle Detected`、0004 写 `during abstract SendObstacleDetected`
> → 该输出动作在 M 内可表达且是参考意图，**作者用错了语法**。
> 台账：已记同族 `EIS-0014-03`（Emergency Stop）与 `EIS-0014-04`（Approaching 的 Send），
> 但前者 `nl_evidence` 只引「Emergency Stop」、后者 scope 是 `InMotion.Approaching`，**均不覆盖此条**。

## ⚙️ 2. `REPRESENTATION_DEBT` —— 我们自己编译链的信息损失

### 定义
事实在编译产物上为真，**但作者在 `stm0.puml` 里已逐字表达该义务**，失真发生在
R4.5 的 PlantUML → FCSTM 有损编译。**不是模型缺陷。**

完整论述见 [REPRESENTATION_DEBT.md](./REPRESENTATION_DEBT.md)；
融合事件的既定操作规则见 [FUSED_EVENT_POLICY.md](./FUSED_EVENT_POLICY.md) —— **「表示限制被如实记录、但记录本身不构成发现」**。

### 判定标准（三条全中）
1. 事实在 `model.fcstm` 上客观为真。
2. 该义务在 `stm0.puml` 上**已被作者逐字表达**（⚠️ 需人工逐行读，词法检索不可靠）。
3. `fcstm_meta.json` → `source_static_reason_codes` 有对应债务码。
   ⚠️ **这一条几乎没有判别力，不要靠它判**：`opaque_transition_label_semantics` 覆盖 **58/60**
   制品，且 `variable_declared` 类**没有专属债务码**只能挂靠它。它的作用是确认编译器
   **自申报**了该类损失，**判别力全在第 2 条**。（每码在两个数组各列一次，数制品数用
   `grep -l <code> */fcstm_meta.json | wc -l`。）

### 与「真漏记」的分界线
**只看第 2 条**：0036 的 `/ UAV Count Decreased` 作者写了 → 债务；
0006 的作者源里**连递减文本都没有** → 真缺陷。

### 五个子类：按**「丢失的是哪一条区分」**切

⛔ **划分维度是「源制品有、编译产物没有的那一条区分」，不是谓词族。**
谓词族、命名变体、roll-up 粒度**一律不参与判类**——它们是同一条损失的不同说法。
三个可检验的锚点：`0027-3/4/5` 是 `edge_declared` 却与 `0027-2` 同类；
`0029-24` 是 `variable_declared` 却入 `D1`；`0016-5/7` 是 `variable_declared` 却入 `D3`。

**按序走这四问，任一新簇即得唯一解**：

1. 损失在标签之外（状态 / 区域 / 初始被重写）？→ **`D4`**
2. 作者用 `/` 或 `[]` 分隔了刺激与非刺激内容、而编译器跨越了它？→ **`D3`**
3. 被指缺失的实体逐个归类，结果 ≥2 种（或含不由任何损失产生的分量）？→ **`D5`**
4. 被指串**恰为作者标签的一个完整析取支**？→ **`D1`**；是子部分 / 标签无析取 → **`D2`**

| 子类 | 丢失的区分 | 条目 | 去重 | 比值 | pair |
| :-- | :-- | --: | --: | --: | --: |
| `D1` 析取备选融合 | **备选之间的可分性**（`or` 被强化成 `and`） | 57 | 7 | **8.14** | 7 |
| `D2` 原子子表达式不可寻址 | **该量 / 该条件是一个可寻址的一等实体** | 49 | 11 | 4.45 | 11 |
| `D3` 槽位焊死 | **槽位角色**（哪段是触发、哪段是效果） | 18 | 4 | 4.50 | 4 |
| `D5` 跨通道打包 | 一簇同时跨 ≥2 个损失通道 | 4 | 4 | 1.00 | 4 |

| **合计** | | **129** | **27** | **4.78** | 17 |

⚠️ **27 个 key 里有 4 个是虚的**：`D5` 的 key 所指内容已被同 pair 的 `D1`/`D2` key 覆盖，
它们是同一批损失的**再打包**。**语料级真正不同的内容 = 23 处**（129 ÷ 23 = 5.6）。
论文若要说「这条链上有多少处编译损失被下游误记为模型缺陷」，该用 **23**。
构成：7 处析取标签融合 + 11 处作者量整体不可寻址 + 4 处槽位焊死 + 1 处结构注入。

**关键分界线**（各自都踩过坑，故写死）：

- **`D1` vs `D2`**：被指串**是不是一个完整析取支**。整支 → `D1`；子部分或标签无析取 → `D2`。
  例：`dist_to_rear<5 && vel>30` 整支缺失 = `D1`；其中的 `vel` 缺失 = `D2`。
- **`D2` vs `D3`**：量写在**守卫侧** → `D2`；写在 `/` **之后的效果槽** → `D3`。
  这是 `0009-12`（`vel`）与 `0046-6`（`uav_count`）虽同为 `variable_declared` 却分属两类的原因。
- **`D1` vs `D5`**：**打包本身不是入 `D5` 的理由，跨通道才是。** 四项全在同一条析取标签内
  （`0059-8`、`0039-6/19`）仍留 `D1`。
- ⚠️ **`D5` 不是兜底类**：入类要通过一个**正向计数测试**（枚举分量归类结果 ≥2 种），
  不是「其他都不像」。

⚠️ **本划分最脆弱的一处**：`dist_to_front<15` 在本批 pair 里出现两次——碰撞激活标签的第 3 析取支

（源判据里有三处专门加了「注意属另一条边」的警告）。这条线**不可从簇自身文本判定**，
必须回读 `stm0.puml` 那一行并确认它对应哪句 NL。受影响 ≤4 条（3.1%），
`D1` 的比值会在 8.14–8.71 间浮动，**结论不翻转**。

## 📄 3. `NO_NL_BASIS` —— 事实为真，但 NL 不要求

### 定义
事实在编译产物上为真，作者源确实没写，**但 NL 并不要求这件事**。属过度规定。

### 判定标准
1. 事实为真（否则是 `FALSE_POSITIVE`）。
2. 回到 `nl.txt` 逐句读，确认 NL **没有**提出该义务。
3. ⚠️ **重点排查四种误读**（见下六个子类）。

### 六个子类

**`N1` 命名字面主义（29 类）** —— 例 `0016-3`
> 把 NL 的**统称词 / 语境状语**当成必须存在的同名元素。
> 「During flight, if task assignment information is received」——`During flight` 是**状语背景**，
> 整台机器全程在飞行，NL 中不存在与之对立的非飞行上下文。要求一个名为 `Flight` 的状态属过度规定。
> 同类：`user_actions`（"based on user actions"）、`region`（"three region"）、`collision_avoidance_controls`。

**`N2` 相位过度指定（20 类）** —— 例 `0033-2`
> NL 只在**解释状态含义**，却被读成 `during`/`entry` 动作义务。
> 「where the pump is activated or controlled」是对子状态含义的说明，未规定必须以 `during` 相位实现；
> 模型另行声明了 `Activate_Pump` / `Pump_Deactivated` 承载该行为。
> 识别信号：NL 用 `indicating that…` / `where the … is …` 这类同位语或定语从句。

**`N4` 合取项被要求拆成独立事件（23 类）** —— 例 `0049-11`
> 判据不是「行为是否等价」，而是**这条断言若被采纳去修，修出来的对不对**：
> - NL 用 `or` 并列备选触发 → 融合后无法只凭其一激活 → **拆开是正确修法** → 成立。
> - NL 用 `and` 连接条件 → 拆成独立事件后任一个都能触发 → **把 AND 变成 OR，比现状更违反 NL**。
>
> 同一处的真实缺口按 M 的 `V` 计（NL 称之为 condition），**同一缺口只计一次**。

**`N3` 范畴错置（19 类）**
> 把变量当事件、把动作当事件。`dist_to_front` 是被比较的**量**不是信号；
> `Send` 是**输出动作**不是输入事件。

**`N0` 谓词操作化产生的义务（5 类）**
> 义务来自**谓词被操作化的方式**而非 NL。`0054-5` 是构造性不可满足——
> NL 2/10 恰恰**许可**该迁移，谓词却禁止它。按 [CLAUDE.md](../../../CLAUDE.md) §13 属
> 「多道门交集为空」类缺陷，**另案登记于
> [PREDICATE_DEFECTS_REGISTERED.md](./PREDICATE_DEFECTS_REGISTERED.md)**。
> ⚠️ 登记 ≠ 本轮修改：冻结的是**谓词词表**，`N0` 是**求值侧**的约束交集缺陷，两者范围不同。

**`N5` 断言锚在不存在的元素上（4 类）** —— 例 `0057-2`
> 制品里根本不存在名为 `Inactive` 的状态，因此「`Inactive --X--> CA` 这条边缺失」是
> **断言自造前提导致的空洞真**。NL 也未点名任何 `Inactive` 前置状态。
> 识别信号：断言的 scope 或 source 绑定到一个模型里查不到的路径。

## ❌ 4. `FALSE_POSITIVE` —— 元素其实存在

### 定义
断言所指的元素**其实存在**（哪怕名字不同字面、或以 `action` 形式存在），主张与制品相反。

### ⛔ 「存在」的硬定义（此前缺失，波及 156 簇的归属）

> **只有该元素在 `model.fcstm` 中作为一个独立的 `state` / `event` / `def` / `action`
> **声明**存在，才算存在。名字可以不同字面，可以是 `action`。**
>
> **仅出现在另一元素的 `named "..."` 显示串内部、或作为其标识符的子串——一律不算存在。**
> 此时事实为真，应走流程 ③ 之后的分支（多半是 `REPRESENTATION_DEBT` 或 `NO_NL_BASIS`）。
>
> **可执行判据**：能否写出一个引用它的合法 FCSTM 断言？
> `event_declared("...vel")` 写不出来 → `vel` 不存在。

**反例（曾按错误读法判过）**：`0009-12` 主张「`vel` 未声明为变量」。`vel` 字面确实出现在
`named "pedestrian_detected || (dist_to_rear<5 && vel>30) || …"` 里，但那只是显示串的子串，
**没有任何 `def vel`**。故事实为真 → 走债务分支（`D1`），**不是**假阳性。
若按「子串也算存在」读，整个 129 簇的 `REPRESENTATION_DEBT` 桶都会塌成假阳性。

### 判定标准
**事实为假**（按上面的硬定义）——这是与 `NO_NL_BASIS` 的唯一分界。

⛔ **不要把「事实为真但义务越界 / 已被政策许可」塞进本类。** 那会污染本类的语义，
而多报口径的成分划分依赖它。

### 四个子类

**`F2` 命名变体：元素已在，仅字面不同（16 类）** —— 例 `0057-6` / `0032-3`
> `0057-6`：断言要求 `possible_frontend_collision`，制品已声明 `Frontend_collision_detected`
> ——正是 NL 2 对应的独立检测事件，只是字面名不同。
> `0032-3`：断言要求 `accelerating`，制品已声明 `event Accelerate`；NL 3 用 `like` 举例，未规定精确拼写。
> ⚠️ 同一主张在不同 pair 上可能一真一假：0017 只有泛化 `collision_detected`（真漏记），
> 0057 已分立三事件（假阳性）。**命名类断言必须逐 pair 核对，不能按 NL 归并结论。**

**`F4` 作者源已表达，主张与制品相反（1 类，仅 `0049-10`——0009 全组已迁往表示债务）**
> 与 `REPRESENTATION_DEBT` 的差别：那类是「IR 上确实没有」，本类是「rationale 声称没有但其实有」。

**`F1` 元素以 `action` 存在，路径清单看不见（5 类）** —— 例 `0004-1`
> 制品有 `state Approaching { during abstract Send; }`——`Send` 已作为**动作**声明。
> 路径清单只列状态与事件、**不列动作**，据此判「未声明」必然出错。
> ⚠️ v46 因此翻转 5 条，其中 `0054-3` 由「真漏记」翻成假阳性。**涉及 A 元素的主张必须读原件全文。**

**`F3` 谓词锚点错置 / 未消费回退被误读成执行轨迹（2 类）**
> 触发只能锚在源态，断言却锚到了目标态。

## 🔧 5. `PREDICATE_ARTIFACT` —— 义务由谓词实现产生，不是被测对象的问题

### 定义
断言多出来的那条义务**写在谓词的实现代码里**，而不是写在断言的参数里。
**重设任何断言参数都无法消除它**；只能改谓词。

### 性质：它与其余五类**不同层**

其余五类回答「这条产出**说错了什么**」——锅在**断言构造侧**（怎么读 NL、选哪个元素种类、
绑哪个锚点、切什么粒度）。本类回答「**仪器坏了**」——锅在
`paper_stm_repair/pipeline/feedback_loop/src/paper_stm_feedback_loop/assertions/predicate_api.py`。

这个层次差有三个可操作的后果：

1. **它不该计入「过度规定率」。** 混进去会让那个数字同时度量两件事，论文里无法解释它衡量什么。
2. **它的修法不同。** 其余五类整改 prompt 与断言构造规范；本类必须改谓词实现。
3. ⛔ **留在 `NO_NL_BASIS` 里会被漏修。** 那个桶的结论是「已解释的非缺陷」，会随桶一起归档；
   而 `persists_until` 那类**恒假**谓词会污染此后**每一代次的每一格**。
   这与 `MERGE_INTO_LEDGER` 被移出意外发现桶是同一条理由：
   **一个回答「不同问题」的标签留在原桶里，代价是它永远得不到应有的处理。**

### 判定标准：参数重设实验（可机械执行）

> **问两句，任一为「是」即入本类：**
> 1. 是否**不存在任何**符合 NL 的模型能让该断言为真？（构造性不可满足）
> 2. 该义务是否写在**谓词的编码**里，而非断言的参数里？

**执行方式**：把断言的每个参数逐个替换成合理的备选值，看断言能否变真。
能 → 不是本类（多半是 `N-ANCHOR` 或 `N-MODAL`）；怎么换都不行 → 本类。

### 在判定流程中的位置：**第 ①.5 步，紧跟「事实是否成立」之后、「边界」之前**

理由是**它会伪装成其余各类**。`0044-2` 表面看是「把 `continuously` 误读成驻留不变式」
（像 `N-MODAL`），`0054-1` 表面看是「要求 NL 未规定的自环」（像 `N-FORM`）。
若不先做参数重设实验，它们会被归到断言构造侧，于是**谓词缺陷被记成了 prompt 问题**。

⚠️ 但它**排在「事实是否成立」之后**：若元素其实存在（`FALSE_POSITIVE`），
那连谓词都没跑到判义务这一步，先判事实。

### 与相邻类的分界线

| vs | 分界判据 |
| :-- | :-- |
| `N-ANCHOR` | 换锚点参数能否成立。`0026-3` 把作用域从子态提回复合态即成立 → `N-ANCHOR` |
| `N-MODAL` | 换 release 参数能否成立。`0046-8` 换个 release 就对了 → `N-MODAL` |
| `N-FORM` | 义务由**断言构造**提出（换个断言写法就没了）→ `N-FORM`；由**谓词编码**提出 → 本类 |
| `FALSE_POSITIVE` | 事实是否成立。元素其实存在 → 假阳性，不进本类 |

### 成员（3 条 / 3 去重 / 2 pair）

| 簇 | 谓词 | 为什么改参数没用 |
| :-- | :-- | :-- |
| `0044-2` | `persists_until` | 被编成覆盖整个 horizon 的有界不变式 `(release) \|\| active(state)`，**不是真正的 until**——release 达成后义务不解除，故**对任何有终止路径的模型恒为 False**，在**作者原件上同样不可满足** |
| `0054-5` | `persists_until` | `release=false` 构造性不可满足，对任何符合 NL 的模型必然为假 |
| `0054-1` | `stays_in` | 自环义务写在 `stays_in` 的操作化里（`if trigger not in self._consumed(view): return False`），非 NL 义务 |

⚠️ **`0054-1` 是三条里最弱的一条**：`0044-2` 与 `0054-5` 是**构造性不可满足**（不存在能通过的模型），
而 `0054-1` 只是把「驻留」操作化成了「必须显式消费 / 自环」——模型**确实可以**写自环，
所以它更像「谓词侧的 `N-FORM`」。三条一起归本类的依据是判据 2（义务写在编码里）对三条都成立；
若日后要收紧，可只保留构造性不可满足的两条。

⛔ **本类只登记不修**——谓词逻辑保持不动，详见
[PREDICATE_DEFECTS_REGISTERED.md](./PREDICATE_DEFECTS_REGISTERED.md)。

## 🚫 6. `OUT_OF_SCOPE` —— 在 M 边界外

### 定义
主张依赖**正交区并发语义**、**不变式**或**时钟**，落在 paper1 建模对象
`M = (S, E, V, Tr, A)` 之外。

### 判定标准
命中任意一条即越界：
1. 谓词族是 `invariant`，或主张要求多个状态**同时**保持活跃。
2. 主张的内容是「某复合态下恰好有 N 个**区**」。⚠️ **本条从属于下面的标准 4**——
   源内无 `--` 分隔符时不适用（例 `0037`：7 个子态是单区真实计数，保留在 M 内）。
3. 主张涉及时钟变量或状态不变式。
4. **R-REGION**：含正交区的制品上，`cardinality` 类主张在 M 内成立
   **当且仅当该违规在「区感知读法」下依然存活**——即不存在任何区分配使 NL 的计数 / 枚举义务被满足。
   若存在一个区恰好满足该义务，违规只在把区拍平成兄弟之后才出现，则越界。

**R-REGION 的机械判据**：`grep -cE "^[[:space:]]*--[[:space:]]*$" stm0.puml` 查分隔符数，
再看盈余是不是区拍平造成的。

### ⚠️ 边界是双向的
[CLAUDE.md](../../../CLAUDE.md) 明确：**不得**把并发 / 时间类问题记为方法未能检出，
也**不得**反过来声称这些模型没有并发 / 时间问题。论文的正确姿态是**双向缄默**。

### 典型例子

**`0027-6` —— invariant + 并发保持（双重越界）**
> 断言以 `invariant + active('ActiveState.BrakeControlState')` 等形式要求三个控制态**同时活跃**。
> 谓词族与并发语义两项都在建模对象之外。

**`0007-3` —— 区数量义务**
> 「`CollisionAvoidance` 下恰好三个区」。且按区计数制品**本已是三个非空区**，
> 「不是三个」只在把区换算成子状态时才成立。

**`0056-1` —— R-REGION 的判例**
> 作者源 `stm0.puml:10` 是正交区分隔符 `--`，`SearchState` 实为两区：
> `region0={Area1,Area2,Area3}`、`region1={NoIntercept,Intercepted}`。
> **NL 2 的「three different state areas」由 region 0 的三个 Area 兑现，义务在作者源上已满足**；
> `cardinality=5≠3` 只在 R4.5 拍平、跨区求和后才出现。

### R-REGION 的可证伪性（必须与结论同批披露）
该规则在**四处给出对方法不利的保留**，说明它不是为某一条现造的：

| pair | `--` 数 | 盈余来源 | 区感知读法下仍违规 | 裁定 |
| :-- | --: | :-- | :-- | :-- |
| 0037 | **0** | 单区复合态，7 个子态就是作者源的数 | 是 | **保留在 M 内** |
| 0002 | 2 | 游离的 `InitialState`，与区无关 | 是 | **保留在 M 内** |
| 0013 | 3 | NL 未枚举的克隆态 | 是 | **保留在 M 内** |
| 0007-1 | 3 | 顶层 `InitialState` + 臆造子树，纯层次 | 是 | **保留在 M 内** |
| 0007-3 | 3 | 区→子态换算 | 否 | 越界 |
| 0056-1 | 1 | 区 1 被拍平 | 否 | 越界 |

## 七、常见误判速查

| 症状 | 多半应判 | 为什么 |
| :-- | :-- | :-- |
| 「模型未声明信号 X」而 X 是输出动作 | `FALSE_POSITIVE` | 路径清单不列 `action`，须读原件全文 |
| 「量 X 未声明为变量」 | `REPRESENTATION_DEBT` | PlantUML 无变量声明语法，作者变量 0/60 |
| 「融合事件应拆成 N 个独立事件」 | 先查作者源 | 作者写了析取守卫 → 债务；作者自己塌缩了 → 真漏记 |
| 「应存在名为 `<NL 里的统称词>` 的状态」 | `NO_NL_BASIS` | 命名字面主义 |
| 「状态 X 应有 `during` 动作」 | `NO_NL_BASIS` | NL 的 `indicating that…` 是语义注解不是动作义务 |
