# 意外发现裁定分类学：五类的定义、判定标准与典型例子

**进入意外发现桶的产出，必须落入且只落入下面五类之一。没有第六类，也不设「待定」。**

## ⛔ 先做零步：这条产出真的属于意外发现吗？

**内容已被现有台账记录承载的产出，按定义就不是意外发现，根本不进这个桶。**

判据：台账中存在一条记录**与本条同根**——由同一处建模失误导致，哪怕表现面不同。
判「同根」的硬判据见下方专节。命中者移入
[unexpected_verdicts/ledger_accounted.jsonl](./v46/unexpected_verdicts/ledger_accounted.jsonl)，
并在那里记录其 `disposition`（真漏配 / 冗余复述 / 同根但该格未建立记录 / 报的是已退役判据）。

⚠️ **`MERGE_INTO_LEDGER` 是已作废的类别，不得复设为第六类。** 它回答的是「这条产出该不该在桶里」，
与其余五类回答的「这条产出是什么」不是同一个问题；并列成第六类会让分母混入 13 条已被台账承载的簇
（13/293，见 [unexpected_tables.md](./v46/unexpected_tables.md) 表 0），并让人误以为
「命中被大幅低估」——这 13 条无一产生新增命中，它们只是「不属于意外发现」。**桶内分母恒为 278。**

### ⛔ 判「同根」的硬判据

> **在作者源 `stm0.puml` 上问：争议元素的存在是否完全依赖于台账所指的那条语句？**
> **仅被那一条引用（改它则元素消失）→ 同根；还被别的语句引用（改它元素仍在）→ 不同根。**

**机械判据**：`grep -c "\b<元素名>\b" stm0.puml`。

⚠️ **基准必须是作者源，不是 `model.fcstm`。** 「同根」问的是两条发现是不是同一处**建模失误**，
而建模失误发生在作者写字的地方。R4.5 下沉会把隐式状态**物化成独立声明**——
0037 的三个叶在 `model.fcstm:25-27` 有独立 `state` 行，但那是编译器加的，作者没写。

⚠️ **不要用「有没有独立 `state` 声明」当判据**，也**不要用「修复它能否同时消除本条」**——
前者在 `model.fcstm` 上恒为真，后者会误杀 [HIT_CRITERION.md](./HIT_CRITERION.md) §3 已认可的
「合取项之一」与「蕴含更根本的原因」（它们按定义就不会一修即消）。**要数引用次数。**

v46 的两个反向实例，同一判据、同一基准：

| | `0037-1` ✅ 同根（移出桶） | `0007-1` ❌ 不同根（留在桶里，判 `NO_NL_BASIS`） |
| :-- | :-- | :-- |
| 争议元素 | `FrontendCollision` 等三个死端叶 | `InitialState` |
| 作者源引用次数 | **各 1 处**（`:9` `:16` `:23`，就是那三条检测边） | **2 处**（`:2` 初始边 + `:32` `Collision Resolved` 回边） |
| 改掉台账所指的那条后 | 元素随之消失，计数主张同时解决 | 元素仍在（`:32` 还引用它），计数仍不对 |

⚠️ **该判据对基准的选择不敏感**：若改用「有没有独立 `state` 声明」，上表两个 pair 的判定会随基准
（`stm0.puml` 还是 `model.fcstm`）一起反转；按「引用次数」判，两者在两种基准下结论都不变。
**判据的价值就在这里。**

⚠️ **移出桶 ≠ 该格记命中。** 那是独立的逐格判定，判据在
[HIT_CRITERION.md](./HIT_CRITERION.md)，与本分类学无关。

**不设「待定」。证据不足不构成一个裁定类别**——判定者手里的证据包不含迁移表 / 动作块 / 比较符时，
那是**取证不足**不是判据不足；取不到证据就去取，取到了就裁。

下面五条示范怎么把证据取到手。⚠️ **本表承载了流程图之外的补充判据，与流程冲突时以流程为准；
流程未覆盖的形态以本表为准**：

| 簇 | 卡在哪 | 怎么取到的证据 | 终裁 |
| :-- | :-- | :-- | :-- |
| `0049-10` | 不知 `dist_to_front_25` 是 `<25` 还是 `>=25` | 读 `model.fcstm:5` 的 `named` 串——比较符逐字保留 | 📄 无 NL 依据（`N-SPLIT`） |

| `0039-18` | 疑似依赖正交读法 | `grep -cE "^\s*--\s*$" stm0.puml` = **0**，源内无正交区 | 📄 无 NL 依据（`N-FUSE`） |

⚠️ 后两条的方法值得单独记：**当静态阅读不足以裁定时，直接调 `FBMCQAPI` / `SimulationAPI`

**但两者可用性不同，实测：**

| API | 可用性 | 注意 |
| :-- | :-- | :-- |
| `SimulationAPI` | 开箱即用，秒级 | 投喂 `cycles=[[事件], ...]`，看 `consumed` / `fired` / `active` |
| `FBMCQAPI` | **在结构最破的制品上恰恰不可用** | 0016 在 `bound>=2` 即抛 `UnsupportedEvidence: partition check exceeded assignment budget`；0027/0012/0037 正常 |

`UnsupportedEvidence` 时的下一跳（按序）：**降 bound → 转 `SimulationAPI` → 静态封裁**。
⚠️ `is_ended()` 不是合法查询；`init cold;` 会被默认注入。`0044-2` 的三次 bound 扫描证明
「首个违反帧永远在 release 之后」，据此把 False 归给谓词而非制品——**这是纯读代码得不出的结论**。

逐簇判据见 [unexpected_evidence.md](./v46/unexpected_evidence.md)，
真源是 [unexpected_verdicts/](./v46/unexpected_verdicts/) 下的 `G*.jsonl`。

## 〇之一、⛔ 一切计数都必须给**两套分母**

> **条目数**（原始簇数）与**去重数**（去掉同质 / 趋同后的实际不同内容数）**必须同时报**。

**去重单元定义**：`(pair, 根因)`。同一个 pair 内、指向**同一处建模失误或同一处编译损失**的簇，
合并计为 1 个；**不同 pair 即使缺陷类型相同也不合并**——那是不同制品上的不同实例。

实现：每条簇带一个自解释的 `merge_key` 字段（如 `0029-作者量与条件不可寻址`、
`0017-三碰撞检测塌缩为单一泛化事件`），去重数 = 不同 `merge_key` 的个数。
⛔ `merge_key` 不许用 `0029-A` 这类无意义编号，也不许跨 verdict / subclass / pair——
[rebuild_unexpected.py](./rebuild_unexpected.py) 会把跨界的 key 判为「去重单元被破坏」并报错。
全部 117 组及其合并理由见
[merge_groups.tsv](./v46/unexpected_verdicts/merge_groups.tsv)。

**为什么这条是硬要求**：同一处缺陷会以不同谓词、不同命名、不同 roll-up 粒度反复产出。
只报条目数会把「一个缺陷被报了 11 次」读成「11 个缺陷」。实测：
`0029` 一个 pair 的 11 条变量类簇讲的是同一件事（该制品作者变量数为零）；
桶内 **278 个条目**归并后只剩 **117 处**不同内容，其中 `VALID_UNRECORDED` 归并后只有 **1 条根因**——
**论文里能说的净增量是 1。** 两套分母见 [unexpected_tables.md](./v46/unexpected_tables.md) 表 1。

⚠️ **条目/去重比本身是可分析的数据**，不只是修正因子。比值高有两种解释，必须分辨：
- **该缺陷天然会被多个谓词命中**（如「零变量」会让每个 `variable_declared` 断言都为假）
  —— 这是缺陷的属性，不是产出的毛病。
- **产出侧在重复报同一件事** —— 这是产出质量问题，应计入多报分析。

## 〇、判定前必须取齐的证据

⚠️ **顺序不能颠倒，颠倒会系统性判错。第 2 步是最容易被跳过、代价也最大的一步**——
v46 八个判定组里只有一组做了它，也只有那一组识别出编译债务：

| # | 材料 | 回答什么 | 不看的后果 |
| --: | :-- | :-- | :-- |
| 1 | `model.fcstm` **全文**（含 `action` 块） | 事实到底成不成立 | 把以 `action` 形式存在的元素判成缺失（`FP-K`） |
| 2 | **`stm0.puml` 作者源逐行** | 缺的是作者没写，还是编译没留 | 把编译债务记成模型缺陷——**最大一类，129 簇** |
| 3 | `fcstm_meta.json` 的 `source_static_reason_codes` | 编译器认不认这笔损失 | 无法确认该类损失已被自申报 |
| 4 | `nl.txt` **逐句** | NL 到底要求什么 | 把统称词、语境状语、语义注解当成元素义务 |
| 5 | `manual_review/expected_issue_set.json` | 台账记没记 | 把已记缺陷当成新发现，**分母虚高**（13/293 即此） |
| 6 | 同 NL 组的其他 pair（`md5sum */nl.txt` 分组） | 参考意图是什么 | 把参考读法当成异类，或反之 |
| 7 | **同 pair 的兄弟簇及其已定裁定** | 组内是否自洽 | 同一缺口的两种框架各判一次，或同一文件既判 A 又判 ¬A |
| 8 | [FUSED_EVENT_POLICY.md](./FUSED_EVENT_POLICY.md) | 融合事件该怎么判 | **最大一类的实际操作规则在那里**：「表示限制被如实记录、但记录本身不构成发现」 |

⚠️ **`grep` 只能定位，不能裁定。** 实测反例：按 `front_distance` 检索 0010 的作者源得出
「作者源亦无」，作者实写 `Front Distance > 10`（大写、有空格）。**必须逐行读原文。**

## 一、判定流程（按序短路，先命中先判）

```
① 事实在 model.fcstm 上成立吗？
├─ 否（元素其实存在，哪怕名字不同字面 / 以 action 形式存在） ──▶ ❌ FALSE_POSITIVE
└─ 是
   │
   ② 主张依赖正交并发 / 不变式 / 时钟吗？
   ├─ 是 ──▶ 🚫 OUT_OF_SCOPE
   └─ 否
      │
      ③ 断言索要的**范畴**对吗？（NL 称之为 condition 却索要 event、
      │  称之为 action 却索要 event、合取项被索要成独立触发）
      ├─ 错 ──▶ 📄 NO_NL_BASIS（N-KIND / N-SPLIT）
      └─ 对
         │
         ④ 同一缺口是否已由本 pair 另一簇以**正确范畴**承载？
         ├─ 是 ──▶ 📄 NO_NL_BASIS（只计一次，注明承载它的那一簇）
         └─ 否
            │
            ⑤ 作者在 stm0.puml 里已逐字表达**该 NL 义务**吗？
            ├─ 是（且 meta 有对应债务码） ──▶ ⚙️ REPRESENTATION_DEBT
            └─ 否
               │
               ⑥ NL 真的要求这件事吗？
               ├─ 否 ──▶ 📄 NO_NL_BASIS（N-CTX / N-FUSE / N-FORM / N-ANCHOR / …）
               └─ 是 ──▶ ✅ VALID_UNRECORDED

（⓪ 台账是否已承载 —— 在进入本流程**之前**判，命中者不进桶，见文首「先做零步」）
```

⚠️ **③④ 必须前置于 ⑤，否则范畴错置（`N-KIND`）与合取拆分（`N-SPLIT`）会被短路成表示债务**
——这两类合计占「无 NL 依据」近半（[unexpected_tables.md](./v46/unexpected_tables.md) 表 2）。
最小实例：`0049-11`（「无独立 `extra_lane_true` 事件」）与 `0049-15`
（「无 `extra_lane` 变量」）指向**同一处缺口**，作者在 `stm0.puml:11,14,21` 都写了
`dist_to_front<25 && extra_lane=true`，故 ⑤ 对两者同样为「是」。区分它们的是 ③——
NL 把 `extra_lane` 称作 condition，属 `V` 不属 `E`，索要事件是范畴错置；以及 ④——
该缺口已由 `0049-15` 以变量框架承载，`0049-11` 只是同一缺口的错误框架，不再计一次。

### ⛔ ③ 的子判据：合取 / 析取分岔

事实为真、且作者源含该文本时，看**融合的逻辑连接词**：

| 作者写法 | 拆开是不是正确修法 | 落点 |
| :-- | :-- | :-- |
| **析取**（`\|` / `\|\|`），且作者逐字写出了各支 | 是——融合后无法只凭其一激活 | ⚙️ `REPRESENTATION_DEBT`（`D1` 析取备选融合） |
| **散文 "or"**，NL 未给任何标识符、作者自己写成单一泛化名 | 否——报告者必须自造分型名，造名空间无上界 | 📄 `NO_NL_BASIS`（`N-SPLIT-PROSE`） |
| **合取**（`&` / `&&` / 散文 "and"） | 否——拆开会把 AND 变 OR | 📄 `NO_NL_BASIS`（`N-SPLIT` / R-CONJ） |
| **`variable_declared` 族** | 不适用 | 连接词分岔**对它不适用**——PlantUML 无变量声明语法，与融合结构无关。⛔ **但落哪个子类仍按 §2 的划分维度判，不由谓词族决定**：实测 47 条 `variable_declared` 里 D2 36 条、D3 8 条、D1 1 条、`N-KIND` 2 条 |

**这条子判据优先于 ⑤。** 不写死它，同一份 NL 下六个制品的同形簇会按判定组分裂——
作者守卫写法六份完全同形，判定却可能一半落债务、一半落无 NL 依据。

⚠️ **⑤ 问的是「该 NL 义务」，不是「断言字面索要的那个元素」。** 两者不同：作者写了
`extra_lane=true`（NL 义务已表达），但没写名为 `extra_lane_true` 的事件（断言字面所求）。
按后者读会把几乎所有簇都判成「作者没写」。

**短路顺序是有意的**：⓪ 是否属本桶 → 事实 → 边界 → **范畴与去重** → 归属（作者 vs 编译）→ NL。
把归属放在范畴之前会漏掉 `N-KIND`/`N-SPLIT`；把 NL 放在归属之前会把编译债务混进 NL 判断。

## ✅ 1. `VALID_UNRECORDED` —— 真实的台账漏记

### 定义
事实在编译产物上为真，**且作者源本身就缺该元素**，**且 NL 有明确依据**，**且台账未记**。
这是**唯一**应当补进台账的类别，也是方法相对台账的净增量。

### 判定标准（四条全中）
1. 事实在 `model.fcstm` 上客观为真（含 action，须读全文）。
2. `stm0.puml` 里作者**没有**以任何形式表达该义务（不只是名字不同，是根本没写）。
3. `nl.txt` 有逐字依据，且该依据**不是**统称词 / 语境状语 / 语义注解，
   **也不是只能靠报告者自造标识符才能落地的散文并列**（后者见 `N-SPLIT-PROSE`）。
4. `expected_issue_set.json` 中无任何记录覆盖同一缺陷（含换谓词、换说法的情形）。

**查同 NL 组的其他 pair**：若多数作者把这件事写对了，说明它是该 NL 的通行读法而非过度指定。

### 唯一的正例：`0014-4`（子类 `V1`，全桶净增量就是它一条）

> 事实：`EmergencyStopping` 内无任何 `enter`/`during` 动作，NL 要求发出的信号被吞进状态名描述串。
> 作者源 `stm0.puml:26` 写 `EmergencyStopping: Obstacle Detected`——PlantUML **描述行**，不是动作。
> 对照 0054:18 作者写 `do/Send Obstacle Detected`、0004 写 `during abstract SendObstacleDetected`
> → 该输出动作在 M 内可表达且是参考意图，**作者用错了语法**（第 2 条成立）。
> 台账：已记同族 `EIS-0014-03`（Emergency Stop）与 `EIS-0014-04`（Approaching 的 Send），
> 但前者 `nl_evidence` 只引「Emergency Stop」、后者 scope 是 `InMotion.Approaching`，
> **均不覆盖此条**（第 4 条成立）。

### 两个最像正例的反例

下面两条簇在「事实为真 + 台账 0 条 + NL 逐字点名」三项上全部满足，仍不属本类。
一条卡在判定标准第 3 条的后半句，另一条**根本走不到这四条**——它在流程 ② 就被短路：

| 簇 | 表面像正例的地方 | 卡在哪 | 实际裁定 |
| :-- | :-- | :-- | :-- |
| `0017-1`（8 簇同源） | 制品只有泛化 `collision_detected`，NL 2 逐字并列三种检测；该 pair 台账 0 条 | **NL 未给任何标识符**：作者自己把散文析取写成一个泛化名，报告者必须自造分型事件名，造名空间无上界；8 簇即同一根因按「分型数 × 命名变体数」膨胀出来的 | 📄 `NO_NL_BASIS`（`N-SPLIT-PROSE`） |
| `0023-7`（6 簇同源） | `PumpControl` 内三子态之间零迁移、全模型无 `event` 声明；NL 4/5 以「can transition to」要求可切换；台账 0 条 | **该现象是展平产物**：作者用 `--` 写了并发区，$M$ 无正交区故被展平成竞争初始边，「区间零迁移」只在展平后出现，参考模型同样如此 | 🚫 `OUT_OF_SCOPE`（`OOS-FLATTEN`） |

⚠️ 两条都不能靠「把措辞改到 Tr/E 层」救回来。`0023` 一族的事实陈述（`E=∅`、非初始迁移数 = 0）
本身完全属实且不提区语义，**但成因仍是展平**——判类看的是现象由什么产生，不是陈述用了哪层词汇。

## ⚙️ 2. `REPRESENTATION_DEBT` —— 我们自己编译链的信息损失

### 定义
事实在编译产物上为真，**但作者在 `stm0.puml` 里已逐字表达该义务**，失真发生在
R4.5 的 PlantUML → FCSTM 有损编译。**不是模型缺陷。**

完整论述见 [REPRESENTATION_DEBT.md](./REPRESENTATION_DEBT.md)；
融合事件的既定操作规则见 [FUSED_EVENT_POLICY.md](./FUSED_EVENT_POLICY.md) —— **「表示限制被如实记录、但记录本身不构成发现」**。

### 判定标准（三条全中）
1. 事实在 `model.fcstm` 上客观为真。
2. 该义务在 `stm0.puml` 上**已被作者逐字表达**（⚠️ 需人工逐行读，词法检索不可靠）。
3. `fcstm_meta.json` → `source_static_reason_codes` 有对应债务码。
   ⚠️ **这一条几乎没有判别力，不要靠它判**：`opaque_transition_label_semantics` 覆盖 **58/60**
   制品，且 `variable_declared` 类**没有专属债务码**只能挂靠它。它的作用是确认编译器
   **自申报**了该类损失，**判别力全在第 2 条**。（每码在两个数组各列一次，数制品数用
   `grep -l <code> */fcstm_meta.json | wc -l`。）

### 与「真漏记」的分界线
**只看第 2 条**：0036 的 `/ UAV Count Decreased` 作者写了 → 债务；
0006 的作者源里**连递减文本都没有** → 真缺陷。

### 五个子类：按**「丢失的是哪一条区分」**切

⛔ **划分维度是「源制品有、编译产物没有的那一条区分」，不是谓词族。**
谓词族、命名变体、roll-up 粒度**一律不参与判类**——它们是同一条损失的不同说法。
三个可检验的锚点：`0027-3/4/5` 是 `edge_declared` 却与 `0027-2` 同类；
`0029-24` 是 `variable_declared` 却入 `D1`；`0016-5/7` 是 `variable_declared` 却入 `D3`。

**按序走这四问，任一新簇即得唯一解**：

1. 损失在标签之外（状态 / 区域 / 初始被重写）？→ **`D4`**
2. 作者用 `/` 或 `[]` 分隔了刺激与非刺激内容、而编译器跨越了它？→ **`D3`**
3. 被指缺失的实体逐个归类，结果 ≥2 种（或含不由任何损失产生的分量）？→ **`D5`**
4. 被指串**恰为作者标签的一个完整析取支**？→ **`D1`**；是子部分 / 标签无析取 → **`D2`**

| 子类 | 丢失的区分 |
| :-- | :-- |
| `D1` 析取备选融合 | **备选之间的可分性**（`or` 被强化成 `and`） |
| `D2` 原子子表达式不可寻址 | **该量 / 该条件是一个可寻址的一等实体** |
| `D3` 槽位焊死 | **槽位角色**（哪段是触发、哪段是效果） |
| `D5` 跨通道打包 | 一簇同时跨 ≥2 个损失通道 |
| `D4` 结构性下沉债务 | **谁是真正的初始态 / 层次深度** |

条目数、去重数、条目/去重比与涉及 pair 数见
[unexpected_tables.md](./v46/unexpected_tables.md) 表 2，**此处不留副本**。

⚠️ **去重数以 `merge_key` 为准。** `D5` 的 key 与同 pair 的 `D1`/`D2` key 指向同一批损失的
再打包，但 `merge_key` 是本文件 §〇之一定义、并由 [rebuild_unexpected.py](./rebuild_unexpected.py)
强制的去重单元（跨 verdict / subclass / pair 的 key 会被它判为破坏去重单元并报错）。
论文若要说「这条链上有多少处编译损失被下游误记为模型缺陷」，该用 **27**：
7 处析取标签融合 + 11 处作者量整体不可寻址 + 4 处槽位焊死 + 4 处跨通道打包 + 1 处结构注入。

**关键分界线**：

- **`D1` vs `D2`**：被指串**是不是一个完整析取支**。整支 → `D1`；子部分或标签无析取 → `D2`。
  例：`dist_to_rear<5 && vel>30` 整支缺失 = `D1`；其中的 `vel` 缺失 = `D2`。
- **`D2` vs `D3`**：量写在**守卫侧** → `D2`；写在 `/` **之后的效果槽** → `D3`。
  这是 `0009-12`（`vel`）与 `0046-6`（`uav_count`）虽同为 `variable_declared` 却分属两类的原因。
- **`D1` vs `D5`**：**打包本身不是入 `D5` 的理由，跨通道才是。** 四项全在同一条析取标签内
  （`0059-8`、`0039-6/19`）仍留 `D1`。
- ⚠️ **`D5` 不是兜底类**：入类要通过一个**正向计数测试**（枚举分量归类结果 ≥2 种），
  不是「其他都不像」。

⚠️ **本划分最脆弱的一处**：`dist_to_front<15` 在本批 pair 里出现两次——碰撞激活标签的第 3 析取支
（NL 12）判 `D1`，城区换道守卫（NL 7/9）判 `D2`。两者清洗名极其形近
（`dist_to_front_15_highway` vs `dist_to_front_15_extra_lane_true`）。**这条线不可从簇自身文本
判定**，必须回读 `stm0.puml` 那一行并确认它对应哪句 NL；受影响 ≤4 条（占表示债务 129 条目的 3.1%）。

## 📄 3. `NO_NL_BASIS` —— 事实为真，但 NL 不要求

### 定义
事实在编译产物上为真，作者源确实没写，**但 NL 并不要求这件事**。属过度规定。

### 判定标准
1. 事实为真（否则是 `FALSE_POSITIVE`）。
2. 回到 `nl.txt` 逐句读，确认 NL **没有**提出该义务。
3. ⚠️ **重点排查下面十种误读。**

### 十个子类

⛔ 各子类的条目数 / 去重数 / 稳定性一律以
[unexpected_tables.md](./v46/unexpected_tables.md) 表 2 为准，**本节不留副本**。
本节只定义「怎么认出它」。

**`N-CTX` 语境词当元素** —— 例 `0016-3` / `0026-2`
> 把 NL 的**语境状语 / 状语从句 / 散文里的场景词**当成必须存在的同名元素。
> 「During flight, if task assignment information is received」——`During flight` 是**状语背景**，
> 整台机器全程在飞行，NL 中不存在与之对立的非飞行上下文；要求一个名为 `Flight` 的状态属过度规定。
> 识别信号：被索要的名字在 NL 里只作时间 / 场景状语，从未作为被操作的对象出现。

**`N-FUSE` 上位范畴词当元素** —— 例 `0003-4` / `0037-2` / `0039-18`
> NL 用一个**统称 / 上位词**概括若干具体元素，断言却索要以该统称词命名的元素本身。
> `user_actions`（"based on user actions"）、`collision_avoidance_controls` 均属此类——
> 模型已声明各具体动作 / 控制态，缺的只是那个概括名。
> 与 `N-CTX` 的分界：`N-FUSE` 的词在 NL 里**确是被操作的对象**，只是层级比模型元素高一层。

**`N-META` 工具注记词当元素** —— 例 `0007-2` / `0017-8` / `0033-1`
> 被索要的名字只出现在**编译器写进 `named` 串的工具注记**里
> （`[PlantUML concurrent region 0..3]`、`substates` 之类），不是任何人建模时命名的东西。
> 识别信号：`grep` 到该词时命中的是注记方括号内部。

**`N-FORM` 相位 / 形态过度指定** —— 例 `0033-2` / `0013-1`
> NL 只在**解释状态含义**，却被读成 `during` / `entry` 动作义务，或读成必须用某种形态实现。
> 「where the pump is activated or controlled」是对子状态含义的说明，未规定必须以 `during` 相位实现；
> 模型另行声明了 `Activate_Pump` / `Pump_Deactivated` 承载该行为。
> 识别信号：NL 用 `indicating that…` / `where the … is …` 这类同位语或定语从句。

**`N-SPLIT` 合取项被要求拆成独立事件（R-CONJ）** —— 例 `0049-11` / `0029-5`
> 判据不是「行为是否等价」，而是**这条断言若被采纳去修，修出来的对不对**：
> - NL 用 `or` 并列备选触发 → 融合后无法只凭其一激活 → **拆开是正确修法** → 不落本类。
> - NL 用 `and` 连接条件 → 拆成独立事件后任一个都能触发 → **把 AND 变成 OR，比现状更违反 NL**。
>
> 同一处的真实缺口按 M 的 `V` 计（NL 称之为 condition），**同一缺口只计一次**。

**`N-SPLIT-PROSE` 散文析取被索要成分型事件名** —— 例 `0017-1` / `0047-1`
> NL 用散文 "or" 并列若干情形，**但不给任何标识符**；作者也把它们写成一个泛化名。
> 报告者必须自造分型事件名，**造名空间无上界**，于是一个根因按「分型数 × 命名变体数」膨胀
> ——本子类的条目/去重比是全表最高的几个之一。
> 与 `N-SPLIT` 的分界：那类的分支在作者源上逐字存在（连接词是 `and`），本类根本没有分支文本。

**`N-KIND` 范畴错置** —— 例 `0049-19` / `0029-20`
> 把变量当事件、把动作当事件。`dist_to_front` 是被比较的**量**不是信号；
> `Send` 是**输出动作**不是输入事件。正确框架下的同一缺口另有簇承载，本类不再计一次。

**`N-ANCHOR` 义务被锚到错误的元素上** —— 例 `0057-2` / `0022-2` / `0026-3`
> 两种形态：断言的 scope / source 绑定到一个**模型里查不到的路径**（`0057-2`：制品无
> `Inactive` 状态，「`Inactive --X--> CA` 这条边缺失」是自造前提导致的空洞真）；
> 或 NL 义务真实存在、但被钉死在 NL 并未指定的那个位置上
> （`0022-2`：NL 未要求根初始边直指 `Operate`，同组 6 个作者无一直连）。
> 识别信号：事实成立，但把它「修好」会与另一条 NL 冲突。

**`N-MODAL` 定性表述被强化为时序不变式** —— 例 `0054-5` / `0046-8`
> NL 的 `continuously` / `remains` 是定性描述，被读成状态驻留不变式。
> `0054-5` 更进一步：`release=false` 把「保持到某条件」读成「永远保持」，**构造性不可满足**。
> 这类义务来自**断言被构造的方式**而非 NL，按 [CLAUDE.md](../../../CLAUDE.md) §13 属
> 「多道门交集为空」类缺陷，**另案登记于
> [PREDICATE_DEFECTS_REGISTERED.md](./PREDICATE_DEFECTS_REGISTERED.md)**。

**`N-CLOSED` 把 NL 的枚举读成封闭计数义务** —— 例 `0007-1` / `0022-3`
> NL 列举了若干元素，断言据此要求「恰好这些、不许多」。NL 的枚举默认不封闭，
> 计数义务需要 NL 明写。识别信号：断言并列枚举若干元素却**未指认哪一个多余**。

## ❌ 4. `FALSE_POSITIVE` —— 元素其实存在

### 定义
断言所指的元素**其实存在**（哪怕名字不同字面、或以 `action` 形式存在），主张与制品相反。

### ⛔ 「存在」的硬定义

> **只有该元素在 `model.fcstm` 中作为一个独立的 `state` / `event` / `def` / `action`
> **声明**存在，才算存在。名字可以不同字面，可以是 `action`。**
>
> **仅出现在另一元素的 `named "..."` 显示串内部、或作为其标识符的子串——一律不算存在。**
> 此时事实为真，应走流程 ③ 之后的分支（多半是 `REPRESENTATION_DEBT` 或 `NO_NL_BASIS`）。
>
> **可执行判据**：能否写出一个引用它的合法 FCSTM 断言？
> `event_declared("...vel")` 写不出来 → `vel` 不存在。

**反例**：`0009-12` 主张「`vel` 未声明为变量」。`vel` 字面确实出现在
`named "pedestrian_detected || (dist_to_rear<5 && vel>30) || …"` 里，但那只是显示串的子串，
**没有任何 `def vel`**。故事实为真 → 走债务分支；又因为被指串是析取支的**子部分**而非整支，
落 `D2` 而不是 `D1`，**更不是**假阳性。
若按「子串也算存在」读，整个 129 簇的 `REPRESENTATION_DEBT` 桶都会塌成假阳性。

### 判定标准
**事实为假**（按上面的硬定义）——这是与 `NO_NL_BASIS` 的唯一分界。

⛔ **不要把「事实为真但义务越界 / 已被政策许可」塞进本类。** 那会污染本类的语义，
而多报口径的成分划分依赖它。

### 四个子类

⛔ 条目数 / 去重数以 [unexpected_tables.md](./v46/unexpected_tables.md) 表 2 为准，**本节不留副本**。

**`FP-N` 命名变体 / 虚构标识符：元素已在，仅字面不同** —— 例 `0057-6` / `0032-3` / `0003-1`
> `0057-6`：断言要求 `possible_frontend_collision`，制品已声明 `Frontend_collision_detected`
> ——正是 NL 2 对应的独立检测事件，只是字面名不同。
> `0032-3`：断言要求 `accelerating`，制品已声明 `event Accelerate`；NL 3 用 `like` 举例，未规定精确拼写。
> `0003-1/2`：断言用的 `power_on` 是虚构标识符，制品的入口边写作 `PoweredOff -> Operate : /start`。
> ⚠️ 同一主张在不同 pair 上可能一真一假：0017 只有泛化 `collision_detected`，
> 0057 已分立三事件。**命名类断言必须逐 pair 核对，不能按 NL 归并结论。**

**`FP-K` 元素以 `action` 存在，路径清单看不见** —— 例 `0004-1` / `0034-1` / `0044-3`
> 制品有 `state Approaching { during abstract Send; }`——`Send` 已作为**动作**声明。
> 路径清单只列状态与事件、**不列动作**，据此判「未声明」必然出错。

**`FP-A` 谓词锚点错置** —— 例 `0027-9`
> 触发只能锚在源态，断言却锚到了目标态：制品是
> `DetectingState -> junction1 : /Frontend_Collision_or_..._detected` 与 `junction1 -> ActiveState`，
> 条件化激活本已成立，目标态 `ActiveState` 本就不应消费该事件。

**`FP-0` 未消费回退被误读成执行轨迹** —— 例 `0044-4`
> 事件被忽略、机器原地未动，断言却声称「运行离开了该状态」并给出一条不相邻的 `transition:N`。
> 成因在测量链侧，登记于
> [PREDICATE_DEFECTS_REGISTERED.md](./PREDICATE_DEFECTS_REGISTERED.md)。

## 🚫 5. `OUT_OF_SCOPE` —— 在 M 边界外

### 定义
主张依赖**正交区并发语义**、**不变式**或**时钟**，落在 paper1 建模对象
`M = (S, E, V, Tr, A)` 之外；**或所报现象本身是正交区被展平之后才出现的产物。**

### 判定标准
命中任意一条即越界：
1. 谓词族是 `invariant`，或主张要求多个状态**同时**保持活跃。 → `OOS-INV`
2. 主张的内容是「某复合态下恰好有 N 个**区**」。⚠️ **本条从属于下面的标准 4**——
   源内无 `--` 分隔符时不适用（例 `0037`：7 个子态是单区真实计数，保留在 M 内）。 → `OOS-REGION`
3. 主张涉及时钟变量或状态不变式。
4. **R-REGION**：含正交区的制品上，`cardinality` 类主张在 M 内成立
   **当且仅当该违规在「区感知读法」下依然存活**——即不存在任何区分配使 NL 的计数 / 枚举义务被满足。
   若存在一个区恰好满足该义务，违规只在把区拍平成兄弟之后才出现，则越界。 → `OOS-REGION`
5. **展平产物**：作者源用 `--` 写了并发区，$M$ 无正交区故被展平；所报现象
   （区间零迁移、竞争初始边、跨区求和的计数）**只在展平后存在**，参考模型同样如此。 → `OOS-FLATTEN`
   ⚠️ 本条与标准 4 的分界：4 管计数义务，5 管**任何**只由展平产生的现象。
   ⚠️ **把陈述改写到 Tr/E 层不能规避本条**——判类看现象由什么产生，不看陈述用了哪层词汇。

**R-REGION 与展平判据的机械入口**：`grep -cE "^[[:space:]]*--[[:space:]]*$" stm0.puml` 查分隔符数，
再看盈余 / 缺口是不是区拍平造成的。

### ⚠️ 边界是双向的
[CLAUDE.md](../../../CLAUDE.md) 明确：**不得**把并发 / 时间类问题记为方法未能检出，
也**不得**反过来声称这些模型没有并发 / 时间问题。论文的正确姿态是**双向缄默**。

### 典型例子

**`0027-6` —— invariant + 并发保持（双重越界）**
> 断言以 `invariant + active('ActiveState.BrakeControlState')` 等形式要求三个控制态**同时活跃**。
> 谓词族与并发语义两项都在建模对象之外。

**`0007-3` —— 区数量义务**
> 「`CollisionAvoidance` 下恰好三个区」。且按区计数制品**本已是三个非空区**，
> 「不是三个」只在把区换算成子状态时才成立。

**`0056-1` —— R-REGION 的判例（`OOS-REGION`）**
> 作者源 `stm0.puml:10` 是正交区分隔符 `--`，`SearchState` 实为两区：
> `region0={Area1,Area2,Area3}`、`region1={NoIntercept,Intercepted}`。
> **NL 2 的「three different state areas」由 region 0 的三个 Area 兑现，义务在作者源上已满足**；
> `cardinality=5≠3` 只在 R4.5 拍平、跨区求和后才出现。

**`0023-7` —— 展平产物（`OOS-FLATTEN`，本类条目最多的一个 merge key）**
> 事实陈述完全属实且不提区语义：`PumpControl` 内三子态之间零迁移、全模型无 `event` 声明。
> 但作者用 `--` 写了三个并发区，展平后三条区内默认入口变成三条竞争初始边，
> 「区间零迁移」正是展平的直接后果，**参考模型在同一处也是如此**。

### R-REGION 的可证伪性（必须与结论同批披露）
该规则在**四处给出对方法不利的保留**，说明它不是为某一条现造的：

| pair | `--` 数 | 盈余来源 | 区感知读法下仍违规 | 裁定 |
| :-- | --: | :-- | :-- | :-- |
| 0037 | **0** | 单区复合态，7 个子态就是作者源的数 | 是 | **保留在 M 内** |
| 0002 | 2 | 游离的 `InitialState`，与区无关 | 是 | **保留在 M 内** |
| 0013 | 3 | NL 未枚举的克隆态 | 是 | **保留在 M 内** |
| 0007-1 | 3 | 顶层 `InitialState` + 臆造子树，纯层次 | 是 | **保留在 M 内** |
| 0007-3 | 3 | 区→子态换算 | 否 | 越界 |
| 0056-1 | 1 | 区 1 被拍平 | 否 | 越界 |
