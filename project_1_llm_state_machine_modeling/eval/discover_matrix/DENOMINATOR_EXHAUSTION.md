# 分母耗尽：人工裁定，不是机械判据的结论

## 结论

**能力主张带的分母结构性耗尽。** 可报记录 2 条（`2 × 2 臂 × 3 轮 = 12` 个判定），
`hit@1` 的取值粒度是 `1/12 = 8.3%`，「70%」需要 ≥ 9/12。候选池无替补。

这不是「暂时不够」，是**本语料在当前主张构造下的上限**。

## 为什么没有替补：逐道规则的实测

台账实际有 **126 条记录、覆盖 48 个 pair**，而格集只有 11 个 pair —— 直觉上「格集外 37 个 pair /
89 条记录」是巨大的未用分母。逐道过 `holdout.py` 的真实规则后，它归零：

| 收缩步骤 | 剩余 | 淘汰依据 |
| :-- | --: | :-- |
| 台账全体 | 126 条 / 48 pair | —— |
| 格集外 | 89 条 / 37 pair | 格集内的 11 个已全部跑过 |
| 未曾被跑过 | 66 条 / 31 pair | 6 个 pair 出现在 `runs/` 目录（行为已被观察） |
| 源码 / 测试未点名 | 47 条 / 23 pair | 8 个 pair 的 id 出现在 `src/` 或 `tests/` |
| 可判定（规则 4）+ 每 pair ≥2 条（规则 5） | 31 条 / 10 pair | 8 条闭词表不可表达；单条记录的 pair 出局 |
| **不在 `previously_run_and_published`** | **5 条 / 1 pair** | **8 个 pair 的 Discover 行为已在 PR #158 §五 及其 gist 发表** |
| NL 组与调优格不交（规则 3） | **0 条 / 0 pair** | 最后那 1 个（`0058`）被連坐 |

⚠️ **中间那几行我第一次是手算的，错了。** 我漏掉三道真实规则（`published_run_ledger`、NL 组連坐、
commit body 点名扫描），手算得「10 个 pair / 31 条」。改为调用 `holdout.compute()` 自己的实现后
得 1 个候选 —— 与冻结快照的 `candidate_count` 一致。**重写判据永远不如调用判据。**

## 最后一个候选 `0058` 的烧毁裁定：人工读，不是机械代理

机械判据说「它在 4 个改了管线行为的 commit 里被点名」。但那是**保守代理，会过度烧毁** —— 按
`CLAUDE.md` §3.5 的动机判据，得读这些 commit 的 body 看它是不是因为这个样本才写的规则。

逐个读完，四处里两处是过度烧毁、两处是真烧毁：

| commit | 提到 `0058` 的语境 | 裁定 |
| :-- | :-- | :-- |
| `5faf75671` | 列出 6 个 NL 含 `Join1`/`Join2` 的 pair —— **泄漏审计清单** | ⚪ 非动机 |
| `dbc2e2652` | 「候选池重算只剩 0058」—— **记账** | ⚪ 非动机 |
| `fc25c232f` | 「A1 触发 3/60…但 0058 与前两者**同属 NL 组 `53d65d24`**」 | 🔴 連坐 |
| `e85dd2570` | 「仅 3 个含 pseudo state —— 0018(9)、0038(4)、0058(3)。前两个是 hold-out，**本规则是看着它们的失败写的**」 | 🔴 連坐 |

**决定性的是連坐，不是点名。** A1（伪状态不得作占据类谓词的主语）是看着 `0018` / `0038` 的失败
写的；`0058` 与它们同 NL 组，意味着同一份需求文本、同一份参考模型 —— 按规则 3 的原话，
「a rule written against one member acts on every member」。而 `0058` 那 5 条记录里 4 条是
`wellformedness` 层的伪状态族，正是 A1 针对的对象。

所以：**人工读纠正了机械判据在两处的过度烧毁，但结论方向不变**，且现在有了实质理由而不只是
字符串命中。

## 三条扩充路径的可行性

指令给了三条，逐条按 §3.5.-1「按构造留出」检验：

| 路径 | 可行性 | 理由 |
| :-- | :-- | :-- |
| 启用格集外 pair | ⛔ **归零** | 见上表。37 个 pair 全部被「已跑 / 已发表 / 已点名 / 不可判定 / 同 NL 组」逐层滤掉 |
| 放宽可判定筛选 | ⛔ **不可且无用** | 规则 4 淘汰的 8 条全是「闭词表不可表达」。放宽等于把**方法边界**报成能力缺口，规则 4 的 rationale 明写禁止。且这 8 条所在 pair 本就被其它规则淘汰，放宽后分母不增 |
| 改变主张构造 | ✅ **唯一可行** | 见下 |

## 唯一可行的方向：改变主张构造

前两条不是「难」，是**语料层面的算术归零**。第三条要回答的是：在只有 2 条可报记录的语料上，
什么主张仍然成立？

### ⚠️ 首版此处推荐「共演化溢价」作为定量主张，那是错的 —— 已由独立裁决推翻，就地改写

首版写：「调优格 71.2% vs 留出格 **39.7%**，CI 不重叠，Fisher p = 3.7e-05，且方向自保守」，并据此
建议把它作为论文主要主张。**三处都不成立。**

**一、`39.7%` 是分子分母错配。** 分子取了两带之和（50），分母只取了烧毁带（126）。正确值：

| | 分子 | 分母 | 率 |
| :-- | --: | --: | --: |
| 可报带 | 8 | 12 | 66.7% |
| 烧毁带 | 42 | 126 | 33.3% |
| **留出带合计** | **50** | **138** | **36.2%** |

这是本轮同一类错误（分母/口径）的第八次。方向上它自保守（缩小了溢价），但仍是错的。
复算：`metrics_at_k.py verdicts/v22_manual.json`。

**二、`Fisher p = 3.7e-05` 用错了推断单元 —— 换成正确单元后效应消失。**

Fisher 以**单个判定**为独立观测，而污染以 **NL 组**为单位传播（`holdout.py:27-29`：「Same group
means the same requirement text and the same reference model, so a rule written against one member
acts on every member」）。**把 NL 组当污染单元、把判定当推断单元，是自相矛盾的。**

按 cluster 级重算，两种统计量都不显著：

| 检验统计量 | 差 | p |
| :-- | --: | --: |
| 合并率（按判定数加权） | 35.0 pp | 0.158 |
| pair 率的非加权均值（cluster 级正确口径） | 20.1 pp | **0.373** |
| NL 组级非加权均值（3 vs 5 组） | 22.8 pp | **0.446** |
| pair 聚类 bootstrap 95% CI | —— | **[−1.3, +59.3] pp，含 0** |

原因在逐 pair 率里一目了然（★ = 调优格）：

```
  0035  100.0%   ← 留出格，高于全部调优格
★ 0006   83.3%
  0043   83.3%   ← 留出格，与最好的调优格并列
★ 0029   80.0%
  0018   66.7%
★ 0050   50.0%
★ 0000   41.7%   ← 最差的调优格只排第 7
  0038   36.1%
  0047   11.1%
  0032    8.3%
  0048    0.0%
```

**留出组同时包含最好和最差的 pair。** 35 pp 的粗差距主要是 pair 间固有难度差，不是共演化。
按归因层直接标准化后差距进一步降到 27.5 pp（约 22% 的粗差距来自层构成不同）。

**三、「方向自保守」不成立，已删除。** 两个已知偏倚方向相反：留出台账与规则同一作者写
（`holdout.py:44-50` 自陈）可能使留出偏易 → 缩小差距；而非盲判定者若预期留出更难，会把留出侧
模糊案例系统性判为未命中 → 扩大差距。**净方向未知。**

### 改写后：溢价只能作定性警示，不能作效应量

可进论文的最强表述（差距仍在、方向在三个共有层上一致，但不可作点估计）：

> 在本语料上，管线在其自身开发所依据的四个 pair 上测得的覆盖率（71.2%，47/66 判定）约为在开跑前
> 即冻结、从未参与任何规则编写的七个 pair 上测得值（36.2%，50/138）的两倍；按归因层直接标准化后
> 差距仍达 27.5 个百分点，且在两组共有的三个层上方向一致。但由于独立变异单元是需求文本而非单次
> 判定（4 vs 7 个 pair、3 vs 5 个 NL 组），该差距无法与 pair 间固有难度差异区分（pair 级精确置换
> p = 0.37，NL 组级 p = 0.45，聚类 bootstrap 差值 95% CI [−1.3, +59.3] pp）。因此我们把它作为
> **方法学警示**而非效应量估计：在自身调优样本上报出的覆盖率数字不可默认可迁移，举证责任在报告
> 方，须出示冻结且经动机审计的留出集。

**不能推出的**（写进 Threats to Validity）：任何点估计（CI 含 0）；「真实能力是 36.2%」（留出仅
7 个 pair、台账与规则同作者、判定未盲）；跨系统泛化（单语料单管线）；「留出覆盖率是能力下界」
（部分未命中可归因于门而非能力）；任何因果措辞（暴露非随机分配，用「伴随」）。

### 那么什么主张是本语料**真能**支撑的

**烧毁普查** —— 它是**普查而非抽样**，无抽样误差、无聚类问题、无 p 值：

> 把「规则是否是看着这个样本写的」做成可执行判据并施加于 126 条记录 / 48 个 pair 的台账，结果是：
> 仅 23 条（18.3%）在构造上可判定，其中 21 条因动机污染或同 NL 组連坐被烧毁，**最终可作能力主张
> 的仅 2 条（1.6%）**；且这个数在三个代次里单调下降 9→3→2。

它把 §3.5.-1 的纪律从一条规范变成了**有量化结论的实证发现**，而结论恰是「几乎没有东西能活下来」。
已知弱点：这是关于本项目自身历史的普查，向他人泛化是论证而非测量；且规则 1（源码点名即烧）比本
仓库自己认可的动机判据更严（本文件下节示范：那个候选的四处点名里两处属过度烧毁），所以
**2/126 是下界**，须如此标注。

配套的存在性主张：**存在性不需要大分母。**「至少存在一条从未参与规则编写的台账缺陷能被三轮稳定
发现」这句话，一条正例即成立 —— `EIS-0035-02` 双臂 `hit@all = 1`（6/6）。错的是把它写成比率。
