# 分母耗尽：人工裁定，不是机械判据的结论

## 结论

**能力主张带的分母结构性耗尽。** 可报记录 2 条（`2 × 2 臂 × 3 轮 = 12` 个判定），
`hit@1` 的取值粒度是 `1/12 = 8.3%`，「70%」需要 ≥ 9/12。候选池无替补。

这不是「暂时不够」，是**本语料在当前主张构造下的上限**。

## 为什么没有替补：逐道规则的实测

台账实际有 **126 条记录、覆盖 48 个 pair**，而格集只有 11 个 pair —— 直觉上「格集外 37 个 pair /
89 条记录」是巨大的未用分母。逐道过 `holdout.py` 的真实规则后，它归零：

| 收缩步骤 | 剩余 | 淘汰依据 |
| :-- | --: | :-- |
| 台账全体 | 126 条 / 48 pair | —— |
| 格集外 | 89 条 / 37 pair | 格集内的 11 个已全部跑过 |
| 未曾被跑过 | 66 条 / 31 pair | 6 个 pair 出现在 `runs/` 目录（行为已被观察） |
| 源码 / 测试未点名 | 47 条 / 23 pair | 8 个 pair 的 id 出现在 `src/` 或 `tests/` |
| 可判定（规则 4）+ 每 pair ≥2 条（规则 5） | 31 条 / 10 pair | 8 条闭词表不可表达；单条记录的 pair 出局 |
| **不在 `previously_run_and_published`** | **5 条 / 1 pair** | **8 个 pair 的 Discover 行为已在 PR #158 §五 及其 gist 发表** |
| NL 组与调优格不交（规则 3） | **0 条 / 0 pair** | 最后那 1 个（`0058`）被連坐 |

⚠️ **中间那几行我第一次是手算的，错了。** 我漏掉三道真实规则（`published_run_ledger`、NL 组連坐、
commit body 点名扫描），手算得「10 个 pair / 31 条」。改为调用 `holdout.compute()` 自己的实现后
得 1 个候选 —— 与冻结快照的 `candidate_count` 一致。**重写判据永远不如调用判据。**

## 最后一个候选 `0058` 的烧毁裁定：人工读，不是机械代理

机械判据说「它在 4 个改了管线行为的 commit 里被点名」。但那是**保守代理，会过度烧毁** —— 按
`CLAUDE.md` §3.5 的动机判据，得读这些 commit 的 body 看它是不是因为这个样本才写的规则。

逐个读完，四处里两处是过度烧毁、两处是真烧毁：

| commit | 提到 `0058` 的语境 | 裁定 |
| :-- | :-- | :-- |
| `5faf75671` | 列出 6 个 NL 含 `Join1`/`Join2` 的 pair —— **泄漏审计清单** | ⚪ 非动机 |
| `dbc2e2652` | 「候选池重算只剩 0058」—— **记账** | ⚪ 非动机 |
| `fc25c232f` | 「A1 触发 3/60…但 0058 与前两者**同属 NL 组 `53d65d24`**」 | 🔴 連坐 |
| `e85dd2570` | 「仅 3 个含 pseudo state —— 0018(9)、0038(4)、0058(3)。前两个是 hold-out，**本规则是看着它们的失败写的**」 | 🔴 連坐 |

**决定性的是連坐，不是点名。** A1（伪状态不得作占据类谓词的主语）是看着 `0018` / `0038` 的失败
写的；`0058` 与它们同 NL 组，意味着同一份需求文本、同一份参考模型 —— 按规则 3 的原话，
「a rule written against one member acts on every member」。而 `0058` 那 5 条记录里 4 条是
`wellformedness` 层的伪状态族，正是 A1 针对的对象。

所以：**人工读纠正了机械判据在两处的过度烧毁，但结论方向不变**，且现在有了实质理由而不只是
字符串命中。

## 三条扩充路径的可行性

指令给了三条，逐条按 §3.5.-1「按构造留出」检验：

| 路径 | 可行性 | 理由 |
| :-- | :-- | :-- |
| 启用格集外 pair | ⛔ **归零** | 见上表。37 个 pair 全部被「已跑 / 已发表 / 已点名 / 不可判定 / 同 NL 组」逐层滤掉 |
| 放宽可判定筛选 | ⛔ **不可且无用** | 规则 4 淘汰的 8 条全是「闭词表不可表达」。放宽等于把**方法边界**报成能力缺口，规则 4 的 rationale 明写禁止。且这 8 条所在 pair 本就被其它规则淘汰，放宽后分母不增 |
| 改变主张构造 | ✅ **唯一可行** | 见下 |

## 唯一可行的方向：改变主张构造

前两条不是「难」，是**语料层面的算术归零**。第三条要回答的是：在只有 2 条可报记录的语料上，
什么主张仍然成立？

已有一个候选，而且它来自同一份数据、强度更高：**共演化溢价** —— 调优格 71.2% vs 留出格 39.7%，
CI 不重叠，Fisher p = 3.7e-05，且方向自保守（若有偏，偏向缩小差距）。它衡量的是
「方法与样本共同演化会把覆盖率抬高多少」，**分母是全部 66 格而不是 2 条记录**，因此不受耗尽影响。

这条主张的意义也不同：它不说「方法能找到 70% 的缺陷」，它说「**任何在自己的调优样本上报覆盖率的
方法，其数字里有约 30 个百分点来自共演化**」—— 这对整个 LLM-for-FM 评测实践都是一条约束，比
单个工具的覆盖率数字更难被推翻。

⚠️ 但这是**主张构造的变更**，属于研究路线决策，须记录：
1. 变更发生在**看到 v22 结果之后**，因此必须双报 —— 原构造（2 条记录）与新构造（66 格）并列，
   不得只报有利的那一个。这正是 §3.5 条款 4「评测口径迁就结果」要防的形态，双报是它的解药。
2. 新构造的分母（66 格）从未参与规则编写吗？**不是** —— 4 个历史格深度参与。但共演化溢价这条
   主张**恰恰以「参与过」为自变量**，污染是被测量的对象而不是混淆因素。这一点必须在报告里写明，
   否则读者会用留出纪律去否证一条以违反留出纪律为研究对象的主张。
