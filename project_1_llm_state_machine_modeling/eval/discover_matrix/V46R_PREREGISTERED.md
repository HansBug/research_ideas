## 一、跑什么

| 项 | 值 |
| :-- | :-- |
| pair | `0000` `0010` `0020` `0030` `0040` `0050`（同一 NL 家族） |

## 二、为什么只跑这六个

`name_in_sentence` 的字段描述与 `REQUIREMENT_REVIEWER_PROMPT` 曾用一条**语料 NL 原句**作为
「并列点名要拆成多行」的例子。该句同时是其中一份制品里的事件声明名，而这六个 pair 共用那条 NL。
按 [CLAUDE.md](../../../CLAUDE.md) §3.5 条款 2，示例取自被测样本本身即构成 prompt 侧泄漏，
该家族上的相关结果不能作为能力度量。例子已换成与语料无交集的合成串。

⛔ **其余 48 个 pair 不重跑。** 它们的 NL 不含该句，泄漏对它们不产生定向提示；
重跑会引入无谓的代码版本混杂。

## 三、判定口径（与 v46 完全一致，不得放宽）

- 命中判据 [HIT_CRITERION.md](./HIT_CRITERION.md)，含 §4 的禁止形态与 §4.2 的引用次数硬判据
- 多报侧裁定 [UNEXPECTED_TAXONOMY.md](./UNEXPECTED_TAXONOMY.md) 五类
- 分母：这六个 pair 上的台账可判记录 × 2 臂 × 3 轮
- 逐格判定要写 `argument` 与 `equivalence_form`，无条目的位不得计入命中

## 四、事前写死的预期与红旗

**预期**：受影响的五条记录（`EIS-0000-02` `EIS-0010-04` `EIS-0020-02` `EIS-0030-03`
`EIS-0040-02`）在 v46 下是 30/30 满命中；去掉定向提示后**命中率下降是正常且预期的结果**，
它衡量的才是真实能力。

**登记档位**（跑前写死，用于跑完后对照，不作为「达标线」）：

| 档 | 这五条记录的命中位 | 读法 |
| :-- | --: | :-- |
| A | ≥ 24/30 | 提示影响小，原数字大体反映能力 |
| B | 12–23/30 | 提示有实质贡献，须按新数字改写结论 |
| C | ≤ 11/30 | 原 6/6 主要由提示造成 |

⛔ **无论落哪一档都照实报**，且必须同时给出 v46 与 v46r 的双份数字。

**回归红旗**（出现任一即须先查代码再谈结果）：

1. 36 格中完成收据 < 36，或出现 `.try` 目录
2. 任一格的降级事件数显著高于 v46 同格
3. 台账里这六个 pair 的其它记录（未受该句影响的）命中位变化 > ±2，
   说明改动的影响面超出了那条例子
4. 多报侧在这六个 pair 上出现 v46 未见过的裁定类别
