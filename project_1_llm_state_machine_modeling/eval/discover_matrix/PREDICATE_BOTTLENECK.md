⚠️ **本文档经历了两次诊断更正，两次都是我猜错、独立裁定纠正。** 保留推理链是为了记住错在哪：

## 二、瓶颈是三个谓词，占 62% 的单元

`state_declared` (38.1%) + `initial_target` (42.9%) + `edge_declared` (45.2%) = **42 / 68 单元
（61.8%）、126 / 204 位**。全体 `hit@1` 51.5% 基本由它们决定。

⚠️ **不要把 100% 那四行当成能力证据**：`cardinality` / `effect_declared` / `guard_distinguishable`
各只有 2 个单元、6 个位，`occupancy_after` 4 个单元。6 个位上的 100% 与 42 个位上的 38% 不可直接比较。
它们只说明「这些谓词没有暴露出问题」，不说明「它们很强」。

## 三、一个假设，及它为什么值得先验证

三个瓶颈谓词恰好是概念上**最简单**的「存在性声明」检查。最简单的最弱，这本身是线索。

区别在于断言的对象：

| 组 | 断言什么 | 需要什么前置知识 |
| :-- | :-- | :-- |
| 100% 组（`occupancy_after` / `cardinality` / `guard_distinguishable`） | 模型里**已有元素的性质** | 定位该元素 |
| 瓶颈组（`state_declared` / `edge_declared` / `initial_target`） | 某个东西**缺失** | **先知道「本该有什么」** |

**要断言缺失，必须先从 NL 正确枚举义务。** 所以假设是：

> 瓶颈在 NL 义务枚举，不在谓词表达力。若成立，该改的是 splitter / 需求抽取阶段，不是谓词词表。

### 已做的第一轮验证：假设的**朴素形式被否证**

查 13 条「两臂三轮全未命中」记录所在格的需求抽取数：0018 → 48、0038 → 48、0048 → 50、0032 → 22。
**需求抽取数并不低** —— 不是「义务完全没被抽出来」这种朴素失败。

所以假设需要收窄为：义务被抽出了，但**没有被转成能证伪它的断言**，或转出的断言选错了谓词 / 锚点。
下一步验证应当查这 13 条对应的 NL 句是否有需求覆盖、该需求是否有断言、断言的谓词与锚点是什么。

## 四之二、真正的解释：需求形成面缺一个模型内在来源

裁定给出的解释是**完美分离**的，且比边界假设深得多。

`wellformedness` 12 条的命中/漏检由一件事决定：**有没有一句 NL 点名了那个缺失元素。**

| | NL 是否点名 | 例 |
| :-- | :-- | :-- |
| **4 条命中** | **全部有** | `0035-01`「The microwave starts in the **DoorShut** state.」；`0043-02`「first transitions to the **PumpState** substate」 |
| **8 条漏检** | **全部无** | `0032` 三句 NL 从不点名默认子态；`0047` 说「There are three region」但不点名初始子态；`0038-06` 的 `nl_evidence` 字段逐字写着「无需 NL 作 oracle」 |

机制在 pipeline，不在边界。`discover/prompts.py` 第 7 行：

> The current FCSTM and inspect diagnostics are orientation evidence only. … **never turn a tool
> warning into a requirement.**

即**方法没有任何模型内在的需求来源**。一条 `layer_basis` 自陈「模型自身即可判定，不需要 NL 也不需要
参考模型」的记录，**按构造不可能被形成为需求** —— 除非 NL 恰好提供了锚点。

📌 **所以 `wellformedness` 层测的是需求形成面的一个洞，不是检测失败。** 这两种说法蕴含完全不同的修法：

- 「方法检测不出合式性缺陷」→ 去改谓词或断言
- 「方法的需求来源只有 NL，纯模型内在的合式性缺陷没有形成路径」→ 去改需求形成阶段

**我原来的诊断（补谓词表达力）指向了错的那个。**

### 一条另有根因的漏检

`EIS-0000-02` **有** NL 锚点（NL 第 5 句），但 prompt **主动禁止**该发现：

> If the model exposes one combined event for a natural-language conjunction or disjunction, use that
> exact declared event and state the representation limitation; **do not invent separate atomic
> events.**

这是 prompt 政策造成的自伤漏检，不是锚点缺失。它与 [GROUND_TRUTH_LIMITATIONS.md](./GROUND_TRUTH_LIMITATIONS.md)
§5 已记录的「可绑定性」偏差同一机制，**现在被量化为整整一层的 8/12**。

### ⚠️ 但「给方法一个模型内在需求来源」本身需要裁定，不能直接做

那条禁令不是疏漏，它防的是「模型照抄工具诊断」。若允许 `UnspecifiedInitial` 这类编译器合成物直接
变成需求，则**发现者等于在转述 pyfcstm 的诊断**，而不是自己发现 —— 那是归因问题，会直接影响能力主张
的含义。

两种可能的正确处置互相排斥，必须先裁定：

1. **放开需求来源** → 但须区分「工具已报的」与「方法自己推出的」，且能力主张只能记后者
2. **收窄层定义** → 承认 pyfcstm 已标记的合式性缺陷不是 discover 的能力目标（它们在上游已被检出），
   把这一层从能力分母移出

## 五、对下一轮的直接含义

**v24 在设计上无法提升覆盖率。** v23 → v24 的唯一实质改动是 `_occupies` 的窗口起点修复，而
`occupancy_after` 的 `hit@1` 已是 100%（12/12）—— 修它不可能提升覆盖。其预期效果相反：把「本该 True
的假 False」变回 True → **少发布发现** → 多报下降，且 `hit@k` **可能小幅下降**（部分命中是靠那些假
False 达成的，`OCCUPANCY_HORIZON_BUG.md` 已警告）。

所以 v24 是**正确性 / 有效性运行**，不是能力运行。这必须写在 v24 报告最前面，否则「指标没涨」会被读成
方法失败，而它实际是「修掉了一个让指标虚高的缺陷」。

### 能力工作的对象已经改变

**不是三个瓶颈谓词。** §四之二 的裁定表明：8/12 的 `wellformedness` 漏检源于**需求形成阶段没有模型
内在来源**，谓词层根本没被调用（实测 `initial_target` 在 `0032` / `0047` 两格调用 **0 次**）。改谓词
对一个从未被调用的谓词无效。

但 §四之二 末尾那个抉择**必须先裁定再动手**：放开需求来源会让发现者变成 pyfcstm 诊断的转述者，那是
归因问题而非工程问题。**在裁定回来之前不改 prompt** —— 无诊断改 prompt 正是前几代次反复发生的事，
而这次连「改哪一层」都还没定。

### 已确认的两种失效模式（修法相反，不可混治）

查 13 条「两臂三轮全未命中」记录在 run1/claude 格的断言层实况：

| 模式 | 条数 | 特征 | 例 |
| :-- | --: | :-- | :-- |
| **A：谓词从未被调用** | 6 | 义务没走到断言层 | `0032-01`（`initial_target` 0 次）、`0047-01/02`（0 次）、`0000-02`（`stays_in` 0 次） |
| **B：谓词调用了却没抓到** | 7 | 断言做了但锚点/参数错 | `0038-03`（`edge_declared` **6 次**）、`0048-02/03`（`initial_target` 1 次） |

A 要改需求形成，B 要改锚定引导。**把两者当成一个问题去改 prompt，必然一边失效。**

### 第三个信号：整格产出量差异极大

`0048` 三轮 `satisfied` = 16/19/16 而 `issue` = 1/1/1 —— 断言跑了十几条**全部返回「没问题」**，而台账
说那里有 5 条缺陷。对比 `0047`：`satisfied` = 1/6/4，**几乎什么都没查**。

这是两种不同的失败：`0048` 是判错，`0047` 是没判。**逐格产出量必须与命中率并列看**，否则会把「没查」
读成「查了没发现」。

## 六、第三种候选根因：attribution 门可能在吃发现（**待裁定**）

追 `0047`「几乎什么都没查」时发现它并非没查。`runs/paper1/matrix-v23/run1/0047-claude` 的产出是
`satisfied=1` / `issue=1` / **`excluded_findings=1` + `excluded_observations=4`** —— 7 个结局里 5 个
被排除。而那条 `excluded_findings` 是：

```
attribution_status: representation_debt
title: REQ-003 并发不变式失败,证据依赖编译器插入的 UnspecifiedInitial(representation_debt)
rationale: ... 其证据(active(UnspecifiedInitial))落在编译器为处理并发缺失而插入的伪状态上,
           attribution 标注为 representation_debt、source_level_claim_allowed=false
```

台账 `EIS-0047-02` 逐字是「CollisionAvoidanceSystem 有三个子状态却没有初始子状态，进入它时落到合成的
UnspecifiedInitial」。**看起来是同一个缺陷** —— 若成立，则方法找到了它、断言了它、判 False 了，
**在发布前被门拦掉**。

那与 §四之二 的「需求未形成」是**不同的失效阶段**，可能是并列的第二个根因。

### 怀疑的机制

attribution 门似乎无法区分两种情形，因为两者表征相同（「证据落在 `UnspecifiedInitial` 上」）：

| 情形 | 该不该排除 |
| :-- | :-- |
| 投影**制造**了缺陷（`EIS-0043-02`：摊平正交区才产生的前提） | 该排除 |
| 投影**暴露**了作者的遗漏（`0047`：作者确实没写初始边，合成态只是症状） | **不该排除** |

若该区分缺失，「作者漏写初始边」这类真缺陷会被系统性吃掉 —— 而它恰是 `wellformedness` 层的主要形态。

### ⛔ 我为此做的两个机械筛都失灵了，不得采信

| 筛法 | 结果 | 为什么不可用 |
| :-- | :-- | :-- |
| 格级共现 | 13 条里 11 条所在格有 `representation_debt`/`unattributed` 排除项 | **格级共现 ≠ 逐记录匹配**。`0048` 的排除项是「AutoFocus 未到达 choice1」这类可达性失败，与 `EIS-0048-02`（Join2 无初始子态）不是同一命题 |
| 元素级重叠 | 仅 1 条重叠 ≥3 | **两个方向都错**：`EIS-0047-02`（语义最清楚）只得 1，因为我把 `UnspecifiedInitial` 当噪声滤掉了 —— 而它正是唯一鉴别性 token；排第一的 `EIS-0047-01` 匹配到「正交并发意图无法表达」，与其缺陷（PlantUML 全局名解析致同名态合并）关系存疑 |

📌 **教训：过滤"噪声" token 时，最鉴别性的那个可能正在里面。** 我滤掉 `UnspecifiedInitial` 的理由是
"它到处都出现"，而它到处出现恰恰因为它是这类缺陷的统一标记。

**重叠高的不一定对，重叠低的不一定错** —— 这个筛只能给裁定者列候选，不能排序，不能计数。已交独立裁定
逐条读原文判定。
