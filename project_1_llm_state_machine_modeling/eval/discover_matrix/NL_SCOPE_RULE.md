# 评测语料的建模对象筛选（NL 层，先验）

## 一、规则

`CLAUDE.md` 把 project_1 的建模对象写死为 $M = (S, E, V, Tr, A)$，并明确
**时钟变量与不变式（$TSM$ 相对 $M$ 多出的 $C$ 与 $Inv$）以及正交区并发语义均排除在建模对象之外**。

据此，一份自然语言规约若要求：

1. **fork / join 伪状态** —— UML 的并发构造，忠实模型需要正交区，而 $M$ 无区分量；
2. **执行时间 / 秒级约束 / 计时器** —— 忠实模型需要时钟与不变式，而 $M$ 两者皆无；

则**该规约的忠实模型无法在 $M$ 中表示**，其 pair 族不进入本方法的评测分母。

判定由 [nl_scope_filter.py](./nl_scope_filter.py) 执行，**只读 `nl.txt`，不读任何模型、产物或结果**。

## 二、为什么筛选单位是 NL 而不是 pair

60 个 pair 由 **10 份不同 NL** 各生成 6 个。**被排除的那份恰好是全部末位为 8 的 pair**，
故可简称为「排除 `00x8`」。

⚠️ 但不要把「NL 索引 = 末位数字」当规律：实测有**两个例外** —— `a391765d` = `0002 0013 0023 0033 0043 0053`、
`9fe426ba` = `0003 0012 0022 0032 0042 0052`，即 `0012` 与 `0013` 在两份 NL 间互换。
其余 8 份按末位对齐，**被排除的那份在干净的一侧**。这是实测事实，由
[test_nl_scope_filter.py](./test_nl_scope_filter.py) 钉住。

| NL | pairs | 并发提及 | 计时提及 | 判定 |
| :-- | :-- | --: | --: | :-- |
| `6af3966c` | `0008` `0018` `0028` `0038` `0048` `0058` | **11** | **17** | ✗ **排除** |
| `934e19bd` | `0005` `0015` `0025` `0035` `0045` `0055` | 0 | 3 | ✓ |
| 其余 8 份 | —— | **0** | **0** | ✓ |

**逐 pair 判定会留下「挑掉某几格」的空间；按 NL 判定没有** —— 一份 NL 的 6 个 pair 同进同出。

## 三、⚠️ 这不是「排除表现差的样本」——四条证据

1. **判据先验**：只读 NL 文本，在任何运行之前即可判定，与结果无关。
2. **被排除集里含优于均值的样本**：`0018` 的 `hit@1` = 12/18 = **66.7%**，高于全量均值 53.9%。
   若目的是挑数字，不会把它一起排掉。
3. **分布双峰且间隔极大**：并发 11 vs 0（其余 9 份全为 0），计时 17 vs 3 vs 0。
   不存在需要「调阈值」的中间地带。
4. **阈值不敏感（可复算）**：`python nl_scope_filter.py --sensitivity` 实测
   **154 / 187 组阈值给出完全相同的 6 个 pair**（并发 1–11 × 计时 4–17 全域一致）。
   唯一断点在计时 3/4 之间 —— 取 ≤ 3 会把 `934e19bd` 也拉进来变成 12 个 pair。

## 四、⚠️ 必须一并说明的代价

我逐条读过被排除三个格集 pair（`0018` / `0038` / `0048`）的 27 条台账记录，
**没有一条的主张真正需要并发语义** —— 它们多是「元素恰好叫 fork/join」的结构缺陷
（边声明、containment、守卫位置、命名作用域、数量断言）。

📌 **所以排除的是「规约」（因其要求 $M$ 表达不了的特性），不是「发现」。**
按 NL 整体排除会连带排除一批在范围内的结构主张。这是诚实的代价，论文中必须写明。

按记录逐条排除的替代方案实测**不改变任何数字**：符合「主张需要并发语义」的记录数为 **0**。

## 五、双份数字（报告义务）

**任何报告不得只给筛选后的数字。** 三个数必须并列：

| 代次 | 全量（含 `00x8`） | **NL 筛选后** | 被排除部分自身 |
| :-- | --: | --: | --: |
| v23 | 100/204 = 49.0% | 78/120 = **65.0%** | 22/84 = 26.2% |
| v24 | 110/204 = 53.9% | 83/120 = **69.2%** | 27/84 = 32.1% |

两个口径下 v23 → v24 都上升（+4.9pp / +4.2pp），**方向一致**，故筛选未改变代次间的趋势结论。

⚠️ 上表的判定沿用各代次**原有**标注（v23 的 249 条、v24 的 215 条），**未重判**。
判定侧此后有三处修复（`hits:X+Y` 多别名、`boundary` 前置、`duplicate-of` 三段式）尚未反映在这些数字里，
因此它们是**下界**。
