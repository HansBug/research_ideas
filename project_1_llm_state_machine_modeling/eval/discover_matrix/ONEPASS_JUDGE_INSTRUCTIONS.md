# 一次标注判定指令（**交给判定者的唯一文件**）

> ## ⚠️ 本文件为什么单独存在
>
> 此前指令与维护记录在**同一个文件**里，用一个 `## ⛔` 标题分隔，并在指令里写明「只读到该标题之前」。
>
> **那不是边界，是约定。** 一次 `Read` 调用返回整个文件 —— v25 的重判中，标注者 B 诚实披露它读了全文，
> 因而看到了两处往轮判定（一条 issue 的标题与命中结论、一条争议的裁定），并指出自己约 14 条判断可能
> 受此影响。**它的标注因此作废。**
>
> 这是同一类泄漏的**第四次**：改动日志 → `HIT_CRITERION.md` → `annotation_*.json` → 同文件内的分节。
> 前三次修的是「哪些文件不能读」，第四次修的是「文件内读到哪」—— **两者都是约定。**
>
> 📌 **唯一的结构性修法是物理拆分**：维护记录移入 `ONEPASS_JUDGE_MAINTENANCE.md`，本文件**物理上不含**
> 任何往轮判定。判定者读全本文件也不会被污染。

## 为什么这份指令必须落成文件

同 `BLIND_JUDGE_PROMPT.md` 的理由：上一代次两次盲判**给的指令不同**，导致偏倚方向不同，而那个差异
**不能归因于任何实验变化** —— 它可能完全来自我改了指令。混杂一旦引入只能披露、无法消除。

所以指令固定在本文件、逐字使用，改口径必须改本文件并记录改动。

## 与 `BLIND_JUDGE_PROMPT.md` 的分工

| | `BLIND_JUDGE_PROMPT.md` | 本文件 |
| :-- | :-- | :-- |
| 判定单元 | (台账记录, 臂) | **(格, 轮)** |
| 问的问题 | 这条缺陷被发现了吗 | **这条 issue 是什么** |
| 能派生 | 覆盖侧 | **覆盖侧 + 多报侧** |

后者能派生前者，前者不能派生后者。**双计在前一种结构里不可表达**，所以也不可检查 —— 这是换结构的
实质收益。

## 指令正文（以下内容逐字交给判定者，仅替换 `{{SAMPLE_PATH}}`）

你是一个**独立的标注者**。样本里每个 unit 是「一个模型 + 一轮运行」，你要对该 unit 里的**每一条已发布
issue** 恰好给一个标签。

### 输入

只读 `{{SAMPLE_PATH}}`

### ✅ 白名单：**只允许读这两个文件**

    {{SAMPLE_PATH}}                  ← 你要标注的样本
    HIT_CRITERION_FOR_JUDGES.md      ← 命中判据（实例全部合成，不含语料内容）

**除这两个之外，不读本目录或仓库里的任何文件。** 不需要列举禁止项 —— 白名单之外一律不读。

⚠️ **为什么改成白名单**：此前用的是黑名单（枚举 `key.json`、`verdicts/`、`V2*.md` 等十来项），
**同一类泄漏漏了三次**：第一次漏了指令文件自身的改动日志；第二次漏了 `HIT_CRITERION.md`（它被承诺
「不含分组信息」而实际含往轮判定）；第三次漏了刚入库的 `annotation_*.json`（上一轮的完整答案）。

**按形态列举永远漏**（这正是仓库纪律 §3.5.-1 自己说过的）。白名单没有这个失效模式。

📌 **特别注意**：`HIT_CRITERION.md`（无 `_FOR_JUDGES` 后缀）**不在**白名单里 —— 它是维护版本，含真实
语料实例。你要读的是 `HIT_CRITERION_FOR_JUDGES.md`。

若你读了白名单之外的任何文件，在最终输出里如实说明。

判据文件 `HIT_CRITERION_FOR_JUDGES.md` 是 `hits:` 标签的标准来源。它的实例**全部是合成占位名**
（`Sys.*`），不含任何语料内容。

### 每个 unit 有什么

- `expected_defects`：该模型的**期望缺陷清单**（人工台账），每条带 `record_alias` 与 `statement`
- `published_issues`：该轮**全部已发布发现**，每条带 `issue_uid`、`title`、`detail`

### 五个标签，每条 issue 恰好一个

| 标签 | 含义 |
| :-- | :-- |
| `hits:<record_alias>` | 它主张的缺陷与该期望缺陷**语义同一**（按 `HIT_CRITERION.md` 的四种形态） |
| `grounded-extra` | 对着 NL 站得住，但**不对应本 unit 任何**期望缺陷 |
| `boundary` | 涉**时钟 / 时间约束 / 正交区并发**（fork-join 需多分支同时到达）—— 不在本研究建模对象内 |
| `fabricated` | 在模型上**不成立**（说缺的其实有、说错的其实对），或 NL 上**无依据** |
| `duplicate-of:<issue_uid>` | 与本 unit **另一条** issue 是同一命题 |

**一条 issue 只能有一个标签。** 若你觉得某条同时属于两类，选**更靠前**的那个（表中顺序即优先级），
并在依据里说明另一类的成分。

> ### ⚠️ `boundary` 是优先级的例外，必须先判
>
> 上一轮一位标注者指出：**绝大多数 `boundary` 类 issue 同时「对着 NL 站得住」**（时钟、时间约束、
> fork-join 多分支同时到达在 NL 里都写着），而 `grounded-extra` 在表中排在 `boundary` 之前 ——
> 严格按「选更靠前的」会使 **`boundary` 永不可用**，25 条全部塌成 `grounded-extra`。
>
> 那不是设计意图。**`boundary` 判的是「该主张是否在 paper1 的断言对象内」，与「它是否站得住」是两个
> 独立维度**，不该由同一条优先级链裁决。
>
> 📌 **执行顺序：先判越界，再判其余。** 若一条 issue 的**实质内容**是时钟 / 时间约束 / 不变式 /
> 正交区并发（含 fork-join 多分支同时到达），一律 `boundary`，**不论它对着 NL 是否站得住**。
> 只有确认在界内之后，才在剩下四个标签间按表中优先级选。

### `hits:` 的判据：严格按 `HIT_CRITERION.md`

该文件 §3 列出语义同一性成立的**四种**形态，四种都算：

1. **直接对应** —— 两个命题说同一件事，只是谓词不同
2. **合取项之一** —— 期望命题是 all(...)，产出证明其中一个合取项为假
3. **负向命题的正向对偶** —— 期望说「不应存在错的边」，产出说「应存在对的边」
4. **蕴含更根本的原因** —— 产出命题为假蕴含期望命题为假，且定位到更上游

§4 列出**不**成立的形态：不同缺陷共用状态名；更弱的命题；反向蕴含。

**两条告诫，请同等对待：**

- **第 ④ 种形态容易被误判为不命中** —— 产出定位到更上游的缺失元素时，它仍然蕴含期望命题。
- **① ～ ④ 四种形态同样容易被过度援引**，尤其 ③ 与 ④。**说不清「产出为假如何蕴含期望为假」这条逻辑
  链，就不要用 `hits:`。** 元素重叠、区域相同、都提到同一个状态名，**都不是**蕴含关系。

### `fabricated` 的判据

判 `fabricated` 必须能指出**具体哪一条不成立**：引用模型文本的具体行，或指出 NL 里找不到对应要求。

### ✅ 本样本**含 NL 原文** —— 请用它

顶层 `nl_by_model[<model_alias>]` 是该模型对应的 NL 需求原文，**按句编号**。每个 unit 的 `nl_ref`
字段指向它。

**判 `fabricated`「NL 上无依据」这一支时，必须引用具体是哪一句、以及为什么它不支持该 issue。**
不要凭印象说「NL 没要求」。

⚠️ **仍然缺的是模型源文**（`.fcstm`）。所以判「在模型上不成立」这一支只有两类证据：

- (a) 台账 `statement` 自身对制品的陈述与该 issue 矛盾
- (b) 同一 `model_alias` 的**另一轮** issue 对制品文本的陈述与该 issue 矛盾（模型按格固定、轮次只换
  分析运行，故跨轮制品陈述可互证）

**两类都没有、且义务能追到某句 NL 的，一律给 `grounded-extra`，不要给 `fabricated`。** 宁可漏判虚构，
不可凭印象判虚构 —— 前者使计数成为下界（可诚实报为「≥」），后者使计数不可信。

📌 **为什么加了 NL**：v1 的两位标注者在 17 条上分歧，其中 **12 条**塌缩成同一个可核查的事实问题
（NL 的某句话该怎么读）。**样本里没有 NL，他们无从核对**。加 NL 就是为了消掉这一整类分歧。

⚠️ 此处原本写明了那个争议的具体命题与「哪一方错」—— 已删。**判据文件与指令都不得含往轮的具体裁定**，
否则你会被预装答案（v24 公平性 review 实证）。

两类特别容易判错：

- **标识符 vs 散文**：模型用 `Door_Closed`，NL 用 "the door can be closed"。**归一化后再判**，不要
  因为字面不同就说 NL 无依据。
- **元素对但命题反**：产出触及了正确元素却主张了相反的事。这类若在模型上不成立就是 `fabricated`，
  不要因为「提到了正确的东西」而放过。

### 输出格式

对每个 unit 出一块：

```
unit_id: C999
  C999-I01 | hits:PAIR-Z-REC-02 | ④ | 无该状态则期望义务不可能成立
  C999-I02 | fabricated         | —  | 模型已声明该状态，「缺失」不成立
  C999-I03 | boundary           | —  | 依赖 join 需两分支同时到达
  未被任何 issue 标 hits 的期望缺陷：PAIR-Z-REC-01, PAIR-Z-REC-03
```

⚠️ 上面的 `C999` / `PAIR-Z-*` 是**不存在的**占位 id —— 格式示例不得使用样本里的真实 id，否则示例里的
标签会被当成提示。

**每个 unit 的每一条 issue 都要有一行**，不得省略、不得写「同上」。第三列填 ①②③④（仅 `hits:` 需要）
或 `—`。最后一行列出该 unit 里**没有**被任何 issue 命中的期望缺陷。

最后给：

1. 五类标签各自的总数
2. 用第 ④ 形态判 `hits:` 的清单，每条一句蕴含链
3. 最不确定的 5 条及原因
4. 若某条期望缺陷**按构造不可判定**（例如它自己声明该缺陷无法用现有谓词表达），单独列出
