## 五、判定方法本轮改了：直接盲判

- 上一代次全量盲判：κ = **0.883**、覆盖 **100%**、偏倚**单向**（三带净偏全 ≤ 0，原判系统性偏严）
- 可报带 `hit@1` 66.7% → **91.7%**、`hit@3` 75% → **100%**、`hit@all` 50% → **75%**
- 因此 v23 **直接盲判**（两个独立盲判者判同一批，κ 在两者之间算），不再「我先判再盲检」
- ⚠️ 披露：两次盲判**指令不同**（前一次我自写口径、未让读判据文件；后一次让读了）。所以
  「带相关偏倚 → 单向偏倚」的变化**不能归因于覆盖率提高**

## 七、目标两半不独立（必须写死）

覆盖率上升与多报下降是**同一事件被数了两次**：10 个位从「未命中」翻成「命中」，即至少 10 条此前
计入「台账外」的发现其实是命中。

    台账命中    79 → 至少  89
    台账外     160 → 至多 150

**发现本身一条没变，变的只是分类。** 推论：

1. 不得把两侧的改善当成两个成果
2. 判据放宽会同时抬高覆盖、压低多报；**只优化一半的改动会在另一半上自动「改善」**

这解释了上一代次那个判据不一致为什么能长期存在：它在两个指标上都产生了看起来有利的效果。

### 第 5 项的结论

92 条（v22 为 16 条）全部是同一条消息：`'trigger' must be a non-empty path`，且 76/92 集中在
fork/join 伪状态族那个 pair。

成因：该模型大量迁移**本就无触发**（`fork1 -> AutoFocus`、`Junction3 -> join2`、`Join2 -> Fork2`），
因为伪状态之间的流转不带事件。生产者用 `occupancy_after` / `edge_declared` 表达这些进展时必须填
`trigger`，而 NL 也没给事件名 → 填空 → 被谓词层拒。

所以它是**「用需要触发器的谓词去表达无触发的进展」**这个结构性错配的症状，与「归因层把并发造成的
False 标成 `safe`」同族：**伪状态密集的模型与这套以事件响应为中心的谓词表存在系统性不匹配**。

v23 比 v22 多 76 条，是因为本轮在该 pair 上写了更多需求、修订轮次也更多 —— **产量变化的副产品，
不是新缺陷**。

📌 关键：这 92 条**全部被谓词层正确拒答**（计入 `refuse@1`），**没有一条变成虚构发现**。所以它是
吞吐损耗而非精度问题 —— 报告里应放在 `refuse@1` 一栏，不放在多报一栏。
