## 二、这个测量为什么是决定性的

**占位符的存在不区分命中与漏检 —— 4 条命中和 4 条漏检全都有。**

因此「pyfcstm 已经报了这个缺陷」对**两侧同样成立**。这排除了一种此前隐含的读法（「命中的是方法自己
推出的、漏检的才依赖工具诊断」），并直接推出：

> **当前 `wellformedness` 层的 4 条命中，同样是 pyfcstm 已经标记的缺陷。**

## 三、裁定

**采用路线 2，判据落在子类而非整层：**

> 凡「机器证据是投影在其主张 scope 内合成的占位符（`UnspecifiedInitial` / `InvalidInitial*`）」的
> 期望缺陷，**移出发现能力的分子与分母**，单列为「上游可检出」。

后果（必须与数字一起报，不能只报结论）：

| 项 | 值 |
| :-- | --: |
| 从 `wellformedness` 能力口径移出 | **8 / 12** |
| 其中**当前命中**的 | **4**（`0035-01` 6/6、`0043-02` 5/6、`0038-06` 2/6、`0048-01` 1/6） |
| 其中当前漏检的 | 4（全 0/6） |
| 留在能力口径内 | `EIS-0000-01`、`EIS-0029-02`、`EIS-0000-02`，以及待判的 `EIS-0032-01` |

📌 **这是一次向下的修正 —— 它减少方法可以主张的东西。** 而此前两次 src 尝试都是想**提升**这一层的
覆盖率：方向从一开始就错了，因为这一层的分母本身就该收窄。

### 为什么不选路线 1

路线 1 要求「区分工具已报的与方法自推的，能力只记后者」。上表表明该区分在本层的**实际效果**是：
8 条里 8 条都属前者。**即路线 1 执行到底会得到与路线 2 相同的分子，只是多绕一圈**，且中间过程需要
在 prompt 里描述占位符的语义 —— 而两次 review 已证明那必然滑向答案形状泄漏
（见 [V25_SYNTHESIZED_PLACEHOLDER_PROPOSAL.md](./V25_SYNTHESIZED_PLACEHOLDER_PROPOSAL.md) 开头）。

## 四、⚠️ 未解项与生效条件

1. **`EIS-0032-01`（1/9）未解**：它的 statement 用「三个 Region」作描述而非字面元素名，
   结构化查询按 scope 名匹配不到。需要读该 pair 的实际 region 元素名再判。
   **1/9 不足以改变结论方向，但它必须被解掉才能定稿。**
2. **本裁定尚未改动任何已发布数字。** 它改变的是口径，按 §3.6「更正就地改原件」，
   一旦生效需同时更新 v22–v24 的相关 comment 与 gist，并给出口径变更前后的**双份数字**。
3. **需要一次独立核验**：本测量由我单人完成，而它会下调方法的能力主张。
   按 §3.5.0「运行后 review」的要求，这类会改变结论的测量应由独立方复算。
4. **`InvalidInitial*` 与 `UnspecifiedInitial` 性质不同**（`nodes.py:3527`：前者是作者写了入口但指错、
   后者是作者什么都没写）。上表把两者一并计入，**这一步需要论证**：若只算 `UnspecifiedInitial`，
   移出数变为 6/12（命中侧 3、漏检侧 3）。**两个口径都要报。**

**v25 不应再尝试提升 `wellformedness` 层的覆盖率。** 该层的能力工作对象是收窄后剩下的
3–4 条，而它们的漏检根因各不相同：

| 记录 | 根因 | 是否可在本代次处理 |
| :-- | :-- | :-- |

它把「该层覆盖率上不去」从一个待解决问题改成了一个**已解释的口径问题**。
