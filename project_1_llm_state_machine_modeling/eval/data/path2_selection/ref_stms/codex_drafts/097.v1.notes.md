# Codex Draft Notes — Case 097

## 1. 设计选择

- mode 列表：
  - `START_STATE`：来自 STM §1 摘录 B / expansion [E3]，表示 UAV landed，GPS、RTK、cameras initialized。
  - `SEARCH`：来自 STM §1 摘录 B / [E5]-[E7]，表示 low-altitude semiellipse search、very low speed/acceleration、both UAV detectors active。
  - `FOLLOW_LONG_RANGE`：来自 STM §1 摘录 B / [E8]-[E9]，表示 long-range following 和 5 m XY fast approach。
  - `FOLLOW_SHORT_RANGE`：来自 STM §1 摘录 B / [E10]-[E11]，表示 short-range following、4 m target standoff、disable Long-Range UAV Detector。
  - `CATCH_BALL`：来自 STM §1 摘录 B / [E12]-[E13]，表示 move toward ball detection and align ball with gripper。
  - `PLANNED_TRAJECTORY`：来自 STM §1 摘录 B / [E14] 的 "continues following the planned trajectory"，用于显式覆盖 ball leaves camera FOV 后的行为。
  - `LAND`：来自 STM §1 摘录 B / [E17]，表示 land at a given position and mission ends。
- event 列表：
  - `START_MISSION`：来自 STM §1 摘录 C / [E4]。
  - `LongRangeDetectionFrame` / `LongRangeMissFrame`：来自 [E8] 的 "detections on 5 consecutive frames" 与 [E9] 的 "new long-range detection"。
  - `ShortRangeDetectionFrame` / `ShortRangeMissFrame`：来自 [E10] 的 "detections on 4 consecutive frames"。
  - `BALL_DETECTED`：来自 STM §1 摘录 C / [E12]。
  - `BALL_LEAVES_CAMERA_FIELD_OF_VIEW`：来自 STM §1 摘录 B / [E14]。
  - `SUCCESSFUL_CATCH`：来自 STM §1 摘录 C / [E16]。
- variable 列表：
  - `detection_count`: `int = 0`，在 `SEARCH` 中表示 long-range detections，在 `FOLLOW_LONG_RANGE` 中表示 short-range detections；阈值 3/5 来自 [E8]，2/4 来自 [E10]。
  - `frame_window`: `int = 0`，与 `detection_count` 共同表达 consecutive frame window；阈值来源同上。
  - `no_new_detection_frames`: `int = 0`，表达 [E15] 的 five consecutive frames with no new detections。
  - `detection_seen_this_frame`: `int = 0`，用于让 detection event cycle 清零 `no_new_detection_frames`，避免 pyfcstm transition 后 during 立即把该帧误计为 missed frame。
- transition 设计：
  - `START_STATE -> SEARCH :: START_MISSION`：operator order starts mission，来源 [E4]。
  - `SEARCH -> SEARCH :: LongRangeDetectionFrame/MissFrame`：累计 long-range 5-frame window，来源 [E8]。
  - `SEARCH -> FOLLOW_LONG_RANGE : if [detection_count >= 3 && frame_window >= 5]`：Table 1 `LONG_RANGE_UAV_DETECTED` 的数值语义，来源 [E8]；目标 state entry 触发 5 m XY approach，来源 [E9]。
  - `SEARCH -> SEARCH : if [frame_window >= 5 && detection_count < 3]`：未达到 3/5 时重置 long-range window，防止把失败窗口无限累积成成功窗口。
  - `FOLLOW_LONG_RANGE -> FOLLOW_LONG_RANGE :: LongRangeDetectionFrame`：每个 new long-range detection 重新触发 fast 5 m approach，来源 [E9]。
  - `FOLLOW_LONG_RANGE -> FOLLOW_LONG_RANGE :: ShortRangeDetectionFrame/MissFrame`：累计 short-range 4-frame window，来源 [E10]。
  - `FOLLOW_LONG_RANGE -> FOLLOW_SHORT_RANGE : if [detection_count >= 2 && frame_window >= 4]`：Table 1 `SHORT_RANGE_UAV_DETECTED` 的数值语义，来源 [E10]；目标 state entry 表达 4 m standoff 和 disable long-range detector，来源 [E11]。
  - `FOLLOW_LONG_RANGE -> FOLLOW_LONG_RANGE : if [frame_window >= 4 && detection_count < 2]`：未达到 2/4 时重置 short-range window。
  - `FOLLOW_SHORT_RANGE -> CATCH_BALL :: BALL_DETECTED`：ball detection triggers catch phase，来源 [E12]-[E13]。
  - `CATCH_BALL -> PLANNED_TRAJECTORY :: BALL_LEAVES_CAMERA_FIELD_OF_VIEW`：ball leaves FOV 后继续 planned trajectory，来源 [E14]。
  - `CATCH_BALL/PLANNED_TRAJECTORY -> LAND :: SUCCESSFUL_CATCH`：laser sensor inside gripper detects ball, then land，来源 [E16]-[E17]。
  - `FOLLOW_LONG_RANGE/FOLLOW_SHORT_RANGE/CATCH_BALL/PLANNED_TRAJECTORY -> SEARCH : if [no_new_detection_frames >= 5]`：`DETECTION_LOST` 的 5-frame recovery path，来源 [E15]。

## 2. C-axis grounding 使用情况

- **C1 (周期执行)**: 用 — 在 `FOLLOW_LONG_RANGE`、`FOLLOW_SHORT_RANGE`、`CATCH_BALL`、`PLANNED_TRAJECTORY` 的 `during {}` 中把 simulator cycle 作为 frame，累计 [E15] 的 no-new-detection consecutive frames；scenarios 覆盖了 ≥3 cycles 和 5-frame boundary。
- **C2 (数值守卫)**: 用 — `detection_count >= 3 && frame_window >= 5` 对应 [E8]；`detection_count >= 2 && frame_window >= 4` 对应 [E10]；`no_new_detection_frames >= 5` 对应 [E15]。
- **C3 (forced fault)**: 未用 — 原文只有 `DETECTION_LOST` 这种具体 recovery event/condition，没有 any-state global fault、emergency stop 或 `! * -> Error` 语义。
- **C4 (硬件)**: 用 — `InitializeGpsRtkCameras` 对应 [E3]；`CommandSemiellipseSearchLowAltitude` 和 `ActivateBothUavDetectors` 对应 [E5]-[E7]；`CommandFastFiveMeterXyApproach` 对应 [E9]；`MaintainFourMeterTargetStandoff` 和 `DisableLongRangeUavDetector` 对应 [E11]；`CommandMotionTowardBallDetection`、`AlignBallWithGripper`、`CommandArduinoNanoGripperManeuver` 对应 [E13] / [E18]；`ContinuePlannedTrajectory` 对应 [E14]；`LandAtGivenPosition` 对应 [E17]。

## 3. 与 NL 的对应关系

- expansion NL [E1]: "search, follow, and grasp a moving object" → root `SearchFollowCatchMissionController` 及 `SEARCH -> FOLLOW_* -> CATCH_BALL -> LAND` 主线。
- [E2]: "solution based on a FSM" → 采用 flat FSM；不引入 hierarchy、orthogonal region 或 global forced transition。
- [E3]: "UAV is landed; GPS, RTK, and cameras are initiated" → `START_STATE` 和 `enter abstract InitializeGpsRtkCameras`。
- [E4]: `START_MISSION` → `START_STATE -> SEARCH :: START_MISSION`。
- [E5]: semiellipse search near long-axis border and middle → `SEARCH.enter abstract CommandSemiellipseSearchLowAltitude`。
- [E6]: low altitude / uniform sky background → 同一 SEARCH abstract action 中体现 camera pointing sky 的 mission profile。
- [E7]: very low speed/acceleration and both detectors active → `SEARCH.enter abstract ActivateBothUavDetectors`。
- [E8]: 3 detections in 5 frames → `SEARCH -> FOLLOW_LONG_RANGE : if [detection_count >= 3 && frame_window >= 5]`。
- [E9]: 5 m XY fast approach on each new long-range detection → `FOLLOW_LONG_RANGE.enter abstract CommandFastFiveMeterXyApproach` 和 `FOLLOW_LONG_RANGE -> FOLLOW_LONG_RANGE :: LongRangeDetectionFrame`。
- [E10]: 2 detections in 4 frames → `FOLLOW_LONG_RANGE -> FOLLOW_SHORT_RANGE : if [detection_count >= 2 && frame_window >= 4]`。
- [E11]: 4 m from target and disable long-range detector → `FOLLOW_SHORT_RANGE.enter abstract MaintainFourMeterTargetStandoff` 与 `DisableLongRangeUavDetector`。
- [E12]: ball detected → `FOLLOW_SHORT_RANGE -> CATCH_BALL :: BALL_DETECTED`。
- [E13]: align ball with gripper → `CATCH_BALL.enter abstract CommandMotionTowardBallDetection` 和 `AlignBallWithGripper`。
- [E14]: continue planned trajectory after ball leaves FOV → `CATCH_BALL -> PLANNED_TRAJECTORY :: BALL_LEAVES_CAMERA_FIELD_OF_VIEW` and `PLANNED_TRAJECTORY.enter abstract ContinuePlannedTrajectory`。
- [E15]: no new detections in 5 consecutive frames → `during {}` updates `no_new_detection_frames`; `>= 5` guards return to `SEARCH`。
- [E16]: laser sensor inside gripper detects ball → `SUCCESSFUL_CATCH` transitions from `CATCH_BALL` / `PLANNED_TRAJECTORY` to `LAND`。
- [E17]: land and mission ends → `LAND.enter abstract LandAtGivenPosition`。
- [E18]: servomotor through Arduino Nano for gripper closing/opening → `CATCH_BALL.enter abstract CommandArduinoNanoGripperManeuver`。

## 5. 与 STM.md 表述的偏差（如有）

- `PLANNED_TRAJECTORY` 不是论文列出的 FSM state 名，而是从 [E14] 的行为句中抽出的显式 mode；这样 scenario 可以直接断言 ball leaves camera FOV 后仍继续 planned trajectory。
- `LongRangeDetectionFrame`、`LongRangeMissFrame`、`ShortRangeDetectionFrame`、`ShortRangeMissFrame` 是为了在 pyfcstm 中显式验证 3/5 与 2/4 阈值而规范化出的 frame-level events；论文 Table 1 的 `LONG_RANGE_UAV_DETECTED` / `SHORT_RANGE_UAV_DETECTED` 被编码为相应 numeric guards。
- `DETECTION_LOST` 没有声明为一个显式 event；其原文语义 "No new detections in 5 consecutive frames" 被编码为 `no_new_detection_frames >= 5` guard，以便 scenarios 覆盖阈值边界。
