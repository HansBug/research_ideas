## pyfcstm DSL syntax cheat-sheet

> Every code snippet below has been verified to parse + sem via the actual
> pyfcstm runtime. Follow the patterns exactly.

### Top-level structure (REQUIRED)

```
def int counter = 0;             // variable definitions go BEFORE the root state
def float temp = 25.0;
state Root { ... }               // EXACTLY ONE top-level state
```

### State definitions

```
state A;                                              // leaf, declaration only
state B { during { counter = counter + 1; } }         // leaf with lifecycle action
state Composite {
    [*] -> Child;                                     // composite MUST have an initial transition
    state Child {
        enter { counter = 0; }
        exit  { counter = 0; }
        enter abstract InitHardware;
    }
}
pseudo state Junction;                                // non-stoppable routing
```

### Transitions — CRITICAL SYNTAX (event and guard are MUTUALLY EXCLUSIVE)

| form | event path | meaning |
| --- | --- | --- |
| `S1 -> S2 :: Tick` | `<Parent>.S1.Tick` | LOCAL — event in source-state namespace |
| `S1 -> S2 : Tick` | `<Parent>.Tick` | CHAIN — event in enclosing parent namespace |
| `S1 -> S2 : /Sub.Tick` | `<RootName>.Sub.Tick` | ABSOLUTE — `/` itself = Root; do NOT repeat root name |
| `S1 -> S2 : if [expr]` | (no event) | GUARD — leading `:` REQUIRED |

ALL VALID:

```
A -> B;                                              // bare
A -> B effect { counter = 0; };                      // effect-only
A -> B :: Tick;                                      // event-only (local)
A -> B :: Tick effect { counter = 0; };              // event + effect
A -> B : if [counter > 0];                           // guard-only (leading `:` required)
A -> B : if [counter > 0] effect { counter = 0; };   // guard + effect
[*] -> A;                                            // initial transition
[*] -> A :: Start effect { counter = 0; };           // initial with event + effect
```

INVALID (parser rejects):

```
A -> B :: Tick if [counter > 0];                     // ✗ event + guard cannot coexist
A -> B if [counter > 0];                             // ✗ guard MUST have leading `:`
```

### Forced transitions (`!` prefix) — global escapes

```
! Source -> Target :: Event;                          // descendants of Source -> Target on Event
! * -> ErrorHandler :: Error;                         // ANY descendant -> ErrorHandler on Error
! * -> ErrorHandler : if [error_flag > 0];            // ANY descendant -> ErrorHandler when guard true
```

**CRITICAL — forced transitions DO NOT support `effect { ... }` blocks.**
Grammar enforces forced transitions to terminate with `;` only. If the
upstream `transitions` list has `is_forced: true` together with a non-null
`effect` field, you MUST relocate that effect into the target state's
`enter { ... }` lifecycle action instead:

```
// WRONG (parse error):  ! * -> Red :: Reset effect { timer = 0; };
// RIGHT:
state Red {
    enter { timer = 0; }
}
! * -> Red :: Reset;
```

### Lifecycle / abstract actions

```
state A {
    enter { counter = 0; }              // enter operation
    during { counter = counter + 1; }   // during (leaf only)
    exit  { counter = 0; }              // exit operation

    enter abstract InitHardware;        // enter abstract (no body, declares hook name)
    exit abstract CloseHardware;        // exit abstract
}
```

### Variable expressions

Arithmetic: `+ - * / % **`. Bitwise: `<< >> & ^ |`. Comparison: `< > <= >= == !=`.
Logical: `&& || !` (also `and / or / not`). Ternary: `(cond) ? a : b`.
Math functions: `sin / cos / tan / sqrt / abs / log / exp / floor / ceil / ...`.
Inside `effect { ... }` you may use nested `if [cond] { ... } else if [...] { ... } else { ... }`.

## Assembly rules

1. **One root state**. Pick a meaningful name based on the system (e.g.
   `TrafficLightController`, `ElevatorController`, `RobotSupervisor`). If
   the states list has hierarchy / parallel regions, model the top-level
   sibling group as the root's direct children.
2. **Variables first**: emit all `def int / def float ...;` lines BEFORE
   the `state Root { ... }` block.
3. **Initial transition**: every composite state needs `[*] -> SomeChild;`
   pointing at the first non-pseudo child. Pick the state with `from: "[*]"`
   in the transitions list, or the first state in the states list.
4. **States in order**: declare each state with its lifecycle actions
   (enter / during / exit / enter abstract / exit abstract / etc.) attached.
   Composite states get an explicit `[*]` initial transition + child state
   declarations inside their `{ ... }` body.
5. **Transitions**:
   - Forced transitions (`is_forced: true`) go at the TOP of the enclosing
     state's body, with `!` prefix.
   - Non-forced transitions go inside their source state's enclosing scope
     (typically the root state's body).
   - `from: "[*]"` => emit `[*] -> Target;`.
   - `from: "*"` (with `is_forced: true`) => emit `! * -> Target ... ;`.
   - If a transition has both event and guard in the input (shouldn't
     happen if Step 4 obeyed the constraint), drop the event and keep the
     guard.
6. **Actions** (from Step 5 list): attach each action to its `state` in the
   correct `slot`. For `kind: "abstract"`, emit `<slot> abstract <content>;`.
   For `kind: "operation"`, emit `<slot> { <content>; }`.
7. **Pseudo states** (`is_pseudo: true` in states list): use `pseudo state X;`.

## Rules

1. **Output ONLY the pyfcstm DSL** — no prose, no markdown code fences, no
   commentary.
2. **No new model elements**: do not add states / events / variables /
   transitions / actions beyond what the upstream lists describe.
3. **Faithfully translate**: each transition / action in the input should
   appear in the output, mapped to the correct DSL syntax.
4. **Validate syntax mentally** before output: every transition must have
   AT MOST one of (event | guard), guards need leading `:`, forced uses
   `!` prefix, composite states need `[*] ->` initial transition.
