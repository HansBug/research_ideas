# 博士毕业要求情报库

> 信息更新时间：`2026-06-16 23:20:00`（Asia/Shanghai）

本目录用于保存和整理 2022 级计算机学院**学术型博士**毕业 / 学位申请相关政策、邮件证据、非正式讨论线索和待补问题。它是毕业成果认定的证据库，不是行政最终解释；任何结论都必须能回到政策原文、老师邮件或加密 raw 档案复核。

**本 README 不是单纯入口索引，而是给博士生本人做毕业成果规划时优先阅读的核心决策页。** 读完本页应能初步判断：2014 版和当前新版候选各自要求什么、哪条路径更可能适合当前成果、哪些点必须找老师确认、哪些成果不应作为主路径冒险。

## 1. 一句话结论

1. **两版都可作为候选方案**：学院老师 2026-06-09 邮件已确认，2022 级博士生可在 2014 版与当前新版创新成果要求之间选择参照；因此后续规划必须同时评估 2014 版和新版候选，不应只押一边。
2. **2014 版更像“数量 + 收录源”路径**：计算机学院条款要求论文不少于 3 篇、至少 1 篇外文，并满足 `SCIE 2 篇`，或 `SCIE 1 篇 + EI/CPCI-S 2 篇且至少 1 篇为 EI 收录源期刊论文`。
3. **新版候选不要用低参考价值的顶刊/高被引条款做常规规划，而要直接按 CS/SE 学术型第 2 条拆解**：先确认是否有 1 篇 CCF 推荐期刊或 JCR Q1 收录源刊等“重要期刊锚点”，再核查 5 类追加条件之一：科研奖励、学术专著、严格限定的发明专利、CCF A 类期刊或主会外文论文、或不少于 2 篇重要期刊 / 会议论文；这些追加条件能否与锚点论文重叠计数仍需老师确认。专业型电子信息文件中的论文类 B/C 分类、预警期刊排除和支撑材料清单更具体，可作为“重要论文/会议”和材料准备的相邻参照，但不能替代 CS/SE 学术型主依据。
4. **两版共同硬风险很强**：第一作者 / 导师第一作者本人第二作者、第一署名单位北航、与学位论文密切相关、导师审阅、录用 / 刊出状态、证明材料都必须逐篇核对。
5. **当前保守建议**：先对所有候选成果建立逐篇资格审计表，同时按 2014 与新版两套规则分别打勾；在老师确认“能否混用”“新版具体文件”“外部论文例外”“2014 免盲审是否仍有效”之前，不把外部单位论文、多个仅录用论文、共同一作论文作为唯一主路径。

## 3. 当前新版候选：按 CS/SE 学术型第 2 条做可操作核算

新版候选中最值得规划的是 CS/SE 学术型第 2 条，而不是低参考价值的顶刊/高被引备查条款；后者仅为原文完整性保留，不作为当前成果规划推荐路线。本库后续只把第 2 条作为常规路线表：先有“重要期刊锚点”，再过追加条件和共性 gate。正式依据仍是 CS/SE 学术型创新成果要求；电子信息专业文件只提供同学院、同批次政策里更具体的成果分类和材料清单，用于形成待问老师清单，不能直接替代学术型主依据。

| 核算步骤 | 具体做法 | 当前证据与注意点 |
|---|---|---|
| 1. 先找“重要期刊锚点” | 至少 1 篇 CCF 推荐期刊或 JCR Q1 收录源刊等国内外公认重要学术期刊；这里的锚点首先是期刊，不要把普通会议或从会当锚点 | CS/SE 学术型原文 Page 1；是否接受“等”范围内的其他重要期刊需老师确认 |
| 2A. 追加条件：CCF A 外文论文 | CCF 推荐 A 类期刊或会议论文不少于 1 篇，且需外文撰写；会议必须是主会，不是从会 | CS/SE 学术型 Page 1-2；若已有 CCF A 主会/期刊外文成果，这一路径值得优先核算；若锚点论文本身也是 CCF A 期刊，能否同时满足追加条件需老师确认 |
| 2B. 追加条件：不少于 2 篇重要论文 | 另有相关学科国内外公认重要期刊或学术会议论文不少于 2 篇，其中至少 1 篇外文 | CS/SE 学术型 Page 1；“2 篇”能否与第 1 步锚点重叠计数必须问老师 |
| 2C. “重要论文/会议”范围怎么落地 | 电子信息专业文件的 B/C 类更具体：B 类含 SCI / SSCI Q2+、中科院 2 区+、中国科协 T2+、CCF A/B 类期刊/会议、A&HCI；C 类为其他相关学科国内外公认重要期刊或会议 | 这是专业型文件分类，不是学术型直接规则；应带着候选论文清单问老师“学术型第 2 条里的重要论文/会议是否可按类似口径认定” |
| 2D. 追加条件：专利 / 奖励 / 专著 | 严格专利条件可作为独立追加条件：学生第一发明者、国际或国家发明专利、北航署名、成果转化并取得经济效益；另有已授权发明专利排名前三且位于学生发明者第一名时，可折算为 2B 中 1 篇 | 两类专利用途不同，不能混淆；奖励、专著也需按原文和支撑材料逐项核对 |
| 2E. 支撑材料和排除项 | 电子信息专业文件列出预警期刊排除、专利授权证书及转化证明、合同转化数与到款凭证、获奖证书、著作目录页/署名页/贡献认定等材料口径 | 这些材料口径不能直接变成学术型硬条件，但非常适合提前作为材料清单和邮件咨询问题，避免临近申请时才发现证明不足 |
| 3. 共性 gate | 所有论文/成果都要与学位论文密切相关、投稿/申请前导师审阅；论文需满足作者序、北航第一署名单位、最多 1 篇录用状态、最高级别已刊出、主会非从会、证明材料齐全 | 这些 gate 任一失败，都可能让新版路径不可用 |


## 4. 两条可选路径的难度、难点和适配场景

| 路径 | 最适合的成果状态 | 主要难度 | 主要风险 | 初步建议 |
|---|---|---|---|---|
| 2014 版 | 已有不少于 3 篇相关论文且其中至少 2 篇 SCIE；或已有 1 篇 SCIE + 2 篇 EI/CPCI-S，且至少 1 篇 EI 源期刊；署名单位和作者顺序均干净；若已有 CCF A/B 期刊或 CCF A 会议等成果，也可同步核验 2014 免盲审子路径 | 要凑够不少于 3 篇，且每篇的 SCIE/EI/CPCI-S 收录源、EI 源期刊属性、外文篇数、刊出/录用状态都要证明；免盲审子路径仍不能绕开不少于 3 篇和至少 1 篇外文前提 | 外部单位论文、多个录用未刊出、EI 会议与 EI 源期刊混淆、口语化 SCI/EI 误写成正式结论；2014 免盲审对 2022 级实际评阅方式是否仍有效尚需老师确认 | 如果成果更偏传统 SCIE/EI/CPCI-S 组合，优先把 2014 版算清楚；若已有 CCF A/B 期刊或 CCF A 会议，不要只按新版理解，也要按 2014 免盲审子路径单独核验，但不能自行假设一定免盲审 |
| 当前新版候选 | 已有 JCR Q1 / CCF 推荐期刊等重要期刊锚点，并可叠加 CCF A 类期刊或主会外文论文、其他重要期刊/会议论文、国家级 / 省部级一等奖科研奖励、学术专著或合格发明专利等成果 | 门槛不只是篇数，必须先过重要期刊锚点；“至少 1 篇重要期刊”和后续“不少于 2 篇重要期刊/会议论文”能否重叠计数仍需确认；重要论文/会议范围、预警期刊排除、专利转化证明和到款凭证等材料需结合老师确认 | 把新版误解成“2 篇即可”、把会议从会当主会、把 CCF B 会议误当 CCF A 追加条件、把电子信息专业 B/C 类直接当学术型硬条件、共同一作条件更严、最新版具体文件未被老师点名确认 | 如果已有 Q1 / CCF 推荐期刊锚点并能叠加 CCF A 外文主会、其他重要论文或合格专利/奖励/专著，新版值得并行评估；否则不要只按数量乐观估计 |
| 两版共同底线 | 论文都由本人第一作者，或导师第一作者本人第二作者；第一署名单位北航；与学位论文强相关；最多 1 篇录用状态；材料齐全 | 每篇论文都需要同时通过身份、单位、相关性、收录源、发表状态、证明材料六类审计 | 任一论文在单位、作者序、相关性或状态上出问题，都可能导致整条路径不稳 | 建议为每篇候选论文建立“资格审计表”，先排除高风险论文，再决定走 2014 还是新版 |

## 6. 不要误判的点

| 易误判 | 正确写法 / 当前结论 |
|---|---|
| “2014 就是 2 SCI 或 1 SCI + 2 EI” | 不要把口语传闻写成正式结论；正式写法是先满足不少于 3 篇且至少 1 篇外文，再满足 `SCIE 2 篇` 或 `SCIE 1 篇 + EI/CPCI-S 2 篇且至少 1 篇为 EI 收录源期刊论文`。 |
| “老师说两版都行，所以可以混用条款” | 只能确定两版都可作为候选；能否混用尚未确认，当前保守按整体选择一版规划。 |
| “外部论文只要本人一作就能用” | 当前证据不支持；两版均有北航第一署名单位约束，特殊例外必须邮件确认。 |
| “新版只要 2 篇重要论文” | 不对；常规可操作路径是 CS/SE 学术型第 2 条：先有 1 篇重要期刊锚点，再核追加条件。即便走“不少于 2 篇重要期刊/会议论文”追加条件，也要确认能否与锚点重叠计数。 |
| “新版里的专利就是任意授权专利” | 不对；作为独立追加条件时，原文限定为学生第一发明者的国际或国家发明专利、北航署名、成果转化并取得经济效益；作为 2B 论文折算时，也至少要求已授权、排名前三且位于学生发明者第一名。 |
| “2014 免盲审要求一定仍能免盲审” | 实施细则写 2020–2023 级博士原则上至少 3 份双盲；2014 免盲审条款对 2022 级是否仍有效需问老师。 |
| “2024 文件一定就是最新版” | 当前只能写作“2024 版 / 当前已取得新版候选”；老师邮件确认的是“最新版创新成果要求”可选，但未点名具体文件。 |

## 11. 原始档案入库原则

- 原始邮件与聊天记录必须完整保存。
- 原始档案以 AES-256 加密 zip 入库，密码不写入仓库；本地通过 `.env` 的 `DEGREE_REQUIREMENTS_ARCHIVE_PASSWORD` 配置。
- Markdown 只写语义索引、关键结论、证据等级、SHA256 和 zip 内文件名；不逐字展开邮件/聊天原文。
- 复核原文时先执行 `source .env`，再运行：

```bash
python degree_requirements/scripts/archive_tool.py archives
python degree_requirements/scripts/archive_tool.py list
python degree_requirements/scripts/archive_tool.py test
python degree_requirements/scripts/archive_tool.py show --member MANIFEST.txt
python degree_requirements/scripts/archive_tool.py extract --output /tmp/degree_raw_check
```

当前只有一个加密 zip 时脚本会自动选择；未来有多个 zip 时，使用 `--archive <zip 文件名>` 或本地 `.env` 中的 `DEGREE_REQUIREMENTS_ARCHIVE_FILE` 指定目标档案。仓库文档和 PR comment 不写任何可复制的口令赋值样式。
