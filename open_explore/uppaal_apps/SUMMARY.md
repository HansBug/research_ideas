# UPPAAL 应用验证文库总账

本文件是 `open_explore/uppaal_apps/` 论文集的总账，用于记录当前已经正式入账的 `UPPAAL` 应用验证论文、分类口径、状态分布、更新进展和失败/阻塞历史。

## 文档定位与使用方式

推荐使用顺序如下：

1. 先读 [README.md](./README.md)，了解本论文集定位和与 [uppaal_tech/README.md](../uppaal_tech/README.md) 的边界。
2. 再读 [GUIDE.md](./GUIDE.md)，确认筛选、分流、回填和一致性检查规范。
3. 若任务涉及单篇 `desc.md`，再读 [DESC_GUIDE.md](./DESC_GUIDE.md)。
4. 最后使用本文件查看当前统计、分类口径、统一论文表和失败记录。

## 当前关注边界

1. 这里只收录 `UPPAAL` 被用于**形式化验证具体模型或系统**的应用论文。
2. 主贡献是 `UPPAAL` 本体技术的论文，不在这里入账，应进入 [uppaal_tech/README.md](../uppaal_tech/README.md)。
3. 只是在正文中顺带提一下 `UPPAAL` 的条目，不应正式入账。
4. 主要目标是调度、优化、测试或控制合成，但没有清晰验证任务、性质或结论的论文，当前不作为优先收录对象。

## 检索关键词簇

### 当前推荐关键词簇

- `UPPAAL + formal verification/model checking + protocol/controller/embedded system/industrial system`
- `UPPAAL + safety/liveness/deadlock/schedulability/reachability + case study`
- `UPPAAL SMC/Tiga/CORA/Stratego/ECDAR + case study/industrial/application`
- `UPPAAL + automotive/railway/avionics/manufacturing/network protocol + verification`

### 已观察到的高命中特征

- 题目、摘要或关键词直接出现 `verification`、`model checking`、`case study`、`industrial`
- 正文明确交代验证对象、建模方式、性质类型和结果
- 官方案例页或官方教程能够反向追到正式论文或稳定技术报告
- 领域词和验证任务词同时出现时，命中质量明显更高

### 已观察到的低命中特征

- 只有工具名，没有验证任务词
- 只有应用对象，没有 `UPPAAL`
- 只有 `optimization`、`testing`、`scheduling`，没有 `verification/model checking`
- 泛 timed automata 案例，但正文与 `UPPAAL` 关系弱

### 检索倾向调整

- 当前优先收“验证主线清晰”的 `UPPAAL` 应用论文，不再把“泛应用”作为首要方向
- 先把 `SUMMARY.md`、`GUIDE.md` 和 `DESC_GUIDE.md` 的口径固定，再做大规模扩库
- 扩库时必须先做“技术/应用”分流，再做“验证/非验证主线”分流
- 后续优先从控制系统、嵌入式系统、工业 `CPS` 与协议案例切入

## 状态口径

### 条目状态

| 状态 | 含义 |
|---|---|
| 🟢 | 直接可用：对博士研究已有较强复用价值，且材料较完整 |
| 🟡 | 可整理：有价值，但仍需补 `desc.md`、补证或进一步结构化 |
| ⚪ | 未收获：不满足目标，或无法形成可靠、可追溯的产物 |
| ⏳ | 尚未提取：论文已入库，但 `desc.md` 尚未完成 |

### `详度` 口径

| 级别 | 含义 |
|---|---|
| 🟢 | 复现级：对象、模型、性质、流程和结果足够细，原则上可据此复现主要验证思路 |
| 🟩 | 较完整：主线与关键结构清楚，但仍需结合其他材料补少量细节 |
| 🟨 | 中等：能看清主要对象、性质与结果，但模型或流程细节仍有缺口 |
| 🟧 | 概览级：主要停留在案例介绍或经验总结层，难以直接据此复现 |
| 🟥 | 细节不足：信息过少、正文不完整或关键部分缺失，短期内难以稳定利用 |

### `实现` 口径

| 级别 | 含义 |
|---|---|
| 🟢 | 论文对应模型/代码/脚本直达：可直接获得与论文案例高度对应的模型文件、源码或脚本 |
| 🟩 | 核心实现线可得：能拿到同一案例线或同一工具线的核心模型/实现，但不保证是论文同期精确快照 |
| 🟨 | 部分材料可得：只能拿到部分模型、脚本、案例文件或辅助实现，主材料仍不完整 |
| 🟧 | 仅工具入口或案例描述可得：只有官网、案例页、工具二进制、文档或论文正文说明 |
| 🟥 | 暂未获取实现或模型材料：当前没有找到可用模型、实现或案例文件线索 |

### `UPPAAL线` 口径

| 取值 | 含义 |
|---|---|
| `UPPAAL` | 主线工具或经典 `UPPAAL` 验证 |
| `UPPAAL SMC` | 统计模型检查应用 |
| `UPPAAL Tiga` | timed game / controller synthesis 相关应用 |
| `UPPAAL CORA` | cost-optimal / priced timed automata 相关应用 |
| `UPPAAL Stratego` | 策略综合、学习或规划相关应用 |
| `UPPAAL PORT` | 组件化、本地时间或 `PORT` 线应用 |
| `ECDAR` | timed I/O specification / compositional verification 相关应用 |
| `其他 UPPAAL 谱系变体` | 其他明确属于 `UPPAAL` 谱系的变体 |
