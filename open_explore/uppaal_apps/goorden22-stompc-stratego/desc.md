问题一句话：本文验证的是如何把 `Uppaal Stratego` 嵌入在线 `MPC` 工作流，核心问题是让控制综合不只停在离线策略，而能周期性接入真实状态和外部仿真器。
方法一句话：作者提出 `STOMPC` 框架，用 Python 封装“读真实状态 -> 调 `Uppaal Stratego` 求未来控制序列 -> 把首步动作送回仿真器/真实系统”的 receding-horizon 闭环。
验证收获一句话：论文用家庭地暖、雨洪调蓄池和交通灯三类案例证明这条框架可落地，其中分别带来约 `40%` 舒适度改善、`10%` 节能、`22%` 调蓄控制性能提升，以及交通场景下 `27%/42%/20%/19%` 的延迟、队列、停车和油耗改进。

## 简报

这篇论文的重点不是某一个控制对象本身，而是“怎样把 `Stratego` 真正放进在线控制回路”。但它没有停在抽象框架层，而是拿三个风格差异很大的真实案例来说明可用性：家庭地暖、城市雨洪调蓄池和多路口交通灯。因此它可以留在 `uppaal_apps/`，但必须明确这是**框架主导、案例支撑**的边界型应用论文。

- 系统：`STOMPC` 框架驱动的 `MPC + Stratego + Simulator` 闭环。
- 特点：周期重规划、外部仿真器耦合、支持不同物理域和不同目标函数。
- 规模：覆盖 `10` 房间家庭地暖、`48 h` 时域调蓄池控制和 `4` 个路口的干道交通灯。
- 模型：`Uppaal Stratego` 负责滚动求控制序列，外部模拟器提供真实状态。
- 性质：安全运行、舒适度/能耗、溢流/沉降、延迟/队列/停车/油耗等定量目标。
- 方法：每个控制周期把当前状态写回模型，再重新综合未来一段时间的控制序列。
- 结果：三个案例都显示在线 `Stratego` 控制优于既有控制器或静态脚本。

`真实状态 -> STOMPC 写回 Stratego 模型 -> 在线求未来控制序列 -> 执行首步动作 -> 下一周期重规划`

## 论文定位

本文属于 `🎛️ + 🏭`。虽然它也是一篇工具框架论文，但正文明确给出了三个实体应用域，并给出了量化性能提升，因此仍可作为 `UPPAAL Stratego` 在线控制应用线的重要条目。需要强调的是，它的“被验证系统”应理解为“控制闭环 + 在线综合机制”，而不是某个单独 plant 模型。

## 验证对象与问题背景

### 系统与场景

作者关注的是在线 `MPC` 场景下的控制软件。系统在每个控制周期读取真实状态，预测未来一段时间的行为，再选择下一步控制动作。

### 系统组成与运行机制

`STOMPC` 的核心组成包括：

1. `MPC setup`
   - 负责调度整个 receding-horizon 循环。
2. `Uppaal Stratego`
   - 根据当前状态综合控制序列。
3. 外部 simulator 或真实系统
   - 执行当前控制步并返回下一个真实状态。

### 验证边界

本文验证的是**在线控制框架和控制目标达成效果**，而不是某个单独 plant 的纯布尔安全性证明。它更偏“safe and optimal control synthesis”的应用展示。

### 核心问题

1. `Stratego` 自身不直接支持周期性更新状态的在线 `MPC` 流程。
2. 不同案例此前往往各写一套 bash / Python 脚本，难以复用。
3. 需要一个统一框架来连接 `Stratego` 与领域仿真器。

## 模型与形式化建模

### 框架模型

`STOMPC` 将标准 `MPC` 三要素固定下来：

1. 用模型预测未来。
2. 计算一段控制序列来优化目标。
3. 只执行首步动作并在下一周期重算。

### 关键实现

1. 在时刻 `t = k` 读入真实状态 `x(k)`。
2. 将 `x(k)` 写入 `Uppaal Stratego` 模型。
3. 调用 `Stratego` 求未来 horizon 内的控制序列。
4. 取第一步 `u(k)` 发送给外部 simulator。
5. 在 `t = k + p` 获得新的真实状态 `x(k+p)` 并重复。

### 三个案例的建模边界

1. **家庭地暖**
   - 用数字孪生和 `Simulink` 替代真实房屋热行为。
2. **雨洪调蓄池**
   - 用 `EPA-SWMM` / `PySWMM` 提供水力状态。
3. **交通灯**
   - 用 `VISSIM` 提供车辆到达和路口状态。

## 验证目标与性质

### 待验证问题

1. 在给定 horizon 内，控制序列能否同时满足安全与优化目标。
2. 重新规划能否优于旧控制器。
3. 跨领域外部仿真器耦合是否可复用。

### 性质类型

1. 安全控制综合。
2. 定量优化。
3. 在线滚动控制评估。

### 性质分组与实际含义

- 地暖：房间舒适度与能耗。
- 调蓄池：避免 overflow，同时促进 sedimentation。
- 交通灯：最小化 delay、queue length、number of stops、fuel consumption。

### 查询表达

论文未给出完整查询清单，重点在于 `Stratego` 的 objective-driven synthesis，而非传统 `A[]` / `E<>` 公式展示。

## 核心方法与验证流程

1. 使用 Python 封装 `MPC setup`。
2. 为当前应用定义状态输入、目标函数和控制周期。
3. 周期性调用 `Uppaal Stratego` 求得最优或近最优策略。
4. 把首步动作送回外部 simulator。
5. 在下一控制周期重复，形成在线闭环。

该方法解决了过去“每个案例都要重新发明一套 `Stratego + script + simulator` 粘合层”的问题。

## 案例与结果

### 1. 家庭地暖

案例位于丹麦北部一栋家庭住宅中：

1. 房屋包含 `10` 个房间。
2. 每 `15` 分钟读取一次各房间温度。
3. 每周期收集 `24 h` 天气预报。
4. 为未来 `75` 分钟综合控制策略。

结果：

1. 平均舒适度提升约 `40%`。
2. 预测式控制额外节能约 `10%`。

### 2. 雨洪调蓄池

案例把 `Stratego` 与 `EPA-SWMM` 结合：

1. 每 `15` 分钟更新一次当前水位。
2. 控制 horizon 为 `48 h`。
3. 目标同时包括“零溢流安全”和“促进沉降改善水质”。

结果：

1. 控制性能提升约 `22%`。

### 3. 交通灯控制

案例为 Aalborg 的 Hobrovej 干道：

1. 包含 `4` 个有信号交叉口。
2. 每秒调用一次 `Stratego` 求解配置序列。
3. 利用 `VISSIM` 区域传感器提供 `200 m` 内车辆预计到达时间。

结果：

1. delay 降低 `27%`。
2. queue length 降低 `42%`。
3. number of stops 降低 `20%`。
4. fuel consumption 降低 `19%`。
