## 简报

这篇论文是非常典型的“现实控制流程 -> 场景规格 -> 形式模型”案例。被验证对象不是单个机械部件，而是一套大型交通基础设施的协同控制系统：船舶、船闸、阀门、闸门和控制中心都要在严格顺序下联动，否则就会出现开错门、未平衡水位就放行、或多个方向争用通道等问题。

- 系统：巴拿马运河式双向船闸通行控制系统。
- 特点：多船并发、双向流动、锁室水位联动、控制中心统一调度。
- 规模：运河长约 `80 km`；船闸室约 `33.53 m × 304.8 m`；两端各有 `3` 级船闸。
- 模型：`LTSA` 负责场景和行为规格，`UPPAAL` 负责把时间因素引入控制模型。
- 性质：deadlock-free、安全门阀顺序、合理通行时间和 liveliness。
- 方法：use case / scenario -> `FSP/LTSA` -> 加入时间约束 -> `UPPAAL` 仿真与验证。
- 结果：论文目标是得到无死锁且安全的控制架构，并用真实运河流程作为案例锚点。

`巴拿马运河场景 -> use case / scenario -> LTSA 行为模型 -> UPPAAL 时间约束 -> 验证并发通行安全`

## 论文定位

本文属于强应用型 `🎛️ + 🚦` 条目。虽然写作形式是硕士论文，但它验证的是非常具体、非常典型的交通基础设施控制系统。更重要的是，论文不是把运河只当背景，而是真的展开了闸门、阀门、水位和控制中心之间的控制逻辑，因此在文库中可标为 `🟢`。

## 验证对象与问题背景

### 系统与场景

研究对象是类巴拿马运河的两车道水运通道。船舶需要通过多级船闸完成升降水位，再穿越湖区到达另一侧。

### 系统组成与运行机制

系统主要包含：

1. 船舶
2. 锁室（locks）
3. 闸门（gates）
4. 阀门（valves）
5. 控制中心

典型通行流程是：

1. 船靠近锁室；
2. 先通过阀门调节相邻锁室水位；
3. 水位对齐后再开门放船；
4. 船进入下一锁室；
5. 重复直到通过整个运河。

### 验证边界

论文验证的是**运河通行控制逻辑与并发协调机制**，不是运河的连续流体仿真或经济运营优化模型。

### 核心问题

1. 多船并发通过时容易发生资源争用和死锁。
2. 若水位未对齐就开门，会带来严重安全风险。
3. 控制中心既要保证安全，也要控制通行等待时间。

### 研究动机

作者强调像运河这种复杂系统本质上是 reactive 且 concurrent 的，仅靠非形式化流程图不足以验证其并发交互正确性。

## 模型与形式化建模

### 场景到模型的链条

论文先从 use cases 和 scenarios 出发，再逐步细化成行为模型：

1. positive scenarios
2. negative scenarios
3. implied scenarios

`LTSA` 用来验证场景覆盖和系统行为是否一致；在得到较稳定的架构后，再用 `UPPAAL` 添加时间因素。

### 关键控制对象

从正文可以明确看出，模型至少覆盖：

1. 控制中心与船长通信；
2. 船舶排队与放行；
3. 闸门开关；
4. 阀门控制水位；
5. 锁室间水位匹配；
6. 湖区双向通行协调。

### 抽象边界

论文更关注控制顺序与同步，而不是高保真流体计算。水位变化被抽象成可用于控制判定的状态条件。

## 验证目标与性质

### 待验证问题

1. 系统是否 deadlock-free。
2. 通行流程是否满足安全顺序。
3. 是否存在 liveliness 违例或不合理等待。
4. 控制中心、船舶、闸门和阀门的消息交互是否满足场景需求。

### 性质类型

1. 安全性质。
2. 活性性质。
3. 死锁自由性质。
4. 场景一致性与时间约束性质。

### 性质分组与实际含义

- 门阀顺序安全：未平衡水位时不得开门。
- 通行活性：船不能无限期卡在队列或锁室中。
- 通信一致性：控制中心和船长/传感器/执行器的交互必须闭环。

### 查询表达

论文在摘要和章节目录里明确把 `deadlock`、`safety` 和 `liveness` 作为核心目标，但没有像短论文那样给出大量 `UPPAAL` 公式文本；更多是按场景和需求条目组织。

## 核心方法与验证流程

1. 描述运河结构与控制需求。
2. 从 use case 生成 scenarios。
3. 用 `LTSA` 发现 implied scenarios 并反复修正规格。
4. 获得稳定架构后，把时间问题交给 `UPPAAL`。
5. 用 `UPPAAL` 对实时控制流程做仿真和验证。

论文特别强调 `LTSA` 与 `UPPAAL` 的互补关系：

1. `LTSA` 适合场景和并发行为结构；
2. `UPPAAL` 适合把时间约束正式加入控制模型。

## 案例与结果

### 案例规模

论文使用巴拿马运河作为主案例，并给出：

1. 运河长度约 `80 km`；
2. 闸室尺寸约 `33.53 m × 304.8 m`；
3. 两端各有三组锁室；
4. 控制目标同时包括安全、效率和可靠性。

### 主要结果

1. 论文的总体目标是获得 deadlock-free 且 safe 的架构模型。
2. `LTSA` 用于发现和消解 implied scenarios。
3. `UPPAAL` 用于在该架构上补入时间约束，形成实时运河控制模型。
4. 论文把控制中心、船闸和水位联动过程固定为可验证流程，而不是停留在文字规程。

### 结果边界

原文更像系统化 thesis，不像短会议论文那样集中给出统一性能表。因此它的价值更多体现在“建模流程完整”和“系统边界清晰”，而不是少数几条数字结果。
