问题一句话：本文验证的是带执行时间区间不确定性的 Herschel-Planck 卫星任务集，核心问题是当 `BCET/WCET` 不再固定时，系统是否仍然可调度以及违例概率有多大。
方法一句话：作者在既有 Herschel-Planck `UPPAAL` 调度模型上引入执行时间区间，并结合符号模型检查与 `UPPAAL SMC` 统计模型检查分析可调度边界。
验证收获一句话：符号模型检查能在 `BCET/WCET >= 90%` 时确认可调度，而 `UPPAAL SMC` 能在 `BCET/WCET <= 71%` 时给出具体违例反例，并进一步估计响应时间与 deadline miss 概率。

## 简报

本文不是重新换一个案例，而是把 `2010` 年 Herschel-Planck 调度案例推进到更真实的“不确定执行时间”条件下。此前模型把每个任务执行时间当成固定值，本文则把它改成区间 `[BCET, WCET]`，直接面对现实嵌入式软件里更常见的抖动与测时不确定性。

- 系统：Herschel-Planck 卫星单 CPU 飞控软件任务集。
- 特点：固定优先级抢占、共享资源、任务挂起、执行时间区间不确定。
- 规模：`32` 个任务、单处理器、混合优先级继承/优先级上限协议，沿用前作工业任务参数。
- 模型：CPU 调度器 + 任务模板 + 资源模板 + 停表变量，并把每个任务执行时间改为 `[BCET, WCET]` 区间。
- 性质：可调度性、deadline miss 反例、期望响应时间、deadline miss 概率。
- 方法：符号 MC 证明安全上界 + `UPPAAL SMC` 生成违例样本并做概率/性能评估。
- 结果：`BCET/WCET >= 90%` 时可确认安全，`<= 71%` 时可构造不可调度反例，中间区间两种方法均可能不定。

`工业任务参数 + 执行时间区间 -> UPPAAL 停表调度模型 -> 符号 MC / 统计 MC -> 可调度边界与违例概率`

## 论文定位

这篇论文是典型的 `UPPAAL SMC` 应用案例。它的重要性不在于换了一个新对象，而在于把真实嵌入式调度问题从“确定执行时间”推进到“不确定执行时间”的分析边界，展示了 `UPPAAL` 统计模型检查在工业任务可调度性上的补位作用。

## 验证对象与问题背景

### 系统与场景

被验证对象仍然是 Herschel-Planck 卫星的软件执行平台。它由多个基础软件和应用软件任务共享单处理器执行，服务于安全关键航天控制任务。

### 系统组成与运行机制

系统运行机制与前作一致，但本文更强调以下几点：

1. 任务按固定优先级在单 CPU 上抢占执行。
2. 任务访问共享资源时要经过优先级继承或优先级上限协议。
3. 任务真实执行时间并非常数，而是位于 `BCET` 与 `WCET` 之间的区间。
4. 一旦允许执行时间在区间内变化，原先“可直接递推上界”的分析方式就会迅速变得不够精确。

### 验证边界

论文验证的是**卫星软件任务调度、资源竞争与时间不确定性下的可调度性边界**，不验证卫星控制算法的功能语义，也不验证硬件电气实现。

### 核心问题

原有响应时间分析过于保守，固定执行时间的 `UPPAAL` 模型又不够真实。作者要回答的是：当执行时间变成区间后，系统到底在哪个区间内仍然安全、在哪个区间里会出现 deadline miss，以及中间模糊区间应该如何解释。

### 研究动机

这篇论文的核心动机是把“工业上更真实、但形式上更难”的执行时间不确定性直接纳入模型，并说明仅靠符号模型检查不足以发现不可调度性时，`UPPAAL SMC` 可以作为补充。

## 模型与形式化建模

作者沿用前作的 `UPPAAL` 调度建模骨架，但把关键参数推广为区间：

1. **任务模板**
   - 任务的计算时间不再是固定 `ET`，而是 `[BCET[id], WCET[id]]`。
2. **CPU 调度器**
   - 保留单处理器固定优先级抢占机制。
3. **资源调度器**
   - 保留优先级继承与优先级上限协议。
4. **停表变量**
   - 继续用于编码抢占、挂起和响应时间度量。

抽象边界没有改变，但语义难度显著上升，因为带停表的区间执行时间模型会触发不可判定性问题。

## 验证目标与性质

### 待验证问题

本文主要关心：在不同 `BCET/WCET` 比例下，所有任务是否都能满足 deadline；如果不能，违例能否被显式构造出来；如果能，平均或期望响应时间又大致是多少。

### 性质分组与实际含义

1. **可调度性确认**
   - `error` 状态不可达，表示没有任务错过 deadline。
2. **不可调度性证伪**
   - 通过统计模型检查采样到 deadline miss 轨迹，表示系统确实可能违例。
3. **期望响应时间**
   - 估计任务在可调度区间内的平均时间表现。
4. **deadline miss 概率**
   - 在不可调度区间中估计出错的概率水平。

### 性质来源与表达方式

这些性质都来自工业任务规格中的 `Period/Deadline/BCET/WCET` 参数。符号模型检查负责验证 `error` 不可达，统计模型检查则通过随机仿真与统计推断分析 `Pr` 型问题和性能期望。

### 判定边界与前提

作者明确指出：带停表和区间执行时间的模型总体上不可判定，因此这里不是在追求“任何参数都给出严格答案”，而是在安全证明、证伪反例和概率估计之间做组合分析。

## 核心方法与验证流程

1. 在 `2010` 版 Herschel-Planck 模型基础上把执行时间改为区间。
2. 用符号模型检查先尝试确认 `error` 是否不可达。
3. 若符号方法无法否证，再用 `UPPAAL SMC` 随机生成具体执行轨迹。
4. 对于不可调度区间，抽取 deadline miss 反例。
5. 对于可调度区间，进一步估计期望响应时间与违例概率。

这个流程的关键价值是：把“证明安全”和“生成不安全证据”拆给两种不同的 `UPPAAL` 分析手段。

## 案例与结果

论文给出的核心结果包括：

1. 当 `BCET/WCET >= 90%` 时，符号模型检查可以确认系统可调度。
2. 当 `BCET/WCET <= 71%` 时，`UPPAAL SMC` 可以构造出不可调度的具体样本轨迹。
3. 对于 `71%-90%` 的中间区间，两类方法都可能因为过近似或计算代价而给不出确定结论。
4. 除了安全/不安全判定，`UPPAAL SMC` 还能估计任务响应时间期望和 deadline miss 概率。

因此，本文真正的贡献不是单纯“又算了一次调度”，而是把工业任务集的分析结果改写成一个分区间的判定框架。

## 与本研究的关系

### 相关性分析

这篇论文非常贴合博士研究中“带不确定性的控制软件模型验证”问题，尤其适合参考“需求参数区间化后如何维持验证闭环”。

### 可借鉴之处

1. 把执行时间不确定性结构化成参数区间。
2. 把“证明安全”和“构造反例”拆给不同验证技术。
3. 在传统 deadline 判定之外加入期望响应时间和违例概率。

### 存在的不足与改进空间

中间区间仍然存在较大的“不确定地带”；同时，建模与参数整理仍然高度依赖人工输入和工业文档。

### 对本研究的启发

对本研究而言，这篇论文说明：当控制系统状态机或任务模型带参数不确定性时，不应只依赖单一符号方法，而应提前考虑“安全证明 + 证伪样本 + 概率解释”的组合式验证框架。
