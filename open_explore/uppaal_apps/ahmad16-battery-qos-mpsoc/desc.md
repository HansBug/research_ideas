验证收获一句话：在 `MPEG-4` decoder 案例上，论文展示了帧率、处理器数和电池数对寿命/容量的系统性影响，并证明其 hybrid automata 路线比先前的 `PTA-KiBaM` 方法更可扩展。

## 简报

这篇论文验证的不是协议，也不是传统控制器，而是“多处理器数据流应用 + 多电池供能”联合系统的寿命与容量边界。它把 throughput、处理器数、电池数、`DVFS/DPM` 和 `KiBaM` 电池动态一起拉进 `UPPAAL`，把原本很容易碎裂成多个子问题的设计空间统一起来分析。

- 系统：`MPEG-4` decoder 在 `Exynos 4210` 风格平台上的多处理器数据流系统。
- 特点：`SDF` 图、`DVFS/DPM`、电压频率岛、多电池调度、`KiBaM` 连续电量动态。
- 规模：代表性实验含 `6` 个处理器、`2` 个电池，并扩展到 `1-10` 个电池；频率层为 `1400/1032.7 MHz`。
- 模型：应用、处理器和电池调度被建为 hybrid automata 并行组合。
- 性质：deadlock、自适应调度正确性、公平用电、系统寿命、最小容量和统计 `QoS`。
- 方法：经典模型检查处理离散性质，统计仿真处理混合连续性质，并与 `PTA-KiBaM` 做扩展性对比。
- 结果：higher fps 会加速耗电；更多处理器和电池可改善寿命；`HA-KiBaM` 比 `PTA-KiBaM` 在容量和电池数上明显更可扩展。

`SDF 应用 + MPSoC + KiBaM -> hybrid automata 组合 -> 模型检查/统计仿真 -> 寿命与容量评估`

## 论文定位

本文是 `⏱️ + 🔋` 的强应用条目。其主对象虽然是资源/性能，而非传统控制软件，但场景具体、模型完整、性质清晰，且直接服务于电池约束移动嵌入式系统设计。

## 验证对象与问题背景

### 系统与场景

被验证对象是电池供电的移动嵌入式数据流应用。论文以 `MPEG-4` decoder 为主案例，关注在受限电池容量下还能运行多久、需要多大电池容量、是否值得增加处理器或电池数。

### 系统组成与运行机制

系统由以下关键部分构成：

1. `SDF` 应用图
2. 多处理器平台与 `VFI`
3. `DVFS/DPM` 功率管理
4. 多 `KiBaM` 电池系统
5. 电池调度器 `Ksched`

应用按 static-order schedule 在处理器上执行；处理器的频率状态影响负载电流；电池调度器根据可用电量选择当前供电电池。

### 验证边界

本文验证的是**系统级寿命/容量评估与若干功能性约束**，不是视频解码算法本身，也不是底层电池化学模型的高保真求解器。

### 核心问题

当 throughput、处理器数量和电池数量同时可变时，很难靠直觉判断哪个设计更划算；同时，先前 `PTA` 离散化方法在电池容量一大就会失去可扩展性。

### 研究动机

作者希望用更准确的 hybrid automata 直接保留 `KiBaM` 的连续动态，并利用 `UPPAAL` 的模型检查与 Monte Carlo 仿真同时覆盖离散与混合性质。

## 模型与形式化建模

### 建模对象

1. `KiBaM` 两槽电池动态（available / bound charge）
2. `SDF` actors 与 static-order firing
3. 处理器频率与空闲/占用负载电流
4. 电池切换调度策略 `best-of-all`
5. 迭代完成与系统寿命观察器

### 模型形式

全局模型由多个 hybrid automata 并行组成：

1. 电池调度器 `Ksched`
2. 各电池 `K1 ... Km`
3. `SDF` 图调度器
4. 各处理器 automata
5. 观察器 `Kobs` 与 `Gobs`

### 关键抽象

1. 将 `KiBaM` 连续变量直接保留为 hybrid dynamics，而非时间离散化。
2. 以迭代完成的视频帧数衡量系统 lifetime。
3. 通过观察器记录公平调度、活跃电池数与 deadlock 等性质。

## 验证目标与性质

### 待验证问题

1. 在不同 fps 约束下，系统寿命如何变化。
2. 达到目标帧数所需的最小初始电池容量是多少。
3. 不同处理器数/电池数对寿命与容量有何影响。
4. 电池调度是否公平、是否同时激活多个电池、是否存在 deadlock。

### 性质类型

1. 死锁自由
2. 功能正确性
3. 统计性能 / 资源性质

### 性质分组与实际含义

1. 调度功能性
   包括 actor 不能违规并行、同一 `VFI` 频率一致、活跃电池数受控等。
2. 电池管理正确性
   包括是否公平切换与是否违反单电池激活假设。
3. `QoS` 量化
   包括寿命、所需容量和 completed frames。

### 查询表达

论文给出了多条典型查询，例如：

1. `A[] not deadlock`
2. `E<> SDFScheduler_0.activeActor == p and SDFScheduler_1.activeActor == q`
3. `Pr[<=1500](<> bound1 - bound0 > n and empty_count < 2)`
4. `Pr[<=1500](<> b0active == true and b1active == true)`

这些查询分别对应 deadlock、非法并行 firing、公平调度和多电池同时激活等问题。

## 核心方法与验证流程

1. 形式化 `KiBaM`、`SDF` 图、平台与调度器。
2. 构建并行 hybrid automata 网络。
3. 在 `MPEG-4` decoder + `Exynos 4210` 上设置不同 fps、处理器数与电池数。
4. 统计 completed frames 与最小容量。
5. 与先前 `PTA-KiBaM` 在可扩展性与计算时间上做对比。

## 案例与结果

### 案例规模

1. 代表性平台含 `6` 个 `Exynos 4210` 处理器与 `2` 个电池。
2. 处理器频率层为 `1400 MHz` 与 `1032.7 MHz`。
3. 电池容量实验扩展到 `5×10^4 mAh`；电池数量实验扩展到 `10` 个电池。

### 主要结果

1. 帧率从约 `100` 提高到 `200 fps` 时，完成帧数下降，最小所需容量上升，但从 `125` 提升到 `200 fps` 时容量增量仅约 `84 mAh`。
2. 在固定 `71 fps` 下，处理器数减少会让同等 throughput 所需电池容量上升。
3. 增加电池数能线性提升完成帧数，但容量收益并非线性，因此“少量大电池”往往优于“大量小电池”。
4. `HA-KiBaM` 可处理大容量和多电池场景；`PTA-KiBaM` 在很小容量外就开始 `Out of Memory`。

### 结果解释

这说明 `UPPAAL` 在这里不仅能回答“有没有 bug”，还可以直接支持体系结构层面的设计权衡：throughput、处理器数和电池数之间的 Pareto 关系能被量化地展示出来。

## 与本研究的关系

### 相关性分析

这篇论文证明，形式化方法完全可以处理“资源与性能性质”而不只是逻辑安全性，这对博士研究中“待验证性质”的定义边界很有启发。

### 可借鉴之处

1. 用观察器把系统级 `QoS` 目标翻译成可检查性质。
2. 让状态机网络同时覆盖应用、平台和资源系统。
3. 在模型层直接支持设计空间比较，而非只输出单个 yes/no 结论。

### 存在的不足与改进空间

1. 模型未公开。
2. 场景聚焦在 `MPEG-4` decoder，一般性仍需更多基准支撑。
3. 一些 fairness/active battery 查询返回不满足，论文更多展示了方法能力而非完全满足的架构。

### 对本研究的启发

若后续要为控制系统状态机自动生成“资源型性质”，这篇论文提供了很强的模板：将寿命、容量、调度公平性等高层目标下沉为可验证状态机/观察器性质。
