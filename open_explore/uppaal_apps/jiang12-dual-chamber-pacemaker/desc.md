## 简报

这篇论文验证的不是一个抽象“心脏节律算法”，而是一个很具体的双腔起搏器控制骨架。作者把心房/心室事件、起搏输出、折返与不应期都压进一个可穷举的闭环时序系统里，因此既能检查基本安全边界，也能专门针对临床已知的 `PMT` 场景做反例驱动分析。

- 系统：双腔 `DDD` 起搏器及其心脏环境闭环模型。
- 特点：安全关键、显式保留心房/心室事件、可表达 `PMT`、mode-switch 与 `ELT`。
- 规模：起搏器核心由 `LRI`、`AVI`、`URI`、`PVARP`、`VRP` 五个定时部件组成，并配套随机心脏模型；文中给出名义参数如 `TAVI=150`、`TLRI=1000`、`TURI=400`、`TPVARP=100`、`TVRP=150`。
- 模型：起搏器与心脏共同构成 `UPPAAL` timed automata 闭环系统，心脏侧用 `Random Heart Model` 覆盖开环节律状态空间。
- 性质：下速率/上速率限制、bradycardia/tachycardia unsafe region、`PMT` unsafe transition、抗 `PMT` 算法正确性。
- 方法：先验证基本速率要求，再把问题升级为“控制器是否会把安全开环心脏驱动到不安全闭环状态”。
- 结果：基本 `DDD` 逻辑满足基础速率约束，但某些抗 `PMT` 修正仍可能留下新的边界问题。

`Boston Scientific 规格 + 医学知识 -> 起搏器/心脏 timed automata -> unsafe region 与 unsafe transition 查询 -> 识别 PMT 与纠正算法边界`

## 论文定位

这是 `UPPAAL` 在医疗设备控制软件上的经典应用案例之一。它既是一个具体设备控制器验证论文，也直接对应“从真实设备规格到闭环形式模型，再从反例回指算法缺陷”的验证流程。与 [uppaal_tech/README.md](../uppaal_tech/README.md) 的关系上，它不属于 `UPPAAL` 本体技术论文，而是很强的真实安全关键对象案例。

## 验证对象与问题背景

### 系统与场景

被验证对象是双腔植入式心脏起搏器。其职责是在心脏天然起搏和传导异常时，以适当时序向心房和心室发放起搏脉冲，维持心率与房室协同。

### 系统组成与运行机制

论文把系统拆成非常清楚的几个核心部件：

1. `LRI`
   - 负责 lower rate interval，保证最低心率。
2. `AVI`
   - 负责 atrio-ventricular interval，管理房室延迟。
3. `URI`
   - 负责 upper rate interval，限制过快室性起搏。
4. `PVARP`
   - 负责 post ventricular atrial refractory period，过滤室后房性无效信号。
5. `VRP`
   - 负责 ventricular refractory period，过滤室性不应期信号。
6. 心脏环境模型
   - 负责产生心房/心室事件，和起搏器通过 `Aget!`、`Vget!`、`AP!`、`VP!` 等同步交互。

### 验证边界

本文验证的是**起搏器控制逻辑与心脏节律抽象环境的闭环离散时序行为**。它不覆盖完整连续电生理机理，也不覆盖真实硬件实现、功耗或患者个体化参数辨识。

### 核心问题

安全风险不只是“起搏器会不会死锁”，而是：

1. 是否会违反最低/最高心率边界；
2. 是否会把原本还能接受的开环心脏状态驱动到危险闭环状态；
3. 面对已知 `PMT` 场景，算法是否真能终止异常节律。

### 研究动机

论文动机很直接：医疗设备越来越复杂，但缺少像航空/汽车那样成熟的软件验证标准，因此需要一个可操作的正式验证样板。

## 模型与形式化建模

### 起搏器模型

起搏器模型围绕五个经典定时器构建：

1. `LRI` 负责最低心率兜底；
2. `AVI` 负责在房性事件后等待并触发室性起搏；
3. `URI` 通过全局时钟限制连续室性事件间隔；
4. `PVARP` / `VRP` 负责过滤不应期内噪声和折返信号。

这些部件共享时钟、同步事件和全局参考时间，使模型保留了真正决定设备安全的时间骨架。

### 心脏模型

作者没有用单一路径心脏模型，而是提出了 `Random Heart Model (RHM)`。它按房性间隔和室性间隔定义闭环状态空间，并允许心脏在相应边界内非确定地演化，从而覆盖 bradycardia 与 tachycardia 邻域。

### 抽象边界

该抽象抓住了：

1. 房/室事件时序；
2. 起搏输出与折返关系；
3. 不应期和速率限制；
4. 心脏与设备之间的关键同步。

被省略的是更细的连续电生理动力学和病人差异化参数。

## 验证目标与性质

### 待验证问题

论文把性质分成两层：

1. **unsafe region**
   - 闭环系统是否落入明确的不安全心率区域；
2. **unsafe transition**
   - 控制器是否把安全开环节律推向不安全闭环状态。

### 性质类型

1. 安全性质
   - 下速率、上速率边界不能被破坏。
2. 有界时序性质
   - 室性事件间隔必须满足 `TLRI` 与 `TURI` 一类边界。
3. 临床风险场景性质
   - `SVT`、`ELT` 等 `PMT` 模式能否发生、能否被终止。

### 性质分组与实际含义

1. **Lower Rate Limit**
   - 防止起搏太慢。
2. **Upper Rate Limit**
   - 防止过快室性起搏。
3. **Mode-switch correctness**
   - 房速异常时切换模式是否真的更安全。
4. **Anti-ELT correctness**
   - 延长 `PVARP` 等策略能否阻断 endless loop tachycardia。

### 查询表达

文中典型查询围绕以下逻辑展开：

1. `A[]` 型安全不变式；
2. 监视器自动机测量心房/心室间隔；
3. `E<>` 型存在性查询，用来证明 `PMT` 场景可发生。

## 核心方法与验证流程

1. 根据设备规格建立基础 `DDD` 起搏器模型。
2. 构建随机心脏环境，形成闭环系统。
3. 按房/室间隔定义状态空间，并圈定 unsafe region。
4. 用监视器自动机验证上下速率基本要求。
5. 再把问题提升为 unsafe transition，主动寻找 `PMT` 反例。
6. 将 mode-switch 与 anti-ELT 算法加入模型，重新验证其安全性与终止性。

这套流程的价值在于：它不是只问“公式真不真”，而是明确区分“系统本身处于坏状态”和“控制器把系统带入坏状态”。

## 案例与结果

### 基础速率性质

基础 `DDD` 模型满足 lower / upper rate limit 相关要求，说明其基本时序框架是成立的。

### `PMT` 场景

论文重点分析两类 `PMT`：

1. `SVT` 相关场景；
2. `ELT`（endless loop tachycardia）相关场景。

作者证明，这些现象可以通过闭环模型中的 unsafe transition 被系统化刻画，而不只是临床经验描述。

### 纠正算法分析

最值得注意的是，论文并没有把厂商已有纠正算法直接当成“已证正确”。文中展示了：

1. mode-switch 算法虽然能针对特定房速场景动作；
2. 但在某些切换边界上仍可能引入新的 lower rate 问题；
3. anti-ELT 策略则可通过增加 `PVARP` 等机制阻断相应折返模式。

因此，这篇论文的真正收获不只是“起搏器被证明安全”，而是“哪些策略安全、哪些策略还有角落没封住”。

## 与本研究的关系

### 相关性分析

这篇论文与博士研究高度相关，因为它完整呈现了“需求/规格 -> 状态机抽象 -> 性质 -> 反例 -> 修正”的闭环。

### 可借鉴之处

1. 用状态空间中的 unsafe region / unsafe transition 区分两类风险。

1. 心脏模型仍是抽象环境，不是个体化病理模型。
