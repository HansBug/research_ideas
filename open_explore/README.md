# `open_explore/`

## 1. 路径定位

`open_explore/` 是本仓库的“探索型专题入口”。它的职责不是替代四个正式 `project_*` 目录，而是在研究方向尚未完全收敛、材料尚未适合放入既有项目时，先提供一个规范化的承接位置。

这里允许放入“自由探索”内容，但“自由”只意味着方向可以先开放，不意味着组织方式可以松散。任何进入本路径的专题，仍然应当具备明确目标、可追溯文件结构和后续维护入口。

## 2. 适合收录的内容

优先适合放在这里的内容包括：

1. 还没想清楚最终归属到哪个 `project_*`，但已经值得长期积累的专题型文献库。
2. 跨多个研究主题共享的基础工具、基础理论、方法谱系或应用谱系。
3. 需要先做基础文库、后续再决定是否拆分或迁移到正式研究项目中的材料。

## 3. 不适合收录的内容

以下内容不应直接放进 `open_explore/`：

1. 没有专题边界、没有维护计划的临时下载文件。
2. 只和某一个正式 `project_*` 强相关、且归属已经清晰的材料。
3. 纯粹的个人随手记录，如果它们还没有形成专题入口、汇总文件或稳定目录约束。

## 4. 文件组织原则

`open_explore/` 下的每个一级子目录，原则上都应该被视为一个独立的专题工作区，而不是普通文件夹。每个专题至少应具备：

1. 自己的入口说明文件。
2. 明确的整理边界与纳入/排除规则。
3. 可持续维护的汇总总账。

如果某个专题已经演化为稳定、长期、且明显归属到博士四大研究主题之一的内容，后续可以考虑迁移到对应 `project_*` 目录；但在迁移前，仍应先在此处维持清晰结构，避免“先乱放、后整理”。

## 6. 推荐工作方式

进入 `open_explore/` 时，建议按以下顺序工作：

1. 先读本文件，确认这里不是“杂项区”，而是“探索型专题区”。
2. 再进入目标专题的 `README.md`，理解该专题的收录边界。
3. 若需要新增或整理论文，继续读该专题的 `GUIDE.md` 与 `SUMMARY.md`。
4. 处理单篇论文时，仍应遵守仓库根级规范中的原文阅读顺序与文件要求。

## 7. 维护约束

后续在 `open_explore/` 中新增材料时，默认还应遵守以下约束：

1. 不要把本路径当作未分类文件回收站。
2. 不要只创建目录，不创建入口说明和汇总文件。
3. 文档中不要写入外部本地绝对路径；如果需要说明材料来源，应使用抽象来源描述，或者直接把需要的文件复制进仓库后再引用仓库内路径。
