# SOS: Safe, Optimal and Small Strategies for Hybrid Markov Decision Processes

- 问题一句话：在 hybrid/stochastic 控制问题里，`UPPAAL Stratego` 虽然能给出安全且近似最优的策略，但这些策略往往大到几百万条配置，难以理解、导出和部署。
- 方法一句话：先用 `Tiga + Stratego` 得到安全/近似最优策略，再用多标签 decision tree 学习、最小分裂阈值和安全剪枝把策略压成更小但仍安全的表示。
- 解决点一句话：第一次系统性把“safe + optimal + small”三目标同时放进 `UPPAAL` 的 hybrid MDP 策略工作流里。

## 论文定位

这篇论文是 `uppaal_tech/` 里 `⚡ 改进与扩展` 路线上极关键的“定题条目”。如果说 [david15-uppaal-stratego](../david15-uppaal-stratego/) 把策略正式做成 `UPPAAL` 查询语言里的对象，那么这篇论文进一步回答了一个更现实的问题：

1. 策略合成出来之后，能不能真的放到资源受限的嵌入式系统里。
2. 能不能让人看懂、调试、追溯和修改。
3. 能不能在不破坏安全保证的前提下，用明显更小的表示保存它。

因此它在技术线上处于一个很清晰的位置：

1. 向前承接 `Stratego` 与 [david14-minimal-expected-cost](../david14-minimal-expected-cost/) 那条“安全壳内优化”工作流。
2. 向后直接通向 [larsen19-synthesis-safe-optimal-compact-strategies-stochastic-hybrid-games](../larsen19-synthesis-safe-optimal-compact-strategies-stochastic-hybrid-games/) 的邀请综述，以及更后面的 [brorholt25-uppaal-coshy](../brorholt25-uppaal-coshy/) compact shield 路线。

换句话说，这篇论文不是在补一个零散技巧，而是在把 `UPPAAL` 的策略合成路线从“能算出来”推进到“能部署、能压缩、能解释”。

## 立足问题

论文立足的问题非常现实：在 hybrid MDP 上，安全与最优只是第一步，策略表示本身也是核心瓶颈。

作者以 adaptive cruise control 为例说明这一点。系统状态里既有连续变量，也有控制者可选模式和环境随机性；`UPPAAL Tiga` 可以先给出安全策略，`UPPAAL Stratego` 可以再在安全壳内学近似最优策略，但最后输出往往是一个庞大的显式列表，论文中 cruise 模型甚至达到近 `600` 万个配置项。

这会带来三个具体问题：

1. **部署问题**
   - 几百万配置的列表不适合直接装进嵌入式控制器。
2. **理解问题**
   - 工程师很难从一长串配置表里读出策略的真正结构。
3. **维护问题**
   - 需求变化、调试或 traceability 分析时，显式列表几乎不可操作。

更重要的是，这里不是一般的模型压缩问题，而是带安全保证的压缩问题。普通 machine learning 里的“多数投票即可”不适用，因为一旦压缩后错选一个动作，就可能直接破坏安全。

因此这篇论文真正要解决的是：

$$
\text{如何把安全且近似最优的 hybrid 策略压缩成小表示，同时不丢掉安全性。}
$$

## 核心方法

这篇论文的方法可以分成三层：`HMDP 建模层 -> Stratego+ 工作流层 -> 决策树压缩层`。

### 1. 先明确对象：Hybrid Markov Decision Process

论文把问题建模成 hybrid Markov decision process，记作：

$$
M = (C, U, X, F, \delta)
$$

其中：

1. `C`
   - 控制器可选的离散 mode。
2. `U`
   - 环境的离散 mode。
3. `X`
   - 连续状态变量。
4. `F_{c,u}`
   - 在控制 mode 与环境 mode 组合下，连续变量如何随时间演化的 flow function。
5. `\delta`
   - 给环境 mode 切换赋概率。

这一定义很重要，因为它准确体现了论文所处的问题层级：

1. 不是纯 timed automata。
2. 也不是完全离散的 MDP。
3. 而是既有连续动力学，又有随机环境，又有控制决策的混合对象。

在这个对象上，论文区分了两种“语义用途”：

1. 把 `\delta` 忽略掉时，可以得到安全分析所需的 hybrid/timed game。
2. 把 `\delta` 保留时，可以对策略做期望代价优化。

所以安全与最优依然延续了 `Stratego` 的主思路：先把 hardest guarantee 固定，再谈平均性能。

### 2. 先求安全策略，再在其内部学近似最优策略

论文沿用了 `Stratego` 的标准主线：

1. 先把系统抽象成 game。
2. 用 `Uppaal Tiga` 合成一个安全策略 `\sigma_safe`。
3. 再把这个安全策略作用回原始 HMDP。
4. 在受限系统内，用 `Uppaal Stratego` 学出近似最优策略 `\sigma_opt`。

其逻辑关系可以压成：

$$
\sigma_{\mathrm{opt}}(s) \subseteq \sigma_{\mathrm{safe}}(s)
$$

也就是说，近似最优策略永远是安全壳内部的子策略。这一层没有新发明，但它是后续“安全压缩”成立的前提：如果没有 permissive safe strategy 作为上界，后面的压缩就很难有理论落脚点。

### 3. 用多标签 decision tree 表示非确定安全策略

论文最重要的新动作，是不用 BDD，也不只保留显式配置表，而是把策略学习成 decision tree。

这里要注意，树学的不是普通分类问题，而是**多标签策略问题**。因为对一个配置 `\gamma` 来说，安全策略 `\sigma_safe(\gamma)` 往往不是单个动作，而是一组允许动作。

训练数据形式可以理解成：

$$
(\gamma, \{a_1, \dots, a_k\})
$$

decision tree 的每个叶子节点不会只存一个类别，而是存每个动作在该叶子里“被允许/不被允许”的计数。论文记作：

$$
\theta(\ell) = [(n_1, y_1), \dots, (n_{|A|}, y_{|A|})]
$$

其中：

1. `n_a`
   - 叶子里不允许动作 `a` 的样本数。
2. `y_a`
   - 叶子里允许动作 `a` 的样本数。

### 4. 只允许叶子输出 pure actions，以保持安全

这是整篇论文最核心的安全机制。作者不采用常见的“叶子按多数类输出”规则，而是只允许叶子输出 pure action，也就是在该叶子中被**所有**样本都允许的动作。

换句话说，如果一个叶子里对动作 `a` 的统计是 `(0, y_a)`，说明没有任何样本禁止它，那么它才可以被预测出来。

这条规则把策略解释从“拟合大多数”变成了“只保留交集”：

$$
a \text{ is pure in leaf } \ell \iff n_a = 0
$$

这是整篇论文的安全关键。因为一旦改成多数原则，就会出现某些状态在叶子里其实禁止动作 `a`，但树为了压缩仍把 `a` 输出出来，安全保证就破了。

### 5. 用 minimum split size 直接构造更小但更保守的树

标准 DT 学习通常把叶子一直分裂到熵为 `0`，从而精确记忆训练数据。论文保留了这条“精确树”主线，但又引入最关键的第一个压缩手段：minimum split size `k`。

它的含义是：

1. 节点中的样本数少于 `k` 时，就不再继续分裂。
2. 叶子因此可能混入多种不同配置。
3. 但只要叶子中至少还存在一个 pure action，树仍能输出一个安全动作集合。

所以 `k` 越大：

1. 树越小。
2. 允许动作越少。
3. 策略越保守。

这不是普通意义上的 approximation，而是“以 permissiveness 换体积”的安全近似。

### 6. 设计 safe pruning，在不破坏安全的情况下合并兄弟叶子

论文的第二个关键压缩手段，是专门为 permissive safe strategy 设计的 `safe pruning`。

设某个内部节点有两个孩子叶子 `A` 和 `B`，如果它们的 pure action 集合有交集，那么作者就允许把这两个孩子合并成一个新叶子，并让新叶子只保留交集中的动作。

其直观形式可以写成：

$$
\mathrm{Pure}(C) = \mathrm{Pure}(A) \cap \mathrm{Pure}(B)
$$

这样做的本质是：

1. 新叶子比原来更不 permissive。
2. 但不会引入任何原来不安全的动作。
3. 因而安全性仍保留。

这一步特别漂亮，因为它把“策略压缩”变成了一种结构化的保守化，而不是黑箱近似。

### 7. 形成 `Stratego+` 两条工作流

论文最终给出了非常清晰的 `Stratego+` 总流程图。其实有两条路：

#### 路径一：先求最优，再精确树化

1. 求 `\sigma_safe`
2. 在其内求 `\sigma_opt`
3. 再学一棵精确表示 `\sigma_opt` 的 DT，记作 `T_opt`

优点是性能最好，缺点是树不一定足够小。

#### 路径二：先压缩安全壳，再在更小安全壳里重新学最优

1. 从 `\sigma_safe` 学出较小的 `T^{k,p}_{\sigma_safe}`
2. 把系统限制到这棵更小的安全树上
3. 再重新优化，得到 `\sigma^{k,p}_{opt}`
4. 最后输出精确树 `T^{k,p}_{opt}`

这条路径的意义极大。它不是“先算完再压”，而是**把压缩过的安全壳重新喂回优化流程**，从而直接控制最终策略大小。

### 8. 对比 BDD，强调 DT 的几个结构优势

论文专门把 DT 与 BDD 做了比较。它并不否认 BDD 也能编码策略，但指出了几个对当前场景非常关键的差异：

1. DT 学习速度通常更快。
2. DT 更容易忽略 don't-care input。
3. DT 更容易输出人能读懂的规则。
4. DT 能天然支持“精确表示”与“安全近似表示”两种模式切换。

作者在案例里甚至展示了：如果再结合一点领域知识设计谓词，DT 还能被压到更小，并更容易做物理解释。

## 解决了什么问题

这篇论文解决的问题可以分成三个层级。

### 1. 它解决了“安全最优策略太大，不能用”的问题

此前 `Stratego` 路线已经能生成很强的策略，但输出形式常常只是巨大查表。`SOS` 证明：这些策略可以被系统压成很小的 decision tree，而且安全性仍保留。

### 2. 它解决了“压缩会不会破坏安全”这个核心顾虑

通过 pure action 语义和 safe pruning，论文把安全约束嵌进了表示学习过程本身。换句话说，它不是先学一个近似分类器，再祈祷安全性没坏；而是从表示规则层面就禁止不安全动作被预测。

### 3. 它解决了“紧凑性是否能进入主工作流”这个路线问题

论文最有价值的一点，是把 compactness 变成 `UPPAAL` 策略合成中的一等目标，而不是一个后处理小技巧。这也正是后面 compact shield / `Coshy` 路线能够成立的基础。

## 与 UPPAAL 技术线的关系

如果把 `UPPAAL` 的控制/策略路线拉成一条线，这篇论文的位置非常清楚：

1. `Tiga`：解决“是否存在安全控制策略”。
2. `Stratego`：解决“在安全壳内如何继续做性能分析与优化”。
3. `SOS`：解决“如何把安全且近似最优的策略压成小而可实施的表示”。
4. `Coshy`：把类似思想继续推进到 shield synthesis 与更现代的 hybrid safety 工具化。

所以这篇论文的真正意义，是把 `UPPAAL` 的角色从“能算出策略”推进成“能产出接近实际控制程序的策略表示”。

## 对本研究的启发

这篇论文对当前博士研究最直接的启发有三点。

1. **修复/控制结果不能只追求正确，还要追求小和可解释**
   - LLM 给出的模型修复建议如果过大、过碎、不可审查，即便逻辑上可行，也很难真正进入工程流程。
2. **安全性要嵌进表示压缩规则本身**
   - 不能先做激进压缩，再额外检查安全性。
   - 更稳健的做法，是像 pure action / safe pruning 那样，让压缩规则从一开始就只产出保守安全结果。
3. **把“紧凑性”放到主工作流，而不是当后处理**
   - 论文两条 `Stratego+` 路径里最有意思的就是第二条：先把安全壳压小，再在其内重做优化。
   - 这对你后续做“生成-验证-修复”闭环也很重要：结构大小、可解释性、修复代价都应该尽早进主流程。

总之，这篇论文让 `UPPAAL` 的策略路线第一次真正具备了“可部署控制程序”的味道，而不仅仅是“理论上最优的巨大策略表”。
