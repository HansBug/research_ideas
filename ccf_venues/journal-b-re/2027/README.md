## 6. 与本仓库 project 的年度相关性观察

- P1：需求获取、表示、验证与需求到模型转换均可作为 project_1 的需求侧理论和投稿入口，依据 [Aims and scope](https://link.springer.com/journal/766/aims-and-scope)。
- P2：scenarios、requirements validation、traceability 和自然语言需求处理可支撑验证场景与待验证性质生成，依据 [Aims and scope](https://link.springer.com/journal/766/aims-and-scope) 与 [Springer collections](https://link.springer.com/journal/766/collections)。
- P3：当稿件包含形式化分析、需求规约验证或复杂系统评价时，可与验证剖面 / 模型检查方向对齐，依据 [Aims and scope](https://link.springer.com/journal/766/aims-and-scope)。
- P4：需求缺陷、需求债、traceability 与变更影响分析可作为模型修复的需求侧证据链，依据 [Aims and scope](https://link.springer.com/journal/766/aims-and-scope)。
