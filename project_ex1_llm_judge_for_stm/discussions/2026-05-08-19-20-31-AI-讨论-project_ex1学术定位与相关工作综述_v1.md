## 1. 我们要解决的问题

### 1.1 表层问题

> 如何对 LLM 生成的状态机制品（state machine artifacts）做**高质量、可重复、可扩展**的自动化评判？

### 1.2 把表层拆成 3 个层级

| 层级 | 具体问题 |
|:-:|---|
| **方法学** | LLM-as-Judge 在结构化制品（不是自由文本）上的可靠性如何？传统 LLM-as-Judge 假设（Wang 2023 SC、Liu 2023 G-Eval）能否平移？ |
| **工程** | 怎么在**有 provider drift / cache 命中 / 偶发 transient fail** 的真实环境下，给出**可复现的实验结果**（带 error bar）？ |
| **领域** | 状态机制品的"评审质量"应该用什么维度刻画？rubric 怎么 anchor 到领域专家共识？ |

### 1.3 为什么这件事值得做

1. **STM 是控制系统软件可靠性的核心工件**——工业界（汽车、医疗、航空）每个安全关键系统设计的代价高、reviewer 资源稀缺
2. **LLM 生成 STM 已快速增长**（baselines/ 62 篇集中 2023-2025），但 **evaluation 滞后于 generation**——几乎所有论文都用 BLEU/F1/pass-fail/作者主观评分这种**粗粒度 metric**，缺少**精细化 review-quality 维度**
3. **LLM-as-Judge 在结构化制品上是开放问题**：Liu G-Eval / Zheng MTBench 主要是自由文本 / dialogue，不是结构化 artifact，**没有现成 best practice**

## 2. 相关工作 — 三条文献线索

### 2.1 LLM-as-Judge 方法学（自由文本主流）

| 工作 | 关键贡献 | 局限 |
|---|---|---|
| **G-Eval**（Liu et al., EMNLP 2023）| form-filling + chain-of-thought + auto-rubric | 单 shot 实验、无 noise floor；rubric 是 prompt-time 生成不稳定 |
| **LLM-as-Judge / MT-Bench**（Zheng et al., NeurIPS 2023）| multi-turn judge + position-bias correction + self-consistency | 自由文本 dialogue 不是结构化 artifact；SC 假设变化源是 multimodal（我们 W3 实测在窄带锁定下信号天然弱）|
| **Constitutional AI**（Bai et al., 2022）| critique-first → revise → score | 评分能力主要靠 RLAIF 训练，不直接迁移到 prompting-only LLM |
| **Calibration via verbalized confidence**（Tian et al., 2023）| 让 LLM 自己 rate confidence | 依赖 LLM 的 metacognition，OpenAI gpt-* 系列已知偏过自信 |
| **Self-Consistency**（Wang et al., 2023）| 多次采样取 median 提升 reasoning | 我们 W2 实测：在 rubric+iter_b 锁定空间下 sample variance ≈ 0，SC 失效 |

#### 这条线索的 generic 局限

1. 全部 single-shot 实验 + 没 error bar
2. 假设 LLM 输出有 informative variance（在锁定结构化任务上不成立）
3. 评测对象是 generic 文本（dialogue / summary / translation），**没有 STM 结构语义**
4. **无 provider drift 讨论**

### 2.2 STM 制品评估的现有 practice — 来自 6 篇 review corpus

| 论文 | review 来源 | 评分尺度 | reviewer 资质 | inter-rater agreement |
|---|---|---|---|---|
| **PSMBench**（Lin et al., NeurIPS 2025 D&B）| 14 个网络协议 RFC → PSM 标注 | annotator A 提 PSM → annotator B 审，分歧 discuss | domain expert（network protocol researchers）| **κ=0.82 states / 0.78 transitions** ✓ |
| **TTool-AI**（Apvrille & Sultan, MODELSWARD 2024）| 116 行 summary-level scored | 0-100 likert（论文报告 81/100 块图、63/100 STM）| 学生 + 系统工程师对照 | 学生组 vs 专家组对照（无 κ）|
| **llms_emp**（Wang et al., Internetware 2025）| 192 行 sample-level reviewed | 语法准确率 + 语义一致性 F1 | SE 研究者 | 报告 reviewer 间一致性讨论（无 κ）|
| **Hermes** | 仍待整理 | — | — | — |
| **RFCNLP** | 仍待整理 | — | — | — |
| **structure-and-event-driven** | 仍待整理 | — | — | — |

#### 这条线索的 generic 局限

1. **每篇论文 evaluation schema 都不同**——没有统一 review-quality 维度
2. **跨论文不可比**——TTool-AI 的"81/100"和 PSMBench 的"κ=0.82"测的不是同一个东西
3. **review 数据规模小**——单篇 100-200 行；6 篇加起来不够 1000 条 cross-domain
4. **reviewer 资质参差**——学生 / 工程师 / domain expert 混在一起，没有效度控制

### 2.3 STM 自动化评估（automated metric）— baselines/ 62 篇主流

绝大多数 STM-generation 论文用：

- **BLEU / ROUGE**——文本相似度，无结构语义
- **state count / transition count F1**——结构 metric，但忽略语义对错
- **pass-fail on test cases**——行为级，但需要参考实现
- **作者主观打分**——不可重复

少数尝试：

- **Umple Llama3** / **HDLBits LLM-FSM**——用 LLM judge 生成代码 → 跑测试，但**判 LLM 用的还是基于 metric 的判定，不是 LLM-as-Judge**
- **SysMBench**（Wang et al.）——提出 SysML behavior benchmark，但 evaluation 仍是结构 metric 主导

#### 这条线索的 generic 局限

- **结构 metric 把"看起来对"和"真的对"混淆**（PSMBench summary 类 score 挤在 0.08 窄带就是这个问题的实证）
- 需要 reference / oracle 才能算（无 ref 的 zero-shot 评估做不了）
- 没有 explainability / per-dim 反馈

## 3. 现有方法的 4 个核心局限

> 把 §2.1 + 2.2 + 2.3 综合：

| # | 局限 | 谁碰过 / 怎么碰的 | 我们 W3 / W2 / V4 实证印证 |
|:-:|---|---|---|
| **L1** | **无 noise floor**——单次 single-shot 数比，"+X HAI 改进"叙事普遍不带 σ | 几乎所有 generation 论文 | W3 §16: W0/W1/W1.5/W2 跨 milestone 数值差异主要来自 provider drift 而非真改进 |
| **L2** | **provider/cache 效应被忽略**——实验环境对 LLM 输出影响极大但很少报告 | LLM-as-Judge 文献完全不讨论 | W3 §13.6: miaocg cache 命中让 σ_W3 偏小 50%，airouter 真 LLM 才是真 noise floor |
| **L3** | **rubric 不锁定**——评分维度由 prompt-time LLM 决定 vs 由领域专家锚定 | G-Eval 是前者；PSMBench 是后者 | W2/W3: rubric form-filling + 18 anchors 让 record regime ScoreAlign 行为 stable，但需要 strict-llm 防 silent fallback |
| **L4** | **无 STM 专用 review-quality framework**——PSMBench 测 state/transition F1，TTool-AI 测 0-100 likert，没人测 calibration / evidence / specificity 等综合维度 | n/a | 我们 7-dim 框架（A-G）覆盖了 |

## 4. 我们能做的贡献 — 4 个层次

### 4.1 工程贡献（已实现，可直接 publish）

1. **strict-llm + per-task checkpoint**——让 LLM-as-Judge 实验可靠重启（rep4/5 验证通过：尾部 fail → checkpoint resume → 几分钟内补完）
2. **provider-aware fallback chain**——multi-provider with cooldown / responses-API（airouter reasoning model fix）
3. **noise floor protocol**——5-rep design，cache effect aware

### 4.2 方法学贡献（部分实现，需更多实验）

1. **rubric+iter_b real trade-off**：V4 实测 calib +5.7 vs ScoreAlign -4.5（已有数据，需要做控制实验确认）
2. **SC 在锁定结构化任务上的失效**：W2 §13.3 假设 + V4 印证（reps 内 σ_HAI=0.83，配置改动效果在 noise 内）
3. **provider drift 量化**：airouter vs miaocg 两条 chain 在同 config 下 mean 差距 < 0.1σ（V4 vs W3 N1 实测）

### 4.3 领域贡献（部分实现）

1. **7 维度 STM review-quality framework**（A 覆盖 / B 准确 / C 具体 / D 证据 / E 校准 / F 可操作 / G 一致性）
2. **跨 6 篇文献的 review schema 对齐**（PSMBench / TTool-AI / llms_emp 已实现到 parquet 层）

### 4.4 数据贡献（最弱，需要补）

1. **当前数据**：116（TTool）+ 192（llms_emp）+ ~PSMBench parquet 暂未抽 + 3 篇待整理 ≈ **总数 < 1000 条**
2. **缺 Path C**——自补 human review benchmark（论文级数据 < 1000 不足以 publish）

## 6. 待用户拍板的 4 个判断

下面这几条决策直接影响接下来 1-3 个月的工作排序：

### 6.1 核心 narrative 应该是哪条

> 倾向 **B**（方法学 paper）+ 同时铺路 A/C/D：
> - W3 noise + V4 strict + checkpoint 已经构成完整方法学故事
> - 不依赖 Path C，可以在 3-4 个月内完成
> - 出来后下一个 paper 再做 C / D

### 6.2 目标 venue 倾向

> Methodology 偏向 EMNLP / ICLR；STM 工程偏向 ICSE / FSE / TSE。
> **影响数据收集与对比 baseline 的取舍**。

### 6.3 是否值得自补 Path C human review

> 4-6 周招募 SE 研究生 / domain expert 自评 ~130 行 STM artifact——数据量虽小但 rigorous human gold，能撑论文里的"validation against humans"那一节。

### 6.4 现有 rubric 7 维度（A-G）是否要在论文里 keep 7 个

> 还是收缩到 3-4 个有清晰 trade-off 的（例如 B 准确 / E 校准 / G 一致）？
> **7 维度多反而会被 reviewer 问"为什么是这 7 个"**。
> 维度收缩会影响后续实验设计的 metric 集合。
