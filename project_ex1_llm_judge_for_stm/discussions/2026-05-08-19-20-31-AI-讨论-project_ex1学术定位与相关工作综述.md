## 1. 关键定义与术语（Definitions）

> 本节列出讨论中将反复出现的核心术语。每条均标注其属于"**领域已有定义**（含参考文献）"还是"**本研究新造定义**（含 rationale + 操作化方式）"。完整参考文献见 §11。

### 1.1 LLM-as-Judge

- **类型**：领域已有定义
- **定义**：使用一个 LLM（评判者）根据指定准则对另一个 LLM（或人类）产出的 candidate 输出进行评分、排序或反馈生成的评估范式
- **来源**：MT-Bench / Chatbot Arena 论文 [1]（Zheng et al., NeurIPS 2023）首次系统使用 "LLM-as-a-judge" 一词；G-Eval [2]（Liu et al., EMNLP 2023）同步独立提出 "LLM-based NLG evaluation" 形式
- **本研究操作化**：strict-llm 模式 + 7 维度 anchored rubric form-filling + 5-rep 重复

### 1.2 Rubric（评分准则）

- **类型**：领域已有定义（教育评估 / NLG eval）
- **定义**：把"质量"分解为多个可量化维度，每个维度配明确评分锚点（anchor descriptions）的结构化评分准则
- **来源**：教育评估学（Brookhart 2013 等经典文献，但本研究主要从 NLG eval 引用）；Prometheus [4]（Kim et al., ICLR 2024）系统使用 "score rubric description" 与 "per-level score description" 两层结构
- **本研究操作化**：7 维度（A 覆盖 / B 准确 / C 具体 / D 证据 / E 校准 / F 可操作 / G 一致），每维有显式 0/1/2/3 评分锚点

### 1.3 Anchored Rubric（锚定 rubric）

- **类型**：本研究新造定义（与既有概念有交集，但口径不同）
- **定义**：评分维度与每维评分锚点**事先由领域专家共识固定**，inference 时直接作为 prompt 输入，**不允许 LLM 在 prompt-time 自主生成或修改**
- **rationale**：与 G-Eval [2] 的 auto-generated criteria 形成对照——auto-generated 的优点是能适应 task，缺点是评分维度不可重复、跨实验不可比；anchored 牺牲灵活性换取**纵向（跨时跨 provider）与横向（跨论文）可比性**，对 methodology paper 的实证纪律是必要前提
- **与 Prometheus [4] 的关系**：Prometheus 在 inference 时也输入 rubric，但其训练数据使用 1k+ 个不同 rubric，所以 rubric 本身仍可变；本研究固定 rubric 维度 → 严格意义上属于 anchored 一支
- **操作化**：见 src/expert_review/rubric/

### 1.4 Form-filling

- **类型**：领域已有定义
- **定义**：把 LLM 评分任务约束为按预设 JSON / structured schema 填写各字段，避免自由文本输出导致的 parsing 不稳定
- **来源**：G-Eval [2] 首次系统化；与 OpenAI structured output / function calling 一脉相承
- **本研究操作化**：每维度产出 (evidence_quotes, score, justification) 三元组的 JSON schema

### 1.5 Self-Consistency

- **类型**：领域已有定义
- **定义**：对同一输入做多次随机采样，对结果做 majority vote / 数值聚合
- **来源**：Wang et al., ICLR 2023 [3]
- **本研究操作化**：**借用了多次采样这一手段，但用途不同**——本研究 5-rep 是为了**测量 noise floor**（评估 evaluator 自身的 stochasticity），不是为了 vote 一个更可信结果；详见 §1.7

### 1.6 Pairwise vs Pointwise

- **类型**：领域已有定义
- **定义**：
  - Pointwise：单 candidate 给绝对分（0-100 / 1-5 等）
  - Pairwise：两 candidate 比较选 better / worse / tie
- **来源**：MT-Bench [1] 同时使用两种形式；Information Retrieval / Recommender Systems 文献使用更早
- **本研究操作化**：当前 V4 主用 pointwise；pairwise 是后续 ablation 的待办

### 1.7 Noise Floor（噪声基底）

- **类型**：本研究新造定义（借自信号处理 / 测量学的术语）
- **定义**：在 candidate 配置完全固定（同 prompt、同 model snapshot、同 input）情况下，多次重复实验得到的某 metric 的标准差 $\sigma$；任何 metric 改进若小于 $3\sigma$，应被视为 noise 内涨落而非真实改进
- **rationale**：LLM-as-Judge 文献几乎全部 single-shot 报告（详见 §3.1.3）；当 evaluator 自身的 $\sigma$ 与待测改进效果同量级时，single-shot 数字毫无说服力。引入 noise floor 概念是把"evaluator stability"显式纳入 SE 评估方法学的尝试
- **操作化**：5-rep + 报告 $(\bar x, \sigma, n_{reps}, \text{provider snapshot})$ 四元组；任何改进 claim 须 $\geq 3\sigma$
- **来源对照**：empirical SE 文献已有"replication studies"概念（Carver 2010、Juristo & Vegas 2011 等），但**未在 LLM-as-Judge 评估上系统使用**；信号处理的 noise floor [SP wiki] 提供了概念锚点

### 1.8 Provider Drift（服务商漂移）

- **类型**：本研究新造定义
- **定义**：同一请求经过同一 LLM 的同一名义 model（如 gpt-4o），在不同 provider（OpenAI 直连 vs 第三方代理 vs 自托管）或不同时间窗口下，输出分布出现系统性偏移
- **rationale**：LLM-as-Judge 实验通常一周内做完，未跨 provider 版本验证；但 W3 §13 实测发现 airouter / miaocg 两条 chain 在同 config 下 mean 差距虽 < $0.1\sigma$，**但 metric variance 与 cache 命中率会显著影响 noise floor 的估算**（miaocg cache 命中让 $\sigma_{W3}$ 偏小约 50%）
- **操作化**：每条实验记录 4 元组中的 provider 字段必须包含 provider name + model snapshot version + commit hash
- **来源对照**：未见现有 LLM-as-Judge 文献系统讨论；"reproducibility crisis in NLP" 论述（Belz et al. 2021 等）涉及但未聚焦 provider drift

### 1.9 Cache Effect（缓存效应）

- **类型**：本研究新造定义
- **定义**：第三方 LLM provider 内置的 prompt-response cache 在重复实验中命中后，返回完全相同的 response，使 $\sigma$ 估算偏低、noise floor 估计失真
- **rationale**：与 provider drift 互补——前者是跨 provider 漂移，后者是同 provider 内 noise 估算被掩盖
- **操作化**：strict-llm 模式 + per-task checkpoint 跨时跨 cache hit 验证

### 1.10 STM Artifact（状态机制品）

- **类型**：本研究操作化（state machine 是经典概念）
- **定义**：在 SE 工件流（NL 需求 → 状态机模型）末端产出的状态机表示，包含状态集 $S$、事件集 $E$、变量集 $V$、迁移集 $Tr$、动作集 $A$（基本五元组），可扩展为含时钟约束 $C$ 与不变式 $Inv$ 的时间状态机 $TSM$
- **来源**：经典 state machine 定义出自 Hopcroft & Ullman 1979；时间自动机出自 Alur & Dill 1994
- **本研究操作化**：[../state_machine_review_corpus/](../state_machine_review_corpus/) 6 篇文献已对齐到统一 schema，含 UML SM / SysML SM / Statechart / Protocol SM / FSM 多家族

### 1.11 Strict-LLM Mode

- **类型**：本研究新造定义（工程术语）
- **定义**：实验中所有 LLM 调用必须实际发生，禁止任何形式的 deterministic fallback / 缓存返回（除 provider 内部不可见 cache）；任何 LLM 端 fail 必须在 checkpoint 中显式记录而非 silent 用规则代偿
- **rationale**：W2 期间发现"silent fallback"会让看似 LLM-driven 的实验实际跑成 deterministic，使 noise floor 估计完全失效；strict-llm 是 noise floor 协议成立的前置条件
- **操作化**：src/expert_review/fallback_llm.py 中的 strict mode flag

### 1.12 Inter-rater Agreement / Cohen's Kappa $\kappa$

- **类型**：领域已有定义
- **定义**：两位独立 reviewer 对同一标注对象给出相同判定的一致性度量；$\kappa = (p_o - p_e) / (1 - p_e)$，其中 $p_o$ 是观察到的一致率，$p_e$ 是随机一致的期望率
- **来源**：Cohen 1960
- **本研究使用方式**：作为 STM review corpus 的入选硬条件之一（hardcondition H3 之 inter-rater 报告）；目标是与领域中已经报告 $\kappa$ 的工作（PSMBench $\kappa = 0.82$ states / $\kappa = 0.78$ transitions）对齐

## 2. 我们要解决的问题

### 2.1 表层问题

> 如何对 LLM 生成的状态机制品（STM artifact，定义见 §1.10）做**高质量、可重复、可扩展**的自动化评判？

### 2.2 三个层级

| 层级 | 具体问题 |
|:-:|---|
| **方法学** | LLM-as-Judge（§1.1）在结构化制品上的可靠性如何？传统 LLM-as-Judge 假设（如 SC §1.5、G-Eval auto-rubric §1.3）能否平移？ |
| **工程** | 怎么在有 provider drift（§1.8）/ cache effect（§1.9）/ 偶发 transient fail 的真实环境下，给出可复现实验结果（带 error bar）？ |
| **领域** | STM 制品的"评审质量"应该用什么维度刻画？rubric（§1.2）怎么 anchor（§1.3）到领域专家共识？ |

### 2.3 为什么这件事值得做

1. **STM 是控制系统软件可靠性的核心工件** — 工业界（汽车、医疗、航空）每个安全关键系统设计的代价高、reviewer 资源稀缺
2. **LLM 生成 STM 已快速增长**（baselines/ 62 篇集中 2023-2025），但 evaluation 滞后于 generation — 几乎所有论文都用 BLEU/F1/pass-fail/作者主观评分这种粗粒度 metric，缺少精细化 review-quality 维度
3. **LLM-as-Judge 在结构化制品上是开放问题** — 详见 §3.2 的 4 篇 SE-artifact LLM-as-Judge 同类工作综述：code（CodeJudge [11]）/ class diagram（UML-Assessment [13]）/ sequence diagram（MCeT [12]）已有，但 STM 仍空白
4. **SE 2030 vision 已点名此方向** — He et al. [9] 在 SE 2030 forward-looking paper 中明确把"LLM-as-Judge for structured SE artifacts"列为关键缺口

### 2.4 论文类型 — Methodology Paper

把 project_ex1 写成 SE 方向的方法学论文，而非 application paper / tool paper。

| 论文类型 | 重点 | 与 project_ex1 的匹配度 |
|---|---|:-:|
| **Methodology paper** | 提出新方法（或新方法学纪律）+ 证明它解决了某个旧方法做不到的问题 | ✅ **目标类型** |
| Empirical study | 大规模实测某现象 / 某工具 | 🟡 我们有实证，但实证不是核心 |
| Benchmark paper | 提出新数据集 + leaderboard | ⚪ 不是主线 |
| Tool paper | 释放工具 + demo + 工业用例 | ⚪ infrastructure 是副产物 |

**贡献分层**（每层独立可被采纳）：

| 层次 | 贡献 | 证据 |
|---|---|---|
| **L1** | STM artifact 多维评审 rubric（7 维 anchored）| 在 STM 数据集上的可解释 review；rubric 与人评对齐度 |

reviewer 不一定接受全部 4 层，但**只要 L1 + L2 站住**，论文就有可发表价值。

### 3.1 Generic LLM-as-Judge 方法学（自由文本主流）

#### 3.1.1 7 篇代表性工作的 method × IO 结构化对比

#### 3.1.2 横向归纳 — 现有方法的 4 大类

| 类别 | 代表 | 核心 | 适合 SE artifact 吗？ |
|---|---|---|:-:|
| **Pure prompting + auto-rubric** | G-Eval | LLM 自己生成 rubric 再打分 | 🟡 SE rubric 应来自工程实践，不能 auto |
| **Pure prompting + anchored rubric** | Prometheus inference 形态、本研究形态 | 输入预定义 rubric → form-filling 打分 | ✅ **最契合** |
| **Aggregation 类** | Self-Consistency / MT-Bench position-swap | 多次采样 + majority vote / pairwise swap | ✅ 用于 noise floor 而非 vote |
| **Trained judge** | Prometheus / JudgeLM | fine-tune 一个 judge LLM | 🔴 SE artifact 数据 < 1k 不可走 |

#### 3.1.3 这条线索的 generic 局限

1. 全部 single-shot 实验 + 没 error bar
2. 假设 LLM 输出有 informative variance（在锁定结构化任务上不成立）
3. 评测对象是 generic 文本（dialogue / summary / translation），没有 STM 结构语义
4. 无 provider drift 讨论

### 3.2 SE-artifact / SE-reliability LLM-as-Judge / 同类工作（7 篇，2026-05-08 新增）

> **重要发现**：v2 讨论之前我们以为"LLM-as-Judge 在 SE artifact 上是空白"，但深入调研（含 code-to-courtroom 综述深读 + 二轮检索）后发现 2024-2026 间已经有 **7 篇代表工作**针对 SE artifact / SE-reliability 做 LLM-as-Judge：4 篇方法 / 3 篇 benchmark+reliability。这一发现迫使我们把"空白"叙事**改为"已有同类工作但仍未覆盖 STM 且未做 noise floor / drift 协议"** 的更精确叙事。

#### 3.2.3 这条线索的 generic 局限

1. **方法工作（4 篇）仍 single-shot / 单 seed 报告**（CodeJudge / UML-Assessment / MCeT / MermaidSeqBench 都未做 noise floor）
2. **3 个 benchmark / reliability 工作仍未触及 noise floor variance**（CRScore / MermaidSeqBench / RESpecBench：CRScore 关注 metric design，MermaidSeqBench 关注 capability ranking，RESpecBench 关注 bias direction）
3. 7 篇都未讨论 provider drift / cache effect
4. 7 篇 rubric anchor 程度不一：UML-Assessment ✓ anchored，MermaidSeqBench ✓ anchored 6 维，CRScore ✓ anchored 3 维，CodeJudge partial（taxonomy），MCeT partial（atomic + perspective），其余 n/a
5. **关键**：7 篇都未覆盖 state machine 类带 guards / temporal constraints 的 behavioral model

### 3.3 STM 制品评估的现有 practice — 来自 6 篇 review corpus

> 三空行已基于 [../state_machine_review_corpus/SUMMARY.md](../state_machine_review_corpus/SUMMARY.md) §3.1 / §3.1.1 补全。

| 论文 | 年份 / Venue | review 来源 | 评分尺度 | reviewer 资质 | inter-rater agreement |
|---|---|---|---|---|---|
| **PSMBench** [14] | 2025 NeurIPS D&B | 14 个网络协议 RFC → PSM 标注 | annotator A 提 PSM → annotator B 审，分歧 discuss | domain expert（network protocol researchers）| $\kappa = 0.82$ states / $\kappa = 0.78$ transitions ✓ |

#### 3.3.1 这条线索的 generic 局限

1. **每篇 evaluation schema 都不同** — 没有统一 review-quality 维度（PSMBench 测 state/transition F1，TTool-AI 测 0-100 likert，llms_emp 测多维 normalized quality，structure-and-event-driven 测 component-level F1）
2. **跨论文不可比** — TTool-AI 的 81/100 和 PSMBench 的 $\kappa = 0.82$ 测的不是同一个东西
3. **review 数据规模仍小** — 单篇 100-500 行；6 篇加起来约 1,000 行
4. **reviewer 资质参差** — 学生 / 工程师 / domain expert 混在一起
5. **inter-rater agreement 报告稀疏** — 6 篇里仅 PSMBench 显式 $\kappa$；其余多依赖 cross-verify 或 multi-rater 描述

### 3.4 STM 自动化评估（automated metric）— baselines/ 62 篇主流

绝大多数 STM-generation 论文用：

- BLEU / ROUGE — 文本相似度，无结构语义
- state count / transition count F1 — 结构 metric，但忽略语义对错
- pass-fail on test cases — 行为级，但需要参考实现
- 作者主观打分 — 不可重复

少数尝试：

- **Umple Llama3** / **HDLBits LLM-FSM** — 用 LLM judge 生成代码 → 跑测试，但**判 LLM 用的还是基于 metric 的判定，不是 LLM-as-Judge**
- **SysMBench** — 提出 SysML behavior benchmark，但 evaluation 仍是结构 metric 主导

#### 3.4.1 这条线索的 generic 局限

- 结构 metric 把"看起来对"和"真的对"混淆（PSMBench summary 类 score 挤在 0.08 窄带就是这个问题的实证）
- 需要 reference / oracle 才能算（无 ref 的 zero-shot 评估做不了）
- 没有 explainability / per-dim 反馈

## 5. 我们能做的贡献 + 诚实的创新点 / 借鉴点分析

### 5.1 工程贡献（已实现，可直接 publish 作为 reproducibility appendix）

1. **strict-llm + per-task checkpoint** — 让 LLM-as-Judge 实验可靠重启（rep4/5 验证通过）
2. **provider-aware fallback chain** — multi-provider with cooldown / responses-API（airouter reasoning model fix）
3. **noise floor protocol** — 5-rep design，cache effect aware

### 5.2 方法学贡献（部分实现，需更多实验）

1. **rubric+iter_b real trade-off**：V4 实测 calib +5.7 vs ScoreAlign $-4.5$
2. **SC 在锁定结构化任务上的失效**：W2 §13.3 假设 + V4 印证（reps 内 $\sigma_{HAI} = 0.83$，配置改动效果在 noise 内）
3. **provider drift 量化**：airouter vs miaocg 两条 chain 在同 config 下 mean 差距 < $0.1\sigma$（V4 vs W3 N1 实测）

### 5.3 领域贡献（部分实现）

1. **7 维度 STM review-quality framework**（A-G）
2. **跨 6 篇文献的 review schema 对齐**（PSMBench / TTool-AI / llms_emp / Hermes / RFCNLP / structure-and-event-driven 已实现到 parquet 层）

### 5.4 数据贡献（最弱，需要补）

1. 当前数据 ~973 行（详见 [state_machine_review_corpus/SUMMARY.md §一](../state_machine_review_corpus/SUMMARY.md)）
2. 缺 Path C — 自补 human review benchmark

### 5.5 学术创新点（诚实分析）

> 把"创新"分为 **方法学新意**、**对象新意**、**纪律新意** 三个维度，逐一对照 §3.1 + §3.2 共 14 篇相关工作，**不夸大**。

| # | 创新点 | 是否真新 / 多新 | 与最近相关工作的差异 |
|:-:|---|---|---|
| **N1** | 把 noise floor + provider drift 显式纳入 LLM-as-Judge 的方法学纪律 | 🟢 **真新**（在 LLM-as-Judge 文献中无人系统做）| §3.1 + §3.2 共 14 篇都没做；与信号处理 noise floor 借概念锚点，与 empirical SE replication studies 借思路，但**首次组合并工程化操作**到 LLM-as-Judge |
| **N2** | 把 anchored rubric（domain-anchored 维度 + 评分锚点）固化为 inference-time 输入，配合 form-filling 与 evidence quoting | 🟡 **方法增量** | UML-Assessment [13] 已做 anchored rubric + few-shot examples；Prometheus [4] 在 inference 时输入 rubric；我们的差异是**3 元组 (evidence, score, justification) 的强 schema** + **strict-llm 拒绝 fallback** |
| **N3** | STM artifact 域的多维评审框架（A-G 7 维）| 🟢 **领域内首次** | 已有 STM eval（PSMBench F1 / TTool-AI likert）都是单维或低维；但要老实说：7 维设计本身受 NLG eval 多维 rubric（如 USR）启发 |
| **N4** | "5-rep aggregation 用于 noise floor 测量而非 vote" 的方法学转向 | 🟢 **新颖应用** | Self-Consistency [3] 用 multi-sample 做 vote；我们用相同 multi-sample 做 stability characterization — 是工具相同、方法学目的不同的转向 |
| **N5** | 把 W2 confidence-formula bug 作为 motivating example 论述"silent fallback hides evaluator stochasticity" | 🟢 **真新** | UML-Assessment [13] 也报告了类似 bug（"LLM 总分 ≠ 子项之和"），但只把它当 limitation；我们把它**升级为方法学论述的核心 case** |
| **N6** | 跨 6 篇异构 STM review schema 的对齐（统一到 parquet schema）| 🟡 **数据工程价值** | 严格说不是方法学创新，但属于 reproducibility appendix 的 strong contribution；为后续 STM-judge benchmark 的可比性奠基 |

**总评**：本研究的真实学术内核是 **N1 + N4 + N5**（noise floor 协议、5-rep 转向、bug 类 motivating example），这是**真创新**；N2 是**方法增量**，不能作为主卖点；N3 是**领域内首次但概念借自 NLG eval**，需要诚实表述。

## 9. §Related Work 段落骨架（可复用到论文里）

```
§2 Related Work
   §2.1 LLM-as-Judge for Free-Text Outputs
        - G-Eval [Liu23]、MT-Bench [Zheng23]、Prometheus [Kim24]、JudgeLM [Zhu23]
        - 共同特征：自由文本 + 单 seed + 隐含 generic rubric
        - 共同空缺：未触及 SE artifact、未做 noise floor

   §2.2 Aggregation & Calibration
        - Self-Consistency [Wang23]、Verbalized Confidence [Tian23]、Constitutional AI [Bai22]
        - 我们的关系：aggregation 思路借鉴用于 noise floor 而非 vote

   §2.3 LLM-as-Judge for SE Artifacts (closest siblings)
        - CodeJudge [Tong24] — code generation, 9-class fault taxonomy
        - CRScore [Naik25] — code review comment, 3-dim reference-free, neuro-symbolic
        - UML-Assessment [Bouali25] — UML class diagrams, anchored rubric, Pearson > 0.76 with TAs
        - MCeT [Ahmed25] — UML sequence diagrams, atomic + multi-perspective + cross-check
        - MermaidSeqBench [Shbita25] — NL→Mermaid sequence diagram, 6-dim benchmark
        - RESpecBench [Anon26] — LLM-as-Judge reliability for formal spec (sound verifier ground truth)
        - SE 2030 vision [He25] — gap of structured-artifact judging
        - 共同空缺：未做 noise floor / provider drift；未覆盖 STM behavioral model（含 guards / temporal）

   §2.4 STM Quality Evaluation (Pre-LLM)
        - PSMBench [Lin25]、TTool-AI [Apvrille24]、llms_emp [Wang25]、Hermes [AlIshtiaq24]、
          RFCNLP [Pacheco22]、structure-and-event-driven [Mussbacher26]
        - 共同空缺：每篇 schema 不同、跨论文不可比、低规模

   §2.5 Bridging the Gap (this work)
        - anchored rubric for STM (vs auto-rubric in G-Eval, vs atomic-only in MCeT)
        - 5-rep noise-floor protocol (vs single-seed in §2.1+2.3)
        - prompting-only path (vs fine-tune in Prometheus / JudgeLM)
        - state machine as first concrete behavioral-model instance with guards / temporal
```

**主要引用句拟稿**：

> "While LLM-as-Judge research has rapidly extended to several SE artifact families — code [Tong24], UML class diagrams [Bouali25], and UML sequence diagrams [Ahmed25] — three methodological gaps remain. First, none of the SE-domain works above adopt a multi-replication noise-floor protocol that can distinguish a genuine quality improvement from LLM-evaluator stochasticity, leaving practitioners with single-shot numbers whose error bars are unknown. Second, none discuss provider drift or cache effects, even though our experiments (W3) show that cache hits can deflate measured variance by ~50%, hiding the true noise floor. Third, the closest sibling work — MCeT [Ahmed25] for UML sequence diagrams — does not generalize to state machines, which add transition guards and temporal constraints absent from sequence diagrams. This paper addresses all three gaps with a 7-dimension anchored rubric for state machine artifacts, a 5-replication noise-floor protocol (strict-llm + per-task checkpointing), and a methodologically explicit treatment of provider drift."
