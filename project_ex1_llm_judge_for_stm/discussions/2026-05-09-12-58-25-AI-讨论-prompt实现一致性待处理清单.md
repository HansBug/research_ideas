## I-1: `evidence_discipline` prompt-implementation 错配

### 现象

- **Prompt "what" 文字声称**：`Self-discipline of the reviewer: whether all claims have locator + snippet, whether reason_text stays close to evidence, whether confidence matches actual evidence amount. This dimension scores the reviewer's own discipline.`
- **Prompt anchor 文字**：`uml_anchor_1.0 — All 6 dim issues have locator: 'prediction:relation:5' → 1.0`
- **代码实际输入** (`build_rubric_prompt`)：与其他 5 维相同 — `(R, M, ref, deterministic extras (trace_ratio / matched_ratio / contradiction_count / ...))`
- **关键事实**：LLM **从未看到 reviewer 的 V_1 输出**（即 5 个 Tier 1 dim 的 score / evidence / reason_text / confidence）

### 实际在量什么

LLM 在这种条件下只能做 **self-prediction**：

> "如果让一个 reviewer 评估当前这个 (R, M, ref)，我预计 review 会有多 disciplined？"

LLM 凭 prior + auxiliary signals 推断：
- 高 trace_ratio / 低 contradiction_count → artifact 易找 evidence-locator → ED 预测高分
- 含糊 artifact → 任何 review 都难给具体 locator → ED 预测低分

→ **实际评的是 artifact 的 reviewability，不是 reviewer 的 discipline**

### 三条对策

| 选项 | 内容 | 工程成本 | paper 故事 |
|:-:|---|---|---|
| **A** | 承认 mis-named；重命名为 `review_groundability`；改 prompt "what" 文字反映实情；abstract method 退化为 **6 维 flat object eval** | 0（仅改名 + 文字）| "5+1 双层 self-audit" 创新点退化 |
| **B**（推荐） | 修代码到 sequential：先并行跑 5 个 Tier 1，再串行用 V_1 拼到 evidence_discipline 的 prompt 里调 LLM | 1-2 小时（+1 次 LLM call 串行延迟）| **5+1 双层 self-audit** 故事完全自洽 |
| **C** | 保留 6 维并行；改 prompt "what" 为 "Expected groundability of a disciplined review of this artifact"；重命名为 `review_groundability` | 0（改名 + 文字）| "5+1" 退化为 "5 + reviewability proxy" |

## I-4: `llm_rubric_score` 内置 deterministic fallback ≠ 讨论稿 strict-llm "no silent fallback" 纪律

### 现象

主讨论 §1.11 / §3.4 一直强调：
> **No silent fallback**：任何 LLM 端 fail 必须显式抛出，不允许偷偷走 deterministic 兜底（这是 noise floor 协议成立的前置条件）

但 `agents/rubric_scorer.py::llm_rubric_score` 函数在以下 4 种情况下**会无声 fallback 到 deterministic_estimate**：

1. `llm is None` → 直接返回 deterministic estimate（reason_text "rubric scorer skipped"）
2. `invoke_llm_json` 抛异常 → 返回 deterministic estimate（reason_text "rubric scorer error"）
3. payload 非 dict → 返回 deterministic estimate（reason_text "rubric scorer returned non-dict"）
4. `raw_score` 不在 [0, 1] 或 hard-reject 触发（偏离 det > 2× bound）→ 返回 deterministic estimate

**第 1 / 2 / 3 条是真正的 silent fallback**——LLM 没真跑成时直接用 deterministic 兜底，不抛异常上游不感知。
**第 4 条是 sanity check fallback**——LLM 跑了但输出不可信时用兜底，与 strict-llm 思想偏冲突但更可辩护。

### 影响

- **noise floor 估计可能被污染**：当某次 LLM call 失败 → 该 rep 静默走 deterministic → 该 rep 的 σ 贡献为 0（因为 deterministic 是确定值）→ k-rep $\hat\sigma$ 被低估
- 与 strict-llm 协议（讨论 §1.11）**直接矛盾**

### 三条对策

| 选项 | 内容 |
|:-:|---|
| **A** | 改 `llm_rubric_score` 让 case 1/2/3 抛异常上传，不再 silent fallback；只保留 case 4（sanity reject）作 deterministic clip |
| **B** | 引入 `strict_mode` flag（讨论稿声称的 "strict-llm mode"），打开时禁用全部 fallback；W4+ 实验默认开 |
| **C** | 在讨论稿明示 "strict-llm 与 rubric_score 内部 fallback 是两个不同 layer"，rubric 内部 fallback 不算违反 strict-llm；并把 rubric fallback 比例显式记录到 noise floor metadata，做事后修正 |

### 决策状态

⏳ 待用户开会回来后拍板（与 I-1 决策可能耦合，因 I-1=B 会改 score_composer 调用顺序，可顺便加 strict_mode）
